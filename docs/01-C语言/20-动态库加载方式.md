# 动态库加载方式

> 掌握动态库的隐式加载与显式加载

***

> **Load only what you need, when you need it.** — Unix Philosophy
> （只加载你需要的，在你需要的时候。）

***

> 💡 **通俗理解 - 两种加载方式？**

想象你要使用一台共享打印机：
- **隐式加载**：打印机一直开着，随时能用，但耗电（程序启动就加载所有库）
- **显式加载**：需要时才打开打印机，用完关掉（按需加载，更省电）

**动态库加载方式决定了何时、如何使用库！**

***

> 🔬 **加载方式的本质**：
> - **隐式加载**：编译时绑定，程序启动自动加载所有依赖
> - **显式加载**：运行时手动控制，按需加载、按需卸载
> - **核心区别**：加载时机和控制权的不同

## 1. 两种加载模式概述

### 1. 隐式加载（静态加载 / 编译时链接）

**特点**：
- 编译时通过 `-lxxx` 链接导入库（Windows `.lib` / Linux `.a`）
- 程序**一启动**，操作系统自动把依赖的 DLL/SO 全部加载进内存
- 全程不用自己写一行加载、卸载代码

### 2. 显式加载（动态加载 / 运行时手动加载）

**特点**：
- **代码里手动控制**：加载 → 拿函数地址 → 调用 → 手动卸载
- 编译**不需要导入库**
- 用到才加载，不用可卸载
- 适合插件、可选功能、兼容多版本库

---

## 2. 隐式加载（编译时链接）

### 1. 工作流程

```
源代码 (main.c)
    │
    ├── 编译时：链接导入库 .lib/.a
    │
    └── 运行时：程序启动自动加载 DLL/SO
```

### 2. 使用方式

**Windows MinGW**：
```bash
# 生成 DLL 和导入库
gcc -shared -o mylib.dll mylib.c -Wl,--out-implib=libmylib.a

# 编译主程序（需要导入库）
gcc main.c -L. -lmylib -o main.exe
```

**Linux**：
```bash
# 生成 .so（不需要单独的导入库）
gcc -fPIC -shared -o libmylib.so mylib.c

# 编译主程序
gcc main.c -L. -lmylib -o main
```

### 3. 特点总结

| 特性 | 说明 |
|------|------|
| 开发难度 | 简单，直接调用函数 |
| 加载时机 | 程序启动时自动加载 |
| 卸载控制 | 不可手动卸载 |
| 库缺失表现 | 启动直接闪退/报错 |
| 适用场景 | 基础依赖、必用库 |

---

## 3. 显式加载（运行时动态加载）

### 1. 工作流程

```
源代码 (main.c)
    │
    ├── 编译时：不需要导入库，不需要 -l 链接
    │
    └── 运行时：
        1. LoadLibrary/dlopen 加载库
        2. GetProcAddress/dlsym 获取函数地址
        3. 调用函数
        4. FreeLibrary/dlclose 卸载库
```

### 2. 核心优势

- **按需加载**：用到才加载，减少启动时间和内存占用
- **容错降级**：库不存在也不会闪退，可以优雅处理
- **插件系统**：支持动态加载插件
- **版本兼容**：可根据情况加载不同版本的库

---

## 4. Windows 显式加载实战

### 1. 核心 API

| 函数 | 作用 |
|------|------|
| `LoadLibraryA()` | 加载 DLL，返回库句柄 |
| `GetProcAddress()` | 获取导出函数地址 |
| `FreeLibrary()` | 卸载 DLL |

### 2. 完整示例

**步骤1：创建 DLL（mylib.c）**

```c
#include <stdio.h>

__declspec(dllexport) int add(int a, int b)
{
    return a + b;
}

__declspec(dllexport) void hello()
{
    printf("Hello from DLL!\n");
}
```

编译：
```bash
gcc -shared -o mylib.dll mylib.c
```

**步骤6：主程序（main.c）**

```c
#include <stdio.h>
#include <windows.h>

typedef int (*PFN_ADD)(int a, int b);
typedef void (*PFN_HELLO)(void);

int main(void)
{
    HMODULE hDll = LoadLibraryA("mylib.dll");
    if (hDll == NULL)
    {
        printf("加载 DLL 失败\n");
        return 8;
    }

    PFN_ADD add = (PFN_ADD)GetProcAddress(hDll, "add");
    PFN_HELLO hello = (PFN_HELLO)GetProcAddress(hDll, "hello");

    if (add == NULL || hello == NULL)
    {
        printf("获取函数地址失败\n");
        FreeLibrary(hDll);
        return 8;
    }

    hello();
    printf("7 + 5 = %d\n", add(7, 5));

    FreeLibrary(hDll);
    return 0;
}
```

编译（无需链接任何库）：
```bash
gcc main.c -o main.exe
```

## 5. Linux 显式加载实战

### 1. 核心 API

| 函数 | 作用 |
|------|------|
| `dlopen()` | 加载 .so 动态库 |
| `dlsym()` | 获取函数/变量地址 |
| `dlclose()` | 卸载动态库 |
| `dlerror()` | 获取错误信息 |

### 2. 常用 flag

- `RTLD_LAZY`：用到函数才解析地址（常用）
- `RTLD_NOW`：立即解析所有符号

### 3. 完整示例

**步骤1：创建 .so（mylib.c）**

```c
#include <stdio.h>

int add(int a, int b)
{
    return a + b;
}

void hello()
{
    printf("Hello from .so!\n");
}
```

编译：
```bash
gcc -fPIC -shared -o libmylib.so mylib.c
```

**步骤2：主程序（main.c）**

```c
#include <stdio.h>
#include <dlfcn.h>

typedef int (*PFN_ADD)(int a, int b);
typedef void (*PFN_HELLO)(void);

int main(void)
{
    void *handle = dlopen("./libmylib.so", RTLD_LAZY);
    if (!handle)
    {
        printf("dlopen 失败: %s\n", dlerror());
        return 1;
    }

    PFN_ADD add = (PFN_ADD)dlsym(handle, "add");
    PFN_HELLO hello = (PFN_HELLO)dlsym(handle, "hello");

    char *err = dlerror();
    if (err || !add || !hello)
    {
        printf("dlsym 失败: %s\n", err ? err : "函数为空");
        dlclose(handle);
        return 1;
    }

    hello();
    printf("7 + 5 = %d\n", add(7, 5));

    dlclose(handle);
    return 0;
}
```

编译（必须加 `-ldl`）：
```bash
gcc main.c -o main -ldl
```

## 6. 两种方式对比总结

| 对比项 | 隐式加载 | 显式加载 |
|--------|----------|----------|
| 是否需要导入库 | ✅ 需要 `.lib` / `.a` | ❌ 不需要 |
| 编译是否要 `-l` 链接 | ✅ 需要 | ❌ 不需要 |
| 加载时机 | 程序启动自动加载 | 代码运行时手动加载 |
| 可否手动卸载 | ❌ 不可卸载 | ✅ 随时可卸载 |
| 库缺失表现 | 启动直接闪退 | 可代码判断、容错降级 |
| 适用场景 | 基础依赖、必用库 | 插件系统、可选功能、多版本兼容 |
| 代码复杂度 | 简单，直接调用 | 稍复杂，需函数指针 |
| 启动速度 | 较慢（加载所有依赖） | 较快（按需加载） |
| 内存占用 | 较大（全部加载） | 较小（按需加载） |

## 7. 关键注意事项

### 1. Linux 必须加 `-ldl`，Windows 不需要

**Linux 为什么要加 `-ldl`？**
- `dlopen / dlsym / dlclose` 函数不在 gcc 自带库中
- 它们存在于系统的 `libdl.so` 动态库中
- 必须告诉编译器链接 `libdl.so`

**`-ldl` 的含义：**
- `-l` = 链接某个库
- `dl` = 库名是 dl（全名 `libdl.so`）

```bash
# Linux 必须加 -ldl
gcc main.c -o main -ldl

# 不加会报错：undefined reference to dlopen
```

**Windows 为什么不用加？**
- `LoadLibrary / GetProcAddress` 属于系统 API，在 `KERNEL32.dll` 里
- MinGW 编译器默认自动链接 `KERNEL32.dll`
- 所以什么都不用加！

```bash
# Windows 直接编译
gcc main.c -o main.exe
```

**一句话总结：**
- **Linux：用 dlopen 必须 `-ldl`**
- **Windows：用 LoadLibrary 啥也不用加**

### 2. C++ 名字改编问题

C++ 编译器会对函数名进行改编（name mangling），导致 `GetProcAddress/dlsym` 找不到函数。

**解决方案**：使用 `extern "C"` 防止名字改编

```c
extern "C" {
    __declspec(dllexport) int add(int a, int b);
}
```

### 3. 路径问题

- 显式加载可以写**绝对路径**或**相对路径**
- 受系统 DLL/SO 搜索路径规则影响
- Windows：优先查找 exe 所在目录
- Linux：优先查找当前目录（使用 `./libxxx.so`）

### 4. 卸载时机

确保 DLL 里的函数、变量不再使用后，再调用 `FreeLibrary`/`dlclose`，否则会崩溃。

### 5. 句柄管理

- 加载一次就缓存句柄，不要重复加载不卸载
- 防止句柄泄露

---

## 8. 一句话总结

- **隐式加载**：编译绑定、启动自动加载，简单粗暴；
- **显式加载**：代码手动控加载/卸载，不用导入库，做插件、容错、动态版本适配必备。
