## 1. 单例模式

单例模式确保一个类只有一个实例，并提供一个全局访问点。

### 1. 适用场景

| 场景    | 说明        |
| ----- | --------- |
| 配置管理器 | 全局配置只需要一份 |
| 日志管理器 | 统一的日志输出   |
| 资源池   | 共享的资源管理   |
| 状态管理器 | 全局状态维护    |

### 2. 单例模式实现

**头文件** **`singleton.h`：**

```c
/*
 * ============================================================
 * 文件: singleton.h
 * 描述: 单例模式实现
 * 
 * 特点：
 * 1. 全局唯一实例
 * 2. 延迟初始化
 * 3. 线程安全（可选）
 * ============================================================
 */

#ifndef SINGLETON_H
#define SINGLETON_H

/* ==================== 单例结构体 ==================== */
typedef struct {
    int counter;
    char name[64];
    /* 其他数据成员... */
} Singleton;

/* ==================== 单例接口 ==================== */

/**
 * @brief 获取单例实例
 * @return 单例指针（首次调用时创建）
 */
Singleton* singleton_get_instance(void);

/**
 * @brief 销毁单例（可选，通常不需要）
 */
void singleton_destroy(void);

/* ==================== 单例操作 ==================== */
void singleton_increment(Singleton *s);
int singleton_get_counter(const Singleton *s);
void singleton_set_name(Singleton *s, const char *name);

#endif /* SINGLETON_H */
```

**实现文件** **`singleton.c`：**

```c
/*
 * ============================================================
 * 文件: singleton.c
 * 描述: 单例模式实现
 * ============================================================
 */

#include "singleton.h"
#include <stdlib.h>
#include <string.h>

/* 静态实例指针 */
static Singleton *instance = NULL;

/* 获取单例实例 */
Singleton* singleton_get_instance(void) {
    /* 延迟初始化：首次调用时创建 */
    if (instance == NULL) {
        instance = malloc(sizeof(Singleton));
        if (instance) {
            /* 初始化 */
            instance->counter = 0;
            instance->name[0] = '\0';
        }
    }
    return instance;
}

/* 销毁单例 */
void singleton_destroy(void) {
    if (instance) {
        free(instance);
        instance = NULL;
    }
}

/* 单例操作 */
void singleton_increment(Singleton *s) {
    if (s) s->counter++;
}

int singleton_get_counter(const Singleton *s) {
    return s ? s->counter : 0;
}

void singleton_set_name(Singleton *s, const char *name) {
    if (s && name) {
        strncpy(s->name, name, sizeof(s->name) - 1);
    }
}
```

### 3. 单例模式使用示例

```c
void demo_singleton(void) {
    /* 获取单例实例 */
    Singleton *s1 = singleton_get_instance();
    Singleton *s2 = singleton_get_instance();
    
    /* s1 和 s2 指向同一个实例 */
    printf("s1 == s2: %s\n", s1 == s2 ? "true" : "false");
    
    /* 使用单例 */
    singleton_set_name(s1, "MySingleton");
    singleton_increment(s1);
    
    printf("Name: %s, Counter: %d\n", 
           singleton_get_name(s2),  /* 注意：使用 s2 也能访问 */
           singleton_get_counter(s2));
    
    /* 程序结束时可选销毁 */
    singleton_destroy();
}
```

### 4. 线程安全考虑

#### 1. 为什么普通懒汉单例线程不安全？

上述基础实现**不是线程安全的**。在多线程环境下，两个线程可能同时执行到 `if (instance == NULL)` 判断：

1. 线程A：判断 `instance == NULL`，进入if块，还未执行 `malloc`
2. 线程B：**同时**也判断 `instance == NULL`，也进入if块
3. 结果：**两次 malloc 分配了两个不同实例**
4. 后果：全局指针被覆盖、内存泄漏、逻辑错乱

👉 **这就是典型的线程不安全：竞态条件（Race Condition）**

#### 2. 方案2：饿汉式单例（天生线程安全）

**程序启动时就提前创建好实例**，无需运行时判空：

```c
/* 静态全局变量，在 main 函数之前初始化 */
static Singleton instance = {0};

Singleton* singleton_get_instance(void) {
    return &instance;
}
```

**特点：**

- 初始化在**main之前**完成，由操作系统保证顺序
- 多线程只是读取地址，没有写操作
- ✅ **天然线程安全**

**缺点：** 程序启动就占用内存，即使不用也会分配。

#### 3. 方案3：懒汉式加互斥锁（最通用）

```c
#include <pthread.h>

static Singleton *instance = NULL;
static pthread_mutex_t singleton_mutex = PTHREAD_MUTEX_INITIALIZER;

Singleton* singleton_get_instance(void) {
    pthread_mutex_lock(&singleton_mutex);
    if (instance == NULL) {
        instance = malloc(sizeof(Singleton));
        if (instance) {
            instance->counter = 0;
            instance->name[0] = '\0';
        }
    }
    pthread_mutex_unlock(&singleton_mutex);
    return instance;
}
```

**特点：**

- 加锁后同一时间只有一个线程能进入创建逻辑
- ✅ 线程安全
- ⚠️ 性能开销：每次调用都要加锁解锁

#### 4. 方案4：C11 静态局部变量（懒人最简）

```c
Singleton* singleton_get_instance(void) {
    static Singleton instance = {0};  // C11 保证线程安全初始化
    return &instance;
}
```

**特点：**

- C11 标准规定：**局部静态变量初始化自带线程安全**
- 编译器自动生成加锁/解锁代码
- ✅ 线程安全且简洁
- 需要 C11 及以上标准支持

#### 5. 方案5：双重检查锁（DCL，性能最优）

```c
#include <pthread.h>

static Singleton *instance = NULL;
static pthread_mutex_t singleton_mutex = PTHREAD_MUTEX_INITIALIZER;

Singleton* singleton_get_instance(void) {
    if (instance == NULL) {           // 第一次检查（无锁）
        pthread_mutex_lock(&singleton_mutex);
        if (instance == NULL) {       // 第二次检查（有锁）
            instance = malloc(sizeof(Singleton));
            if (instance) {
                instance->counter = 0;
                instance->name[0] = '\0';
            }
        }
        pthread_mutex_unlock(&singleton_mutex);
    }
    return instance;
}
```

**特点：**

- 只有首次创建时才加锁，后续调用直接返回
- ✅ 线程安全
- ✅ 性能最优
- 注意：需要编译器支持内存屏障

#### 6. 线程安全方案对比

| 方案       | 线程安全 | 懒加载 | 性能 | 复杂度 |
| -------- | ---- | --- | -- | --- |
| 普通懒汉（无锁） | ❌    | ✅   | 高  | 低   |
| 饿汉式      | ✅    | ❌   | 高  | 低   |
| 懒汉式加锁    | ✅    | ✅   | 中  | 低   |
| C11 静态局部 | ✅    | ✅   | 高  | 低   |
| 双重检查锁    | ✅    | ✅   | 高  | 中   |

#### 7. 核心总结

- **不加锁的懒汉单例 = 绝对线程不安全**：多线程会同时创建多个对象
- **饿汉单例 = 天生线程安全**：启动时一次性建好，无竞态
- **懒汉要安全：加互斥锁 或 用 C11 局部静态 或 双重检查锁**

## 2. 工厂模式

工厂模式定义一个创建对象的接口，让子类决定实例化哪个类。

### 1. 适用场景

| 场景     | 说明            |
| ------ | ------------- |
| 对象创建复杂 | 隐藏创建细节        |
| 需要解耦   | 调用者不需要知道具体类型  |
| 支持扩展   | 新增类型不需要修改现有代码 |
| 统一管理   | 集中管理对象创建逻辑    |

### 2. 工厂模式实现

**头文件** **`factory.h`：**

```c
/*
 * ============================================================
 * 文件: factory.h
 * 描述: 工厂模式实现
 * 
 * 用途：
 * 1. 统一的对象创建接口
 * 2. 隐藏具体类型
 * 3. 便于扩展新类型
 * ============================================================
 */

#ifndef FACTORY_H
#define FACTORY_H

#include "shape.h"

/* ==================== 形状类型枚举 ==================== */
typedef enum {
    SHAPE_RECTANGLE,
    SHAPE_CIRCLE,
    SHAPE_TRIANGLE
} ShapeType;

/* ==================== 工厂接口 ==================== */

/**
 * @brief 根据类型创建形状
 * @param type 形状类型
 * @param params 创建参数（可变参数）
 * @return 形状对象指针
 */
Shape* shape_factory_create(ShapeType type, ...);

/**
 * @brief 注册新的形状类型（扩展机制）
 */
typedef Shape* (*ShapeCreator)(void *params);
int shape_factory_register(ShapeType type, ShapeCreator creator);

#endif /* FACTORY_H */
```

**实现文件** **`factory.c`：**

```c
/*
 * ============================================================
 * 文件: factory.c
 * 描述: 工厂模式实现
 * ============================================================
 */

#include "factory.h"
#include "rectangle.h"
#include <stdarg.h>
#include <stdlib.h>

/* 最大支持类型数 */
#define MAX_SHAPE_TYPES 32

/* 创建函数表 */
static ShapeCreator creators[MAX_SHAPE_TYPES] = {NULL};

/* 默认创建函数 */
static Shape* create_rectangle(void *params) {
    double *size = (double *)params;
    //28-C语言面向对象实现 2.3 继承的实现 rectangle_create 函数实现
    return (Shape *)rectangle_create(0, size[0], size[1]);
}

/* 初始化默认创建函数 */
__attribute__((constructor))  // GCC扩展，标记的函数会先于main函数执行
static void init_default_creators(void) {
    // 注册创建函数(自动)
    creators[SHAPE_RECTANGLE] = create_rectangle;
    /* 其他默认类型... */
}

/* 工厂创建函数 */
Shape* shape_factory_create(ShapeType type, ...) {
    // creators[type] == NULL → 没注册 创建函数
    if (type < 0 || type >= MAX_SHAPE_TYPES || !creators[type]) {
        return NULL;
    }
    
    /* 获取可变参数 */
    va_list args;
    va_start(args, type);
    void *params = va_arg(args, void *);
    va_end(args);
    
    /* 调用创建函数 */
    return creators[type](params);
}

/* 注册新类型 */
int shape_factory_register(ShapeType type, ShapeCreator creator) {
    if (type < 0 || type >= MAX_SHAPE_TYPES) {
        return -1;
    }
    creators[type] = creator;
    return 0;
}
```

### 3. 工厂模式使用示例

```c
void demo_factory(void) {
    /* 创建参数 */
    double rect_params[] = {5.0, 3.0};
    double circle_params[] = {3.0};
    
    /* 使用工厂创建对象 */
    Shape *rect = shape_factory_create(SHAPE_RECTANGLE, rect_params);
    Shape *circle = shape_factory_create(SHAPE_CIRCLE, circle_params);
    
    /* 多态调用 */
    if (rect) {
        shape_draw(rect);
        shape_destroy(rect);
    }
    
    if (circle) {
        shape_draw(circle);
        shape_destroy(circle);
    }
    
    /* 注册新类型 (注册创建函数-手动) (运行时扩展) */
    shape_factory_register(SHAPE_TRIANGLE, create_triangle);
}
```

## 3. 观察者模式

观察者模式定义对象间的一对多依赖，当一个对象状态改变时，所有依赖它的对象都会收到通知。

### 1. 核心概念

| 抽象角色 | 接地气别名 | 说明 |
| -------- | --------- | ---- |
| **Subject** | 发布者 / 事件源 | 发起事件、发布消息 |
| **Observer** | 订阅者 / 监听者 | 监听事件、接收通知 |
| **attach** | 关注 / 订阅 | 注册观察者 |
| **detach** | 取关 / 取消 | 移除观察者 |
| **notify** | 群发推送 | 通知所有观察者 |

### 2. 生活比喻

**Subject = 微信公众号**，**Observer = 关注用户**：
1. 用户关注公众号（attach）
2. 公众号发文章（notify）→ 所有用户收到推送（on_notify）
3. 用户取关（detach）→ 不再收到通知

**本质**：事件发起方遍历列表，主动调用每个监听者的回调函数。

### 3. 观察者模式实现

**头文件** **`observer.h`：**

```c
// 观察者模式核心接口
// 简单理解：Subject = 微信公众号，Observer = 关注用户
// 用户通过 attach 关注公众号，公众号通过 notify 群发消息

#ifndef OBSERVER_H
#define OBSERVER_H

// 前向声明：告诉编译器有这两个结构体
typedef struct Observer Observer;
typedef struct Subject Subject;

// 观察者虚函数表（接口）
// 所有具体观察者都要实现这两个函数
typedef struct {
    // 收到通知时调用的回调函数
    // self: 自己的指针, subject: 哪个主题发的通知, data: 通知内容
    void (*on_notify)(Observer *self, Subject *subject, void *data);
    // 销毁自己的函数
    void (*destroy)(Observer *self);
} ObserverVTable;

// 观察者基类
// 具体观察者需要内嵌这个结构体作为基类
struct Observer {
    const ObserverVTable *vtable;  // 虚函数表指针（实现多态）
    int id;                         // 观察者唯一标识
};

// 主题（发布者）结构体
// 管理所有订阅者，负责群发通知
typedef struct {
    Observer **observers;  // 订阅者列表（动态数组）
    int count;             // 当前订阅者数量
    int capacity;          // 列表容量（自动扩容）
} Subject;

// 主题操作函数声明
Subject* subject_create(void);           // 创建主题
void subject_destroy(Subject *subject);   // 销毁主题
int subject_attach(Subject *subject, Observer *observer);  // 订阅（关注）
int subject_detach(Subject *subject, Observer *observer);  // 取消订阅（取关）
void subject_notify(Subject *subject, void *data);         // 群发通知

#endif /* OBSERVER_H */
```

**实现文件** **`observer.c`：**

```c
/*
 * ============================================================
 * 文件: observer.c
 * 描述: 观察者模式实现
 * ============================================================
 */

#include "observer.h"
#include <stdlib.h>

Subject* subject_create(void) {
    Subject *subject = malloc(sizeof(Subject));
    if (subject) {
        subject->observers = NULL;
        subject->count = 0;
        subject->capacity = 0;
    }
    return subject;
}

void subject_destroy(Subject *subject) {
    if (subject) {
        if (subject->observers) {
            free(subject->observers);
        }
        free(subject);
    }
}

int subject_attach(Subject *subject, Observer *observer) {
    if (!subject || !observer) return -1;
    
    /* 扩容 */
    if (subject->count >= subject->capacity) {
        int new_capacity = subject->capacity == 0 ? 4 : subject->capacity * 2;
        Observer **new_observers = realloc(subject->observers, 
                                           new_capacity * sizeof(Observer *));
        if (!new_observers) return -1;
        
        subject->observers = new_observers;
        subject->capacity = new_capacity;
    }
    
    subject->observers[subject->count++] = observer;
    return 0;
}

int subject_detach(Subject *subject, Observer *observer) {
    if (!subject || !observer) return -1;
    
    for (int i = 0; i < subject->count; i++) {
        if (subject->observers[i] == observer) {
            /* 移动后面的元素 */
            for (int j = i; j < subject->count - 1; j++) {
                subject->observers[j] = subject->observers[j + 1];
            }
            subject->count--;
            return 0;
        }
    }
    return -1;
}

void subject_notify(Subject *subject, void *data) {
    if (!subject) return;
    
    for (int i = 0; i < subject->count; i++) {
        if (subject->observers[i]->vtable->on_notify) {
            subject->observers[i]->vtable->on_notify(
                subject->observers[i], subject, data);
        }
    }
}
```

### 4. 观察者模式使用示例

```c
/* 具体观察者实现 */
typedef struct {
    Observer base;
    char name[32];
} ConcreteObserver;

static void observer_notify(Observer *self, Subject *subject, void *data) {
    ConcreteObserver *obs = (ConcreteObserver *)self;
    printf("观察者 %s 收到通知: %s\n", obs->name, (char *)data);
}

static void observer_destroy(Observer *self) {
    free(self);
}

static const ObserverVTable observer_vtable = {
    .on_notify = observer_notify,
    .destroy = observer_destroy
};

ConcreteObserver* observer_create(const char *name) {
    ConcreteObserver *obs = malloc(sizeof(ConcreteObserver));
    if (obs) {
        obs->base.vtable = &observer_vtable;
        strncpy(obs->name, name, sizeof(obs->name) - 1);
    }
    return obs;
}

void demo_observer(void) {
    /* 创建主题 */
    Subject *subject = subject_create();
    
    /* 创建观察者 */
    Observer *obs1 = (Observer *)observer_create("Observer1");
    Observer *obs2 = (Observer *)observer_create("Observer2");
    
    /* 注册观察者 */
    subject_attach(subject, obs1);
    subject_attach(subject, obs2);
    
    /* 发送通知 */
    subject_notify(subject, "Hello, observers!");
    
    /* 移除一个观察者 */
    subject_detach(subject, obs1);
    
    /* 再次发送通知 */
    subject_notify(subject, "Only observer2 should see this");
    
    /* 清理 */
    obs1->vtable->destroy(obs1);
    obs2->vtable->destroy(obs2);
    subject_destroy(subject);
}
```

### 5. 执行流程

```
1. 创建主题 → 空观察者列表
2. 创建观察者 → 绑定虚函数表
3. attach → 观察者加入列表
4. notify → 遍历列表，逐个调用 on_notify
5. detach → 观察者移除列表
6. 销毁 → 清理资源
```

### 6. 底层机制

**"自动通知"的本质**：Subject 主动遍历观察者列表，逐个调用其 `on_notify` 回调函数。

```c
// subject_notify 核心逻辑
for (每个观察者 obs in 列表) {
    obs->vtable->on_notify(obs, 数据);
}
```

### 7. 核心技术点

| 技术 | 说明 |
|------|------|
| **函数指针** | `on_notify` 回调机制，收到通知时自动调用 |
| **虚函数表** | `ObserverVTable` 统一接口格式，实现多态 |
| **动态数组** | `observers` 自动扩容存储观察者列表 |
| **解耦** | 发布者与订阅者只通过接口通信，互不依赖 |

### 8. 真实应用场景

| 场景 | 说明 |
|------|------|
| UI 按钮点击 | 按钮是 Subject，监听器是 Observer |
| 游戏事件系统 | 敌人发现玩家 → 通知所有单位 |
| 消息推送 | 服务端发布 → 所有客户端接收 |
| 状态广播 | 配置变更 → 相关模块同步更新 |
| 日志系统 | 日志产生 → 多个接收器分发 |

## 4. 策略模式

策略模式将算法族封装，使算法可以独立于使用它的客户端变化。

### 1. 核心概念

| 抽象角色 | 说明 |
| -------- | ---- |
| **Strategy** | 策略接口，定义算法的统一调用方式 |
| **ConcreteStrategy** | 具体策略，实现不同的算法 |
| **Context** | 上下文，持有策略引用，委托策略执行算法 |

### 2. 生活比喻

**Context = 出行者**，**Strategy = 交通方式**：
1. 出行者选择交通方式（设置策略）
2. 近距离 → 骑自行车；中距离 → 开车；远距离 → 坐飞机
3. 出行方式可以随时切换，出行者本身不需要改变

**本质**：将"做什么"和"怎么做"分离，算法可以自由切换。

### 3. 适用场景

| 场景 | 说明 |
| ---- | ---- |
| 排序算法选择 | 不同场景选择不同排序策略 |
| 压缩算法选择 | ZIP/GZIP/LZ4等算法切换 |
| 支付方式选择 | 微信/支付宝/银行卡等支付切换 |
| 路径规划 | 步行/驾车/公交不同路线策略 |

### 4. 策略模式实现

**头文件** **`strategy.h`：**

```c
 * ============================================================
 * 文件: strategy.h

 * 特点：

    SortStrategy strategy;
    const char *strategy_name;

 * @brief 创建排序上下文

 * @param name 策略名称
 */
void sort_context_set_strategy(SortContext *ctx, SortStrategy strategy, const char *name);

 * @param ctx 排序上下文
 * @param arr 待排序数组
 * @param n 数组长度

/**

/* ==================== 具体策略声明 ==================== */

void quick_sort(int *arr, size_t n);
```

**实现文件** **`strategy.c`：**

```c
/*
 * ============================================================
 * 文件: strategy.c
 * 描述: 策略模式实现 - 排序策略
 * ============================================================
 */

#include "strategy.h"
#include <stdlib.h>
#include <string.h>

/* ==================== 上下文操作 ==================== */

SortContext* sort_context_create(SortStrategy strategy, const char *name) {
    SortContext *ctx = malloc(sizeof(SortContext));
    if (ctx) {
        ctx->strategy = strategy;
        ctx->strategy_name = name;
    }
    return ctx;
}

void sort_context_set_strategy(SortContext *ctx, SortStrategy strategy, const char *name) {
    if (ctx) {
        ctx->strategy = strategy;
        ctx->strategy_name = name;
    }
}

void sort_context_execute(SortContext *ctx, int *arr, size_t n) {
    if (ctx && ctx->strategy) {
        printf("使用策略: %s\n", ctx->strategy_name);
        ctx->strategy(arr, n);
    }
}

void sort_context_destroy(SortContext *ctx) {
    free(ctx);
}

/* ==================== 具体策略：冒泡排序 ==================== */

void bubble_sort(int *arr, size_t n) {
    for (size_t i = 0; i < n - 1; i++) {
        for (size_t j = 0; j < n - 1 - i; j++) {
            if (arr[j] > arr[j + 1]) {
                int temp = arr[j];
                arr[j] = arr[j + 1];
                arr[j + 1] = temp;
            }
        }
    }
}

/* ==================== 具体策略：快速排序 ==================== */

static int partition(int *arr, int low, int high) {
    int pivot = arr[high];
    int i = low - 1;
    for (int j = low; j < high; j++) {
        if (arr[j] <= pivot) {
            i++;
            int temp = arr[i];
            arr[i] = arr[j];
            arr[j] = temp;
        }
    }
    int temp = arr[i + 1];
    arr[i + 1] = arr[high];
    arr[high] = temp;
    return i + 1;
}

static void quick_sort_impl(int *arr, int low, int high) {
    if (low < high) {
        int pi = partition(arr, low, high);
        quick_sort_impl(arr, low, pi - 1);
        quick_sort_impl(arr, pi + 1, high);
    }
}

void quick_sort(int *arr, size_t n) {
    if (n > 0) {
        quick_sort_impl(arr, 0, (int)n - 1);
    }
}

/* ==================== 具体策略：归并排序 ==================== */

static void merge(int *arr, int *temp, int left, int mid, int right) {
    int i = left, j = mid + 1, k = left;
    while (i <= mid && j <= right) {
        if (arr[i] <= arr[j]) {
            temp[k++] = arr[i++];
        } else {
            temp[k++] = arr[j++];
        }
    }
    while (i <= mid) temp[k++] = arr[i++];
    while (j <= right) temp[k++] = arr[j++];
    for (int idx = left; idx <= right; idx++) {
        arr[idx] = temp[idx];
    }
}

static void merge_sort_impl(int *arr, int *temp, int left, int right) {
    if (left < right) {
        int mid = left + (right - left) / 2;
        merge_sort_impl(arr, temp, left, mid);
        merge_sort_impl(arr, temp, mid + 1, right);
        merge(arr, temp, left, mid, right);
    }
}

void merge_sort(int *arr, size_t n) {
    if (n > 1) {
        int *temp = malloc(n * sizeof(int));
        if (temp) {
            merge_sort_impl(arr, temp, 0, (int)n - 1);
            free(temp);
        }
    }
}
```

```c
void demo_strategy(void) {
```

### 6. 执行流程

```
1. 创建上下文 → 绑定初始策略（冒泡排序）
2. execute → 调用当前策略的排序函数
3. set_strategy → 运行时切换策略（快速排序/归并排序）
4. execute → 调用新策略的排序函数
5. 销毁上下文
```

### 7. 核心技术点

| 技术 | 说明 |
|------|------|
| **函数指针** | `SortStrategy` 类型定义，统一算法调用签名 |
| **上下文封装** | `SortContext` 持有策略引用，对外屏蔽策略细节 |
| **运行时切换** | `set_strategy` 动态更换算法，无需修改调用方 |
| **开放封闭** | 新增排序算法只需实现函数，无需修改上下文代码 |

## 5. 状态模式

状态模式允许对象在其内部状态改变时改变其行为，对象看起来似乎修改了它的类。

### 1. 核心概念

| 抽象角色 | 说明 |
| -------- | ---- |
| **State** | 状态接口，定义该状态下可执行的操作 |
| **ConcreteState** | 具体状态，实现状态对应的行为 |
| **Context** | 上下文，持有当前状态，委托状态执行操作 |

### 2. 生活比喻

**Context = 自动售货机**，**State = 机器状态**：
1. 投币前 → 等待投币状态（投币才有效）
2. 投币后 → 等待选择状态（选择商品才有效）
3. 选择后 → 出货状态（出货后回到等待投币）
4. 同一个"选择商品"操作，在不同状态下行为完全不同

**本质**：状态决定行为，状态切换时行为自动改变。

### 3. 适用场景

| 场景 | 说明 |
| ---- | ---- |
| TCP连接状态机 | CLOSED/LISTEN/SYN_SENT/ESTABLISHED等状态转换 |
| 订单状态管理 | 待支付/已支付/已发货/已完成等状态流转 |
| 游戏角色状态 | 站立/奔跑/跳跃/攻击等状态切换 |
| 工作流引擎 | 审批中/已通过/已驳回等流程状态 |

**头文件** **`state.h`：**

```c
 * ============================================================
 * 文件: state.h
 * 描述: 状态模式实现 - TCP连接状态机

 * 特点：
```

**实现文件** **`state.c`：**

```c
/*
 * ============================================================
 * 文件: state.c
 * 描述: 状态模式实现 - TCP连接状态机
 * ============================================================
 */

#include "state.h"
#include <stdlib.h>

/* ==================== 状态转换表 ==================== */

typedef struct {
    TcpState next_state;
    void (*action)(TcpConnection *conn);
} StateTransition;

/* 状态转换动作 */

static void action_listen(TcpConnection *conn) {
    printf("[%s] 开始监听端口...\n", conn->name);
}

static void action_syn_sent(TcpConnection *conn) {
    printf("[%s] 发送SYN包，等待SYN+ACK...\n", conn->name);
}

static void action_syn_rcvd(TcpConnection *conn) {
    printf("[%s] 收到SYN，发送SYN+ACK...\n", conn->name);
}

static void action_established(TcpConnection *conn) {
    printf("[%s] 连接建立！可以传输数据\n", conn->name);
}

static void action_fin_wait_1(TcpConnection *conn) {
    printf("[%s] 发送FIN包，请求关闭连接...\n", conn->name);
}

static void action_fin_wait_2(TcpConnection *conn) {
    printf("[%s] 收到ACK，等待对方FIN...\n", conn->name);
}

static void action_closing(TcpConnection *conn) {
    printf("[%s] 同时关闭中，等待ACK...\n", conn->name);
}

static void action_time_wait(TcpConnection *conn) {
    printf("[%s] 等待2MSL超时...\n", conn->name);
}

static void action_close_wait(TcpConnection *conn) {
    printf("[%s] 收到FIN，等待应用层关闭...\n", conn->name);
}

static void action_last_ack(TcpConnection *conn) {
    printf("[%s] 发送FIN，等待最后ACK...\n", conn->name);
}

static void action_closed(TcpConnection *conn) {
    printf("[%s] 连接已关闭\n", conn->name);
}

static void action_timeout(TcpConnection *conn) {
    printf("[%s] 超时，关闭连接\n", conn->name);
}

/* 无操作 */
static void action_none(TcpConnection *conn) {
    /* 忽略无效事件 */
}

/* 状态转换表 [当前状态][事件] = {下一状态, 动作} */
static const StateTransition transition_table[TCP_STATE_COUNT][TCP_EVENT_COUNT] = {
    /* CLOSED 状态 */
    [TCP_CLOSED] = {
        [TCP_EVT_PASSIVE_OPEN] = {TCP_LISTEN,      action_listen},
        [TCP_EVT_ACTIVE_OPEN]  = {TCP_SYN_SENT,    action_syn_sent},
    },
    /* LISTEN 状态 */
    [TCP_LISTEN] = {
        [TCP_EVT_RECV_SYN]     = {TCP_SYN_RCVD,    action_syn_rcvd},
        [TCP_EVT_CLOSE]        = {TCP_CLOSED,      action_closed},
    },
    /* SYN_SENT 状态 */
    [TCP_SYN_SENT] = {
        [TCP_EVT_RECV_SYN_ACK] = {TCP_ESTABLISHED, action_established},
        [TCP_EVT_CLOSE]        = {TCP_CLOSED,      action_closed},
    },
    /* SYN_RCVD 状态 */
    [TCP_SYN_RCVD] = {
        [TCP_EVT_RECV_ACK]     = {TCP_ESTABLISHED, action_established},
        [TCP_EVT_CLOSE]        = {TCP_FIN_WAIT_1,  action_fin_wait_1},
    },
    /* ESTABLISHED 状态 */
    [TCP_ESTABLISHED] = {
        [TCP_EVT_CLOSE]        = {TCP_FIN_WAIT_1,  action_fin_wait_1},
        [TCP_EVT_RECV_FIN]     = {TCP_CLOSE_WAIT,  action_close_wait},
    },
    /* FIN_WAIT_1 状态 */
    [TCP_FIN_WAIT_1] = {
        [TCP_EVT_RECV_ACK]     = {TCP_FIN_WAIT_2,  action_fin_wait_2},
        [TCP_EVT_RECV_FIN]     = {TCP_CLOSING,     action_closing},
        [TCP_EVT_RECV_FIN_ACK] = {TCP_TIME_WAIT,   action_time_wait},
    },
    /* FIN_WAIT_2 状态 */
    [TCP_FIN_WAIT_2] = {
        [TCP_EVT_RECV_FIN]     = {TCP_TIME_WAIT,   action_time_wait},
    },
    /* CLOSING 状态 */
    [TCP_CLOSING] = {
        [TCP_EVT_RECV_ACK]     = {TCP_TIME_WAIT,   action_time_wait},
    },
    /* TIME_WAIT 状态 */
    [TCP_TIME_WAIT] = {
        [TCP_EVT_TIMEOUT]      = {TCP_CLOSED,      action_timeout},
    },
    /* CLOSE_WAIT 状态 */
    [TCP_CLOSE_WAIT] = {
        [TCP_EVT_CLOSE]        = {TCP_LAST_ACK,    action_last_ack},
    },
    /* LAST_ACK 状态 */
    [TCP_LAST_ACK] = {
        [TCP_EVT_RECV_ACK]     = {TCP_CLOSED,      action_closed},
    },
};

/* ==================== 连接操作 ==================== */

TcpConnection* tcp_connection_create(const char *name) {
    TcpConnection *conn = malloc(sizeof(TcpConnection));
    if (conn) {
        conn->current_state = TCP_CLOSED;
        conn->name = name;
    }
    return conn;
}

void tcp_connection_handle_event(TcpConnection *conn, TcpEvent event) {
    if (!conn || event < 0 || event >= TCP_EVENT_COUNT) return;

    TcpState old_state = conn->current_state;
    const StateTransition *trans = &transition_table[old_state][event];

    /* 检查转换是否有效（下一状态不为0或动作不为none） */
    if (trans->action == NULL || trans->action == action_none) {
        printf("[%s] 状态 %s 下忽略事件 %d\n",
               conn->name, tcp_state_names[old_state], event);
        return;
    }

    printf("[%s] 状态转换: %s --事件%d--> %s\n",
           conn->name, tcp_state_names[old_state], event,
           tcp_state_names[trans->next_state]);

    /* 执行动作 */
    trans->action(conn);

    /* 切换状态 */
    conn->current_state = trans->next_state;
}

const char* tcp_connection_get_state_name(const TcpConnection *conn) {
    if (!conn || conn->current_state >= TCP_STATE_COUNT) return "UNKNOWN";
    return tcp_state_names[conn->current_state];
}

void tcp_connection_destroy(TcpConnection *conn) {
    free(conn);
}
```

```c

    tcp_connection_destroy(server);
```

### 6. 执行流程

```
1. 创建连接 → 初始状态为 CLOSED
2. handle_event → 查状态转换表，执行动作，切换状态
3. 无效事件 → 忽略（当前状态下不允许该事件）
4. 三次握手: CLOSED → SYN_SENT → ESTABLISHED
5. 四次挥手: ESTABLISHED → FIN_WAIT_1 → FIN_WAIT_2 → TIME_WAIT → CLOSED
```

### 7. 核心技术点

| 技术 | 说明 |
|------|------|
| **枚举状态** | `TcpState` 枚举定义所有可能状态 |
| **状态转换表** | 二维数组 `[状态][事件]` 映射到下一状态和动作 |
| **函数指针** | 转换表中嵌入动作函数指针，进入状态时自动执行 |
| **表驱动** | 状态逻辑数据化，避免大量 if-else 分支 |

## 6. 装饰器模式

装饰器模式动态地给对象添加额外的职责，比生成子类更加灵活。

### 1. 核心概念

| 抽象角色 | 说明 |
| -------- | ---- |
| **Component** | 组件接口，定义对象和装饰器的公共接口 |
| **ConcreteComponent** | 具体组件，被装饰的原始对象 |
| **Decorator** | 装饰器，持有组件引用，在委托前后添加行为 |
| **ConcreteDecorator** | 具体装饰器，实现具体的增强功能 |

### 2. 生活比喻

**Component = 一杯奶茶**，**Decorator = 加料**：
1. 原味奶茶（基础组件）
2. +珍珠（装饰器1）
3. +椰果（装饰器2）
4. +奶盖（装饰器3）
5. 每加一层料，价格和描述都变化，但仍然是"奶茶"

**本质**：像套娃一样层层包装，每层添加新功能，核心接口不变。

### 3. 适用场景

| 场景 | 说明 |
| ---- | ---- |
| 日志装饰 | 在函数调用前后添加日志记录 |
| 权限检查 | 在操作执行前验证权限 |
| 缓存装饰 | 在计算前检查缓存，命中则直接返回 |
| I/O流包装 | 缓冲流 → 压缩流 → 加密流层层包装 |

### 4. 装饰器模式实现

**头文件** **`decorator.h`：**

```c
/*
 * ============================================================
 * 文件: decorator.h
 * 描述: 装饰器模式实现 - 数据处理器
 *
 * 特点：
 * 1. 动态添加功能
 * 2. 装饰器可任意组合
 * 3. 装饰顺序可调整
 * ============================================================
 */

#ifndef DECORATOR_H
#define DECORATOR_H

#include <stddef.h>

/* ==================== 数据处理器接口 ==================== */

/**
 * @brief 数据处理函数类型
 * @param data 输入数据
 * @param len 数据长度
 * @param out 输出缓冲区
 * @param out_len 输出长度
 * @return 0成功，-1失败
 */
typedef int (*ProcessFunc)(void *self, const char *data, size_t len,
                           char *out, size_t *out_len);

/**
 * @brief 销毁函数类型
 */
typedef void (*DestroyFunc)(void *self);

/* ==================== 处理器基类 ==================== */

typedef struct DataProcessor {
    ProcessFunc process;
    DestroyFunc destroy;
    struct DataProcessor *inner;
    const char *name;
} DataProcessor;

/* ==================== 基础处理器 ==================== */

/**
 * @brief 创建基础处理器（直接透传数据）
 * @return 处理器指针
 */
DataProcessor* base_processor_create(void);

/* ==================== 日志装饰器 ==================== */

/**
 * @brief 创建日志装饰器（在处理前后打印日志）
 * @param inner 被装饰的内部处理器
 * @return 装饰后的处理器指针
 */
DataProcessor* log_decorator_create(DataProcessor *inner);

/* ==================== 加密装饰器 ==================== */

/**
 * @brief 创建加密装饰器（简单异或加密）
 * @param inner 被装饰的内部处理器
 * @param key 加密密钥
 * @return 装饰后的处理器指针
 */
DataProcessor* encrypt_decorator_create(DataProcessor *inner, char key);

/* ==================== 压缩装饰器 ==================== */

/**
 * @brief 创建压缩装饰器（简单RLE压缩）
 * @param inner 被装饰的内部处理器
 * @return 装饰后的处理器指针
 */
DataProcessor* compress_decorator_create(DataProcessor *inner);

/* ==================== 通用操作 ==================== */

/**
 * @brief 执行数据处理链
 * @param processor 最外层处理器
 * @param data 输入数据
 * @param len 数据长度
 * @param out 输出缓冲区
 * @param out_len 输出长度
 * @return 0成功，-1失败
 */
int processor_process(DataProcessor *processor, const char *data, size_t len,
                      char *out, size_t *out_len);

/**
 * @brief 销毁整个处理链
 * @param processor 最外层处理器
 */
void processor_destroy(DataProcessor *processor);

#endif /* DECORATOR_H */
```

**实现文件** **`decorator.c`：**

```c
/*
 * ============================================================
 * 文件: decorator.c
 * 描述: 装饰器模式实现 - 数据处理器
 * ============================================================
 */

#include "decorator.h"
#include <stdlib.h>
#include <string.h>
#include <stdio.h>

/* ==================== 通用操作 ==================== */

int processor_process(DataProcessor *processor, const char *data, size_t len,
                      char *out, size_t *out_len) {
    if (!processor || !processor->process) return -1;
    return processor->process(processor, data, len, out, out_len);
}

void processor_destroy(DataProcessor *processor) {
    if (!processor) return;
    /* 先销毁内层（递归） */
    if (processor->inner) {
        processor_destroy(processor->inner);
    }
    /* 再销毁自己 */
    if (processor->destroy) {
        processor->destroy(processor);
    }
}

/* ==================== 基础处理器 ==================== */

static int base_process(void *self, const char *data, size_t len,
                        char *out, size_t *out_len) {
    /* 直接透传数据 */
    memcpy(out, data, len);
    *out_len = len;
    return 0;
}

static void base_destroy(void *self) {
    free(self);
}

DataProcessor* base_processor_create(void) {
    DataProcessor *p = malloc(sizeof(DataProcessor));
    if (p) {
        p->process = base_process;
        p->destroy = base_destroy;
        p->inner = NULL;
        p->name = "基础处理器";
    }
    return p;
}

/* ==================== 日志装饰器 ==================== */

typedef struct {
    DataProcessor base;
} LogDecorator;

static int log_process(void *self, const char *data, size_t len,
                       char *out, size_t *out_len) {
    LogDecorator *dec = (LogDecorator *)self;
    printf("[日志] >>> 开始处理，输入长度: %zu\n", len);

    /* 委托给内部处理器 */
    int result = processor_process(dec->base.inner, data, len, out, out_len);

    printf("[日志] <<< 处理完成，输出长度: %zu，结果: %s\n",
           *out_len, result == 0 ? "成功" : "失败");
    return result;
}

static void log_destroy(void *self) {
    free(self);
}

DataProcessor* log_decorator_create(DataProcessor *inner) {
    LogDecorator *dec = malloc(sizeof(LogDecorator));
    if (dec) {
        dec->base.process = log_process;
        dec->base.destroy = log_destroy;
        dec->base.inner = inner;
        dec->base.name = "日志装饰器";
    }
    return (DataProcessor *)dec;
}

/* ==================== 加密装饰器 ==================== */

typedef struct {
    DataProcessor base;
    char key;
} EncryptDecorator;

static int encrypt_process(void *self, const char *data, size_t len,
                           char *out, size_t *out_len) {
    EncryptDecorator *dec = (EncryptDecorator *)self;

    /* 先加密数据 */
    char *encrypted = malloc(len);
    if (!encrypted) return -1;
    for (size_t i = 0; i < len; i++) {
        encrypted[i] = data[i] ^ dec->key;
    }

    /* 委托给内部处理器 */
    int result = processor_process(dec->base.inner, encrypted, len, out, out_len);

    printf("[加密] 使用密钥 0x%02X 完成异或加密\n", (unsigned char)dec->key);
    free(encrypted);
    return result;
}

static void encrypt_destroy(void *self) {
    free(self);
}

DataProcessor* encrypt_decorator_create(DataProcessor *inner, char key) {
    EncryptDecorator *dec = malloc(sizeof(EncryptDecorator));
    if (dec) {
        dec->base.process = encrypt_process;
        dec->base.destroy = encrypt_destroy;
        dec->base.inner = inner;
        dec->base.name = "加密装饰器";
        dec->key = key;
    }
    return (DataProcessor *)dec;
}

/* ==================== 压缩装饰器 ==================== */

typedef struct {
    DataProcessor base;
} CompressDecorator;

static int compress_process(void *self, const char *data, size_t len,
                            char *out, size_t *out_len) {
    CompressDecorator *dec = (CompressDecorator *)self;

    /* 简单RLE压缩：连续相同字符压缩为 (字符,次数) */
    char *compressed = malloc(len * 2);
    if (!compressed) return -1;
    size_t comp_len = 0;
    size_t i = 0;

    while (i < len) {
        char current = data[i];
        size_t count = 1;
        while (i + count < len && data[i + count] == current && count < 255) {
            count++;
        }
        compressed[comp_len++] = current;
        compressed[comp_len++] = (char)count;
        i += count;
    }

    /* 委托给内部处理器 */
    int result = processor_process(dec->base.inner, compressed, comp_len, out, out_len);

    printf("[压缩] RLE压缩: %zu字节 -> %zu字节\n", len, comp_len);
    free(compressed);
    return result;
}

static void compress_destroy(void *self) {
    free(self);
}

DataProcessor* compress_decorator_create(DataProcessor *inner) {
    CompressDecorator *dec = malloc(sizeof(CompressDecorator));
    if (dec) {
        dec->base.process = compress_process;
        dec->base.destroy = compress_destroy;
        dec->base.inner = inner;
        dec->base.name = "压缩装饰器";
    }
    return (DataProcessor *)dec;
}
```

### 5. 装饰器模式使用示例

```c
void demo_decorator(void) {
    char input[] = "AAAAAABBBCCDDDD";
    char output[256] = {0};
    size_t out_len = 0;
    size_t input_len = strlen(input);

    /* 方案1：仅基础处理器 */
    printf("===== 方案1：仅基础处理器 =====\n");
    DataProcessor *p1 = base_processor_create();
    processor_process(p1, input, input_len, output, &out_len);
    printf("输出长度: %zu\n\n", out_len);
    processor_destroy(p1);

    /* 方案2：基础 + 日志装饰 */
    printf("===== 方案2：基础 + 日志装饰 =====\n");
    DataProcessor *p2 = log_decorator_create(base_processor_create());
    processor_process(p2, input, input_len, output, &out_len);
    printf("\n");
    processor_destroy(p2);

    /* 方案3：基础 + 加密 + 日志（加密在内，日志在外） */
    printf("===== 方案3：基础 + 加密 + 日志 =====\n");
    DataProcessor *p3 = log_decorator_create(
        encrypt_decorator_create(
            base_processor_create(), 0x55
        )
    );
    processor_process(p3, input, input_len, output, &out_len);
    printf("\n");
    processor_destroy(p3);

    /* 方案4：基础 + 压缩 + 加密 + 日志（全装饰器组合） */
    printf("===== 方案4：基础 + 压缩 + 加密 + 日志 =====\n");
    DataProcessor *p4 = log_decorator_create(
        encrypt_decorator_create(
            compress_decorator_create(
                base_processor_create()
            ), 0xAA
        )
    );
    processor_process(p4, input, input_len, output, &out_len);
    printf("\n");
    processor_destroy(p4);

    /* 方案5：调整装饰顺序 - 压缩在外，加密在内 */
    printf("===== 方案5：基础 + 加密 + 压缩 + 日志（不同顺序）=====\n");
    DataProcessor *p5 = log_decorator_create(
        compress_decorator_create(
            encrypt_decorator_create(
                base_processor_create(), 0xAA
            )
        )
    );
    processor_process(p5, input, input_len, output, &out_len);
    processor_destroy(p5);
}
```

### 6. 执行流程

```
1. 创建基础处理器 → 透传数据
2. 用装饰器包装 → 每层添加 inner 指向下一层
3. process 调用 → 从外层开始，每层先做自己的事，再委托给 inner
4. 递归处理 → 像剥洋葱一样，从外到内逐层执行
5. destroy → 递归销毁，从外到内逐层释放
```

### 7. 装饰器链的调用顺序

```
日志装饰器.process()
  ├── 打印 "开始处理"
  ├── 加密装饰器.process()
  │     ├── 异或加密数据
  │     ├── 压缩装饰器.process()
  │   │     ├── RLE压缩数据
  │   │     └── 基础处理器.process() → 透传
  │     └── 打印 "加密完成"
  └── 打印 "处理完成"
```

### 8. 核心技术点

| 技术 | 说明 |
|------|------|
| **嵌套结构体** | 装饰器内嵌 `DataProcessor` 基类，实现多态 |
| **inner指针** | 每层装饰器持有内层处理器引用，形成链式结构 |
| **函数指针链** | 每层 `process` 先执行自身逻辑，再委托给 `inner->process` |
| **递归销毁** | `processor_destroy` 递归调用，从外到内逐层释放 |

## 7. 设计模式总结

### 1. 六种模式对比

| 模式        | 核心思想    | 适用场景        | 优点        | C语言实现方式 |
| --------- | ------- | ----------- | --------- | -------- |
| **单例模式**  | 确保唯一实例  | 全局配置、资源管理   | 全局访问、节省资源 | 静态指针+延迟初始化 |
| **工厂模式**  | 封装对象创建  | 对象创建复杂、需要解耦 | 解耦、易于扩展   | 函数指针表+注册机制 |
| **观察者模式** | 发布-订阅机制 | 事件通知、状态监控   | 解耦、支持多订阅者 | 虚函数表+动态数组 |
| **策略模式**  | 封装算法族   | 算法切换、策略选择   | 算法独立变化    | 函数指针+上下文结构体 |
| **状态模式**  | 状态驱动行为  | 状态机、状态流转    | 消除条件分支    | 枚举+状态转换表+函数指针 |
| **装饰器模式** | 动态添加职责  | 功能增强、层层包装   | 比继承更灵活    | 嵌套结构体+inner指针链 |
