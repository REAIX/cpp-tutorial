## 1. const 正确性

### 1. 为什么需要 const

`const` 是 C++ 中表达"不可变"语义的核心机制。正确使用 `const` 可以：

1. **防止意外修改**：编译器帮你检查，不该改的值不会被修改
2. **表达设计意图**：让代码的读者一眼看出哪些东西是不可变的
3. ** enabling 优化**：编译器可以根据 `const` 做更好的优化
4. **接口契约**：函数参数加 `const`，告诉调用者"我不会修改你的数据"

> 📌 **核心原则**：能用 `const` 就用 `const`，这是 C++ 程序员的基本素养。

### 2. const 变量

```cpp
const int maxCount = 100;       // 必须初始化
maxCount = 200;                 // ❌ 编译错误：不能修改 const 变量

const std::string appName = "MyApp";

// const 替代宏定义
const double PI = 3.14159265;   // ✅ 有类型检查，有作用域
#define PI 3.14159265           // ❌ 无类型检查，无作用域，文本替换
```

> 💡 **通俗理解**：`const` 变量就像"刻在石头上的字"，一旦刻好就不能再改。

### 3. const 与指针

`const` 与指针的组合是初学者最容易混淆的部分。关键在于理解 `const` 修饰的是谁：

```cpp
// 1. 指向 const 的指针（pointer to const）
//    指针指向的数据不可变，但指针本身可以指向别处
const int* p1 = &value;     // *p1 不可修改，p1 可以修改
int const* p2 = &value;     // 等价写法（const 在 * 左边都一样）

*p1 = 10;                   // ❌ 不能通过 p1 修改指向的值
p1 = &anotherValue;         // ✅ 可以让 p1 指向别处

// 2. const 指针（const pointer）
//    指针本身不可变，但指向的数据可以修改
int* const p3 = &value;     // p3 不可修改，*p3 可以修改

*p3 = 10;                   // ✅ 可以通过 p3 修改指向的值
p3 = &anotherValue;         // ❌ 不能让 p3 指向别处

// 3. 指向 const 的 const 指针
//    指针和指向的数据都不可变
const int* const p4 = &value;

*p4 = 10;                   // ❌ 不能修改值
p4 = &anotherValue;         // ❌ 不能修改指针
```

> 💡 **记忆技巧**：从右往左读，`const` 修饰它左边最近的东西。
> - `const int* p` → p is a pointer to int that is const
> - `int* const p` → p is a const pointer to int
> - `const int* const p` → p is a const pointer to int that is const

### 4. const 引用

`const` 引用是最常用的 `const` 形式之一，尤其在函数参数中：

```cpp
int value = 42;
const int& ref = value;      // ref 是 value 的 const 引用

ref = 100;                   // ❌ 不能通过 const 引用修改
value = 100;                 // ✅ 可以直接修改原变量

// const 引用可以绑定到右值
const int& r1 = 42;          // ✅ const 引用延长临时对象的生命周期
int& r2 = 42;                // ❌ 非const引用不能绑定到右值

// 函数参数：避免拷贝，同时承诺不修改
void printVector(const std::vector<int>& vec) {
    // vec 不能被修改，调用者放心传入
    for (const auto& elem : vec) {
        std::cout << elem << " ";
    }
}
```

> 📌 **最佳实践**：函数参数中，基本类型按值传递，自定义类型按 `const` 引用传递。

### 5. const 成员函数

`const` 成员函数承诺不会修改对象的成员变量：

```cpp
class BankAccount {
private:
    double balance;

public:
    BankAccount(double b) : balance(b) {}

    // const 成员函数：承诺不修改对象状态
    double getBalance() const {
        return balance;       // ✅ 只读访问
    }

    // 非 const 成员函数：会修改对象状态
    void deposit(double amount) {
        balance += amount;    // ✅ 修改成员变量
    }

    // ❌ const 成员函数中不能修改成员变量
    // void badFunc() const { balance = 0; }  // 编译错误
};

// const 对象只能调用 const 成员函数
const BankAccount account(1000.0);
account.getBalance();         // ✅ 可以调用 const 成员函数
// account.deposit(500);      // ❌ 不能调用非 const 成员函数
```

> ⚠️ **注意**：`const` 对象只能调用 `const` 成员函数。如果你忘记给 getter 加 `const`，`const` 对象就无法使用它。

### 6. mutable 关键字

`mutable` 允许在 `const` 成员函数中修改特定成员变量，用于"逻辑上不变但物理上可变"的场景：

```cpp
class Cache {
private:
    std::string data;
    mutable bool cached;        // mutable：即使在 const 函数中也可修改
    mutable std::string cache;

public:
    Cache(const std::string& d) : data(d), cached(false) {}

    // 逻辑上是 const 操作（不改变外部可见状态）
    // 但内部可能需要更新缓存
    const std::string& getData() const {
        if (!cached) {
            cache = expensiveProcess(data);  // ✅ mutable 成员可以在 const 函数中修改
            cached = true;
        }
        return cache;
    }

private:
    std::string expensiveProcess(const std::string& input) const {
        return "processed: " + input;
    }
};
```

> 📌 **`mutable` 的典型使用场景**：
> - 缓存（`cache`）：计算结果缓存，不影响逻辑状态
> - 计数器（`counter`）：统计函数调用次数，用于调试/性能分析
> - 互斥锁（`mutex`）：多线程中的锁，需要在 `const` 函数中加锁

### 7. const 总结表

| 用法 | 含义 | 示例 |
| --- | --- | --- |
| `const T` | 不可变的 `T` 类型变量 | `const int x = 10;` |
| `const T*` | 指向 `const T` 的指针 | `const int* p = &x;` |
| `T* const` | `const` 指针，指向 `T` | `int* const p = &x;` |
| `const T* const` | `const` 指针，指向 `const T` | `const int* const p = &x;` |
| `const T&` | `const T` 的引用 | `const int& r = x;` |
| `void f() const` | 不修改对象状态的成员函数 | `int getX() const;` |
| `mutable T` | 在 `const` 函数中仍可修改的成员 | `mutable int cache;` |

## 2. 类型转换

### 1. 为什么避免 C 风格转换

C 风格的类型转换 `(Type)value` 存在严重问题：

```cpp
int x = 42;
double d = (double)x;              // C 风格：什么都能转，太危险

// C 风格转换可能悄悄做了你不想做的事
const int* p = &x;
int* q = (int*)p;                  // ❌ 静默去掉了 const，非常危险！
*q = 100;                          // 修改了原本 const 的值
```

> ⚠️ **C 风格转换的问题**：
> - 可以组合多种转换（`const_cast` + `reinterpret_cast`），极其危险
> - 在代码中难以搜索和审查
> - 不表达转换的意图

### 2. C++ 四种具名转换

C++ 提供了四种具名类型转换运算符，每种都有明确的用途：

| 转换运算符 | 用途 | 安全性 | 典型场景 |
| --- | --- | --- | --- |
| `static_cast` | 相关类型之间的转换 | 较安全 | 数值转换、上行转换 |
| `dynamic_cast` | 多态类型的安全下行转换 | 安全（运行时检查） | 多态继承层次 |
| `const_cast` | 添加/移除 `const` 或 `volatile` | 危险 | 与 `const` 不正确的 API 交互 |
| `reinterpret_cast` | 底层位模式的重新解释 | 极危险 | 序列化、硬件交互 |

### 3. static_cast

`static_cast` 是最常用的转换，用于相关类型之间的转换，在编译时检查：

```cpp
// 1. 数值类型转换
int i = 42;
double d = static_cast<double>(i);     // int → double，安全
int j = static_cast<int>(3.14);        // double → int，截断（有警告）

// 2. 上行转换（派生类 → 基类），安全
class Base { public: virtual ~Base() = default; };
class Derived : public Base {};

Derived derived;
Base* basePtr = static_cast<Base*>(&derived);   // ✅ 安全

// 3. 下行转换（基类 → 派生类），不保证安全
Base* b = new Derived();
Derived* d = static_cast<Derived*>(b);  // ⚠️ 编译通过，但运行时不安全
                                        // 如果 b 实际不是 Derived*，行为未定义

// 4. void* 与其他指针类型转换
void* vp = &i;
int* ip = static_cast<int*>(vp);        // ✅ 合理使用
```

> 📌 **原则**：能用 `static_cast` 解决的，就不要用其他三种转换。

### 4. dynamic_cast

`dynamic_cast` 用于多态类型的安全下行转换，依赖运行时类型信息（RTTI）：

```cpp
class Base { public: virtual ~Base() = default; };
class DerivedA : public Base { public: void funcA() { std::cout << "A\n"; } };
class DerivedB : public Base { public: void funcB() { std::cout << "B\n"; } };

void process(Base* basePtr) {
    // 指针版本：转换失败返回 nullptr
    DerivedA* a = dynamic_cast<DerivedA*>(basePtr);
    if (a) {
        a->funcA();        // 安全调用
    } else {
        std::cout << "Not a DerivedA\n";
    }

    // 引用版本：转换失败抛出 std::bad_cast
    try {
        DerivedB& b = dynamic_cast<DerivedB&>(*basePtr);
        b.funcB();
    } catch (const std::bad_cast& e) {
        std::cout << "Not a DerivedB: " << e.what() << "\n";
    }
}
```

> ⚠️ **注意**：
> - `dynamic_cast` 要求基类有虚函数（多态类型）
> - 有运行时开销（RTTI 查找）
> - 指针转换失败返回 `nullptr`，引用转换失败抛出 `std::bad_cast`
> - 频繁使用 `dynamic_cast` 可能意味着设计有问题，考虑虚函数替代

### 5. const_cast

`const_cast` 唯一合法的用途是添加或移除 `const` / `volatile` 限定符：

```cpp
// 合法用途：与 const 不正确的 C API 交互
void legacyCFunction(char* str);  // C 函数，不会修改 str，但参数没加 const

void wrapper(const std::string& s) {
    // legacyCFunction 实际不修改数据，但签名不正确
    legacyCFunction(const_cast<char*>(s.c_str()));  // 勉强可以
}

// ❌ 危险用法：修改原本确实是 const 的对象
const int value = 42;
int* p = const_cast<int*>(&value);
*p = 100;                    // ❌ 未定义行为！value 可能存储在只读内存中
```

> 📌 **原则**：`const_cast` 只用于与 `const` 不正确的 API 交互，永远不要用它来修改原本就是 `const` 的对象。

### 6. reinterpret_cast

`reinterpret_cast` 是最危险的转换，直接重新解释底层位模式：

```cpp
// 1. 指针与整数互转（序列化、硬件地址）
int x = 42;
uintptr_t addr = reinterpret_cast<uintptr_t>(&x);  // 指针 → 整数

// 2. 不相关指针类型转换
char* buffer = new char[4];
int* intPtr = reinterpret_cast<int*>(buffer);  // 将 char 缓冲区当作 int 使用

// 3. 函数指针转换（极危险）
typedef void (*FuncType)();
FuncType f = reinterpret_cast<FuncType>(0x1000);  // ❌ 硬编码地址，极不可移植
```

> ⚠️ **警告**：`reinterpret_cast` 几乎总是设计缺陷的信号。只有在与硬件、序列化等底层操作交互时才考虑使用，且必须确保类型大小和对齐匹配。

### 7. 类型转换选择流程

```
需要类型转换？
  │
  ├─ 相关类型（数值、继承层次）→ static_cast
  │
  ├─ 多态下行转换（需要安全检查）→ dynamic_cast
  │
  ├─ 需要去掉/添加 const → const_cast
  │
  └─ 底层位模式重新解释 → reinterpret_cast（三思而后行！）
```

## 3. static 关键字

### 1. static 的四种用法

`static` 在 C++ 中有四种不同的含义，取决于使用的上下文：

| 用法 | 作用域 | 生命周期 | 典型场景 |
| --- | --- | --- | --- |
| 局部静态变量 | 函数内 | 程序运行期间 | 计数器、延迟初始化 |
| 全局/文件静态变量/函数 | 文件内（内部链接） | 程序运行期间 | 隐藏实现细节 |
| 类静态成员变量 | 类作用域 | 程序运行期间 | 类级别的共享数据 |
| 类静态成员函数 | 类作用域 | — | 不依赖实例的工具函数 |

### 2. 局部静态变量

局部静态变量在函数内声明，但生命周期贯穿整个程序运行期，且只初始化一次：

```cpp
int generateId() {
    static int counter = 0;   // 只在第一次调用时初始化
    return ++counter;         // 后续调用保持上次的值
}

// 每次调用返回递增的 ID
generateId();  // 返回 1
generateId();  // 返回 2
generateId();  // 返回 3
```

> 💡 **通俗理解**：局部静态变量就像"记事本"，函数每次调用都能看到上次的记录，而且只在第一次使用时翻开新的一页。

局部静态变量的线程安全性：

```cpp
// C++11 保证：局部静态变量的初始化是线程安全的
// 如果多个线程同时首次调用，只有一个线程执行初始化
class Singleton {
public:
    static Singleton& getInstance() {
        static Singleton instance;  // ✅ 线程安全的懒汉式单例
        return instance;
    }

private:
    Singleton() = default;
    Singleton(const Singleton&) = delete;
    Singleton& operator=(const Singleton&) = delete;
};
```

> 📌 **最佳实践**：利用局部静态变量的线程安全初始化实现单例模式，比手动加锁更简洁高效。

### 3. 全局/文件静态（内部链接）

在全局作用域使用 `static`，变量或函数具有内部链接性，只在当前翻译单元（.cpp 文件）可见：

```cpp
// ===== utils.cpp =====
static int internalCounter = 0;       // 只在 utils.cpp 中可见

static void helperFunction() {        // 只在 utils.cpp 中可见
    internalCounter++;
}

// ===== main.cpp =====
extern int internalCounter;           // ❌ 链接错误：找不到，因为 static 限制了可见性
```

> 📌 **现代 C++ 替代方案**：推荐使用匿名命名空间替代文件级 `static`：
> ```cpp
> namespace {
>     int internalCounter = 0;        // 等价于 static，但更通用
>     void helperFunction() {}
> }
> ```

### 4. 类静态成员变量

静态成员变量属于类，不属于任何实例，所有对象共享同一份数据：

```cpp
class Employee {
private:
    std::string name;
    int id;
    static int totalEmployees;        // 声明（类内）

public:
    Employee(const std::string& n) : name(n), id(++totalEmployees) {}

    static int getCount() {           // 静态成员函数
        return totalEmployees;
    }
};

// 定义（类外），必须在类外初始化
int Employee::totalEmployees = 0;

// 使用
Employee e1("Alice");
Employee e2("Bob");
Employee::getCount();                 // 返回 2
```

C++17 引入了 `inline` 静态成员变量，可以在类内直接初始化：

```cpp
class Config {
public:
    inline static const std::string appName = "MyApp";    // C++17：类内定义
    inline static int maxConnections = 100;                // C++17：类内定义
};
```

### 5. 类静态成员函数

静态成员函数不依赖对象实例，没有 `this` 指针：

```cpp
class MathUtils {
public:
    // 静态成员函数：不依赖对象实例
    static double square(double x) { return x * x; }
    static double distance(double x1, double y1, double x2, double y2) {
        double dx = x2 - x1;
        double dy = y2 - y1;
        return std::sqrt(square(dx) + square(dy));
    }

private:
    int instanceData;                // 非静态成员
    static void helper();            // ✅ 静态函数可以调用静态函数
    // static void badHelper() { instanceData = 0; }  // ❌ 不能访问非静态成员
};

// 调用方式
double d = MathUtils::distance(0, 0, 3, 4);  // 不需要创建对象
```

> ⚠️ **注意**：
> - 静态成员函数没有 `this` 指针
> - 静态成员函数不能访问非静态成员变量/函数
> - 静态成员函数不能是 `virtual` 的
> - 静态成员函数不能是 `const` 的（`const` 修饰的是 `this` 指向的对象）

### 6. static 使用总结

| 场景 | 推荐做法 |
| --- | --- |
| 函数内需要持久状态 | 局部 `static` 变量 |
| 限制全局变量/函数可见性 | 匿名命名空间（优于文件级 `static`） |
| 类级别的共享数据 | `static` 成员变量 |
| 不依赖实例的工具函数 | `static` 成员函数 |
| 单例模式 | 局部 `static` + 引用返回 |

## 4. explicit 关键字

### 1. 隐式转换的问题

C++ 允许编译器在某些情况下自动进行隐式类型转换，这可能导致意想不到的行为：

```cpp
class String {
private:
    std::string data;

public:
    // 没有 explicit，允许隐式转换
    String(const char* str) : data(str) {}

    int length() const { return data.size(); }
};

void printLength(const String& s) {
    std::cout << s.length() << std::endl;
}

printLength("hello");    // 隐式转换：const char* → String
                          // 看起来方便，但可能导致难以发现的 bug
```

更危险的例子：

```cpp
class Timer {
public:
    Timer(int seconds) : duration(seconds) {}
private:
    int duration;
};

void startTimer(const Timer& t) {}

startTimer(10);    // 你真的想创建一个 10 秒的定时器吗？
                   // 还是这是一个拼写错误？
```

### 2. explicit 禁止隐式转换

`explicit` 关键字告诉编译器：这个构造函数/转换运算符必须显式调用，不允许隐式转换：

```cpp
class String {
private:
    std::string data;

public:
    explicit String(const char* str) : data(str) {}

    int length() const { return data.size(); }
};

void printLength(const String& s) {
    std::cout << s.length() << std::endl;
}

printLength("hello");                // ❌ 编译错误：不允许隐式转换
printLength(String("hello"));        // ✅ 显式构造
printLength(static_cast<String>("hello"));  // ✅ 显式转换
```

### 3. explicit 与多参数构造函数

C++98 中 `explicit` 只能用于单参数构造函数。C++11 扩展了 `explicit` 的适用范围：

```cpp
class Point {
public:
    int x, y;

    // C++11：explicit 可用于多参数构造函数
    explicit Point(int x, int y) : x(x), y(y) {}
};

Point p1(1, 2);                      // ✅ 直接初始化
// Point p2 = {1, 2};               // ❌ C++11 中 explicit 禁止拷贝列表初始化
Point p3{1, 2};                      // ✅ C++11 中直接列表初始化仍允许（但 C++14 起也禁止）
```

### 4. explicit 转换运算符

C++11 引入了 `explicit` 转换运算符：

```cpp
class SmartBool {
private:
    bool value;

public:
    SmartBool(bool v) : value(v) {}

    // 非 explicit：允许隐式转换
    // operator bool() const { return value; }  // 危险！

    // explicit：禁止隐式转换，但允许条件上下文
    explicit operator bool() const { return value; }
};

SmartBool sb(true);
if (sb) {                            // ✅ 条件上下文中允许
    std::cout << "true\n";
}

int n = sb;                          // ❌ 禁止隐式转换为 int
bool b = sb;                         // ❌ 禁止隐式转换为 bool
bool b2 = static_cast<bool>(sb);     // ✅ 显式转换
```

> 📌 **最佳实践**：
> - 单参数构造函数几乎总是应该加 `explicit`
> - 布尔转换运算符应该加 `explicit`（避免"安全布尔问题"）
> - 只有在明确需要隐式转换时才不加 `explicit`（如 `string(const char*)`）

## 5. RAII资源管理

### 1. 什么是RAII

RAII（Resource Acquisition Is Initialization，资源获取即初始化）是C++中管理资源的核心技术。其基本思想是：

1. **资源获取**：在构造函数中获取资源（内存、文件句柄、锁等）
2. **资源释放**：在析构函数中释放资源
3. **自动管理**：利用栈对象的生命周期自动管理资源

### 2. 基本示例

```cpp
class FileHandle {
private:
    FILE* file;

public:
    FileHandle(const char* filename, const char* mode)
        : file(fopen(filename, mode)) {
        if (!file) throw std::runtime_error("Cannot open file");
    }

    ~FileHandle() {
        if (file) fclose(file);
    }

    // 禁止拷贝
    FileHandle(const FileHandle&) = delete;
    FileHandle& operator=(const FileHandle&) = delete;

    // 允许移动
    FileHandle(FileHandle&& other) noexcept : file(other.file) {
        other.file = nullptr;
    }

    void write(const char* data) {
        fputs(data, file);
    }
};

// 使用：资源自动管理
{
    FileHandle fh("test.txt", "w");
    fh.write("Hello, RAII!");
}  // 离开作用域时自动调用析构函数，关闭文件
```

### 3. RAII的优势

| 优势 | 说明 |
| --- | --- |
| **异常安全** | 异常发生时，栈展开会自动调用析构函数释放资源 |
| **简化代码** | 不需要手动调用释放函数，减少遗漏 |
| **确定性释放** | 离开作用域时立即释放，不依赖垃圾回收 |
| **资源封装** | 资源管理逻辑集中在一处，易于维护 |

### 4. 异常安全的RAII

```cpp
void processData() {
    FileHandle fh("data.txt", "r");  // 获取资源
    std::vector<int> data(1000000); // 可能抛出std::bad_alloc
    // 如果上面抛出异常，fh的析构函数仍会被调用
    // 文件资源正确释放，不会泄漏
}
```

### 5. RAII的常见应用

| 资源类型 | RAII封装 | 标准库实现 |
| --- | --- | --- |
| 动态内存 | 智能指针 | `std::unique_ptr`、`std::shared_ptr` |
| 文件 | 文件句柄类 | `std::fstream` |
| 互斥锁 | 锁守卫 | `std::lock_guard`、`std::unique_lock` |
| 线程 | 线程对象 | `std::thread` |
| 套接字 | Socket封装类 | ASIO库 |

> 📌 **核心规则**：任何需要手动释放的资源，都应该用RAII封装

## 6. Rule of Five/Three

### 1. Rule of Three（C++98）

如果一个类需要自定义以下三个函数中的任何一个，通常需要同时定义全部三个：

1. **析构函数**（Destructor）
2. **拷贝构造函数**（Copy Constructor）
3. **拷贝赋值运算符**（Copy Assignment Operator）

### 2. Rule of Five（C++11）

C++11引入移动语义后，Rule of Three扩展为Rule of Five，增加了：

4. **移动构造函数**（Move Constructor）
5. **移动赋值运算符**（Move Assignment Operator）

### 3. Rule of Five 完整示例

```cpp
class Resource {
private:
    int* data;
    size_t size;

public:
    // 构造函数
    Resource(size_t s) : data(new int[s]), size(s) {
        std::fill(data, data + size, 0);
    }

    // 1. 析构函数
    ~Resource() { delete[] data; }

    // 2. 拷贝构造函数
    Resource(const Resource& other)
        : data(new int[other.size]), size(other.size) {
        std::copy(other.data, other.data + size, data);
    }

    // 3. 拷贝赋值运算符
    Resource& operator=(const Resource& other) {
        if (this != &other) {
            int* newData = new int[other.size];
            std::copy(other.data, other.data + other.size, newData);
            delete[] data;
            data = newData;
            size = other.size;
        }
        return *this;
    }

    // 4. 移动构造函数
    Resource(Resource&& other) noexcept
        : data(other.data), size(other.size) {
        other.data = nullptr;
        other.size = 0;
    }

    // 5. 移动赋值运算符
    Resource& operator=(Resource&& other) noexcept {
        if (this != &other) {
            delete[] data;
            data = other.data;
            size = other.size;
            other.data = nullptr;
            other.size = 0;
        }
        return *this;
    }
};
```

### 4. Rule of Zero

如果类不需要自定义任何特殊成员函数，就不要定义一个——让编译器自动生成。

```cpp
// Rule of Zero：使用标准库组件管理资源
class Person {
private:
    std::string name;  // string自动管理内存
    int age;

public:
    Person(std::string n, int a) : name(std::move(n)), age(a) {}
    // 不需要定义析构函数、拷贝/移动操作
    // 编译器自动生成的版本就能正确工作
};
```

### 总结

| 规则 | 内容 | 适用场景 |
| --- | --- | --- |
| **Rule of Zero** | 不定义任何特殊成员函数 | 成员变量自己管理资源 |
| **Rule of Three** | 定义析构、拷贝构造、拷贝赋值 | 管理原始资源，不需要移动 |
| **Rule of Five** | 定义全部五个特殊成员函数 | 管理原始资源，需要移动优化 |

> 📌 **最佳实践**：优先遵循Rule of Zero；如果需要手动管理资源，遵循Rule of Five；使用 `= default` 和 `= delete` 明确表达意图

## 7. 移动语义基础

### 1. 为什么需要移动语义

```cpp
std::vector<int> createLargeVector() {
    std::vector<int> v(1000000);
    return v;  // C++11前：拷贝整个数组（100万个元素）
               // C++11后：移动资源，仅转移内部指针
}
```

### 2. 左值与右值

| 概念 | 说明 | 示例 |
| --- | --- | --- |
| **左值（lvalue）** | 有内存地址，可以取地址 | `int x = 10;` 中的 `x` |
| **右值（rvalue）** | 临时对象，没有持久地址 | `10`、`std::move(x)` 的结果 |

### 3. std::move

```cpp
#include <utility>

std::vector<int> v1 = {1, 2, 3, 4, 5};
std::vector<int> v2 = std::move(v1);  // v1的资源被移动到v2

// v1不再持有数据，处于有效但未指定的状态
// v1.size() 可能为 0
```

> ⚠️ **注意**：`std::move` 本身并不移动任何东西，它只是将参数转换为右值引用，使得移动构造函数/移动赋值运算符可以被调用。

### 4. 移动语义的性能优势

```cpp
// 拷贝：深度复制
std::string a = "hello" + std::string(1000, ' ');
std::string b = a;  // 拷贝：分配新内存，复制所有字符

// 移动：转移所有权

```

## 8. 复制消除与RVO

### 1. 什么是复制消除

复制消除（Copy Elision）是编译器优化技术，省去不必要的拷贝/移动操作。即使这些操作有副作用（如打印日志），编译器也可能直接消除它们。

### 2. RVO（Return Value Optimization）

RVO 是最常见的复制消除场景——函数返回值优化：

```cpp
class Widget {
public:
    Widget() { std::cout << "构造\n"; }
    Widget(const Widget&) { std::cout << "拷贝构造\n"; }
    Widget(Widget&&) { std::cout << "移动构造\n"; }
    ~Widget() { std::cout << "析构\n"; }
};

// 没有 RVO：构造 → 拷贝/移动 → 析构临时对象（2次构造 + 1次析构）
// 有 RVO：直接在调用者的栈上构造（1次构造）
Widget createWidget() {
    return Widget();  // RVO：直接在调用者位置构造
}

// 命名返回值优化（NRVO）
Widget createWidgetNamed() {
    Widget w;         // 局部对象
    // ... 对 w 做一些操作
    return w;         // NRVO：直接将 w 构造在调用者位置
}

Widget w1 = createWidget();       // RVO 生效
Widget w2 = createWidgetNamed();  // NRVO 生效
// 输出（有RVO/NRVO）：仅 "构造" 一次
```

### 3. C++17 保证的复制消除

C++17 标准在特定情况下**强制要求**复制消除，不再是可选优化：

```cpp
// C++17 保证：以下情况必须消除拷贝
Widget createWidget() {
    return Widget();  // C++17：保证不调用拷贝/移动构造函数
}

// 返回纯右值（prvalue）时，C++17 保证复制消除
Widget w = Widget(Widget(Widget()));  // C++17：只构造一次
```

> 📌 **C++17 保证复制消除的条件**：返回纯右值（prvalue），即返回临时对象的表达式。NRVO（命名返回值优化）仍然是可选的。

### 4. RVO 失效的情况

```cpp
// 1. 条件分支返回不同对象
Widget createWidget(bool flag) {
    Widget a, b;
    if (flag) return a;   // NRVO 可能失效
    return b;             // 编译器不知道该在哪个位置构造
}

// 2. 返回参数
Widget process(Widget w) {
    // ... 修改 w
    return w;             // ❌ 参数不享受 NRVO
}

// 3. 返回全局/成员变量
class Manager {
    Widget member;
    Widget getWidget() {
        return member;    // ❌ 返回成员变量，不能消除
    }
};
```

### 5. 按值传递与移动

C++11 以后，按值返回局部对象即使不触发 RVO，也会优先使用移动而非拷贝：

```cpp
Widget createWidget() {
    Widget w;
    return w;  // 先尝试 NRVO
               // NRVO 失败时，调用移动构造（而非拷贝构造）
               // 因为局部变量在 return 时被当作右值处理
}
```

> 📌 **最佳实践**：放心地按值返回，编译器会自动优化。不要为了"优化"而返回引用指向局部对象（那是悬空引用）。

## 9. inline 与 constexpr

### 1. inline 关键字

`inline` 关键字建议编译器将函数体直接嵌入调用处，避免函数调用开销：

```cpp
// inline 建议（编译器可以忽略）
inline int add(int a, int b) {
    return a + b;
}

// 现代编译器会自动内联短小函数，即使没有 inline 关键字
int multiply(int a, int b) {
    return a * b;  // 编译器很可能自动内联
}
```

> ⚠️ **`inline` 的现代含义**：
> - `inline` 更重要的作用是**允许函数在头文件中定义而不违反 ODR（One Definition Rule）**
> - 编译器对内联的决策远比 `inline` 关键字重要（基于优化级别、函数大小等）
> - 类内定义的成员函数隐式为 `inline`

```cpp
// ===== header.h =====
inline void globalFunc() {   // inline 允许多个翻译单元包含同一函数定义
    // ...
}

class MyClass {
    void method() {          // 隐式 inline
        // ...
    }
};
```

### 2. constexpr 关键字

`constexpr` 比 `inline` 更强——它要求函数或变量在编译期就可求值：

```cpp
// constexpr 变量：编译期常量
constexpr int maxSize = 100;
constexpr double pi = 3.14159265;

// constexpr 函数：可以在编译期求值
constexpr int factorial(int n) {
    return (n <= 1) ? 1 : n * factorial(n - 1);
}

// 编译期计算
constexpr int f10 = factorial(10);        // ✅ 编译期求值
int arr[factorial(5)];                    // ✅ 可以用作数组大小

// 运行时也可以调用
int n;
std::cin >> n;
int result = factorial(n);                // ✅ 运行时求值（此时与普通函数无异）
```

### 3. constexpr 的演进

| 标准 | `constexpr` 函数限制 |
| --- | --- |
| **C++11** | 只能包含一条 `return` 语句（极其受限） |
| **C++14** | 允许局部变量、`if`/`for`/`while` 等控制流 |
| **C++17** | 允许 `if constexpr`、lambda |
| **C++20** | 允许动态内存分配、虚函数、`try/catch` |

```cpp
// C++14：更自由的 constexpr 函数
constexpr int fibonacci(int n) {
    if (n <= 1) return n;          // ✅ C++14 允许 if
    int a = 0, b = 1;              // ✅ C++14 允许局部变量
    for (int i = 2; i <= n; ++i) { // ✅ C++14 允许 for 循环
        int temp = a + b;
        a = b;
        b = temp;
    }
    return b;
}
```

### 4. constexpr 构造函数

`constexpr` 析构函数和构造函数使得编译期创建对象成为可能：

```cpp
class Point {
private:
    int x, y;

public:
    constexpr Point(int x, int y) : x(x), y(y) {}

    constexpr int getX() const { return x; }
    constexpr int getY() const { return y; }

    constexpr int distanceSquared() const {
        return x * x + y * y;
    }
};

constexpr Point p(3, 4);
constexpr int dist = p.distanceSquared();  // 编译期计算：25
static_assert(dist == 25, "Distance should be 25");
```

### 5. consteval（C++20）

C++20 引入 `consteval`，要求函数**必须**在编译期求值：

```cpp
// constexpr：可以在编译期求值，也可以在运行时求值
constexpr int maybeCompileTime(int n) { return n * 2; }

// consteval：必须在编译期求值
consteval int mustCompileTime(int n) { return n * 2; }

constexpr int a = maybeCompileTime(5);    // ✅ 编译期
int x = 5;
int b = maybeCompileTime(x);             // ✅ 运行时

constexpr int c = mustCompileTime(5);     // ✅ 编译期
// int d = mustCompileTime(x);           // ❌ 编译错误：x 不是编译期常量
```

### 6. inline 与 constexpr 对比

| 特性 | `inline` | `constexpr` |
| --- | --- | --- |
| 目的 | 允许头文件定义 / 建议内联 | 编译期求值 |
| 编译期保证 | 无 | 有（`constexpr` 变量保证编译期求值） |
| 运行时可用 | ✅ | ✅（`constexpr` 函数） |
| 头文件安全 | ✅ | ✅（隐式 `inline`） |
| 替代宏 | 部分 | 完全替代数值宏 |

> 📌 **最佳实践**：
> - 用 `constexpr` 替代宏定义常量
> - 能用 `constexpr` 的函数就用 `constexpr`（不影响运行时使用）
> - 不要为了"优化"而滥用 `inline`，让编译器自己决定

## 10. 友元

### 1. 友元函数

友元函数是一个非成员函数，但可以访问类的私有成员：

```cpp
class Point {
private:
    int x, y;

public:
    Point(int x, int y) : x(x), y(y) {}

    // 友元函数可以访问私有成员
    friend Point operator+(const Point& a, const Point& b) {
        return Point(a.x + b.x, a.y + b.y);
    }

    friend std::ostream& operator<<(std::ostream& os, const Point& p) {
        os << "(" << p.x << ", " << p.y << ")";
        return os;
    }
};
```

### 2. 友元类

一个类可以作为另一个类的友元，从而访问其私有成员：

```cpp
class A {
private:
    int secret;

public:
    A() : secret(42) {}
    friend class B;  // B是A的友元类
};

class B {
public:
    void revealSecret(const A& a) {
        std::cout << "Secret: " << a.secret << std::endl;  // ✅ 可以访问私有成员
    }
};
```

### 3. 友元的使用原则

| 原则 | 说明 |
| --- | --- |
| **谨慎使用** | 友元破坏封装性，只在必要时使用 |
| **运算符重载** | 需要访问私有成员的二元运算符（如 `<<`、`>>`） |
| **紧密协作的类** | 两个类高度耦合时（如迭代器与容器） |
| **避免滥用** | 能用公有接口解决的问题，就不用友元 |

> 🔗 **友元在运算符重载中的详细应用见第6章：运算符重载与友元**

## 11. 最佳实践与常见陷阱

### 1. const 相关陷阱

```cpp
// ❌ 陷阱1：忘记给 getter 加 const
class Bad {
    int value;
public:
    int getValue() { return value; }     // 非 const，const 对象无法调用
};

// ✅ 正确做法
class Good {
    int value;
public:
    int getValue() const { return value; }  // const 成员函数
};

// ❌ 陷阱2：返回内部数据的可修改引用/指针
class Container {
    std::vector<int> data;
public:
    int* getData() { return data.data(); }  // 破坏封装
};

// ✅ 正确做法：提供 const 和非 const 两个版本
class Container2 {
    std::vector<int> data;
public:
    int* getData() { return data.data(); }
    const int* getData() const { return data.data(); }
};

// ❌ 陷阱3：临时对象的 const 引用生命周期
const std::string& ref = std::string("hello");  // ✅ const 引用延长生命周期
std::string&& rref = std::string("hello");      // ✅ 右值引用也延长生命周期
// 但注意：函数返回的临时对象不能这样绑定
const std::string& bad = getString().substr(0, 3);  // ❌ substr 返回新临时对象
// 如果 getString() 返回值被销毁，bad 可能悬空
```

### 2. 类型转换陷阱

```cpp
// ❌ 陷阱1：滥用 dynamic_cast 代替虚函数
class Animal { public: virtual ~Animal() = default; };
class Dog : public Animal { public: void bark() {} };
class Cat : public Animal { public: void meow() {} };

void badSound(Animal* a) {
    if (Dog* d = dynamic_cast<Dog*>(a)) d->bark();
    else if (Cat* c = dynamic_cast<Cat*>(a)) c->meow();
    // 每添加新动物都要改这里！
}

// ✅ 正确做法：使用虚函数
class Animal2 { public: virtual ~Animal2() = default; virtual void makeSound() = 0; };
class Dog2 : public Animal2 { public: void makeSound() override { /* bark */ } };
class Cat2 : public Animal2 { public: void makeSound() override { /* meow */ } };

// ❌ 陷阱2：const_cast 修改真正的 const 对象
const int x = 10;
int* p = const_cast<int*>(&x);
*p = 20;   // ❌ 未定义行为！x 可能存储在只读内存
```

### 3. static 相关陷阱

```cpp
// ❌ 陷阱1：静态成员变量忘记在类外定义（C++17 前）
class Foo {
    static int count;  // 只是声明
};
// int Foo::count = 0;  // 必须在 .cpp 文件中定义，否则链接错误

// ❌ 陷阱2：在头文件中定义非 inline 的静态变量
// ===== header.h =====
static int counter = 0;  // 每个 include 此头文件的 .cpp 都有一份独立的 counter！
// 用 inline static 或匿名命名空间替代

// ❌ 陷阱3：静态初始化顺序问题（Static Initialization Order Fiasco）
// ===== a.cpp =====
const std::string& getConfig() {
    static std::string config = readConfigFile();  // ✅ 延迟到首次调用时初始化
    return config;
}

// ❌ 全局变量之间的初始化顺序不确定
// ===== a.cpp =====
std::string name = "Alice";           // 全局变量
// ===== b.cpp =====
extern std::string name;
std::string greeting = "Hello, " + name;  // ❌ name 可能还没初始化！
```

### 4. explicit 相关陷阱

```cpp
// ❌ 陷阱1：单参数构造函数不加 explicit
class Size {
public:
    Size(int s) : width(s), height(s) {}
    int width, height;
};

void drawRect(Size s) {}

drawRect(100);   // 隐式转换：100 → Size(100, 100)
                  // 你确定想要一个 100x100 的矩形吗？

// ✅ 加 explicit 防止意外
class Size2 {
public:
    explicit Size2(int s) : width(s), height(s) {}
    int width, height;
};

// drawRect2(100);              // ❌ 编译错误
drawRect2(Size2(100));          // ✅ 意图明确
```

### 5. RAII 与资源管理陷阱

```cpp
// ❌ 陷阱1：在析构函数中抛出异常
class BadRAII {
public:
    ~BadRAII() {
        if (!cleanup()) {
            throw std::runtime_error("cleanup failed");  // ❌ 析构函数不应抛异常
        }
    }
private:
    bool cleanup() { return false; }
};

// ✅ 正确做法：析构函数中吞掉异常或记录日志
class GoodRAII {
public:
    ~GoodRAII() noexcept {
        try {
            if (!cleanup()) {
                std::cerr << "cleanup failed\n";  // 记录日志
            }
        } catch (...) {
            // 吞掉异常，避免栈展开时 terminate
        }
    }
private:
    bool cleanup() { return false; }
};

// ❌ 陷阱2：移动后的对象使用
std::vector<int> v1 = {1, 2, 3};
std::vector<int> v2 = std::move(v1);
// v1 处于"有效但未指定"的状态
// v1[0];   // ❌ 不要访问移动后的对象
// v1.size(); // ⚠️ 可能返回 0，也可能返回原值
v1.clear();   // ✅ 可以调用，移动后的对象保证可以安全析构和赋值
v1 = {4, 5};  // ✅ 可以重新赋值
```

### 6. 核心机制最佳实践清单

| 实践 | 说明 |
| --- | --- |
| **`const` 一切能 `const` 的** | 变量、参数、返回值、成员函数 |
| **用 C++ 具名转换** | 拒绝 C 风格转换，明确转换意图 |
| **单参数构造函数加 `explicit`** | 防止意外隐式转换 |
| **遵循 Rule of Zero** | 优先使用标准库组件管理资源 |
| **析构函数不要抛异常** | 标记 `noexcept`，异常时记录日志 |
| **不要使用移动后的对象** | 移动后对象处于"有效但未指定"状态 |
| **放心按值返回** | RVO/NRVO + 移动语义让按值返回很高效 |
| **用 `constexpr` 替代宏** | 类型安全、作用域正确、可调试 |
| **局部 `static` 实现单例** | 线程安全、简洁 |
| **优先虚函数而非 `dynamic_cast`** | 避免类型切换的代码异味 |

## 12. 本章小结

### 1. 核心概念回顾

| 概念 | 说明 | 关键点 |
| --- | --- | --- |
| **`const` 正确性** | 表达不可变语义 | 变量、指针、引用、成员函数、`mutable` |
| **类型转换** | C++ 四种具名转换 | `static_cast`、`dynamic_cast`、`const_cast`、`reinterpret_cast` |
| **`static`** | 四种不同用法 | 局部静态、文件静态、类静态成员变量、类静态成员函数 |
| **`explicit`** | 禁止隐式转换 | 单参数构造函数、转换运算符 |
| **RAII** | 资源获取即初始化 | 构造获取资源，析构释放资源 |
| **Rule of Five** | 五个特殊成员函数 | 析构、拷贝构造/赋值、移动构造/赋值 |
| **Rule of Zero** | 让编译器自动生成 | 使用标准库组件管理资源 |
| **移动语义** | 资源所有权的转移 | `std::move`、右值引用 |
| **复制消除** | 编译器优化省去拷贝 | RVO/NRVO，C++17 保证 |
| **`inline`/`constexpr`** | 编译期优化 | `constexpr` 替代宏，`consteval` 强制编译期 |
| **友元** | 访问私有成员的权限 | 谨慎使用，避免破坏封装 |

### 2. 关键语法要点

1. **`const`**：从右往左读，`const` 修饰它左边最近的东西；`const` 对象只能调用 `const` 成员函数
2. **类型转换**：优先 `static_cast`，多态下行用 `dynamic_cast`，`const_cast` 只用于 API 交互，`reinterpret_cast` 极少使用
3. **`static`**：局部静态变量只初始化一次且线程安全；静态成员属于类不属于实例
4. **`explicit`**：单参数构造函数几乎总是应该加 `explicit`
5. **RAII**：用构造函数获取资源，析构函数释放资源，禁止拷贝或正确实现拷贝语义
6. **Rule of Five**：管理原始资源时需要定义全部五个特殊成员函数
7. **移动语义**：`std::move` 不移动任何东西，只是将左值转换为右值引用
8. **RVO**：放心按值返回，C++17 保证纯右值的复制消除
9. **`constexpr`**：能用就用，让编译器在编译期帮你计算
10. **友元**：友元关系不能继承，不能传递
