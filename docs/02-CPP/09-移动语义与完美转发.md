> 💡 **通俗理解 - 什么是移动语义？**

**传统拷贝 = 复印文件**

想象你要把一份100页的文件给别人：
- **拷贝**：用复印机完整复印100页 → 费时费力费纸
- **移动**：直接把原件递过去 → 瞬间完成！

**移动语义就是"直接递原件，不复印"！**

```cpp
std::vector<int> v1(1000000);  // 大容器
std::vector<int> v2 = v1;      // 拷贝：复制100万元素，慢！
std::vector<int> v3 = std::move(v1);  // 移动：只转移指针，快！
```

**完美转发 = 传话筒游戏**

想象你在玩传话筒：
- 朋友A小声说话（左值）→ 你传给B时也要小声
- 朋友C大声喊话（右值）→ 你传给D时也要大声
- **完美转发**：保持原始"音量"不变地传递

> 🔬 **抽象理解 - 移动语义的本质**：
>
> - **移动语义**：将资源所有权从一个对象转移到另一个对象，避免深拷贝
> - **右值引用**：`T&&` 是移动语义的基础，可以绑定到临时对象
> - **std::move**：不是真的"移动"，而是将左值转换为右值引用（类型转换）
> - **完美转发**：通过万能引用 `T&&` + `std::forward<T>` 保持参数的值类别
> - **核心价值**：减少不必要的内存分配和拷贝，提升性能

## 1. 值类别详解

### 1. 为什么需要理解值类别

在 C++11 之前，表达式只有简单的"左值"和"右值"之分。C++11 引入移动语义后，值类别的理解变得至关重要——它决定了对象**能否被移动**、**能否被取地址**、**生命周期如何**。

```
拷贝语义时代（C++03）：
  表达式 → 左值 or 右值（二分法，够用了）

移动语义时代（C++11起）：
  表达式 → lvalue / prvalue / xvalue（三分法，必须理解！）
```

### 2. C++11值类别

```
表达式
├── glvalue（泛左值）→ 有身份
│   ├── lvalue（左值）→ 有身份，不可移动
│   └── xvalue（亡值）→ 有身份，可移动
└── rvalue（右值）→ 可移动
    ├── xvalue（亡值）→ 有身份，可移动
    └── prvalue（纯右值）→ 无身份，可移动
```

> 💡 **两个独立属性**：
> - **有身份（has identity）**：可以确定对象的内存地址，可以通过指针或引用访问
> - **可移动（can be moved from）**：对象可以被"窃取"资源，转移后处于有效但未指定的状态

### 3. 判断方法

| 类别 | 示例 | 可取地址 | 可移动 | 生命周期 |
|------|------|---------|--------|----------|
| lvalue | `int x; x` | ✓ | ✗ | 持久，直到离开作用域 |
| prvalue | `42`, `x + y` | ✗ | ✓ | 临时，通常到完整表达式结束 |
| xvalue | `std::move(x)` | ✓ | ✓ | 持久，但资源已被标记可转移 |

```cpp
int a = 10;           // a 是 lvalue
int b = a + 5;        // a+5 是 prvalue
int&& r = std::move(a); // std::move(a) 是 xvalue
```

### 4. 常见的值类别判断

```cpp
// ===== lvalue（左值）=====
int x = 42;
x;                    // 变量名是 lvalue
std::string s = "hi";
s[0];                 // 下标运算符返回引用，是 lvalue
++x;                  // 前置++返回 lvalue
*x_ptr;               // 解引用返回 lvalue

// ===== prvalue（纯右值）=====
42;                   // 字面量（除字符串字面量外）
x + 5;                // 算术运算结果
x++;                  // 后置++返回 prvalue
std::string("hello"); // 临时对象
lambda;               // lambda 表达式

// ===== xvalue（亡值）=====
std::move(x);         // std::move 的返回值
std::forward<T>(x);   // 条件转发的返回值（当T为右值引用时）
static_cast<int&&>(x);// 显式转为右值引用
```

> ⚠️ **注意**：字符串字面量 `"hello"` 是 lvalue，因为它有存储地址且生命周期贯穿整个程序。这是初学者常犯的错误。

## 2. 右值引用

### 1. 基本用法

```cpp
int x = 10;
int& lr = x;          // 左值引用
int&& rr = 10;        // 右值引用
int&& rr2 = std::move(x);  // 将左值转为右值引用

// 右值引用延长临时对象生命周期
const std::string& ref1 = std::string("hello");  // 延长到ref1生命周期
std::string&& ref2 = std::string("world");        // 延长到ref2生命周期
```

### 2. 右值引用绑定规则

| 引用类型 | 可绑定 lvalue | 可绑定 rvalue | 典型用途 |
|---------|-------------|-------------|---------|
| `T&` | ✓ | ✗ | 修改左值 |
| `const T&` | ✓ | ✓ | 只读访问（万能只读引用） |
| `T&&` | ✗ | ✓ | 移动语义、绑定临时对象 |

### 3. 右值引用的生命周期延长

右值引用的一个重要特性：绑定到临时对象时，会延长临时对象的生命周期到引用的生命周期。

```cpp
// ❌ 危险：悬空引用
const std::string& bad_example() {
    return std::string("hello");  // 返回对局部临时对象的引用
    // 临时对象在函数返回时销毁 → 悬空引用！
}

// ✅ 正确：按值返回
std::string good_example() {
    return std::string("hello");  // RVO 或移动语义保证高效
}

// ✅ 生命周期延长：在同一个作用域内
std::string&& ref = std::string("hello");
// 临时 std::string 的生命周期被延长到 ref 的作用域结束
std::cout << ref << std::endl;  // 安全
```

### 4. 右值引用 vs const左值引用

两者都能绑定到右值，但有关键区别：

```cpp
std::string&& rref = std::string("hello");     // 可修改
const std::string& cref = std::string("world"); // 只读

rref += "!";     // ✅ OK，可以修改
// cref += "!";  // ❌ 编译错误，const 不可修改

// 右值引用的核心价值：允许"窃取"资源
void process(std::string&& s) {
    // 我们知道 s 是临时对象或被标记为可移动的
    // 可以安全地"窃取"其内部资源
    std::string stolen = std::move(s);
}
```

> 💡 **关键区别**：`const T&` 只能观察临时对象，而 `T&&` 可以修改（窃取）临时对象的资源。这就是移动语义的基础。

## 3. 移动构造与移动赋值

### 1. 为什么需要移动

```cpp
// 拷贝：深拷贝，代价大
std::vector<int> v1(1000000);
std::vector<int> v2 = v1;  // 拷贝100万个元素

// 移动：资源转移，代价小
std::vector<int> v3 = std::move(v1);  // 只转移内部指针，O(1)
```

让我们更直观地对比拷贝和移动的开销：

```
┌─────────────────────────────────────────────────────────┐
│              拷贝 vs 移动：性能对比                       │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  拷贝 std::vector<int>(1,000,000)：                     │
│  ┌──────────────────────────────────────┐               │
│  │ 1. 分配新内存（4MB）                  │               │
│  │ 2. 复制 1,000,000 个 int             │  ← 慢！      │
│  │ 3. 原对象不变                         │               │
│  └──────────────────────────────────────┘               │
│                                                         │
│  移动 std::vector<int>(1,000,000)：                     │
│  ┌──────────────────────────────────────┐               │
│  │ 1. 复制 3 个指针/值（size,capacity,  │               │
│  │    data_ptr）                         │  ← 快！      │
│  │ 2. 将源对象指针置空                    │               │
│  └──────────────────────────────────────┘               │
│                                                         │
│  性能差距：O(n) vs O(1)，n = 元素数量                    │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 2. 自定义移动操作

```cpp
class Buffer {
    size_t size_;
    int* data_;

public:
    // 构造
    explicit Buffer(size_t n) : size_(n), data_(new int[n]()) {}

    // 析构
    ~Buffer() { delete[] data_; }

    // 拷贝构造
    Buffer(const Buffer& other) : size_(other.size_), data_(new int[other.size_]) {
        std::copy(other.data_, other.data_ + size_, data_);
    }

    // 拷贝赋值
    Buffer& operator=(const Buffer& other) {
        if (this != &other) {
            delete[] data_;
            size_ = other.size_;
            data_ = new int[size_];
            std::copy(other.data_, other.data_ + size_, data_);
        }
        return *this;
    }

    // 移动构造
    Buffer(Buffer&& other) noexcept : size_(other.size_), data_(other.data_) {
        other.size_ = 0;
        other.data_ = nullptr;
    }

    // 移动赋值
    Buffer& operator=(Buffer&& other) noexcept {
        if (this != &other) {
            delete[] data_;
            size_ = other.size_;
            data_ = other.data_;
            other.size_ = 0;
            other.data_ = nullptr;
        }
        return *this;
    }
};
```

### 3. 为什么移动操作要加 noexcept

`noexcept` 不仅仅是"承诺不抛异常"，它还影响 STL 容器的行为：

```cpp
// std::vector 在扩容时，需要将旧元素移动到新内存
// 如果移动构造函数是 noexcept，vector 会使用移动
// 如果移动构造函数可能抛异常，vector 会退回到拷贝（更安全）

std::vector<Buffer> v;
v.push_back(Buffer(1000));  // 如果 Buffer 的移动构造不是 noexcept，
                             // vector 可能选择拷贝而非移动！

// noexcept 保证：让 STL 大胆使用移动而非拷贝
Buffer(Buffer&& other) noexcept;  // ← 告诉编译器：移动不会失败
```

> ⚠️ **重要**：移动操作通常只是指针交换，不会分配内存，不会失败。因此大多数移动操作都应该标记为 `noexcept`。如果你的移动操作确实可能抛异常，那就不要标记 `noexcept`，但要注意 STL 容器可能因此退回拷贝语义。

### 4. Rule of Five

如果自定义了以下任何一个，就应该定义全部五个：

1. 析构函数
2. 拷贝构造函数
3. 拷贝赋值运算符
4. 移动构造函数
5. 移动赋值运算符

```cpp
// ❌ 只定义析构和拷贝，忘记移动 → 移动会退化为拷贝！
class BadBuffer {
    size_t size_;
    int* data_;
public:
    ~BadBuffer() { delete[] data_; }
    BadBuffer(const BadBuffer& other);  // 自定义了拷贝
    // 没有移动构造 → 移动时退化为拷贝，性能损失！
};

// ✅ Rule of Five：全部定义
class GoodBuffer {
    size_t size_;
    int* data_;
public:
    ~GoodBuffer();
    GoodBuffer(const GoodBuffer& other);
    GoodBuffer& operator=(const GoodBuffer& other);
    GoodBuffer(GoodBuffer&& other) noexcept;
    GoodBuffer& operator=(GoodBuffer&& other) noexcept;
};

// ✅ Rule of Zero：完全不自定义，让编译器生成
class BestBuffer {
    std::vector<int> data_;  // 使用 RAII 成员，自动处理一切
    // 编译器自动生成正确的析构、拷贝、移动
};
```

> 💡 **Rule of Zero** 是现代 C++ 的最佳实践：如果类只使用 RAII 成员（如 `std::vector`、`std::string`、智能指针），就不需要自定义任何特殊成员函数，编译器会自动生成正确的版本。

### 5. 移动操作被隐式删除的条件

编译器不会在以下情况下生成默认的移动操作：

```cpp
// 1. 类显式声明了拷贝构造或拷贝赋值 → 移动被隐式删除
class A {
public:
    A(const A&);  // 自定义拷贝构造 → 移动构造被删除
};

// 2. 类显式声明了移动构造或移动赋值 → 其他移动操作被隐式删除
class B {
public:
    B(B&&);  // 自定义移动构造 → 移动赋值被删除
};

// 3. 类声明了析构函数 → 移动操作被隐式删除（C++11的缺陷，C++20部分修复，P1155R2）
class C {
public:
    ~C();  // 自定义析构 → 移动操作可能被删除
};

// 4. 类有不可移动的成员
class D {
    std::mutex mtx_;  // mutex 不可移动 → D 不可移动
};
```

## 4. std::move原理

### 1. std::move的实现

```cpp
// std::move 的本质：无条件的类型转换
template<typename T>
constexpr typename std::remove_reference<T>::type&&
move(T&& t) noexcept {
    return static_cast<typename std::remove_reference<T>::type&&>(t);
}

// std::move 不移动任何东西！
// 它只是一个 static_cast，将左值转为右值引用
// 真正的"移动"发生在移动构造/赋值函数中

int x = 10;
int&& r = std::move(x);  // x 仍然是有效的！
// 但语义上，x 的值已经"被转移"，不应再使用
```

### 2. std::move不移动任何东西

`std::move` 是 C++ 中最大的命名误导之一。它**不移动任何东西**，它只是一个类型转换：

```cpp
// std::move 对基本类型：什么都不会改变
int a = 42;
int b = std::move(a);  // 只是拷贝！a 的值仍然是 42
// 因为 int 没有移动构造函数，"移动" int 和拷贝 int 完全一样

// std::move 对类类型：触发移动构造/赋值
std::string s1 = "hello";
std::string s2 = std::move(s1);  // 触发 string 的移动构造
// s1 现在是有效但未指定的状态（通常为空字符串）
```

### 3. std::move的完整流程

```
┌─────────────────────────────────────────────────────────┐
│           std::move 的工作流程                           │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  1. std::move(x)                                        │
│     → 将 x 转换为右值引用（T&&）                         │
│     → x 本身没有被修改！                                 │
│                                                         │
│  2. 右值引用被用来初始化新对象或赋值                      │
│     → 匹配移动构造函数或移动赋值运算符                    │
│                                                         │
│  3. 移动构造/赋值函数执行实际的资源转移                    │
│     → 这才是真正"移动"发生的地方                         │
│                                                         │
│  结论：std::move 只是"请求移动"，不是"执行移动"          │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 4. 没有移动构造函数时的行为

```cpp
class CopyOnly {
public:
    CopyOnly() = default;
    CopyOnly(const CopyOnly&) { std::cout << "拷贝构造\n"; }
    // 没有移动构造函数！
};

CopyOnly a;
CopyOnly b = std::move(a);  // 输出：拷贝构造
// 因为没有移动构造函数，退化为拷贝构造
// std::move 只是转换了类型，但匹配不到移动构造函数
```

## 5. 万能引用与引用折叠

### 1. 万能引用（Forwarding Reference）

```cpp
// T&& 在模板推导上下文中是万能引用
template<typename T>
void foo(T&& arg) {
    // arg 可以接受左值和右值
}

int x = 10;
foo(x);          // T = int&, arg = int&
foo(10);         // T = int, arg = int&&
```

> ⚠️ **万能引用的两个必要条件**：
> 1. 类型推导必须发生（`T` 需要被推导）
> 2. 形式必须是 `T&&`（不能有 `const` 等修饰）
>
> ```cpp
> template<typename T>
> void f1(T&& arg);        // ✅ 万能引用
> void f2(int&& arg);      // ❌ 不是万能引用，T没有推导
> template<typename T>
> void f3(const T&& arg);  // ❌ 不是万能引用，有const修饰
> ```

### 2. 万能引用 vs 右值引用

```cpp
// 右值引用：只能绑定右值
void rvalue_ref(std::string&& s);  // 只接受右值

// 万能引用：可以绑定左值和右值
template<typename T>
void universal_ref(T&& s);  // 接受左值和右值

std::string x = "hello";
// rvalue_ref(x);          // ❌ 编译错误
rvalue_ref(std::move(x));  // ✅
universal_ref(x);          // ✅ T = std::string&, s = std::string&
universal_ref(std::move(x)); // ✅ T = std::string, s = std::string&&
```

### 3. 引用折叠规则

| T 的类型 | T&& 折叠结果 |
|---------|-------------|
| `int` | `int&&` |
| `int&` | `int&` |
| `int&&` | `int&&` |

引用折叠规则：只要其中一个引用是左值引用(&)，折叠结果就是左值引用；只有两个都是右值引用(&&)，折叠结果才是右值引用。即：T& & → T&、T& && → T&、T&& & → T&、T&& && → T&&

完整的引用折叠规则表：

| 模板实参 T | `T& &` | `T& &&` | `T&& &` | `T&& &&` |
|-----------|--------|---------|---------|----------|
| `int` | `int&` | `int&` | `int&` | `int&&` |
| `int&` | `int&` | `int&` | `int&` | `int&` |
| `int&&` | `int&` | `int&` | `int&` | `int&&` |

> 💡 **记忆口诀**：左值引用是"传染的"——只要有一个 `&`，结果就是 `&`。只有全是 `&&`，结果才是 `&&`。

### 4. 引用折叠发生的场景

引用折叠不仅仅在万能引用中出现，它在以下四种场景都会发生：

```cpp
// 1. 模板实例化
template<typename T>
void f(T&& arg);  // 万能引用中的折叠

// 2. auto 类型推导
int x = 10;
auto&& r1 = x;    // auto = int&, r1 = int&（左值 → 折叠为左值引用）
auto&& r2 = 10;   // auto = int, r2 = int&&（右值 → 右值引用）

// 3. typedef 和 alias
template<typename T>
using LRef = T&;
template<typename T>
using RRef = T&&;

LRef<int&>  → int&  // int& & 折叠为 int&
RRef<int&>  → int&  // int& && 折叠为 int&

// 4. decltype
int x = 10;
decltype((x))&&  → int& && 折叠为 int&
```

## 6. 完美转发

### 1. 问题

```cpp
template<typename T>
void wrapper(T&& arg) {
    // arg 始终是左值（有名字的变量都是左值）
    process(arg);  // arg是命名变量（左值），永远调用 process 的左值重载版本
}
```

这是完美转发要解决的核心问题：**命名变量是左值**，即使它原本是右值引用，一旦有了名字，就变成了左值。

```cpp
void process(int& x)  { std::cout << "左值\n"; }
void process(int&& x) { std::cout << "右值\n"; }

template<typename T>
void wrapper(T&& arg) {
    process(arg);  // 永远输出"左值"！
}

int x = 10;
wrapper(x);          // 期望：左值 ✓
wrapper(10);         // 期望：右值 ✗ 实际输出：左值！
wrapper(std::move(x)); // 期望：右值 ✗ 实际输出：左值！
```

### 2. 解决方案：std::forward

```cpp
template<typename T>
void wrapper(T&& arg) {
    process(std::forward<T>(arg));
    // 如果 arg 原本是右值 → 转发为右值
    // 如果 arg 原本是左值 → 转发为左值
}

// std::forward 的实现
template<typename T>
constexpr T&& forward(typename std::remove_reference<T>::type& t) noexcept {
    return static_cast<T&&>(t);
}
```

### 3. std::forward的工作原理

```
┌─────────────────────────────────────────────────────────┐
│           std::forward 的工作原理                         │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  当传入左值时：                                          │
│    wrapper(x) → T = int&                                │
│    std::forward<int&>(arg)                              │
│    → static_cast<int& &&>(arg)                          │
│    → static_cast<int&>(arg)  （引用折叠）                │
│    → 返回左值引用                                        │
│                                                         │
│  当传入右值时：                                          │
│    wrapper(10) → T = int                                │
│    std::forward<int>(arg)                               │
│    → static_cast<int&&>(arg)                            │
│    → 返回右值引用                                        │
│                                                         │
│  关键：T 的推导结果决定了转发方向                         │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 4. 完美转发实战

```cpp
class Widget {
public:
    template<typename T>
    void set_name(T&& name) {
        name_ = std::forward<T>(name);
    }

private:
    std::string name_;
};

Widget w;
std::string s = "hello";
w.set_name(s);              // 左值转发，调用拷贝赋值
w.set_name(std::move(s));   // 右值转发，调用移动赋值
w.set_name("world");        // 右值转发，调用移动赋值
```

### 5. 完美转发可变参数

```cpp
template<typename... Args>
void emplace(Args&&... args) {
    construct(std::forward<Args>(args)...);
}
```

更完整的示例——实现一个简单的 `make_unique`：

```cpp
template<typename T, typename... Args>
std::unique_ptr<T> my_make_unique(Args&&... args) {
    return std::unique_ptr<T>(new T(std::forward<Args>(args)...));
}

// 使用
auto p = my_make_unique<std::string>(10, 'x');  // "xxxxxxxxxx"
auto p2 = my_make_unique<std::string>("hello");
```

### 6. std::move vs std::forward

```cpp
// std::move：无条件转为右值
// std::forward：有条件地转为右值（仅当原始参数是右值时）

// 使用原则：
// 1. 当你总是想移动时 → 用 std::move
// 2. 当你想保持原始值类别时 → 用 std::forward

template<typename T>
void wrapper(T&& arg) {
    // 想要移动 arg → std::move
    auto other = std::move(arg);

    // 想要转发 arg 保持原始值类别 → std::forward
    process(std::forward<T>(arg));
}
```

> 💡 **简单记忆**：`std::move` 用于你想**主动放弃**资源的场景；`std::forward` 用于你想**忠实地传递**参数的场景。

## 7. 移动语义在STL容器中的应用

### 1. 容器的移动语义

C++11 之后，STL 容器全面支持移动语义，这带来了显著的性能提升：

```cpp
// vector 的移动：O(1) 时间
std::vector<int> v1(1000000, 42);
std::vector<int> v2 = std::move(v1);  // 只转移内部指针，瞬间完成
// v1 现在为空

// string 的移动：O(1) 时间
std::string s1 = "very long string........................";
std::string s2 = std::move(s1);  // 只转移内部指针
// s1 现在为空字符串

// map/set 的移动：O(1) 时间
std::map<int, std::string> m1 = {{1, "one"}, {2, "two"}};
std::map<int, std::string> m2 = std::move(m1);  // 只转移根节点指针
```

### 2. 容器元素的移动

```cpp
std::vector<std::string> v;

// push_back 有两个重载：
// void push_back(const T& val);   // 拷贝
// void push_back(T&& val);        // 移动

std::string s = "hello";
v.push_back(s);              // 调用拷贝版本，s 不变
v.push_back(std::move(s));   // 调用移动版本，s 变为空
v.push_back("world");        // 调用移动版本，临时 string

// emplace_back：直接在容器内构造，避免临时对象
v.emplace_back(10, 'x');     // 构造 std::string(10, 'x') = "xxxxxxxxxx"
v.emplace_back("direct");    // 构造 std::string("direct")
```

### 3. 容器扩容时的移动

```cpp
// 当 vector 扩容时，需要将旧元素迁移到新内存
// 如果元素的移动构造是 noexcept → 使用移动
// 如果元素的移动构造不是 noexcept → 使用拷贝（更安全）

class MaybeThrowOnMove {
public:
    MaybeThrowOnMove(MaybeThrowOnMove&& other)  // 没有 noexcept
        : data_(std::move(other.data_)) {}
    // vector 扩容时会退回拷贝！
};

class SafeMove {
public:
    SafeMove(SafeMove&& other) noexcept  // 有 noexcept
        : data_(std::move(other.data_)) {}
    // vector 扩容时会使用移动 ✓
private:
    std::vector<int> data_;
};
```

### 4. swap 与移动

```cpp
// std::swap 在 C++11 后使用移动语义实现
template<typename T>
void swap(T& a, T& b) {
    T tmp = std::move(a);   // 移动构造 tmp
    a = std::move(b);       // 移动赋值给 a
    b = std::move(tmp);     // 移动赋值给 b
}
// 对于大对象，比 C++03 的拷贝 swap 快得多

// 容器的 swap 更高效：O(1)
std::vector<int> a(1000000), b;
std::swap(a, b);  // 只交换内部指针，O(1)
```

## 8. RVO/NRVO与移动省略

### 1. 什么是RVO/NRVO

**RVO**（Return Value Optimization，返回值优化）和 **NRVO**（Named Return Value Optimization，命名返回值优化）是编译器的优化技术，可以完全消除拷贝/移动操作。

```cpp
// RVO：返回临时对象（纯右值）
std::string create_string() {
    return std::string("hello");  // 编译器直接在调用者的栈上构造
    // 没有拷贝，没有移动，直接构造！
}

// NRVO：返回命名对象
std::string create_string2() {
    std::string s = "hello";
    s += " world";
    return s;  // 编译器可能将 s 直接构造在调用者的栈上
    // 没有拷贝，没有移动！
}
```

### 2. C++17的保证性省略

C++17 标准规定：当返回纯右值（prvalue）时，拷贝/移动省略是**强制**的，不再是可选优化：

```cpp
struct Widget {
    Widget() { std::cout << "构造\n"; }
    Widget(const Widget&) { std::cout << "拷贝\n"; }
    Widget(Widget&&) { std::cout << "移动\n"; }
};

Widget create() {
    return Widget();  // C++17：保证无拷贝无移动
    // C++11/14：编译器可能省略（但不保证）
}

Widget w = create();  // C++17：只输出"构造"一次
```

### 3. 为什么不要对返回值使用std::move

```cpp
// ❌ 错误：对返回值使用 std::move
std::string bad_func() {
    std::string s = "hello";
    return std::move(s);  // 阻止 NRVO！
    // 编译器无法将 s 构造在调用者栈上
    // 因为 std::move(s) 是一个不同的表达式
    // 结果：强制调用移动构造函数
}

// ✅ 正确：直接返回
std::string good_func() {
    std::string s = "hello";
    return s;  // NRVO 优化：零拷贝零移动
    // 即使 NRVO 没有生效，C++11 也保证将 s 视为右值
    // 会调用移动构造（而不是拷贝构造）
}
```

> ⚠️ **重要规则**：永远不要对返回的局部变量使用 `std::move`！C++11 标准规定，当返回局部变量时，编译器会自动将其视为右值（如果找不到更好的优化）。使用 `std::move` 反而会阻止 NRVO 优化。

### 4. RVO/NRVO与移动的优先级

```
┌─────────────────────────────────────────────────────────┐
│          返回值处理的优先级（从优到劣）                    │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  1. RVO/NRVO（零开销）                                  │
│     → 直接在调用者栈上构造，完全无拷贝无移动              │
│     → C++17 对 prvalue 返回保证执行                      │
│                                                         │
│  2. 移动语义（O(1) 开销）                               │
│     → 当 RVO/NRVO 不可用时自动退回                      │
│     → 返回局部变量时，编译器自动视为右值                  │
│                                                         │
│  3. 拷贝语义（O(n) 开销）                               │
│     → 最差情况，应尽量避免                               │
│     → 仅当移动构造被删除时发生                           │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

## 9. 移动语义陷阱

### 1. 移动后使用

```cpp
std::string s = "hello";
std::string s2 = std::move(s);
// s 现在是有效但未定义状态，不应使用其值
// 但可以赋新值
s = "new value";  // OK
```

更详细的说明：

```cpp
std::vector<int> v1 = {1, 2, 3, 4, 5};
std::vector<int> v2 = std::move(v1);

// v1 的状态：有效但未指定
// 通常 v1 为空（size() == 0），但标准不保证
// 安全操作：赋值、析构
// 不安全操作：读取值、假设 size()

v1 = {10, 20};    // ✅ 安全：赋新值
v1.clear();       // ✅ 安全：清空
// int x = v1[0]; // ❌ 不安全：未指定状态
// v1.push_back(1); // ⚠️ 技术上合法，但依赖未指定状态
```

### 2. 函数返回值的移动是多余的

```cpp
std::string make_string() {
    std::string s = "hello";
    return s;           // RVO/NRVO 优化，比 std::move(s) 更好
    // return std::move(s);  // 反而阻止了RVO！
}
```

### 3. 容器中移动

```cpp
std::vector<std::string> v;
std::string s = "hello";
v.push_back(std::move(s));  // 移动到vector中，s变为空

// 但如果 vector 需要扩容，已有元素会被移动
```

### 4. 返回局部对象的引用

```cpp
// ❌ 严重错误：返回对局部变量的引用（无论左值还是右值引用）
const std::string& bad1() {
    std::string s = "hello";
    return s;  // 悬空引用！s 在函数返回时销毁
}

std::string&& bad2() {
    std::string s = "hello";
    return std::move(s);  // 悬空右值引用！
    // std::move 不会延长生命周期
}

// ✅ 正确：按值返回
std::string good() {
    std::string s = "hello";
    return s;  // RVO 或移动语义保证高效
}
```

### 5. 移动"this"指针

```cpp
class Widget {
    std::string name_;
public:
    Widget(Widget&& other) noexcept
        : name_(std::move(other.name_))  // ✅ 正确：移动成员
    {}

    // ❌ 错误：不要移动 this 指针
    // Widget(Widget&& other) noexcept
    //     : name_(std::move(this)->name_)  // 多余且令人困惑
    // {}
};

// 在成员函数中移动成员：
class Builder {
    std::string name_;
    int value_;
public:
    Builder(Builder&& other) noexcept
        : name_(std::move(other.name_))  // ✅ 移动成员
        , value_(other.value_)           // ✅ 拷贝基本类型
    {
        other.value_ = 0;  // 重置源对象状态
    }
};
```

### 6. 在条件表达式中使用移动

```cpp
// ❌ 错误：在条件表达式中移动
std::string process(bool flag) {
    std::string s = "hello";
    if (flag) {
        return std::move(s);  // 阻止 NRVO
    }
    return s;  // 可能 NRVO
}

// ✅ 正确：统一返回方式
std::string process(bool flag) {
    std::string s = "hello";
    // ... 修改 s ...
    return s;  // 编译器会处理好一切
}
```

### 7. 移动与线程安全

```cpp
// ❌ 危险：在多线程中移动
std::string shared_data = "hello";

// 线程1
std::string local = std::move(shared_data);  // 移动

// 线程2（同时）
std::cout << shared_data << std::endl;  // 数据竞争！
// shared_data 可能已经被移动，状态未定义

// ✅ 正确：使用互斥量保护
std::mutex mtx;
std::string shared_data = "hello";

// 线程1
{
    std::lock_guard<std::mutex> lock(mtx);
    std::string local = std::move(shared_data);
}

// 线程2
{
    std::lock_guard<std::mutex> lock(mtx);
    std::cout << shared_data << std::endl;  // 安全
}
```

## 10. 最佳实践

### 1. 何时使用 std::move

| 场景 | 使用 | 说明 |
|------|------|------|
| 传递局部变量给函数 | `std::move` | 最后一次使用时移动 |
| 返回局部变量 | **不用** | 依赖 RVO/NRVO |
| 将值存入容器 | `std::move` | `v.push_back(std::move(x))` |
| 转发参数给其他函数 | `std::forward` | 保持值类别 |
| 在移动构造/赋值中移动成员 | `std::move` | 移动每个成员 |
| 交换两个对象 | `std::swap` | 内部使用移动 |

### 2. 何时使用 std::forward

```cpp
// ✅ 在万能引用参数上使用 std::forward
template<typename T>
void wrapper(T&& arg) {
    target(std::forward<T>(arg));  // 保持原始值类别
}

// ❌ 不要在非万能引用上使用 std::forward
void process(std::string&& arg) {
    target(std::forward<std::string>(arg));  // 多余，直接用 std::move
    target(std::move(arg));  // 更清晰
}

// ✅ 在可变参数模板中使用 std::forward
template<typename... Args>
void emplace_back(Args&&... args) {
    container_.emplace_back(std::forward<Args>(args)...);
}
```

### 3. 移动操作的设计原则

```cpp
// 1. 移动操作应标记 noexcept
class Good {
public:
    Good(Good&& other) noexcept;            // ✅
    Good& operator=(Good&& other) noexcept; // ✅
};

// 2. 移动后对象应处于有效但未指定的状态
// - 可以安全地析构
// - 可以安全地赋值
// - 不应假设其具体值

// 3. 遵循 Rule of Five 或 Rule of Zero
// Rule of Zero（首选）：
class Best {
    std::vector<int> data_;
    std::string name_;
    // 编译器自动生成所有特殊成员函数
};

// Rule of Five（需要自定义资源管理时）：
class Custom {
    int* data_;
    size_t size_;
public:
    ~Custom();
    Custom(const Custom&);
    Custom& operator=(const Custom&);
    Custom(Custom&&) noexcept;
    Custom& operator=(Custom&&) noexcept;
};
```

### 4. 性能优化检查清单

```
┌─────────────────────────────────────────────────────────┐
│              移动语义性能检查清单                         │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  □ 自定义的类是否实现了移动操作？                        │
│    → 如果管理资源，必须实现 Rule of Five                 │
│    → 如果只用 RAII 成员，遵循 Rule of Zero               │
│                                                         │
│  □ 移动操作是否标记了 noexcept？                         │
│    → 否则 STL 容器可能退回拷贝                           │
│                                                         │
│  □ 是否对返回值使用了 std::move？                        │
│    → 立即删除！依赖 RVO/NRVO 更高效                      │
│                                                         │
│  □ 函数参数是否使用万能引用 + std::forward？             │
│    → 避免不必要的拷贝                                    │
│                                                         │
│  □ 容器操作是否优先使用 emplace 系列函数？               │
│    → emplace_back > push_back(std::move(x))              │
│                                                         │
│  □ 是否在移动后使用了源对象？                            │
│    → 移动后只应赋值或析构，不应读取                      │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 5. 常见模式速查

```cpp
// 模式1：移动构造
Widget(Widget&& other) noexcept
    : resource_(std::move(other.resource_)) {
    other.resource_ = nullptr;  // 重置源对象
}

// 模式2：移动赋值（copy-and-swap 变体）
Widget& operator=(Widget&& other) noexcept {
    if (this != &other) {
        // 释放当前资源
        delete resource_;
        // 窃取其他资源
        resource_ = other.resource_;
        other.resource_ = nullptr;
    }
    return *this;
}

// 模式3：完美转发的工厂函数
template<typename T, typename... Args>
std::unique_ptr<T> make(Args&&... args) {
    return std::unique_ptr<T>(new T(std::forward<Args>(args)...));
}

// 模式4：完美转发的 setter
template<typename T>
void set_value(T&& val) {
    value_ = std::forward<T>(val);
}

// 模式5：按值传递 + 移动（简化版完美转发）
void set_value(std::string val) {  // 按值传递
    value_ = std::move(val);       // 移动到成员
}
// 调用者传左值 → 一次拷贝 + 一次移动
// 调用者传右值 → 一次移动 + 一次移动（零拷贝）
// 比重载两个版本更简洁
```

## 11. 本章小结

| 主题 | 核心内容 |
|------|---------|
| **值类别** | lvalue（有身份不可移动）、prvalue（无身份可移动）、xvalue（有身份可移动） |
| **右值引用** | `T&&` 绑定右值，是移动语义的基础；可延长临时对象生命周期 |
| **移动语义** | 移动构造/赋值，资源转移而非深拷贝，O(n) → O(1) |
| **noexcept** | 移动操作应标记 noexcept，否则 STL 容器可能退回拷贝 |
| **Rule of Five/Zero** | 自定义资源管理时遵循 Rule of Five；否则遵循 Rule of Zero |
| **std::move** | 无条件转为右值引用，不执行移动；真正的移动发生在移动构造/赋值中 |
| **万能引用** | 模板中的 `T&&`，结合引用折叠可接受左值和右值 |
| **引用折叠** | 有 `&` 则折叠为 `&`，全 `&&` 才折叠为 `&&` |
| **完美转发** | `std::forward<T>` 有条件地转为右值，保持原始值类别 |
| **STL容器** | 全面支持移动语义，扩容时优先移动（需 noexcept） |
| **RVO/NRVO** | 返回值优化，零拷贝零移动；不要对返回值用 std::move |
| **移动后状态** | 有效但未指定，只应赋值或析构，不应读取 |
| **最佳实践** | 移动加 noexcept、返回值不用 move、优先 emplace、遵循 Rule of Zero |
