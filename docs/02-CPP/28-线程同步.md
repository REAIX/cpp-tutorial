> （Mutex, condition variables: traffic lights between threads.）

> 
> （没有同步，程序会乱套。）

---

> 💡 **通俗理解 - 为什么要线程同步？**

想象厕所只有一个坑位：
- 两个人同时冲进去 → 尴尬了！
- 需要一个"锁门"的机制

**线程同步就是"解决抢厕所"的问题！**

- **互斥量** 就像厕所的"锁"
  - 一个人进去，锁上门
  - 其他人只能在外面等
  - 出来后再开门

- **条件变量** 就像"等人叫号"
  - 线程A在等某个条件
  - 线程B满足了条件，叫A可以继续了

> 🔬 **抽象理解 - 同步与互斥的本质**：
> - **同步**：是"协调"多个线程的执行顺序，确保线程按照一定顺序执行
> - **互斥（Mutual Exclusion）**：是"排他"，同一时刻只有一个线程可以访问共享资源
> - **锁**：是实现互斥的机制，通过"加锁-访问-解锁"保护共享资源
> - **条件变量**：是"等待通知"机制，让线程可以等待某个条件满足后再继续
> - **死锁**：是"互相等待"，两个或多个线程互相持有对方需要的资源
> - **同步的本质**：是解决"竞态条件"，确保共享资源访问的一致性和正确性

## 1. 互斥量

### 1. 概念与定义

**互斥量（mutex）**：C++11引入的新特性，用于保护共享资源，避免竞态条件。互斥量可以确保同一时刻只有一个线程能访问共享资源。

**临界区（critical section）**：访问共享资源的代码段。临界区需要使用互斥量保护，避免多个线程同时访问。

**锁（lock）**：互斥量的操作，用于获取互斥量的所有权。例如`mtx.lock()`表示获取互斥量`mtx`的所有权。

**解锁（unlock）**：互斥量的操作，用于释放互斥量的所有权。例如`mtx.unlock()`表示释放互斥量`mtx`的所有权。

**死锁（deadlock）**：多个线程相互等待对方释放资源，导致所有线程都无法继续执行的问题。

**活锁（livelock）**：多个线程相互让步，导致所有线程都无法继续执行的问题。

**饥饿（starvation）**：一个线程长期无法获取锁，导致无法继续执行的问题。

**std::lock_guard**：C++11引入的新特性，用于自动管理互斥量。`std::lock_guard`在构造函数中获取锁，在析构函数中释放锁，避免忘记解锁。

**std::unique_lock**：C++11引入的新特性，用于灵活管理互斥量。`std::unique_lock`可以延迟获取锁、释放锁、转移锁所有权等。

### 2. 互斥量工作原理

```
线程A                    互斥量mtx                  线程B
  │                         │                        │
  │  lock()                 │                        │
  ├────────────────────────→│                        │
  │                         │ 状态：锁定              │
  │  访问共享资源            │                        │  lock() - 阻塞
  ├─────────────────────────┼────────────────────────┤
  │                         │                        │
  │  unlock()               │                        │  等待中...
  ├────────────────────────→│                        │
  │                         │ 状态：解锁              │
  │                         │                        │  lock() 成功
  │                         │←───────────────────────┤
  │                         │ 状态：锁定              │
  │                         │                        │  访问共享资源
  │                         │                        ├────────────────
  │                         │                        │
  │                         │                        │  unlock()
  │                         │←───────────────────────┤
  │                         │ 状态：解锁              │
  ▼                         ▼                        ▼

关键点：
- 同一时刻只有一个线程能持有锁
- 其他线程必须等待锁释放
- 保护临界区，避免数据竞争
```

### 3. 基本使用

```cpp
#include <iostream>
#include <thread>
#include <vector>
#include <mutex>

class Counter {
    int value_ = 0;
    mutable std::mutex mutex_;
    
public:
    void increment() {
        std::lock_guard<std::mutex> lock(mutex_);
        ++value_;
    }
    
    int get() const {
        std::lock_guard<std::mutex> lock(mutex_);
        return value_;
    }
};

int main() {
    Counter counter;
    std::vector<std::thread> threads;
    
    for (int i = 0; i < 10; ++i) {
        threads.emplace_back([&counter]() {
            for (int j = 0; j < 1000; ++j) {
                counter.increment();
            }
        });
    }
    
    for (auto& t : threads) {
        t.join();
    }
    
    std::cout << "Counter: " << counter.get() << "\n";  // 10000
    
    return 0;
}
```

### 4. mutex类型

| 类型 | 说明 |
|-----|------|
| `std::mutex` | 基本互斥量 |
| `std::recursive_mutex` | 递归互斥量（同一线程可多次加锁） |
| `std::timed_mutex` | 支持超时的互斥量 |
| `std::recursive_timed_mutex` | 递归+超时 |

## 2. 锁管理

### 1. lock_guard

```cpp
#include <mutex>

std::mutex mtx;

void safe_operation() {
    std::lock_guard<std::mutex> lock(mtx);
    // 临界区代码
    // 自动解锁
}
```

### 2. unique_lock

```cpp
#include <mutex>

std::mutex mtx;

void flexible_lock() {
    std::unique_lock<std::mutex> lock(mtx);
    
    // 可以手动解锁
    lock.unlock();
    
    // 可以重新加锁
    lock.lock();
    
    // 可以尝试加锁
    if (lock.try_lock()) {
        // 成功
    }
    
    // 自动解锁
}
```

### 3. scoped_lock（C++17）

```cpp
#include <mutex>

std::mutex mtx1, mtx2;

void multi_lock() {
    // 同时锁定多个互斥量，避免死锁
    std::scoped_lock lock(mtx1, mtx2);
    // 临界区代码
}
```

### 4. lock和try_lock

```cpp
#include <mutex>

std::mutex mtx1, mtx2;

void deadlock_free() {
    // 使用 std::lock 同时锁定
    std::lock(mtx1, mtx2);
    
    // 使用 adopt_lock 假设已锁定
    std::lock_guard<std::mutex> lock1(mtx1, std::adopt_lock);
    std::lock_guard<std::mutex> lock2(mtx2, std::adopt_lock);
    
    // 临界区代码
}
```

## 3. 条件变量

### 1. 生产者-消费者模型

```cpp
#include <iostream>
#include <thread>
#include <queue>
#include <mutex>
#include <condition_variable>

std::queue<int> dataQueue;
std::mutex mtx;
std::condition_variable cv;
bool finished = false;

void producer() {
    for (int i = 0; i < 10; ++i) {
        {
            std::lock_guard<std::mutex> lock(mtx);
            dataQueue.push(i);
            std::cout << "Produced: " << i << "\n";
        }
        cv.notify_one();
        std::this_thread::sleep_for(std::chrono::milliseconds(100));
    }
    
    {
        std::lock_guard<std::mutex> lock(mtx);
        finished = true;
    }
    cv.notify_one();
}

void consumer() {
    while (true) {
        std::unique_lock<std::mutex> lock(mtx);
        cv.wait(lock, []() { return !dataQueue.empty() || finished; });
        
        if (dataQueue.empty() && finished) {
            break;
        }
        
        int data = dataQueue.front();
        dataQueue.pop();
        std::cout << "Consumed: " << data << "\n";
    }
}

int main() {
    std::thread p(producer);
    std::thread c(consumer);
    
    p.join();
    c.join();
    
    return 0;
}
```

### 2. wait_for和wait_until

```cpp
#include <mutex>
#include <condition_variable>

std::mutex mtx;
std::condition_variable cv;
bool ready = false;

void wait_with_timeout() {
    std::unique_lock<std::mutex> lock(mtx);
    
    // 等待最多1秒
    if (cv.wait_for(lock, std::chrono::seconds(1), []() { return ready; })) {
        // 条件满足
    } else {
        // 超时
    }
}
```

## 4. 读写锁

### 1. shared_mutex（C++17）

```cpp
#include <shared_mutex>
#include <thread>
#include <vector>

class ThreadSafeCache {
    mutable std::shared_mutex mutex_;
    std::map<std::string, int> data_;
    
public:
    int get(const std::string& key) const {
        // 共享锁（读锁）
        std::shared_lock<std::shared_mutex> lock(mutex_);
        auto it = data_.find(key);
        return it != data_.end() ? it->second : -1;
    }
    
    void set(const std::string& key, int value) {
        // 独占锁（写锁）
        std::unique_lock<std::shared_mutex> lock(mutex_);
        data_[key] = value;
    }
};
```

## 5. 注意事项与最佳实践

### 1. 死锁避免

```cpp
// 1. 按固定顺序加锁
std::mutex mtx1, mtx2;

void operation1() {
    std::lock_guard<std::mutex> lock1(mtx1);
    std::lock_guard<std::mutex> lock2(mtx2);
    // ...
}

void operation2() {
    std::lock_guard<std::mutex> lock1(mtx1);  // 相同顺序
    std::lock_guard<std::mutex> lock2(mtx2);
    // ...
}

// 2. 使用 scoped_lock
void safe_operation() {
    std::scoped_lock lock(mtx1, mtx2);  // 避免死锁
    // ...
}

// 3. 使用 std::lock
void another_safe_way() {
    std::lock(mtx1, mtx2);
    std::lock_guard<std::mutex> lock1(mtx1, std::adopt_lock);
    std::lock_guard<std::mutex> lock2(mtx2, std::adopt_lock);
    // ...
}
```

### 2. 最佳实践

```cpp
// 1. 使用 RAII 锁管理
void good() {
    std::lock_guard<std::mutex> lock(mtx);
    // 自动解锁
}

// 2. 最小化临界区
void efficient() {
    int local_copy;
    {
        std::lock_guard<std::mutex> lock(mtx);
        local_copy = shared_data;
    }
    // 在锁外处理
    process(local_copy);
}

// 3. 避免在临界区调用未知函数
void dangerous() {
    std::lock_guard<std::mutex> lock(mtx);
    unknown_function();  // 可能导致死锁
}
```

## 6. 本章小结

### 1. 核心概念回顾

| 概念 | 说明 | 示例 |
|-----|------|------|
| **mutex** | 互斥量 | `std::mutex` |
| **lock_guard** | 简单RAII锁 | `std::lock_guard<std::mutex>` |
| **unique_lock** | 灵活锁 | `std::unique_lock<std::mutex>` |
| **scoped_lock** | 多锁管理 | `std::scoped_lock(mtx1, mtx2)` |
| **condition_variable** | 条件变量 | `cv.wait(lock, pred)` |
| **shared_mutex** | 读写锁 | `std::shared_mutex` |

### 2. 关键语法要点

1. **互斥量**：保护共享数据
2. **锁管理**：使用 RAII 自动解锁
3. **条件变量**：线程间通知
4. **读写锁**：读多写少场景
5. **死锁避免**：固定顺序、scoped_lock

### 3. 最佳实践

1. 使用 lock_guard 或 unique_lock
2. 最小化临界区范围
3. 使用 scoped_lock 锁定多个互斥量
4. 条件变量使用谓词避免虚假唤醒
5. 读多写少用 shared_mutex
