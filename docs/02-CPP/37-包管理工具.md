> 💡 **通俗理解 - 什么是包管理工具？**

**传统方式 = 手工买菜做饭**

想象你要做一顿大餐：
- 需要去菜市场买各种食材（下载库源码）
- 自己清洗、切菜、处理（编译配置）
- 每个菜的处理方式不同（不同的构建系统）
- 食材之间可能有依赖关系（这个库需要那个库）
- **太麻烦了！**

**包管理工具 = 外卖APP**

```
vcpkg/Conan 就像美团/饿了么：
- 浏览菜单（搜索包）
- 一键下单（安装包）
- 自动配送（自动下载依赖）
- 统一管理（统一安装路径）
```

**核心价值：**
- ⚡ **快速安装**：`vcpkg install fmt` 一行命令搞定
- 🔗 **自动依赖**：自动下载安装所有依赖库
- 📦 **版本管理**：精确控制每个库的版本
- 🔄 **跨平台**：Windows/Linux/macOS统一体验

> 🔬 **抽象理解 - 包管理的本质**：
>
> - **包管理工具**：自动化管理第三方库的下载、编译、安装、依赖解析
> - **vcpkg**：Microsoft开发，CMake友好，适合Windows开发
> - **Conan**：跨语言支持，Python编写，适合复杂项目
> - **清单模式**：用JSON/YAML文件声明依赖，类似npm的package.json
> - **核心价值**：从"手动下载编译"到"一行命令安装"，提升开发效率

## 1. vcpkg

### 1. 安装

```bash
git clone https://github.com/Microsoft/vcpkg.git
cd vcpkg
./bootstrap-vcpkg.bat   # Windows
# ./bootstrap-vcpkg.sh  # Linux/Mac
```

### 2. 基本使用

```bash
# 搜索包
vcpkg search fmt

# 安装包
vcpkg install fmt
vcpkg install nlohmann-json
vcpkg install spdlog

# 安装特定平台
vcpkg install fmt:x64-windows
vcpkg install fmt:x64-linux

# 查看已安装
vcpkg list

# 移除包
vcpkg remove fmt
```

### 3. CMake集成

```bash
# 全局集成（推荐）
vcpkg integrate install

# CMake配置时指定
cmake -B build -DCMAKE_TOOLCHAIN_FILE=[vcpkg路径]/scripts/buildsystems/vcpkg.cmake
```

### 4. vcpkg.json（清单模式）

```json
{
    "name": "my-project",
    "version": "1.0.0",
    "dependencies": [
        "fmt",
        "nlohmann-json",
        "spdlog",
        {
            "name": "boost",
            "version>=": "1.82.0"
        }
    ],
    "overrides": [
        {
            "name": "fmt",
            "version": "10.1.1"
        }
    ]
}
```

### 5. vcpkg进阶特性

#### 1. 二进制缓存（Binary Cache）

> 💡 **为什么需要二进制缓存？**
>
> 默认情况下，vcpkg每次安装包都会从源码编译。当你有多个项目使用相同的依赖，
> 或者在CI/CD中频繁构建时，重复编译会浪费大量时间。二进制缓存让你**编译一次，到处使用**。

**配置环境变量 `VCPKG_BINARY_SOURCES`：**

```bash
# 文件系统缓存（本地目录）
set VCPKG_BINARY_SOURCES="clear;files,D:\vcpkg-cache,readwrite"

# NuGet缓存（适合团队共享）
set VCPKG_BINARY_SOURCES="clear;nuget,https://my-nuget-server.com/v3/index.json,readwrite"

# AWS S3缓存（适合大规模CI/CD）
set VCPKG_BINARY_SOURCES="clear;nuget,https://vcpkg-binary-cache.s3.amazonaws.com/index.json,readwrite"

# 组合使用：本地优先，远程备份
set VCPKG_BINARY_SOURCES="clear;files,D:\vcpkg-cache,readwrite;nuget,https://my-nuget-server.com/v3/index.json,readwrite"
```

**CI/CD中的缓存配置示例（GitHub Actions）：**

```yaml
# .github/workflows/build.yml
env:
  VCPKG_BINARY_SOURCES: "clear;nuget,GitHub,readwrite"

steps:
  - name: 配置NuGet认证
    run: |
      `./vcpkg/vcpkg fetch nuget | % { "$_" }` `
        sources add -source "https://nuget.pkg.github.com/$env:GITHUB_REPOSITORY_OWNER/index.json" `
        -name "GitHub" `
        -username "$env:GITHUB_REPOSITORY_OWNER" `
        -password "$env:GITHUB_TOKEN"

  - name: 安装依赖
    run: cmake -B build -DCMAKE_TOOLCHAIN_FILE=vcpkg/scripts/buildsystems/vcpkg.cmake
```

**缓存源类型对比：**

| 缓存源 | 适用场景 | 优点 | 缺点 |
|--------|---------|------|------|
| **文件系统** | 个人开发 | 配置简单，零依赖 | 无法跨机器共享 |
| **NuGet** | 团队协作 | 成熟的包管理协议 | 需要NuGet服务器 |
| **AWS S3** | 大规模CI/CD | 高可用，全球加速 | 需要AWS账号和配置 |

#### 2. Feature依赖

> 💡 **Feature = 可选功能模块**
>
> 很多大型库（如Boost）包含大量模块，你通常只需要其中几个。
> Feature依赖让你只安装需要的模块，减少编译时间和磁盘占用。

```bash
# 只安装boost的filesystem和system模块
vcpkg install boost[filesystem,system]

# 安装spdlog的fmt外部格式化功能
vcpkg install spdlog[fmt]

# 查看包可用的feature
vcpkg search boost
```

**在vcpkg.json中声明feature依赖：**

```json
{
    "name": "my-project",
    "version": "1.0.0",
    "dependencies": [
        {
            "name": "boost",
            "features": ["filesystem", "system"]
        },
        {
            "name": "spdlog",
            "features": ["fmt"]
        },
        "nlohmann-json"
    ]
}
```

#### 3. Overlay端口

> 💡 **Overlay端口 = 本地补丁/自定义版本**
>
> 当vcpkg官方仓库中的包版本过旧、有Bug，或者你需要自定义编译选项时，
> 可以通过Overlay端口提供自己的portfile.cmake，而不需要修改vcpkg源码。

**目录结构：**

```
my-project/
├── vcpkg.json
├── overlay-ports/          # 自定义端口目录
│   └── my-lib/
│       ├── portfile.cmake  # 自定义构建脚本
│       └── vcpkg.json     # 端口元数据
└── CMakeLists.txt
```

**使用方式：**

```bash
# 通过环境变量指定overlay端口目录
set VCPKG_OVERLAY_PORTS=D:\my-project\overlay-ports

# 或通过CMake变量指定
cmake -B build -DCMAKE_TOOLCHAIN_FILE=vcpkg/scripts/buildsystems/vcpkg.cmake `
    -DVCPKG_OVERLAY_PORTS=D:\my-project\overlay-ports
```

**自定义portfile.cmake示例：**

```cmake
# overlay-ports/my-lib/portfile.cmake
vcpkg_from_github(
    OUT_SOURCE_PATH SOURCE_PATH
    REPO myuser/mylib
    REF v1.2.3
    SHA512 0
)

vcpkg_cmake_configure(
    SOURCE_PATH "${SOURCE_PATH}"
    OPTIONS
        -DMY_LIB_ENABLE_TESTS=OFF    # 关闭测试
        -DMY_LIB_CUSTOM_FEATURE=ON   # 启用自定义功能
)

vcpkg_cmake_install()
vcpkg_cmake_config_fixup()
```

#### 4. Registries（私有包仓库）

> 💡 **Registries = 你自己的vcpkg仓库**
>
> 企业内部通常有私有库，无法发布到vcpkg官方仓库。
> Registries让你创建和管理私有包仓库，使用方式与官方仓库完全一致。

**在vcpkg.json中配置Registry：**

```json
{
    "name": "my-project",
    "version": "1.0.0",
    "dependencies": [
        "fmt",
        {
            "name": "my-private-lib",
            "version>=": "2.0.0"
        }
    ],
    "registries": [
        {
            "kind": "git",
            "repository": "https://git.mycompany.com/vcpkg-registry.git",
            "packages": [
                "my-private-lib",
                "company-utils"
            ]
        }
    ]
}
```

**私有Registry仓库结构：**

```
vcpkg-registry/
├── ports/
│   ├── my-private-lib/
│   │   ├── portfile.cmake
│   │   └── vcpkg.json
│   └── company-utils/
│       ├── portfile.cmake
│       └── vcpkg.json
├── versions/
│   ├── my-private-lib.json    # 版本基线
│   └── company-utils.json
└── baseline.json              # 默认版本基线
```


```python
from conan import ConanFile

class MyProjectConan(ConanFile):
    name = "my_project"
    version = "1.0.0"

    generators = "CMakeDeps", "CMakeToolchain"

        self.requires("fmt/10.1.1")
```

### 6. Conan 2.0重大变更

> ⚠️ **Conan 2.0是一次破坏性更新**
>
> Conan 2.0对架构进行了全面重构，不兼容1.x版本。如果你正在从1.x迁移，
> 请务必阅读迁移指南，逐步升级。

#### 1. 新架构概览

```
Conan 1.x 架构                          Conan 2.0 架构
┌─────────────┐                        ┌─────────────┐
│  旧生成器    │                        │  新生成器    │
│  cmake      │  ──淘汰──▶             │  CMakeDeps  │
│  cmake_multi│                        │  CMakeToolchain │
│  xcode     │                        │  ...        │
├─────────────┤                        ├─────────────┤
│  集中式解析  │  ──改进──▶             │  去中心化解析 │
│  依赖图慢   │                        │  更快的图解析 │
├─────────────┤                        ├─────────────┤
│  复杂Profile│  ──简化──▶             │  简化Profile │
└─────────────┘                        └─────────────┘
```

**核心改进：**

| 方面 | Conan 1.x | Conan 2.0 |
|------|-----------|-----------|
| **架构** | 集中式，单进程 | 去中心化，更快的图解析 |
| **生成器** | cmake, cmake_multi, xcode等 | 统一CMakeDeps + CMakeToolchain |
| **Profile** | 复杂，多配置混用 | 简化，单配置清晰 |
| **命令** | conan install/build/create | conan install/build/create（语义更清晰） |
| **兼容性** | Python 2/3 | 仅Python 3.6+ |

#### 2. 去除旧生成器，统一用CMakeDeps + CMakeToolchain

> 💡 **为什么统一生成器？**
>
> Conan 1.x有太多生成器（cmake, cmake_multi, cmake_paths等），
> 功能重叠且行为不一致。2.0将职责拆分为两个生成器：
> - **CMakeToolchain**：生成工具链文件（编译器、标志等）
> - **CMakeDeps**：生成find_package支持文件

**Conan 1.x（旧方式）：**

```ini
# conanfile.txt（1.x风格，已废弃）
[generators]
cmake
cmake_multi

[options]
fmt:shared=False
```

**Conan 2.0（新方式）：**

```ini
# conanfile.txt（2.0风格）
[generators]
CMakeDeps
CMakeToolchain

[options]
fmt/*:shared=False
```

> ⚠️ 注意2.0中选项语法的变更：`fmt:shared` → `fmt/*:shared`

#### 3. Profile简化

**Conan 1.x Profile（复杂）：**

```ini
# ~/.conan/profiles/default（1.x风格）
[settings]
os=Windows
os_build=Windows
arch=x86_64
arch_build=x86_64
compiler=msvc
compiler.version=193
compiler.runtime=dynamic
build_type=Release

[options]
*:shared=False

[env]
```

**Conan 2.0 Profile（简化）：**

```ini
# ~/.conan2/profiles/default（2.0风格）
[settings]
os=Windows
arch=x86_64
compiler=msvc
compiler.version=193
compiler.runtime=dynamic
build_type=Release

[conf]
tools.cmake.cmaketoolchain:generator=Ninja
```

> 💡 **主要变化：**
> - 去除了`os_build`和`arch_build`（构建机和目标机统一通过`-pr:b`和`-pr:h`区分）
> - `[options]`移至conanfile中，Profile中用`[conf]`替代
> - 配置路径从`~/.conan/`变为`~/.conan2/`

#### 4. conanfile.py的变化

**Conan 1.x conanfile.py：**

```python
from conans import ConanFile, CMake

class MyProjectConan(ConanFile):
    name = "my_project"
    version = "1.0.0"
    settings = "os", "compiler", "build_type", "arch"
    generators = "cmake"           # 旧生成器
    exports_sources = "src/*"      # 旧方式

    def requirements(self):
        self.requires("fmt/10.1.1")

    def build(self):
        cmake = CMake(self)        # 旧CMake辅助类
        cmake.configure()
        cmake.build()

    def package(self):
        self.copy("*.h", dst="include", src="src")
        self.copy("*.lib", dst="lib", keep_path=False)

    def package_info(self):
        self.cpp_info.libs = ["my_project"]
```

**Conan 2.0 conanfile.py：**

```python
from conan import ConanFile
from conan.tools.cmake import CMake, cmake_layout

class MyProjectConan(ConanFile):
    name = "my_project"
    version = "1.0.0"
    settings = "os", "compiler", "build_type", "arch"
    generators = "CMakeDeps", "CMakeToolchain"  # 新生成器

    def layout(self):
        cmake_layout(self)         # 新增：标准目录布局

    def requirements(self):
        self.requires("fmt/10.1.1")

    def build(self):
        cmake = CMake(self)
        cmake.configure()
        cmake.build()

    def package(self):
        copy(self, "*.h", self.source_folder, dst=self.package_path / "include")
        copy(self, "*.lib", self.source_folder, dst=self.package_path / "lib")

    def package_info(self):
        self.cpp_info.libs = ["my_project"]
```

> 💡 **关键变化：**
> - 导入路径：`conans` → `conan`
> - `exports_sources`被`layout()`方法替代
> - `self.copy()` → `conan.tools.files.copy()`
> - 新增`cmake_layout()`提供标准构建目录结构
> - `self.package_folder` → `self.package_path`（Path对象）

#### 5. 迁移指南（Conan 1.x → 2.0）

**步骤1：升级Conan**

```bash
pip install --upgrade conan
conan --version   # 确认版本 >= 2.0
```

**步骤2：迁移Profile**

```bash
# 2.0使用新的配置目录
# 旧：~/.conan/profiles/
# 新：~/.conan2/profiles/

# 自动检测并生成默认Profile
conan profile detect
```

**步骤3：更新conanfile**

| 1.x | 2.0 | 说明 |
|-----|-----|------|
| `from conans import ConanFile` | `from conan import ConanFile` | 导入路径变更 |
| `generators = "cmake"` | `generators = "CMakeDeps", "CMakeToolchain"` | 生成器替换 |
| `self.copy(...)` | `copy(self, ...)` | 文件拷贝API变更 |
| `exports_sources = "src/*"` | `layout()` + 自动检测 | 源码导出方式变更 |
| `self.package_folder` | `self.package_path` | 属性名变更 |
| `fmt:shared=False` | `fmt/*:shared=False` | 选项语法变更 |

**步骤4：更新构建命令**

```bash
# Conan 1.x
conan install . --install-folder=build --build=missing
cmake -B build -DCMAKE_TOOLCHAIN_FILE=build/conan_toolchain.cmake

# Conan 2.0
conan install . --output-folder=build --build=missing
cmake -B build -DCMAKE_TOOLCHAIN_FILE=build/conan_toolchain.cmake \
    -DCMAKE_BUILD_TYPE=Release
```

> ⚠️ `--install-folder`已重命名为`--output-folder`

**步骤5：验证迁移**

```bash
# 清理旧缓存
conan cache clean

# 重新安装依赖
conan install . --output-folder=build --build=missing

# 构建验证
cmake -B build -DCMAKE_TOOLCHAIN_FILE=build/conan_toolchain.cmake
cmake --build build
```

#### 6. Conan 2.0完整构建流程示例

**项目结构：**

```
my-project/
├── conanfile.py
├── CMakeLists.txt
└── src/
    └── main.cpp
```

**conanfile.py：**

```python
from conan import ConanFile
from conan.tools.cmake import CMake, cmake_layout

class MyProjectConan(ConanFile):
    name = "my_project"
    version = "1.0.0"
    settings = "os", "compiler", "build_type", "arch"
    generators = "CMakeDeps", "CMakeToolchain"

    def layout(self):
        cmake_layout(self)

    def requirements(self):
        self.requires("fmt/10.2.1")
        self.requires("nlohmann-json/3.11.3")
        self.requires("spdlog/1.14.1")

    def validate(self):
        # 验证编译器兼容性
        pass
```

**CMakeLists.txt：**

```cmake
cmake_minimum_required(VERSION 3.15)
project(my_project CXX)

find_package(fmt REQUIRED)
find_package(nlohmann_json REQUIRED)
find_package(spdlog REQUIRED)

add_executable(main src/main.cpp)

target_link_libraries(main PRIVATE
    fmt::fmt
    nlohmann_json::nlohmann_json
    spdlog::spdlog
)
```

**构建流程：**

```bash
# 1. 检测并生成Profile（首次使用）
conan profile detect

# 2. 安装依赖
conan install . --build=missing

# 3. 配置CMake（使用Conan生成的工具链）
cmake --preset conan-default

# 4. 编译
cmake --build --preset conan-release

# 5. 运行
./build/Release/main
```

## 3. CMake集成

### 1. vcpkg + CMake

```cmake
cmake_minimum_required(VERSION 3.15)
project(my_project)

find_package(fmt CONFIG REQUIRED)
find_package(nlohmann_json CONFIG REQUIRED)
find_package(spdlog CONFIG REQUIRED)

add_executable(main src/main.cpp)

target_link_libraries(main PRIVATE
    fmt::fmt
    nlohmann_json::nlohmann_json
    spdlog::spdlog
)
```

### 2. FetchContent（无需包管理器）

```cmake
include(FetchContent)

FetchContent_Declare(
    fmt
    GIT_REPOSITORY https://github.com/fmtlib/fmt.git
    GIT_TAG 10.1.1
)

FetchContent_Declare(
    json
    GIT_REPOSITORY https://github.com/nlohmann/json.git
    GIT_TAG v3.11.2
)

FetchContent_MakeAvailable(fmt json)

target_link_libraries(main PRIVATE fmt::fmt nlohmann_json::nlohmann_json)
```
