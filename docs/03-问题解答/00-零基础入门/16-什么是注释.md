# 什么是注释？
> 📖 相关章节：[编程入门](../../01-C语言/导学/00-编程入门.md)、[C语言概述](../../01-C语言/00-C语言概述.md)、[数据类型与变量](../../01-C语言/01-数据类型与变量.md)

## 用生活比喻理解注释

想象你搬进一个新家，发现每个开关旁边都贴着小纸条：

> "这个开关控制客厅灯"
> "这个是热水器，需要等 3 分钟"
> "⚠️ 这个按钮别按！会断电！"

这些小纸条就是**注释**——不影响开关本身的功能，但帮你理解每个开关是干什么的。

**注释**（`comment`）是写给人看的文字，编译器会**完全忽略**它。注释的目的是让代码更容易理解。

> 💡 **比喻**：注释就像地图上的标注——地图本身不会因为你写了"这里有厕所"而改变，但标注让看地图的人更方便。

## 注释的两种写法

### 单行注释 `//`

用 `//` 开头，从 `//` 到行末都是注释：

```cpp
int age = 25;  // 这是单行注释，写在代码右边

// 这也是单行注释，独占一行
int score = 100;
```

### 多行注释 `/* */`

用 `/*` 开头，`*/` 结尾，中间可以写多行：

```cpp
/*
 * 这是一段多行注释
 * 可以写很多内容
 * 适合解释复杂的逻辑
 */
int total = calculateTotal();

int result = /* 也可以在代码中间插入注释 */ 42;
```

### 两种注释对比

| 特点 | `//` 单行注释 | `/* */` 多行注释 |
|------|-------------|----------------|
| 适用场景 | 简短说明 | 详细解释 |
| 能否跨行 | ❌ 只到行末 | ✅ 可以跨多行 |
| 嵌套 | ✅ 可以嵌套 | ❌ 不能嵌套 |
| 常用程度 | ⭐⭐⭐ 更常用 | ⭐⭐ 特定场景 |

> ⚠️ **注意**：多行注释不能嵌套！`/* 外层 /* 内层 */ 这里已经不是注释了 */` 会导致编译错误。

## 为什么要写注释？

### 1. 帮助自己

三个月后你回头看自己写的代码，可能完全不记得当时为什么这么写：

```cpp
// 没有注释：三个月后的你
int x = (n * (n + 1)) / 2;  // 这是什么鬼？

// 有注释：恍然大悟
int sum = (n * (n + 1)) / 2;  // 等差数列求和公式：1+2+...+n
```

### 2. 帮助他人

团队协作时，别人需要理解你的代码：

```cpp
// 计算折扣后的价格，会员打 8 折，非会员打 9 折
double finalPrice = isMember ? price * 0.8 : price * 0.9;
```

### 3. 临时禁用代码

调试时，可以用注释暂时"关掉"某行代码：

```cpp
std::cout << "调试信息A" << std::endl;
// std::cout << "这行暂时不用" << std::endl;  // 注释掉
std::cout << "调试信息C" << std::endl;
```

## 注释的最佳实践

### ✅ 应该这样写注释

**解释"为什么"，而不是"是什么"**：

```cpp
// ✅ 好注释：解释为什么
// 使用二分查找而非线性查找，因为数据量超过 100 万
int index = binarySearch(data, target);

// ❌ 坏注释：只重复代码
// 使用二分查找
int index = binarySearch(data, target);
```

**对复杂逻辑加注释**：

```cpp
// ✅ 好注释：解释不直观的逻辑
// 闰年判断：能被4整除且不能被100整除，或者能被400整除
bool isLeapYear = (year % 4 == 0 && year % 100 != 0) || (year % 400 == 0);
```

**对函数加说明注释**：

```cpp
// ✅ 好注释：说明函数的用途、参数、返回值
// 计算圆的面积
// 参数：radius - 圆的半径（必须为正数）
// 返回：圆的面积
double circleArea(double radius) {
    return 3.14159 * radius * radius;
}
```

### ❌ 不应该这样写注释

**不要注释显而易见的事**：

```cpp
// ❌ 多余的注释
int age = 25;  // 把 25 赋值给 age

// ❌ 多余的注释
i++;  // i 加 1
```

**不要用注释代替好命名**：

```cpp
// ❌ 代码烂，靠注释补
int d;  // 经过的天数

// ✅ 好的命名不需要注释
int elapsedDays;
```

**不要留着过时的注释**：

```cpp
// ❌ 注释和代码不一致！
// 计算矩形面积
double result = 3.14159 * radius * radius;  // 实际算的是圆面积
```

> ⚠️ **过时的注释比没有注释更危险**——它会误导读者！

## Doxygen 风格注释

`Doxygen` 是一种专业的文档生成工具，用特定格式的注释可以自动生成 API 文档：

```cpp
/**
 * @brief 计算两个整数的最大公约数
 *
 * 使用辗转相除法（欧几里得算法）计算最大公约数。
 *
 * @param a 第一个正整数
 * @param b 第二个正整数
 * @return a 和 b 的最大公约数
 *
 * @note 如果 a 或 b 为 0，行为未定义
 */
int gcd(int a, int b) {
    while (b != 0) {
        int temp = b;
        b = a % b;
        a = temp;
    }
    return a;
}
```

常用 Doxygen 标记：

| 标记 | 含义 | 示例 |
|------|------|------|
| `@brief` | 简要描述 | `@brief 计算面积` |
| `@param` | 参数说明 | `@param radius 半径` |
| `@return` | 返回值说明 | `@return 面积值` |
| `@note` | 注意事项 | `@note 半径必须为正` |
| `@warning` | 警告 | `@warning 可能溢出` |

## 注释 vs 代码可读性

**好的代码本身就是最好的注释**。与其写很多注释，不如把代码写得更清晰：

```cpp
// ❌ 需要注释才能看懂
if (t > 37.3) {  // 如果体温超过 37.3 度
    q = 1;        // 标记为发烧
}

// ✅ 代码本身就能看懂，不需要注释
const double FEVER_THRESHOLD = 37.3;
bool hasFever = temperature > FEVER_THRESHOLD;
```

**原则**：

1. 先让代码自己说话（好命名、好结构）
2. 代码说不清楚的地方，再用注释补充
3. 注释解释"为什么"，代码展示"怎么做"

## 小结

| 概念 | 一句话理解 |
|------|-----------|
| 单行注释 `//` | 写在行尾或独占一行的简短说明 |
| 多行注释 `/* */` | 跨多行的详细解释 |
| 注释的目的 | 帮人理解代码，编译器忽略 |
| 好注释 | 解释"为什么" |
| 坏注释 | 重复代码、过时、显而易见 |
| Doxygen | 自动生成文档的专业注释格式 |
| 代码可读性 | 好代码 > 坏代码 + 好注释 |

记住：**注释是给未来的自己和他人写的信**——写清楚，别让读的人猜！
