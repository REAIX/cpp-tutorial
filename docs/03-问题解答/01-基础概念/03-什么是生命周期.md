# 什么是生命周期
> 📖 相关章节：[运算符与表达式](../../01-C语言/02-运算符与表达式.md)、[控制结构](../../01-C语言/03-控制结构.md)、[函数](../../01-C语言/04-函数.md)、[基础特性](../../02-CPP/01-基础特性.md)、[命名空间](../../02-CPP/02-命名空间与编码规范.md)

> **An object's lifetime is the runtime property: from construction to destruction.** — 对象的生命周期是运行期属性：从构造到析构。

***

### 1. 先抓核心

**生命周期**（Lifetime）= 对象从创建到销毁的时间段。在生命周期内，对象占据内存、可以安全使用；生命周期结束后，内存被回收，继续使用就是未定义行为。

***

### 2. 生活类比

把对象比作**酒店住客**：

- **自动存储期** → 临时住客，到退房日期自动离开（局部变量随函数返回自动销毁）
- **静态存储期** → 长租住客，酒店运营期间一直住着（全局变量和 static 变量程序结束才销毁）
- **动态存储期** → 自由住客，自己决定什么时候来、什么时候走（new 出来的对象，手动 delete 才销毁）

退房后还用房间钥匙进门——这就是**悬空引用**（dangling reference）。

### 3. 三种存储持续时间

| 存储期 | 关键字/位置 | 何时创建 | 何时销毁 |
|--------|-----------|---------|---------|
| 自动存储期 | 局部变量 | 执行到定义处 | 离开所在块 |
| 静态存储期 | 全局变量、`static` 变量 | 程序启动 | 程序结束 |
| 动态存储期 | `new` 分配 | 执行 new 时 | 执行 delete 时 |

```cpp
#include <iostream>

int g_val = 10;            // 静态存储期：程序开始→程序结束

void func() {
    int local = 20;        // 自动存储期：进入函数→离开函数
    static int count = 0;  // 静态存储期：首次执行→程序结束
    ++count;
    std::cout << count << std::endl;
}

int main() {
    int* p = new int(30);  // 动态存储期：new→delete
    delete p;              // 手动销毁
}
```

### 4. 自动存储期详解

自动存储期的对象在**栈**上分配，离开作用域时自动销毁：

```cpp
#include <iostream>
#include <string>

class Logger {
    std::string name_;
public:
    explicit Logger(std::string name) : name_(std::move(name)) {
        std::cout << name_ << " 创建" << std::endl;
    }
    ~Logger() {
        std::cout << name_ << " 销毁" << std::endl;
    }
};

void demo() {
    Logger a("A");        // 输出：A 创建
    {
        Logger b("B");    // 输出：B 创建
    }                     // 输出：B 销毁（离开内层块）
    Logger c("C");        // 输出：C 创建
}                         // 输出：C 销毁，A 销毁（离开函数，逆序销毁）

// 完整输出：
// A 创建
// B 创建
// B 销毁
// C 创建
// C 销毁
// A 销毁
```

**关键规则**：同一作用域内，对象按定义顺序构造，按**逆序**析构。

### 5. 静态存储期详解

```cpp
#include <iostream>

struct Counter {
    int value;
    Counter() : value(0) {
        std::cout << "Counter 构造" << std::endl;
    }
    ~Counter() {
        std::cout << "Counter 析构，value=" << value << std::endl;
    }
};

Counter g_counter;  // 全局对象：main 之前构造，main 之后析构

void func() {
    static Counter s_counter;  // 静态局部变量：首次调用时构造，程序结束时析构
    ++s_counter.value;
}

int main() {
    std::cout << "main 开始" << std::endl;
    func();  // 首次调用，构造 s_counter
    func();  // 不再构造，value 变为 2
    std::cout << "main 结束" << std::endl;
    return 0;
}
// 析构顺序：s_counter → g_counter（与构造顺序相反）
```

**静态局部变量的特点**：

| 特性 | 说明 |
|------|------|
| 只构造一次 | 首次执行到定义处时构造 |
| 线程安全初始化 | C++11 保证静态局部变量初始化是线程安全的 |
| 程序结束时析构 | 与其他静态对象一起，按逆序析构 |

### 6. 动态存储期详解

```cpp
#include <iostream>

class Resource {
public:
    Resource() { std::cout << "Resource 分配" << std::endl; }
    ~Resource() { std::cout << "Resource 释放" << std::endl; }
};

void dynamic_lifetime() {
    Resource* p = new Resource();  // 手动分配：生命周期开始
    // ... 使用 p ...
    delete p;                      // 手动释放：生命周期结束

    // 现代 C++ 推荐用智能指针
    auto sp = std::make_unique<Resource>();  // 自动管理
    // 离开作用域自动 delete
}
```

**动态存储期的风险**：

| 问题 | 原因 | 后果 |
|------|------|------|
| 内存泄漏 | 忘记 delete | 内存持续占用 |
| 悬空指针 | delete 后继续使用 | 未定义行为 |
| 重复释放 | delete 两次 | 未定义行为 |

### 7. 构造与析构的时机

```cpp
#include <iostream>
#include <memory>

class Obj {
    std::string name_;
public:
    explicit Obj(std::string name) : name_(std::move(name)) {
        std::cout << name_ << " 构造" << std::endl;
    }
    ~Obj() {
        std::cout << name_ << " 析构" << std::endl;
    }
};

Obj global("global");  // 1. 最先构造

int main() {
    std::cout << "--- main 开始 ---" << std::endl;

    Obj local("local");                       // 2. 执行到这里构造
    static Obj static_local("static_local");  // 3. 首次执行构造
    auto heap = std::make_unique<Obj>("heap"); // 4. make_unique 时构造

    std::cout << "--- main 结束 ---" << std::endl;
    // 析构顺序：heap → local → static_local → global
}
```

### 8. 悬空引用——生命周期最危险的 Bug

```cpp
#include <iostream>

// 错误：返回局部变量的引用
int& dangerous() {
    int local = 42;
    return local;  // 警告：返回局部变量的引用
}  // local 已销毁，返回的引用指向无效内存

int* also_dangerous() {
    int local = 42;
    return &local;  // 同样危险：返回局部变量的地址
}

// 正确做法
int safe_return() {
    int local = 42;
    return local;  // 返回值的副本，安全
}

// 正确：返回静态变量引用
int& safe_static() {
    static int value = 42;
    return value;  // 静态变量生命周期持续到程序结束
}
```

**悬空引用常见场景**：

| 场景 | 示例 | 解决方案 |
|------|------|----------|
| 返回局部变量引用 | `int& f() { int x; return x; }` | 返回值而非引用 |
| 容器元素引用失效 | `int& r = v[0]; v.push_back(1);` | 操作后重新获取引用 |
| 指向已 delete 的对象 | `delete p; p->func();` | 用智能指针 |
| 字符串字面量拼接 | `const char* p = (s1 + s2).c_str();` | 先存到变量 |

### 9. 临时对象的生命周期

```cpp
#include <iostream>
#include <string>

void temp_lifetime() {
    // 临时 string 对象的生命周期到完整表达式结束
    const std::string& ref = std::string("hello");  // 延长生命周期！
    std::cout << ref << std::endl;  // 安全：const 引用延长了临时对象的生命周期

    // 非 const 引用无法绑定临时对象
    // std::string& bad = std::string("hello");  // 错误！

    // 但注意：只在直接绑定时有效
    const std::string& get_ref() {
        return std::string("hello");  // 危险！返回绑定到临时对象的引用
    }
    // 临时对象在返回语句结束时销毁，引用悬空
}
```

**const 引用延长临时对象生命周期的规则**：

| 情况 | 临时对象何时销毁 |
|------|----------------|
| 直接绑定到 const 引用 | 引用生命周期结束时 |
| 作为函数参数 | 完整表达式结束时 |
| 返回的临时对象 | 完整表达式结束时 |

### 10. 极简总结

**生命周期 = 对象从创建到销毁的时间段 → 自动/静态/动态三种存储期 → 构造顺序=定义顺序，析构顺序=逆序 → 悬空引用是最危险的 Bug → const 引用可延长临时对象生命周期 → 智能指针自动管理动态存储期**
