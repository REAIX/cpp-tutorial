# 什么是头文件
> 📖 相关章节：[运算符与表达式](../../01-C语言/02-运算符与表达式.md)、[控制结构](../../01-C语言/03-控制结构.md)、[函数](../../01-C语言/04-函数.md)、[基础特性](../../02-CPP/01-基础特性.md)、[命名空间](../../02-CPP/02-命名空间与编码规范.md)

> **Headers are the contract between modules. They declare what's available, source files define how it works.** — 头文件是模块间的契约：声明有什么，源文件定义怎么做。

***

### 1. 一句话概括

**头文件**（Header File）= 存放声明和接口的文件，让多个源文件共享同一套类型定义、函数声明和常量。它是 C/C++ 分离编译的基石。

***

### 2. 生活类比

把头文件比作**餐厅菜单**：

- **头文件**（`.h`）→ 菜单：告诉你有哪些菜、什么价格（声明），但看不到做法
- **源文件**（`.cpp`）→ 后厨：真正做菜的地方（定义/实现）
- **`#include`** → 顾客翻看菜单：知道能点什么菜

没有菜单，顾客不知道有什么菜；没有后厨，菜单上的菜做不出来。两者缺一不可。

### 3. 为什么需要头文件

C/C++ 采用**分离编译**：每个 `.cpp` 文件独立编译，编译器一次只看一个文件。

```cpp
// ===== 没有 header 的问题 =====

// file1.cpp
void greet();  // 必须手动声明，否则编译器不认识
int main() { greet(); }

// file2.cpp
void greet() { /* 实现 */ }

// 如果 greet 的参数改了，file1.cpp 的声明没更新 → 链接错误或 UB
```

**头文件解决的核心问题**：让声明只写一次，多个文件共享，保证一致性。

```cpp
// ===== 用 header 的正确做法 =====

// greet.h
#pragma once
void greet(const char* name);  // 声明只写一次

// file1.cpp
#include "greet.h"  // 自动获得最新声明
int main() { greet("World"); }

// file2.cpp
#include "greet.h"  // 同样获得最新声明
void greet(const char* name) { /* 实现 */ }
```

### 4. 头文件 vs 源文件

| 特性 | 头文件（`.h` / `.hpp`） | 源文件（`.cpp` / `.cc`） |
|------|:---:|:---:|
| 内容 | 声明、类型定义、内联函数 | 函数实现、变量定义 |
| 被包含 | 可以被多个文件 `#include` | 不被包含 |
| 编译 | 不直接编译 | 独立编译为目标文件 |
| ODR | 声明可重复出现 | 定义只能出现一次 |

### 5. `.h` vs `.hpp`

| 后缀 | 含义 | 使用场景 |
|------|------|----------|
| `.h` | C 风格头文件 | C 项目、C/C++ 混合项目 |
| `.hpp` | C++ 头文件 | 纯 C++ 项目，含模板/内联实现 |
| `.hxx` | C++ 头文件（少见） | 某些项目规范 |

```cpp
// C 风格头文件：utils.h
#pragma once
#ifdef __cplusplus
extern "C" {        // C++ 中调用时保持 C 链接
#endif

int add(int a, int b);

#ifdef __cplusplus
}
#endif

// C++ 风格头文件：utils.hpp
#pragma once
namespace utils {
    int add(int a, int b);

    // 模板实现通常也放在 hpp 中
    template<typename T>
    T multiply(T a, T b) {
        return a * b;
    }
}
```

### 6. 什么放在头文件中

| 放在头文件 ✅ | 不放在头文件 ❌ |
|-------------|--------------|
| 函数声明 | 函数定义（非内联/非模板） |
| 类定义 | 全局变量定义 |
| 模板定义 | `static` 变量定义 |
| 内联函数定义 | 命名空间级的 `using` |
| `constexpr` 定义 | 匿名命名空间内容 |
| `extern` 声明 | 可能冲突的宏 |
| 类型别名（`typedef`/`using`） | 大量实现细节 |

```cpp
// ===== good.h：正确的头文件内容 =====
#pragma once
#include <string>
#include <vector>

class User {
    std::string name_;
    int age_;
public:
    User(std::string name, int age);  // 声明
    std::string get_name() const;      // 声明
};

extern int g_user_count;  // 声明（不分配内存）

// ===== good.cpp：正确的源文件内容 =====
#include "good.h"

User::User(std::string name, int age)
    : name_(std::move(name)), age_(age) {}

std::string User::get_name() const { return name_; }

int g_user_count = 0;  // 定义（分配内存）
```

### 7. 头文件守卫

防止头文件被重复包含：

```cpp
// 方式1：传统宏守卫
#ifndef MY_HEADER_H
#define MY_HEADER_H

// 头文件内容

#endif // MY_HEADER_H

// 方式2：#pragma once（推荐，简洁）
#pragma once

// 头文件内容
```

| 方式 | 优点 | 缺点 |
|------|------|------|
| 宏守卫 | 标准保证，可移植 | 冗长，宏名可能冲突 |
| `#pragma once` | 简洁，不会冲突 | 非标准，但主流编译器都支持 |

**推荐**：使用 `#pragma once`，除非需要最大可移植性。

### 8. 常见错误

**错误1：头文件中定义变量**

```cpp
// ===== bad.h =====
int g_count = 0;  // 每个 include 的 .cpp 都生成一个定义 → 链接错误

// 正确：
extern int g_count;  // 声明
```

**错误2：头文件中定义非内联函数**

```cpp
// ===== bad.h =====
void func() { /* ... */ }  // 多个 .cpp 包含 → 重复定义

// 正确：
inline void func() { /* ... */ }  // 内联函数可以放在头文件
// 或者只在头文件声明，在 .cpp 中定义
```

**错误3：头文件中使用 `using namespace`**

```cpp
// ===== bad.h =====
using namespace std;  // 污染所有包含此头文件的代码

// 正确：在头文件中使用完整限定名
std::string get_name();
```

**错误4：循环包含**

```cpp
// a.h
#include "b.h"  // b.h 又 include a.h → 无限递归

// 正确：使用前向声明
class B;  // 前向声明代替 #include
```

### 9. 头文件包含顺序

Google C++ 风格建议的包含顺序：

```
1. 对应的头文件（如 foo.cpp 包含 foo.h）
2. C 系统头文件（<cstdio>）
3. C++ 标准库头文件（<vector>）
4. 其他库头文件
5. 项目内头文件
```

```cpp
// ===== player.cpp =====
#include "player.h"          // 1. 对应头文件

#include <cstdio>            // 2. C 系统头文件
#include <vector>            // 3. C++ 标准库
#include <string>

#include "engine/physics.h"  // 4. 项目内头文件
#include "utils/math.h"
```

### 10. 极简总结

**头文件 = 存放声明的契约文件 → 分离编译的基石 → .h 放声明，.cpp 放定义 → 用 #pragma once 防重复包含 → 头文件中不要定义变量和非内联函数 → 用前向声明减少包含 → 不要在头文件中 using namespace**
