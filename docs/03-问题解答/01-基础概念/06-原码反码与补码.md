# 原码、反码与补码 — 计算机如何表示负数
> 📖 相关章节：[数据类型与变量](../../01-C语言/01-数据类型与变量.md)、[位操作实战](../../01-C语言/12-位操作实战.md)

### 1. 核心速览

**计算机只用补码存储整数**。原码是人脑最直觉的表示（最高位当符号），反码是原码到补码的过渡，补码才是 CPU 真正使用的格式——它让减法变成加法，零的表示唯一，加减法电路只需一套。但补码不是终点——移码用于浮点数指数，BCD 码用于金融，符号扩展和整数提升是 C/C++ 程序员的日常陷阱。

***

### 2. 为什么需要补码？

人脑做减法很自然：`5 - 3 = 2`。但 CPU 只有加法器，没有减法器。如果能让减法变成加法，硬件就简单了。

```
人脑：5 - 3 = 2
CPU：5 + (-3) = 2    ← 如果 -3 的二进制表示能让加法器直接算出 2，问题就解决了
```

补码就是这个"让减法变加法"的编码方案。

***

### 3. 三种编码规则（以 8 位为例）

假设用 8 位二进制表示整数，最高位是符号位（0 正 1 负）。

#### 原码（Sign-Magnitude）

**规则**：最高位是符号位，其余位是绝对值的二进制。

```
+5 的原码：0 0000101
-5 的原码：1 0000101

+0 的原码：0 0000000
-0 的原码：1 0000000    ← 问题：零有两种表示！
```

**致命缺陷**：
1. 零有两种表示（+0 和 -0），比较和判断麻烦
2. 减法无法直接用加法器完成：`5 + (-3)` 用原码算出来是 `10001000`（-8），不是 2

**原码的现存场景**：IEEE 754 浮点数的尾数部分仍然使用原码（符号位 + 绝对值），因为浮点运算不依赖补码的"减法变加法"特性。

#### 反码（Ones' Complement）

**规则**：正数与原码相同；负数 = 符号位不变，其余位取反。

```
+5 的反码：0 0000101    （正数不变）
-5 的反码：1 1111010    （正数各位取反）

+0 的反码：0 0000000
-0 的反码：1 1111111    ← 零仍然有两种表示！
```

**进步**：减法可以转化为加法了，但需要"循环进位"：

```
5 - 3 = 5 + (-3的反码)
  00000101
+ 11111100    ← -3 的反码
-----------
 100000001    ← 9 位，溢出最高位的 1
 把溢出的 1 加回低位：
  00000001
+        1
-----------
  00000010    = 2  ✓

但零仍然不唯一，且循环进位增加了硬件复杂度。
```

**反码的现存场景**：
- IPv4 校验和计算使用反码（方便硬件实现"进位回卷"）
- 按位取反操作 `~x` 本质上就是求反码

#### 补码（Two's Complement）

**规则**：正数与原码相同；负数 = 反码 + 1（等价于：按位取反再加 1）。

```
+5 的补码：0 0000101    （正数不变）
-5 的补码：1 1111011    （反码 11111010 + 1）

+0 的补码：0 0000000
-0 的补码：1 1111111 + 1 = 1 00000000 → 溢出丢弃 → 00000000
           ← 零只有一种表示！
```

**为什么补码能直接做减法**：

```
5 - 3 = 5 + (-3的补码)
  00000101
+ 11111101    ← -3 的补码
-----------
  00000010    = 2  ✓  不需要循环进位！直接丢弃溢出位即可
```

### 4. 补码的核心直觉

**补码的本质是"模运算"**。8 位二进制能表示 0~255，模为 256。对于负数 -x，它的补码就是 `256 - x`。

```
时钟比喻：12 小时制，模为 12
  往前拨 3 小时 = 往后拨 9 小时（12 - 3 = 9）
  所以 -3 的"补码"就是 9

8 位二进制，模为 256
  -3 的补码 = 256 - 3 = 253 = 11111101₂
  5 + 253 = 258 = 1 00000010₂ → 丢弃溢出 → 00000010₂ = 2 ✓
```

**快速求补码口诀**：按位取反，再加 1。

```
求 -5 的补码：
  +5 = 00000101
  取反 = 11111010
  +1  = 11111011    ← 这就是 -5 的补码

验证：5 + (-5) = ?
  00000101
+ 11111011
-----------
  00000000    ✓  结果为零
```

**数学证明**：为什么"取反加1"等价于"模 - x"？

```
设 n 位二进制，模 M = 2^n

对 x 按位取反 = M - 1 - x    （因为 x + ~x = 111...1 = M - 1）
取反后加 1 = M - 1 - x + 1 = M - x    ✓

所以 ~x + 1 = M - x，这正是 -x 的补码表示
```

### 5. 补码的值域

8 位补码的表示范围是 **-128 ~ +127**（不是对称的 -127 ~ +127）。

```
补码值域（8位）：

  00000000 =    0
  00000001 =   +1
  01111111 =  +127    ← 最大正数
  10000000 =  -128    ← 最小负数（没有对应的正数！）
  10000001 =  -127
  11111110 =   -2
  11111111 =   -1     ← 全1是-1，不是-255或最大负数

规律：最高位为 1 的是负数，为 0 的是正数（含零）
      全 1 = -1，全 0 = 0
      1000...0 是最小负数，只有负数端"多出一个"
```

**为什么负数比正数多一个？**

```
8 位二进制共 256 种组合：
  零占 1 种：00000000
  正数占 127 种：00000001 ~ 01111111
  负数占 128 种：10000000 ~ 11111111

原码和反码中 +0 和 -0 各占一种，所以正负各 127 种
补码中零只有一种，省下的那个编码给了 -128
```

**常见类型的补码值域**：

| 类型 | 位数 | 最小值 | 最大值 |
|------|------|--------|--------|
| `char`（signed） | 8 | -128 | +127 |
| `short` | 16 | -32768 | +32767 |
| `int` | 32 | -2147483648 | +2147483647 |
| `long long` | 64 | -9223372036854775808 | +9223372036854775807 |

公式：**n 位补码的范围是 -2^(n-1) ~ 2^(n-1) - 1**

### 6. 移码（Excess-N / Bias）

移码是补码的"偏移版本"——将补码的符号位取反，使数值从 0 开始递增。

**规则**：移码 = 补码的符号位取反（等价于：真实值 + 偏移量）

```
8 位移码（偏移量 127）：

  真实值    补码        移码
  -128    10000000    00000000    ← 移码从 0 开始
  -127    10000001    00000001
  -1      11111111    01111111
   0      00000000    10000000    ← 零在中间
  +1      00000001    10000001
  +127    01111111    11111111    ← 移码最大

移码特点：数值大小与二进制大小一致，可以直接比较大小
```

**移码的用途：IEEE 754 浮点数的指数部分**

```
float 的指数（8位，偏移量 127）：
  实际指数 = 移码值 - 127
  移码 00000000 → 实际指数 -127（非正规数/零）
  移码 01111111 → 实际指数 0
  移码 11111110 → 实际指数 +127
  移码 11111111 → 实际指数 +128（无穷大/NaN）

为什么浮点指数用移码不用补码？
  → 移码可以直接比较大小，浮点数比较时先比指数再比尾数
  → 硬件实现更简单：两个 float 比较大小，当符号相同时，
    直接按无符号整数比较即可（因为移码保持了单调性）
```

### 7. 符号扩展与零扩展

当把一个较小位宽的整数赋值给较大位宽的变量时，需要扩展高位。扩展方式取决于是否有符号。

#### 符号扩展（Sign Extension）— 有符号数

**规则**：用符号位（最高位）填充新增的高位。

```
8 位 → 16 位符号扩展：

  +5:  00000101 → 00000000 00000101    ← 符号位0，高位全填0
  -5:  11111011 → 11111111 11111011    ← 符号位1，高位全填1

原理：补码中负数的高位全是1，扩展后值不变
  -5 的 8位补码 = 11111011 = 256 - 5 = 251
  -5 的16位补码 = 11111111 11111011 = 65536 - 5 = 65531
  两者都表示 -5，只是模不同
```

#### 零扩展（Zero Extension）— 无符号数

**规则**：高位全部填 0。

```
8 位 → 16 位零扩展：

  5:   00000101 → 00000000 00000101
  251: 11111011 → 00000000 11111011    ← 高位填0，值保持251不变
```

#### C/C++ 中的隐式扩展规则

```c
#include <stdio.h>

int main() {
    // 场景1：char → int（符号扩展）
    signed char sc = -1;       // 0xFF
    int si = sc;               // 符号扩展 → 0xFFFFFFFF = -1 ✓

    // 场景2：unsigned char → int（零扩展）
    unsigned char uc = 255;    // 0xFF
    int ui = uc;               // 零扩展 → 0x000000FF = 255 ✓

    // 场景3：陷阱 — char 的符号性由编译器决定！
    char c = 0xFF;             // char 可能是 signed 或 unsigned
    int i = c;                 // 结果取决于编译器！
    // MSVC/GCC 默认 signed char: 符号扩展 → -1
    // ARM 某些编译器 unsigned char: 零扩展 → 255

    // 场景4：位运算中的隐式扩展
    unsigned char flags = 0x80;
    if (flags & 0x80) {        // 0x80 是 int，flags 被零扩展为 int
        printf("高位已设置\n"); // 正确执行
    }

    // 场景5：严重陷阱 — 右移时符号扩展
    int x = -1;                // 0xFFFFFFFF
    unsigned int y = x >> 1;   // 算术右移 → 0xFFFFFFFF（符号位扩展）
    unsigned int z = (unsigned)x >> 1;  // 逻辑右移 → 0x7FFFFFFF

    return 0;
}
```

### 8. 整数提升与隐式转换

C/C++ 的整数转换规则与补码密切相关，是最常见的 Bug 来源之一。

#### 整数提升（Integer Promotion）

C 标准规定：比 `int` 小的类型（`char`、`short`）在运算前会被提升为 `int`。

```c
signed char a = -1;           // 0xFF
signed char b = -2;           // 0xFE
int result = a + b;           // a 和 b 先符号扩展为 int，再相加

// 过程：
// a: 0xFF → 0xFFFFFFFF (int, -1)
// b: 0xFE → 0xFFFFFFFE (int, -2)
// 相加: 0xFFFFFFFF + 0xFFFFFFFE = 0x1FFFFFFFD → 截断 → 0xFFFFFFFD = -3
```

#### 隐式转换规则（寻常算术转换）

当两个操作数类型不同时，按以下规则转换：

```
1. 如果两个都是有符号或都是无符号：较小类型提升为较大类型
2. 如果无符号类型 ≥ 有符号类型的位宽：有符号转为无符号
3. 如果有符号类型能表示无符号类型的所有值：无符号转为有符号
4. 否则：两者都转为与有符号类型同位宽的无符号类型
```

```c
// 规则2的典型陷阱
int x = -1;
unsigned int y = 1;

if (x < y) {
    // 期望执行，但实际不会！
    // x 被转为 unsigned int → 4294967295
    // 4294967295 < 1 → false
}

// 规则3的例子（64位系统）
long long ll = -1;
unsigned int ui = 1;

if (ll < ui) {
    // 会执行！long long (64位) 能表示 unsigned int (32位) 的所有值
    // ui 被转为 long long → 1
    // -1 < 1 → true
}

// 死循环经典 Bug
for (size_t i = 10; i >= 0; i--) {
    // size_t 是无符号类型，永远 >= 0，死循环！
    // 当 i = 0 时，i-- 变成 SIZE_MAX（补码环绕）
}
```

### 9. 补码与位运算的关系

理解补码后，很多位运算技巧才能理解：

```c
// 快速取负：按位取反加1
int x = 5;
int neg_x = ~x + 1;    // -5（等价于 -x）

// 判断一个数是否为负数
int is_neg = x >> 31;   // 算术右移：负数结果为 -1（全1），正数为 0

// 取绝对值（无分支）
int abs_x = (x ^ (x >> 31)) - (x >> 31);

// 为什么 -1 的二进制是全1？
// -1 的补码 = ~1 + 1 = 11111110 + 1 = 11111111
// 所以 memset(buf, -1, size) 可以把每个字节都设为 0xFF
// memset(buf, 0, size) 把每个字节设为 0x00

// 补码的乘法技巧
// x * 2  = x << 1
// x * 4  = x << 2
// x * -1 = ~x + 1
// x * 7  = (x << 3) - x    ← 编译器优化常用
// x * -8 = -(x << 3)       ← 编译器将乘法转为移位和取负

// 补码的除法：右移 ≠ 除法（对负数不成立！）
int a = -7;
int b = a >> 1;    // -4（向负无穷取整），不是 -3（向零取整）
int c = a / 2;     // -3（C99 起规定向零取整）
// 右移对负数是算术右移（填符号位），除法是向零截断，两者行为不同！
```

### 10. 补码带来的溢出陷阱

补码的溢出是"环绕"的，不会报错：

```c
#include <stdio.h>
#include <limits.h>

int main() {
    int max = INT_MAX;   // 2147483647
    int min = INT_MIN;   // -2147483648

    // 正溢出：最大值 + 1 → 最小值
    printf("INT_MAX + 1 = %d\n", max + 1);   // -2147483648！

    // 负溢出：最小值 - 1 → 最大值
    printf("INT_MIN - 1 = %d\n", min - 1);   // 2147483647！

    // 永远为真的循环（补码溢出导致）
    // for (char c = 0; c <= 127; c++)  ← 当 c=127 时 +1 变成 -128，死循环！

    return 0;
}
```

**为什么 `INT_MAX + 1 = INT_MIN`？**

```
INT_MAX = 0111...1111 (31个1)
                    +1
=        1000...0000        ← 这恰好是 INT_MIN 的补码表示
```

**检测溢出的方法**：

```c
// 方法1：提前检查
int safe_add(int a, int b) {
    if (b > 0 && a > INT_MAX - b) { /* 正溢出 */ }
    if (b < 0 && a < INT_MIN - b) { /* 负溢出 */ }
    return a + b;
}

// 方法2：用更大的类型
long long sum = (long long)a + (long long)b;
if (sum > INT_MAX || sum < INT_MIN) { /* 溢出 */ }

// 方法3：无符号数检测（利用补码环绕特性）
unsigned int ua = (unsigned int)a;
unsigned int ub = (unsigned int)b;
unsigned int usum = ua + ub;
if (usum > INT_MAX * 2U + 1U) { /* 溢出 */ }

// 方法4：编译器内置函数
// GCC/Clang: __builtin_add_overflow(a, b, &result)
// 返回 true 表示溢出
```

### 11. 无符号数与有符号数的转换

补码的二进制表示与无符号数的二进制表示在位模式上完全相同，只是解释不同：

```c
#include <stdio.h>

int main() {
    int signed_val = -1;
    unsigned int unsigned_val = (unsigned int)signed_val;

    // 位模式完全相同：11111111 11111111 11111111 11111111
    printf("signed:   %d\n", signed_val);      // -1
    printf("unsigned: %u\n", unsigned_val);     // 4294967295

    // 危险：无符号与有符号比较
    int x = -1;
    unsigned int y = 1;
    if (x < y) {           // 期望为真，但实际为假！
        printf("x < y\n"); // 不会执行
    } else {
        printf("x >= y\n"); // 会执行！x 被隐式转为 unsigned，变成 4294967295
    }

    return 0;
}
```

**C 标准对有符号数表示的规定**：

C 标准允许三种有符号整数表示：原码、反码、补码。但 C23 标准已规定**只允许补码**。

```c
// C23 之前：三种表示都合法
// C23 起：只允许补码

// 这意味着以下代码在 C23 后行为完全确定：
int x = -1;
// 所有用补码的机器：x 的位模式是全1
// 原码机器（已绝迹）：x 的位模式是 1000...0001
// 反码机器（已绝迹）：x 的位模式是 1111...1110

// 实际上，从 2000 年代起所有主流 CPU 都使用补码
// C23 只是把既成事实写进了标准
```

### 12. 补码与 CPU 标志位

CPU 的算术逻辑单元（ALU）执行加法后会设置标志位，这些标志位与补码密切相关：

```
以 x86 为例，执行 ADD 指令后设置以下标志位：

  CF (Carry Flag)     — 无符号溢出标志
  OF (Overflow Flag)  — 有符号溢出标志
  SF (Sign Flag)      — 结果的符号位（最高位）
  ZF (Zero Flag)      — 结果是否为零

示例：8 位加法

  127 + 1 = 128（有符号溢出）
  01111111 + 00000001 = 10000000
  CF=0（无符号没溢出，128 < 256）
  OF=1（有符号溢出了，+127 + 1 应该是 +128，但变成了 -128）
  SF=1（结果是负数）
  ZF=0（结果不为零）

  255 + 1 = 256（无符号溢出）
  11111111 + 00000001 = 1 00000000
  CF=1（无符号溢出，256 > 255）
  OF=0（有符号没溢出，-1 + 1 = 0）
  SF=0
  ZF=1

  关键：CPU 不知道你把操作数当有符号还是无符号
  它同时设置 CF 和 OF，由软件决定看哪个
```

**C/C++ 中如何检测溢出**：

```c
// 有符号溢出在 C 中是未定义行为（UB）！
// 不能依赖标志位，因为编译器可能优化掉溢出检查

// 错误示例（编译器可能优化掉检查）：
int add(int a, int b) {
    int sum = a + b;
    if (sum < a) { /* 优化器可能删除这个检查，因为"有符号溢出不可能发生" */ }
    return sum;
}

// 正确做法：在加法之前检查
int safe_add(int a, int b) {
    if ((b > 0 && a > INT_MAX - b) || (b < 0 && a < INT_MIN - b)) {
        // 处理溢出
    }
    return a + b;
}
```

### 13. 补码的加减法电路原理

补码最核心的优势：**加法和减法用同一套电路**。

```
加法器电路（简化）：

  输入 A[7:0] 和 B[7:0]
  结果 S[7:0] = A + B（丢弃最高位进位）

  做 A + B 时：直接输入
  做 A - B 时：将 B 取反加1后输入（即输入 ~B + 1）

  一套加法器搞定加减法！
```

**补码乘法**：

```
补码乘法比加法复杂，常见算法：

1. Booth 算法：通过观察乘数中相邻位的差异来决定加/减/不变
   优点：统一处理有符号和无符号乘法

2. 现代CPU做法：使用更宽的乘法器，直接得到双倍宽度的结果
   32 × 32 → 64 位结果，高位和低位分别可取

   ARM: SMULL RdLo, RdHi, Rn, Rm  （有符号乘法）
   x86: IMUL 指令
```

**补码除法**：

```
补码除法的特殊情况：

  INT_MIN / -1 = ?

  数学上：-2147483648 / -1 = 2147483648
  但 2147483648 > INT_MAX，结果溢出！
  x86 上会触发硬件异常（除法溢出）
  C 标准中这是未定义行为

  另一个陷阱：负数除法向零取整
  -7 / 2 = -3（不是 -4）
  -7 % 2 = -1（余数与被除数同号，C99 规定）
```

### 14. BCD 码 — 金融领域的另一种表示

BCD（Binary-Coded Decimal）用 4 位二进制表示 1 个十进制数字，不依赖补码。

```
8421 BCD 编码（最常用）：

  十进制    BCD
    0      0000
    1      0001
    2      0010
    5      0101
    9      1001

  举例：25 的 BCD = 0010 0101（不是 00011001）

  注意：4 位二进制能表示 0~15，BCD 只用 0~9
  1010~1111 在 BCD 中是非法编码
```

**为什么金融系统用 BCD 而不用补码？**

```
补码的 0.1 无法精确表示（二进制是无限循环小数）
BCD 每个十进制位独立存储，0.1 就是 0001，精确无误

银行账户：$1000000.01
  补码浮点数：可能有 ±0.005 的误差
  BCD：精确到分，没有误差

COBOL 语言至今仍在金融领域广泛使用，其默认数值格式就是 BCD
大型机（IBM Z系列）有专门的 BCD 硬件指令
```

### 15. 大端序与小端序 — 补码在内存中的存储

多字节整数在内存中的存储顺序取决于 CPU 的字节序：

```
int x = 0x01020304;  // 补码表示

大端序（Big-Endian，网络字节序）：
  地址:    0x00  0x01  0x02  0x03
  内容:    01    02    03    04    ← 高位在前（人类阅读顺序）

小端序（Little-Endian，x86/ARM）：
  地址:    0x00  0x01  0x02  0x03
  内容:    04    03    02    01    ← 低位在前（最低有效字节在最低地址）

负数示例：int x = -1 = 0xFFFFFFFF

大端序：FF FF FF FF
小端序：FF FF FF FF    ← 全 FF 时看起来一样
```

```c
// 检测字节序
int x = 1;
if (*(char*)&x == 1) {
    printf("小端序\n");    // x86, ARM (大多数模式)
} else {
    printf("大端序\n");    // SPARC, PowerPC (某些模式), 网络传输
}

// 网络编程中必须转换
#include <arpa/inet.h>   // 或 <winsock2.h>
uint32_t host_order = 0x12345678;
uint32_t net_order = htonl(host_order);   // 主机序 → 网络序（大端）
```

### 16. 补码与浮点数的关系

IEEE 754 浮点数 = 符号位（1位）+ 移码指数（8/11位）+ 尾数（23/52位）

```
float 的 -0.75 如何存储？

-0.75 = -1.1 × 2^(-1)

符号位：1（负数，使用原码方式，不是补码！）
指数位：-1 + 127 = 126 = 01111110（移码）
尾数位：.10000000000000000000000（去掉前导1）

完整32位：1 01111110 10000000000000000000000

关键区别：
  整数用补码：符号位参与运算
  浮点数用原码+移码：符号位单独处理，指数用移码，尾数用原码
```

**浮点数的 -0 和 +0**：

```c
#include <stdio.h>
#include <math.h>

int main() {
    // 浮点数有 +0 和 -0（与补码整数不同！）
    double pos_zero = +0.0;
    double neg_zero = -0.0;

    printf("+0 == -0: %d\n", pos_zero == neg_zero);     // 1（相等）
    printf("1/+0 = %f\n", 1.0 / pos_zero);               // +inf
    printf("1/-0 = %f\n", 1.0 / neg_zero);               // -inf
    printf("signbit(+0) = %d\n", signbit(pos_zero));      // 0
    printf("signbit(-0) = %d\n", signbit(neg_zero));      // 非零

    // 整数没有 -0（补码中零唯一）
    int izero = 0;
    // 不存在 -0 的整数

    return 0;
}
```

### 17. 补码在安全与密码学中的应用

补码的溢出环绕特性在密码学和哈希算法中被广泛利用：

```c
// CRC32 利用补码溢出实现多项式除法
// MD5/SHA-256 内部使用 32/64 位补码加法（模 2^32 / 模 2^64）

// 哈希函数中的"混合"操作利用补码溢出
uint32_t hash_mix(uint32_t x) {
    x = ((x >> 16) ^ x) * 0x45d9f3b;   // 乘法溢出是预期行为
    x = ((x >> 16) ^ x) * 0x45d9f3b;
    x = (x >> 16) ^ x;
    return x;
}

// 随机数生成器利用补码溢出
// 线性同余法：x = (a * x + c) mod m
// 当 m = 2^32 时，补码溢出自动完成取模
uint32_t lcg(uint32_t x) {
    return x * 1103515245 + 12345;  // 自动 mod 2^32
}

// TEA/XTEA 加密算法利用补码溢出
void tea_encrypt(uint32_t* v, const uint32_t* k) {
    uint32_t v0 = v[0], v1 = v[1], sum = 0;
    for (int i = 0; i < 32; i++) {
        sum += 0x9E3779B9;                    // 补码溢出 = mod 2^32
        v0 += ((v1 << 4) + k[0]) ^ (v1 + sum) ^ ((v1 >> 5) + k[1]);
        v1 += ((v0 << 4) + k[2]) ^ (v0 + sum) ^ ((v0 >> 5) + k[3]);
    }
    v[0] = v0; v[1] = v1;
}
```

### 18. 历史演变 — 从原码到补码

```
1940s：早期计算机使用原码
  - ENIAC 使用十进制原码
  - 问题：加减法需要两套电路，+0/-0 混乱

1950s：反码短暂流行
  - CDC 6600 使用反码
  - 优点：减法变加法
  - 缺点：循环进位，+0/-0

1960s：补码成为主流
  - IBM System/360 确立补码标准
  - PDP-11, VAX 使用补码
  - 从此所有商用 CPU 都使用补码

1970s-1980s：C 语言允许三种表示
  - C89 标准允许原码/反码/补码
  - 但实际上所有 C 实现都用补码

2023：C23 标准规定只用补码
  - C23 正式废除原码和反码
  - 补码成为 C 语言唯一合法的有符号整数表示
```

### 19. 全景总结

| 编码 | 零的表示 | 减法→加法 | 值域(8位) | 硬件复杂度 | 应用场景 |
|------|---------|----------|----------|-----------|---------|
| 原码 | 两种 | ❌ | -127~+127 | 高 | IEEE 754 尾数 |
| 反码 | 两种 | ⚠️ 循环进位 | -127~+127 | 中 | IPv4 校验和 |
| 补码 | **唯一** | ✅ | -128~+127 | **最低** | **所有整数运算** |
| 移码 | 唯一 | N/A | -128~+127 | 低 | IEEE 754 指数 |
| BCD | 唯一 | ❌ | 0~99 | 高 | 金融/COBOL |

**知识关联图**：

```
                        ┌─ 原码 ─── IEEE 754 浮点尾数
                        │
补码核心 ─── 三种编码 ──┼─ 反码 ─── IPv4 校验和 / 按位取反
                        │
                        ├─ 补码 ──┬── 整数运算（CPU唯一使用）
                        │         ├── 符号扩展 / 零扩展
                        │         ├── 整数提升 / 隐式转换
                        │         ├── 溢出检测 / UB
                        │         ├── 位运算技巧
                        │         ├── 乘除法（Booth/移位）
                        │         └── 密码学/哈希
                        │
                        └─ 移码 ─── IEEE 754 浮点指数

横向关联：
  补码 ←→ 大小端序（多字节存储）
  补码 ←→ CPU 标志位（CF/OF/SF/ZF）
  补码 ←→ 浮点数（符号位原码 + 指数移码 + 尾数原码）
  补码 ←→ BCD 码（金融精度 vs 二进制效率）
```

**记忆要点**：
1. 计算机内部只用补码存储整数，原码和反码是理解补码的阶梯
2. 补码 = 按位取反 + 1；本质是模运算
3. 全 1 是 -1，全 0 是 0，1000...0 是最小负数
4. 符号扩展填符号位，零扩展填 0——char 的符号性决定扩展方式
5. 有符号与无符号混用时，有符号被隐式转为无符号——这是最常见 Bug 来源
6. 溢出是环绕的，有符号溢出是未定义行为——编译器可能优化掉溢出检查
7. 移码 = 补码符号位取反，用于浮点指数——可以直接比较大小
8. 浮点数的符号位用原码（有 +0/-0），整数用补码（零唯一）
9. 负数右移 ≠ 除法（右移向负无穷取整，除法向零取整）
10. BCD 码用于金融——精度比效率重要
