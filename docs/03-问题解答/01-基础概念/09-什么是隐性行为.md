# 什么是隐性行为
> 📖 相关章节：[核心机制](../../02-CPP/05-核心机制.md)

> "The devil is in the details" — 细节决定成败

### 1. 本质速解

**隐性行为** = 编译器自动帮你做的事，你没写代码但编译器默默执行了。C 和 C++ 都有，但 C++ 远多于 C。

***

### 2. C 的隐性行为

| 行为 | 示例 | 说明 |
|------|------|------|
| 整型提升 | `char + char` → `int + int` | 小于 int 的整数类型运算前自动提升到 int |
| 隐式类型转换 | `int` 赋给 `double` | 整型→浮点、浮点→整型、指针转换 |
| 数组退化 | 数组名 → 首元素指针 | `int a[10]; f(a);` → 传的是 `int*` |
| 默认 int（C89） | `foo()` → 返回 int | C89 中未指定返回类型默认 int |
| 隐式函数声明（C89） | 未声明函数默认返回 int | C99 后移除 |

### 3. C++ 额外的隐性行为

| 行为 | 示例 | 说明 |
|------|------|------|
| 构造函数隐式转换 | `void f(string s); f("hello");` | 隐式构造 string |
| 拷贝省略 | RVO/NRVO | 编译器优化掉拷贝/移动构造 |
| 默认成员函数 | 编译器生成默认构造/析构/拷贝/移动 | 特定条件下自动生成 |
| 运算符重载 | `a + b` 可能调用 `operator+` | 编译期查找运算符重载 |
| 名称查找 | ADL（参数依赖查找） | 根据实参命名空间查找函数 |
| 模板实例化 | 隐式推导模板参数 | `f(42)` → `f<int>(42)` |
| 虚函数调用 | 通过 vtable 间接调用 | 运行时多态 |

### 4. 隐性行为的代码陷阱

#### 1. 陷阱1：整型提升导致的意外

```cpp
char a = 100, b = 100;
char c = a + b;  // a+b 是 int 类型 (200)，赋值给 char 可能溢出
// -128 ≤ char ≤ 127，200 超出范围 → 实现定义行为
```

#### 2. 陷阱2：隐式转换导致意外匹配

```cpp
void foo(int);
void foo(double);

void bar() {
    float f = 3.14f;
    foo(f);  // 调用 foo(double) 而不是 foo(int)
    // 浮点提升优先于浮点→整型转换
}
```

#### 3. 陷阱3：ADL 导致的意外调用

```cpp
namespace ns {
    struct S {};
    void f(S) {}
}

int main() {
    ns::S s;
    f(s);  // ADL 找到 ns::f，不需要 using
    // 如果全局也有 f(S)，则产生歧义
}
```

#### 4. 陷阱4：隐式构造导致代码歧义

```cpp
struct Timer {
    Timer(int ms) {}  // 非 explicit
};

void schedule(Timer t);

schedule(1000);  // 隐式构造 Timer(1000)，可读性差
// 加上 explicit 可禁止此类调用
```

#### 5. 陷阱5：默认拷贝构造的浅拷贝问题

```cpp
class Buffer {
    int* data;
    size_t size;
public:
    Buffer(size_t n) : data(new int[n]), size(n) {}
    // 编译器默认生成拷贝构造函数 → 浅拷贝！
    // ~Buffer() { delete[] data; }  // 析构时 double free!
};

void bad() {
    Buffer a(10);
    Buffer b(a);  // 默认拷贝 → a.data == b.data
    // 函数结束 → 两个对象析构 → double free!
}
```

### 5. 编译器差异与检测

#### 1. 不同编译器的隐性行为差异

| 行为 | GCC | Clang | MSVC |
|------|:---:|:---:|:---:|
| RVO 强制（C++17） | ✅ | ✅ | ✅ |
| 隐式窄化转换警告 | `-Wnarrowing` | 默认警告 | 默认警告 |
| 整型提升符号性 | 实现定义 | 实现定义 | 实现定义 |
| 隐式函数声明（C89） | 警告 | 警告 | 警告 |

#### 2. 检测隐性行为的编译器标志

```bash
# GCC/Clang
g++ -Wall -Wextra -Wconversion -Wsign-conversion -Wshadow

# Clang 更严格
clang++ -Weverything

# MSVC
cl /Wall /W4
```

### 6. 如何控制隐性行为

```cpp
// 1. 禁止隐式转换
class String {
public:
    explicit String(const char* s);  // 加 explicit
};
String s = "hello";  // 编译错误
String s("hello");   // OK

// 2. 禁止默认生成
class NonCopyable {
public:
    NonCopyable(const NonCopyable&) = delete;
    NonCopyable& operator=(const NonCopyable&) = delete;
};

// 3. 禁止隐式窄化转换（C++11 列表初始化）
int x = 3.14;      // OK（隐式截断）
int y{3.14};       // 编译错误（窄化转换）

// 4. 显式控制模板实例化
template class std::vector<int>;  // 显式实例化

// 5. override 关键字防止虚函数误写
struct Base {
    virtual void foo(int);
};
struct Derived : Base {
    void foo(int) override;  // 正确：覆盖
    // void foo(double) override;  // 编译错误：没有覆盖任何函数
};
```

### 7. 极简总结

**C 和 C++ 都有隐性行为 → C++ 远多于 C → 用 explicit/delete/{}/override 控制 → 开启编译器警告检测陷阱**
