# C语言如何实现访问控制
> 📖 相关章节：[运算符与表达式](../../01-C语言/02-运算符与表达式.md)、[控制结构](../../01-C语言/03-控制结构.md)、[函数](../../01-C语言/04-函数.md)、[基础特性](../../02-CPP/01-基础特性.md)、[命名空间](../../02-CPP/02-命名空间与编码规范.md)

### 1. 本质速解

C 语言没有 `private/public/protected` 关键字，但通过**头文件与源文件分离 + 不透明指针 + static 限制 + 命名约定**四板斧，完全可以实现与 C++ 等价的访问控制效果。

***

### 2. C语言访问控制的本质

C 语言的访问控制不是语言层面的强制约束，而是**编译与链接层面的可见性控制**：

| 层面 | 控制手段 | 效果 |
|------|----------|------|
| 编译期 | 头文件只暴露声明，不暴露定义 | 外部看不到结构体成员 |
| 编译期 | `static` 限制符号的链接属性 | 外部无法引用该符号 |
| 链接期 | 不导出符号 | 外部无法链接到内部函数/变量 |
| 约定层 | 命名规范 | 提醒开发者不要调用 |

核心原则：**对外暴露什么写在 `.h`，对内隐藏什么写在 `.c`**。

### 3. 手法1：不透明指针（Opaque Pointer）模式详解

不透明指针是 C 语言实现封装的黄金模式，广泛用于 GLib、SQLite、OpenSSL 等知名库。

**核心思想**：头文件只前向声明结构体，不暴露定义；外部只能拿到指针，无法访问成员。

**头文件 `stack.h`（公开接口）：**

```c
#ifndef STACK_H
#define STACK_H

// 只前向声明，不暴露结构体定义
typedef struct Stack Stack;

// 公开接口函数
Stack* stack_create(int capacity);
void   stack_destroy(Stack* s);
int    stack_push(Stack* s, int value);
int    stack_pop(Stack* s, int* out_value);
int    stack_size(const Stack* s);
int    stack_is_empty(const Stack* s);

#endif
```

**源文件 `stack.c`（隐藏实现）：**

```c
#include "stack.h"
#include <stdlib.h>
#include <string.h>

// 完整定义藏在 .c 文件中
struct Stack {
    int*  data;      // 外部完全看不到
    int   top;       // 外部无法直接访问
    int   capacity;  // 外部无法直接修改
};

Stack* stack_create(int capacity) {
    Stack* s = (Stack*)malloc(sizeof(Stack));
    if (!s) return NULL;
    s->data = (int*)malloc(sizeof(int) * capacity);
    if (!s->data) { free(s); return NULL; }
    s->top = -1;
    s->capacity = capacity;
    return s;
}

void stack_destroy(Stack* s) {
    if (s) {
        free(s->data);
        free(s);
    }
}

int stack_push(Stack* s, int value) {
    if (!s || s->top + 1 >= s->capacity) return -1;
    s->data[++s->top] = value;
    return 0;
}

int stack_pop(Stack* s, int* out_value) {
    if (!s || s->top < 0) return -1;
    *out_value = s->data[s->top--];
    return 0;
}

int stack_size(const Stack* s) {
    return s ? s->top + 1 : 0;
}

int stack_is_empty(const Stack* s) {
    return s ? s->top < 0 : 1;
}
```

**使用者代码 `main.c`：**

```c
#include "stack.h"
#include <stdio.h>

int main(void) {
    Stack* s = stack_create(100);
    stack_push(s, 42);
    stack_push(s, 99);

    // s->top = 5;       // 编译错误！struct Stack 的定义不可见
    // s->data[0] = 0;   // 编译错误！无法访问成员

    int val;
    stack_pop(s, &val);
    printf("Popped: %d, Size: %d\n", val, stack_size(s));

    stack_destroy(s);
    return 0;
}
```

**效果**：外部只能通过接口函数操作，无法直接访问或修改内部成员，实现了真正的封装。

### 4. 手法2：static 限制文件作用域

`static` 关键字让全局变量和函数只在当前 `.c` 文件内可见，等效于 C++ 的 `private`。

**static 函数 —— 模块私有函数：**

```c
// stack.c
#include "stack.h"

struct Stack { /* ... */ };

// 内部辅助函数，外部完全无法调用
static int stack_grow(Stack* s) {
    int new_cap = s->capacity * 2;
    int* new_data = (int*)realloc(s->data, sizeof(int) * new_cap);
    if (!new_data) return -1;
    s->data = new_data;
    s->capacity = new_cap;
    return 0;
}

// 内部校验函数
static int stack_validate(const Stack* s) {
    return s && s->data && s->top >= -1 && s->top < s->capacity;
}

// 公开函数可以调用 static 函数
int stack_push(Stack* s, int value) {
    if (!stack_validate(s)) return -1;
    if (s->top + 1 >= s->capacity) {
        if (stack_grow(s) != 0) return -1;
    }
    s->data[++s->top] = value;
    return 0;
}
```

**static 全局变量 —— 模块私有状态：**

```c
// stack.c

// 模块内部计数器，外部无法 extern 引用
static int stack_instance_count = 0;

Stack* stack_create(int capacity) {
    Stack* s = (Stack*)malloc(sizeof(Stack));
    if (!s) return NULL;
    // ...
    stack_instance_count++;  // 内部维护
    return s;
}

void stack_destroy(Stack* s) {
    if (s) {
        stack_instance_count--;
        free(s->data);
        free(s);
    }
}
```

**static 与非 static 的链接差异：**

```c
// file1.c
static int   private_var = 42;       // 内部链接，仅 file1.c 可见
int          public_var = 100;       // 外部链接，其他文件可 extern
static void  private_func(void) {}   // 内部链接，仅 file1.c 可调用
void         public_func(void) {}    // 外部链接，其他文件可调用

// file2.c
extern int public_var;               // OK，可以引用
extern int private_var;              // 链接错误！找不到 private_var
```

### 5. 手法3：头文件分两层（公开头文件 + 私有头文件）

大型项目中，将头文件分为公开和私有两层，是模块化设计的标准做法。

**目录结构：**

```
项目/
├── include/                  # 公开头文件目录（发布给用户）
│   └── stack.h
├── src/                      # 源文件目录（不发布）
│   ├── stack.c
│   └── stack_internal.h      # 私有头文件（仅内部使用）
└── Makefile
```

**公开头文件 `include/stack.h`：**

```c
#ifndef STACK_H
#define STACK_H

typedef struct Stack Stack;

Stack* stack_create(int capacity);
void   stack_destroy(Stack* s);
int    stack_push(Stack* s, int value);
int    stack_pop(Stack* s, int* out_value);

#endif
```

**私有头文件 `src/stack_internal.h`：**

```c
#ifndef STACK_INTERNAL_H
#define STACK_INTERNAL_H

#include "stack.h"

// 完整结构体定义，只有内部模块才能包含此头文件
struct Stack {
    int*  data;
    int   top;
    int   capacity;
};

// 内部函数声明（定义在 .c 中用 static）
int  stack_grow(Stack* s);
int  stack_validate(const Stack* s);
void stack_log(const char* msg);

#endif
```

**源文件 `src/stack.c`：**

```c
#include "stack_internal.h"   // 包含私有头文件，可访问完整定义
#include <stdlib.h>
#include <stdio.h>

static void stack_log(const char* msg) {
    fprintf(stderr, "[Stack] %s\n", msg);
}

// 实现中可以自由访问所有成员
int stack_push(Stack* s, int value) {
    if (s->top + 1 >= s->capacity) {
        stack_log("growing stack");
        if (stack_grow(s) != 0) return -1;
    }
    s->data[++s->top] = value;
    return 0;
}
```

**关键**：用户拿不到 `src/stack_internal.h`，自然无法看到结构体定义和内部函数。

### 6. 手法4：命名约定做"软访问控制"

命名约定虽然不是编译器强制的，但在团队协作中是重要的约定：

| 命名模式 | 含义 | 等效 C++ 权限 | 示例 |
|----------|------|---------------|------|
| `_module_func()` | 下划线开头 = 内部私有 | private | `_stack_grow()` |
| `module_func()` | 无前缀 = 公开接口 | public | `stack_push()` |
| `MODULE_FUNC()` | 全大写 = 宏/常量 | - | `STACK_MAX_SIZE` |
| `module_internal_*` | explicit 标记内部 | private | `stack_internal_validate()` |

```c
// 公开接口（用户可调用）
Stack* stack_create(int capacity);
void   stack_destroy(Stack* s);
int    stack_push(Stack* s, int value);

// 内部函数（约定不调用，但编译器不阻止）
int  _stack_resize(Stack* s, int new_cap);
void _stack_debug_dump(const Stack* s);
```

**注意**：C 标准保留以下划线开头后跟大写字母的标识符（如 `_Stack`），以及双下划线开头的标识符（如 `__stack`），用户代码不应使用。

### 7. 完整可运行示例：链表模块

以下是一个完整的链表模块，综合运用所有访问控制手法：

**`linked_list.h`（公开头文件）：**

```c
#ifndef LINKED_LIST_H
#define LINKED_LIST_H

typedef struct LinkedList LinkedList;

LinkedList* list_create(void);
void        list_destroy(LinkedList* list);
int         list_append(LinkedList* list, int value);
int         list_prepend(LinkedList* list, int value);
int         list_remove(LinkedList* list, int value);
int         list_size(const LinkedList* list);
void        list_print(const LinkedList* list);

#endif
```

**`linked_list.c`（隐藏实现）：**

```c
#include "linked_list.h"
#include <stdlib.h>
#include <stdio.h>

// 节点结构：外部完全不可见
typedef struct ListNode {
    int              value;
    struct ListNode* next;
} ListNode;

// 链表结构：外部只知 LinkedList*，不知内部
struct LinkedList {
    ListNode* head;
    int       size;
};

// 模块私有：创建节点
static ListNode* node_create(int value) {
    ListNode* node = (ListNode*)malloc(sizeof(ListNode));
    if (!node) return NULL;
    node->value = value;
    node->next  = NULL;
    return node;
}

// 模块私有：销毁节点链
static void node_destroy_chain(ListNode* node) {
    while (node) {
        ListNode* next = node->next;
        free(node);
        node = next;
    }
}

// 模块私有：实例计数
static int list_instance_count = 0;

// 公开接口
LinkedList* list_create(void) {
    LinkedList* list = (LinkedList*)malloc(sizeof(LinkedList));
    if (!list) return NULL;
    list->head = NULL;
    list->size = 0;
    list_instance_count++;
    return list;
}

void list_destroy(LinkedList* list) {
    if (list) {
        node_destroy_chain(list->head);
        list_instance_count--;
        free(list);
    }
}

int list_append(LinkedList* list, int value) {
    if (!list) return -1;
    ListNode* node = node_create(value);
    if (!node) return -1;
    if (!list->head) {
        list->head = node;
    } else {
        ListNode* cur = list->head;
        while (cur->next) cur = cur->next;
        cur->next = node;
    }
    list->size++;
    return 0;
}

int list_size(const LinkedList* list) {
    return list ? list->size : 0;
}

void list_print(const LinkedList* list) {
    if (!list) { printf("(null)\n"); return; }
    ListNode* cur = list->head;
    printf("[");
    while (cur) {
        printf("%d", cur->value);
        if (cur->next) printf(" -> ");
        cur = cur->next;
    }
    printf("] (size=%d)\n", list->size);
}
```

**`main.c`（使用者）：**

```c
#include "linked_list.h"
#include <stdio.h>

int main(void) {
    LinkedList* list = list_create();

    list_append(list, 10);
    list_append(list, 20);
    list_append(list, 30);
    list_print(list);  // [10 -> 20 -> 30] (size=3)

    // list->head = NULL;          // 编译错误！结构体定义不可见
    // list->size = 999;           // 编译错误！
    // node_create(42);            // 编译错误！static 函数不可见

    list_destroy(list);
    return 0;
}
```

### 8. 与C++访问控制的对比

| 特性 | C 语言手法 | C++ 关键字 | 强制性 |
|------|-----------|-----------|--------|
| 隐藏成员变量 | 不透明指针 | `private` | C++ 编译器强制；C 编译器因定义不可见而强制 |
| 隐藏成员函数 | `static` 函数 | `private` 方法 | C++ 编译器强制；C 编译器因符号不导出而强制 |
| 隐藏辅助类型 | 定义放在 `.c` 中 | `private` 嵌套类 | C++ 编译器强制；C 编译器因定义不可见而强制 |
| 公开接口 | 头文件中声明 | `public` | 语义等价 |
| 保护继承 | 不支持 | `protected` | C 无法实现 |
| 友元 | 不支持 | `friend` | C 无法实现 |
| 运行时检查 | 无 | 访问控制是编译期 | 均为编译期 |
| 绕过方式 | 包含私有头文件 | 指针偏移/宏技巧 | 均可被恶意绕过 |

**C 语言访问控制的优势：**

- 二进制层面更彻底：没有结构体定义，连偏移量都不知道
- ABI 稳定：修改内部结构不影响外部编译
- 编译隔离：修改 `.c` 不需要重新编译使用者

**C 语言访问控制的劣势：**

- 语法冗长，需要手动维护头文件与源文件的对应关系
- 无法实现 `protected`（继承场景的受保护访问）
- 命名约定只是软约束，没有编译器强制

### 9. 常见陷阱

**陷阱1：在头文件中暴露了结构体定义**

```c
// stack.h — 错误做法！
typedef struct Stack {
    int* data;   // 暴露了！外部可以直接访问
    int  top;    // 暴露了！
    int  capacity;
} Stack;
```

**陷阱2：忘记前向声明导致编译错误**

```c
// stack.h — 错误！
typedef struct Stack Stack;  // 前向声明 OK
Stack* stack_create(int cap);

// 但如果在 .h 中有函数参数用到了 struct 内部类型：
void stack_foo(Stack* s, int* data_ptr);  // OK，只用指针
// void stack_bar(Stack* s, int top);     // OK，int 是完整类型
// 但如果返回 struct 本身则不行：
// struct Stack stack_clone(struct Stack s);  // 错误！不完整类型
```

**陷阱3：static 函数放在头文件中**

```c
// utils.h — 错误！每个包含此头文件的 .c 都会生成一份 static 函数副本
static int helper(int x) { return x * 2; }

// 正确做法：放在 .c 中，或在 .h 中用 inline（C99+）
// inline int helper(int x) { return x * 2; }
```

**陷阱4：不透明指针的内存分配问题**

```c
// 错误：外部不知道结构体大小，无法栈上分配
// Stack s;           // 编译错误！不完整类型
// Stack* s = ...;    // 只能用指针，必须由库函数创建和销毁

// 正确：始终提供 create/destroy 对
Stack* s = stack_create(100);
// ... 使用 ...
stack_destroy(s);
s = NULL;  // 防止悬空指针
```

### 10. 最佳实践

1. **所有模块都使用不透明指针**：头文件只前向声明结构体，定义放在 `.c` 中
2. **内部函数一律加 `static`**：防止符号污染和命名冲突
3. **模块状态用 `static` 全局变量**：避免全局变量泄漏
4. **提供 create/destroy 函数对**：不透明指针必须由库管理生命周期
5. **头文件分公开/私有两层**：大型项目必须做的隔离
6. **命名约定保持一致**：`module_action()` 公开，`_module_internal()` 私有
7. **返回错误码而非直接暴露内部状态**：接口函数通过参数返回数据

### 11. 极简总结

**C 语言访问控制 = 不透明指针隐藏结构 + static 私有化函数/变量 + 头文件分层隔离 + 命名约定软约束**。四板斧组合，实现与 C++ private/public 等价的封装效果，且在二进制层面更加彻底。
