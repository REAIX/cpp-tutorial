# 作用域解析运算符 `::` 详解
> 📖 相关章节：[运算符与表达式](../../01-C语言/02-运算符与表达式.md)、[控制结构](../../01-C语言/03-控制结构.md)、[函数](../../01-C语言/04-函数.md)、[基础特性](../../02-CPP/01-基础特性.md)、[命名空间](../../02-CPP/02-命名空间与编码规范.md)

## 1. `::` 是什么？

`::` 是 C++ 中的**作用域解析运算符**（Scope Resolution Operator），用于指定访问哪个作用域中的标识符（变量、函数、类、命名空间等）。

## 2. 主要用途

### 1. 访问命名空间中的成员

```cpp
#include <iostream>

namespace MyNamespace {
    void func() {
        std::cout << "Hello from MyNamespace\n";
    }
}

int main() {
    MyNamespace::func();  // 使用 :: 访问命名空间中的函数
    return 0;
}
```

### 2. 访问类的静态成员

```cpp
class MyClass {
public:
    static int value;  // 静态成员变量
    static void func() {  // 静态成员函数
        std::cout << "Static function\n";
    }
};

int MyClass::value = 42;  // 类外定义静态成员

int main() {
    MyClass::func();      // 调用静态函数
    std::cout << MyClass::value << std::endl;  // 访问静态变量
    return 0;
}
```

### 3. 访问类的嵌套类型

```cpp
class Outer {
public:
    class Inner {
    public:
        void show() {
            std::cout << "Inner class\n";
        }
    };
};

int main() {
    Outer::Inner obj;  // 使用 :: 访问嵌套类
    obj.show();
    return 0;
}
```

### 4. 解决名称冲突

当局部变量与全局变量同名时，可以使用 `::` 访问全局变量：

```cpp
int x = 100;  // 全局变量

void func() {
    int x = 10;  // 局部变量
    std::cout << "局部 x: " << x << std::endl;     // 输出 10
    std::cout << "全局 x: " << ::x << std::endl;   // 输出 100
}
```

### 5. 在派生类中访问基类成员

```cpp
class Base {
protected:
    int value = 42;
};

class Derived : public Base {
public:
    void show() {
        std::cout << Base::value << std::endl;  // 访问基类成员
    }
};
```

### 6. 访问枚举类型的成员

```cpp
enum class Color { RED, GREEN, BLUE };

int main() {
    Color c = Color::RED;  // 使用 :: 访问枚举值
    return 0;
}
```

## 3. 使用场景总结

| 场景 | 语法示例 | 说明 |
|------|----------|------|
| 命名空间 | `std::cout` | 访问标准库命名空间 |
| 类静态成员 | `MyClass::value` | 访问类的静态变量/函数 |
| 嵌套类型 | `Outer::Inner` | 访问嵌套类/结构体 |
| 全局变量 | `::x` | 访问全局作用域的变量 |
| 基类成员 | `Base::member` | 在派生类中访问基类成员 |
| 枚举值 | `Color::RED` | 访问枚举类型的值 |

## 4. 注意事项

1. **全局作用域**：单独使用 `::` 表示全局作用域，如 `::printf` 表示全局的 printf 函数
2. **优先级**：`::` 是 C++ 中优先级最高的运算符之一
3. **命名空间别名**：可以使用 `using namespace` 简化命名空间访问，但不建议在头文件中使用

## 5. 示例对比

```cpp
#include <iostream>
using namespace std;  // 简化命名空间访问

int x = 100;  // 全局变量

namespace NS {
    int x = 200;
    void func() {
        int x = 300;
        cout << "局部 x: " << x << endl;       // 300
        cout << "NS::x: " << NS::x << endl;    // 200
        cout << "全局 x: " << ::x << endl;     // 100
    }
}

int main() {
    NS::func();
    return 0;
}
```

## 7. ADL 与 `::` 的交互

**ADL**（Argument-Dependent Lookup，参数依赖查找）是 C++ 的一项名称查找规则：调用函数时，编译器除了在当前作用域查找外，还会在函数参数的命名空间中查找候选函数。而使用 `::` 限定会**禁用 ADL**，只在该限定作用域中查找。

### ADL 查找 vs `::` 限定的区别

```cpp
#include <iostream>

namespace Math {
    struct Vec2 {
        float x, y;
    };

    // 在 Vec2 所属命名空间中定义 operator<<
    std::ostream& operator<<(std::ostream& os, const Vec2& v) {
        return os << "(" << v.x << ", " << v.y << ")";
    }

    void print(const Vec2& v) {
        std::cout << v << std::endl;  // ADL 生效：自动找到 Math::operator<<
    }
}

int main() {
    Math::Vec2 v{1.0f, 2.0f};

    // ADL 生效：虽然当前作用域没有 operator<<，
    // 但参数 v 属于 Math 命名空间，编译器会在 Math 中查找
    std::cout << v << std::endl;  // 正确：ADL 找到 Math::operator<<

    // 使用 :: 限定则禁用 ADL
    // ::print(v);  // 错误！全局作用域中没有 print，ADL 被禁用

    Math::print(v);  // 正确：显式限定到 Math 命名空间

    return 0;
}
```

### `::` 禁用 ADL 的典型场景

```cpp
#include <algorithm>
#include <iostream>
#include <vector>

namespace MyLib {
    struct Data { int value; };

    // 自定义 swap，比 std::swap 更高效
    void swap(Data& a, Data& b) {
        std::cout << "MyLib::swap 被调用\n";
        // ... 高效交换实现 ...
    }
}

int main() {
    MyLib::Data a{1}, b{2};

    // ADL 生效：找到 MyLib::swap 和 std::swap，重载决议选 MyLib::swap
    using std::swap;
    swap(a, b);  // 输出: MyLib::swap 被调用

    // :: 限定禁用 ADL，只在全局作用域查找
    // ::swap(a, b);  // 错误！全局作用域没有接受 Data 的 swap

    // 强制使用 std::swap，跳过 ADL
    std::swap(a, b);  // 调用 std::swap（可能效率低）

    return 0;
}
```

> **关键要点**：当你写 `func(args...)` 时，ADL 会参与查找；当你写 `NS::func(args...)` 或 `::func(args...)` 时，ADL 被完全禁用，编译器只在 `NS` 或全局作用域中查找。这就是为什么泛型代码中推荐使用 `using std::swap; swap(a, b);` 而非 `std::swap(a, b);`。

## 8. 模板中的依赖名查找

在模板中，名称查找分为**依赖名**（dependent name，依赖于模板参数）和**非依赖名**（non-dependent name，不依赖模板参数）。`::` 在这两类名称的查找中行为不同。

### `typename` 前缀的必要性

当通过 `::` 访问依赖于模板参数的类型时，必须加 `typename` 前缀，告知编译器该名称是一个类型：

```cpp
#include <iostream>
#include <vector>

template<typename T>
void print_size() {
    // 错误！T::size_type 是依赖名，编译器不知道它是类型还是变量
    // T::size_type s = 0;

    // 正确：typename 告诉编译器 T::size_type 是一个类型
    typename T::size_type s = 0;
    std::cout << "size_type 的大小: " << sizeof(s) << std::endl;
}

int main() {
    print_size<std::vector<int>>();  // 输出 size_type 的大小
    return 0;
}
```

### `::` 与模板特化的关系

`::` 可以用于访问模板特化中的成员，也可以用于访问模板模板参数的成员：

```cpp
#include <iostream>
#include <type_traits>

// 主模板
template<typename T>
struct Traits {
    using value_type = T;
    static constexpr bool is_integer = false;
};

// 特化：针对 int
template<>
struct Traits<int> {
    using value_type = int;
    static constexpr bool is_integer = true;
};

// 偏特化：针对指针类型
template<typename T>
struct Traits<T*> {
    using value_type = T;
    static constexpr bool is_pointer = true;
};

int main() {
    // 通过 :: 访问不同特化的成员
    std::cout << std::boolalpha;
    std::cout << "int 是整数: " << Traits<int>::is_integer << std::endl;   // true
    std::cout << "double 是整数: " << Traits<double>::is_integer << std::endl; // false

    // 访问偏特化的成员
    using PtrType = Traits<int*>::value_type;  // int
    std::cout << "指针的 value_type 大小: " << sizeof(PtrType) << std::endl;

    return 0;
}
```

### 依赖作用域 vs 非依赖作用域

```cpp
#include <iostream>

int value = 100;  // 全局变量

namespace Lib {
    int value = 200;

    template<typename T>
    void func() {
        // 非依赖名：在模板定义时查找，找到 Lib::value
        std::cout << "非依赖 value: " << value << std::endl;  // 200

        // 全局限定：始终查找全局作用域
        std::cout << "全局 value: " << ::value << std::endl;  // 100

        // 依赖名：在实例化时查找 T 的关联命名空间
        // 如果 T 定义在某个命名空间中，ADL 会参与查找
    }
}

int main() {
    Lib::func<int>();
    return 0;
}
```

> **关键要点**：非依赖名在模板定义时查找（两阶段查找的第一阶段），依赖名在实例化时查找（第二阶段）。`::` 限定使名称成为非依赖名，在定义时即确定查找结果。

## 9. 嵌套命名空间简化写法（C++17）

C++17 引入了嵌套命名空间的简化写法，用 `::` 连接各层命名空间，使代码更简洁。

### 传统写法 vs C++17 写法

```cpp
// 传统 C++11/14 写法：层层嵌套
namespace Company {
    namespace Project {
        namespace Module {
            class Engine {
            public:
                void run() {}
            };
        }
    }
}

// C++17 简化写法：一行搞定
namespace Company::Project::Module {
    class EngineV2 {
    public:
        void run() {}
    };
}

int main() {
    // 两种写法访问方式完全一致
    Company::Project::Module::Engine e1;
    Company::Project::Module::EngineV2 e2;
    e1.run();
    e2.run();
    return 0;
}
```

### 内联命名空间的简化写法

C++20 进一步支持了内联命名空间的简化写法：

```cpp
// C++17 写法
namespace Lib {
    inline namespace V2 {
        class Handler {};
    }
}

// C++20 简化写法
namespace Lib::inline V3 {
    class HandlerV3 {};
}

int main() {
    // 两种方式访问效果相同
    Lib::V2::Handler h1;   // 通过完整路径访问
    Lib::Handler h2;       // 内联命名空间可直接访问

    Lib::V3::HandlerV3 h3; // 通过完整路径访问
    Lib::HandlerV3 h4;     // 内联命名空间可直接访问

    return 0;
}
```

> **关键要点**：C++17 的 `namespace A::B::C` 纯粹是语法糖，语义与传统嵌套写法完全相同。但注意，简化写法中所有中间层命名空间都不能是 `inline` 的（除非用 C++20 的 `inline` 语法标记）。

## 10. `using` 声明与 `::` 的关系

`using` 声明和 `::` 限定是两种访问命名空间成员的方式，它们各有适用场景，理解它们的交互至关重要。

### `using namespace` vs `using NS::name`

```cpp
#include <iostream>
#include <vector>

namespace Math {
    void compute() { std::cout << "Math::compute\n"; }
    void analyze() { std::cout << "Math::analyze\n"; }
}

namespace Physics {
    void compute() { std::cout << "Physics::compute\n"; }
}

int main() {
    // using namespace：引入整个命名空间的所有名字
    using namespace Math;
    compute();  // Math::compute（无需 ::）
    analyze();  // Math::analyze

    // using 声明：只引入特定名字
    using Physics::compute;  // 引入 Physics::compute

    // 现在有两个 compute 在当前作用域：Math::compute 和 Physics::compute
    // 二义性！
    // compute();  // 错误：对 compute 的调用不明确

    // 使用 :: 限定消除二义性
    Math::compute();     // 明确调用 Math 版本
    Physics::compute();  // 明确调用 Physics 版本

    return 0;
}
```

### `using` 声明引入的名字与 `::` 限定的优先级

```cpp
#include <iostream>

namespace Lib {
    void func() { std::cout << "Lib::func\n"; }
    void func(int x) { std::cout << "Lib::func(int): " << x << "\n"; }
}

void func() { std::cout << "全局 func\n"; }

int main() {
    // using 声明引入的是整个重载集
    using Lib::func;

    func();        // 调用 Lib::func()
    func(42);      // 调用 Lib::func(int)

    // using 声明会隐藏外层作用域的同名名字
    // 全局的 func() 被 using 声明隐藏
    // func();  // 调用的是 Lib::func，不是全局 func

    // 使用 :: 强制访问全局版本
    ::func();  // 全局 func

    return 0;
}
```

### 在类继承中的 `using` 与 `::`

```cpp
#include <iostream>

class Base {
public:
    void func() { std::cout << "Base::func\n"; }
    void func(int x) { std::cout << "Base::func(int): " << x << "\n"; }
};

class Derived : public Base {
public:
    void func() { std::cout << "Derived::func\n"; }

    // using 声明将基类重载集引入派生类
    using Base::func;  // 引入 Base::func() 和 Base::func(int)
};

int main() {
    Derived d;
    d.func();     // Derived::func（派生类版本优先）
    d.func(10);   // Base::func(int)（通过 using 声明引入）

    // 使用 :: 显式选择基类版本
    d.Base::func();  // Base::func()

    return 0;
}
```

> **关键要点**：`using namespace` 引入所有名字且可能造成命名冲突；`using NS::name` 引入特定名字（含整个重载集）并隐藏外层同名名字；`::` 限定始终可以绕过 `using` 声明，直接访问指定作用域。

## 11. `::` 与友元

友元函数的定义位置和 `::` 的使用密切相关，这是 C++ 中容易混淆的知识点。

### 友元函数定义中的 `::` 含义

```cpp
#include <iostream>

namespace Graphics {
    class Point {
        double x_, y_;
    public:
        Point(double x, double y) : x_(x), y_(y) {}

        // 友元声明：声明一个外部函数为友元
        friend void print(const Point& p);

        // 友元声明：声明另一个命名空间的函数为友元
        friend void Logger::log(const Point& p);
    };

    // 友元定义在命名空间内——它属于 Graphics 命名空间
    void print(const Point& p) {
        // 友元可以访问私有成员
        std::cout << "(" << p.x_ << ", " << p.y_ << ")\n";
    }
}

namespace Logger {
    void log(const Graphics::Point& p) {
        // 友元可以访问私有成员
        // std::cout << p.x_ << ", " << p.y_ << "\n";
        std::cout << "Point logged\n";
    }
}

int main() {
    Graphics::Point p(1.0, 2.0);

    // 通过 ADL 或 :: 限定调用
    print(p);           // ADL 找到 Graphics::print
    Graphics::print(p); // :: 限定调用

    Logger::log(p);     // :: 限定调用另一个命名空间的友元

    return 0;
}
```

### 友元不在类的命名空间中（隐式友元陷阱）

```cpp
#include <iostream>

class Wrapper {
    int data_ = 42;
public:
    // 在类体内定义的友元函数，不属于任何命名空间！
    // 它是"自由函数"，不在 Wrapper 的命名空间中
    friend void show(const Wrapper& w) {
        std::cout << "data = " << w.data_ << std::endl;
    }
};

namespace Outer {
    class Box {
        int val_ = 99;
    public:
        // 同样，这个友元不在 Outer 命名空间中
        friend void reveal(const Box& b) {
            std::cout << "val = " << b.val_ << std::endl;
        }
    };
}

int main() {
    Wrapper w;
    show(w);  // 正确：通过 ADL 找到（参数 w 的类型是 Wrapper）

    // Outer::reveal(b);  // 错误！reveal 不在 Outer 命名空间中
    // ::reveal(b);       // 错误！reveal 不在全局作用域中

    // 只能通过 ADL 调用
    Outer::Box b;
    reveal(b);  // 正确：ADL 在 Box 的关联命名空间 Outer 中查找...
                // 但 reveal 实际上不在 Outer 中！
                // 注意：某些编译器可能允许，但标准行为是 ADL 仍可找到

    return 0;
}
```

> **关键要点**：在类体内定义的友元函数，虽然可以通过 ADL 被找到，但它**不属于**包围该类的命名空间。如果需要通过 `::` 限定调用友元函数，应在类外（命名空间内）定义它。

## 12. `::` 与全局 `new`/`delete`

`operator new` 和 `operator delete` 既可以是类的成员，也可以是全局版本。`::` 限定可以强制使用全局版本。

### 全局版本 vs 类成员版本

```cpp
#include <iostream>
#include <cstdlib>

class Pool {
public:
    // 类成员版本的 operator new/delete
    static void* operator new(std::size_t size) {
        std::cout << "Pool::operator new 被调用, 大小: " << size << "\n";
        return std::malloc(size);
    }

    static void operator delete(void* ptr) {
        std::cout << "Pool::operator delete 被调用\n";
        std::free(ptr);
    }

private:
    int data_[100];
};

int main() {
    // 使用类成员版本的 new/delete
    Pool* p1 = new Pool();   // 输出: Pool::operator new 被调用
    delete p1;               // 输出: Pool::operator delete 被调用

    // 使用 ::new 强制调用全局版本
    Pool* p2 = ::new Pool(); // 输出: （无，调用全局 operator new）
    ::delete p2;             // 输出: （无，调用全局 operator delete）

    return 0;
}
```

### 在自定义内存管理中的实际应用

```cpp
#include <iostream>
#include <cstdlib>

class Tracked {
public:
    static void* operator new(std::size_t size) {
        std::cout << "[跟踪] 分配 " << size << " 字节\n";
        void* p = std::malloc(size);
        if (!p) throw std::bad_alloc();
        return p;
    }

    static void operator delete(void* ptr) noexcept {
        std::cout << "[跟踪] 释放内存\n";
        std::free(ptr);
    }

    Tracked() { std::cout << "Tracked 构造\n"; }
    ~Tracked() { std::cout << "Tracked 析构\n"; }
};

int main() {
    std::cout << "=== 使用类自定义 new ===\n";
    Tracked* t1 = new Tracked;
    delete t1;

    std::cout << "\n=== 使用全局 new ===\n";
    Tracked* t2 = ::new Tracked;   // 全局 new 分配，但构造函数仍被调用
    ::delete t2;                    // 全局 delete 释放，但析构函数仍被调用

    std::cout << "\n=== placement new ===\n";
    char buffer[sizeof(Tracked)];
    // placement new 不调用任何 operator new，只在已有内存上构造
    Tracked* t3 = new(buffer) Tracked;
    t3->~Tracked();  // 显式调用析构函数

    return 0;
}
```

> **关键要点**：`::new` 强制使用全局 `operator new`，`::delete` 强制使用全局 `operator delete`。这在类自定义了内存管理时非常有用——当你需要绕过类的自定义分配器时。注意：`::new` 仍会调用构造函数，`::delete` 仍会调用析构函数，`::` 只影响内存分配/释放函数的选择。

## 13. `::` 在 SFINAE 和 type_traits 中的应用

`::` 在模板元编程中扮演核心角色，用于访问类型特征（type traits）的结果和检测类型成员。

### 检测成员是否存在（`void_t` 技巧）

```cpp
#include <iostream>
#include <type_traits>

// 主模板：默认情况下，类型 T 没有 value_type 成员
template<typename T, typename = void>
struct has_value_type : std::false_type {};

// 偏特化：如果 T::value_type 是合法类型，则匹配此版本
// void_t 的作用：如果 T::value_type 不存在，替换失败（SFINAE），
// 偏特化被丢弃，回退到主模板
template<typename T>
struct has_value_type<T, std::void_t<typename T::value_type>> : std::true_type {};

// 检测是否具有成员函数 size()
template<typename T, typename = void>
struct has_size_method : std::false_type {};

template<typename T>
struct has_size_method<T, std::void_t<decltype(std::declval<T>().size())>>
    : std::true_type {};

struct MyContainer {
    using value_type = int;
    std::size_t size() const { return 0; }
};

struct PlainType {};

int main() {
    std::cout << std::boolalpha;
    std::cout << "MyContainer 有 value_type: "
              << has_value_type<MyContainer>::value << std::endl;  // true
    std::cout << "PlainType 有 value_type: "
              << has_value_type<PlainType>::value << std::endl;    // false

    std::cout << "MyContainer 有 size(): "
              << has_size_method<MyContainer>::value << std::endl; // true
    std::cout << "PlainType 有 size(): "
              << has_size_method<PlainType>::value << std::endl;   // false

    return 0;
}
```

### `decltype` 与 `::` 配合进行类型检测

```cpp
#include <iostream>
#include <type_traits>
#include <vector>

// 检测类型 T 是否可以和 int 进行 == 比较
template<typename T, typename = void>
struct is_equality_comparable : std::false_type {};

template<typename T>
struct is_equality_comparable<T,
    std::void_t<decltype(std::declval<T>() == std::declval<int>())>>
    : std::true_type {};

// 检测 T 是否有嵌套类型 iterator
template<typename T, typename = void>
struct has_iterator : std::false_type {};

template<typename T>
struct has_iterator<T, std::void_t<typename T::iterator>> : std::true_type {};

int main() {
    std::cout << std::boolalpha;

    // is_equality_comparable 检测
    std::cout << "int 可与 int 比较: "
              << is_equality_comparable<int>::value << std::endl;    // true
    std::cout << "vector<int> 可与 int 比较: "
              << is_equality_comparable<std::vector<int>>::value << std::endl; // false

    // has_iterator 检测
    std::cout << "vector 有 iterator: "
              << has_iterator<std::vector<int>>::value << std::endl;  // true
    std::cout << "int 有 iterator: "
              << has_iterator<int>::value << std::endl;               // false

    return 0;
}
```

### `decltype(::std::declval<T>())` 的用法

```cpp
#include <iostream>
#include <type_traits>
#include <string>

// 在某些复杂场景中，使用 ::std 限定确保使用标准库版本
// 避免用户自定义的 std 命名空间污染
template<typename T>
struct SafeTraits {
    // 使用 ::std 确保引用的是全局 std 命名空间
    using type = decltype(::std::declval<T>());

    // 检测 T 是否可以转换为 std::string
    static constexpr bool can_convert_to_string =
        std::is_convertible_v<T, std::string>;
};

int main() {
    std::cout << std::boolalpha;
    std::cout << "const char* 可转为 string: "
              << SafeTraits<const char*>::can_convert_to_string << std::endl; // true
    std::cout << "int 可转为 string: "
              << SafeTraits<int>::can_convert_to_string << std::endl;         // false
    return 0;
}
```

> **关键要点**：`::` 在 SFINAE 中的核心作用是通过 `T::member_name` 访问依赖类型的成员，如果成员不存在则触发替换失败（而非硬错误）。`std::void_t<>` 是 C++17 引入的便利工具，使得这种检测模式更加简洁。

## 14. 常见陷阱

### 陷阱 1：`::` 隐藏重载集

```cpp
#include <iostream>

namespace Lib {
    void process(int x) { std::cout << "Lib::process(int): " << x << "\n"; }
    void process(double x) { std::cout << "Lib::process(double): " << x << "\n"; }
}

namespace App {
    // 这个 process 隐藏了 Lib 中的所有 process 重载
    void process(const char* s) { std::cout << "App::process(str): " << s << "\n"; }

    void run() {
        process(42);     // 错误！App::process 隐藏了 Lib::process
                         // App::process 只接受 const char*，没有 int 版本

        // 解决方案 1：使用 :: 限定
        Lib::process(42);     // 正确：显式指定 Lib 命名空间
        Lib::process(3.14);   // 正确

        // 解决方案 2：using 声明引入重载集
        using Lib::process;
        process(42);     // 正确：using 声明将 Lib::process 引入当前作用域
        process("hi");   // 正确：App::process 仍然可用
    }
}

int main() {
    App::run();
    return 0;
}
```

### 陷阱 2：`::` 与私有成员访问

```cpp
#include <iostream>

class Secret {
private:
    static int key;  // 私有静态成员
public:
    static int get_key() { return key; }
};

int Secret::key = 12345;

int main() {
    // Secret::key;  // 错误！虽然语法上可以用 :: 访问，
                     // 但 key 是私有的，不允许在类外访问

    std::cout << Secret::get_key() << std::endl;  // 正确：通过公有接口访问

    return 0;
}
```

> `::` 只解决作用域问题，不解决访问权限问题。即使使用 `::` 正确定位了成员，如果该成员是私有的，仍然无法访问。

### 陷阱 3：`::` 在模板基类中的问题

```cpp
#include <iostream>

template<typename T>
class Base {
public:
    void impl() { std::cout << "Base::impl\n"; }
    int value = 10;
};

template<typename T>
class Derived : public Base<T> {
public:
    void run() {
        // 错误！编译器在两阶段查找的第一阶段找不到 impl 和 value
        // 因为 Base<T> 是依赖基类，编译器不会在依赖基类中查找非依赖名
        // impl();         // 错误
        // std::cout << value;  // 错误

        // 解决方案 1：使用 this->（推荐）
        this->impl();              // 正确：this-> 使名称成为依赖名
        std::cout << this->value;  // 正确

        // 解决方案 2：使用 Base<T>:: 限定
        Base<T>::impl();           // 正确：显式限定到基类
        std::cout << Base<T>::value; // 正确

        // 解决方案 3：using 声明
        // using Base<T>::impl;
        // using Base<T>::value;
        // impl();  // 正确
    }
};

int main() {
    Derived<int> d;
    d.run();
    return 0;
}
```

### 陷阱 4：`::` 与全局变量遮蔽的隐蔽 bug

```cpp
#include <iostream>

int count = 0;  // 全局变量

namespace Stats {
    int count = 100;  // 命名空间变量

    void report() {
        int count = 5;  // 局部变量
        std::cout << count << std::endl;        // 5（局部）
        std::cout << Stats::count << std::endl; // 100（命名空间）
        std::cout << ::count << std::endl;      // 0（全局）
    }
}

class Counter {
public:
    static int count;  // 类静态成员
};

int Counter::count = 50;

void test() {
    std::cout << count << std::endl;     // 0（全局）
    std::cout << ::count << std::endl;   // 0（全局）
    std::cout << Counter::count << std::endl;  // 50（类静态）
}

int main() {
    Stats::report();
    std::cout << "---\n";
    test();
    return 0;
}
```

### 陷阱 5：`::` 在宏定义中的误用

```cpp
#include <iostream>

// 危险！宏中包含 ::，可能导致意外行为
#define GET_VALUE(obj) obj::value

class A {
public:
    static int value;
};
int A::value = 10;

class B {
public:
    static int value;
};
int B::value = 20;

int main() {
    std::cout << A::value << std::endl;  // 10

    // 宏展开为 obj::value，如果 obj 不是类型名则出错
    // GET_VALUE(A) 展开为 A::value，正确
    std::cout << GET_VALUE(A) << std::endl;  // 10

    // 但这种宏容易和变量混淆
    // A a;
    // GET_VALUE(a);  // 展开为 a::value，错误！变量不能用 ::

    // 正确做法：使用模板代替宏
    template<typename T>
    constexpr auto get_value() -> decltype(T::value) {
        return T::value;
    }

    return 0;
}
```

> **关键要点**：在模板基类中，依赖基类的成员必须通过 `this->`、`Base<T>::` 或 `using` 声明来访问，否则编译器无法找到它们。`::` 只解决作用域定位，不解决访问权限问题。同名变量在不同作用域中容易造成混淆，务必注意 `::` 限定的目标作用域。

## 15. 总结

`::` 运算符是 C++ 中用于**作用域限定**的核心运算符，其用途远不止简单的命名空间访问：

1. 区分不同作用域中的同名标识符
2. 访问命名空间、类、枚举等的成员
3. 解决名称冲突问题
4. 禁用 ADL，精确控制函数查找
5. 配合 `typename` 在模板中访问依赖类型
6. 强制使用全局 `operator new`/`delete`
7. 在 SFINAE 中检测类型成员是否存在
8. 在模板继承中解决依赖基类的名称查找问题

掌握 `::` 的各种用法和陷阱，是编写健壮、可维护 C++ 代码的关键。
