# 浮点数精度陷阱
> 📖 相关章节：[运算符与表达式](../../01-C语言/02-运算符与表达式.md)、[控制结构](../../01-C语言/03-控制结构.md)、[函数](../../01-C语言/04-函数.md)、[基础特性](../../02-CPP/01-基础特性.md)、[命名空间](../../02-CPP/02-命名空间与编码规范.md)

### 1. 本质洞察

**0.1 + 0.2 != 0.3**！因为浮点数用二进制存储，0.1 和 0.2 无法精确表示，累加误差导致结果不等于 0.3。永远不要用 `==` 比较浮点数，金融计算必须用整数或专用库。

***

### 2. IEEE 754 标准详解

IEEE 754 是浮点数的国际标准，定义了浮点数的存储格式和运算规则。

**浮点数的存储结构：**

```
float (32位 = 4字节):
┌─────┬──────────┬───────────────────────────┐
│ 符号 │  指数(8位) │       尾数(23位)            │
│ 1位  │  偏移127  │       隐含前导1              │
└─────┴──────────┴───────────────────────────┘

double (64位 = 8字节):
┌─────┬───────────┬─────────────────────────────────┐
│ 符号 │  指数(11位) │         尾数(52位)                │
│ 1位  │  偏移1023  │         隐含前导1                 │
└─────┴───────────┴─────────────────────────────────┘
```

**浮点数的值计算公式：**

```
value = (-1)^sign × 1.mantissa × 2^(exponent - bias)
```

**具体示例：float 类型存储 0.75**

```
0.75 (十进制) = 0.11 (二进制) = 1.1 × 2^(-1)

符号位：0（正数）
指数位：-1 + 127 = 126 → 01111110
尾数位：.10000000000000000000000（去掉前导1）

完整32位：0 01111110 10000000000000000000000
```

**float 与 double 的精度对比：**

| 特性 | float | double |
|------|-------|--------|
| 总位数 | 32 | 64 |
| 符号位 | 1 | 1 |
| 指数位 | 8 | 11 |
| 尾数位 | 23 | 52 |
| 有效十进制位数 | 6-7 | 15-16 |
| 指数范围 | -126 ~ +127 | -1022 ~ +1023 |
| 最小正值 | ~1.2e-38 | ~2.2e-308 |
| 最大值 | ~3.4e38 | ~1.8e308 |
| 精确表示整数范围 | -2^24 ~ 2^24 | -2^53 ~ 2^53 |

**特殊值：**

| 特殊值 | 指数 | 尾数 | 含义 |
|--------|------|------|------|
| +0 / -0 | 全0 | 全0 | 正零/负零 |
| 非正规数 | 全0 | 非0 | 极小数，渐近下溢 |
| +∞ / -∞ | 全1 | 全0 | 正无穷/负无穷 |
| NaN | 全1 | 非0 | 非数字（Not a Number） |

```cpp
#include <cmath>
#include <limits>
#include <iostream>

void demo_special_values() {
    double pos_inf = std::numeric_limits<double>::infinity();
    double neg_inf = -std::numeric_limits<double>::infinity();
    double nan_val = std::numeric_limits<double>::quiet_NaN();

    std::cout << "1.0 / 0.0 = " << 1.0 / 0.0 << std::endl;     // inf
    std::cout << "0.0 / 0.0 = " << 0.0 / 0.0 << std::endl;     // nan
    std::cout << "inf + 1   = " << pos_inf + 1.0 << std::endl;  // inf
    std::cout << "inf - inf = " << pos_inf - pos_inf << std::endl; // nan
    std::cout << "nan == nan: " << (nan_val == nan_val) << std::endl;  // 0 (false!)
    std::cout << "isnan(nan): " << std::isnan(nan_val) << std::endl;  // 1 (true)
}
```

### 3. 为什么 0.1 不能精确表示

**核心原因**：十进制小数转二进制时，很多数是无限循环的。

**0.1 的二进制表示：**

```
0.1 (十进制) = 0.0001100110011001100110011... (二进制，无限循环)

推导过程：
0.1 × 2 = 0.2 → 整数部分 0
0.2 × 2 = 0.4 → 整数部分 0
0.4 × 2 = 0.8 → 整数部分 0
0.8 × 2 = 1.6 → 整数部分 1
0.6 × 2 = 1.2 → 整数部分 1
0.2 × 2 = 0.4 → 整数部分 0  ← 开始循环
0.4 × 2 = 0.8 → 整数部分 0
0.8 × 2 = 1.6 → 整数部分 1
0.6 × 2 = 1.2 → 整数部分 1
... 无限循环 "0011"
```

**存储时截断导致误差：**

```
0.1 的精确值（double）:
  实际存储值 ≈ 0.1000000000000000055511151231257827021181583404541015625
  误差 ≈ 5.55e-18

0.2 的精确值（double）:
  实际存储值 ≈ 0.200000000000000011102230246251565404236316680908203125
  误差 ≈ 1.11e-17

0.1 + 0.2 的结果:
  ≈ 0.3000000000000000444089209850062616169452667236328125
  ≠ 0.3
```

**哪些十进制小数可以精确表示？**

| 十进制数 | 二进制表示 | 是否精确 |
|----------|-----------|----------|
| 0.5 | 0.1 | 精确 |
| 0.25 | 0.01 | 精确 |
| 0.125 | 0.001 | 精确 |
| 0.75 | 0.11 | 精确 |
| 0.375 | 0.011 | 精确 |
| 0.1 | 0.000110011... | 不精确 |
| 0.2 | 0.00110011... | 不精确 |
| 0.3 | 0.010011001... | 不精确 |
| 0.7 | 0.101100110... | 不精确 |

**规律**：只有分母为 2 的幂次的分数（如 1/2, 1/4, 3/8, 5/16）才能精确表示。

### 4. 常见陷阱详解

#### 1. 陷阱1：相等比较

```cpp
// 最经典的陷阱
double a = 0.1 + 0.2;
if (a == 0.3) {
    // 永远不会进入！
    // a ≈ 0.30000000000000004
}

// 更隐蔽的陷阱
double x = 0.0;
for (int i = 0; i < 10; ++i) {
    x += 0.1;
}
if (x == 1.0) {
    // 可能不会进入！
    // x ≈ 0.9999999999999999
}

// 即使看起来"应该"相等的值
double a = 1.0 / 3.0;
double b = 1.0 - 2.0 / 3.0;
// a ≈ 0.3333333333333333
// b ≈ 0.3333333333333333
// 但 a 和 b 的二进制表示可能不同！
if (a == b) { /* 不一定进入 */ }
```

#### 2. 陷阱2：累加误差

```cpp
// 正向累加
double sum = 0.0;
for (int i = 0; i < 1000000; ++i) {
    sum += 0.1;
}
// 期望: 100000.0
// 实际: ≈ 100000.00000001484
// 误差随累加次数增长

// 反向累加（更糟）
double sum2 = 0.0;
for (int i = 0; i < 1000000; ++i) {
    sum2 += 0.000001;
}
// 期望: 1.0
// 实际: ≈ 1.0000000000079183
```

#### 3. 陷阱3：大数吃小数

```cpp
// 经典案例：大数加小数，小数被"吞掉"
float big   = 1e10f;
float small = 1.0f;
float result = big + small - big;
// 期望: 1.0
// 实际: 0.0  （1.0 在 1e10 的精度范围内被忽略）

// 原因：float 只有 23 位尾数，1e10 需要 34 位才能精确表示
// 1e10 + 1.0 在 float 精度下等于 1e10

// double 也存在同样问题，只是阈值更大
double big_d   = 1e16;
double small_d = 1.0;
double result_d = big_d + small_d - big_d;
// 期望: 1.0
// 实际: 0.0  （1.0 在 1e16 的精度范围内被忽略）

// 正确做法：先加小数
double correct = big_d - big_d + small_d;  // 1.0 ✓
// 或先排序后累加（从小到大）
```

#### 4. 陷阱4：隐式类型转换

```cpp
// float 与 double 混合运算
float  f = 0.1f;    // 0.1f 是 float，精度约7位
double d = 0.1;     // 0.1 是 double，精度约16位

// f 的值 ≠ d 的值！
// 0.1f ≈ 0.10000000149011612
// 0.1  ≈ 0.10000000000000001

if (f == d) { /* 可能不相等！ */ }
// f 被提升为 double 后，值是 0.10000000149011612
// 不等于 0.10000000000000001

// 整数除法 vs 浮点除法
int a = 1, b = 3;
double r1 = a / b;       // 0.0！整数除法先完成
double r2 = (double)a / b; // 0.333... ✓

// 字面量陷阱
float x = 0.1;   // 0.1 是 double，赋值给 float 时截断
// 等价于 float x = 0.1f; 但中间过程可能不同
```

### 5. 正确的比较方式

**方法1：绝对误差比较（适用于接近0的值）**

```cpp
#include <cmath>

bool approx_equal_abs(double a, double b, double eps = 1e-9) {
    return std::abs(a - b) < eps;
}

// 使用
double x = 0.1 + 0.2;
if (approx_equal_abs(x, 0.3)) {
    // 正确进入
}
```

**方法2：相对误差比较（适用于任意大小的值）**

```cpp
bool approx_equal_rel(double a, double b, double eps = 1e-9) {
    double diff = std::abs(a - b);
    double largest = std::max(std::abs(a), std::abs(b));
    if (largest < eps) return diff < eps;  // 处理接近0的情况
    return diff / largest < eps;
}
```

**方法3：混合误差比较（最推荐）**

```cpp
bool approx_equal(double a, double b, double abs_eps = 1e-12, double rel_eps = 1e-9) {
    double diff = std::abs(a - b);
    if (diff <= abs_eps) return true;
    return diff <= rel_eps * std::max(std::abs(a), std::abs(b));
}
```

**方法4：相对误差比较方式（简洁）**

```cpp
#include <cmath>

// 对于已知数量级的值
bool nearly_equal(double a, double b) {
    return std::abs(a - b) < 1e-9 * std::max(std::abs(a), std::abs(b));
}
```

**比较方式选择指南：**

| 场景 | 推荐方式 | 原因 |
|------|----------|------|
| 值接近0 | 绝对误差 | 相对误差在0附近不稳定 |
| 值远离0 | 相对误差 | 绝对误差无法适应不同数量级 |
| 通用场景 | 混合误差 | 兼顾两种情况 |
| NaN 检测 | `std::isnan()` | NaN 不等于任何值 |
| 无穷检测 | `std::isinf()` | 无穷有特殊比较规则 |

### 6. Kahan 求和算法

Kahan 求和是一种补偿求和算法，显著减少浮点数累加的误差：

**普通求和 vs Kahan 求和：**

```cpp
#include <iostream>
#include <vector>
#include <iomanip>
#include <cmath>

// 普通求和：误差随累加次数增长
double naive_sum(const std::vector<double>& values) {
    double sum = 0.0;
    for (double v : values) {
        sum += v;
    }
    return sum;
}

// Kahan 求和：补偿累加误差
double kahan_sum(const std::vector<double>& values) {
    double sum = 0.0;
    double compensation = 0.0;  // 累积的舍入误差

    for (double v : values) {
        double y = v - compensation;        // 减去之前累积的误差
        double t = sum + y;                  // 新的累加值
        compensation = (t - sum) - y;        // 计算本次舍入误差
        // (t - sum) 是实际加到 sum 上的值
        // 减去 y 得到本次丢失的精度
        sum = t;
    }

    return sum;
}

// 测试
int main() {
    std::vector<double> values(1000000, 0.1);

    std::cout << std::setprecision(20);
    std::cout << "期望值:     " << 100000.0 << std::endl;
    std::cout << "普通求和:   " << naive_sum(values) << std::endl;
    std::cout << "Kahan求和:  " << kahan_sum(values) << std::endl;

    return 0;
}
// 输出：
// 期望值:     100000
// 普通求和:   100000.00000001484
// Kahan求和:  100000.00000000000
```

**Kahan 求和的原理：**

```
每次累加时：
  y = value - compensation     // 补偿上次丢失的精度
  t = sum + y                  // 新的累加值
  compensation = (t - sum) - y // 计算本次丢失的精度
  sum = t

关键：compensation 记录了每次加法中因精度限制而丢失的部分
下次累加时补偿回来，从而保持高精度
```

### 7. 金融计算的正确做法

金融计算对精度要求极高，绝不能直接使用浮点数：

**错误做法：**

```cpp
// 错误！浮点数不精确
double price = 19.99;
double tax = 0.08;
double total = price * (1 + tax);
// total ≈ 21.589200000000002，不是精确的 21.5892

// 错误！累加误差
double sum = 0.0;
for (int i = 0; i < 100; ++i) {
    sum += 0.01;
}
// sum ≈ 0.9999999999999999，不是 1.0
```

**正确做法1：用整数（分）代替浮点数**

```cpp
// 所有金额用"分"表示，避免小数
long long price_cents = 1999;    // 19.99 元 = 1999 分
long long tax_rate_bp  = 800;     // 8% = 800 基点
long long total_cents = price_cents * (10000 + tax_rate_bp) / 10000;
// 注意：整数除法会截断（向下取整），此处 1999 * 10800 / 10000 = 2158 分
// 精确值为 2158.92 分，如需四舍五入可使用：(price_cents * (10000 + tax_rate_bp) + 5000) / 10000
// total_cents = 1999 * 10800 / 10000 = 2158 分 = 21.58 元

// 输出时转换
void print_money(long long cents) {
    std::cout << cents / 100 << "." << std::setw(2) << std::setfill('0')
              << cents % 100 << std::endl;
}
print_money(total_cents);  // 21.58
```

**正确做法2：使用高精度库**

```cpp
// C++ 没有内置的 Decimal 类型，但可以使用：
// 1. boost::multiprecision::cpp_dec_float
// 2. 第三方库如 GMP、MPFR
// 3. C++23 std::decimal（提案中）

// 示例：使用 boost
#include <boost/multiprecision/cpp_dec_float.hpp>
using decimal = boost::multiprecision::cpp_dec_float_50;

decimal price("19.99");
decimal tax("0.08");
decimal total = price * (1 + tax);
// total 精确等于 21.5892
```

**正确做法3：四舍六入五成双（银行家舍入）**

```cpp
#include <cmath>

// 银行家舍入：0.5 向最近的偶数舍入
double bankers_round(double value, int decimals) {
    double multiplier = std::pow(10.0, decimals);
    double shifted = value * multiplier;
    double floored = std::floor(shifted);
    double fraction = shifted - floored;

    if (fraction > 0.5) {
        return (floored + 1.0) / multiplier;
    } else if (fraction < 0.5) {
        return floored / multiplier;
    } else {
        // 0.5 向偶数舍入
        int int_part = static_cast<int>(floored);
        if (int_part % 2 == 0) {
            return floored / multiplier;
        } else {
            return (floored + 1.0) / multiplier;
        }
    }
}

// 2.5 → 2.0（向偶数）
// 3.5 → 4.0（向偶数）
// 2.4 → 2.0
// 2.6 → 3.0
```

### 8. double vs float 选择指南

| 考量 | 选择 float | 选择 double |
|------|-----------|------------|
| 精度需求 | 6-7位有效数字足够 | 需要15-16位有效数字 |
| 内存/存储 | 大量数据（图像、3D坐标） | 一般计算 |
| GPU计算 | GPU 原生支持 float 更快 | 部分GPU支持但较慢 |
| 科学计算 | 不够精确 | 必须用 double |
| 金融计算 | 都不行，用整数 | 都不行，用整数 |
| 兼容性 | 某些API只接受float | C/C++默认浮点类型 |
| 坐标系统 | 游戏世界坐标 | 地理坐标、天文计算 |

**默认规则：没有特殊理由就用 double。**

```cpp
// float 的精度陷阱
float f = 16777217.0f;   // 2^24 + 1
// f 实际存储为 16777216.0f！因为 float 只有23位尾数
// 16777217 无法精确表示

// double 的安全整数范围
double d = 9007199254740993.0;  // 2^53 + 1
// d 实际存储为 9007199254740992.0！
// 超过 2^53 的整数无法精确表示

// 检查整数是否可以精确表示为浮点数
#include <cmath>
bool is_representable(int64_t n) {
    double d = static_cast<double>(n);
    return static_cast<int64_t>(d) == n;
}
```

### 9. 完整示例：浮点数陷阱演示与修复

```cpp
#include <iostream>
#include <cmath>
#include <vector>
#include <iomanip>
#include <limits>

// ============================================================
// 1. 精度比较工具
// ============================================================
bool nearly_equal(double a, double b,
                  double abs_eps = 1e-12,
                  double rel_eps = 1e-9) {
    double diff = std::abs(a - b);
    if (diff <= abs_eps) return true;
    return diff <= rel_eps * std::max(std::abs(a), std::abs(b));
}

// ============================================================
// 2. Kahan 求和
// ============================================================
double kahan_sum(const std::vector<double>& values) {
    double sum = 0.0;
    double c   = 0.0;
    for (double v : values) {
        double y = v - c;
        double t = sum + y;
        c = (t - sum) - y;
        sum = t;
    }
    return sum;
}

// ============================================================
// 3. 安全的浮点数比较
// ============================================================
int compare_double(double a, double b, double eps = 1e-9) {
    if (nearly_equal(a, b, eps)) return 0;
    return (a < b) ? -1 : 1;
}

// ============================================================
// 演示所有陷阱
// ============================================================
int main() {
    std::cout << std::setprecision(20);

    // --- 陷阱1：0.1 + 0.2 != 0.3 ---
    std::cout << "=== 陷阱1：相等比较 ===" << std::endl;
    double a = 0.1 + 0.2;
    std::cout << "0.1 + 0.2 = " << a << std::endl;
    std::cout << "0.1 + 0.2 == 0.3 ? " << (a == 0.3) << std::endl;
    std::cout << "nearly_equal(0.1+0.2, 0.3) ? "
              << nearly_equal(a, 0.3) << std::endl;

    // --- 陷阱2：累加误差 ---
    std::cout << "\n=== 陷阱2：累加误差 ===" << std::endl;
    std::vector<double> vals(1000000, 0.1);
    double naive = 0.0;
    for (double v : vals) naive += v;
    double kahan = kahan_sum(vals);
    std::cout << "普通求和: " << naive << std::endl;
    std::cout << "Kahan求和: " << kahan << std::endl;
    std::cout << "期望值:    100000" << std::endl;

    // --- 陷阱3：大数吃小数 ---
    std::cout << "\n=== 陷阱3：大数吃小数 ===" << std::endl;
    float big = 1e10f;
    float small = 1.0f;
    float eaten = big + small - big;
    std::cout << "1e10f + 1.0f - 1e10f = " << eaten << std::endl;
    std::cout << "期望: 1.0, 实际: " << eaten << std::endl;
    // 修复：先减后加
    float fixed = big - big + small;
    std::cout << "1e10f - 1e10f + 1.0f = " << fixed << std::endl;

    // --- 陷阱4：隐式转换 ---
    std::cout << "\n=== 陷阱4：隐式转换 ===" << std::endl;
    float  f = 0.1f;
    double d = 0.1;
    std::cout << "0.1f = " << f << std::endl;
    std::cout << "0.1  = " << d << std::endl;
    std::cout << "0.1f == 0.1 ? " << (f == d) << std::endl;
    // float 被提升为 double 后，值不等于 double 的 0.1

    // --- 陷阱5：NaN 和无穷 ---
    std::cout << "\n=== 陷阱5：NaN 和无穷 ===" << std::endl;
    double nan1 = std::numeric_limits<double>::quiet_NaN();
    double inf1 = std::numeric_limits<double>::infinity();
    std::cout << "NaN == NaN ? " << (nan1 == nan1) << std::endl;   // false!
    std::cout << "isnan(NaN) ? " << std::isnan(nan1) << std::endl; // true
    std::cout << "inf + 1 = " << inf1 + 1.0 << std::endl;         // inf
    std::cout << "inf - inf = " << inf1 - inf1 << std::endl;      // nan

    // --- 陷阱6：整数精度 ---
    std::cout << "\n=== 陷阱6：大整数精度 ===" << std::endl;
    double big_int = 9007199254740993.0;  // 2^53 + 1
    std::cout << "2^53+1 as double = " << big_int << std::endl;
    // 输出 9007199254740992，不是 9007199254740993

    return 0;
}
```

### 10. 常见陷阱速查表

| 陷阱 | 错误写法 | 后果 | 修复 |
|------|----------|------|------|
| 相等比较 | `a == 0.3` | 永远不成立 | 用误差范围比较 |
| 累加误差 | `for(...) sum+=0.1` | 误差累积 | Kahan 求和 |
| 大数吃小数 | `1e10 + 1.0 - 1e10` | 小数丢失 | 先减后加，或排序后累加 |
| 隐式转换 | `float f=0.1; f==0.1` | 精度不一致 | 统一用 double |
| NaN 比较 | `nan == nan` | 永远 false | 用 `std::isnan()` |
| 整数除法 | `1/3` | 结果为 0 | `(double)1/3` |
| 大整数 | `double d = 2^53+1` | 丢失精度 | 用 int64_t |
| 金融计算 | `double price=19.99` | 不精确 | 用整数（分）或高精度库 |

### 11. 最佳实践

1. **永远不要用 == 比较浮点数**：用误差范围比较（绝对误差 + 相对误差）
2. **优先用 double 而非 float**：除非有明确的内存/性能需求
3. **金融计算用整数（分）或专用库**：绝不用浮点数
4. **注意运算顺序**：先加小数再加大数，避免大数吃小数
5. **大量累加用 Kahan 求和**：显著减少累加误差
6. **避免 float 和 double 混合运算**：统一类型
7. **整数除法要显式转换**：`(double)a / b`
8. **NaN 检测用 `std::isnan()`**：NaN 不等于自身
9. **了解精度极限**：float 6-7位，double 15-16位有效数字
10. **测试边界值**：0、极大值、极小值、NaN、无穷

### 12. 极简总结

**浮点数 = 二进制近似存储 → 0.1+0.2!=0.3 → 永远不要用==比较 → 用误差范围比较 → 金融用整数 → 累加用Kahan求和 → 默认用double**
