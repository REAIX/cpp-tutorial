# 数据结构与算法的关系
> 📖 相关章节：[链表与数据结构](../../01-C语言/25-链表与数据结构.md)、[排序与查找算法](../../01-C语言/26-排序与查找算法.md)

### 1. 先抓核心

**数据结构**是数据的组织方式，**算法**是解决问题的步骤。两者互相依赖：选错数据结构，再好的算法也慢；没有算法，数据结构只是静态的容器。程序 = 数据结构 + 算法。

***

### 2. 核心关系：程序 = 数据结构 + 算法

这是 Niklaus Wirth 提出的经典公式：

```
Programs = Data Structures + Algorithms
```

**数据结构决定了算法能做什么：**

- 用数组，你可以随机访问，但插入删除代价高
- 用链表，你可以快速插入删除，但随机访问代价高
- 用哈希表，你可以 O(1) 查找，但无法有序遍历

**算法决定了数据结构怎么用：**

- 同一个数组，线性搜索是 O(n)，二分搜索是 O(log n)
- 同一个图，DFS 和 BFS 遍历顺序不同，解决的问题也不同
- 同一组数据，排序后可以用二分查找，不排序只能线性查找

**两者的协同关系：**

```
问题 → 选择数据结构 → 设计算法 → 分析复杂度 → 优化
  ↑                                          |
  └──────── 可能需要换数据结构 ←──────────────┘
```

### 3. 不同数据结构对算法的影响

**常见操作的时间复杂度对比：**

| 操作 | 数组 | 链表 | 哈希表 | 平衡BST | 堆 |
|------|:----:|:----:|:------:|:-------:|:--:|
| 按索引访问 | O(1) | O(n) | - | O(log n) | O(1) |
| 按值查找 | O(n) | O(n) | O(1) | O(log n) | O(n) |
| 头部插入 | O(n) | O(1) | O(1) | O(log n) | - |
| 尾部插入 | O(1)* | O(1)* | O(1) | O(log n) | O(log n) |
| 中间插入 | O(n) | O(1)** | O(1) | O(log n) | - |
| 删除 | O(n) | O(1)** | O(1) | O(log n) | O(log n) |
| 有序遍历 | O(1)空间 | O(1)空间 | O(n)空间 | O(1)空间 | O(n)空间 |
| 取最大/最小 | O(n) | O(n) | O(n) | O(log n) | O(1) |
| 前驱/后继 | O(n) | O(n) | O(n) | O(log n) | - |

> *O(1) 均摊（动态数组扩容时为 O(n)）
> **O(1) 假设已定位到节点位置

**数据结构选择决策树：**

```
需要什么操作？
├── 快速随机访问 → 数组 / vector
├── 频繁插入删除（两端）→ 链表 / deque / list
├── 快速查找（不需要有序）→ 哈希表 / unordered_map
├── 快速查找 + 有序遍历 → 平衡树 / map / set
├── 总是取最大/最小 → 堆 / priority_queue
├── 表达层次关系 → 树
├── 表达网络关系 → 图
└── 字符串匹配 → Trie / 后缀数组
```

### 4. 实际案例分析

#### 1. 案例1：电话簿

**需求**：按名字查号码，支持动态添加新联系人

```
方案1：无序数组
  查找：O(n) 线性搜索 → 100万联系人需要比较100万次
  插入：O(1) 尾部追加

方案2：有序数组 + 二分搜索
  查找：O(log n) → 100万联系人只需约20次比较
  插入：O(n) 插入后需要移动元素 → 慢

方案3：哈希表
  查找：O(1) → 1次计算即可定位
  插入：O(1) → 最优选择

方案4：平衡二叉搜索树
  查找：O(log n) → 约20次比较
  插入：O(log n) → 适合需要有序遍历的场景
```

**代码对比：**

```cpp
#include <iostream>
#include <vector>
#include <algorithm>
#include <unordered_map>
#include <map>
#include <string>

// 方案1：无序数组 — O(n) 查找
int find_linear(const std::vector<std::pair<std::string,int>>& book,
                const std::string& name) {
    for (const auto& entry : book) {
        if (entry.first == name) return entry.second;
    }
    return -1;
}

// 方案2：有序数组 + 二分搜索 — O(log n) 查找
int find_binary(const std::vector<std::pair<std::string,int>>& book,
                const std::string& name) {
    auto it = std::lower_bound(book.begin(), book.end(),
        std::make_pair(name, 0),
        [](const auto& a, const auto& b) { return a.first < b.first; });
    if (it != book.end() && it->first == name) return it->second;
    return -1;
}

// 方案3：哈希表 — O(1) 查找
void demo_hash_table() {
    std::unordered_map<std::string, int> phonebook;
    phonebook["Alice"] = 12345;
    phonebook["Bob"]   = 67890;
    // 查找：O(1)
    auto it = phonebook.find("Alice");
    if (it != phonebook.end()) {
        std::cout << it->second << std::endl;  // 12345
    }
}

// 方案4：平衡树 — O(log n) 查找，支持有序遍历
void demo_bst() {
    std::map<std::string, int> phonebook;
    phonebook["Alice"] = 12345;
    phonebook["Bob"]   = 67890;
    // 查找：O(log n)
    auto it = phonebook.find("Alice");
    // 有序遍历：按名字字母序
    for (const auto& [name, num] : phonebook) {
        std::cout << name << ": " << num << std::endl;
    }
}
```

#### 2. 案例2：任务调度

**需求**：总是取优先级最高的任务执行，支持动态添加新任务

```
方案1：无序数组
  取最高优先级：O(n) 扫描全数组
  添加任务：O(1)

方案2：有序数组
  取最高优先级：O(1) 取最后一个
  添加任务：O(n) 需要移动元素保持有序

方案3：堆（优先队列）
  取最高优先级：O(1) 取堆顶，O(log n) 删除
  添加任务：O(log n)
  → 最优选择！
```

```cpp
#include <queue>
#include <vector>
#include <iostream>

void demo_task_scheduler() {
    // 最大堆：优先级最高的在堆顶
    std::priority_queue<std::pair<int, std::string>> tasks;

    // 添加任务：O(log n)
    tasks.push({5, "Fix bug #123"});
    tasks.push({1, "Update docs"});
    tasks.push({8, "Critical security patch"});
    tasks.push({3, "Code review"});

    // 按优先级处理：每次 O(log n)
    while (!tasks.empty()) {
        auto [priority, task] = tasks.top();
        std::cout << "Priority " << priority << ": " << task << std::endl;
        tasks.pop();
    }
    // 输出：
    // Priority 8: Critical security patch
    // Priority 5: Fix bug #123
    // Priority 3: Code review
    // Priority 1: Update docs
}
```

#### 3. 案例3：拼写检查

**需求**：判断一个单词是否在字典中，支持前缀搜索

```
方案1：哈希表
  精确查找：O(1) ✓
  前缀搜索：O(n) 遍历所有键 ✗

方案2：有序数组 + 二分搜索
  精确查找：O(log n) ✓
  前缀搜索：O(log n + k) 找到起点后遍历 ✓

方案3：Trie（前缀树）
  精确查找：O(m)，m 为单词长度 ✓
  前缀搜索：O(m + k)，m 为前缀长度，k 为匹配数 ✓✓
  → 最优选择！
```

```cpp
#include <string>
#include <unordered_map>

// Trie 节点
struct TrieNode {
    std::unordered_map<char, TrieNode*> children;
    bool is_end = false;
};

class Trie {
    TrieNode* root;

public:
    Trie() : root(new TrieNode()) {}

    void insert(const std::string& word) {
        TrieNode* node = root;
        for (char c : word) {
            if (!node->children.count(c))
                node->children[c] = new TrieNode();
            node = node->children[c];
        }
        node->is_end = true;
    }

    bool search(const std::string& word) {
        TrieNode* node = find(word);
        return node && node->is_end;
    }

    bool startsWith(const std::string& prefix) {
        return find(prefix) != nullptr;
    }

private:
    TrieNode* find(const std::string& s) {
        TrieNode* node = root;
        for (char c : s) {
            if (!node->children.count(c)) return nullptr;
            node = node->children[c];
        }
        return node;
    }
};

// 使用
void demo_spell_check() {
    Trie dict;
    dict.insert("hello");
    dict.insert("help");
    dict.insert("world");

    dict.search("hello");     // true
    dict.search("hell");      // false（不是完整单词）
    dict.startsWith("hel");   // true（有以 "hel" 开头的单词）
    dict.startsWith("wor");   // true
    dict.startsWith("xyz");   // false
}
```

### 5. STL 容器与算法的对应关系

**STL 容器的底层数据结构：**

| STL 容器 | 底层数据结构 | 特点 |
|----------|-------------|------|
| `vector` | 动态数组 | 连续内存，随机访问 O(1) |
| `deque` | 分段数组 | 双端操作 O(1)，随机访问 O(1) |
| `list` | 双向链表 | 任意位置插入删除 O(1) |
| `forward_list` | 单向链表 | 内存更省，只能单向遍历 |
| `stack` | deque（默认） | LIFO，只能操作顶部 |
| `queue` | deque（默认） | FIFO，只能操作两端 |
| `priority_queue` | 最大堆（vector+heap算法） | O(log n) 插入/删除 |
| `set` / `map` | 红黑树 | 有序，O(log n) 查找 |
| `unordered_set` / `unordered_map` | 哈希表 | 无序，O(1) 平均查找 |
| `bitset` | 位数组 | 固定大小，位操作 O(1) |

**STL 算法与最佳容器搭配：**

| 算法需求 | 推荐容器 | STL 算法 | 复杂度 |
|----------|----------|----------|--------|
| 排序 | `vector` | `std::sort` | O(n log n) |
| 二分查找 | `vector`/`set` | `std::binary_search` / `set::find` | O(log n) |
| 查找元素 | `unordered_map` | `find()` | O(1) |
| 去重 | `vector` + `sort` | `std::sort` + `std::unique` | O(n log n) |
| 合并有序序列 | `vector` | `std::merge` | O(n+m) |
| 第K大元素 | `vector` | `std::nth_element` | O(n) 平均 |
| 堆操作 | `vector` | `std::make_heap` / `push_heap` | O(n) / O(log n) |
| 全排列 | `vector` | `std::next_permutation` | O(n) |
| 最小/最大 | 任意 | `std::min_element` / `max_element` | O(n) |
| 计数 | 任意 | `std::count` | O(n) |

### 6. 时间复杂度对比与选择指南

**常见算法的时间复杂度：**

| 算法 | 时间复杂度 | 适用场景 |
|------|-----------|----------|
| 线性搜索 | O(n) | 无序数据，小规模 |
| 二分搜索 | O(log n) | 有序数据 |
| 冒泡排序 | O(n^2) | 教学用，实际不用 |
| 快速排序 | O(n log n) 平均 | 通用排序，缓存友好 |
| 归并排序 | O(n log n) | 稳定排序，外部排序 |
| 堆排序 | O(n log n) | 原地排序，不需要额外空间 |
| 哈希查找 | O(1) 平均 | 精确匹配，不需要有序 |
| BFS | O(V+E) | 最短路径（无权图） |
| DFS | O(V+E) | 连通性、拓扑排序 |
| Dijkstra | O((V+E) log V) | 最短路径（有权图） |

**数据结构选择指南：**

| 场景 | 首选 | 备选 | 原因 |
|------|------|------|------|
| 需要随机访问 | `vector` | `deque` | 连续内存，缓存友好 |
| 频繁头尾操作 | `deque` | `list` | 两端 O(1) |
| 频繁中间插入 | `list` | - | 链表插入 O(1) |
| 快速精确查找 | `unordered_map` | `unordered_set` | O(1) 平均 |
| 有序查找 | `map` | `set` | O(log n)，支持范围查询 |
| 优先级队列 | `priority_queue` | `multiset` | 堆操作高效 |
| 去重 | `unordered_set` | `set` | O(n) 插入 |
| 键值对存储 | `unordered_map` | `map` | 按是否需要有序选择 |
| 字符串前缀 | `Trie`（自定义） | `set` | 前缀搜索 O(m) |
| 图的表示 | `vector<vector>` | `unordered_map` | 邻接表 |

### 7. 完整代码示例：同一问题不同数据结构的性能差异

以下用"统计单词频率并找出前K个高频词"这一经典问题，展示不同数据结构+算法组合的性能差异：

```cpp
#include <iostream>
#include <vector>
#include <string>
#include <unordered_map>
#include <map>
#include <algorithm>
#include <queue>
#include <chrono>

// ============================================================
// 方案1：vector + sort
// 时间：O(n) 统计 + O(m log m) 排序 + O(k) 取前k
// 空间：O(m)，m 为不同单词数
// ============================================================
std::vector<std::pair<std::string, int>>
top_k_vector(const std::vector<std::string>& words, int k) {
    // 统计频率
    std::unordered_map<std::string, int> freq;
    for (const auto& w : words) freq[w]++;

    // 转为 vector
    std::vector<std::pair<std::string, int>> vec(freq.begin(), freq.end());

    // 排序：O(m log m)
    std::partial_sort(vec.begin(), vec.begin() + k, vec.end(),
        [](const auto& a, const auto& b) { return a.second > b.second; });

    // 取前 k 个
    vec.resize(std::min(k, (int)vec.size()));
    return vec;
}

// ============================================================
// 方案2：unordered_map + priority_queue（小顶堆）
// 时间：O(n) 统计 + O(m log k) 堆操作
// 空间：O(m + k)
// 当 k << m 时，比方案1更快
// ============================================================
std::vector<std::pair<std::string, int>>
top_k_heap(const std::vector<std::string>& words, int k) {
    // 统计频率
    std::unordered_map<std::string, int> freq;
    for (const auto& w : words) freq[w]++;

    // 小顶堆：堆顶是频率最小的
    using Entry = std::pair<int, std::string>;
    std::priority_queue<Entry, std::vector<Entry>, std::greater<Entry>> min_heap;

    for (const auto& [word, count] : freq) {
        min_heap.push({count, word});
        if ((int)min_heap.size() > k) {
            min_heap.pop();  // 移除频率最小的
        }
    }

    // 提取结果
    std::vector<std::pair<std::string, int>> result;
    while (!min_heap.empty()) {
        auto [count, word] = min_heap.top();
        result.push_back({word, count});
        min_heap.pop();
    }
    std::reverse(result.begin(), result.end());
    return result;
}

// ============================================================
// 方案3：如果用 map（红黑树）统计频率
// 时间：O(n log m) 统计 + O(m log k) 堆操作
// 比 unordered_map 慢，但结果天然有序
// ============================================================
std::vector<std::pair<std::string, int>>
top_k_ordered_map(const std::vector<std::string>& words, int k) {
    // 用 map 统计：每次插入 O(log m)
    std::map<std::string, int> freq;
    for (const auto& w : words) freq[w]++;

    // 转为 vector 后取 top-k
    std::vector<std::pair<std::string, int>> vec(freq.begin(), freq.end());
    std::partial_sort(vec.begin(), vec.begin() + k, vec.end(),
        [](const auto& a, const auto& b) { return a.second > b.second; });
    vec.resize(std::min(k, (int)vec.size()));
    return vec;
}

// ============================================================
// 测试
// ============================================================
int main() {
    std::vector<std::string> words = {
        "hello", "world", "hello", "cpp", "world", "hello",
        "algorithm", "data", "structure", "hello", "world",
        "cpp", "template", "class", "hello", "algorithm"
    };

    int k = 3;

    auto result1 = top_k_vector(words, k);
    std::cout << "方案1 (vector + sort):" << std::endl;
    for (const auto& [word, count] : result1) {
        std::cout << "  " << word << ": " << count << std::endl;
    }

    auto result2 = top_k_heap(words, k);
    std::cout << "方案2 (unordered_map + heap):" << std::endl;
    for (const auto& [word, count] : result2) {
        std::cout << "  " << word << ": " << count << std::endl;
    }

    auto result3 = top_k_ordered_map(words, k);
    std::cout << "方案3 (map + sort):" << std::endl;
    for (const auto& [word, count] : result3) {
        std::cout << "  " << word << ": " << count << std::endl;
    }

    return 0;
}
```

**三种方案复杂度对比：**

| 方案 | 统计 | 取Top-K | 总复杂度 | 适用场景 |
|------|------|---------|----------|----------|
| vector + sort | O(n) | O(m log m) | O(n + m log m) | 通用，k 较大时 |
| unordered_map + heap | O(n) | O(m log k) | O(n + m log k) | k 远小于 m 时最优 |
| map + sort | O(n log m) | O(m log m) | O(n log m + m log m) | 需要有序遍历时 |

### 8. 常见陷阱

**陷阱1：用错了数据结构导致性能灾难**

```cpp
// 错误：频繁在 vector 头部插入
std::vector<int> v;
for (int i = 0; i < 100000; ++i) {
    v.insert(v.begin(), i);  // 每次移动所有元素，O(n^2)
}

// 正确：用 deque 或在尾部插入后反转
std::vector<int> v;
for (int i = 0; i < 100000; ++i) {
    v.push_back(i);  // O(n) 总计
}
std::reverse(v.begin(), v.end());  // O(n)
```

**陷阱2：忽略了缓存局部性**

```cpp
// 链表看似插入 O(1)，但缓存不友好
std::list<int> lst;
for (int i = 0; i < 1000000; ++i) lst.push_back(i);

// 遍历：每个节点可能缓存未命中
long long sum = 0;
for (int x : lst) sum += x;  // 慢！缓存不友好

// vector 虽然插入慢，但遍历快得多
std::vector<int> vec;
for (int i = 0; i < 1000000; ++i) vec.push_back(i);

// 遍历：连续内存，缓存友好
sum = 0;
for (int x : vec) sum += x;  // 快！缓存友好
```

**陷阱3：哈希表的最坏情况**

```cpp
// 哈希表平均 O(1)，但最坏 O(n)
std::unordered_map<std::string, int> dict;
// 如果所有键的哈希值相同 → 退化为链表 → O(n) 查找
// 实际中：确保键类型有好的哈希函数
```

**陷阱4：过度使用有序容器**

```cpp
// 不需要有序，却用了 map
std::map<std::string, int> freq;  // 每次插入 O(log n)
// 如果只需要统计频率，不需要有序遍历
std::unordered_map<std::string, int> freq;  // 每次插入 O(1) 平均
```

### 9. 最佳实践

1. **先确定操作需求，再选数据结构**：查找多还是插入多？需要有序吗？
2. **默认选 vector**：连续内存、缓存友好，大多数场景最优
3. **需要 O(1) 查找用 unordered_map/set**：不需要有序时优先于 map/set
4. **需要有序用 map/set**：范围查询、有序遍历时选择红黑树
5. **优先级场景用 priority_queue**：堆是处理"取最大/最小"的最优解
6. **考虑缓存局部性**：链表理论复杂度好，实际性能可能不如数组
7. **用 STL 算法而非手写**：`std::sort`、`std::lower_bound` 等经过高度优化
8. **分析最坏情况**：哈希表最坏 O(n)，平衡树最坏 O(log n)
9. **空间换时间**：有时多存一个索引结构，查询速度提升巨大

### 10. 极简总结

**数据结构 = 数据怎么组织 | 算法 = 怎么处理数据 | 选对数据结构 = 算法事半功倍 | 程序 = 数据结构 + 算法**
