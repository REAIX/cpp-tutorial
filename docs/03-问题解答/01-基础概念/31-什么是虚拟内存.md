# 什么是虚拟内存
> 📖 相关章节：[内存管理](../../01-C语言/09-内存管理.md)

> 虚拟内存让每个进程以为自己独占了整个内存空间，而物理内存只是幕后的一块共享资源。

***

### 1. 一句话概括

虚拟内存是一种由操作系统和硬件（MMU）协同实现的地址抽象机制，它将进程看到的连续虚拟地址映射到离散的物理内存页或磁盘交换区，从而实现进程隔离、按需分配和内存超卖。

***

### 2. 虚拟地址与物理地址

每个进程拥有独立的虚拟地址空间，CPU 发出的地址是虚拟地址，需要经过内存管理单元（MMU）翻译为物理地址后才能访问真实内存。

```
进程视角（虚拟地址）          物理内存
┌──────────────┐           ┌──────────────┐
│ 0x00000000   │           │              │
│  (不可访问)   │           │  物理页帧 0   │
├──────────────┤           ├──────────────┤
│ .text 段     │───映射───→│  物理页帧 3   │
│ 0x00400000   │           ├──────────────┤
├──────────────┤           │  物理页帧 7   │
│ .data 段     │───映射───→│              │
│ 0x00600000   │           ├──────────────┤
├──────────────┤           │  物理页帧 1   │
│ heap ↓       │───映射───→│              │
│ ...          │           ├──────────────┤
├──────────────┤           │  ...         │
│ stack ↑      │───映射───→│  物理页帧 12  │
│ 0x7fff0000   │           └──────────────┘
├──────────────┤
│ 内核空间     │  (每个进程都映射，但用户态不可访问)
│ 0xFFFF0000   │
└──────────────┘
```

| 特性 | 虚拟地址 | 物理地址 |
|------|---------|---------|
| 可见性 | 进程可见 | 仅内核/硬件可见 |
| 连续性 | 看起来连续 | 实际离散 |
| 空间大小 | 取决于 CPU 位宽（如 48 位） | 取决于实际内存条容量 |
| 隔离性 | 每个进程独立 | 所有进程共享 |

```cpp
#include <iostream>
#include <cstdint>

int global_var = 42;

int main() {
    int stack_var = 100;
    int* heap_var = new int(200);

    std::cout << "global_var 虚拟地址: " << &global_var << "\n";
    std::cout << "stack_var  虚拟地址: " << &stack_var << "\n";
    std::cout << "heap_var   虚拟地址: " << heap_var << "\n";

    delete heap_var;
    return 0;
}
```

> 不同进程可以拥有相同的虚拟地址，但映射到不同的物理页，互不干扰。

### 3. 页表与地址翻译

虚拟地址到物理地址的翻译通过页表（Page Table）完成。页表以虚拟页号（VPN）为索引，存储对应的物理页帧号（PFN）和权限标志位。

```
虚拟地址 (以 4KB 页为例，48 位有效地址)
┌────────────────────┬───────────────┐
│   VPN (36 bits)    │ Offset (12bit)│
└────────────────────┴───────────────┘
         │
         ▼
┌─────────────────────────────────┐
│  页表项 (PTE)                    │
│ ┌─────┬──────┬─────┬─────┬────┐ │
│ │ PFN │Valid │Read │Write│User│ │
│ └─────┴──────┴─────┴─────┴────┘ │
└─────────────────────────────────┘
         │
         ▼
物理地址 = PFN << 12 + Offset
```

为减少页表占用的内存，现代系统采用多级页表：

| 页表级别 | 层级数 | 优点 | 缺点 |
|---------|--------|------|------|
| 单级页表 | 1 | 一次查表 | 占用内存巨大 |
| 二级页表 | 2 | 稀疏映射节省空间 | 两次查表 |
| 四级页表（x86-64 Linux） | 4 | 支持 48 位地址空间 | 四次查表 |
| 五级页表（x86-64 Linux 5.x） | 5 | 支持 57 位地址空间 | 五次查表 |

```cpp
#include <cstdint>
#include <iostream>

struct PageTableEntry {
    uint64_t pfn       : 36;
    uint64_t present   : 1;
    uint64_t writable  : 1;
    uint64_t user      : 1;
    uint64_t accessed  : 1;
    uint64_t dirty     : 1;
    uint64_t reserved  : 24;
};

int main() {
    std::cout << "PTE 大小: " << sizeof(PageTableEntry) << " 字节\n";
    std::cout << "4KB 页表可容纳 PTE 数: " << 4096 / sizeof(PageTableEntry) << "\n";
    std::cout << "单级页表覆盖地址范围: "
              << (4096 / sizeof(PageTableEntry)) * 4096 << " 字节\n";
    return 0;
}
```

> Linux 中可通过 `/proc/pid/pagemap` 查看进程的页表映射信息。

### 4. TLB——地址翻译加速器

每次内存访问都需要查页表，多级页表意味着多次内存读取。TLB（Translation Lookaside Buffer）是 MMU 内部的地址翻译缓存，缓存最近使用的 VPN→PFN 映射。

```
CPU 发出虚拟地址
       │
       ▼
  ┌──────────┐    命中
  │  TLB 查找 │─────────→ 直接得到物理地址（1~2 周期）
  └──────────┘
       │ 未命中
       ▼
  ┌──────────────┐
  │ 多级页表遍历  │ → 多次访问内存（数十~数百周期）
  │ (Page Walk)  │
  └──────────────┘
       │
       ▼
  将结果填入 TLB，返回物理地址
```

| 指标 | 典型值 |
|------|--------|
| L1 ITLB 大小 | 64~128 项 |
| L1 DTLB 大小 | 64~128 项 |
| L2 STLB 大小 | 1024~2048 项 |
| TLB 命中延迟 | 1~2 周期 |
| TLB 未命中延迟 | 50~200 周期 |
| 典型命中率 | >99% |

**大页（Huge Pages）减少 TLB 失效**：

```cpp
#include <iostream>

int main() {
    const size_t page_4kb = 4 * 1024;
    const size_t page_2mb = 2 * 1024 * 1024;
    const size_t page_1gb = 1024 * 1024 * 1024;

    size_t mapping_size = 1ULL * 1024 * 1024 * 1024;

    std::cout << "映射 1GB 内存所需 TLB 项:\n";
    std::cout << "  4KB 页: " << mapping_size / page_4kb << " 项\n";
    std::cout << "  2MB 页: " << mapping_size / page_2mb << " 项\n";
    std::cout << "  1GB 页: " << mapping_size / page_1gb << " 项\n";
    return 0;
}
```

> Linux 可通过 `cat /proc/cpuinfo | grep -i tlb` 或 `perf stat -e dTLB-load-misses` 观察 TLB 行为。

### 5. 缺页中断与按需调页

当进程访问的虚拟地址对应的页表项 Valid 位为 0 时，CPU 触发缺页中断（Page Fault），由操作系统决定如何处理。

```
进程访问虚拟地址
       │
       ▼
  页表项 Valid=1? ──是──→ 正常访问
       │ 否
       ▼
  触发 Page Fault (#PF)
       │
       ▼
  ┌──────────────────────────┐
  │ OS 缺页处理程序           │
  │                          │
  │  1. 检查地址是否合法      │
  │     不合法 → SIGSEGV     │
  │                          │
  │  2. 分配一个物理页帧      │
  │                          │
  │  3. 若需要，从磁盘读入数据 │
  │     (如 mmap 文件映射)    │
  │                          │
  │  4. 更新页表项            │
  │                          │
  │  5. 刷新 TLB              │
  │                          │
  │  6. 重新执行触发指令      │
  └──────────────────────────┘
```

```cpp
#include <iostream>
#include <vector>
#include <chrono>

int main() {
    const size_t size = 256 * 1024 * 1024;

    auto* buf = static_cast<int*>(malloc(size * sizeof(int)));

    auto t1 = std::chrono::high_resolution_clock::now();
    for (size_t i = 0; i < size; ++i) {
        buf[i] = static_cast<int>(i);
    }
    auto t2 = std::chrono::high_resolution_clock::now();

    auto ms = std::chrono::duration_cast<std::chrono::milliseconds>(t2 - t1).count();
    std::cout << "写入 " << size * sizeof(int) / (1024 * 1024) << " MB 耗时: "
              << ms << " ms\n";
    std::cout << "(首次写入触发大量缺页中断，速度较慢)\n";

    auto t3 = std::chrono::high_resolution_clock::now();
    for (size_t i = 0; i < size; ++i) {
        buf[i] = static_cast<int>(i);
    }
    auto t4 = std::chrono::high_resolution_clock::now();

    ms = std::chrono::duration_cast<std::chrono::milliseconds>(t4 - t3).count();
    std::cout << "第二次写入耗时: " << ms << " ms\n";
    std::cout << "(页已在内存中，无缺页中断，速度更快)\n";

    free(buf);
    return 0;
}
```

> Linux 下可通过 `ps -o pid,maj_flt,min_flt -p <pid>` 查看进程的缺页统计。

### 6. 交换区与页面换出

当物理内存不足时，操作系统将不活跃的页面换出到磁盘交换区（Swap），腾出物理页帧供其他进程使用。

| 换出策略 | 说明 |
|---------|------|
| LRU 近似 | Linux 使用时钟算法（Clock Algorithm）近似 LRU |
| PTE Accessed 位 | 硬件自动设置，OS 周期性清除，据此判断活跃度 |
| Swap 分区/文件 | Windows 使用 pagefile.sys，Linux 使用 swap 分区或文件 |
| kswapd | Linux 后台守护线程，提前回收内存避免直接回收 |

```cpp
#include <iostream>
#include <cstdlib>
#include <cstring>

int main() {
    const size_t chunk = 256 * 1024 * 1024;
    std::vector<void*> allocations;

    std::cout << "逐步分配内存，观察 Swap 行为...\n";

    for (int i = 0; i < 20; ++i) {
        void* p = malloc(chunk);
        if (!p) {
            std::cout << "分配失败! 已分配 " << i << " 块\n";
            break;
        }
        memset(p, 0xAA, chunk);
        allocations.push_back(p);
        std::cout << "已分配: " << (i + 1) * chunk / (1024 * 1024) << " MB\n";
    }

    for (auto p : allocations) {
        free(p);
    }
    return 0;
}
```

> 运行此程序时可用 `watch -n 1 free -h` 或任务管理器观察可用内存和 Swap 使用量的变化。

**Swap 的利弊**：

| 优点 | 缺点 |
|------|------|
| 允许运行超过物理内存的进程 | 磁盘 I/O 极慢（比内存慢 10 万倍） |
| 为不活跃页面提供去处 | 频繁换入换出导致 Thrashing |
| 紧急时提供缓冲 | 增加延迟，降低响应速度 |

### 7. mmap——内存映射文件

`mmap` 将文件或设备映射到进程的虚拟地址空间，访问内存等同于读写文件，无需 `read/write` 系统调用。

```cpp
#ifdef _WIN32
// Windows (MSVC/MinGW)
#include <windows.h>
#else
// POSIX (Linux/macOS)
#include <sys/mman.h>
#include <sys/stat.h>
#include <fcntl.h>
#include <unistd.h>
#endif

#include <iostream>

int main() {
    const char* filepath = "test_mmap.dat";
    const size_t filesize = 4096 * 10;

#ifdef _WIN32
    // Windows (MSVC/MinGW)
    HANDLE hFile = CreateFileA(filepath, GENERIC_READ | GENERIC_WRITE,
                               0, NULL, CREATE_ALWAYS, FILE_ATTRIBUTE_NORMAL, NULL);
    HANDLE hMap = CreateFileMapping(hFile, NULL, PAGE_READWRITE, 0,
                                    static_cast<DWORD>(filesize), NULL);
    char* addr = static_cast<char*>(MapViewOfFile(hMap, FILE_MAP_ALL_ACCESS,
                                                   0, 0, filesize));
    for (size_t i = 0; i < filesize; ++i) {
        addr[i] = static_cast<char>('A' + (i % 26));
    }
    std::cout << "Windows mmap 写入完成\n";
    UnmapViewOfFile(addr);
    CloseHandle(hMap);
    CloseHandle(hFile);
#else
    // POSIX (Linux/macOS)
    int fd = open(filepath, O_RDWR | O_CREAT, 0666);
    ftruncate(fd, filesize);

    void* addr = mmap(nullptr, filesize, PROT_READ | PROT_WRITE,
                       MAP_SHARED, fd, 0);
    char* p = static_cast<char*>(addr);
    for (size_t i = 0; i < filesize; ++i) {
        p[i] = static_cast<char>('A' + (i % 26));
    }
    std::cout << "Linux mmap 写入完成\n";
    munmap(addr, filesize);
    close(fd);
#endif
    return 0;
}
```

| 特性 | read/write | mmap |
|------|-----------|------|
| 数据拷贝 | 2 次（内核缓冲区→用户缓冲区） | 0 次（直接访问） |
| 系统调用 | 每次读写均需 | 仅映射时一次 |
| 随机访问 | 需 seek + read | 直接指针偏移 |
| 适用场景 | 大文件顺序读写 | 随机访问、共享内存 |
| 风险 | 无 | 信号 SIGBUS（文件被截断） |

> `mmap` 的 MAP_SHARED 选项使得修改对其他映射同一文件的进程可见，这是共享内存 IPC 的基础。

### 8. 虚拟内存的三大核心收益

| 收益 | 说明 | 示例 |
|------|------|------|
| 进程隔离 | 每个进程独立地址空间，互不可见 | 进程 A 地址 0x1000 与进程 B 地址 0x1000 映射到不同物理页 |
| 内存保护 | 页级权限控制（R/W/X/U） | .text 段设为只读+可执行，防止代码被篡改 |
| 内存超卖 | 虚拟地址总和可超过物理内存 | 4GB 物理内存可运行 10 个各需 2GB 的进程（按需调页） |

```cpp
#include <iostream>

int main() {
    int* p = new int(42);

    std::cout << "值: " << *p << "\n";

    volatile int* vp = p;
    *vp = 100;
    std::cout << "修改后: " << *p << "\n";

    delete p;

    return 0;
}
```

> 试图访问已释放的内存（use-after-free）可能触发段错误，也可能因为页面仍被映射而"成功"——这正是虚拟内存保护粒度为页而非字节的体现。

### 9. 页大小与大页

标准页大小为 4KB，但现代 CPU 支持更大的页尺寸以减少 TLB 压力。

| 页大小 | 体系结构 | TLB 覆盖率提升 |
|--------|---------|---------------|
| 4 KB | x86-64 (默认) | 基准 |
| 2 MB | x86-64 (1GB 页表项) | 512x |
| 1 GB | x86-64 (1GB 页) | 262144x |
| 64 KB | ARM64 (默认) | 16x |
| 16 MB | PowerPC | 4096x |

```cpp
#include <iostream>

#ifdef _WIN32
// Windows (MSVC/MinGW)
#include <windows.h>
#else
// POSIX (Linux/macOS)
#include <sys/mman.h>
#endif

int main() {
    const size_t huge_size = 2 * 1024 * 1024;

#ifdef _WIN32
    // Windows (MSVC/MinGW)
    HANDLE hMap = CreateFileMapping(INVALID_HANDLE_VALUE, NULL,
                                     SEC_COMMIT | SEC_LARGE_PAGES,
                                     0, static_cast<DWORD>(huge_size), NULL);
    if (hMap) {
        void* p = MapViewOfFile(hMap, FILE_MAP_ALL_ACCESS, 0, 0, huge_size);
        std::cout << "Windows 大页分配成功: " << p << "\n";
        UnmapViewOfFile(p);
        CloseHandle(hMap);
    }
#else
    // POSIX (Linux/macOS)
    void* p = mmap(nullptr, huge_size, PROT_READ | PROT_WRITE,
                    MAP_PRIVATE | MAP_ANONYMOUS | MAP_HUGETLB, -1, 0);
    if (p != MAP_FAILED) {
        std::cout << "Linux 大页分配成功: " << p << "\n";
        munmap(p, huge_size);
    } else {
        std::cout << "Linux 大页分配失败，请检查 /proc/sys/vm/nr_hugepages\n";
    }
#endif
    return 0;
}
```

> Linux 使用大页前需配置：`echo 100 > /proc/sys/vm/nr_hugepages` 或使用透明大页（THP）。

### 10. 写时复制（COW）

写时复制（Copy-On-Write）让多个进程共享同一物理页，仅在写入时才创建私有副本，广泛用于 `fork()` 和内存映射。

```
fork() 前:                fork() 后 (COW):
父进程                    父进程          子进程
┌──────┐                 ┌──────┐       ┌──────┐
│ PTE  │→ 物理页A        │ PTE  │→ 物理页A ←│ PTE  │
│ RW   │                 │ RO   │       │ RO   │
└──────┘                 └──────┘       └──────┘

子进程写入时:
父进程                    子进程
┌──────┐                 ┌──────┐
│ PTE  │→ 物理页A        │ PTE  │→ 物理页B (新复制)
│ RW   │                 │ RW   │
└──────┘                 └──────┘
```

```cpp
#include <iostream>
#include <cstring>

#ifdef _WIN32
#include <windows.h>
#else
#include <unistd.h>
#include <sys/wait.h>
#endif

int main() {
    char shared_buf[4096];
    strcpy(shared_buf, "Hello from parent");

#ifdef _WIN32
    std::cout << "Windows 下 COW 机制由 Copy-on-Write 内存管理实现\n";
    std::cout << "shared_buf 内容: " << shared_buf << "\n";
#else
    pid_t pid = fork();

    if (pid == 0) {
        std::cout << "[子进程] 读取: " << shared_buf << "\n";
        strcpy(shared_buf, "Hello from child");
        std::cout << "[子进程] 写入后: " << shared_buf << "\n";
        _exit(0);
    } else {
        waitpid(pid, nullptr, 0);
        std::cout << "[父进程] 子进程退出后: " << shared_buf << "\n";
    }
#endif
    return 0;
}
```

> COW 使得 `fork()` 几乎是 O(1) 操作——只需复制页表，不复制物理内存。

### 11. 栈的自动增长

进程的栈空间并非一次性分配全部物理内存，而是随着函数调用深度增加，由操作系统按需扩展。

```
虚拟地址空间布局 (Linux x86-64):

高地址 ┌──────────────┐
       │  内核空间     │
       ├──────────────┤
       │  栈 ↓ 增长    │ ← 栈顶 (RSP)
       │  (未映射区域)  │ ← 触发缺页时自动扩展
       │  ...         │
       │  已使用的栈   │
       ├──────────────┤
       │  共享库       │
       ├──────────────┤
       │  堆 ↑ 增长    │
       ├──────────────┤
       │  .bss         │
       │  .data        │
       │  .text        │
低地址 └──────────────┘
```

```cpp
#include <iostream>
#include <vector>

void deep_recursion(int depth) {
    char buf[4096];
    buf[0] = static_cast<char>(depth);

    if (depth <= 0) {
        std::cout << "递归到底, 深度: " << depth << "\n";
        return;
    }
    deep_recursion(depth - 1);
}

int main() {
    std::cout << "测试栈自动增长...\n";

    deep_recursion(100);

    std::cout << "递归完成\n";

    return 0;
}
```

| 平台 | 默认栈大小 | 查看方式 | 修改方式 |
|------|-----------|---------|---------|
| Linux | 8 MB | `ulimit -s` | `ulimit -s unlimited` |
| Windows | 1 MB | PE 头中 | 链接器 `/STACK:size` 选项 |
| macOS | 8 MB | `ulimit -s` | `ulimit -s size` |

> Windows 栈大小在编译时写入 PE 头，Linux 栈大小可运行时调整。栈溢出时 Linux 发送 SIGSEGV，Windows 触发 STATUS_STACK_OVERFLOW 异常。

### 12. 极简总结

| 概念 | 核心要点 |
|------|---------|
| 虚拟地址 | 每个进程独立、连续的地址空间，由 MMU 翻译为物理地址 |
| 页表 | VPN→PFN 的映射表，多级结构节省内存，由 OS 维护 |
| TLB | 地址翻译缓存，命中时 1~2 周期，未命中需 Page Walk |
| 缺页中断 | 访问未映射页时触发，OS 按需分配物理页并填入页表 |
| 按需调页 | 页面在首次访问时才分配物理内存，避免浪费 |
| Swap | 物理内存不足时将不活跃页换出到磁盘 |
| mmap | 文件映射到地址空间，零拷贝访问，支持共享内存 |
| 三大收益 | 隔离、保护、超卖 |
| 页大小 | 默认 4KB，大页 2MB/1GB 减少 TLB 压力 |
| COW | fork 时共享物理页，写入时才复制，节省内存 |
| 栈增长 | 栈空间按需扩展，访问未映射区域触发缺页自动增长 |

**关键公式**：
- 物理地址 = PFN × 页大小 + 页内偏移
- 虚拟地址 = VPN × 页大小 + 页内偏移
- TLB 命中率 > 99% 是系统性能的关键
