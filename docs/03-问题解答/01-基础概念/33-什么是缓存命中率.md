# 什么是缓存命中率
> 📖 相关章节：[运算符与表达式](../../01-C语言/02-运算符与表达式.md)、[控制结构](../../01-C语言/03-控制结构.md)、[函数](../../01-C语言/04-函数.md)、[基础特性](../../02-CPP/01-基础特性.md)、[命名空间](../../02-CPP/02-命名空间与编码规范.md)

### 1. 核心定义

**缓存命中率** = 缓存中找到数据的次数 / 总访问次数 × 100%

### 2. CPU 读数据的流程

```
L1缓存 → L2缓存 → L3缓存 → 内存
就近原则：能在近处拿就不去远处
```

- **命中**：缓存里有数据 → 原地拿走，**极快**
- **未命中**：缓存里没有 → 跑去内存拿，**巨慢**

### 3. 缓存层级详解

| 层级 | 大小 | 访问时间 | 位置 |
|:---:|:---:|:---:|:---:|
| L1 | 32KB / 核 | ~1 ns | CPU 核心内 |
| L2 | 256KB / 核 | ~4 ns | CPU 核心内 |
| L3 | 8-32MB 共享 | ~15 ns | CPU 芯片内 |
| 内存 RAM | 8-64GB | ~100 ns | 芯片外 |

**关键结论**：L1 到内存的速度差约 **100 倍**，这就是为什么缓存命中率至关重要。

### 4. 缓存行 (Cache Line)

CPU 不按字节读取，而按 **缓存行**（通常 64 字节）读取：

```
内存地址 0x00 ~ 0x3F  → 缓存行 0
内存地址 0x40 ~ 0x7F  → 缓存行 1
...
```

**影响**：访问一个字节，相邻 64 字节都被载入缓存 → 利用此特性可大幅提升性能。

### 5. 时间局部性与空间局部性

| 特性 | 定义 | 例子 |
|:---|:---|:---|
| 时间局部性 | 刚用过的数据很快再用 | 循环中的计数器 |
| 空间局部性 | 相邻地址的数据会被用到 | 数组顺序遍历 |

### 6. 生活类比

把 CPU 当成你本人：

- **L1/L2 缓存**：手边桌面，伸手就拿到
- **内存 RAM**：楼下仓库，要走路、排队、找东西，慢死

**场景：**
你一天要拿 1000 份文件：

- 920 份就在桌上，伸手就拿 → **命中**
- 80 份桌上没有，必须跑楼下仓库 → **未命中**

**命中率 92%** = **92% 都在手边，只有 8% 要跑远路**

### 7. 速度差距（关键！）

| 存储层级 | 访问时间 |
| ----- | ------ |
| L1 缓存 | 1 纳秒 |
| 内存 | 100 纳秒 |

**去内存拿一次 = 缓存里拿 100 次的时间**

### 8. 代码示例：缓存友好 vs 不友好

```cpp
const int N = 1024;
int a[N][N];

// ❌ 缓存不友好：按列访问（跳跃式）
int sum_col = 0;
for (int j = 0; j < N; j++)          // 外层列
    for (int i = 0; i < N; i++)      // 内层行
        sum_col += a[i][j];           // 每步跨 N×4 字节

// ✅ 缓存友好：按行访问（连续）
int sum_row = 0;
for (int i = 0; i < N; i++)          // 外层行
    for (int j = 0; j < N; j++)      // 内层列
        sum_row += a[i][j];           // 连续访问，缓存行充分利用
```

**性能差距**：按行访问比按列访问通常快 **10~50 倍**（N 越大差距越大）。

### 9. 极端例子对比

**场景A：命中率 99%**

- 100 次访问，99 次在缓存，只 1 次跑内存
- 总耗时 ≈ 99×1ns + 1×100ns = 199ns
- 👉 几乎全程超速，程序飞快

**场景B：命中率 50%**

- 100 次访问，50 次要跑去内存
- 总耗时 ≈ 50×1ns + 50×100ns = 5050ns
- 👉 慢 25 倍以上，程序明显卡顿

### 10. 缓存未命中的三种类型

| 类型 | 原因 | 解决方法 |
|:---|:---|:---|
| 强制未命中 | 第一次访问数据 | 预取 |
| 容量未命中 | 缓存不够大 | 分块处理 |
| 冲突未命中 | 地址映射冲突 | 调整数据对齐 |

### 11. 与抽象开销的关联

复杂封装（vtable、函数指针、多层封装）会破坏 **CPU 缓存局部性**，导致：

```
缓存命中率下降 → 更多内存访问 → 程序变慢
```

### 12. 极简一句话总结

**缓存命中率高 = 要的数据大多就在 CPU 手边，不用跑去慢腾腾的内存**
