# 栈与堆的区别
> 📖 相关章节：[指针](../../01-C语言/06-指针.md)、[结构体与联合体](../../01-C语言/08-结构体与联合体.md)、[内存管理](../../01-C语言/09-内存管理.md)、[智能指针](../../02-CPP/08-智能指针与内存管理.md)、[内存模型](../../02-CPP/32-内存模型.md)

> **Stack is automatic, heap is manual. Know the difference, avoid the pain.** — 栈是自动的，堆是手动的。了解区别，避免痛苦。

***

### 1. 核心速览

**栈和堆都在内存条上**，区别在于管理方式：栈由编译器自动管理（后进先出），堆由程序员手动管理（malloc/new 申请，free/delete 释放）。

***

### 2. 进程内存布局

```
高地址
┌─────────────────────┐
│     内核空间         │  操作系统保留
├─────────────────────┤
│     栈区 (Stack)     │  ↓ 向低地址增长
│         ↓           │
│                     │
│     （空闲空间）      │
│                     │
│         ↑           │
│     堆区 (Heap)      │  ↑ 向高地址增长
├─────────────────────┤
│     BSS段            │  未初始化的全局/静态变量
├─────────────────────┤
│     数据段 (Data)     │  已初始化的全局/静态变量
├─────────────────────┤
│     代码段 (Text)     │  程序指令
└─────────────────────┘
低地址
```

**栈和堆都在内存条上**，CPU 缓存对两者一视同仁——哪个刚被访问过就缓存哪个。

### 3. 栈 vs 堆 对比

| 特性 | 栈（Stack） | 堆（Heap） |
|------|:---:|:---:|
| 分配方式 | 编译器自动 | 程序员手动 |
| 释放方式 | 作用域结束自动释放 | 手动 free/delete |
| 速度 | 极快（移动指针） | 较慢（查找空闲块） |
| 大小 | 小（通常1-8MB） | 大（受系统内存限制） |
| 碎片 | 无 | 有 |
| 生命周期 | 函数调用期间 | 手动控制 |
| 线程安全 | 是（每线程独立栈） | 否（共享堆） |
| 分配方向 | 向低地址增长 | 向高地址增长 |

### 4. 栈的工作原理

```cpp
void foo() {
    int a = 1;      // push a
    int b = 2;      // push b
    // 函数结束 → pop b, pop a（后进先出）
}
```

**栈指针移动一下就完成分配/释放，所以极快。**

每次函数调用都会在栈上创建一个**栈帧（Stack Frame）**，包含：局部变量、参数、返回地址。

```
调用 foo(3, 4) 时的栈帧：
┌──────────────┐
│ 返回地址      │
│ 参数2: 4      │
│ 参数1: 3      │
│ 局部变量 a    │
│ 局部变量 b    │
└──────────────┘
```

### 5. 堆的工作原理

```cpp
int* p = new int(42);
// 1. 在堆中找到一块空闲内存
// 2. 标记为已使用
// 3. 返回地址
delete p;
// 1. 标记该内存为空闲
// 2. 可能合并相邻空闲块
```

**堆需要查找空闲块、维护分配表，所以较慢。**

堆分配器的常见策略：

| 策略 | 原理 | 特点 |
|------|------|------|
| 首次适配 | 找到第一个够大的空闲块 | 速度快，碎片多 |
| 最佳适配 | 找到最小的够大空闲块 | 碎片少，速度慢 |
| 伙伴系统 | 按2的幂次分配 | 适合内核，外部碎片少 |

### 6. 栈溢出（Stack Overflow）

栈空间有限，超出限制就会栈溢出：

```cpp
void infinite_recursion(int n) {
    int big_array[10000];  // 每次调用占 ~40KB
    infinite_recursion(n + 1);  // 无限递归，很快溢出
}
```

常见栈溢出原因：

| 原因 | 示例 | 解决方案 |
|------|------|----------|
| 无限递归 | 缺少终止条件 | 确保递归有基线条件 |
| 局部数组过大 | `int arr[1000000];` | 改用堆分配或std::vector |
| 递归深度过大 | 快排最坏情况 | 改用迭代或限制深度 |

各平台默认栈大小：

| 平台 | 默认栈大小 |
|------|-----------|
| Linux | 8 MB |
| macOS | 8 MB |
| Windows | 1 MB（主线程），可配置 |
| 嵌入式 | 通常几KB |

Windows 上可以在链接器选项中修改栈大小：`/STACK:8388608`（8MB）。

### 7. 内存对齐

CPU 访问内存时，按对齐边界读取效率最高。未对齐的访问可能导致性能下降甚至崩溃（某些架构）。

```cpp
#include <iostream>

struct Unaligned {
    char a;     // 1字节
    int b;      // 4字节
    char c;     // 1字节
};

struct Aligned {
    int b;      // 4字节
    char a;     // 1字节
    char c;     // 1字节
};

int main() {
    std::cout << "Unaligned: " << sizeof(Unaligned) << std::endl;  // 12
    std::cout << "Aligned: " << sizeof(Aligned) << std::endl;      // 8
}
```

| 类型 | 大小 | 对齐要求 |
|------|------|----------|
| char | 1 | 1 |
| short | 2 | 2 |
| int | 4 | 4 |
| double | 8 | 8 |
| 指针（64位） | 8 | 8 |

C++11 提供对齐控制：

```cpp
struct alignas(16) SIMDVector {
    float data[4];
};
```

### 8. RAII — 资源获取即初始化

RAII 是 C++ 管理资源的核心范式：在构造函数中获取资源，在析构函数中释放资源。

```cpp
#include <iostream>
#include <fstream>
#include <string>

class FileWrapper {
    std::fstream file_;
public:
    explicit FileWrapper(const std::string& path) {
        file_.open(path);
        if (!file_.is_open()) {
            throw std::runtime_error("无法打开文件");
        }
    }

    ~FileWrapper() {
        if (file_.is_open()) {
            file_.close();
        }
    }

    FileWrapper(const FileWrapper&) = delete;
    FileWrapper& operator=(const FileWrapper&) = delete;

    std::string read_line() {
        std::string line;
        std::getline(file_, line);
        return line;
    }
};

void process_file() {
    FileWrapper fw("data.txt");
    std::string line = fw.read_line();
    std::cout << line << std::endl;
}
```

即使 `read_line()` 抛出异常，`fw` 的析构函数也会被调用，文件自动关闭。

### 9. 智能指针 — 现代C++的堆管理

智能指针是 RAII 在堆内存上的应用，自动管理 new/delete：

```cpp
#include <iostream>
#include <memory>
#include <vector>

class Resource {
public:
    Resource() { std::cout << "Resource acquired" << std::endl; }
    ~Resource() { std::cout << "Resource released" << std::endl; }
    void use() { std::cout << "Using resource" << std::endl; }
};

int main() {
    {
        std::unique_ptr<Resource> p1 = std::make_unique<Resource>();
        p1->use();
    }

    {
        std::shared_ptr<Resource> p2 = std::make_shared<Resource>();
        std::shared_ptr<Resource> p3 = p2;
        std::cout << "引用计数: " << p2.use_count() << std::endl;
    }

    {
        std::unique_ptr<Resource[]> arr = std::make_unique<Resource[]>(3];
    }
}
```

| 智能指针 | 所有权 | 开销 | 适用场景 |
|----------|--------|------|----------|
| unique_ptr | 独占 | 几乎为零 | 默认选择 |
| shared_ptr | 共享（引用计数） | 有 | 需要共享所有权 |
| weak_ptr | 不拥有 | 有 | 打破shared_ptr循环引用 |

### 10. 什么时候用栈，什么时候用堆

| 场景 | 选择 | 原因 |
|------|------|------|
| 局部变量、函数参数 | 栈 | 自动管理，无需手动释放 |
| 小对象、确定大小 | 栈 | 栈分配快，缓存友好 |
| 大对象（超过栈大小） | 堆 | 栈空间有限 |
| 生命周期超出函数 | 堆 | 栈变量随函数返回销毁 |
| 运行时才知大小 | 堆 | 栈要求编译期确定大小 |
| 多线程共享数据 | 堆 | 堆是线程共享的 |
| 多态对象 | 堆 | 基类指针指向派生类 |

现代 C++ 的选择优先级：

```
1. 栈分配（首选）
2. std::vector / std::string（内部用堆，外部用RAII）
3. std::unique_ptr（需要多态或生命周期控制）
4. std::shared_ptr（需要共享所有权）
5. 裸 new/delete（几乎不应该使用）
```

### 11. 现代 C++ 内存管理最佳实践

```cpp
#include <vector>
#include <memory>
#include <string>

class Entity {
public:
    virtual ~Entity() = default;
    virtual std::string name() const = 0;
};

class Player : public Entity {
    std::string name_;
public:
    explicit Player(std::string name) : name_(std::move(name)) {}
    std::string name() const override { return name_; }
};

std::unique_ptr<Entity> create_entity(const std::string& type) {
    return std::make_unique<Player>(type);
}

int main() {
    std::vector<int> data = {1, 2, 3, 4, 5};

    auto entity = create_entity("勇者");

    auto shared_data = std::make_shared<std::vector<double>>(100, 0.0);
}
```

| 做法 | 推荐 | 说明 |
|------|------|------|
| `std::vector` 替代 `new[]` | 推荐 | 自动管理，支持RAII |
| `std::make_unique` 替代 `new` | 推荐 | 异常安全 |
| `std::make_shared` 替代 `new` | 推荐 | 一次分配，缓存友好 |
| 裸 `new`/`delete` | 不推荐 | 容易忘记释放或重复释放 |
| `malloc`/`free` | 不推荐 | 不调用构造/析构函数 |

### 12. 极简总结

**栈 = 编译器自动管理 + 后进先出 + 快 + 小；堆 = 程序员手动管理 + 灵活 + 慢 + 大；两者都在内存条上 → 栈溢出要警惕 → RAII是C++资源管理核心 → 智能指针替代裸new/delete → 优先栈分配**
