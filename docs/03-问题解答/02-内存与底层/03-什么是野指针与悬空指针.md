# 什么是野指针与悬空指针
> 📖 相关章节：[指针](../../01-C语言/06-指针.md)、[内存管理](../../01-C语言/09-内存管理.md)

> **Dangling pointers are the silent killers of C/C++ programs.** — 悬空指针是 C/C++ 程序的隐形杀手。

***

### 1. 核心提炼

**野指针**（Wild Pointer）= 未初始化的指针，指向随机地址。**悬空指针**（Dangling Pointer）= 指向已释放内存的指针。两者解引用都是**未定义行为**，可能崩溃、可能数据损坏、可能看似正常——这是最危险的 Bug 类型。

***

### 2. 生活类比

把指针比作**门钥匙**：

- **野指针** → 捡到一把来历不明的钥匙，不知道能开哪扇门（随机地址），可能开别人的门，也可能打不开
- **悬空指针** → 房子已经拆了，但你还拿着那把钥匙（地址），再去开门就是闯入废墟
- **use-after-free** → 房子拆了，你还进去翻东西（访问已释放的内存）

### 3. 野指针 vs 悬空指针

| 特性 | 野指针（Wild） | 悬空指针（Dangling） |
|------|:---:|:---:|
| 原因 | 未初始化 | 指向已释放的内存 |
| 指向 | 随机地址 | 曾经有效的地址 |
| 危险程度 | 极高 | 极高 |
| 可预测性 | 完全不可预测 | 可能暂时"正常工作" |
| 检测难度 | 较难 | 很难（可能时隐时现） |

### 4. 野指针的产生

```cpp
// 情况1：未初始化
int* p1;           // 野指针！指向随机地址
// *p1 = 42;       // 未定义行为

// 情况2：malloc 未检查返回值
#include <cstdlib>
int* p2 = (int*)malloc(sizeof(int));
// 如果 malloc 失败返回 NULL，p2 是空指针
// 但如果不检查就使用，也可能出问题

// 情况3：指针越界后使用
int arr[5];
int* p3 = arr + 10;  // 越界指针，行为类似野指针
// *p3 = 42;         // 未定义行为
```

**正确做法：初始化所有指针**

```cpp
#include <memory>  // 智能指针所需头文件
int* p1 = nullptr;              // 初始化为空
int value = 42;
int* p2 = &value;               // 初始化为有效地址
auto p3 = std::make_unique<int>(42);  // 智能指针
```

### 5. 悬空指针的产生

**场景1：局部变量销毁**

```cpp
#include <iostream>

int* create_dangling() {
    int local = 42;
    return &local;  // 返回局部变量地址 → 悬空指针
}  // local 在此销毁

void example() {
    int* p = create_dangling();
    // std::cout << *p;  // 未定义行为！p 是悬空指针
}
```

**场景2：delete 后继续使用**

```cpp
int* p = new int(42);
delete p;        // 内存已释放
// *p = 100;    // 未定义行为！p 是悬空指针
// p 此时仍保存原地址，但内存已不属于你
```

**场景3：容器操作导致引用失效**

```cpp
#include <vector>

void vector_dangling() {
    std::vector<int> v = {1, 2, 3};
    int& ref = v[0];       // 引用第一个元素
    v.push_back(4);        // 可能触发重新分配！
    // std::cout << ref;   // 未定义行为！ref 可能悬空
}
```

**场景4：对象析构后使用**

```cpp
#include <iostream>
#include <memory>

class Resource {
public:
    int value = 42;
};

void use_after_free() {
    Resource* p = new Resource();
    delete p;
    // std::cout << p->value;  // use-after-free！未定义行为
}
```

### 6. Use-After-Free 详解

Use-after-free（释放后使用）是悬空指针最常见、最危险的形式：

```cpp
#include <iostream>

char* get_data() {
    char buffer[64];
    std::strcpy(buffer, "secret data");
    return buffer;  // 返回局部数组地址 → 悬空指针
}

void exploit() {
    char* data = get_data();
    // data 指向的栈空间可能已被其他函数覆盖
    // std::cout << data;  // 可能输出乱码、崩溃、或泄露其他数据
}
```

**安全风险**：攻击者可以利用 use-after-free 漏洞执行任意代码（CVE 中最常见的漏洞类型之一）。

### 7. 如何预防

| 策略 | 说明 | 示例 |
|------|------|------|
| 初始化指针 | 始终初始化为 `nullptr` 或有效地址 | `int* p = nullptr;` |
| delete 后置空 | 释放后立即置空 | `delete p; p = nullptr;` |
| 使用智能指针 | 自动管理生命周期 | `auto p = make_unique<int>(42);` |
| 使用容器 | 替代手动数组管理 | `vector<int>` 替代 `new int[n]` |
| 避免返回局部引用 | 返回值而非引用 | `int f()` 而非 `int& f()` |
| 注意容器操作 | 操作后重新获取引用/迭代器 | `push_back` 后不用旧引用 |

**智能指针解决方案**：

```cpp
#include <iostream>
#include <memory>
#include <vector>

// 用 unique_ptr 替代裸 new/delete
void smart_pointer_solution() {
    auto p = std::make_unique<int>(42);
    // 不需要 delete，离开作用域自动释放
    // 也不可能忘记 delete 或重复 delete
}

// 用 shared_ptr 共享所有权
void shared_solution() {
    auto sp1 = std::make_shared<int>(42);
    auto sp2 = sp1;  // 共享所有权
    // 引用计数为 2，两个指针都有效
}

// 用容器替代手动数组
void container_solution() {
    std::vector<int> v = {1, 2, 3};
    v.push_back(4);  // 容器自动管理内存
    // 不会出现悬空指针
}
```

### 8. 检测工具

#### AddressSanitizer（ASan）

最强大的内存错误检测工具，能检测 use-after-free、越界访问等：

```bash
# GCC / Clang
g++ -fsanitize=address -g -O1 program.cpp -o program
./program

# MSVC
cl /fsanitize=address /Zi program.cpp
```

ASan 检测 use-after-free 的输出示例：

```
==12345==ERROR: AddressSanitizer: heap-use-after-free
READ of size 4 at 0x602000000010 thread T0
    #0 0x4008d7 in main /path/test.cpp:8:10
    #1 0x7f... in __libc_start_main

0x602000000010 is located 0 bytes inside of 4-byte region
freed by thread T0 here:
    #0 0x4d3b82 in operator delete(void*)
    #1 0x4008a4 in main /path/test.cpp:7:5
```

#### Valgrind

```bash
valgrind --leak-check=full ./program
```

#### 工具对比

| 工具 | 检测能力 | 性能开销 | 平台 |
|------|---------|---------|------|
| ASan | use-after-free、越界、泄漏 | ~2x | GCC/Clang/MSVC |
| Valgrind | 内存错误、泄漏 | ~20x | Linux/macOS |
| UBSan | 未定义行为 | ~1.5x | GCC/Clang |
| cppcheck | 静态分析 | 无运行开销 | 跨平台 |

### 9. 常见模式：安全 vs 危险

```cpp
#include <iostream>
#include <memory>
#include <vector>
#include <string>

// ===== 危险模式 =====

// 危险：返回局部变量指针
int* bad_return() {
    int x = 42;
    return &x;  // 悬空指针
}

// 危险：手动管理数组
void bad_array() {
    int* arr = new int[100];
    // ... 使用 arr ...
    delete[] arr;
    // arr[0] = 1;  // use-after-free！
}

// ===== 安全模式 =====

// 安全：返回值
int good_return() {
    int x = 42;
    return x;  // 返回副本
}

// 安全：使用 vector
void good_array() {
    std::vector<int> arr(100);
    // ... 使用 arr ...
    // 自动管理，不会悬空
}

// 安全：使用智能指针
std::unique_ptr<int[]> good_dynamic() {
    auto arr = std::make_unique<int[]>(100);
    return arr;  // 所有权转移
}
```

### 10. 极简总结

**野指针 = 未初始化（随机地址）；悬空指针 = 指向已释放内存 → 两者解引用都是 UB → 预防：初始化为 nullptr、delete 后置空、用智能指针、用容器 → 检测：ASan 是最强工具 → use-after-free 是最常见的安全漏洞之一**
