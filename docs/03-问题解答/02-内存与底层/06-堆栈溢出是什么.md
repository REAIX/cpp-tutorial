# 堆栈溢出是什么
> 📖 相关章节：[内存管理](../../01-C语言/09-内存管理.md)、[函数](../../01-C语言/04-函数.md)

> "Stack overflow: when recursion goes too deep" — 递归过深，栈溢出了

### 1. 本质洞察

**栈溢出**（Stack Overflow）= 栈空间用完了，通常是无限递归或局部变量太大导致。程序会立即崩溃。

***

### 2. 栈帧结构

每次函数调用都会在栈上分配一个**栈帧**（stack frame）：

```
高地址
+------------------+ ← 栈底（高地址）
| 上一个栈帧       |
+------------------+
| 参数              | ← 函数参数
| 返回地址          | ← 调用者下一条指令地址
| 保存的基址指针    | ← 旧 ebp/rbp
| 局部变量          | ← 局部变量和临时对象
| 保存的寄存器      |
+------------------+ ← 栈顶（低地址），esp/rsp
低地址
```

栈帧大小示例：
```cpp
void func(int a, double b) {
    int local1;        // 4 字节
    double local2;     // 8 字节
    char buffer[256];  // 256 字节
    // 一个栈帧约 280+ 字节（含返回地址、寄存器保存等）
}
```

### 3. 栈的大小

不同系统/编译器的默认栈大小：

```bash
# Linux 默认栈大小
ulimit -s  # 通常 8192 KB = 8 MB
# 临时修改：ulimit -s 16384（16 MB）

# Windows 默认栈大小
# 主线程：1 MB（VS 默认）
# 可通过编译选项修改：/STACK:reserve,commit
# 例：/STACK:8388608,4096（8 MB 保留，4 KB 提交）

# macOS 默认栈大小
# 主线程：8 MB（8192 KB）
# 辅助线程：512 KB
```

各线程栈大小对比：
| 线程类型 | 默认栈大小 | 修改方式 |
|----------|:----------:|----------|
| Linux 主线程 | 8 MB | `ulimit -s` |
| Linux 子线程 | 8 MB | `pthread_attr_setstacksize` |
| Windows 主线程 | 1 MB | `/STACK` 链接选项 |
| Windows 子线程 | 1 MB | `CreateThread` 参数 |
| macOS 主线程 | 8 MB | `sysctl` |
| 嵌入式系统 | 1-4 KB | 编译配置 |

### 4. 常见原因

#### 1. 原因1：无限递归

```cpp
void recurse() {
    int buf[100];  // 每次递归占 400+ 字节
    recurse();      // 无限递归 → 栈溢出
}
```

#### 2. 原因2：大局部变量

```cpp
void foo() {
    int big_array[1000000];  // 4 MB，超过栈大小
}

// 栈上分配大对象
void bar() {
    std::string huge_str(500000, 'x');  // 500KB，可能溢出
    // std::string 内部会堆分配，但栈上仍有小型对象
}

// 递归层数太多
void deep_recursion(int n) {
    char buffer[1024];  // 每层 1 KB
    if (n > 0) deep_recursion(n - 1);
    // n = 10000 时，需要约 10 MB 栈空间
}
```

#### 3. 原因3：深层函数调用

```cpp
// 调用链太深
a() → b() → c() → ... → z()
// 每层都有局部变量，累加超过栈大小

// 回调地狱
void onEvent() {
    processData();
}
void processData() {
    validate();
    compute();
    save();
}
void save() {
    onEvent();  // 循环调用，栈不断增长
}
```

### 5. 如何检测栈溢出

#### 1. 编译期检测

```cpp
// GCC/Clang: -fstack-protector-strong
// 在函数中插入栈保护检查

// MSVC: /GS
// 启用缓冲区安全检查

// 示例：stack smashing detected 错误
void vulnerable() {
    char buffer[8];
    strcpy(buffer, "this string is too long!");  // 溢出检测
}
```

#### 2. 运行时检测

```cpp
// POSIX (Linux/macOS)
#include <sys/resource.h>  // Linux
#include <signal.h>

// 设置栈大小限制
void set_stack_limit() {
    struct rlimit rl;
    rl.rlim_cur = 8 * 1024 * 1024;  // 8 MB
    rl.rlim_max = 16 * 1024 * 1024; // 16 MB
    setrlimit(RLIMIT_STACK, &rl);
}

// 信号处理：捕获段错误
void sigsegv_handler(int sig) {
    std::cerr << "Stack overflow detected!" << std::endl;
    _exit(1);
}

// Windows 结构化异常处理（SEH）
// __try { ... } __except(EXCEPTION_STACK_OVERFLOW) { ... }
```

#### 3. 工具检测

```bash
# Valgrind 检测栈使用
valgrind --tool=memcheck --max-stackframe=1048576 ./program

# AddressSanitizer（ASan）
g++ -fsanitize=address -g program.cpp
# 输出：ERROR: AddressSanitizer: stack-buffer-overflow

# 查看栈使用情况
gdb ./program
(gdb) info frame    # 查看当前栈帧
(gdb) backtrace     # 查看调用栈
```

### 6. 递归深度限制

递归深度上限估算：

```cpp
// 估算递归深度上限
// 假设栈大小 = 8 MB，每帧 = 64 字节 → 最大约 131072 层

// 尾递归优化（编译器可能优化为迭代）
int tail_factorial(int n, int acc = 1) {
    if (n <= 1) return acc;
    return tail_factorial(n - 1, n * acc);  // 尾递归
}

// 检查：编译器是否启用了优化
// g++ -O2 -foptimize-sibling-calls

// 手动限制递归深度
void safe_recurse(int depth) {
    const int MAX_DEPTH = 10000;
    if (depth > MAX_DEPTH) {
        throw std::runtime_error("recursion too deep");
    }
    // ... 递归逻辑
}
```

各类型函数每帧占用估算：
| 函数类型 | 每帧大小 | 8MB 栈最大递归层数 |
|----------|:--------:|:----------------:|
| 空函数 | ~16 字节 | ~500K |
| 少量局部变量 | ~64 字节 | ~130K |
| 中等局部变量（256B） | ~280 字节 | ~30K |
| 大局部变量（4KB） | ~4KB | ~2000 |
| 超大局部变量（1MB） | ~1MB+ | ~8 |

### 7. 解决方法

| 原因 | 解决方法 |
|------|----------|
| 无限递归 | 加终止条件 |
| 递归太深 | 改为迭代 |
| 大局部变量 | 用堆分配（new/vector） |
| 栈太小 | 调整系统限制（不推荐） |
| 深调用链 | 重构减少嵌套 |
| 回调循环 | 检查逻辑避免循环调用 |

### 8. 递归改迭代示例

```cpp
// 递归版本（可能栈溢出）
int factorial(int n) {
    if (n <= 1) return 1;
    return n * factorial(n - 1);
}

// 迭代版本（不会栈溢出）
int factorial(int n) {
    int result = 1;
    for (int i = 2; i <= n; ++i) {
        result *= i;
    }
    return result;
}

// 递归：二叉树遍历
void traverse_recursive(TreeNode* node) {
    if (!node) return;
    traverse_recursive(node->left);
    process(node);
    traverse_recursive(node->right);
}

// 迭代：使用显式栈
void traverse_iterative(TreeNode* root) {
    std::stack<TreeNode*> stack;
    TreeNode* curr = root;
    while (curr || !stack.empty()) {
        while (curr) {
            stack.push(curr);
            curr = curr->left;
        }
        curr = stack.top();
        stack.pop();
        process(curr);
        curr = curr->right;
    }
}

// 递归：快速排序
// 递归深度 O(log n) 到 O(n)，最坏情况下可能溢出
// 优化：尾递归优化 + 小规模用插入排序
void quicksort(int arr[], int low, int high) {
    while (low < high) {
        int pi = partition(arr, low, high);
        if (pi - low < high - pi) {
            quicksort(arr, low, pi - 1);  // 递归小半边
            low = pi + 1;                  // 迭代大半边
        } else {
            quicksort(arr, pi + 1, high);
            high = pi - 1;
        }
    }
}
```

### 9. 堆分配替代栈分配

```cpp
// 错误：栈上分配大数组
void bad() {
    int large[1000000];  // 4 MB in stack
}

// 正确：堆上分配
void good() {
    std::vector<int> large(1000000);  // 4 MB in heap
}

// 智能指针管理堆内存
void process_data() {
    auto buffer = std::make_unique<char[]>(1024 * 1024);  // 1 MB in heap
    // 使用 buffer...
}  // 自动释放

// 栈上分配小对象，堆上分配大对象
class SafeObject {
    char small_buf[64];      // 栈上
    std::string dynamic_buf; // 堆上
};
```

### 10. 极简总结

**栈溢出 = 栈空间耗尽 → 递归太深/局部太大/无限分配 → 段错误崩溃；堆溢出 = 堆空间耗尽 → new抛bad_alloc → 防范 = 限制递归深度 + 避免大数组栈分配 + 检查返回值 + 使用容器替代裸数组**
