# 什么是写时复制
> 📖 相关章节：[智能指针与内存管理](../../02-CPP/08-智能指针与内存管理.md)、[核心机制](../../02-CPP/05-核心机制.md)

> "不修改就不复制，改了才各管各的"——COW 让共享变成零成本的默认行为，只在真正需要修改时才付出复制的代价。

***

### 1. 核心定义

**写时复制（Copy-on-Write，COW）** = 多个持有者共享同一份数据，直到有人要修改时才真正复制一份。

核心思想：**读共享，写分离**。不修改就不复制，修改了才各自独立。

| 要素 | 说明 |
|------|------|
| 共享 | 多个对象指向同一份数据，读操作直接访问 |
| 引用计数 | 记录有多少个持有者正在共享数据 |
| 延迟复制 | 只有在写操作时才检测引用计数，>1 则复制一份 |
| 独立 | 复制后修改者拥有自己的副本，不影响其他持有者 |

***

### 2. 生活类比

**COW = 共享文档**：

| 场景 | 类比 | 对应 COW |
|------|------|---------|
| 10个人看同一份在线文档 | 大家都看同一份，无需复制 | 读共享，零开销 |
| 有人要编辑 | 系统自动创建副本给他改 | 写时复制 |
| 其他人继续看原版 | 不受编辑者影响 | 修改者独立 |

**另一个类比：复印机**：

10个人看同一份报告（共享），只有需要批注的人才去复印一份（写时复制）。没人批注就不需要复印，省纸省时间。

***

### 3. COW 的工作原理

**流程图**：

```
初始状态：多个指针/引用指向同一份数据，引用计数 = 2

┌────────┐     ┌─────────────────┐
│ 指针 A  │────→│                 │
└────────┘     │   共享数据       │
               │   ref_count = 2  │
┌────────┐     │                 │
│ 指针 B  │────→│                 │
└────────┘     └─────────────────┘

读取操作：直接读取共享数据，无需复制
  指针 A 读取 → 直接返回共享数据 ✓
  指针 B 读取 → 直接返回共享数据 ✓

写入操作（指针 B 要修改）：
  1. 检测引用计数 > 1 → 需要复制
  2. 复制一份数据给 B
  3. B 修改自己的副本
  4. 原数据引用计数 -1

┌────────┐     ┌─────────────────┐
│ 指针 A  │────→│   原数据         │
└────────┘     │   ref_count = 1  │
               └─────────────────┘
┌────────┐     ┌─────────────────┐
│ 指针 B  │────→│   副本（已修改）  │
└────────┘     │   ref_count = 1  │
               └─────────────────┘
```

**伪代码流程**：

```cpp
void write(CowData& cow, const NewValue& val) {
    if (cow.ref_count > 1) {
        cow.data = copy(cow.data);  // 复制一份
        cow.ref_count -= 1;         // 原数据引用计数 -1
        cow.ref_count = 1;          // 新副本引用计数 = 1
    }
    cow.data = val;                 // 修改自己的副本
}
```

### 4. C++ 中的 COW 实现

#### 1. 方式1：手写 COW 类

```cpp
#include <iostream>
#include <cstring>
#include <atomic>

class CowString {
    struct SharedData {
        char* data;
        std::atomic<int> ref_count;

        SharedData(const char* s) : ref_count(1) {
            data = new char[std::strlen(s) + 1];
            std::strcpy(data, s);
        }

        ~SharedData() {
            delete[] data;
        }

        void add_ref() { ref_count.fetch_add(1); }
        int release() { return ref_count.fetch_sub(1) - 1; }
    };

    SharedData* shared;

    void detach() {
        if (shared && shared->ref_count > 1) {
            shared->release();
            shared = new SharedData(shared->data);
        }
    }

public:
    CowString(const char* s = "") : shared(new SharedData(s)) {}

    CowString(const CowString& other) : shared(other.shared) {
        shared->add_ref();
    }

    CowString& operator=(const CowString& other) {
        if (this != &other) {
            if (shared->release() == 0) delete shared;
            shared = other.shared;
            shared->add_ref();
        }
        return *this;
    }

    ~CowString() {
        if (shared->release() == 0) delete shared;
    }

    const char& operator[](size_t idx) const {
        return shared->data[idx];
    }

    char& operator[](size_t idx) {
        detach();
        return shared->data[idx];
    }

    void set(size_t idx, char c) {
        detach();
        shared->data[idx] = c;
    }

    const char* c_str() const { return shared->data; }

    int ref_count() const { return shared->ref_count; }
};

int main() {
    CowString a("Hello");
    std::cout << "a: " << a.c_str() << " ref=" << a.ref_count() << "\n";

    CowString b = a;
    std::cout << "b = a 后: a.ref=" << a.ref_count()
              << " b.ref=" << b.ref_count() << "\n";

    b.set(0, 'h');
    std::cout << "b 修改后: a=" << a.c_str()
              << " b=" << b.c_str() << "\n";
    std::cout << "a.ref=" << a.ref_count()
              << " b.ref=" << b.ref_count() << "\n";
}
```

**输出**：

```
a: Hello ref=1
b = a 后: a.ref=2 b.ref=2
b 修改后: a=Hello b=hello
a.ref=1 b.ref=1
```

**关键点**：
- 拷贝构造：共享数据，引用计数 +1
- 写操作（`set`/`operator[]`）：检测引用计数，>1 则复制（`detach`）
- 析构：引用计数 -1，为 0 则释放

**operator[] 的读写区分陷阱**：

```cpp
CowString s("Hello");
char c = s[0];    // 读操作，但 operator[] 无法区分！
s[0] = 'h';       // 写操作，需要 detach

// 如果 operator[] 总是 detach → 读操作也会触发复制，违背 COW 精神
// 如果 operator[] 不 detach → 写操作会修改共享数据，影响其他持有者

// 解决方案：proxy 模式（见下方）
```

**Proxy 模式区分读写**：

```cpp
class CowString {
    struct CharProxy {
        CowString& parent;
        size_t idx;

        CharProxy(CowString& p, size_t i) : parent(p), idx(i) {}

        operator char() const {
            return parent.shared->data[idx];
        }

        CharProxy& operator=(char c) {
            parent.detach();
            parent.shared->data[idx] = c;
            return *this;
        }
    };

public:
    CharProxy operator[](size_t idx) {
        return CharProxy(*this, idx);
    }

    const char& operator[](size_t idx) const {
        return shared->data[idx];
    }
};

CowString s("Hello");
char c = s[0];    // 调用 operator char()，不触发 detach
s[0] = 'h';       // 调用 operator=，触发 detach
```

#### 2. 方式2：使用 shared_ptr 实现 COW

```cpp
#include <iostream>
#include <memory>
#include <string>

class CowText {
    std::shared_ptr<std::string> data;

    void detach() {
        if (data.use_count() > 1) {
            data = std::make_shared<std::string>(*data);
        }
    }

public:
    CowText(const std::string& s = "")
        : data(std::make_shared<std::string>(s)) {}

    CowText(const CowText&) = default;
    CowText& operator=(const CowText&) = default;

    const std::string& read() const { return *data; }

    void write(const std::string& new_val) {
        detach();
        *data = new_val;
    }

    void append(const std::string& suffix) {
        detach();
        *data += suffix;
    }

    int ref_count() const { return data.use_count(); }
};

int main() {
    CowText a("Hello");
    CowText b = a;

    std::cout << "共享: a.ref=" << a.ref_count()
              << " b.ref=" << b.ref_count() << "\n";

    b.append(" World");

    std::cout << "b 修改后: a=" << a.read()
              << " b=" << b.read() << "\n";
    std::cout << "a.ref=" << a.ref_count()
              << " b.ref=" << b.ref_count() << "\n";
}
```

**输出**：

```
共享: a.ref=2 b.ref=2
b 修改后: a=Hello b=Hello World
a.ref=1 b.ref=1
```

#### 3. 方式3：C++17 shared_mutex 读写锁

不是真正的 COW，但可以实现"读共享写独占"的语义：

```cpp
#include <iostream>
#include <shared_mutex>
#include <string>
#include <thread>

class ThreadSafeData {
    std::string data;
    mutable std::shared_mutex mtx;

public:
    ThreadSafeData(const std::string& s = "") : data(s) {}

    std::string read() const {
        std::shared_lock lock(mtx);
        return data;
    }

    void write(const std::string& new_val) {
        std::unique_lock lock(mtx);
        data = new_val;
    }

    void append(const std::string& suffix) {
        std::unique_lock lock(mtx);
        data += suffix;
    }
};

int main() {
    ThreadSafeData d("Hello");

    auto reader = [&d]() {
        for (int i = 0; i < 3; ++i) {
            std::cout << "读: " << d.read() << "\n";
        }
    };

    auto writer = [&d]() {
        d.append(" World");
        std::cout << "写完成\n";
    };

    std::thread t1(reader);
    std::thread t2(writer);
    std::thread t3(reader);

    t1.join();
    t2.join();
    t3.join();
}
```

| 方式 | 真正的 COW | 复杂度 | 适用场景 |
|------|:---:|:---:|---------|
| 手写 COW 类 | 是 | 高 | 需要精确控制复制时机 |
| shared_ptr | 是 | 中 | 快速实现，代码简洁 |
| shared_mutex | 否（读写锁） | 低 | 多线程读写保护 |

### 5. COW 的典型应用场景

| 场景 | 说明 | COW 优势 |
|------|------|---------|
| 字符串 | 旧版 std::string 用 COW（C++11 后禁止） | 大量字符串拷贝时省内存 |
| 进程 fork | Linux fork() 子进程共享父进程内存页 | fork 速度快，内存省 |
| 数据库 MVCC | 多版本并发控制 | 读不阻塞写，写不阻塞读 |
| Qt 隐式共享 | Qt 的 QByteArray/QImage 等 | 值语义 + 共享实现 |
| 文件系统 Btrfs/ZFS | 写时复制文件系统 | 崩溃一致性、快照 |
| Git 版本控制 | 每次提交不复制整个仓库 | 存储效率高 |

**Linux fork 的 COW**：

```cpp
#include <iostream>
#include <unistd.h>

int main() {
    int shared_var = 42;

    pid_t pid = fork();

    if (pid == 0) {
        shared_var = 100;
        std::cout << "子进程: shared_var = " << shared_var << "\n";
    } else {
        std::cout << "父进程: shared_var = " << shared_var << "\n";
    }
}
```

```
父进程: shared_var = 42
子进程: shared_var = 100
```

fork 后父子进程共享内存页，子进程修改 `shared_var` 时触发页级 COW，父子各自独立。

### 6. std::string 为什么不用 COW 了

C++11 标准禁止 `std::string` 使用 COW 实现。

**原因1：operator[] 无法区分读和写**

```cpp
std::string s = "Hello";
std::string s2 = s;  // COW：共享数据

char c = s[0];   // 读操作，不应该触发复制
s[0] = 'h';      // 写操作，应该触发复制

// 但 operator[] 返回引用，编译器无法区分这两种情况！
// COW 实现只能选择：要么总是复制（违背 COW），要么不复制（写操作修改共享数据）
```

**原因2：多线程环境下引用计数的开销**

```cpp
// COW 的引用计数必须是原子操作
std::atomic<int> ref_count;  // 每次 add_ref/release 都是原子操作

// 即使是单线程的读操作，也要承受原子操作的开销
// 而 SSO 的短字符串完全不需要引用计数
```

**原因3：迭代器失效规则复杂**

```cpp
std::string a = "Hello";
std::string b = a;  // COW：共享数据

// COW 实现下，以下操作可能导致 a 和 b 的迭代器同时失效
// 标准要求：对 a 的修改不应影响 b 的迭代器
a[0] = 'h';  // COW 触发复制，a 的数据地址变了
// 如果之前保存了 a 的迭代器，现在可能失效
```

**原因4：SSO 对短字符串更高效**

| 维度 | COW | SSO |
|------|:---:|:---:|
| 短字符串构造 | 原子引用计数 +1 | 直接拷贝到内部缓冲区 |
| 短字符串析构 | 原子引用计数 -1 | 无操作 |
| 短字符串读取 | 间接寻址（指针→数据） | 直接访问（数据在对象内） |
| 多线程安全 | 原子操作开销 | 无共享状态，天然安全 |

**COW string 的 operator[] 陷阱完整示例**：

```cpp
#include <iostream>
#include <string>

void dangerous_cow_usage() {
    std::string a = "Hello";
    std::string b = a;

    // COW 实现下的问题：
    // 1. 保存了 a 的引用/指针
    const char* p = a.c_str();

    // 2. 修改 b（COW 会复制，a 不受影响）
    //    但如果 COW 实现有 bug，可能影响 a
    b[0] = 'h';

    // 3. 修改 a（COW 会复制，a 的数据地址变了）
    a[0] = 'H';

    // p 可能已经失效！
    // C++11 后标准保证 string 不用 COW，所以 p 仍然有效
    // 但在旧版 COW 实现中，这是未定义行为
    std::cout << p << "\n";
}
```

### 7. COW vs 深拷贝 vs 浅拷贝

| 维度 | 浅拷贝 | 深拷贝 | COW |
|------|--------|--------|-----|
| 复制速度 | 最快（复制指针） | 最慢（复制全部数据） | 拷贝时快（共享），写入时慢（触发复制） |
| 内存占用 | 共享 | 独立 | 按需分配 |
| 安全性 | 不安全（双重释放） | 安全 | 安全 |
| 读性能 | 快（直接访问） | 快（直接访问） | 快（直接访问共享数据） |
| 写性能 | 快但不安全 | 快（修改自己的副本） | 首次写入慢（需复制） |
| 适用场景 | 几乎不用 | 默认选择 | 读多写少 |

**代码对比**：

```cpp
#include <iostream>
#include <cstring>

class ShallowBuffer {
    int* data;
    size_t size;
public:
    ShallowBuffer(size_t n) : size(n), data(new int[n]()) {}
    ~ShallowBuffer() { delete[] data; }

    ShallowBuffer(const ShallowBuffer& other)
        : size(other.size), data(other.data) {}  // 浅拷贝：共享指针
};

class DeepBuffer {
    int* data;
    size_t size;
public:
    DeepBuffer(size_t n) : size(n), data(new int[n]()) {}
    ~DeepBuffer() { delete[] data; }

    DeepBuffer(const DeepBuffer& other)
        : size(other.size), data(new int[other.size]) {  // 深拷贝：重新分配
        std::copy(other.data, other.data + size, data);
    }
};

class CowBuffer {
    struct Shared { int* data; size_t size; std::atomic<int> ref; };
    Shared* shared;
    void detach() {
        if (shared->ref > 1) {
            shared->ref--;
            Shared* ns = new Shared{new int[shared->size], shared->size, 1};
            std::copy(shared->data, shared->data + ns->size, ns->data);
            shared = ns;
        }
    }
public:
    CowBuffer(size_t n) : shared(new Shared{new int[n](), n, 1}) {}
    ~CowBuffer() { if (--shared->ref == 0) { delete[] shared->data; delete shared; } }

    CowBuffer(const CowBuffer& other) : shared(other.shared) { shared->ref++; }  // COW：共享

    int read(size_t i) const { return shared->data[i]; }
    void write(size_t i, int v) { detach(); shared->data[i] = v; }
};
```

### 8. COW 的注意事项

**1. 写操作的性能不可预测**

```cpp
CowString a = "Very long string......";
CowString b = a;  // 共享，O(1)

// 首次写入触发复制，O(n)
b.set(0, 'v');  // 突然变慢！复制整个字符串

// 实时系统中这种不可预测的延迟是不可接受的
```

**2. 引用计数的原子操作开销**

```cpp
// 多线程环境下，引用计数必须是原子操作
std::atomic<int> ref_count;

// 每次拷贝构造/析构都有原子操作开销
// 即使只是读取，也要修改引用计数
CowString a = "Hello";
CowString b = a;  // atomic fetch_add
// b 离开作用域    // atomic fetch_sub
```

**3. proxy 模式增加复杂度**

```cpp
// operator[] 返回 proxy 对象而非 char&
// 可能导致以下问题：
CowString s("Hello");

// 问题1：无法取地址
// char* p = &s[0];  // 编译错误！proxy 对象的地址不是 char*

// 问题2：模板推导可能出错
// auto c = s[0];  // c 是 CharProxy，不是 char！

// 问题3：重载决议可能不符合预期
void f(char c);
void f(CharProxy p);
f(s[0]);  // 可能调用错误的重载
```

**4. 实时系统不适用**

```cpp
// 写时复制的延迟不可控
// 在实时系统中，最坏情况的延迟比平均延迟更重要
// COW 的最坏情况 = 复制整个数据结构

// 实时系统应使用预分配 + 深拷贝
class RealtimeBuffer {
    int data[1024];  // 预分配，固定大小
public:
    RealtimeBuffer(const RealtimeBuffer& other) {
        std::copy(std::begin(other.data), std::end(other.data), data);
        // 延迟可预测：总是 O(n)，不会突然翻倍
    }
};
```

***

### 9. 极简总结

**COW = 读共享写分离，不修改就不复制。适用于读多写少的场景（fork/MVCC/Qt 隐式共享）。C++11 后 std::string 不再用 COW（SSO 更优），但手写 COW 类仍是重要技巧。核心实现：引用计数 + 延迟复制。**

| 要点 | 说明 |
|------|------|
| 核心思想 | 多个持有者共享数据，写时才复制 |
| 实现关键 | 引用计数 + detach（延迟复制） |
| 最佳场景 | 读多写少（fork、MVCC、Qt 隐式共享） |
| 不适用 | 实时系统、写密集场景 |
| std::string | C++11 后禁止 COW，改用 SSO |
| 注意事项 | 写延迟不可预测、proxy 模式复杂、原子操作开销 |
