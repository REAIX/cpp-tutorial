# 构造函数成员初始化列表
> 📖 相关章节：[类与对象](../../02-CPP/03-类与对象.md)

### 1. 一句话答案

冒号 `:` 后面的叫**成员初始化列表**，作用是：**给类的成员变量赋值（比在函数体里赋值更快、更正规）**。

***

### 2. 代码拆解

```cpp
Student() : name(""), age(0) {}
```

| 部分                 | 含义                             |
| ------------------ | ------------------------------ |
| `Student()`        | 默认构造函数                         |
| `:`                | 标志：开始初始化成员变量                   |
| `name(""), age(0)` | 直接给 `name` 赋值空字符串，给 `age` 赋值 0 |
| `{}`               | 函数体为空，啥也不用干                    |

***

### 3. 两种写法对比

#### 1. 初始化列表写法（推荐）

```cpp
Student() : name(""), age(0) {}
```

#### 2. 函数体赋值写法（不推荐）

```cpp
Student() {
    name = "";
    age = 0;
}
```

***

### 4. 核心区别

| 写法        | 特点             |
| --------- | -------------- |
| **冒号初始化** | 真正的初始化，只做一次    |
| **大括号赋值** | 先创建默认值，再覆盖，效率低 |

### 5. 通俗比喻

- **冒号初始化** = 出生就设定好名字和年龄
- **大括号赋值** = 先生下来，再改名字改年龄

***

### 6. 初始化列表 vs 函数体赋值：性能差异详解

#### 1. 对于类类型成员（如 std::string）

```cpp
class Student {
    std::string name;
    int age;
public:
    // 方式1：初始化列表 —— 直接构造 name 为 ""
    Student() : name(""), age(0) {}

    // 方式2：函数体赋值 —— 先默认构造 name，再赋值 ""
    Student() {
        name = "";  // 先调用 string 默认构造，再调用 operator=
        age = 0;
    }
};
```

**方式2 实际执行了两次操作**：

1. 进入函数体前，`name` 已经被默认构造为空字符串
2. 函数体中 `name = ""` 又执行了一次赋值操作

**方式1 只执行了一次操作**：直接用 `""` 构造 `name`。

#### 2. 对于内置类型（如 int）

```cpp
class Counter {
    int count;
public:
    Counter() : count(0) {}  // 直接初始化
    Counter() { count = 0; } // 先未定义值，再赋值
};
```

内置类型性能差异极小，但初始化列表语义更清晰。

### 7. 三种初始化方式对比

#### 1. 方式1：构造函数初始化列表（推荐首选）

```cpp
class Student {
    string name;
    int age;
public:
    Student() : name(""), age(0) {}
};
```

**特点**：

- 最早初始化，出生直接赋值
- 效率最高
- **必须用它初始化 const 成员、引用成员**
- 初始化顺序只看**类定义顺序**，不看书写顺序

#### 2. 方式2：构造函数函数体内赋值

```cpp
Student() {
    name = "";
    age = 0;
}
```

**特点**：

- 先默认构造一遍，再重新赋值
- 比初始化列表慢一点
- **不能初始化 const 成员、引用成员**
- 只是赋值，不是原生初始化

#### 3. 方式3：类内就地初始化（C++11 及以后）

```cpp
class Student {
    string name = "";   // 就地给默认值
    int age = 0;
public:
    Student() {}  // 构造函数空着都行
};
```

**特点**：

- 成员声明时直接给默认值
- 多个构造函数共用默认值，代码最简洁
- 如果构造函数初始化列表又写了，**以初始化列表覆盖类内默认值**

#### 4. 三种方式对比总表

| 特性 | 初始化列表 | 函数体赋值 | 类内就地初始化 |
|:----:|:--------:|:--------:|:----------:|
| 效率 | 最高 | 较低 | 最高 |
| const 成员 | 支持 | 不支持 | 支持 |
| 引用成员 | 支持 | 不支持 | 支持 |
| 无默认构造的成员 | 支持 | 不支持 | 支持 |
| 多构造函数共享 | 不方便 | 不方便 | 方便 |
| C++ 版本 | C++98 | C++98 | C++11 |

### 8. 初始化顺序规则（C++铁律）

**成员变量的初始化顺序 = 类中声明的先后顺序**

跟你初始化列表里写的顺序**毫无关系**！

#### 1. 例子

```cpp
class Student {
private:
    std::string name;   // 第1个声明
    int age;            // 第2个声明
public:
    // 你故意倒着写：age 先、name 后
    Student() : age(0), name("") {}
};
```

**实际执行顺序**：

1. 先初始化 `name`（按类里定义顺序）
2. 再初始化 `age`

#### 2. 为什么要保持顺序一致？

**坑：一个成员依赖另一个初始值**

```cpp
class A {
    int x;
    int y;
public:
    A() : y(x + 1), x(10) {}  // y 依赖 x，但 x 还没初始化！
};
```

如果类里顺序是 `x` 在前，则没问题；如果反过来，就会用未初始化的 `x` 给 `y` 赋值。

#### 3. 更危险的例子

```cpp
class BadExample {
    std::string name;
    int length;
public:
    // length 依赖 name，但 name 还没初始化！
    BadExample() : length(name.size()), name("hello") {}
    // 实际执行顺序：先 name("hello")，再 length(name.size())
    // 但如果声明顺序反过来，length 会用未初始化的 name
};
```

### 9. 优先级规则（谁覆盖谁）

```
构造函数初始化列表 > 类内就地默认值 > 函数体赋值
```

#### 1. 完整示例

```cpp
class Demo {
    int a = 10;       // 类内就地初始化
    int b = 20;
    int c = 30;
public:
    Demo() : b(100) {  // 初始化列表覆盖 b
        c = 200;        // 函数体赋值覆盖 c
    }
    // 结果：a=10, b=100, c=200
};

Demo d;
// a = 10  （类内默认值生效）
// b = 100 （初始化列表覆盖类内默认值）
// c = 200 （函数体赋值覆盖初始化列表和类内默认值）
```

### 10. 必须用初始化列表的场景

下面这几种**只能用** `:` 初始化列表，别的方式都做不到：

#### 1. 场景1：const 成员

```cpp
class Circle {
    const double PI;  // const 成员
    double radius;
public:
    // 必须用初始化列表
    Circle(double r) : PI(3.14159), radius(r) {}

    // 以下写法编译错误
    // Circle(double r) { PI = 3.14159; radius = r; }  // const 不能赋值
};
```

#### 2. 场景2：引用成员

```cpp
class Wrapper {
    int& ref;  // 引用成员
public:
    // 必须用初始化列表
    Wrapper(int& val) : ref(val) {}

    // 以下写法编译错误
    // Wrapper(int& val) { ref = val; }  // 引用必须在声明时绑定
};
```

#### 3. 场景3：没有默认构造的类对象

```cpp
class Id {
    int id;
public:
    Id(int i) : id(i) {}  // 没有默认构造函数
};

class Person {
    Id personId;  // 没有默认构造
    std::string name;
public:
    // 必须用初始化列表
    Person(int id, const std::string& n) : personId(id), name(n) {}

    // 以下写法编译错误
    // Person(int id, const std::string& n) { personId = Id(id); name = n; }
    // 因为进入函数体前 personId 已经需要默认构造，但 Id 没有默认构造
};
```

#### 4. 场景4：初始化父类构造函数

```cpp
class Base {
    int value;
public:
    Base(int v) : value(v) {}
};

class Derived : public Base {
public:
    // 必须用初始化列表调用父类构造
    Derived(int v) : Base(v) {}

    // 以下写法编译错误
    // Derived(int v) { Base(v); }  // 这是在函数体内创建临时对象
};
```

### 11. 常见陷阱

#### 1. 陷阱1：初始化顺序与书写顺序不一致

```cpp
class Trap {
    int size;
    std::vector<int> data;
public:
    // 看起来 data 用 size 初始化，但 size 还没初始化！
    // 如果声明顺序是 data 在前、size 在后，就会用未初始化的 size
    Trap(int n) : size(n), data(size) {}
};
// 安全做法：确保声明顺序是 size 在前、data 在后
```

#### 2. 陷阱2：初始化列表中调用虚函数

```cpp
class Base {
public:
    virtual int getValue() { return 10; }
    Base() : value(getValue()) {}  // 调用的是 Base::getValue，不是 Derived 的
    int value;
};

class Derived : public Base {
public:
    int getValue() override { return 20; }
};

Derived d;
// d.value = 10，不是 20！
// 在基类构造期间，虚函数机制尚未生效
```

#### 3. 陷阱3：初始化列表中的求值顺序

```cpp
class Order {
    int a;
    int b;
public:
    // 初始化顺序按声明顺序（a 先、b 后）
    // 但函数参数的求值顺序是未定义的！
    Order(int x) : a(x), b(a + 1) {}  // 安全：a 先初始化
    // Order(int x) : b(a + 1), a(x) {}  // 危险：a 还没初始化就用了
};
```

### 12. 委托构造（C++11）

一个构造函数可以在初始化列表中调用另一个构造函数：

```cpp
class Rectangle {
    double width;
    double height;
public:
    // 主构造函数
    Rectangle(double w, double h) : width(w), height(h) {}

    // 委托构造：正方形
    Rectangle(double side) : Rectangle(side, side) {}

    // 委托构造：默认
    Rectangle() : Rectangle(1.0, 1.0) {}
};
```

**注意**：委托构造后不能再有其他成员初始化。

```cpp
// 错误！委托后不能再初始化其他成员
Rectangle() : Rectangle(1.0), height(2.0) {}
```

### 13. 完整示例

```cpp
#include <iostream>
#include <string>
#include <vector>

class Student {
private:
    const int id;               // const 成员：必须用初始化列表
    std::string name;           // 类类型成员
    int age;                    // 内置类型
    double& scoreRef;           // 引用成员：必须用初始化列表
    std::vector<int> scores;    // 容器成员

public:
    // 主构造函数
    Student(int id, const std::string& name, int age, double& score)
        : id(id)               // const 成员
        , name(name)           // 类类型成员
        , age(age)             // 内置类型
        , scoreRef(score)      // 引用成员
        , scores()             // 空容器
    {
        std::cout << "Student " << name << " created\n";
    }

    // 委托构造：只有 id 和 name
    Student(int id, const std::string& name)
        : Student(id, name, 0, *(new double(0.0))) {}

    // 获取信息
    void printInfo() const {
        std::cout << "ID: " << id
                  << ", Name: " << name
                  << ", Age: " << age
                  << ", Score: " << scoreRef << "\n";
    }
};

int main() {
    double score = 95.5;
    Student s1(1, "Alice", 20, score);
    s1.printInfo();

    Student s2(2, "Bob");
    s2.printInfo();

    return 0;
}
```

***

### 14. 最佳实践

1. **初始化列表的顺序，严格和类内成员声明顺序保持一致**
2. 不要用还没初始化的成员去给另一个成员赋值
3. 日常写代码优先顺序：**类内就地初始化 → 初始化列表 → 函数体内赋值**
4. 所有构造函数应尽量使用初始化列表
5. 类内就地初始化用于多个构造函数共享的默认值
6. 初始化列表用于每个构造函数不同的初始化值

***

### 15. 极简总结

| 要点 | 内容 |
|:----:|:----:|
| 语法 | 构造函数后 `: member(value), ...` |
| 本质 | 真正的初始化，不是先构造再赋值 |
| 顺序 | 按类内声明顺序，与书写顺序无关 |
| 优先级 | 初始化列表 > 类内就地初始化 > 函数体赋值 |
| 必须用 | const 成员、引用成员、无默认构造的成员、父类构造 |
| 委托构造 | C++11，一个构造函数调用另一个 |
| 最佳实践 | 列表顺序与声明顺序一致，优先用初始化列表 |
