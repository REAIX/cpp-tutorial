# 构造函数委托
> 📖 相关章节：[类与对象](../../02-CPP/03-类与对象.md)、[继承与多态](../../02-CPP/04-继承与多态.md)、[核心机制](../../02-CPP/05-核心机制.md)、[异常处理](../../02-CPP/07-异常处理.md)、[移动语义](../../02-CPP/09-移动语义与完美转发.md)

### 1. 一句话大白话

**一个构造函数，调用本类里的另一个构造函数，帮自己把初始化工作做完，这就叫「构造函数委托」。**

属于 **C++11 新特性**，专门用来**减少重复初始化代码**。

***

### 2. 语法示例

```cpp
class Student
{
    string name;
    int age;
public:
    // 主构造：做真正初始化
    Student(string n, int a) : name(n), age(a) {}

    // 委托构造：委托上面那个构造帮忙初始化
    Student() : Student("", 0) {}   // 委托
};
```

**关键点**：

- 在**初始化列表**里，直接写本类构造 `Student("",0)`
- 把初始化全权**委托**给另一个构造函数
- 自己函数体里不用再写任何初始化

***

### 3. 没委托之前有多啰嗦

不使用委托，只能重复写初始化：

```cpp
Student()  : name(""), age(0)  {}
Student(string n, int a) : name(n), age(a) {}
```

**初始化代码写两遍**，冗余、改一处要改多处，容易错。

#### 1. 更严重的例子：多个构造函数

```cpp
class Config {
    std::string host;
    int port;
    std::string username;
    std::string password;
    bool useSSL;
public:
    // 全参数构造
    Config(std::string h, int p, std::string u, std::string pwd, bool ssl)
        : host(h), port(p), username(u), password(pwd), useSSL(ssl) {}

    // 不用委托：每个构造函数都重复写初始化列表
    Config(std::string h, int p)
        : host(h), port(p), username("admin"), password(""), useSSL(false) {}

    Config()
        : host("localhost"), port(8080), username("admin"), password(""), useSSL(false) {}
};
```

**问题**：默认值 `"admin"`、`""`、`false` 写了多遍，改一处容易漏改。

***

### 4. 用委托构造重构

```cpp
class Config {
    std::string host;
    int port;
    std::string username;
    std::string password;
    bool useSSL;
public:
    // 主构造函数：所有参数
    Config(std::string h, int p, std::string u, std::string pwd, bool ssl)
        : host(h), port(p), username(u), password(pwd), useSSL(ssl) {}

    // 委托构造：只指定 host 和 port
    Config(std::string h, int p)
        : Config(h, p, "admin", "", false) {}

    // 委托构造：全部默认
    Config()
        : Config("localhost", 8080, "admin", "", false) {}
};
```

**好处**：默认值只在主构造函数中出现一次，维护简单。

### 5. 委托构造的规则（记住3条）

#### 1. 规则1：只能在初始化列表里委托

```cpp
class A {
    int x;
public:
    A(int v) : x(v) {}

    // 正确：在初始化列表中委托
    A() : A(0) {}

    // 错误：不能在函数体中调用构造函数
    // A() { A(0); }  // 这只是创建了一个临时对象！
};
```

**函数体中调用构造函数的后果**：

```cpp
class Counter {
    int value;
public:
    Counter(int v) : value(v) { std::cout << "构造: " << v << "\n"; }

    Counter() {
        Counter(0);  // 创建了一个临时对象！不是初始化自己
        // value 仍然是未初始化的
    }
};

Counter c;  // 输出 "构造: 0"，但 c.value 是未定义值
```

#### 2. 规则2：不能循环委托

```cpp
class Bad {
public:
    Bad(int) : Bad() {}      // 委托给 Bad()
    Bad()    : Bad(0) {}     // 又委托回 Bad(int) → 循环！
};
// 编译器可能不报错，但运行时栈溢出
```

#### 3. 规则3：委托后不能再初始化其他成员

```cpp
class Student {
    string name;
    int age;
public:
    Student(string n, int a) : name(n), age(a) {}

    // 错误！委托了别人，就不能再单独初始化成员
    // Student() : Student("", 0), age(0) {}

    // 正确：只委托，不额外初始化
    Student() : Student("", 0) {}
};
```

### 6. 委托构造 vs init 函数

#### 1. 方式1：init 函数（C++11 之前的做法）

```cpp
class Student {
    string name;
    int age;

    void init(const string& n, int a) {
        name = n;
        age = a;
    }

public:
    Student(const string& n, int a) { init(n, a); }
    Student() { init("", 0); }
};
```

#### 2. 方式2：委托构造（C++11 推荐）

```cpp
class Student {
    string name;
    int age;
public:
    Student(const string& n, int a) : name(n), age(a) {}
    Student() : Student("", 0) {}
};
```

#### 3. 对比

| 特性 | init 函数 | 委托构造 |
|:----:|:---------:|:--------:|
| 初始化 vs 赋值 | 赋值（不是真正的初始化） | 初始化（真正初始化） |
| const 成员 | 不能处理 | 可以处理 |
| 引用成员 | 不能处理 | 可以处理 |
| 基类构造 | 不能调用 | 可以调用 |
| 代码重复 | 减少 | 减少 |
| C++ 版本 | C++98 | C++11 |

**init 函数的致命缺陷**：

```cpp
class IdHolder {
    const int id;       // const 成员
    std::string name;

    void init(int i, const std::string& n) {
        // id = i;    // 编译错误！const 成员不能赋值
        name = n;
    }

public:
    IdHolder(int i, const std::string& n) : id(i) { init(i, n); }
    // init 函数无法初始化 const 成员
};
```

### 7. 委托链

委托可以形成链式调用：

```cpp
class Window {
    std::string title;
    int width;
    int height;
    bool visible;
public:
    // 主构造函数（4个参数）
    Window(std::string t, int w, int h, bool v)
        : title(t), width(w), height(h), visible(v) {
        std::cout << "主构造\n";
    }

    // 委托链：3个参数 → 4个参数
    Window(std::string t, int w, int h)
        : Window(t, w, h, true) {
        std::cout << "3参数构造\n";
    }

    // 委托链：2个参数 → 3个参数 → 4个参数
    Window(std::string t, int w)
        : Window(t, w, 600) {
        std::cout << "2参数构造\n";
    }

    // 委托链：0个参数 → 2个参数 → 3个参数 → 4个参数
    Window()
        : Window("Untitled", 800) {
        std::cout << "默认构造\n";
    }
};

Window w;
// 输出：
// 主构造
// 3参数构造
// 2参数构造
// 默认构造
```

**执行顺序**：先执行被委托的构造函数，再执行委托者的函数体。

### 8. 委托构造与异常

```cpp
class Resource {
public:
    Resource() { throw std::runtime_error("初始化失败"); }
};

class Manager {
    Resource* res;
public:
    Manager(int) : res(nullptr) {
        std::cout << "int 构造\n";
    }

    Manager() : Manager(0) {
        res = new Resource();  // 如果这里抛异常
        // Manager 对象的析构函数不会被调用
        // 但已经完成的基类和成员初始化会被正确析构
    }
};
```

**关键点**：如果委托的目标构造函数抛出异常，委托者的函数体不会执行，对象不会被构造。

### 9. C++11 之前的方法

在 C++11 之前，没有委托构造，只能用以下方式减少重复：

#### 1. 方法1：init 函数

```cpp
class Student {
    string name;
    int age;
    void init(const string& n, int a) { name = n; age = a; }
public:
    Student(const string& n, int a) { init(n, a); }
    Student() { init("", 0); }
};
```

缺点：不能初始化 const/引用成员。

#### 2. 方法2：默认参数

```cpp
class Student {
    string name;
    int age;
public:
    Student(const string& n = "", int a = 0) : name(n), age(a) {}
};
```

缺点：所有调用者共享同一组默认值，灵活性差。

#### 3. 方法3：重复写初始化列表

```cpp
class Student {
    string name;
    int age;
public:
    Student(const string& n, int a) : name(n), age(a) {}
    Student() : name(""), age(0) {}
};
```

缺点：代码重复，维护困难。

### 10. 完整示例

```cpp
#include <iostream>
#include <string>

class Logger {
    std::string name;
    std::string level;
    bool toFile;
    bool toConsole;

public:
    // 主构造函数：所有参数
    Logger(const std::string& n, const std::string& lvl, bool file, bool console)
        : name(n), level(lvl), toFile(file), toConsole(console) {
        std::cout << "Logger [" << name << "] created, level=" << level << "\n";
    }

    // 委托：只指定名字，其他默认
    Logger(const std::string& n)
        : Logger(n, "INFO", true, true) {}

    // 委托：指定名字和级别
    Logger(const std::string& n, const std::string& lvl)
        : Logger(n, lvl, true, true) {}

    // 委托：默认构造
    Logger()
        : Logger("default", "INFO", true, true) {}

    void log(const std::string& msg) {
        if (toConsole) {
            std::cout << "[" << level << "] " << name << ": " << msg << "\n";
        }
    }
};

int main() {
    Logger l1;                    // 默认构造
    Logger l2("app");             // 只指定名字
    Logger l3("app", "DEBUG");    // 指定名字和级别
    Logger l4("app", "ERROR", false, true);  // 全参数

    l1.log("系统启动");
    l2.log("连接数据库");
    l3.log("查询执行");
    l4.log("连接超时");

    return 0;
}
```

### 11. 常见陷阱

#### 1. 陷阱1：函数体中误调用构造函数

```cpp
class Foo {
    int x;
public:
    Foo(int v) : x(v) {}
    Foo() {
        Foo(0);  // 这只是创建临时对象！x 仍然未初始化
    }
};
```

#### 2. 陷阱2：循环委托

```cpp
class Circular {
public:
    Circular(int) : Circular() {}
    Circular() : Circular(0) {}  // 无限递归！
};
```

#### 3. 陷阱3：委托后还写成员初始化

```cpp
class Bad {
    int a, b;
public:
    Bad(int x, int y) : a(x), b(y) {}
    Bad() : Bad(1, 2), b(3) {}  // 编译错误！委托后不能再初始化成员
};
```

#### 4. 陷阱4：委托构造中的 this 指针

```cpp
class Danger {
    int* data;
public:
    Danger(int size) : data(new int[size]) {
        std::cout << "分配了 " << size << " 个 int\n";
    }

    Danger() : Danger(10) {
        // 此时 this->data 已经被主构造初始化
        // 但如果主构造抛异常，这里不会执行
    }
};
```

### 12. 最佳实践

1. **选一个构造函数作为"主构造"**，其他构造函数全部委托给它
2. **主构造函数参数最多**，包含所有需要初始化的成员
3. **委托链不要太长**，避免多层嵌套影响可读性
4. **不要用 init 函数替代委托构造**，除非必须兼容 C++98
5. **委托构造的函数体可以为空**，所有逻辑在主构造中完成

| 要点 | 内容 |
|:----:|:----:|
| 语法 | 在初始化列表中调用本类另一个构造函数 |
| C++ 版本 | C++11 |
| 核心作用 | 消除重复初始化代码 |
| 规则1 | 只能在初始化列表中委托 |
| 规则2 | 不能循环委托 |
| 规则3 | 委托后不能再初始化其他成员 |
| vs init 函数 | 委托是真正初始化，init 是赋值 |
| 执行顺序 | 先执行被委托者，再执行委托者函数体 |
| 最佳实践 | 选一个主构造，其他全部委托 |
