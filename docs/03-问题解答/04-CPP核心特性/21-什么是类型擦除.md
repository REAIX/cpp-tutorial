# 什么是类型擦除
> 📖 相关章节：[类与对象](../../02-CPP/03-类与对象.md)、[继承与多态](../../02-CPP/04-继承与多态.md)、[核心机制](../../02-CPP/05-核心机制.md)、[异常处理](../../02-CPP/07-异常处理.md)、[移动语义](../../02-CPP/09-移动语义与完美转发.md)

> "接口统一，类型隐身"——类型擦除让你只关心"能做什么"，不关心"具体是什么"。

***

### 1. 核心定义

**类型擦除（Type Erasure）** = 在运行时隐藏对象的具体类型，通过统一接口使用。调用方不需要知道对象的真实类型，只要它满足接口约定就行。

简单说：**把不同类型的东西，塞进同一个壳子里，用同一套接口调用**。

***

### 2. 生活类比

**万能充电器**：不管什么品牌的手机（苹果、华为、小米），只要接口对（USB-C），充电器就能充电。充电器不需要知道手机内部型号，手机也不需要知道充电器品牌——双方只认接口。

类型擦除就是那个"统一接口"：你不用知道对象是 `Dog` 还是 `Cat`，只要它"能叫"就行。

***

### 3. C++ 中类型擦除的五种方式

#### 1. 虚函数/继承（传统 OOP 方式）

最经典的类型擦除：基类指针指向派生类对象，通过虚函数统一调用。

```cpp
class Animal {
public:
    virtual void speak() const = 0;
    virtual ~Animal() = default;
};

class Dog : public Animal {
public:
    void speak() const override { std::cout << "汪汪" << std::endl; }
};

class Cat : public Animal {
public:
    void speak() const override { std::cout << "喵喵" << std::endl; }
};

void make_sound(const Animal& a) {
    a.speak();
}

int main() {
    Dog d;
    Cat c;
    make_sound(d);
    make_sound(c);
}
```

**类型在哪被擦除了？** `make_sound` 只看到 `Animal&`，不知道具体是 `Dog` 还是 `Cat`。

#### 2. void* + 函数指针（C 风格）

C 语言没有虚函数，用 `void*` 擦除类型，用函数指针回调。

```cpp
#include <iostream>

void dog_speak(void* ctx) {
    std::cout << "汪汪" << std::endl;
}

void cat_speak(void* ctx) {
    std::cout << "喵喵" << std::endl;
}

void make_sound(void* ctx, void (*speak)(void*)) {
    speak(ctx);
}

int main() {
    make_sound(nullptr, dog_speak);
    make_sound(nullptr, cat_speak);
}
```

**类型在哪被擦除了？** `void*` 把具体类型信息丢掉了，靠函数指针间接调用。

**缺点**：完全没有类型安全，传错函数指针就崩溃。

#### 3. std::function（存储可调用对象）

`std::function` 是最常用的类型擦除工具：能装 lambda、函数指针、仿函数，只要签名匹配。

```cpp
#include <iostream>
#include <functional>
#include <vector>

int main() {
    std::vector<std::function<void()>> tasks;

    tasks.push_back([] { std::cout << "任务1" << std::endl; });
    tasks.push_back([] { std::cout << "任务2" << std::endl; });

    auto func = static_cast<void(*)()>([] { std::cout << "任务3" << std::endl; });
    tasks.push_back(func);

    for (auto& t : tasks) {
        t();
    }
}
```

**类型在哪被擦除了？** lambda、函数指针、仿函数是不同类型，但 `std::function<void()>` 把它们统一了。

#### 4. std::any（存储任意类型值）

`std::any` 能装任何类型的值，连接口都不需要——纯"黑盒存储"。

```cpp
#include <iostream>
#include <any>
#include <string>
#include <vector>

int main() {
    std::vector<std::any> items;

    items.push_back(42);
    items.push_back(3.14);
    items.push_back(std::string("hello"));

    for (auto& item : items) {
        if (item.type() == typeid(int)) {
            std::cout << "int: " << std::any_cast<int>(item) << std::endl;
        } else if (item.type() == typeid(double)) {
            std::cout << "double: " << std::any_cast<double>(item) << std::endl;
        } else if (item.type() == typeid(std::string)) {
            std::cout << "string: " << std::any_cast<std::string>(item) << std::endl;
        }
    }
}
```

**类型在哪被擦除了？** `std::any` 内部用模板+虚函数隐藏了具体类型，外部只能用 `std::any_cast` 取回。

#### 5. 模板 + 类型推导（编译期擦除）

C++20 ranges/views 用模板+概念实现编译期类型擦除：不同类型的 range 通过 `auto` 或概念统一使用，不需要运行时开销。

```cpp
#include <iostream>
#include <vector>
#include <list>

template <typename Range>
void print_all(const Range& r) {
    for (const auto& x : r) {
        std::cout << x << " ";
    }
    std::cout << std::endl;
}

int main() {
    std::vector<int> v = {1, 2, 3};
    std::list<double> l = {4.5, 5.5, 6.5};

    print_all(v);
    print_all(l);
}
```

**类型在哪被擦除了？** `print_all` 不关心 `vector` 还是 `list`，只要能 `for` 循环就行。这是编译期擦除，零运行时开销。

### 4. 手写简单类型擦除

理解原理最好的方式：手写一个简化版 `std::function`。

```cpp
#include <iostream>
#include <memory>
#include <utility>

class Callable {
public:
    virtual void call() = 0;
    virtual ~Callable() = default;
};

template <typename F>
class CallableImpl : public Callable {
    F func_;
public:
    explicit CallableImpl(F func) : func_(std::move(func)) {}
    void call() override { func_(); }
};

class MyFunction {
    std::unique_ptr<Callable> ptr_;
public:
    MyFunction() = default;

    template <typename F>
    MyFunction(F f) : ptr_(std::make_unique<CallableImpl<F>>(std::move(f))) {}

    void operator()() { ptr_->call(); }
};

int main() {
    int count = 0;

    MyFunction f1 = [] { std::cout << "hello" << std::endl; };
    MyFunction f2 = [&count] { std::cout << "count=" << ++count << std::endl; };

    f1();
    f2();
    f2();
}
```

**原理拆解**：

1. `Callable` 是统一接口（虚函数 `call`）
2. `CallableImpl<F>` 是模板派生类，持有具体可调用对象 `F`
3. `MyFunction` 构造函数是模板，把任意 `F` 包装进 `CallableImpl<F>`
4. 外部只看到 `MyFunction`，不知道里面是 lambda 还是函数指针

**这就是类型擦除的本质：模板构造 + 虚函数调用**。

### 5. 各种方式对比

| 方式 | 类型安全 | 性能 | 灵活性 | 适用场景 |
|------|:---:|:---:|:---:|------|
| 虚函数/继承 | ✅ 高 | ⚠️ 有虚调用开销 | ⚠️ 必须继承同一基类 | OOP 多态 |
| void* + 函数指针 | ❌ 无 | ✅ 接近原生 | ✅ 任意类型 | C 语言接口 |
| std::function | ✅ 高 | ⚠️ 有堆分配+虚调用 | ✅ 任意可调用对象 | 回调、事件系统 |
| std::any | ⚠️ 运行时检查 | ⚠️ 有堆分配+类型检查 | ✅ 任意类型 | 配置、脚本绑定 |
| 模板 + auto/概念 | ✅ 最高 | ✅ 零开销 | ⚠️ 编译期确定 | 泛型算法、ranges |

***

### 6. 与 CRTP 的对比

CRTP（[CRTP模式与静态多态](./17-CRTP模式与静态多态.md)）和类型擦除都能实现"统一接口"，但方向完全相反：

| 对比项 | CRTP | 类型擦除 |
|--------|------|----------|
| 多态时机 | 编译期 | 运行时 |
| 类型信息 | 保留（编译器知道具体类型） | 隐藏（运行时不知道具体类型） |
| 开销 | 零（可内联） | 有（虚调用/堆分配） |
| 灵活性 | 低（编译期确定） | 高（运行时可替换） |
| 异构容器 | 不支持 | 支持 |
| 典型用途 | Mixin、静态接口 | 回调、插件、事件系统 |

**一句话**：CRTP 是"编译期知道类型但假装不知道"，类型擦除是"运行时真的不知道类型"。

***

### 7. 极简总结

**类型擦除 = 模板构造 + 虚函数调用 = 运行时隐藏具体类型，统一接口使用**

| 场景 | 推荐方式 |
|------|----------|
| 需要运行时多态 + 类型安全 | 虚函数 / std::function |
| 需要存储任意类型 | std::any |
| C 语言兼容接口 | void* + 函数指针 |
| 性能关键 + 编译期确定 | 模板 + 概念（编译期擦除） |
| 需要手写定制擦除 | 模板 + 虚函数（参考 82.4） |
