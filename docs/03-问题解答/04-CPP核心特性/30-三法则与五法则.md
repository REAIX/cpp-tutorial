***

### 1. 核心提炼

三法则：析构/拷贝构造/拷贝赋值必须同时定义；五法则：加上移动构造/移动赋值共五个；零法则：不手动管理资源时全部用默认，让编译器生成。

***

### 2. 三法则（Rule of Three）

**核心原则**：如果一个类需要自定义析构函数、拷贝构造函数或拷贝赋值运算符中的任何一个，那么它几乎肯定需要自定义这三个。

**为什么？**

```cpp
class BadBuffer {
    int* data_;
    size_t size_;
public:
    BadBuffer(size_t n) : data_(new int[n]), size_(n) {}
    ~BadBuffer() { delete[] data_; }
};
```

上述代码只定义了析构函数，编译器自动生成的拷贝构造和拷贝赋值会执行**浅拷贝**：

```
原始对象:  data_ ──→ [0,1,2,3]
拷贝对象:  data_ ──→ (同一块内存)

析构原始对象: delete[] data_  → 内存释放
析贝拷贝对象: delete[] data_  → 重复释放！(double free)
```

| 缺失的函数 | 后果 |
|-----------|------|
| 缺拷贝构造 | 浅拷贝 → 双重释放 |
| 缺拷贝赋值 | 浅拷贝 → 双重释放 + 内存泄漏 |
| 缺析构 | 资源泄漏 |

***

### 3. 五法则（Rule of Five）

C++11 引入移动语义后，三法则扩展为五法则：

| 函数 | C++11 前 | C++11 起 |
|------|---------|---------|
| 析构函数 | ✅ 三法则 | ✅ 五法则 |
| 拷贝构造函数 | ✅ 三法则 | ✅ 五法则 |
| 拷贝赋值运算符 | ✅ 三法则 | ✅ 五法则 |
| 移动构造函数 | — | ✅ 五法则 |
| 移动赋值运算符 | — | ✅ 五法则 |

**关键规则**：一旦自定义了析构函数，编译器就不会自动生成移动操作（会退化为拷贝操作）。

```cpp
class OnlyDtor {
    int* data_;
    size_t size_;
public:
    OnlyDtor(size_t n) : data_(new int[n]), size_(n) {}
    ~OnlyDtor() { delete[] data_; }
};

OnlyDtor a(10);
OnlyDtor b = std::move(a);
```

上述代码中 `b = std::move(a)` 实际执行的是**拷贝构造**而非移动构造，因为没有自定义移动操作。结果：双重释放。

***

### 4. 零法则（Rule of Zero）

**核心原则**：如果一个类不直接管理资源，就不要定义任何特殊成员函数，全部使用编译器默认生成的。

```cpp
#include <memory>  // 智能指针所需头文件
class GoodUser {
    std::string name_;
    std::vector<int> data_;
    std::unique_ptr<Connection> conn_;
public:
    GoodUser(const std::string& name)
        : name_(name), conn_(std::make_unique<Connection>()) {}
};
```

| 成员 | 自身管理 | GoodUser 需要 |
|------|---------|--------------|
| `std::string` | 内部管理内存 | ❌ 不需要 |
| `std::vector` | 内部管理内存 | ❌ 不需要 |
| `std::unique_ptr` | 管理所有权 | ❌ 不需要 |

编译器自动生成的五个函数全部正确：`std::string`/`vector` 深拷贝，`unique_ptr` 移动语义。

**三法则 vs 五法则 vs 零法则：**

| 法则 | 适用场景 | 需要定义的函数 |
|------|---------|--------------|
| 零法则 | 不直接管理资源 | 0 个（全部默认） |
| 三法则 | 管理资源，不需要移动 | 析构 + 拷贝构造 + 拷贝赋值 |
| 五法则 | 管理资源，需要移动 | 析构 + 拷贝构造 + 拷贝赋值 + 移动构造 + 移动赋值 |

### 5. 完整 Buffer 类示例（五法则）

```cpp
#include <algorithm>
#include <utility>

class Buffer {
    int* data_;
    size_t size_;

public:
    Buffer() : data_(nullptr), size_(0) {}

    explicit Buffer(size_t n) : data_(new int[n]()), size_(n) {}

    ~Buffer() {
        delete[] data_;
    }

    Buffer(const Buffer& other)
        : data_(new int[other.size_]), size_(other.size_) {
        std::copy(other.data_, other.data_ + other.size_, data_);
    }

    Buffer& operator=(const Buffer& other) {
        if (this != &other) {
            int* new_data = new int[other.size_];
            std::copy(other.data_, other.data_ + other.size_, new_data);
            delete[] data_;
            data_ = new_data;
            size_ = other.size_;
        }
        return *this;
    }

    Buffer(Buffer&& other) noexcept
        : data_(other.data_), size_(other.size_) {
        other.data_ = nullptr;
        other.size_ = 0;
    }

    Buffer& operator=(Buffer&& other) noexcept {
        if (this != &other) {
            delete[] data_;
            data_ = other.data_;
            size_ = other.size_;
            other.data_ = nullptr;
            other.size_ = 0;
        }
        return *this;
    }

    size_t size() const { return size_; }
    int& operator[](size_t i) { return data_[i]; }
    const int& operator[](size_t i) const { return data_[i]; }
};
```

**每个函数的职责：**

| 函数 | 职责 | 关键操作 |
|------|------|---------|
| 析构 | 释放资源 | `delete[] data_` |
| 拷贝构造 | 深拷贝 | 分配新内存 + 复制数据 |
| 拷贝赋值 | 先分配再释放 | 异常安全的赋值 |
| 移动构造 | 窃取资源 | 接管指针 + 置空源对象 |
| 移动赋值 | 释放+窃取 | 释放自身 + 接管指针 |

### 6. FileHandle 示例（RAII + 禁用拷贝）

```cpp
#include <cstdio>

class FileHandle {
    FILE* file_;

public:
    explicit FileHandle(const char* path, const char* mode)
        : file_(std::fopen(path, mode)) {
        if (!file_) {
            throw std::runtime_error("无法打开文件");
        }
    }

    ~FileHandle() {
        if (file_) std::fclose(file_);
    }

    FileHandle(const FileHandle&) = delete;
    FileHandle& operator=(const FileHandle&) = delete;

    FileHandle(FileHandle&& other) noexcept : file_(other.file_) {
        other.file_ = nullptr;
    }

    FileHandle& operator=(FileHandle&& other) noexcept {
        if (this != &other) {
            if (file_) std::fclose(file_);
            file_ = other.file_;
            other.file_ = nullptr;
        }
        return *this;
    }

    FILE* get() const { return file_; }

    void write(const char* data, size_t len) {
        std::fwrite(data, 1, len, file_);
    }
};
```

**设计决策：**

| 决策 | 原因 |
|------|------|
| 禁用拷贝 | 文件句柄不可共享，拷贝语义不明确 |
| 允许移动 | 文件所有权可转移 |
| 析构中 fclose | RAII 保证文件关闭 |
| 移动赋值中先关闭自身 | 避免资源泄漏 |

### 7. 常见错误与陷阱

**错误1：只定义析构，忘记拷贝操作**

```cpp
class LeakyString {
    char* data_;
public:
    LeakyString(const char* s) {
        data_ = new char[std::strlen(s) + 1];
        std::strcpy(data_, s);
    }
    ~LeakyString() { delete[] data_; }
};

LeakyString a("hello");
LeakyString b = a;
```

结果：`a` 和 `b` 的 `data_` 指向同一块内存，析构时双重释放。

**错误2：自赋值未处理**

```cpp
Buffer& operator=(const Buffer& other) {
    delete[] data_;
    size_ = other.size_;
    data_ = new int[size_];
    std::copy(other.data_, other.data_ + size_, data_);
    return *this;
}

Buffer x(10);
x = x;
```

结果：先 `delete[] data_`，再从已释放的 `other.data_` 拷贝，未定义行为。

**错误3：移动后使用源对象**

```cpp
Buffer a(10);
Buffer b = std::move(a);
a[0] = 42;
```

结果：移动后 `a` 的 `data_` 为 `nullptr`，解引用崩溃。

**错误4：移动构造未置空源对象**

```cpp
Buffer(Buffer&& other) noexcept : data_(other.data_), size_(other.size_) {
}
```

结果：`other` 析构时 `delete[] other.data_`，新对象也持有同一指针，双重释放。

**错误汇总表：**

| 错误 | 症状 | 修复 |
|------|------|------|
| 缺拷贝操作 | 双重释放 | 定义深拷贝 |
| 自赋值未检查 | 未定义行为 | 先检查 `this != &other` 或 copy-and-swap |
| 移动后使用源 | 崩溃 | 移动后源对象应处于有效但未指定状态 |
| 移动未置空源 | 双重释放 | 移动后置空源对象指针 |
| 拷贝赋值异常不安全 | 内存泄漏 | 先分配新内存再释放旧内存 |

### 8. Copy-and-Swap 惯用法

Copy-and-Swap 是一种异常安全的赋值实现方式：

```cpp
class Buffer {
    int* data_;
    size_t size_;

    friend void swap(Buffer& a, Buffer& b) noexcept {
        using std::swap;
        swap(a.data_, b.data_);
        swap(a.size_, b.size_);
    }

public:
    Buffer() : data_(nullptr), size_(0) {}
    explicit Buffer(size_t n) : data_(new int[n]()), size_(n) {}
    ~Buffer() { delete[] data_; }

    Buffer(const Buffer& other)
        : data_(new int[other.size_]), size_(other.size_) {
        std::copy(other.data_, other.data_ + other.size_, data_);
    }

    Buffer(Buffer&& other) noexcept : Buffer() {
        swap(*this, other);
    }

    Buffer& operator=(Buffer other) noexcept {
        swap(*this, other);
        return *this;
    }
};
```

**关键点**：`operator=` 的参数是**按值传递**，自动处理拷贝和移动两种情况：

| 调用方式 | 参数构造 | 交换后 |
|---------|---------|--------|
| `a = b;` | 拷贝构造 `other` | 交换后旧资源随 `other` 析构 |
| `a = std::move(b);` | 移动构造 `other` | 交换后旧资源随 `other` 析构 |

| 优势 | 说明 |
|------|------|
| 异常安全 | 拷贝在函数外完成，失败不影响 `*this` |
| 自赋值安全 | 交换后资源仍有效 |
| 代码简洁 | 一个函数处理拷贝和移动 |
| 自动选择 | 按值传参自动选择拷贝/移动 |

**代价**：移动赋值不是最优的（多一次交换），但对大多数类影响可忽略。

### 9. 零法则何时失效

零法则在以下场景会失效，需要手动定义特殊成员函数：

| 失效场景 | 原因 | 解决方案 |
|---------|------|---------|
| 多态基类 | 需要虚析构函数 | 定义虚析构，禁用拷贝/移动 |
| 包含裸指针 | 浅拷贝导致双重释放 | 替换为智能指针或实现五法则 |
| 包含互斥锁 | `std::mutex` 不可拷贝/移动 | 使用 `std::unique_ptr<std::mutex>` |
| 引用成员 | 引用不可重绑定 | 替换为指针或 `std::reference_wrapper` |
| 需要自定义析构逻辑 | 如日志记录 | 考虑用 RAII 包装器替代 |

**多态基类示例：**

```cpp
class Base {
public:
    virtual ~Base() = default;

    Base(const Base&) = default;
    Base& operator=(const Base&) = default;
    Base(Base&&) = default;
    Base& operator=(Base&&) = default;
};

class Derived : public Base {
    int* resource_;
public:
    Derived() : resource_(new int(0)) {}
    ~Derived() { delete resource_; }

    Derived(const Derived& other)
        : Base(other), resource_(new int(*other.resource_)) {}

    Derived& operator=(const Derived& other) {
        if (this != &other) {
            Base::operator=(other);
            delete resource_;
            resource_ = new int(*other.resource_);
        }
        return *this;
    }

    Derived(Derived&& other) noexcept
        : Base(std::move(other)), resource_(other.resource_) {
        other.resource_ = nullptr;
    }

    Derived& operator=(Derived&& other) noexcept {
        if (this != &other) {
            Base::operator=(std::move(other));
            delete resource_;
            resource_ = other.resource_;
            other.resource_ = nullptr;
        }
        return *this;
    }
};
```

> **继承中的关键点**：派生类的拷贝/移动操作必须显式调用基类对应操作，否则基类部分会被默认构造而非拷贝/移动。

### 10. 实战检查清单

**编写新类时的检查流程：**

```
类是否直接管理资源？
    │
    ├── 否 → 零法则：不定义任何特殊成员函数
    │
    └── 是 → 类是否可拷贝？
              │
              ├── 否 → 禁用拷贝，实现移动 + 析构
              │        (如 FileHandle)
              │
              └── 是 → 五法则：全部实现
                       (如 Buffer)
```

| 检查项 | 是 | 否 |
|--------|-----|-----|
| 类是否管理裸指针/文件句柄/网络连接？ | 需要五法则或禁用拷贝 | 零法则 |
| 析构函数是否需要自定义？ | 需要五法则 | 零法则 |
| 拷贝语义是否合理？ | 实现深拷贝 | `= delete` |
| 移动语义是否有意义？ | 实现移动操作 | `= delete` |
| 是否是多态基类？ | 虚析构 + 默认其余 | — |
| 自赋值是否安全？ | 检查或 copy-and-swap | 修复 |
| 移动后源对象是否有效？ | 置空指针 | 修复 |
| 移动操作是否 noexcept？ | 加 noexcept | 性能影响 |

### 11. 极简总结

| 法则 | 核心要点 | 适用场景 |
|------|---------|---------|
| 零法则 | 不管理资源就不定义特殊函数 | 使用标准库组件的类 |
| 三法则 | 析构+拷贝构造+拷贝赋值同时定义 | C++11 前的资源类 |
| 五法则 | 三法则 + 移动构造 + 移动赋值 | C++11 的资源类 |

**记忆口诀**：

- **零法则**：能不写就不写，用智能指针和标准容器
- **三法则**：写了一个就要写三个（析构/拷贝构造/拷贝赋值）
- **五法则**：三法则加俩移动，noexcept 别忘记
- **copy-and-swap**：按值传参 + swap，异常安全自赋值全搞定

**一句话决策树**：管资源？不管→零法则；管→可拷贝？不可→禁拷贝+移动+析构；可→五法则。
