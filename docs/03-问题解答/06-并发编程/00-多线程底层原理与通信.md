# 多线程底层原理与通信机制
> 📖 相关章节：[多线程基础](../../02-CPP/27-多线程基础.md)

> "Concurrency is not parallelism" — 并发非并行

### 1. 一句话概括

**进程是资源容器，线程是执行流；主线程是老板，子线程是员工；CPU是办公桌，共享内存是文件柜，锁是排队规则。**

***

### 2. 通俗比喻：一秒理解

#### 1. 进程 = 独立办公室

每个程序都是**一间单独的办公室**：

- 有自己的办公桌、文件柜、笔记本、资料
- 和别的办公室完全隔离，别人进不来、拿不到你文件

#### 2. 线程 = 办公室里的打工人

一间办公室（进程）里，可以坐**好多打工人（线程）**：

- 所有人**共用同一套文件柜、同一张大办公桌、同一份资料**
- 每个人**有自己专属的草稿纸、自己正在写的进度**

**对应程序：**

| 概念                     | 类比        |
| ---------------------- | --------- |
| 全局变量、静态变量、堆内存 `malloc` | 公用文件柜     |
| 线程局部变量、函数栈             | 每个人自己的草稿纸 |

#### 3. 主线程 = 办公室老板

程序一开机，**自动生成第一个打工人：老板**：

- `main()` 函数就是老板在干活
- 老板负责：开局、安排任务、招员工（创建子线程）、收尾
- **关键点**：老板走人（主线程退出），整个办公室直接关门，所有员工全部赶走

#### 4. CPU = 唯一的大办公桌

**CPU 核心就一张大桌子，同一时刻只能有一个人在桌上干活：**

- 单核CPU：就**1张桌子**，所有员工轮流上来用
- 多核CPU：有**多张桌子**，可以真的同时多人干活

#### 5. 多线程的意义

办公室里多雇几个员工：

- 有人算数据、有人下载文件、有人读写日志
- 不用一个人从头忙到尾
- **把耗时、阻塞的活分给别人，整体不卡顿、跑得快**

***

### 3. 线程 vs 进程：核心对比

| 维度       | 进程                | 线程                 |
| -------- | ----------------- | ------------------ |
| 本质       | 资源分配的基本单位         | CPU调度的基本单位          |
| 地址空间     | 各自独立，互相隔离         | 同进程内共享             |
| 创建开销     | 大（需复制地址空间）        | 小（共享进程资源）          |
| 切换开销     | 大（切换页表、TLB、上下文）   | 小（只切换栈和寄存器）        |
| 通信方式     | 管道、共享内存、信号、socket | 直接读写共享变量           |
| 安全性      | 一个进程崩溃不影响其他       | 一个线程崩溃整个进程挂掉       |
| 并发性      | 多进程并发             | 多线程并发              |
| 典型创建时间   | 毫秒级               | 微秒级                |
| 典型切换时间   | 微秒级               | 百纳秒级               |

**一句话区分**：进程是"隔离的房间"，线程是"同房间里的多个人"。

### 4. 线程的内存模型

同一个进程内的所有线程共享进程的整个虚拟地址空间，但各自有独立的栈：

#### 1. 共享区域（所有线程都能访问）

| 内存区域   | 内容            | 示例                     |
| ------ | ------------- | ---------------------- |
| 代码段    | 可执行指令         | 函数体、常量字符串              |
| 数据段    | 全局变量、静态变量     | `static int count;`    |
| 堆      | 动态分配的内存       | `malloc`/`new` 分配的内存   |
| 文件描述符表 | 打开的文件、socket  | `open()` 返回的 fd        |
| 环境变量   | 进程运行环境        | `getenv()` 获取的变量       |

#### 2. 独有区域（每个线程私有）

| 内存区域    | 内容          | 大小（默认）  |
| ------- | ----------- | ------- |
| 栈空间     | 局部变量、函数调用帧  | 8MB     |
| CPU寄存器  | PC、SP、通用寄存器 | 硬件决定    |
| 线程局部存储  | `__thread` 变量 | 可配置     |
| errno   | 每线程独立错误码    | 4B      |

**内存布局示意：**

```
高地址
┌──────────────────────┐
│     内核空间（不可访问）      │
├──────────────────────┤
│     栈（线程1私有）        │ ← 每个线程独立
├──────────────────────┤
│     栈（线程2私有）        │ ← 每个线程独立
├──────────────────────┤
│          ...          │
├──────────────────────┤
│     堆（共享）           │ ← malloc 分配，所有线程可见
├──────────────────────┤
│     BSS段（共享）        │ ← 未初始化全局/static
├──────────────────────┤
│     数据段（共享）         │ ← 已初始化全局/static
├──────────────────────┤
│     代码段（共享）         │ ← 函数指令
└──────────────────────┘
低地址
```

**关键结论**：线程间通信天然免费（共享地址空间），但共享带来竞争，必须加锁保护。

### 5. CPU硬件底层原理

#### 1. 进程 底层本质

**进程 = 资源容器**：

- 独占一套：虚拟地址空间、内存、文件描述符、环境变量
- 进程之间**完全隔离**，互不干扰

#### 2. 线程 底层本质

**线程 = 轻量级执行流**。同一个进程内的所有线程：

**共享**：

- 整个进程虚拟内存（全局、static、堆）
- 文件表、信号处理、工作目录

**独有**：

- **独立栈空间**（局部变量都在这）
- **CPU 上下文寄存器**（PC程序计数器、栈指针、各种运算寄存器）
- 独立调度状态（就绪、运行、阻塞）

**一句话底层：**

> **线程只独有「栈 + CPU寄存器现场」，其余全部共享进程资源。**

#### 3. CPU 怎么执行多线程？

##### 单核CPU：时间片轮转

CPU 给每个线程分**极短时间片（几毫秒）**：

1. 线程A上来跑几毫秒
2. 保存A的寄存器现场 -> 切走
3. 加载线程B的寄存器现场 -> B跑几毫秒
4. 无限快速轮换

**切换太快，肉眼/程序感觉是同时运行**，实际是**串行快速轮流**。

##### 多核CPU：真正并行

每个核心独立跑一个线程，**同一时刻真的多条线程同时在算**。

#### 4. 上下文切换的开销

| 操作         | 开销（约）   | 说明                |
| ---------- | ------- | ----------------- |
| 线程切换       | 1-2微秒   | 只切换寄存器和栈指针        |
| 进程切换       | 5-10微秒  | 还要切换页表、刷新TLB      |
| 系统调用（无阻塞）  | 0.1-1微秒 | 用户态/内核态切换         |
| 缓存失效       | 10-50微秒 | 切换后L1/L2缓存全部冷启动   |

### 6. 线程调度原理

#### 1. 调度策略

Linux 内核对线程（轻量级进程）的调度策略：

| 策略                | 名称     | 适用场景       | 特点               |
| ----------------- | ------ | ---------- | ---------------- |
| `SCHED_OTHER`    | 默认分时调度 | 普通应用       | CFS完全公平调度器       |
| `SCHED_FIFO`     | 先进先出实时 | 实时性要求高     | 不主动让出则一直运行       |
| `SCHED_RR`       | 时间片轮转实时 | 实时+公平      | 同优先级轮流执行         |
| `SCHED_BATCH`    | 批处理调度  | 后台计算任务     | 低交互性，吞吐量优先       |

#### 2. 调度时机

线程在以下情况会被调度器切换：

1. **时间片用完**：CFS调度器按虚拟运行时间公平分配
2. **主动让出**：调用 `sched_yield()`、`sleep()`
3. **阻塞等待**：等锁、等I/O、等条件变量
4. **更高优先级线程就绪**：被抢占
5. **创建新线程**：新线程进入就绪队列

#### 3. 调度流程示意

```
线程A运行中
    │
    ├── 时间片用完 ──→ 保存A上下文 → A进就绪队列
    │                              │
    ├── 等待I/O ───→ 保存A上下文 → A进等待队列
    │                              │
    └── 主动sleep ─→ 保存A上下文 → A进定时等待队列
                                   │
                            调度器选下一个线程B
                                   │
                            加载B上下文 → B开始运行
```

### 7. 任务分配模式

工程就两种模式，没别的：

#### 1. 模式1：静态分工

线程A固定做任务1，线程B固定做任务2，写死逻辑。

```c
void* thread_func_download(void* arg) {
    // 线程A：专门下载
    while (1) {
        download_file(get_next_url());
    }
}

void* thread_func_process(void* arg) {
    // 线程B：专门处理数据
    while (1) {
        process_data(get_downloaded_data());
    }
}

int main() {
    pthread_t t1, t2;
    pthread_create(&t1, NULL, thread_func_download, NULL);
    pthread_create(&t2, NULL, thread_func_process, NULL);
    pthread_join(t1, NULL);
    pthread_join(t2, NULL);
    return 0;
}
```

#### 2. 模式2：任务队列 + 线程池（最常用）

主线程把任务丢进**公共环形队列**，所有子线程循环去队列抢任务。

```c
// 任务结构体
typedef struct {
    int type;
    void* data;
} Task;

// 全局任务队列（共享资源）
Task task_queue[1024];
int queue_head = 0;
int queue_tail = 0;
pthread_mutex_t queue_mutex;
pthread_cond_t queue_cond;

// 线程工作函数
void* worker_thread(void* arg) {
    while (1) {
        pthread_mutex_lock(&queue_mutex);

        // 队列为空，等待任务
        while (queue_head == queue_tail) {
            pthread_cond_wait(&queue_cond, &queue_mutex);
        }

        // 取出任务
        Task task = task_queue[queue_head++];
        pthread_mutex_unlock(&queue_mutex);

        // 执行任务
        execute_task(&task);
    }
}

// 主线程添加任务
void add_task(Task* task) {
    pthread_mutex_lock(&queue_mutex);
    task_queue[queue_tail++] = *task;
    pthread_cond_signal(&queue_cond);  // 唤醒一个线程
    pthread_mutex_unlock(&queue_mutex);
}
```

#### 3. 两种模式对比

| 维度     | 静态分工       | 任务队列+线程池   |
| ------ | ----------- | ----------- |
| 灵活性    | 低，写死逻辑      | 高，动态分配任务    |
| 负载均衡   | 差，可能忙闲不均    | 好，自动均衡      |
| 实现复杂度  | 简单          | 较复杂         |
| 适用场景   | 固定流水线       | 通用场景        |
| 扩展性    | 差，加任务要加线程   | 好，线程数与任务解耦  |

### 8. 线程间通信方式

因为**同进程共享地址空间**，天生不用像进程那样搞管道/socket：

#### 1. 方式1：共享内存（最底层原生）

全局变量 / static / malloc堆内存，所有线程直接**同指针同地址读写**。

```c
// 共享数据
int shared_counter = 0;
pthread_mutex_t counter_mutex;

void* increment_thread(void* arg) {
    for (int i = 0; i < 1000; i++) {
        pthread_mutex_lock(&counter_mutex);
        shared_counter++;  // 临界区
        pthread_mutex_unlock(&counter_mutex);
    }
    return NULL;
}
```

**缺点**：并发争抢 -> **必须加互斥锁**串行访问

#### 2. 方式2：任务队列通信

把数据打包成任务结构体，丢队列，线程从队列取数据。

**优点**：解耦、安全、好维护

#### 3. 方式3：条件变量 做等待/唤醒

条件变量允许线程在条件不满足时**挂起等待**（不消耗 CPU），由另一个线程在条件满足时**发出通知唤醒**。必须配合互斥锁使用，核心操作：`wait`（释放锁→挂起→被唤醒后重新获取锁）、`notify_one/notify_all`（唤醒等待线程）。

条件变量的详细用法（虚假唤醒、丢失唤醒、完整示例），请参阅 → [什么是条件变量condition-variable](16-什么是条件变量condition-variable.md)

#### 4. 方式4：信号量

信号量用于控制对有限数量资源的访问，适合"生产者-消费者"场景。

```c
#include <semaphore.h>

sem_t empty_slots;  // 空位数量
sem_t filled_slots; // 已填充数量
pthread_mutex_t buf_mutex;

#define BUF_SIZE 16
int buffer[BUF_SIZE];
int buf_index = 0;

void* producer(void* arg) {
    for (int i = 0; i < 100; i++) {
        sem_wait(&empty_slots);         // 等空位
        pthread_mutex_lock(&buf_mutex);
        buffer[buf_index++] = i;        // 放入数据
        pthread_mutex_unlock(&buf_mutex);
        sem_post(&filled_slots);        // 通知有数据
    }
    return NULL;
}

void* consumer(void* arg) {
    for (int i = 0; i < 100; i++) {
        sem_wait(&filled_slots);         // 等数据
        pthread_mutex_lock(&buf_mutex);
        int data = buffer[--buf_index];  // 取出数据
        pthread_mutex_unlock(&buf_mutex);
        sem_post(&empty_slots);          // 通知有空位
        printf("消费: %d\n", data);
    }
    return NULL;
}

int main() {
    sem_init(&empty_slots, 0, BUF_SIZE);
    sem_init(&filled_slots, 0, 0);

    pthread_t prod, cons;
    pthread_create(&prod, NULL, producer, NULL);
    pthread_create(&cons, NULL, consumer, NULL);

    pthread_join(prod, NULL);
    pthread_join(cons, NULL);

    sem_destroy(&empty_slots);
    sem_destroy(&filled_slots);
    return 0;
}
```

#### 5. 四种通信方式对比

| 方式     | 原理        | 优点       | 缺点       | 适用场景       |
| ------ | --------- | -------- | -------- | ---------- |
| 共享内存   | 直接读写全局/堆  | 最快、最直接   | 需加锁、易出错  | 简单数据共享     |
| 任务队列   | 结构体+环形缓冲区 | 解耦、好维护   | 实现较复杂    | 通用任务分发     |
| 条件变量   | 等待/唤醒机制   | 避免轮询省CPU | 必须配合互斥锁  | 事件通知、状态等待  |
| 信号量    | 计数器+等待队列  | 控制资源数量   | 语义不如条件变量 | 生产者-消费者模型  |

### 9. 线程安全概念

#### 1. 什么是线程安全？

**线程安全** = 多个线程同时访问某段代码/数据，结果始终正确，不依赖线程的执行顺序。

#### 2. 线程不安全的根本原因

```c
// 看似一行代码，实际是三步操作
shared_counter++;
// 等价于：
// 1. 读取 shared_counter 到寄存器
// 2. 寄存器值 +1
// 3. 写回 shared_counter
```

**两个线程同时执行这三步，就会丢失更新：**

| 时序 | 线程A           | 线程B           | shared_counter |
| -- | ------------- | ------------- | -------------- |
| T1 | 读 counter=0   | -             | 0              |
| T2 | -             | 读 counter=0   | 0              |
| T3 | 寄存器+1 = 1    | -             | 0              |
| T4 | 写回 counter=1  | 寄存器+1 = 1    | 1              |
| T5 | -             | 写回 counter=1  | 1              |

**结果：两次加1，counter只从0变成1，丢失了一次更新。**

#### 3. 线程安全的实现手段

| 手段       | 原理          | 示例                         |
| -------- | ----------- | -------------------------- |
| 互斥锁      | 临界区串行化      | `pthread_mutex_lock/unlock` |
| 原子操作     | 硬件级不可分割     | `__sync_add_and_fetch`     |
| 线程局部存储   | 每线程独立副本     | `__thread int count;`      |
| 只读共享     | 不修改就不竞争     | `const char* msg = "hello"` |
| 无锁数据结构   | CAS等原子指令实现  | 无锁队列、无锁栈                   |

#### 4. 常见线程不安全函数

| 函数              | 不安全原因         | 线程安全替代            |
| --------------- | ------------- | ----------------- |
| `strtok()`      | 内部静态状态        | `strtok_r()`      |
| `rand()`        | 内部静态种子        | `rand_r()`        |
| `asctime()`     | 返回静态缓冲区指针     | `asctime_r()`     |
| `gmtime()`      | 返回静态结构体指针     | `gmtime_r()`      |
| `strerror()`    | 静态字符串缓冲区      | `strerror_r()`    |
| `malloc()/free()` | 需要内部锁保护（通常已实现） | 大多数实现已线程安全        |

### 10. 完整C代码示例：多线程协作

```c
#include <stdio.h>
#include <stdlib.h>
#include <pthread.h>
#include <unistd.h>

// 共享数据
typedef struct {
    int produced_count;
    int consumed_count;
    int buffer[8];
    int buf_head;
    int buf_tail;
    int buf_size;
} SharedData;

// 同步原语
pthread_mutex_t g_mutex = PTHREAD_MUTEX_INITIALIZER;
pthread_cond_t  g_cond_produce = PTHREAD_COND_INITIALIZER;
pthread_cond_t  g_cond_consume = PTHREAD_COND_INITIALIZER;

#define BUFFER_CAPACITY 8
#define TOTAL_ITEMS 20

void* producer(void* arg) {
    SharedData* data = (SharedData*)arg;

    for (int i = 1; i <= TOTAL_ITEMS; i++) {
        pthread_mutex_lock(&g_mutex);

        // 缓冲区满，等待消费者取走
        while (data->buf_size >= BUFFER_CAPACITY) {
            pthread_cond_wait(&g_cond_produce, &g_mutex);
        }

        // 生产：放入缓冲区
        data->buffer[data->buf_tail] = i;
        data->buf_tail = (data->buf_tail + 1) % BUFFER_CAPACITY;
        data->buf_size++;
        data->produced_count++;

        printf("[生产者] 生产物品 %d, 缓冲区大小=%d\n", i, data->buf_size);

        // 通知消费者
        pthread_cond_signal(&g_cond_consume);
        pthread_mutex_unlock(&g_mutex);

        usleep(100000);  // 模拟生产耗时
    }

    printf("[生产者] 完成所有生产\n");
    return NULL;
}

void* consumer(void* arg) {
    SharedData* data = (SharedData*)arg;

    for (int i = 1; i <= TOTAL_ITEMS; i++) {
        pthread_mutex_lock(&g_mutex);

        // 缓冲区空，等待生产者放入
        while (data->buf_size <= 0) {
            pthread_cond_wait(&g_cond_consume, &g_mutex);
        }

        // 消费：从缓冲区取出
        int item = data->buffer[data->buf_head];
        data->buf_head = (data->buf_head + 1) % BUFFER_CAPACITY;
        data->buf_size--;
        data->consumed_count++;

        printf("[消费者] 消费物品 %d, 缓冲区大小=%d\n", item, data->buf_size);

        // 通知生产者
        pthread_cond_signal(&g_cond_produce);
        pthread_mutex_unlock(&g_mutex);

        usleep(200000);  // 模拟消费耗时
    }

    printf("[消费者] 完成所有消费\n");
    return NULL;
}

int main() {
    SharedData data = {0, 0, {0}, 0, 0, 0};

    pthread_t prod_thread, cons_thread;
    pthread_create(&prod_thread, NULL, producer, &data);
    pthread_create(&cons_thread, NULL, consumer, &data);

    pthread_join(prod_thread, NULL);
    pthread_join(cons_thread, NULL);

    printf("\n===== 最终统计 =====\n");
    printf("生产总数: %d\n", data.produced_count);
    printf("消费总数: %d\n", data.consumed_count);

    pthread_mutex_destroy(&g_mutex);
    pthread_cond_destroy(&g_cond_produce);
    pthread_cond_destroy(&g_cond_consume);

    return 0;
}
```

### 11. 常见陷阱与最佳实践

#### 1. 常见陷阱

| 陷阱              | 后果          | 解决方案                |
| --------------- | ----------- | ------------------- |
| 忘记加锁保护共享变量      | 数据竞争、结果错误   | 所有共享写操作必须加锁         |
| 条件变量用 if 而非 while | 虚假唤醒导致错误    | 必须用 while 循环等待      |
| 主线程先于子线程退出      | 子线程被强制终止    | 主线程用 pthread_join 等待 |
| 锁粒度过大           | 多线程退化为串行    | 只锁必要的临界区            |
| 忘记释放锁           | 死锁          | lock/unlock 严格配对     |
| 使用非线程安全函数       | 数据混乱        | 使用 `_r` 后缀的可重入版本    |

#### 2. 最佳实践

1. **最小化临界区**：只锁共享数据读写的代码，不要锁计算和I/O
2. **锁的获取顺序一致**：多把锁时，所有线程按相同顺序获取，避免死锁
3. **条件变量必须配合 while**：防止虚假唤醒
4. **优先使用不可变数据**：只读共享不需要锁
5. **线程数不宜过多**：一般不超过CPU核心数的2-3倍
6. **避免在临界区内调用阻塞函数**：如 `sleep()`、`printf()`

### 12. 极简总结

#### 1. 比喻版

> 进程是独立办公室，线程是办公室员工，主线程是老板；CPU是办公桌，单核轮流用，多核同时用；员工共用文件柜（共享内存），各有草稿纸（私有栈），抢工单干活，改公共文件要排队加锁。

#### 2. 底层版

> 线程是共享进程资源、独有栈和CPU寄存器的轻量级执行流；CPU靠时间片切换实现并发，多核实现并行；线程天然靠共享内存通信，靠锁和队列解决争抢与任务分配。

#### 3. 通信版

> 共享内存最直接但要加锁，任务队列最解耦，条件变量做等待/唤醒最省CPU，信号量控资源数量最方便——四种方式按场景选用。
