# 什么是竞态条件
> 📖 相关章节：[多线程基础](../../02-CPP/27-多线程基础.md)、[线程同步](../../02-CPP/28-线程同步.md)、[原子操作](../../02-CPP/29-原子操作与异步编程.md)、[无锁编程](../../02-CPP/33-无锁编程.md)

> **A race condition is when the outcome depends on the timing of uncontrollable events.** — 竞态条件：程序结果取决于不可控的事件时序。

***

### 1. 一句话概括

**竞态条件**（Race Condition）= 多个线程访问同一数据，且至少一个线程在写，由于执行顺序不确定，导致结果不可预测。**数据竞争**（Data Race）是竞态条件的子集，特指无同步的并发读写。

***

### 2. 生活类比

把竞态条件比作**两人同时编辑同一文档**：

- 人 A 把标题改成"报告 v1"
- 人 B 同时把标题改成"报告 v2"
- 最后保存的标题取决于谁最后按了保存键 → 结果不可预测

如果两人约定：编辑前先"锁定"文档，另一个人必须等待 → 这就是**加锁同步**。

### 3. 竞态条件 vs 数据竞争

| 概念 | 定义 | 关系 |
|------|------|------|
| 数据竞争（Data Race） | 多线程无同步地同时读写同一内存 | 是竞态条件的子集 |
| 竞态条件（Race Condition） | 程序结果依赖线程执行顺序 | 范围更广 |

**数据竞争一定是竞态条件，但竞态条件不一定是数据竞争。**

```cpp
#include <iostream>
#include <mutex>

int balance = 1000;
std::mutex mtx;

// 数据竞争：无同步的并发读写
void unsafe_deposit(int amount) {
    balance += amount;  // 不是原子操作！
    // 实际步骤：读 balance → 计算 → 写 balance
    // 两个线程可能读到相同的旧值
}

// 安全：加锁保护
void safe_deposit(int amount) {
    std::lock_guard<std::mutex> lock(mtx);
    balance += amount;
}
```

### 4. 经典竞态条件示例

#### 银行转账问题

```cpp
#include <iostream>
#include <thread>

int account = 1000;

void deposit(int amount) {
    // balance += amount 不是原子操作，实际是三步：
    // 1. 读取 account 的值
    // 2. 计算新值
    // 3. 写回 account
    account += amount;
}

int main() {
    // 两个线程各存 100，期望结果 1200
    std::thread t1(deposit, 100);
    std::thread t2(deposit, 100);
    t1.join();
    t2.join();

    std::cout << "余额: " << account << std::endl;
    // 可能输出 1100！而不是 1200
    // 因为两个线程可能都读到 1000，各加 100，都写回 1100
}
```

**时序分析**：

| 时刻 | 线程1 | 线程2 | account 值 |
|------|-------|-------|-----------|
| T1 | 读取 1000 | | 1000 |
| T2 | | 读取 1000 | 1000 |
| T3 | 计算 1100 | | 1000 |
| T4 | | 计算 1100 | 1000 |
| T5 | 写入 1100 | | 1100 |
| T6 | | 写入 1100 | 1100 |

结果：1100，丢失了一次存款！

#### 懒加载的双重检查锁

```cpp
#include <iostream>
#include <mutex>

class Singleton {
    static Singleton* instance_;
    static std::mutex mtx_;

    Singleton() { std::cout << "构造" << std::endl; }
public:
    // 有竞态条件的版本（即使加锁也可能有问题）
    static Singleton* get_instance() {
        if (!instance_) {                    // 第一次检查（无锁）
            std::lock_guard<std::mutex> lock(mtx_);
            if (!instance_) {                // 第二次检查（有锁）
                instance_ = new Singleton(); // 可能被编译器重排
            }
        }
        return instance_;
    }
};

Singleton* Singleton::instance_ = nullptr;
std::mutex Singleton::mtx_;

// C++11 正确做法：使用局部静态变量
class SafeSingleton {
public:
    static SafeSingleton& get_instance() {
        static SafeSingleton instance;  // C++11 保证线程安全
        return instance;
    }
};
```

### 5. 如何修复竞态条件

#### 方法1：互斥锁（Mutex）

```cpp
#include <iostream>
#include <mutex>
#include <thread>

int counter = 0;
std::mutex counter_mtx;

void safe_increment() {
    for (int i = 0; i < 100000; ++i) {
        std::lock_guard<std::mutex> lock(counter_mtx);
        ++counter;  // 受锁保护，安全
    }
}

int main() {
    std::thread t1(safe_increment);
    std::thread t2(safe_increment);
    t1.join();
    t2.join();
    std::cout << counter << std::endl;  // 一定是 200000
}
```

#### 方法2：原子操作（Atomic）

```cpp
#include <iostream>
#include <atomic>
#include <thread>

std::atomic<int> counter{0};

void atomic_increment() {
    for (int i = 0; i < 100000; ++i) {
        ++counter;  // 原子操作，无锁但安全
    }
}

int main() {
    std::thread t1(atomic_increment);
    std::thread t2(atomic_increment);
    t1.join();
    t2.join();
    std::cout << counter.load() << std::endl;  // 一定是 200000
}
```

#### 方法3：避免共享（线程局部存储）

```cpp
#include <iostream>
#include <thread>

// 每个线程有自己的计数器，无需同步
void count_with_tls() {
    thread_local int local_counter = 0;
    for (int i = 0; i < 100000; ++i) {
        ++local_counter;
    }
    std::cout << "线程计数: " << local_counter << std::endl;
}
```

### 6. 修复方法对比

| 方法 | 优点 | 缺点 | 适用场景 |
|------|------|------|---------|
| 互斥锁 | 通用、可保护复杂操作 | 有性能开销、可能死锁 | 复杂的临界区 |
| 原子操作 | 无锁、性能好 | 只能保护简单操作 | 计数器、标志位 |
| 线程局部存储 | 无竞争 | 不能共享数据 | 独立计算 |
| 不可变数据 | 天然线程安全 | 不能修改 | 配置信息 |
| 消息传递 | 避免共享 | 需要通信机制 | 生产者-消费者 |

### 7. 常见竞态条件模式

| 模式 | 描述 | 示例 |
|------|------|------|
| 检查后使用 | 检查条件和使用结果之间状态可能改变 | `if (ptr) use(*ptr);` ptr 可能被其他线程置空 |
| 读-修改-写 | 读取、计算、写回不是原子的 | `++counter` |
| 延迟初始化 | 多线程同时初始化 | 双重检查锁 |
| 发布逸出 | 对象未构造完就被其他线程看到 | 构造函数中启动线程 |

### 8. ThreadSanitizer 检测

```bash
# GCC / Clang
g++ -fsanitize=thread -g -O1 program.cpp -o program
./program
```

ThreadSanitizer 检测数据竞争的输出示例：

```
==================
WARNING: ThreadSanitizer: data race (pid=12345)
  Write of size 4 at 0x7b0400000180 by thread T2:
    #0 deposit /path/test.cpp:5:5

  Previous write of size 4 at 0x7b0400000180 by thread T1:
    #0 deposit /path/test.cpp:5:5

  Location is global 'account' of size 4 at 0x7b0400000180
==================
```

### 9. 极简总结

**竞态条件 = 结果依赖线程执行顺序 → 数据竞争是无同步的并发读写 → 修复：互斥锁、原子操作、避免共享 → `++counter` 不是原子操作 → ThreadSanitizer 检测 → 核心原则：共享可变状态必须同步**
