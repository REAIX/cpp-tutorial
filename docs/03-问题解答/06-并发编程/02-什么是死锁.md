# 什么是死锁
> 📖 相关章节：[线程同步](../../02-CPP/28-线程同步.md)

> **Deadlock: two threads, each waiting for the other, forever.** — 死锁：两个线程互相等待，永远等下去。

***

### 1. 精髓速览

**死锁**（Deadlock）= 两个或多个线程互相持有对方需要的锁，同时又等待对方释放锁，导致所有线程永远阻塞，程序卡死。

***

### 2. 生活类比

把死锁比作**窄桥相遇**：

- 线程 A 拿着左半边桥的通行证，想走右半边
- 线程 B 拿着右半边桥的通行证，想走左半边
- 两人都等对方让路，谁也不让 → 永远堵在桥上

另一个经典类比：两个人吃饭，只有一双筷子，每人拿了一根，都等对方放下 → 都吃不了饭。

### 3. 死锁的四个必要条件

死锁必须**同时满足**以下四个条件：

| 条件 | 含义 | 生活类比 |
|------|------|---------|
| 互斥（Mutual Exclusion） | 资源同一时刻只能被一个线程使用 | 筷子只有一双 |
| 持有并等待（Hold and Wait） | 持有资源的同时等待其他资源 | 拿着一根筷子等另一根 |
| 不可剥夺（No Preemption） | 不能强行夺走线程持有的资源 | 不能抢别人的筷子 |
| 循环等待（Circular Wait） | 形成环形等待链 | A 等 B，B 等 A |

**打破任意一个条件，死锁就不会发生。**

### 4. 死锁代码示例

```cpp
#include <iostream>
#include <mutex>
#include <thread>

std::mutex mutex_a;
std::mutex mutex_b;

// 线程1：先锁 A，再锁 B
void thread1() {
    std::lock_guard<std::mutex> lock_a(mutex_a);
    std::cout << "线程1: 已锁 A，等待锁 B" << std::endl;
    std::this_thread::sleep_for(std::chrono::milliseconds(100));  // 增加死锁概率
    std::lock_guard<std::mutex> lock_b(mutex_b);
    std::cout << "线程1: 获得锁 B" << std::endl;
}

// 线程2：先锁 B，再锁 A（顺序相反 → 死锁！）
void thread2() {
    std::lock_guard<std::mutex> lock_b(mutex_b);
    std::cout << "线程2: 已锁 B，等待锁 A" << std::endl;
    std::this_thread::sleep_for(std::chrono::milliseconds(100));
    std::lock_guard<std::mutex> lock_a(mutex_a);
    std::cout << "线程2: 获得锁 A" << std::endl;
}

int main() {
    std::thread t1(thread1);
    std::thread t2(thread2);
    t1.join();
    t2.join();
    // 程序卡死！两个线程互相等待
    std::cout << "这行永远不会输出" << std::endl;
}
```

### 5. 哲学家就餐问题

经典的死锁场景：5 个哲学家围坐圆桌，每两人之间一根筷子，每人需要两根筷子才能吃饭。

```
     哲学家0
    /        \
  筷子0      筷子4
  /            \
哲学家1        哲学家4
  \            /
  筷子1      筷子3
    \        /
     哲学家2-筷子2-哲学家3
```

如果每个哲学家都先拿左边的筷子，再拿右边的筷子 → 所有人都拿着一根筷子等另一根 → 死锁！

```cpp
#include <iostream>
#include <mutex>
#include <thread>

std::mutex chopsticks[5];

void philosopher(int id) {
    int left = id;
    int right = (id + 1) % 5;

    // 死锁版本：先拿左再拿右
    chopsticks[left].lock();
    std::cout << "哲学家" << id << "拿起左边筷子" << std::endl;
    chopsticks[right].lock();
    std::cout << "哲学家" << id << "开始吃饭" << std::endl;
    chopsticks[right].unlock();
    chopsticks[left].unlock();
}
```

### 6. 如何预防死锁

#### 策略1：固定加锁顺序（最常用）

所有线程按相同顺序获取锁，打破"循环等待"条件：

```cpp
// 正确：两个线程都先锁 A 再锁 B
void thread1_fixed() {
    std::lock_guard<std::mutex> lock_a(mutex_a);
    std::lock_guard<std::mutex> lock_b(mutex_b);
    // ...
}

void thread2_fixed() {
    std::lock_guard<std::mutex> lock_a(mutex_a);  // 也先锁 A
    std::lock_guard<std::mutex> lock_b(mutex_b);
    // ...
}
```

#### 策略2：使用 std::lock 同时获取多个锁

```cpp
#include <mutex>

std::mutex mutex_a, mutex_b;

void safe_double_lock() {
    // std::lock 同时获取多个锁，不会死锁
    std::lock(mutex_a, mutex_b);

    // 用 adopt_lock 告诉 lock_guard 锁已经被获取
    std::lock_guard<std::mutex> lock_a(mutex_a, std::adopt_lock);
    std::lock_guard<std::mutex> lock_b(mutex_b, std::adopt_lock);

    // 安全地操作共享数据
}
```

#### 策略3：C++17 std::scoped_lock

```cpp
#include <mutex>

std::mutex mutex_a, mutex_b;

void modern_safe_lock() {
    // C++17：scoped_lock 自动管理多个锁，不会死锁
    std::scoped_lock lock(mutex_a, mutex_b);
    // 安全地操作共享数据
    // 离开作用域自动释放两个锁
}
```

#### 策略4：哲学家问题的解决方案

```cpp
void philosopher_fixed(int id) {
    int left = id;
    int right = (id + 1) % 5;

    // 方案：奇数号先拿左，偶数号先拿右（打破循环等待）
    int first = (id % 2 == 0) ? right : left;
    int second = (id % 2 == 0) ? left : right;

    std::lock_guard<std::mutex> lock1(chopsticks[first]);
    std::lock_guard<std::mutex> lock2(chopsticks[second]);
    std::cout << "哲学家" << id << "开始吃饭" << std::endl;
}
```

### 7. 如何检测死锁

| 方法 | 说明 |
|------|------|
| 代码审查 | 检查加锁顺序是否一致 |
| 超时机制 | `try_lock_for` 设置超时 |
| 死锁检测工具 | Valgrind (helgrind)、ThreadSanitizer |
| 日志分析 | 记录加锁/解锁操作 |
| 线程转储 | 分析线程阻塞状态 |

**ThreadSanitizer 检测死锁**：

```bash
g++ -fsanitize=thread -g -O1 program.cpp -o program
./program
```

**超时机制**：

```cpp
#include <mutex>
#include <iostream>

std::mutex mtx;

void try_with_timeout() {
    std::unique_lock<std::mutex> lock(mtx, std::defer_lock);
    if (lock.try_lock_for(std::chrono::milliseconds(100))) {
        // 成功获取锁
    } else {
        std::cout << "获取锁超时，可能死锁" << std::endl;
        // 执行回退逻辑
    }
}
```

### 8. 死锁预防策略总结

| 策略 | 打破的条件 | 实现方式 |
|------|-----------|---------|
| 固定加锁顺序 | 循环等待 | 所有线程按相同顺序加锁 |
| 同时获取多个锁 | 持有并等待 | `std::lock` / `scoped_lock` |
| 超时机制 | 不可剥夺 | `try_lock_for` |
| 单锁设计 | 互斥 | 用一个粗粒度锁替代多个细粒度锁 |
| 避免嵌套锁 | 持有并等待 | 持有锁时不获取其他锁 |

### 9. 极简总结

**死锁 = 互相等待，永远阻塞 → 四个必要条件：互斥、持有并等待、不可剥夺、循环等待 → 打破任意一个即可预防 → 最实用策略：固定加锁顺序 → C++17 scoped_lock 同时获取多锁 → 超时机制作为安全网 → ThreadSanitizer 检测**
