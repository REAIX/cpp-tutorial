# 并发/并行/异步/同步概念辨析
> 📖 相关章节：[多线程基础](../../02-CPP/27-多线程基础.md)、[原子操作与异步编程](../../02-CPP/29-原子操作与异步编程.md)

> "一个人交替接两通电话，还是两个人各接一通电话？发完邮件就去做别的事，还是打电话必须等对方接听？"——并发与并行说的是"怎么安排任务"，异步与同步说的是"怎么等待结果"。

***

## 1. 为什么这四个概念容易混淆

这四个概念之所以常被混为一谈，根本原因在于**日常语境与计算机语境的含义不同**：

| 概念 | 日常含义 | 计算机含义 | 混淆原因 |
|------|---------|-----------|---------|
| 并发 | "同时发生" | 逻辑上的交替处理 | 日常"并发"≈"同时"，计算机强调"交替" |
| 并行 | "并排进行" | 物理上的同时执行 | 与日常含义接近，但常与并发混淆 |
| 异步 | "不同步" | 发起操作后不等待完成 | 日常"异步"含贬义，计算机是中性甚至褒义 |
| 同步 | "步调一致" | 发起操作后等待完成才继续 | 日常"同步"偏正面，计算机中可能意味着阻塞 |

**核心混淆点**：

```
日常语境：并发 ≈ 并行 ≈ "同时"
计算机语境：并发 ≠ 并行（并发是逻辑同时，并行是物理同时）

日常语境：异步 ≈ "不协调"
计算机语境：异步 = "不阻塞等待"（一种高效的编程模式）

日常语境：同步 ≈ "协调一致"
计算机语境：同步 = "阻塞等待"（可能降低效率）
```

**两组概念描述的是不同维度**：

- **并发 vs 并行**：描述的是**任务如何执行**（执行模型）
- **异步 vs 同步**：描述的是**调用者如何等待**（交互模式）

这两组概念是正交的，可以自由组合。

***

## 2. 并发（Concurrency）— 交替处理多个任务

### 1. 定义

并发是指**逻辑上的同时处理多个任务**。多个任务在同一时间段内启动并运行，但不一定在同一时刻同时执行。通过快速交替（时间片轮转），让多个任务看起来是"同时"在进行。

### 2. 比喻

**一个人同时接两个电话**：

```
时间线：
电话A: 说话█  等待░░░  说话█  等待░░░  说话█
电话B: 等待░░░  说话█  等待░░░  说话█  等待░
         ↑ 切换    ↑ 切换    ↑ 切换

你只有一张嘴（单核），但通过在两通电话间快速切换，
让对方都感觉你在"同时"和他们通话。
```

### 3. 关键点

| 要点 | 说明 |
|------|------|
| 单核也能并发 | 通过时间片轮转实现逻辑上的同时处理 |
| 目标是结构化 | 让程序的结构可以处理多个任务 |
| 不要求物理同时 | 任务可以在一个核心上交替执行 |
| 关注点 | 任务的管理和调度 |

### 4. C++ 中的并发

```cpp
#include <iostream>
#include <thread>
#include <mutex>

std::mutex mtx;

void task(const std::string& name, int count) {
    for (int i = 0; i < count; ++i) {
        std::lock_guard<std::mutex> lock(mtx);
        std::cout << name << " step " << i << std::endl;
    }
}

int main() {
    std::thread t1(task, "A", 5);
    std::thread t2(task, "B", 5);
    t1.join();
    t2.join();
    return 0;
}
```

即使运行在单核机器上，两个线程也会通过时间片轮转交替执行，这就是并发。

## 3. 并行（Parallelism）— 真正的同时执行

### 1. 定义

并行是指**物理上的同时执行多个任务**。多个任务在同一时刻真正同时运行在不同的处理器核心上。

### 2. 比喻

**两个人各自接一个电话**：

```
时间线：
人1（核心1）: 电话A ████████████████████████
人2（核心2）: 电话B ████████████████████████
              ↑ 真正同时进行，不需要切换

两个人（多核），各接一通电话，真正的同时通话。
```

### 3. 关键点

| 要点 | 说明 |
|------|------|
| 需要多核/多处理器 | 单核无法实现真正的并行 |
| 目标是加速 | 让任务更快完成 |
| 物理同时执行 | 同一时刻有多个任务在执行 |
| 关注点 | 计算资源的利用 |

### 4. 并发与并行的关系

```
并发是结构性的：程序可以处理多个任务（设计层面）
并行是执行性的：多个任务真正同时运行（硬件层面）

所有并行都是并发，但并发不一定是并行。

单核多任务：并发 ✓  并行 ✗  （交替执行）
多核多任务：并发 ✓  并行 ✓  （真正同时）
单核单任务：并发 ✗  并行 ✗  （顺序执行）
```

### 5. C++ 中的并行

```cpp
#include <iostream>
#include <vector>
#include <algorithm>
#include <execution>

int main() {
    std::vector<int> data(10000000);
    for (int i = 0; i < 10000000; ++i) data[i] = i;

    // 并行排序，自动利用多核
    std::sort(std::execution::par, data.begin(), data.end(),
              std::greater<int>());

    // 并行遍历
    std::for_each(std::execution::par, data.begin(), data.end(),
                  [](int& x) { x *= 2; });

    return 0;
}
```

## 4. 异步（Asynchronous）— 不等结果就继续

### 1. 定义

异步是指**发起一个操作后不等待其完成就继续执行后续代码**。操作完成后通过回调、Future 或事件通知等方式获取结果。

### 2. 比喻

**发邮件**：

```
你：写邮件 → 发送 → 去做别的事（喝咖啡、写代码...）
                    ↓
对方：收到邮件 → 处理 → 回信
                              ↓
你：收到回信通知 → 查看结果

关键：发完邮件你不需要干等，可以去做别的事情。
```

### 3. 异步的几种实现模式

```
1. 回调（Callback）
   发起操作 → 继续执行 → 操作完成时调用回调函数

2. Promise/Future
   发起操作 → 获得 Future → 继续执行 → 需要时从 Future 获取结果

3. async
   发起操作 → 继续执行 → 需要时等待 Future.get()
```

### 4. C++ 中的异步

```cpp
#include <iostream>
#include <future>
#include <chrono>

int async_compute(int x) {
    std::this_thread::sleep_for(std::chrono::seconds(2));
    return x * x;
}

void callback_example() {
    std::cout << "回调模式：发起请求" << std::endl;
}

int main() {
    // std::async 异步启动任务
    std::future<int> fut = std::async(std::launch::async, async_compute, 42);

    std::cout << "任务已发起，继续做别的事..." << std::endl;
    callback_example();

    // 需要结果时再获取
    int result = fut.get();
    std::cout << "异步结果: " << result << std::endl;

    return 0;
}
```

```cpp
#include <iostream>
#include <future>
#include <thread>

// Promise/Future 模式
void producer(std::promise<int>& prom) {
    std::this_thread::sleep_for(std::chrono::seconds(1));
    prom.set_value(100);
}

int main() {
    std::promise<int> prom;
    std::future<int> fut = prom.get_future();

    std::thread t(producer, std::ref(prom));

    std::cout << "等待结果..." << std::endl;
    int val = fut.get();
    std::cout << "收到: " << val << std::endl;

    t.join();
    return 0;
}
```

## 5. 同步（Synchronous）— 等结果才继续

### 1. 定义

同步是指**发起一个操作后等待其完成才继续执行后续代码**。调用方被阻塞，直到操作返回结果。

### 2. 比喻

**打电话**：

```
你：拨号 → 等待对方接听 → 通话 → 挂断 → 才能做别的事
         ████████████████████████
         整个过程你都被占用，不能做其他事情

关键：对方不接电话你就一直等，什么也干不了。
```

### 3. 同步 = 阻塞

在大多数语境下，同步调用意味着阻塞调用：

```
同步调用流程：
调用方 ──调用──→ 被调用方
       ←──等待──→  执行中...
       ←──返回───  完成
调用方继续执行

异步调用流程：
调用方 ──调用──→ 被调用方
       继续执行    执行中...
       ←──通知───  完成
调用方处理结果
```

### 4. C++ 中的同步

```cpp
#include <iostream>
#include <thread>
#include <mutex>
#include <condition_variable>

std::mutex mtx;
std::condition_variable cv;
bool ready = false;

void worker() {
    std::unique_lock<std::mutex> lock(mtx);
    cv.wait(lock, [] { return ready; });
    std::cout << "工作线程开始处理" << std::endl;
}

int main() {
    std::thread t(worker);

    {
        std::lock_guard<std::mutex> lock(mtx);
        ready = true;
    }
    cv.notify_one();

    t.join(); // 同步等待线程结束
    std::cout << "主线程继续" << std::endl;
    return 0;
}
```

```cpp
#include <iostream>
#include <thread>

void sync_task() {
    std::cout << "任务开始" << std::endl;
    std::this_thread::sleep_for(std::chrono::seconds(2));
    std::cout << "任务完成" << std::endl;
}

int main() {
    std::thread t(sync_task);
    t.join(); // 同步等待：阻塞直到线程结束
    std::cout << "join 之后才继续" << std::endl;
    return 0;
}
```

## 6. 四者关系矩阵

### 1. 常见误解澄清

| 误解 | 事实 |
|------|------|
| 并发 = 并行 | 并发是逻辑同时，并行是物理同时 |
| 异步 = 多线程 | 异步可以用单线程实现（如事件循环） |
| 同步 = 单线程 | 多线程也可以用同步方式交互（join/mutex） |
| 并行一定比并发快 | 不当的并行反而可能更慢（线程开销、伪共享） |

### 2. ×2 关系矩阵

```
                    ┌─────────────────┬─────────────────┐
                    │     并发         │     并行         │
                    │ （逻辑同时）      │ （物理同时）      │
    ┌───────────────┼─────────────────┼─────────────────┤
    │  异步          │ 单线程事件循环    │ 异步I/O + 线程池  │
    │ （不等结果）    │ Node.js/epoll   │ std::async(par)  │
    │               │ 协程             │ TBB + Future     │
    ├───────────────┼─────────────────┼─────────────────┤
    │  同步          │ 多线程 + mutex   │ OpenMP 并行区域   │
    │ （等结果）      │ join 等待        │ std::execution   │
    │               │ 条件变量等待      │ 并行算法 + 同步    │
    └───────────────┴─────────────────┴─────────────────┘
```

### 3. 组合示例

| 组合 | 含义 | 典型场景 |
|------|------|---------|
| 并发 + 异步 | 交替处理多个任务，不等每个完成 | Node.js 事件循环、协程 |
| 并发 + 同步 | 交替处理多个任务，但需要等待同步点 | 多线程 mutex + join |
| 并行 + 异步 | 多核同时执行，不等结果 | 线程池 + Future |
| 并行 + 同步 | 多核同时执行，需要同步等待 | OpenMP 并行区域、屏障同步 |

## 7. 实际场景对照

### 1. Web 服务器 — 并发处理请求

```
客户端A ──请求──→ ┌──────────────┐
客户端B ──请求──→ │  Web 服务器   │ ──→ 并发处理多个请求
客户端C ──请求──→ │  (epoll/kqueue)│     单线程或少量线程
                 └──────────────┘     交替处理 I/O
```

特点：大量 I/O 等待，用并发 + 异步效率最高。

### 2. 科学计算 — 并行矩阵运算

```
核心1: 矩阵第1~250行  ████████████
核心2: 矩阵第251~500行 ████████████
核心3: 矩阵第501~750行 ████████████
核心4: 矩阵第751~1000行████████████
                         ↓
                   合并结果 → 完成
```

特点：纯计算，用并行 + 同步效率最高。

### 3. UI 应用 — 异步网络请求

```
用户点击按钮 → 发起网络请求 → UI 继续响应用户操作
                                    ↓
                              网络响应到达 → 更新界面

关键：网络请求不能阻塞 UI 线程，必须异步。
```

特点：UI 不能卡顿，网络请求必须异步。

### 4. 文件操作 — 同步读写

```
打开文件 → 读取数据 → 处理数据 → 写入结果 → 关闭文件
          ████████████████████████████████████
          每一步都依赖上一步的结果，必须同步顺序执行
```

特点：步骤间有依赖关系，同步执行逻辑最清晰。

## 8. C++ 代码示例对比

### 1. 并发 vs 并行

```cpp
#include <iostream>
#include <thread>
#include <vector>
#include <algorithm>
#include <execution>
#include <chrono>

void concurrency_example() {
    // 并发：两个线程交替执行（单核也能运行）
    auto task = [](const char* name) {
        for (int i = 0; i < 3; ++i) {
            std::cout << name << " step " << i << std::endl;
        }
    };
    std::thread t1(task, "并发A");
    std::thread t2(task, "并发B");
    t1.join();
    t2.join();
}

void parallelism_example() {
    // 并行：利用多核同时处理数据
    std::vector<int> data(1000000);
    for (int i = 0; i < 1000000; ++i) data[i] = i;

    auto start = std::chrono::high_resolution_clock::now();
    std::sort(std::execution::par, data.begin(), data.end(),
              std::greater<int>());
    auto end = std::chrono::high_resolution_clock::now();

    std::cout << "并行排序耗时: "
              << std::chrono::duration_cast<std::chrono::milliseconds>(
                     end - start).count() << "ms" << std::endl;
}

int main() {
    std::cout << "=== 并发示例 ===" << std::endl;
    concurrency_example();
    std::cout << "=== 并行示例 ===" << std::endl;
    parallelism_example();
    return 0;
}
```

### 2. 异步 vs 同步

```cpp
#include <iostream>
#include <future>
#include <chrono>

int heavy_work() {
    std::this_thread::sleep_for(std::chrono::seconds(2));
    return 42;
}

void sync_example() {
    std::cout << "[同步] 开始调用..." << std::endl;
    int result = heavy_work(); // 阻塞等待2秒
    std::cout << "[同步] 结果: " << result << std::endl;
    std::cout << "[同步] 才能继续" << std::endl;
}

void async_example() {
    std::cout << "[异步] 开始调用..." << std::endl;
    std::future<int> fut = std::async(std::launch::async, heavy_work);
    std::cout << "[异步] 立即继续做别的事" << std::endl;
    std::cout << "[异步] 需要结果时再获取..." << std::endl;
    int result = fut.get(); // 此处才阻塞
    std::cout << "[异步] 结果: " << result << std::endl;
}

int main() {
    std::cout << "=== 同步示例 ===" << std::endl;
    sync_example();
    std::cout << "=== 异步示例 ===" << std::endl;
    async_example();
    return 0;
}
```

### 3. 极简总结

| 概念 | 一句话 | 关键词 |
|------|--------|--------|
| 并发 | 交替处理多个任务 | 逻辑同时、时间片轮转 |
| 并行 | 真正同时执行多个任务 | 物理同时、多核 |
| 异步 | 发起操作后不等结果 | 非阻塞、回调/Future |
| 同步 | 发起操作后等结果才继续 | 阻塞、等待 |

## 1. 什么是[同步和异步](03-并发并行异步同步辨析.md)？

### 1. 通俗理解

想象你去餐厅点餐：

**同步（Synchronous）**：
- 你点完餐后站在柜台前等，直到服务员把餐做好给你
- 在这期间你不能做其他事情，只能等待
- **特点**：阻塞、顺序执行、简单直接

**异步（Asynchronous）**：
- 你点完餐后拿到一个号码牌，回到座位玩手机
- 餐做好了服务员会叫你的号码
- **特点**：非阻塞、并发执行、效率高但复杂

---

## 2. 同步与异步的实现方式

### 1. 同步实现

#### 1. （1）互斥锁（Mutex）

```cpp
#include <mutex>
#include <thread>
#include <iostream>

std::mutex mtx;
int shared_data = 0;

void safe_increment() {
    std::lock_guard<std::mutex> lock(mtx);  // 加锁
    shared_data++;  // 临界区：同一时间只有一个线程能执行
}  // 自动解锁

int main() {
    std::thread t1(safe_increment);
    std::thread t2(safe_increment);
    t1.join();
    t2.join();
    std::cout << "Result: " << shared_data << std::endl;
    return 0;
}
```

**核心**：同一时间只允许一个线程访问共享资源。

#### 2. （2）条件变量（Condition Variable）

```cpp
#include <mutex>
#include <condition_variable>
#include <thread>
#include <iostream>

std::mutex mtx;
std::condition_variable cv;
bool ready = false;

void worker() {
    std::this_thread::sleep_for(std::chrono::seconds(2));
    {
        std::lock_guard<std::mutex> lock(mtx);
        ready = true;
    }
    cv.notify_one();  // 通知等待的线程
}

int main() {
    std::thread t(worker);

    {
        std::unique_lock<std::mutex> lock(mtx);
        cv.wait(lock, []{ return ready; });  // 等待条件满足
    }

    std::cout << "Worker is done!" << std::endl;
    t.join();
    return 0;
}
```

#### 3. （3）原子操作（Atomic）

```cpp
#include <atomic>
#include <thread>
#include <iostream>

std::atomic<int> counter(0);

void increment() {
    for (int i = 0; i < 1000; ++i) {
        counter.fetch_add(1);  // 原子操作，线程安全
    }
}

int main() {
    std::thread t1(increment);
    std::thread t2(increment);
    t1.join();
    t2.join();
    std::cout << "Counter: " << counter.load() << std::endl;  // 2000
    return 0;
}
```

### 2. 异步实现

#### 1. （1）多线程 / 线程池

```cpp
#include <thread>
#include <iostream>
#include <chrono>

void async_task() {
    std::this_thread::sleep_for(std::chrono::seconds(2));
    std::cout << "Async task completed" << std::endl;
}

int main() {
    // 异步执行：主线程不等待
    std::thread t(async_task);
    t.detach();  // 分离线程

    std::cout << "Main thread continues..." << std::endl;
    std::this_thread::sleep_for(std::chrono::seconds(3));  // 等待子线程完成

    return 0;
}
```

#### 2. （2）Future / Promise

```cpp
#include <future>
#include <thread>
#include <iostream>

int compute() {
    std::this_thread::sleep_for(std::chrono::seconds(2));
    return 42;
}

int main() {
    // 异步执行
    std::future<int> fut = std::async(std::launch::async, compute);

    // 主线程可以做其他事情
    std::cout << "Doing other work..." << std::endl;

    // 需要结果时才获取（会阻塞）
    int result = fut.get();
    std::cout << "Result: " << result << std::endl;

    return 0;
}
```

#### 3. （3）回调函数

```cpp
#include <thread>
#include <functional>
#include <iostream>

void async_operation(std::function<void(int)> callback) {
    std::thread t([callback]() {
        std::this_thread::sleep_for(std::chrono::seconds(1));
        callback(100);  // 调用回调传递结果
    });
    t.detach();
}

int main() {
    async_operation([](int result) {
        std::cout << "Callback received: " << result << std::endl;
    });

    std::cout << "Main continues..." << std::endl;
    std::this_thread::sleep_for(std::chrono::seconds(2));

    return 0;
}
```

## 3. 同步与异步的应用场景

### 1. 同步适用场景

| 场景 | 说明 |
|------|------|
| 多线程修改共享变量 | 必须加锁保护，避免数据竞争 |
| 操作文件、数据库 | 需要保证操作顺序和数据一致性 |
| 需要严格执行顺序 | 后续步骤依赖前一步的结果 |
| 简单的任务流程 | 逻辑清晰，不需要复杂并发 |

### 2. 异步适用场景

| 场景 | 说明 |
|------|------|
| 网络请求 | HTTP请求、WebSocket通信 |
| 文件读写 | 大文件IO操作 |
| 耗时计算 | 图像处理、数据分析 |
| UI响应 | 不能卡住用户界面 |
| 高并发服务 | Web服务器、游戏服务器 |

## 4. 技巧与注意事项

### 1. 同步注意事项

#### 1. 锁粒度越小越好

**锁粒度** = 你加锁包住的代码范围、执行时间。

```cpp
// ❌ 错误：锁粒度太大
void bad_example() {
    std::lock_guard<std::mutex> lock(mtx);
    do_network_request();  // 耗时操作不应该在锁内
    complex_computation();  // 耗时操作不应该在锁内
    modify_shared_data();   // 真正需要锁的只有这一句
}

// ✅ 正确：锁粒度最小
void good_example() {
    do_network_request();   // 锁外执行
    complex_computation();  // 锁外执行

    {
        std::lock_guard<std::mutex> lock(mtx);
        modify_shared_data();  // 只锁这一行
    }
}
```

**原因**：
- 减少线程阻塞等待时间
- 提升并发性能
- 降低死锁概率
- 避免把无关业务卡在锁内

#### 2. 避免嵌套锁，防止死锁

```cpp
// ❌ 危险：可能导致死锁
void dangerous() {
    std::lock_guard<std::mutex> lock1(mtx1);
    std::lock_guard<std::mutex> lock2(mtx2);  // 可能死锁
}

// ✅ 安全：使用 std::scoped_lock
void safe() {
    std::scoped_lock lock(mtx1, mtx2);  // 同时加锁，避免死锁
}
```

#### 3. 不要在锁里做耗时操作

```cpp
// ❌ 错误
void bad() {
    std::lock_guard<std::mutex> lock(mtx);
    sleep(10);  // 持有锁10秒，其他线程全部阻塞
}

// ✅ 正确
void good() {
    auto data = prepare_data();  // 锁外准备
    {
        std::lock_guard<std::mutex> lock(mtx);
        save_data(data);  // 锁内只做关键操作
    }
}
```

### 2. 异步注意事项

#### 1. 子线程一般不能直接更新 UI

**原因**：几乎所有 UI 框架（Qt、WinForm、WPF、iOS、Android）都规定 UI 控件不是线程安全的，只允许主线程（UI 线程）操作。

```cpp
// ❌ 错误：子线程直接更新 UI
void worker() {
    label.setText("Done");  // 可能导致崩溃
}

// ✅ 正确：通过信号槽或事件队列通知主线程
void worker() {
    emit signal_done();  // Qt 信号槽机制
}
```

#### 2. 避免过多回调嵌套（回调地狱）

```cpp
// ❌ 错误：回调地狱
async_op1([](result1) {
    async_op2(result1, [](result2) {
        async_op3(result2, [](result3) {
            // ... 无限嵌套
        });
    });
});

// ✅ 正确：使用 async/await 或 future 扁平化
auto r1 = co_await async_op1();
auto r2 = co_await async_op2(r1);
auto r3 = co_await async_op3(r2);
```

#### 3. 异步必须捕获异常

**原因**：主线程 try-catch 抓不到子线程异步里的异常。

```cpp
// ❌ 错误：未捕获异常
void worker() {
    throw std::runtime_error("Error");  // 无人处理，程序崩溃
}

// ✅ 正确：异步内部捕获异常
void worker() {
    try {
        // 异步任务
    } catch (const std::exception& e) {
        std::cerr << "Error: " << e.what() << std::endl;
    }
}
```

#### 4. 异步修改共享数据仍需要同步锁

**误区**：很多人以为用异步、多线程跑，就不用管锁了。

**真相**：异步本质还是多线程并发，多个异步任务同时读写同一个全局变量依然存在竞态条件。

```cpp
// ❌ 错误：异步中未加锁
std::vector<int> shared_data;

void async_task() {
    shared_data.push_back(42);  // 数据竞争！
}

// ✅ 正确：异步中仍需加锁
std::mutex mtx;
std::vector<int> shared_data;

void async_task() {
    std::lock_guard<std::mutex> lock(mtx);
    shared_data.push_back(42);  // 线程安全
}
```

#### 5. 不要无限创建线程，要用线程池

**为什么不能无限 new 线程？**

1. **线程资源昂贵**：每个线程占栈内存、内核 PCB 资源
2. **CPU 上下文切换爆炸**：线程远超 CPU 核心数，大量时间浪费在切换
3. **不可控**：任务多就疯狂建线程，系统卡顿、OOM、程序直接挂掉

```cpp
// ❌ 错误：无限创建线程
for (int i = 0; i < 10000; ++i) {
    std::thread t(task);  // 创建10000个线程，系统崩溃
    t.detach();
}

// ✅ 正确：使用线程池
#include <thread>
#include <vector>

const int MAX_THREADS = 8;
std::vector<std::thread> pool;

for (int i = 0; i < MAX_THREADS; ++i) {
    pool.emplace_back(task);
}
for (auto& t : pool) {
    t.join();
}
```

## 5. 总结

### 3. 同步 vs 异步对比

| 特性 | 同步 | 异步 |
|------|------|------|
| **执行方式** | 顺序执行 | 并发执行 |
| **阻塞** | 阻塞等待 | 非阻塞 |
| **复杂度** | 简单 | 复杂 |
| **性能** | 较低 | 较高 |
| **适用场景** | 简单任务、共享数据保护 | IO密集型、高并发 |

### 4. 核心原则

1. **锁粒度越小越好**：快进快出、少阻塞、高并发、少死锁
2. **异步五条本质**：
   - UI 只能主线程碰
   - 少嵌套，用 async/await
   - 异步必捕异常
   - 共享数据照样要加锁
   - 不裸开线程，统一用线程池

## 5. 极简口诀

```
同步排队等结果，异步后台跑任务
锁住共享保安全，粒度越小越高效
异步注意五要点，线程池来管并发
UI更新回主线，异常捕获不能忘
```
