# 线程安全详解
> 📖 相关章节：[线程同步](../../02-CPP/28-线程同步.md)、[多线程基础](../../02-CPP/27-多线程基础.md)

## 1. 什么是线程安全？

**线程安全**（Thread Safety）是指一段代码或数据结构在**多线程环境**下能够正确运行，不会产生数据竞争、死锁或其他并发问题。

### 1. 核心概念

```
线程安全的代码：多个线程同时执行时，结果与单线程执行相同
线程不安全的代码：多个线程同时执行时，可能产生不可预测的结果
```

### 2. 示例对比

```cpp
// 线程不安全的代码
int counter = 0;

void increment() {
    counter++;  // 不是原子操作！
}

// 如果两个线程同时调用 increment()，counter 可能只增加 1
```

```cpp
// 线程安全的代码（使用互斥锁）
#include <mutex>

int counter = 0;
std::mutex mtx;

void safe_increment() {
    std::lock_guard<std::mutex> lock(mtx);  // 加锁
    counter++;  // 临界区
}  // 自动解锁

// 多个线程同时调用时，每次都会正确增加
```

## 2. 什么场景是线程安全的？

### 1. 只读数据

```cpp
// 只读数据是线程安全的
const int value = 42;  // 常量，只读
const std::string name = "test";  // 只读字符串

void read_value() {
    std::cout << value << std::endl;  // 线程安全
}
```

### 2. 局部变量

```cpp
// 函数局部变量是线程安全的（每个线程有独立的栈）
void thread_func() {
    int x = 0;  // 每个线程都有自己的 x
    x++;  // 线程安全
}
```

### 3. 原子操作

```cpp
#include <atomic>

std::atomic<int> counter(0);

void increment() {
    counter.fetch_add(1);  // 原子操作，线程安全
}
```

### 4. 使用同步原语保护的共享数据

```cpp
#include <mutex>
#include <queue>

std::queue<int> q;
std::mutex mtx;

void push(int value) {
    std::lock_guard<std::mutex> lock(mtx);
    q.push(value);  // 线程安全
}

int pop() {
    std::lock_guard<std::mutex> lock(mtx);
    int val = q.front();
    q.pop();
    return val;
}
```

### 5. 无状态函数

```cpp
// 无状态函数：不依赖外部状态，只依赖参数
int add(int a, int b) {
    return a + b;  // 线程安全
}
```

## 3. 常见的线程不安全场景

### 1. 共享可变数据

```cpp
// 线程不安全
int global_var = 0;

void modify() {
    global_var = global_var + 1;  // 读-改-写不是原子的
}
```

### 2. 非原子操作

```cpp
// 线程不安全：i++ 不是原子操作
int i = 0;
i++;  // 等价于: i = i + 1;（读、加、写三个步骤）
```

### 3. 未保护的资源访问

```cpp
// 线程不安全：多个线程同时写入文件
void write_to_file(const std::string& data) {
    std::ofstream file("output.txt", std::ios::app);
    file << data << std::endl;  // 可能产生数据混乱
}
```

### 4. 双重检查锁定（DCL）

```cpp
// 线程不安全的 DCL
Singleton* instance = nullptr;

Singleton* get_instance() {
    if (instance == nullptr) {  // 第一次检查
        std::lock_guard<std::mutex> lock(mtx);
        if (instance == nullptr) {
            instance = new Singleton();  // 可能有问题
        }
    }
    return instance;
}
```

## 4. 线程安全的级别

### 1. 完全线程安全

```cpp
// 所有操作都是线程安全的
class SafeQueue {
    std::mutex mtx;
    std::queue<int> q;
public:
    void push(int val) {
        std::lock_guard<std::mutex> lock(mtx);
        q.push(val);
    }
    
    bool try_pop(int& val) {
        std::lock_guard<std::mutex> lock(mtx);
        if (q.empty()) return false;
        val = q.front();
        q.pop();
        return true;
    }
};
```

### 2. 条件线程安全

```cpp
// 某些操作需要调用者自己加锁
class PartiallySafe {
public:
    void method1() { /* 内部有锁 */ }
    void method2() { /* 内部有锁 */ }
    
    // 复合操作需要外部同步
    void composite_operation() {
        // 需要调用者确保在同一锁保护下调用
        method1();
        method2();
    }
};
```

### 3. 非线程安全

```cpp
// 完全不是线程安全的
class Unsafe {
    int value;
public:
    void set(int v) { value = v; }
    int get() { return value; }
};
```

## 5. 实现线程安全的方法

### 1. 使用互斥锁

```cpp
#include <mutex>

std::mutex mtx;

void safe_operation() {
    std::lock_guard<std::mutex> lock(mtx);
    // 临界区代码
}
```

### 2. 使用原子类型

```cpp
#include <atomic>

std::atomic<int> count(0);
std::atomic<bool> flag(false);
```

### 3. 使用线程局部存储

```cpp
#include <thread>

thread_local int tls_value = 0;  // 每个线程有独立副本

void thread_func() {
    tls_value++;  // 线程安全，不影响其他线程
}
```

### 4. 使用无锁数据结构

```cpp
#include <atomic>

// 无锁栈（简化版）
template<typename T>
class LockFreeStack {
    struct Node {
        T data;
        std::atomic<Node*> next;
    };
    std::atomic<Node*> head;
public:
    void push(T data) {
        Node* new_node = new Node{data};
        new_node->next = head.load();
        while (!head.compare_exchange_weak(new_node->next, new_node)) {}
    }
};
```

## 6. 总结

| 场景 | 是否线程安全 | 原因 |
|------|-------------|------|
| 只读数据 | 是 | 没有写操作 |
| 局部变量 | 是 | 每个线程独立栈空间 |
| 原子操作 | 是 | 不可分割的操作 |
| 共享可变数据 | 否 | 需要同步保护 |
| 非原子操作 | 否 | 可能被中断 |
| 无状态函数 | 是 | 不依赖外部状态 |

**核心原则：**
- 共享可变状态是线程不安全的根源
- 使用同步机制（互斥锁、原子操作）保护共享数据
- 尽量减少共享状态，使用线程局部存储

---

## 6. 极简口诀

```
线程安全要牢记，共享可变是问题
只读数据最安全，局部变量各独立
原子操作不可拆，互斥锁来保临界
减少共享多使用，线程局部最省心
```
