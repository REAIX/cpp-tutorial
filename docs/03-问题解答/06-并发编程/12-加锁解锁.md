# 加锁解锁实战指南
> 📖 相关章节：[多线程基础](../../02-CPP/29-多线程基础.md)、[线程同步](../../02-CPP/30-线程同步.md)、[原子操作](../../02-CPP/31-原子操作与异步编程.md)、[无锁编程](../../02-CPP/33-无锁编程.md)

### 1. 一句话铁律

**哪段代码不能同时被多个线程跑，就把锁包在哪段代码身上。**

***

### 2. 标准固定模板

```c
static pthread_mutex_t mtx = PTHREAD_MUTEX_INITIALIZER;

void* worker(void* arg) {
    pthread_mutex_lock(&mtx);      // 加锁：进门

    // 【临界区】这段同一时刻只能一个线程进
    // 比如：改全局变量、单例判空、读写共享数据

    pthread_mutex_unlock(&mtx);    // 解锁：出门
    return NULL;
}
```

**核心逻辑**：`lock` 进门口，`unlock` 出门口，中间包住的就是**独享区域**。

#### 1. 模板的三要素

| 要素 | 代码 | 含义 |
| --- | --- | --- |
| 锁对象 | `static pthread_mutex_t mtx` | 全局唯一的"门锁" |
| 加锁 | `pthread_mutex_lock(&mtx)` | 关门，别人进不来 |
| 解锁 | `pthread_mutex_unlock(&mtx)` | 开门，下一个人可以进 |

***

### 3. 单例加锁示例

#### 1. 不安全裸写

```c
if (!inst) {
    inst = malloc(sizeof(Singleton));
}
```

**问题**：两个线程同时判断 `!inst` 都为真，都去 malloc，创建出两个实例。

#### 2. 加锁保护后

```c
pthread_mutex_lock(&mtx);
if (!inst) {
    inst = malloc(sizeof(Singleton));
}
pthread_mutex_unlock(&mtx);
```

**效果**：同一时间**只有一个线程能进到 if 里面**，其他线程在 `lock` 那里**排队等着**。

#### 3. 完整单例模式

```c
typedef struct {
    int counter;
    char name[64];
} Singleton;

static Singleton* instance = NULL;
static pthread_mutex_t singleton_mutex = PTHREAD_MUTEX_INITIALIZER;

Singleton* singleton_get_instance(void) {
    pthread_mutex_lock(&singleton_mutex);

    if (instance == NULL) {
        instance = malloc(sizeof(Singleton));
        instance->counter = 0;
        memset(instance->name, 0, sizeof(instance->name));
    }

    pthread_mutex_unlock(&singleton_mutex);
    return instance;
}

void singleton_destroy(void) {
    pthread_mutex_lock(&singleton_mutex);
    free(instance);
    instance = NULL;
    pthread_mutex_unlock(&singleton_mutex);
}
```

### 4. 通俗比喻

把 `lock` 当成**进单人卫生间关门**，把 `unlock` 当成**上完厕所开门出来**：

- 线程A 先 `lock` -> 进去关门
- 线程B 也走到 `lock` -> **进不去，原地排队休眠**
- A 执行完中间代码 -> `unlock` 开门
- 内核唤醒一个排队线程，进去执行

**锁只保护中间那一小块代码**，不锁整个线程函数。

#### 1. 更形象的比喻

| 概念 | 比喻 |
| --- | --- |
| 互斥锁 | 单人卫生间的门锁 |
| 加锁 | 进门反锁 |
| 解锁 | 出门开锁 |
| 临界区 | 卫生间内部 |
| 等待的线程 | 门口排队的人 |
| 死锁 | 门锁坏了，里面出不来，外面进不去 |

### 5. 三条核心规矩

#### 1. 规矩1：只锁「共享数据读写」那一小截

不要把整个 worker 函数全锁了，那变成**串行**，多线程毫无意义。

```c
// 差：整个函数都锁了，等于单线程
void* worker(void* arg) {
    pthread_mutex_lock(&mtx);
    int result = heavy_computation();  // 不需要锁
    shared_data = result;              // 只有这行需要锁
    save_to_disk(shared_data);         // 不需要锁
    pthread_mutex_unlock(&mtx);
}

// 好：只锁必要的操作
void* worker(void* arg) {
    int result = heavy_computation();
    pthread_mutex_lock(&mtx);
    shared_data = result;              // 只锁这一行
    pthread_mutex_unlock(&mtx);
    save_to_disk(shared_data);
}
```

#### 2. 规矩2：lock 之后必须配对 unlock

中途千万别随便 `return`，不然**死锁**，所有线程卡死排队。

```c
// 危险：中途 return 导致锁未释放
void* worker(void* arg) {
    pthread_mutex_lock(&mtx);

    if (error) {
        return NULL;  // 死锁！锁没释放
    }

    shared_data = new_value;
    pthread_mutex_unlock(&mtx);
    return NULL;
}

// 安全：用 goto 确保所有路径都解锁
void* worker(void* arg) {
    pthread_mutex_lock(&mtx);

    if (error) {
        goto cleanup;
    }

    shared_data = new_value;

cleanup:
    pthread_mutex_unlock(&mtx);
    return NULL;
}
```

#### 3. 规矩3：所有线程必须用同一把锁

线程A用锁1，线程B用锁2 -> **等于没锁**，照样竞争乱套。

```c
// 错误：两把不同的锁
pthread_mutex_t mtx1 = PTHREAD_MUTEX_INITIALIZER;
pthread_mutex_t mtx2 = PTHREAD_MUTEX_INITIALIZER;

void* thread_a(void* arg) {
    pthread_mutex_lock(&mtx1);  // 用锁1
    shared_data++;
    pthread_mutex_unlock(&mtx1);
}

void* thread_b(void* arg) {
    pthread_mutex_lock(&mtx2);  // 用锁2，和锁1无关！
    shared_data++;
    pthread_mutex_unlock(&mtx2);
}

// 正确：同一把锁
static pthread_mutex_t shared_mtx = PTHREAD_MUTEX_INITIALIZER;

void* thread_a(void* arg) {
    pthread_mutex_lock(&shared_mtx);  // 同一把锁
    shared_data++;
    pthread_mutex_unlock(&shared_mtx);
}

void* thread_b(void* arg) {
    pthread_mutex_lock(&shared_mtx);  // 同一把锁
    shared_data++;
    pthread_mutex_unlock(&shared_mtx);
}
```

### 6. 完整可运行例子

```c
#include <stdio.h>
#include <pthread.h>

static int count = 0;
static pthread_mutex_t mtx = PTHREAD_MUTEX_INITIALIZER;

void* worker(void* arg) {
    for (int i = 0; i < 100000; i++) {
        pthread_mutex_lock(&mtx);
        count++;
        pthread_mutex_unlock(&mtx);
    }
    return NULL;
}

int main() {
    pthread_t t1, t2;
    pthread_create(&t1, NULL, worker, NULL);
    pthread_create(&t2, NULL, worker, NULL);

    pthread_join(t1, NULL);
    pthread_join(t2, NULL);

    printf("count = %d\n", count);
    return 0;
}
```

- 不加锁：`count` 结果乱掉
- 加锁后：结果永远正确

### 7. 死锁预防

#### 1. 什么是死锁？

两个或多个线程互相等待对方释放锁，导致所有线程永久阻塞。

#### 2. 死锁的四个必要条件

| 条件 | 含义 | 破坏方法 |
| --- | --- | --- |
| 互斥 | 锁只能被一个线程持有 | 无法破坏（锁的本质） |
| 持有并等待 | 持有一把锁，同时等另一把 | 一次性获取所有锁 |
| 不可抢占 | 不能强行夺走别人持有的锁 | 设置超时（pthread_mutex_timedlock） |
| 循环等待 | A等B，B等A | 按固定顺序加锁 |

#### 3. 死锁的典型场景

```c
// 线程A：先锁1再锁2
pthread_mutex_lock(&mtx1);
pthread_mutex_lock(&mtx2);  // 等待mtx2
// ...

// 线程B：先锁2再锁1
pthread_mutex_lock(&mtx2);
pthread_mutex_lock(&mtx1);  // 等待mtx1
// ...
// A等B释放mtx2，B等A释放mtx1 -> 死锁！
```

#### 4. 预防死锁的方法

**方法1：固定加锁顺序（最常用）**

```c
// 所有线程都按 mtx1 -> mtx2 的顺序加锁
void* thread_a(void* arg) {
    pthread_mutex_lock(&mtx1);   // 先锁1
    pthread_mutex_lock(&mtx2);   // 再锁2
    // 临界区
    pthread_mutex_unlock(&mtx2);
    pthread_mutex_unlock(&mtx1);
}

void* thread_b(void* arg) {
    pthread_mutex_lock(&mtx1);   // 也先锁1
    pthread_mutex_lock(&mtx2);   // 也再锁2
    // 临界区
    pthread_mutex_unlock(&mtx2);
    pthread_mutex_unlock(&mtx1);
}
```

**方法2：一次性获取所有锁**

```c
// 用一个全局锁保护多把锁的获取
static pthread_mutex_t global_lock = PTHREAD_MUTEX_INITIALIZER;

void acquire_both() {
    pthread_mutex_lock(&global_lock);
    pthread_mutex_lock(&mtx1);
    pthread_mutex_lock(&mtx2);
    pthread_mutex_unlock(&global_lock);
}

void release_both() {
    pthread_mutex_unlock(&mtx2);
    pthread_mutex_unlock(&mtx1);
}
```

**方法3：使用 trylock 避免阻塞**

```c
void* worker(void* arg) {
    pthread_mutex_lock(&mtx1);

    // 尝试获取第二把锁，失败则释放第一把锁重试
    while (pthread_mutex_trylock(&mtx2) != 0) {
        pthread_mutex_unlock(&mtx1);
        usleep(1000);  // 短暂等待
        pthread_mutex_lock(&mtx1);
    }

    // 两把锁都拿到了
    // 临界区...

    pthread_mutex_unlock(&mtx2);
    pthread_mutex_unlock(&mtx1);
    return NULL;
}
```

### 8. 锁粒度控制

#### 1. 什么是锁粒度？

锁粒度 = 临界区的大小。临界区越大，锁粒度越粗；临界区越小，锁粒度越细。

#### 2. 粗粒度 vs 细粒度

| 维度 | 粗粒度（锁大段代码） | 细粒度（锁小段代码） |
| --- | --- | --- |
| 安全性 | 高（不容易遗漏） | 需要仔细分析 |
| 性能 | 低（并发度低） | 高（并发度高） |
| 复杂度 | 简单 | 复杂 |
| 死锁风险 | 低 | 稍高（多把锁） |

#### 3. 锁粒度优化示例

```c
// 场景：银行转账，从账户A扣钱，给账户B加钱

// 方案1：粗粒度（一把全局锁）
static pthread_mutex_t bank_mutex = PTHREAD_MUTEX_INITIALIZER;

void transfer(Account* from, Account* to, int amount) {
    pthread_mutex_lock(&bank_mutex);
    from->balance -= amount;   // 所有转账串行
    to->balance += amount;
    pthread_mutex_unlock(&bank_mutex);
}

// 方案2：细粒度（每个账户一把锁）
void transfer_fine(Account* from, Account* to, int amount) {
    // 按地址顺序加锁，避免死锁
    if (from < to) {
        pthread_mutex_lock(&from->mutex);
        pthread_mutex_lock(&to->mutex);
    } else {
        pthread_mutex_lock(&to->mutex);
        pthread_mutex_lock(&from->mutex);
    }

    from->balance -= amount;   // 不同账户的转账可以并行
    to->balance += amount;

    pthread_mutex_unlock(&from->mutex);
    pthread_mutex_unlock(&to->mutex);
}
```

#### 4. 锁粒度选择原则

1. **先粗后细**：先保证正确性，再优化性能
2. **只锁共享数据读写**：计算、I/O 不需要锁
3. **读多写少用读写锁**：`pthread_rwlock_t` 允许多个线程同时读
4. **独立数据用独立锁**：不同数据用不同锁，提高并发度

### 9. 读写锁：读多写少的优化

当读操作远多于写操作时，用读写锁替代互斥锁可以大幅提升性能。

```c
#include <stdio.h>
#include <pthread.h>

static int shared_data = 0;
static pthread_rwlock_t rwlock = PTHREAD_RWLOCK_INITIALIZER;

// 读线程：多个可以同时读
void* reader(void* arg) {
    for (int i = 0; i < 100000; i++) {
        pthread_rwlock_rdlock(&rwlock);    // 读锁
        int val = shared_data;              // 只读
        pthread_rwlock_unlock(&rwlock);
    }
    return NULL;
}

// 写线程：独占写入
void* writer(void* arg) {
    for (int i = 0; i < 10000; i++) {
        pthread_rwlock_wrlock(&rwlock);    // 写锁
        shared_data++;                      // 写入
        pthread_rwlock_unlock(&rwlock);
    }
    return NULL;
}

int main() {
    pthread_t readers[3], writer_thread;

    for (int i = 0; i < 3; i++) {
        pthread_create(&readers[i], NULL, reader, NULL);
    }
    pthread_create(&writer_thread, NULL, writer, NULL);

    for (int i = 0; i < 3; i++) {
        pthread_join(readers[i], NULL);
    }
    pthread_join(writer_thread, NULL);

    printf("shared_data = %d\n", shared_data);
    return 0;
}
```

#### 1. 互斥锁 vs 读写锁对比

| 维度 | 互斥锁 | 读写锁 |
| --- | --- | --- |
| 同时读 | 不允许 | 允许 |
| 同时写 | 不允许 | 不允许 |
| 读写同时 | 不允许 | 不允许 |
| 适用场景 | 读写均衡 | 读多写少 |
| 实现复杂度 | 简单 | 较复杂 |

### 10. 常见陷阱与最佳实践

#### 1. 常见陷阱汇总

| 陷阱 | 后果 | 修复 |
| --- | --- | --- |
| 临界区内 return | 死锁 | 用 goto 确保解锁 |
| 不同线程用不同锁 | 等于没锁 | 共享数据用同一把锁 |
| 锁粒度过大 | 串行化，性能差 | 只锁必要的代码 |
| 嵌套加锁顺序不一致 | 死锁 | 固定加锁顺序 |
| 忘记初始化锁 | 未定义行为 | 用 PTHREAD_MUTEX_INITIALIZER |
| 重复加锁（普通锁） | 死锁 | 用递归锁或重构代码 |

#### 2. 最佳实践

1. **最小化临界区**：只锁共享数据读写的代码
2. **lock/unlock 严格配对**：像 malloc/free 一样
3. **多把锁按固定顺序获取**：避免死锁
4. **优先用静态初始化**：`PTHREAD_MUTEX_INITIALIZER`
5. **读多写少用读写锁**：提升并发度
6. **调试时用检错锁**：帮助发现重复加锁

***

### 11. 极简总结

1. **哪里有共享数据竞争，就在哪里上下包 `lock / unlock`**
2. `lock` 进临界区，`unlock` 出临界区
3. 只包必要的一小段，不要全包整个线程
4. 所有线程必须用**同一把锁**才生效
5. 多把锁按**固定顺序**获取，避免死锁
6. 临界区内**不要 return**，用 goto 确保解锁
