# 锁的粒度与性能
> 📖 相关章节：[多线程基础](../../02-CPP/29-多线程基础.md)、[线程同步](../../02-CPP/30-线程同步.md)、[原子操作](../../02-CPP/31-原子操作与异步编程.md)、[无锁编程](../../02-CPP/33-无锁编程.md)

> "粗锁=整栋楼只有一个大门钥匙（安全但排队），细锁=每个房间独立钥匙（并发但管理复杂）。"

***

### 1. 核心定义

**锁粒度（Lock Granularity）** = 被锁保护的代码范围大小。

- **粗锁（Coarse-grained Lock）**：锁保护的范围大，多段代码共用一把锁
- **细锁（Fine-grained Lock）**：锁保护的范围小，不同数据用不同锁

核心矛盾：**粗锁安全但并发低，细锁并发高但易出错**。

***

### 2. 生活类比

**整栋楼 vs 每个房间**：

| 比喻 | 粗锁 | 细锁 |
|------|------|------|
| 钥匙 | 整栋楼只有一个大门钥匙 | 每个房间独立钥匙 |
| 进出 | 所有人在大门排队 | 各进各的房间 |
| 安全 | 简单，不会走错房间 | 复杂，可能拿错钥匙 |
| 效率 | 排队久，一次只能进一人 | 并行进出，效率高 |
| 风险 | 低（只有一把钥匙） | 高（可能死锁：A 拿了1号等2号，B 拿了2号等1号） |

***

### 3. 粗锁 vs 细锁的权衡

| 维度 | 粗锁 | 细锁 |
|------|------|------|
| 临界区大小 | 大 | 小 |
| 并发度 | 低（串行化） | 高（并行） |
| 代码复杂度 | 简单 | 复杂 |
| 死锁风险 | 低（一把锁不会死锁） | 高（多把锁可能循环等待） |
| 调试难度 | 低 | 高 |
| 性能瓶颈 | 容易出现 | 不容易出现 |
| 适用场景 | 竞争少、简单场景 | 竞争激烈、高性能场景 |

***

### 4. 同一场景的粗锁和细锁实现对比

#### 1. 场景：银行账户系统，支持查询余额和转账

#### 2. 粗锁实现：一把全局锁

```cpp
#include <iostream>
#include <thread>
#include <mutex>
#include <vector>
#include <chrono>

struct Account {
    int id;
    int balance;
};

class BankSystem {
    std::vector<Account> accounts_;
    std::mutex global_mutex_;

public:
    BankSystem(int n) : accounts_(n) {
        for (int i = 0; i < n; ++i) {
            accounts_[i] = {i, 1000};
        }
    }

    int get_balance(int id) {
        std::lock_guard<std::mutex> lock(global_mutex_);
        return accounts_[id].balance;
    }

    void transfer(int from, int to, int amount) {
        std::lock_guard<std::mutex> lock(global_mutex_);
        if (accounts_[from].balance >= amount) {
            accounts_[from].balance -= amount;
            accounts_[to].balance += amount;
        }
    }

    int total_balance() {
        std::lock_guard<std::mutex> lock(global_mutex_);
        int sum = 0;
        for (auto& acc : accounts_) {
            sum += acc.balance;
        }
        return sum;
    }
};

int main() {
    BankSystem bank(10);

    auto start = std::chrono::high_resolution_clock::now();

    std::vector<std::thread> threads;
    for (int i = 0; i < 8; ++i) {
        threads.emplace_back([&bank, i]() {
            for (int j = 0; j < 100000; ++j) {
                int from = i % 10;
                int to = (i + 1) % 10;
                bank.transfer(from, to, 1);
            }
        });
    }

    for (auto& t : threads) {
        t.join();
    }

    auto end = std::chrono::high_resolution_clock::now();
    auto ms = std::chrono::duration_cast<std::chrono::milliseconds>(end - start).count();

    std::cout << "Total balance: " << bank.total_balance() << std::endl;
    std::cout << "Time (coarse lock): " << ms << "ms" << std::endl;
    return 0;
}
```

**问题**：所有转账操作串行执行，8 个线程实际只能一个一个跑，等于单线程。

#### 3. 细锁实现：每个账户一把锁

```cpp
#include <iostream>
#include <thread>
#include <mutex>
#include <vector>
#include <chrono>

struct Account {
    int id;
    int balance;
    std::mutex mtx;
};

class BankSystem {
    std::vector<Account> accounts_;

public:
    BankSystem(int n) : accounts_(n) {
        for (int i = 0; i < n; ++i) {
            accounts_[i].id = i;
            accounts_[i].balance = 1000;
        }
    }

    int get_balance(int id) {
        std::lock_guard<std::mutex> lock(accounts_[id].mtx);
        return accounts_[id].balance;
    }

    void transfer(int from, int to, int amount) {
        if (from == to) return;

        if (from < to) {
            std::lock_guard<std::mutex> lock1(accounts_[from].mtx);
            std::lock_guard<std::mutex> lock2(accounts_[to].mtx);
            do_transfer(from, to, amount);
        } else {
            std::lock_guard<std::mutex> lock1(accounts_[to].mtx);
            std::lock_guard<std::mutex> lock2(accounts_[from].mtx);
            do_transfer(from, to, amount);
        }
    }

    int total_balance() {
        int sum = 0;
        for (auto& acc : accounts_) {
            std::lock_guard<std::mutex> lock(acc.mtx);
            sum += acc.balance;
        }
        return sum;
    }

private:
    void do_transfer(int from, int to, int amount) {
        if (accounts_[from].balance >= amount) {
            accounts_[from].balance -= amount;
            accounts_[to].balance += amount;
        }
    }
};

int main() {
    BankSystem bank(10);

    auto start = std::chrono::high_resolution_clock::now();

    std::vector<std::thread> threads;
    for (int i = 0; i < 8; ++i) {
        threads.emplace_back([&bank, i]() {
            for (int j = 0; j < 100000; ++j) {
                int from = i % 10;
                int to = (i + 1) % 10;
                bank.transfer(from, to, 1);
            }
        });
    }

    for (auto& t : threads) {
        t.join();
    }

    auto end = std::chrono::high_resolution_clock::now();
    auto ms = std::chrono::duration_cast<std::chrono::milliseconds>(end - start).count();

    std::cout << "Total balance: " << bank.total_balance() << std::endl;
    std::cout << "Time (fine lock): " << ms << "ms" << std::endl;
    return 0;
}
```

**改进**：
- 不同账户之间的转账可以并行
- 按账户 ID 顺序加锁，避免死锁
- 典型性能提升：2~5 倍（取决于竞争程度）

#### 4. 性能对比

| 版本 | 并发度 | 死锁风险 | 代码复杂度 | 典型性能 |
|------|:---:|:---:|:---:|:---:|
| 粗锁（全局锁） | 低 | 无 | 简单 | 基准 |
| 细锁（每账户锁） | 高 | 需防死锁 | 较复杂 | 2~5x 提升 |

### 5. 锁粒度选择策略

#### 1. 策略1：先粗后细

```
第一步：用粗锁保证正确性
第二步：性能测试，找到瓶颈
第三步：只对瓶颈处细化锁
```

过早优化是万恶之源。先用粗锁跑通，确认有性能问题再细化。

#### 2. 策略2：只锁共享数据读写

```cpp
void worker() {
    int result = heavy_computation();

    std::lock_guard<std::mutex> lock(mtx);
    shared_data = result;

    save_to_disk(shared_data);
}
```

计算和 I/O 不需要锁，只有 `shared_data = result` 这一行需要。

#### 3. 策略3：读多写少用读写锁

```cpp
#include <shared_mutex>
#include <thread>
#include <vector>
#include <iostream>

class Cache {
    mutable std::shared_mutex rw_mtx_;
    std::vector<std::string> data_;

public:
    std::string get(int index) const {
        std::shared_lock<std::shared_mutex> lock(rw_mtx_);
        return data_.at(index);
    }

    void set(int index, const std::string& value) {
        std::unique_lock<std::shared_mutex> lock(rw_mtx_);
        data_.at(index) = value;
    }
};
```

- 多个读者可以同时持有 `shared_lock`
- 写者需要 `unique_lock`，独占访问

#### 4. 策略4：独立数据用独立锁

```cpp
class Stats {
    std::mutex request_mtx_;
    int request_count_ = 0;

    std::mutex error_mtx_;
    int error_count_ = 0;

public:
    void record_request() {
        std::lock_guard<std::mutex> lock(request_mtx_);
        ++request_count_;
    }

    void record_error() {
        std::lock_guard<std::mutex> lock(error_mtx_);
        ++error_count_;
    }
};
```

`request_count_` 和 `error_count_` 互不相关，用两把锁，互不阻塞。

#### 5. 策略5：用 std::scoped_lock 同时获取多把锁

```cpp
#include <mutex>

struct Account {
    int balance;
    std::mutex mtx;
};

void transfer(Account& from, Account& to, int amount) {
    std::scoped_lock lock(from.mtx, to.mtx);
    if (from.balance >= amount) {
        from.balance -= amount;
        to.balance += amount;
    }
}
```

`std::scoped_lock`（C++17）自动按无死锁顺序获取多把锁，避免手动排序的麻烦。

### 6. 常见错误

#### 1. 错误1：锁粒度过细导致死锁

```cpp
std::mutex mtx_a, mtx_b;

void thread1() {
    std::lock_guard<std::mutex> lock1(mtx_a);
    std::lock_guard<std::mutex> lock2(mtx_b);
}

void thread2() {
    std::lock_guard<std::mutex> lock1(mtx_b);
    std::lock_guard<std::mutex> lock2(mtx_a);
}
```

**修复**：统一加锁顺序，或使用 `std::scoped_lock`。

#### 2. 错误2：锁粒度过粗导致性能瓶颈

```cpp
class WebServer {
    std::mutex global_mtx_;
    std::map<std::string, std::string> cache_;
    std::vector<std::string> logs_;
    int request_count_ = 0;

public:
    void handle_request(const std::string& url) {
        std::lock_guard<std::mutex> lock(global_mtx_);
        auto it = cache_.find(url);
        if (it != cache_.end()) {
            logs_.push_back("hit: " + url);
        } else {
            logs_.push_back("miss: " + url);
        }
        ++request_count_;
    }
};
```

**问题**：缓存查询、日志记录、请求计数全用一把锁，所有请求串行。

**修复**：拆分为三把锁：

```cpp
class WebServer {
    std::shared_mutex cache_mtx_;
    std::mutex logs_mtx_;
    std::mutex count_mtx_;
    std::map<std::string, std::string> cache_;
    std::vector<std::string> logs_;
    int request_count_ = 0;

public:
    void handle_request(const std::string& url) {
        {
            std::shared_lock<std::shared_mutex> lock(cache_mtx_);
            auto it = cache_.find(url);
        }
        {
            std::lock_guard<std::mutex> lock(logs_mtx_);
            logs_.push_back("request: " + url);
        }
        {
            std::lock_guard<std::mutex> lock(count_mtx_);
            ++request_count_;
        }
    }
};
```

#### 3. 错误3：临界区内做耗时操作

```cpp
void process() {
    std::lock_guard<std::mutex> lock(mtx);
    auto data = fetch_from_database();
    result = compute(data);
    write_to_disk(result);
}
```

**问题**：数据库查询和磁盘写入都在锁内，其他线程白白等待。

**修复**：只在必要时持锁：

```cpp
void process() {
    auto data = fetch_from_database();
    auto result = compute(data);
    {
        std::lock_guard<std::mutex> lock(mtx);
        shared_result = result;
    }
    write_to_disk(result);
}
```

#### 4. 错误4：忘记保护所有访问路径

```cpp
class Counter {
    std::mutex mtx_;
    int count_ = 0;

public:
    void increment() {
        std::lock_guard<std::mutex> lock(mtx_);
        ++count_;
    }

    int get() {
        return count_;
    }
};
```

**问题**：`get()` 没加锁，可能读到正在修改中的值。

**修复**：所有访问路径都要加锁，或用 `std::atomic<int>`。

### 8. 极简总结

**锁粒度 = 安全与性能的平衡，先粗后细，只锁必要代码。**

| 要点 | 说明 |
|------|------|
| 粗锁 | 一把锁包所有，安全但慢 |
| 细锁 | 多把锁各管各，快但易死锁 |
| 策略 | 先粗后细，测量后优化 |
| 禁忌 | 临界区内做 I/O、忘记保护所有路径 |
| 一句话 | 锁越细越快，也越容易出错；先保证正确，再追求性能 |
