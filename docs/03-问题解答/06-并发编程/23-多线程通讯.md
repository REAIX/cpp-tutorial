## 1. 什么是多线程通讯？

想象一下：你（主线程）让你的朋友（子线程）去帮你买一杯奶茶。

- **同步通讯**：你站在原地等朋友回来，拿到奶茶后才继续做其他事
- **异步通讯**：你让朋友去买奶茶，自己继续看电视，朋友买回来后通知你

多线程通讯就是主线程和子线程之间传递数据和信息的方式。

## 2. 主线程如何获取子线程的数据？

### 1. 方法1：共享笔记（共享变量 + 互斥锁）

**场景**：你和朋友共用一个笔记本，你让朋友把奶茶的价格写在上面。

```cpp
#include <iostream>
#include <thread>
#include <mutex>

// 共享的笔记本（需要加锁保护）
std::mutex notebook_lock;  // 笔记本的锁
std::string shared_note;   // 共享的笔记内容

// 子线程（朋友）：去买奶茶，把价格写在笔记本上
void buy_milk_tea() {
    std::cout << "朋友：出发去买奶茶..." << std::endl;

    // 模拟买奶茶需要2秒
    std::this_thread::sleep_for(std::chrono::seconds(2));

    // 拿到奶茶后，写在共享笔记本上
    {
        // 先上锁
        std::lock_guard<std::mutex> lock(notebook_lock);
        shared_note = "奶茶价格：15元";
        std::cout << "朋友：已经把价格写在笔记本上了" << std::endl;
    }
    // 自动解锁
}

int main() {
    std::cout << "我：让朋友去买奶茶" << std::endl;

    // 创建子线程（让朋友去买奶茶）
    std::thread friend_thread(buy_milk_tea);

    // 等待朋友回来（阻塞等待）
    friend_thread.join();

    // 读取笔记本上的价格
    {
        std::lock_guard<std::mutex> lock(notebook_lock);
        std::cout << "我：看到笔记本上写着：" << shared_note << std::endl;
    }

    return 0;
}
```

**关键点**：
- 互斥锁保证同一时间只有一个线程访问共享数据
- 就像只有一把钥匙，谁拿到谁用
- 避免两个线程同时修改数据导致混乱

### 2. 方法2：快递传递（消息队列）

**场景**：工人把做好的产品放到快递站，你需要时去取。

```cpp
#include <thread>
#include <mutex>
#include <queue>
#include <condition_variable>
#include <iostream>

std::queue<int> message_queue;  // 快递站（消息队列）
std::mutex mtx;                 // 快递站钥匙
std::condition_variable cv;     // 快递到站通知铃
bool done = false;              // 下班标志

void producer() {
    for (int i = 0; i < 5; ++i) {
        {
            std::lock_guard<std::mutex> lock(mtx);  // 打开快递站门
            message_queue.push(i);                   // 放包裹进去
            std::cout << "Produced: " << i << std::endl;
        }
        cv.notify_one();  // 按门铃通知有新快递
        std::this_thread::sleep_for(std::chrono::milliseconds(100));
    }
    {
        std::lock_guard<std::mutex> lock(mtx);
        done = true;  // 告诉消费者下班了
    }
    cv.notify_one();
}

void consumer() {
    while (true) {
        std::unique_lock<std::mutex> lock(mtx);
        // 等着门铃响，或者下班了
        cv.wait(lock, []{ return !message_queue.empty() || done; });

        // 取走所有包裹
        while (!message_queue.empty()) {
            int data = message_queue.front();
            message_queue.pop();
            std::cout << "Consumed: " << data << std::endl;
        }

        if (done) break;  // 下班就回家
    }
}

int main() {
    std::thread t1(producer);
    std::thread t2(consumer);
    t1.join();
    t2.join();
    return 0;
}
```

**关键点**：
- 条件变量像门铃，有消息时通知等待的线程
- 消费者不用一直轮询，没消息时可以睡觉（wait）
- 比共享内存更解耦，生产者和消费者不用直接打交道

### 3. 方法3：预约送货（std::future）

**场景**：你跟工人说："做好后送到我办公室"，然后你继续做自己的事。

```cpp
#include <thread>
#include <future>
#include <iostream>

int compute() {
    // 模拟耗时计算
    std::this_thread::sleep_for(std::chrono::seconds(2));
    return 42;
}

int main() {
    // 创建 future，异步执行 compute
    std::future<int> fut = std::async(std::launch::async, compute);

    // 主线程可以做其他事情，不会阻塞
    std::cout << "Main thread doing other work..." << std::endl;

    // 获取子线程的结果（会阻塞直到结果可用）
    int result = fut.get();
    std::cout << "Result from thread: " << result << std::endl;

    return 0;
}
```

**关键点**：
- `std::future` 像是一个预约单，承诺未来会给结果
- 主线程可以继续工作，需要结果时才调用 `get()` 获取
- 这是最推荐的多线程通讯方式之一

### 4. 方法4：装电话（回调函数）

**场景**：你给工人装个电话，告诉他："做完了打电话给我"。

```cpp
#include <thread>
#include <functional>
#include <iostream>

void worker(std::function<void(const std::string&)> callback) {
    std::this_thread::sleep_for(std::chrono::seconds(1));
    callback("Hello from callback!");  // 调用回调传递数据
}

int main() {
    // 定义回调函数
    auto callback = [](const std::string& msg) {
        std::cout << "Callback received: " << msg << std::endl;
    };

    std::thread t(worker, callback);
    t.detach();  // 分离线程

    // 主线程继续执行
    std::cout << "Main continues..." << std::endl;
    std::this_thread::sleep_for(std::chrono::seconds(2));

    return 0;
}
```

**关键点**：
- 回调函数是事件驱动的通讯方式
- 子线程完成时主动通知主线程
- 注意 `detach()` 后需要确保程序不提前退出

## 3. 常见通讯方式对比

| 方式 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| **共享内存** | 简单直接 | 需要同步，易出错 | 简单数据共享 |
| **消息队列** | 解耦性好 | 有一定开销 | 生产者-消费者模式 |
| **std::future** | 异步获取结果 | 获取时会阻塞 | 需要获取计算结果 |
| **回调函数** | 事件驱动 | 代码较复杂 | 异步通知场景 |
| **条件变量** | 高效等待 | 需要配合 mutex | 等待特定条件 |

---

## 4. 总结

### 1. 主线程获取子线程数据的方法：

1. **共享变量 + 互斥锁**：简单直接，但需要手动同步
2. **消息队列**：解耦性好，适合生产者-消费者模式
3. **std::future**：异步执行，获取结果时阻塞
4. **回调函数**：子线程完成时主动通知主线程

### 2. 核心原则：

- 尽量使用高层抽象（`std::future`、`std::async`）而非手动管理线程
- 避免共享可变状态，使用消息传递
- 合理选择同步机制，避免死锁和数据竞争

---

## 4. 极简口诀

```
线程通讯有多种，共享内存最常用
future异步拿结果，回调函数来通知

想要主线不阻塞，detach异步都可以
```
