# 协程与线程的区别
> 📖 相关章节：[多线程基础](../../02-CPP/27-多线程基础.md)、[线程同步](../../02-CPP/28-线程同步.md)、[原子操作](../../02-CPP/29-原子操作与异步编程.md)、[无锁编程](../../02-CPP/33-无锁编程.md)

> "多个厨师各自占一个灶台，还是一个厨师在多个灶台间切换"——线程是系统分配资源的并发单元，协程是用户自己调度的轻量级并发。

***

### 1. 核心定义

- **线程（Thread）** = 内核态的并发执行单元，由操作系统调度，抢占式切换，每个线程有独立的栈和上下文
- **协程（Coroutine）** = 用户态的轻量级并发，协作式调度，由程序自己决定何时挂起和恢复，共享线程的栈

关键点：**线程是操作系统调度的，协程是程序员调度的；线程被抢占，协程主动让出**。

***

### 2. 生活类比

**厨房做菜**：

| 概念 | 类比 | 对应代码 |
|------|------|---------|
| 线程 | 多个厨师，每人占一个灶台，各做各的菜 | 多个线程，各有独立栈，由 OS 调度 |
| 协程 | 一个厨师在多个灶台间切换，炖汤等待时去切菜 | 一个线程内多个协程，等待时主动让出 CPU |

**线程模型**：

```
厨师A（线程1）: 灶台1 → 炒菜 → 等待 → 炒菜 → ...
厨师B（线程2）: 灶台2 → 炒菜 → 等待 → 炒菜 → ...
厨师C（线程3）: 灶台3 → 炒菜 → 等待 → 炒菜 → ...

问题：3 个厨师 = 3 份工资（内存开销大）
      厨师等待时灶台空闲（阻塞浪费资源）
```

**协程模型**：

```
厨师（线程）: 灶台1 炖汤 → 汤要炖30分钟 → 切换到灶台2 切菜
           → 切完菜 → 切换到灶台3 炒饭 → 饭要焖5分钟
           → 切换回灶台1 看汤 → 还没好 → 切换到灶台2 ...

优势：1 个厨师 = 1 份工资（内存开销小）
      厨师不停歇，等待时去做别的（非阻塞利用资源）
```

**关键区别**：

- 线程切换：厨师正在炒菜，经理（OS）强行让他停下来换另一个厨师 → 抢占式
- 协程切换：厨师自己觉得"汤要炖一会儿，我先去切菜" → 协作式

### 3. 调度方式对比

#### 1. 抢占式调度（线程）

```
时间线：
线程A: ████░░░░████░░░░████
线程B: ░░░░████░░░░████░░░░
              ↑ OS 强制切换

特点：
- 操作系统决定何时切换
- 线程无法控制切换时机
- 切换开销大（保存/恢复完整上下文）
- 可能出现在任何代码点
```

#### 2. 协作式调度（协程）

```
时间线：
协程1: ████......████......████
协程2: ....████......████......
              ↑ 协程主动让出

特点：
- 协程自己决定何时让出（co_await / co_yield）
- 只在明确指定的点切换
- 切换开销小（只保存少量寄存器）
- 切换点可预测，更容易推理
```

#### 3. 代码示例：线程 vs 协程的切换

```cpp
// 线程：OS 决定何时切换，你无法控制
#include <iostream>
#include <thread>

void task_a() {
    for (int i = 0; i < 5; ++i) {
        std::cout << "A:" << i << " ";
    }
}

void task_b() {
    for (int i = 0; i < 5; ++i) {
        std::cout << "B:" << i << " ";
    }
}

int main() {
    std::thread ta(task_a);
    std::thread tb(task_b);
    ta.join();
    tb.join();
}
// 输出顺序不可预测：A:0 A:1 B:0 A:2 B:1 ...
// OS 随时可能切换
```

```cpp
// 协程：程序员决定何时让出（C++20 概念示例）
#include <iostream>
#include <coroutine>

struct Generator {
    struct promise_type {
        int current_value;
        auto yield_value(int value) {
            current_value = value;
            return std::suspend_always{};
        }
        Generator get_return_object() {
            return Generator{std::coroutine_handle<promise_type>::from_promise(*this)};
        }
        auto initial_suspend() { return std::suspend_always{}; }
        auto final_suspend() noexcept { return std::suspend_always{}; }
        void return_void() {}
        void unhandled_exception() { throw; }
    };
    std::coroutine_handle<promise_type> handle;
    bool next() { handle.resume(); return !handle.done(); }
    int value() { return handle.promise().current_value; }
    ~Generator() { if (handle) handle.destroy(); }
};

Generator counter() {
    for (int i = 0; i < 5; ++i) {
        co_yield i;  // 主动让出，返回 i
    }
}

int main() {
    auto gen = counter();
    while (gen.next()) {
        std::cout << gen.value() << " ";
    }
}
// 输出始终是：0 1 2 3 4
// 切换点完全由 co_yield 决定
```

### 4. 内存开销对比

| 维度 | 线程 | 协程 |
|------|------|------|
| 栈大小 | 1~8 MB（OS 默认） | 几十~几百字节（按需分配） |
| 上下文大小 | 几十~几百 KB（完整寄存器集） | 几十个字节（少量寄存器） |
| 创建开销 | 系统调用，较重 | 用户态分配，极轻 |
| 切换开销 | 陷入内核，保存/恢复完整上下文 | 用户态，保存/恢复少量寄存器 |
| 可创建数量 | 几千~几万（受内存限制） | 几十万~几百万（甚至上亿） |

**直观对比**：

```
1 GB 内存可创建：
- 线程（1MB 栈）：约 1000 个
- 协程（1KB 栈）：约 1,000,000 个

差距：1000 倍
```

#### 1. 代码示例：创建开销对比

```cpp
#include <iostream>
#include <thread>
#include <vector>

// 线程：创建 1000 个线程
void test_threads() {
    std::vector<std::thread> threads;
    for (int i = 0; i < 1000; ++i) {
        threads.emplace_back([] {
            std::this_thread::sleep_for(std::chrono::seconds(1));
        });
    }
    for (auto& t : threads) {
        t.join();
    }
}

// 协程：创建 100000 个协程（概念示例）
// 实际 C++20 协程需要框架支持，这里展示原理
// 真实场景使用 asio/llvm/libunifex 等库
```

### 5. 适用场景

#### 1. 线程适合的场景

| 场景 | 原因 |
|------|------|
| CPU 密集型计算 | 多核并行，充分利用硬件 |
| 需要真正并行执行 | 线程可同时运行在多个 CPU 核心上 |
| 计算密集型任务 | 不需要频繁等待，抢占式调度无碍 |
| 系统级并发 | 文件 I/O、网络 I/O 的系统调用 |

#### 2. 协程适合的场景

| 场景 | 原因 |
|------|------|
| I/O 密集型任务 | 大量等待时间，协程可在等待时做其他事 |
| 高并发连接 | 每个连接一个协程，内存开销极小 |
| 异步编程 | 用同步的写法写异步代码，更易读 |
| 状态机 | 天然适合实现状态机（每次 co_yield 是一个状态） |
| 生产者-消费者 | co_yield 天然匹配生产消费模型 |

#### 3. 组合使用

```
最佳实践：线程 + 协程

线程池（少量线程，匹配 CPU 核心数）
  └── 每个线程运行大量协程
       ├── 协程A: 等待网络 I/O → 让出
       ├── 协程B: 等待数据库 → 让出
       ├── 协程C: 处理完成 → 继续
       └── ...

线程负责并行（利用多核）
协程负责并发（管理大量 I/O 任务）
```

### 6. C++20 协程基础概念

C++20 引入了协程的语言支持，但标准库只提供了最基础的框架：

| 组件 | 说明 | C++20 是否提供 |
|------|------|:---:|
| `co_await` | 挂起协程，等待某个操作完成 | 语言关键字 |
| `co_yield` | 挂起协程，返回一个值 | 语言关键字 |
| `co_return` | 从协程返回 | 语言关键字 |
| `promise_type` | 协程的承诺类型，控制协程行为 | 需用户定义 |
| `coroutine_handle` | 协程句柄，用于恢复/销毁协程 | 标准库提供 |
| `suspend_always` | 总是挂起 | 标准库提供 |
| `suspend_never` | 从不挂起 | 标准库提供 |
| 任务类型（Task） | 类似 Python 的 async def | **不提供**，需第三方库 |
| 生成器（Generator） | 类似 Python 的 yield | **不提供**，需自己实现或用库 |

**C++20 协程的"半成品"状态**：

```
C++20 提供了：协程的"发动机"（语言机制）
C++20 缺少了：协程的"方向盘和车身"（实用抽象）

需要第三方库来补全：
- cppcoro（C++ 协程库，原作者 Lewis Baker）
- asio（C++23 已纳入 std::execution）
- folly/coro（Facebook 的协程库）
```

#### 1. 最简协程示例

```cpp
#include <iostream>
#include <coroutine>

struct Task {
    struct promise_type {
        Task get_return_object() {
            return Task{std::coroutine_handle<promise_type>::from_promise(*this)};
        }
        auto initial_suspend() { return std::suspend_never{}; }
        auto final_suspend() noexcept { return std::suspend_always{}; }
        void return_void() {}
        void unhandled_exception() { throw; }
    };
    std::coroutine_handle<promise_type> handle;
    ~Task() { if (handle && !handle.done()) handle.destroy(); }
};

Task hello_coroutine() {
    std::cout << "Hello ";
    co_await std::suspend_always{};
    std::cout << "Coroutine!\n";
}

int main() {
    auto task = hello_coroutine();
    std::cout << "(suspended)\n";
    task.handle.resume();
}
```

**输出**：

```
Hello
(suspended)
Coroutine!
```

### 7. 对比表格

| 维度 | 线程 | 协程 |
|------|:---:|:---:|
| 调度方式 | 抢占式（OS 决定） | 协作式（程序员决定） |
| 调度位置 | 内核态 | 用户态 |
| 栈大小 | 1~8 MB | 几十~几百字节 |
| 切换开销 | 大（内核态切换） | 极小（用户态切换） |
| 并发量 | 几千~几万 | 几十万~几百万 |
| 并行能力 | 真正并行（多核） | 并发但不并行（单线程内） |
| 数据同步 | 需要锁/原子操作 | 通常不需要（单线程内顺序执行） |
| 适用场景 | CPU 密集型 | I/O 密集型 |
| C++ 版本 | C++11（std::thread） | C++20（语言支持，库不完整） |
| 调试难度 | 较高（竞态条件） | 较低（切换点可预测） |
| 编程模型 | 复杂（锁、条件变量） | 简单（同步写法写异步） |

***

### 8. 极简总结

**线程是 OS 调度的重型并发，协程是用户调度的轻型并发**

| 要点 | 说明 |
|------|------|
| 核心区别 | 线程抢占式（OS 控制），协程协作式（程序员控制） |
| 内存开销 | 线程 MB 级，协程 KB 级以下，差距 1000 倍 |
| 并发 vs 并行 | 协程是并发（交替执行），线程是并行（同时执行） |
| 适用场景 | CPU 密集用线程，I/O 密集用协程 |
| C++ 支持 | 线程 C++11 完整，协程 C++20 语言支持但库不完整 |
| 一句话 | 线程是多个厨师各占灶台，协程是一个厨师在灶台间切换 |
