# C语言标准库分类与使用指南
> 📖 相关章节：[字符串处理](../../01-C语言/07-字符串处理.md)、[内存管理](../../01-C语言/09-内存管理.md)、[文件操作](../../01-C语言/15-文件操作.md)

## 1. 通俗理解

标准库就是"编程超市"，不同分类就像不同货架区——生鲜区（数学）、日用品区（字符串）、工具区（工具函数）。知道货架在哪，才能快速找到需要的东西。

你不会在生鲜区买洗发水，也不会在日用品区买鱼。同理，做数学运算找 `<math.h>`，处理字符串找 `<string.h>`，分配内存找 `<stdlib.h>`。搞清楚分类，编程效率翻倍。

## 4. 库函数使用的基本套路

### 1. 套路1：包含头文件 → 调用函数 → 检查返回值

```c
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    FILE *fp = fopen("test.txt", "r");
    if (fp == NULL) {
        perror("fopen failed");
        return EXIT_FAILURE;
    }

    // ... 使用fp读写文件 ...

    fclose(fp);
    return EXIT_SUCCESS;
}
```

这是最基本的使用模式：**包含头文件 → 调用函数 → 检查返回值**。几乎所有C标准库函数都遵循这个套路。

### 2. 套路2：检查errno获取错误信息

```c
#include <stdio.h>
#include <errno.h>
#include <string.h>

int main(void) {
    FILE *fp = fopen("nonexistent.txt", "r");
    if (fp == NULL) {
        printf("错误码: %d\n", errno);
        printf("错误信息: %s\n", strerror(errno));
        perror("fopen");
        return 1;
    }
    fclose(fp);
    return 0;
}
```

`errno` 是全局变量，函数出错时会设置它。配合 `strerror()` 可以把错误码转成可读的字符串。

### 3. 套路3：用perror快速输出错误

```c
#include <stdio.h>

int main(void) {
    if (remove("nonexistent.txt") != 0) {
        perror("remove failed");
        // 输出: remove failed: No such file or directory
    }
    return 0;
}
```

`perror()` 是最简单的错误输出方式，自动把 `errno` 对应的信息拼接到你给的提示文字后面。

## 6. 常见陷阱与最佳实践

### 1. 陷阱1：忘记包含头文件

```c
// 错误：没包含<string.h>，编译器可能隐式声明
char *p = strcpy(dest, src);  // 警告：implicit declaration

// 正确：
#include <string.h>
```

忘记包含头文件时，编译器会假设函数返回 `int`，这可能导致截断或未定义行为。编译时加 `-Wall` 可以捕获这类警告。

### 2. 陷阱2：不检查返回值

```c
// 错误：fopen可能返回NULL
FILE *fp = fopen("file.txt", "r");
fgetc(fp);  // 如果fp是NULL，段错误！

// 正确：
FILE *fp = fopen("file.txt", "r");
if (fp == NULL) {
    perror("fopen");
    return 1;
}
```

**永远不要假设函数调用一定成功**。特别是I/O函数和内存分配函数，返回值检查是必须的。

### 3. 陷阱3：混淆string.h和strings.h

| 头文件 | 说明 |
|--------|------|
| `<string.h>` | C标准，所有平台可用 |
| `<strings.h>` | BSD扩展，仅POSIX系统可用 |

建议：只用 `<string.h>`。如果需要大小写不敏感比较，自己写一个或用 `<ctype.h>` 配合实现。

### 4. 陷阱4：用atoi代替strtol

```c
// 不推荐：atoi无法检测错误
int val = atoi("abc");  // 返回0，但"abc"不是0

// 推荐：strtol可以检测错误
char *endptr;
long val = strtol("abc", &endptr, 10);
if (endptr == "abc") {
    printf("转换失败！\n");
}
```

`atoi` 遇到非法输入时返回0，但你无法区分"输入是0"还是"输入非法"。`strtol` 通过 `endptr` 参数可以精确判断转换是否成功。

### 5. 陷阱5：rand()的随机性不够

```c
// 不推荐：rand()质量差，范围小
int r = rand() % 100;

// 推荐：用更好的随机源（C23的rand_r或系统random）
srandom(time(NULL));
int r = random() % 100;
```

`rand()` 的随机数质量较差，低位可能有明显规律。在安全敏感场景下，应使用系统提供的安全随机源（如 `/dev/urandom` 或 `getrandom()`）。

### 6. 陷阱6：用sprintf而不检查缓冲区

```c
// 危险：可能缓冲区溢出
char buf[10];
sprintf(buf, "%s", very_long_string);

// 安全：指定最大写入长度
char buf[10];
snprintf(buf, sizeof(buf), "%s", very_long_string);
```

### 7. 最佳实践

1. **始终检查返回值** — 特别是I/O函数和内存分配
2. **用snprintf代替sprintf** — 防止缓冲区溢出
3. **用strncpy代替strcpy** — 指定最大长度
4. **用strtol代替atoi** — 可以检测转换错误
5. **用sizeof代替硬编码大小** — `sizeof(buf)` 而不是 `256`
6. **编译时加-Wall** — 编译器会警告遗漏的头文件
7. **free后置NULL** — 防止悬空指针误用
8. **malloc和free成对出现** — 每个malloc必须有对应的free

## 7. 与C++标准库的关系

### 1. C头文件在C++中的对应

| C标准库 | C++中的对应 | 区别 |
|---------|-----------|------|
| `<stdio.h>` | `<cstdio>` | C++版本把函数放入std命名空间 |
| `<stdlib.h>` | `<cstdlib>` | 同上 |
| `<string.h>` | `<cstring>` | 注意：`<cstring>`≠`<string>` |
| `<math.h>` | `<cmath>` | C++版增加了重载函数 |
| `<ctype.h>` | `<cctype>` | 同上 |
| `<assert.h>` | `<cassert>` | 同上 |
| `<time.h>` | `<ctime>` | 同上 |
| `<signal.h>` | `<csignal>` | 同上 |
| `<errno.h>` | `<cerrno>` | 同上 |
| `<stddef.h>` | `<cstddef>` | 同上 |

### 2. C++中使用C库的注意事项

1. **用 `<cstdio>` 而不是 `<stdio.h>`** — 虽然都能用，但C++风格推荐前者
2. **`<cstring>` 是C字符串函数，`<string>` 是C++的std::string** — 不要搞混
3. **优先用C++的替代方案** — iostream替代stdio、string替代cstring、vector替代手动内存管理
4. **C++中可以用C库** — 但要理解两者的差异，不要混用（比如不要 `malloc` 后用 `delete`）

### 3. C库 vs C++替代方案速查

| C库方案 | C++替代 | 优势 |
|--------|--------|------|
| printf/scanf | cout/cin | 类型安全 |
| malloc/free | new/delete | 自动调用构造/析构 |
| char[] + string.h | std::string | 自动内存管理 |
| qsort | std::sort | 类型安全、内联优化 |
| FILE* | fstream | RAII自动关闭 |
| errno | try/catch | 结构化错误处理 |
| assert | static_assert | 编译期检查 |
