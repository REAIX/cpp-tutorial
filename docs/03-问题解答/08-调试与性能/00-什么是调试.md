# 什么是调试
> 📖 相关章节：[调试技巧](../../04-工程实践/07-调试技巧.md)、[性能优化](../../04-工程实践/09-性能优化.md)

> **Debugging is twice as hard as writing the code in the first place.** — 调试比写代码难一倍。

***

### 1. 核心提炼

**调试**（Debugging）= 找到并修复程序中错误的过程。核心方法是：**观察程序的实际行为，找出与期望行为的差异，定位原因，修复验证**。

***

### 2. 生活类比

把调试比作**医生看病**：

- **症状** → 程序崩溃、输出错误、运行缓慢
- **诊断** → 用各种检查手段找出病因
- **治疗** → 修改代码修复问题
- **复查** → 确认修复有效且没有副作用

| 调试方法 | 医学类比 |
|---------|---------|
| print 调试 | 量体温、测血压（简单快速） |
| 断点调试 | CT 扫描（精确深入） |
| 单步执行 | 逐帧慢放（看每一步） |
| 查看变量 | 验血报告（看内部状态） |
| 调用栈 | 转诊记录（怎么走到这一步的） |

### 3. 调试方法分类

| 方法 | 优点 | 缺点 | 适用场景 |
|------|------|------|---------|
| print 调试 | 简单、无需工具 | 需要重新编译、输出多 | 快速定位简单问题 |
| 断点调试 | 精确、可交互 | 需要学习调试器 | 复杂逻辑问题 |
| 日志调试 | 不中断运行 | 日志量大 | 生产环境问题 |
| 静态分析 | 编译前发现问题 | 可能有误报 | 代码质量检查 |
| 动态分析 | 运行时检测 | 有性能开销 | 内存/并发问题 |

### 4. Print 调试（printf debugging）

最简单直接的调试方法：

```cpp
#include <iostream>
#include <vector>

int binary_search(const std::vector<int>& arr, int target) {
    int left = 0, right = arr.size() - 1;

    while (left <= right) {
        int mid = left + (right - left) / 2;
        std::cout << "DEBUG: left=" << left
                  << " right=" << right
                  << " mid=" << mid
                  << " arr[mid]=" << arr[mid] << std::endl;

        if (arr[mid] == target) return mid;
        else if (arr[mid] < target) left = mid + 1;
        else right = mid - 1;
    }
    return -1;
}
```

**技巧**：用宏控制调试输出

```cpp
#include <iostream>

#ifdef DEBUG
#define DBG(x) std::cerr << "[DEBUG] " << x << std::endl
#else
#define DBG(x)
#endif

void process(int value) {
    DBG("process called with value=" << value);
    // ... 业务逻辑
}
```

### 5. 断点调试

断点调试是最强大的调试方式，使用调试器（GDB、LLDB、Visual Studio 等）：

**基本概念**：

| 概念 | 说明 |
|------|------|
| 断点（Breakpoint） | 程序执行到此处暂停 |
| 单步跳过（Step Over） | 执行当前行，不进入函数内部 |
| 单步进入（Step Into） | 进入函数内部 |
| 单步跳出（Step Out） | 执行完当前函数，回到调用处 |
| 继续（Continue） | 继续运行到下一个断点 |
| 观察变量（Watch） | 监视变量值的变化 |
| 调用栈（Call Stack） | 显示函数调用链 |

```cpp
#include <iostream>
#include <vector>

// 示例：调试一个有 bug 的函数
int sum_positive(const std::vector<int>& nums) {
    int total = 0;
    for (size_t i = 0; i <= nums.size(); ++i) {  // Bug: <= 应该是 <
        if (nums[i] > 0) {                        // 越界访问
            total += nums[i];
        }
    }
    return total;
}

int main() {
    std::vector<int> data = {1, -2, 3, -4, 5};
    std::cout << sum_positive(data) << std::endl;
}
```

**调试步骤**：
1. 在 `sum_positive` 函数入口设断点
2. 单步执行，观察 `i` 和 `nums[i]` 的值
3. 当 `i == nums.size()` 时，发现越界访问
4. 修复：`i <= nums.size()` → `i < nums.size()`

### 6. GDB 基本使用

```bash
# 编译时加 -g 保留调试信息
g++ -g -O0 program.cpp -o program

# 启动 GDB
gdb ./program
```

**GDB 常用命令**：

| 命令 | 缩写 | 功能 |
|------|------|------|
| `break main` | `b main` | 在 main 函数设断点 |
| `break file.cpp:10` | `b file.cpp:10` | 在第10行设断点 |
| `run` | `r` | 运行程序 |
| `next` | `n` | 单步跳过 |
| `step` | `s` | 单步进入 |
| `finish` | `fin` | 执行完当前函数 |
| `continue` | `c` | 继续运行 |
| `print var` | `p var` | 打印变量值 |
| `display var` | `disp var` | 每次暂停自动显示变量 |
| `backtrace` | `bt` | 显示调用栈 |
| `info locals` | `i locals` | 显示局部变量 |
| `watch var` | | 监视变量变化 |
| `list` | `l` | 显示源代码 |
| `quit` | `q` | 退出 GDB |

**GDB 调试示例**：

```
(gdb) break main
Breakpoint 1 at 0x1159: file program.cpp, line 15.
(gdb) run
Breakpoint 1, main () at program.cpp:15
15          std::vector<int> data = {1, -2, 3, -4, 5};
(gdb) next
16          std::cout << sum_positive(data) << std::endl;
(gdb) step

6           int total = 0;
(gdb) next

(gdb) print nums.size()
$1 = 5
(gdb) print i

(gdb) watch i

(gdb) continue
```

### 7. Visual Studio 调试

在 Windows 上使用 Visual Studio 调试：

| 操作 | 快捷键 | 功能 |
|------|--------|------|
| 设断点 | F9 | 在当前行设/取消断点 |
| 开始调试 | F5 | 启动调试 |
| 单步跳过 | F10 | Step Over |
| 单步进入 | F11 | Step Into |
| 单步跳出 | Shift+F11 | Step Out |
| 继续 | F5 | 继续运行 |
| 停止调试 | Shift+F5 | 终止调试 |

### 8. 调用栈

调用栈显示函数的调用链，是定位问题来源的关键：

```cpp
#include <iostream>

void level3() {
    std::cout << "在 level3" << std::endl;
    int* p = nullptr;
    *p = 42;  // 崩溃！在这里设断点查看调用栈
}

void level2() { level3(); }
void level1() { level2(); }

int main() { level1(); }
```

**调用栈显示**：

```
#0  level3() at program.cpp:5
#1  level2() at program.cpp:9
#2  level1() at program.cpp:10
#3  main() at program.cpp:12
```

从栈底到栈顶：`main → level1 → level2 → level3`，告诉你"怎么走到这一步的"。

### 9. 条件断点

只在满足条件时暂停，避免反复手动继续：

```bash
# GDB：当 i == 5 时暂停
(gdb) break program.cpp:7 if i == 5

# Visual Studio：右键断点 → Conditions → 输入 i == 5
```

```cpp
// 场景：循环中某个特定值出错
for (int i = 0; i < 10000; ++i) {
    process(data[i]);  // 只在 i == 42 时出错
    // 设条件断点：i == 42，直接跳到出错的那次迭代
}
```

### 10. 调试策略

| 策略 | 说明 |
|------|------|
| 二分法 | 在代码中间设断点，判断问题在前半段还是后半段 |
| 最小复现 | 精简代码到最小可复现示例 |
| 假设验证 | 先假设原因，再验证假设 |
| 回归测试 | 修复后确认没有引入新问题 |
| 版本对比 | 用 git bisect 找到引入 bug 的提交 |

### 11. 极简总结

**调试 = 找到并修复错误 → print 调试简单快速，断点调试精确深入 → GDB/LLDB 命令行调试，Visual Studio 图形化调试 → 断点/单步/变量/调用栈是四大核心操作 → 条件断点跳过无关迭代 → 二分法缩小范围 → 编译时加 -g -O0 保留调试信息**
