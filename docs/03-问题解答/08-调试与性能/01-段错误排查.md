# 段错误排查指南
> 📖 相关章节：[调试技巧](../../04-工程实践/07-调试技巧.md)、[性能优化](../../04-工程实践/09-性能优化.md)

> **"Segmentation fault: accessing what you shouldn't"** — 访问禁区，段错误

***

### 1. 要义概览

**段错误**（Segmentation Fault）= 程序访问了不允许访问的内存地址。五大常见原因：空指针、野指针、越界、栈溢出、重复释放。

***

### 2. 五大常见原因

| 原因 | 示例 | 典型报错 |
|------|------|----------|
| 空指针解引用 | `int* p = nullptr; *p;` | SIGSEGV |
| 野指针 | `int* p; *p;`（未初始化） | SIGSEGV |
| 数组越界 | `arr[100]`（数组只有10） | SIGSEGV 或静默错误 |
| 栈溢出 | 无限递归 | SIGSEGV 或 Stack Overflow |
| 重复释放 | `delete p; delete p;` | SIGABRT 或堆损坏 |

### 3. 排查方法1：GDB（Linux/macOS）

```bash
g++ -g program.cpp -o program
gdb ./program
(gdb) run
# 崩溃后
(gdb) bt        # 查看调用栈
(gdb) frame 0   # 跳到崩溃帧
(gdb) print var # 查看变量值
(gdb) info locals # 查看所有局部变量
```

GDB 常用命令速查：

| 命令 | 作用 |
|------|------|
| `bt` / `backtrace` | 查看调用栈 |
| `frame N` | 切换到第N帧 |
| `print expr` | 打印表达式值 |
| `info locals` | 查看当前帧局部变量 |
| `list` | 查看源代码 |
| `watch var` | 监视变量变化 |
| `break func` | 在函数处设断点 |
| `continue` | 继续执行 |

### 4. 排查方法2：Visual Studio 调试器（Windows）

Windows 上 Visual Studio 是最强大的段错误排查工具：

**基本步骤：**

1. 使用 Debug 模式编译（`/Zi` 调试信息，`/Od` 禁用优化）
2. 按 F5 启动调试
3. 崩溃时自动断点，显示调用栈
4. 查看局部变量、内存、寄存器

**关键窗口：**

| 窗口 | 快捷键 | 作用 |
|------|--------|------|
| 调用堆栈 | Ctrl+Alt+C | 查看函数调用链 |
| 局部变量 | Ctrl+Alt+V, L | 查看当前作用域变量 |
| 监视 | Ctrl+Alt+W, 1 | 监视自定义表达式 |
| 内存 | Ctrl+Alt+M, 1 | 查看原始内存内容 |
| 断点 | Ctrl+Alt+B | 管理所有断点 |

**异常设置：**

调试 → 窗口 → 异常设置，勾选「C++ 异常」和「Win32 异常」，可以在异常抛出时立即断点，而不是等到崩溃。

**数据断点：**

当变量被意外修改时，可以设置数据断点：

1. 调试 → 新建断点 → 新建数据断点
2. 输入变量地址：`&my_variable`
3. 当该内存被写入时自动断点

### 5. 排查方法3：WinDbg（Windows高级调试）

WinDbg 是 Windows 上最强大的内核级调试器，适合排查复杂问题：

```bash
# 基本命令
windbg program.exe

# 崩溃后
!analyze -v           # 自动分析崩溃原因
k                     # 查看调用栈
dv                    # 查看局部变量
!address <addr>       # 查看内存地址信息
!heap -s              # 查看堆摘要
!heap -p -a <addr>    # 查看堆分配详情
```

| 命令 | 作用 |
|------|------|
| `!analyze -v` | 自动分析崩溃，最常用 |
| `k` / `kb` | 查看调用栈 |
| `~*k` | 所有线程的调用栈 |
| `!address addr` | 查看地址属性（可读/可写/已提交） |
| `.ecxr` | 切换到异常上下文 |
| `!heap -p -a addr` | 查看堆块信息 |

### 6. 排查方法4：AddressSanitizer

AddressSanitizer（ASan）能在运行时检测内存错误，精度极高。

**GCC/Clang：**

```bash
g++ -fsanitize=address -g -O1 program.cpp -o program
./program
```

**MSVC（Visual Studio 2019+）：**

```bash
cl /fsanitize=address /Zi program.cpp
```

或在 Visual Studio 中：项目属性 → C/C++ → 常规 → 启用地址擦除器 → 是。

ASan 能检测的错误类型：

| 错误类型 | 检测能力 | 示例 |
|----------|----------|------|
| 堆缓冲区溢出 | ✅ | `arr[10]` 但只分配了5 |
| 栈缓冲区溢出 | ✅ | `local_arr[100]` 越界 |
| 全局缓冲区溢出 | ✅ | 全局数组越界 |
| Use-after-free | ✅ | `delete p; *p;` |
| Double-free | ✅ | `delete p; delete p;` |
| 内存泄漏 | 需配合 LeakSanitizer | 忘记 delete |


### 7. 排查方法5：Core Dump 分析

程序崩溃时可以生成 core dump 文件，事后分析：

**Linux：**

```bash
ulimit -c unlimited           # 允许生成core dump
g++ -g program.cpp -o program
./program                     # 崩溃后生成 core 文件
gdb ./program core
(gdb) bt                      # 查看崩溃时的调用栈
```

**Windows（Minidump）：**

Windows 上通过 `SetUnhandledExceptionFilter` 生成 minidump：

```cpp
#include <windows.h>
#include <dbghelp.h>
#include <iostream>

LONG WINAPI crash_handler(EXCEPTION_POINTERS* info) {
    HANDLE hFile = CreateFileA("crash.dmp", GENERIC_WRITE, 0, nullptr,
                               CREATE_ALWAYS, FILE_ATTRIBUTE_NORMAL, nullptr);
    MINIDUMP_EXCEPTION_INFORMATION mei;
    mei.ThreadId = GetCurrentThreadId();
    mei.ExceptionPointers = info;
    mei.ClientPointers = FALSE;
    MiniDumpWriteDump(GetCurrentProcess(), GetCurrentProcessId(),
                      hFile, MiniDumpNormal, &mei, nullptr, nullptr);
    CloseHandle(hFile);
    return EXCEPTION_EXECUTE_HANDLER;
}

int main() {
    SetUnhandledExceptionFilter(crash_handler);
}
```

### 8. 更多段错误模式

```cpp
#include <vector>
#include <string>

int& return_local_ref() {
    int x = 42;
    return x;  // 悬空引用：x已销毁
}

void iterator_invalidation() {
    std::vector<int> v = {1, 2, 3};
    auto it = v.begin();
    v.push_back(4);  // 可能重新分配内存
    *it;             // 迭代器失效，段错误
}

void string_c_str_expired() {
    const char* p;
    {
        std::string s = "hello";
        p = s.c_str();
    }  // s已销毁
    std::cout << p;  // 访问已释放内存
}

void wrong_delete() {
    int* arr = new int[10];
    delete arr;   // 应该用 delete[] arr;
}

void virtual_call_in_constructor() {
    class Base {
    public:
        Base() { init(); }
        virtual void init() { std::cout << "Base" << std::endl; }
    };

    class Derived : public Base {
    public:
        void init() override { std::cout << "Derived" << std::endl; }
    };

    Derived d;  // 调用Base::init()而非Derived::init()
}
```

| 模式 | 原因 | 预防 |
|------|------|------|
| 返回局部引用 | 引用指向已销毁的栈变量 | 返回值而非引用 |
| 迭代器失效 | 容器重新分配导致迭代器无效 | 操作后重新获取迭代器 |
| c_str()过期 | string销毁后指针悬空 | 先拷贝再使用 |
| delete vs delete[] | 单对象删除用于数组 | 数组用 `delete[]` |
| 构造中调虚函数 | 此时虚表未完成 | 用init()两阶段初始化 |

### 9. 预防编码规范

| 规范 | 说明 |
|------|------|
| 初始化所有指针 | `int* p = nullptr;` 而非 `int* p;` |
| 使用智能指针 | `unique_ptr`/`shared_ptr` 替代裸指针 |
| 使用容器 | `vector`/`string` 替代裸数组和 `char*` |
| 检查指针非空 | 解引用前检查 `if (p != nullptr)` |
| 使用 RAII | 资源在析构函数中释放 |
| 边界检查 | 用 `at()` 替代 `[]` 访问容器 |
| 编译警告 | `-Wall -Wextra -Werror` 或 `/W4 /WX` |
| ASan 测试 | 开发阶段始终开启 ASan |

```cpp
#include <vector>
#include <memory>
#include <iostream>

void safe_code() {
    auto p = std::make_unique<int>(42);
    std::cout << *p << std::endl;

    std::vector<int> v = {1, 2, 3};
    int val = v.at(5);  // 抛出std::out_of_range而非段错误
}

int main() {
    try {
        safe_code();
    } catch (const std::exception& e) {
        std::cerr << "异常: " << e.what() << std::endl;
    }
}
```

### 10. 平台差异速查

| 特性 | Linux | Windows | macOS |
|------|-------|---------|-------|
| 调试器 | GDB/LLDB | Visual Studio/WinDbg | LLDB |
| ASan | GCC/Clang | MSVC 2019+ | Clang |
| Core Dump | `ulimit -c unlimited` | Minidump API | `ulimit -c unlimited` |
| 栈大小 | 8MB（可调） | 1MB（可调） | 8MB（可调） |
| 段错误信号 | SIGSEGV | STATUS_ACCESS_VIOLATION | SIGSEGV |

### 11. 极简总结

**段错误 = 访问非法内存 → GDB/VS看栈 → ASan精确定位 → WinDbg分析dump → 防范：智能指针+容器+RAII+边界检查**
