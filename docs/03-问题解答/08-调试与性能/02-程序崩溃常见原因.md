# 程序崩溃常见原因
> 📖 相关章节：[调试技巧](../../04-工程实践/06-调试技巧.md)、[性能优化](../../04-工程实践/08-性能优化.md)

> "Crashes are just bugs waiting to be found" — 崩溃只是待发现的BUG

### 1. 一句话铁律

**程序崩溃 = 程序遇到了无法处理的错误，操作系统强制终止进程。五大类原因：内存问题、对象生命周期、并发问题、库/系统问题、资源耗尽。**

***

### 2. 崩溃的本质

#### 1. 什么是崩溃

程序在运行过程中，执行了一条**非法操作**，操作系统检测到后向进程发送信号（如 SIGSEGV、SIGABRT），强制终止进程。

#### 2. 崩溃信号一览

| 信号 | 含义 | 典型原因 |
|:----:|------|----------|
| SIGSEGV | 段错误（非法内存访问） | 空指针、野指针、越界 |
| SIGABRT | 程序异常终止 | assert 失败、double free |
| SIGFPE | 浮点异常 | 整数除零、整数溢出 |
| SIGBUS | 总线错误 | 未对齐的内存访问 |
| SIGKILL | 被系统杀死 | OOM killer |
| SIGTERM | 终止信号 | 外部 kill 命令 |

#### 3. 崩溃 ≠ 挂起

| 现象 | 表现 | 原因 |
|:----:|------|------|
| 崩溃 | 程序退出，有信号 | 非法操作 |
| 挂起 | 程序不退出也不响应 | 死锁、无限循环 |
| 数据损坏 | 程序继续运行但数据错误 | 竞态条件、UB |

### 3. 第一大类：内存问题（最常见）

#### 1. 空指针解引用

```cpp
int* p = nullptr;
*p = 42;              // SIGSEGV：访问地址 0

std::string* s = nullptr;
s->size();            // SIGSEGV：通过空指针调用成员函数

int& ref = *(int*)0;  // SIGSEGV：创建空引用
ref = 10;
```

**排查方法**：
- 检查指针是否为空再使用
- 使用 `assert(p != nullptr)`
- AddressSanitizer 精确定位

#### 2. 野指针（悬空指针）

```cpp
int* createValue() {
    int x = 42;
    return &x;    // 返回局部变量地址
}

int* p = createValue();
*p;               // 野指针：x 已销毁，地址无效

int* q = new int(42);
delete q;
*q;               // 野指针：内存已释放

std::vector<int> v = {1, 2, 3};
int* ptr = v.data();
v.push_back(4);   // 可能重新分配
*ptr;             // 野指针：旧内存已释放
```

**排查方法**：
- 用智能指针替代裸指针
- 遵循 RAII 原则
- AddressSanitizer 检测 use-after-free

#### 3. 数组越界

```cpp
int arr[5] = {1, 2, 3, 4, 5};
arr[10] = 99;        // 越界写入，覆盖其他内存

std::vector<int> v = {1, 2, 3};
v[5];                // 越界读取（不抛异常！）
v.at(5);             // 抛出 std::out_of_range

char buf[10];
strcpy(buf, "this string is way too long");  // 缓冲区溢出
```

**排查方法**：
- 使用 `at()` 代替 `[]`
- AddressSanitizer 检测越界
- `std::array` + `at()` 更安全

#### 4. 重复释放（Double Free）

```cpp
int* p = new int(42);
delete p;
delete p;            // double free！堆管理器崩溃

int* q = new int(10);
int* r = q;
delete q;
delete r;            // double free！同一块内存释放两次
```

**排查方法**：
- 用 `unique_ptr` 避免重复释放
- delete 后立即置 `nullptr`
- AddressSanitizer 检测

#### 5. 使用未初始化变量

```cpp
int x;
std::cout << x;      // UB：值不确定

int* p;
*p = 42;             // UB：p 指向随机地址

bool flag;
if (flag) { }        // UB：flag 值不确定
```

**排查方法**：
- 声明时立即初始化
- 编译器警告 `-Wuninitialized`
- Valgrind 检测

### 4. 第二大类：对象生命周期问题

#### 1. 返回局部变量引用/指针

```cpp
std::string& getName() {
    std::string name = "hello";
    return name;      // 悬空引用
}

int* getValue() {
    int x = 42;
    return &x;        // 悬空指针
}
```

#### 2. 析构后使用对象

```cpp
class Widget {
public:
    void doWork() { std::cout << "working" << std::endl; }
};

Widget* w = new Widget();
delete w;
w->doWork();          // use-after-free
```

#### 3. 纯虚函数调用

```cpp
class Base {
public:
    Base() { callVirtual(); }  // 构造函数中调用虚函数
    virtual void callVirtual() = 0;
};

class Derived : public Base {
public:
    void callVirtual() override { std::cout << "Derived" << std::endl; }
};

Derived d;  // 构造时调用 Base() → callVirtual()
// 此时 Derived 部分尚未构造 → 调用的是 Base 版本（纯虚）→ 纯虚函数调用崩溃
```

#### 4. 迭代器失效后使用

```cpp
std::vector<int> v = {1, 2, 3, 4, 5};
auto it = v.begin();
v.erase(it);
*it;                  // 迭代器已失效

v.push_back(6);       // 可能重新分配
*it;                  // 所有迭代器失效
```

### 5. 第三大类：并发问题

#### 1. 数据竞争

```cpp
int counter = 0;

void increment() {
    for (int i = 0; i < 1000000; ++i) {
        counter++;    // 多线程同时修改，无保护
    }
}

std::thread t1(increment);
std::thread t2(increment);
// counter 最终值不确定，可能远小于 2000000
```

#### 2. 死锁

```cpp
std::mutex mtx1, mtx2;

void threadA() {
    std::lock_guard<std::mutex> lk1(mtx1);  // 先锁1
    std::lock_guard<std::mutex> lk2(mtx2);  // 再锁2
}

void threadB() {
    std::lock_guard<std::mutex> lk2(mtx2);  // 先锁2
    std::lock_guard<std::mutex> lk1(mtx1);  // 再锁1
}
// A 等待 B 释放 mtx2，B 等待 A 释放 mtx1 → 死锁
```

**解决方法**：
- 始终按相同顺序加锁
- 使用 `std::lock(mtx1, mtx2)` 同时加锁
- 使用 `std::scoped_lock`（C++17）

#### 3. 竞态导致崩溃

```cpp
std::vector<int> data;

void writer() {
    data.push_back(42);  // 可能重新分配
}

void reader() {
    if (!data.empty()) {
        data[0];          // 如果 writer 正在重新分配 → 崩溃
    }
}
```

### 6. 第四大类：库/系统问题

#### 1. 缺少动态库

```bash
./myapp: error while loading shared libraries: libfoo.so: cannot open shared object file
```

**解决方法**：
- `ldd ./myapp` 查看依赖
- 设置 `LD_LIBRARY_PATH`
- 把库放到 `/usr/local/lib`

#### 2. ABI 不兼容

```cpp
// 用 GCC 5.1 编译的库
// 用 GCC 11 链接
// std::string 的 ABI 变了 → 链接通过但运行时崩溃
```

**解决方法**：
- 库和应用用同一编译器版本
- 使用稳定的 C 接口

#### 3. 断言失败

```cpp
assert(ptr != nullptr);  // Release 模式下 assert 被禁用
// Debug 模式下断言失败 → SIGABRT
```

#### 4. 未捕获异常

```cpp
void foo() {
    throw std::runtime_error("error");
}

int main() {
    foo();  // 未捕获异常 → std::terminate → SIGABRT
}
```

### 7. 第五大类：资源耗尽

#### 1. 内存耗尽

```cpp
std::vector<int> v;
while (true) {
    v.push_back(0);  // 最终 new 抛出 bad_alloc 或被 OOM killer 杀掉
}
```

#### 2. 栈溢出

```cpp
void recurse() {
    int buf[1024];   // 每次占 4KB
    recurse();        // 无限递归 → 栈溢出 → SIGSEGV
}
```

#### 3. 文件描述符耗尽

```cpp
while (true) {
    fopen("test.txt", "r");  // 忘记 fclose → 文件描述符用完
}
```

### 8. 排查工具详解

#### 1. GDB 调试

```bash
# 编译时加调试信息
g++ -g -O0 program.cpp -o program

# 启动 GDB
gdb ./program

# 运行
(gdb) run

# 崩溃后查看调用栈
(gdb) bt
#0  0x0000000000401156 in foo () at program.cpp:15
#1  0x0000000000401178 in main () at program.cpp:22

# 查看具体帧
(gdb) frame 0
(gdb) list
(gdb) print variable_name
(gdb) print *pointer
```

#### 2. AddressSanitizer

```bash
# 编译
g++ -fsanitize=address -g -O0 program.cpp -o program

# 运行
./program

# 输出示例：
# ==12345==ERROR: AddressSanitizer: heap-use-after-free
# READ of size 4 at 0x602000000010 thread T0
#     #0 0x400b86 in main program.cpp:15
#     #1 0x7f... in __libc_start_main
# 0x602000000010 is located 0 bytes inside of 4-byte region [0x602000000010,0x602000000014)
# freed by thread T0 here:
#     #0 0x400a00 in operator delete
#     #1 0x400b70 in main program.cpp:13
```

#### 3. Valgrind

```bash
# 内存泄漏检测
valgrind --leak-check=full --show-leak-kinds=all ./program

# 输出示例：
# ==12345== Invalid read of size 4
# ==12345==    at 0x400B86: main (program.cpp:15)
# ==12345==  Address 0x5205044 is 0 bytes inside a block of size 4 free'd
```

#### 4. UndefinedBehaviorSanitizer

```bash
g++ -fsanitize=undefined -g -O0 program.cpp -o program
./program
# 检测：有符号溢出、空指针、未对齐访问等
```

### 9. 预防措施清单

| 措施 | 工具/方法 | 检测什么 |
|------|----------|----------|
| 编译器警告 | `-Wall -Wextra -Werror` | 未初始化、类型不匹配 |
| 静态分析 | clang-tidy, cppcheck | 潜在bug、代码风格 |
| 内存检测 | AddressSanitizer | 越界、use-after-free、double free |
| 未定义行为 | UBSan | 有符号溢出、空指针、未对齐 |
| 内存泄漏 | Valgrind, Leaks | 内存泄漏、非法读写 |
| 线程检测 | ThreadSanitizer | 数据竞争 |
| 智能指针 | unique_ptr, shared_ptr | 避免手动 delete |
| RAII | 构造/析构绑定资源 | 避免忘记释放 |
| 异常安全 | try/catch | 避免未捕获异常 |

***

### 10. 崩溃排查决策树

```
程序崩溃了
    │
    ├── 有信号信息？
    │   ├── SIGSEGV → 内存问题（空指针/越界/野指针）
    │   ├── SIGABRT → assert/abort/double free/未捕获异常
    │   ├── SIGFPE  → 整数除零
    │   └── SIGBUS  → 未对齐访问
    │
    ├── 没有信号信息？
    │   ├── 用 GDB 重现 → bt 看调用栈
    │   ├── 用 ASan 重现 → 精确定位
    │   └── 用 Valgrind 重现 → 内存问题
    │
    └── 无法重现？
        ├── 可能是并发问题 → ThreadSanitizer
        ├── 可能是时序相关 → 加日志
        └── 可能是特定数据 → 缩小输入范围
```

***

### 11. 极简总结

**崩溃五大类 = 内存问题 + 对象生命周期 + 并发 + 库/系统 + 资源耗尽 → GDB看栈 → ASan定位 → 预防优于排查**
