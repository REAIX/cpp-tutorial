# 什么是内存泄漏及检测方法
> 📖 相关章节：[调试技巧](../../04-工程实践/06-调试技巧.md)、[性能优化](../../04-工程实践/08-性能优化.md)

> 内存泄漏不是"内存消失了"，而是"你丢了钥匙，门还锁着"。

***

### 1. 核心要义

内存泄漏是指程序动态分配的内存因失去所有引用而无法被释放，导致该内存持续占用直至进程结束，严重时可耗尽系统资源引发崩溃。

***

### 2. 内存泄漏的定义与本质

动态内存管理遵循"谁分配，谁释放"原则。当通过 `malloc`/`new` 获得的内存地址不再被任何指针持有，且未调用 `free`/`delete` 时，这块内存便成为"孤儿"——仍然存在，却永远无法回收。

```cpp
void leak_example() {
    int* p = new int(42);
    p = new int(100);
}
```

上面代码中，第一次 `new int(42)` 分配的内存在 `p` 被重新赋值后便再也无法释放，这就是典型的内存泄漏。

从操作系统视角看，泄漏的内存在进程生命周期内始终被标记为"已分配"。进程退出后，操作系统会回收所有资源，因此内存泄漏的影响范围是**进程级别**而非系统级别（但长期运行的服务进程例外）。

| 角度 | 说明 |
|------|------|
| 程序员视角 | 丢失了指向已分配内存的指针 |
| 进程视角 | 堆内存持续增长，无法复用 |
| 系统视角 | 进程占用物理内存/虚拟内存持续增长 |
| 用户视角 | 程序越来越慢，最终可能崩溃 |

***

### 3. 内存泄漏的常见原因

**1. 忘记释放**

```cpp
void forget_delete() {
    int* arr = new int[1000];
}
```

**2. 异常导致跳过 delete**

```cpp
void exception_leak() {
    int* p = new int(42);
    throw std::runtime_error("error");
    delete p;
}
```

`throw` 之后 `delete` 永远不会执行。

**3. 提前返回**

```cpp
int early_return(bool flag) {
    char* buf = new char[1024];
    if (flag) {
        return -1;
    }
    delete[] buf;
    return 0;
}
```

**4. 循环引用（shared_ptr 互指）**

```cpp
struct Node {
    std::shared_ptr<Node> next;
    ~Node() { std::cout << "destroyed\n"; }
};

void circular_ref() {
    auto a = std::make_shared<Node>();
    auto b = std::make_shared<Node>();
    a->next = b;
    b->next = a;
}
```

`a` 和 `b` 的引用计数永远不为 0，两者都无法释放。

**5. 容器中堆积未释放的指针**

```cpp
void container_leak() {
    std::vector<int*> vec;
    for (int i = 0; i < 1000; ++i) {
        vec.push_back(new int(i));
    }
}
```

vector 析构时只释放指针本身，不会 `delete` 指针指向的对象。

### 4. 内存泄漏的分类

| 分类 | 说明 | 严重程度 |
|------|------|----------|
| 一次性泄漏 | 只泄漏一次，如初始化时分配后遗忘 | 低 |
| 渐进式泄漏 | 循环/频繁调用中持续泄漏 | 高 |
| 隐式泄漏 | 缓存/池不断增长但逻辑上不算 bug | 中 |
| 资源泄漏 | 文件描述符、socket、数据库连接未关闭 | 高 |

渐进式泄漏最为危险，尤其在服务端程序中：

```cpp
void handle_request() {
    char* log_buf = new char[4096];
    process(log_buf);
}
```

每次请求泄漏 4KB，日积月累后果严重。

### 5. 检测工具详解

**Valgrind（Linux）**

```bash
Linux:
g++ -g -O0 leak.cpp -o leak
valgrind --leak-check=full --show-leak-kinds=all ./leak
```

输出示例：

```
==12345== HEAP SUMMARY:
==12345==     in use at exit: 4,000 bytes in 1 blocks
==12345==   total heap usage: 2 allocs, 1 frees, 4,004 bytes allocated
==12345==
==12345== 4,000 bytes in 1 blocks are definitely lost in loss record 1 of 1
==12345==    at 0x4C2FB0F: operator new[](unsigned long)
==12345==    by 0x10915E: forget_delete() (leak.cpp:5)
```

**AddressSanitizer（跨平台）**

```bash
Linux/Mac:
g++ -fsanitize=address -g -O0 leak.cpp -o leak
./leak
```

```bash
Windows:
cl /fsanitize=address /Zi leak.cpp
leak.exe
```

ASan 在程序退出时报告泄漏：

```
=================================================================
==12345==ERROR: LeakSanitizer: detected memory leaks

Direct leak of 4000 byte(s) in 1 object(s) allocated from:
    #0 0x4c2fb0f in operator new[](unsigned long)
    #1 0x10915e in forget_delete() leak.cpp:5
```

**Visual Studio CRT 调试堆（Windows）**

```cpp
Windows:
#define _CRTDBG_MAP_ALLOC
#include <stdlib.h>
#include <crtdbg.h>

int main() {
    _CrtSetDbgFlag(_CRTDBG_ALLOC_MEM_DF | _CRTDBG_LEAK_CHECK_DF);
    int* p = new int(42);
    return 0;
}
```

输出：

```

Dumping objects ->
{142} normal block at 0x00A8F3B0, 4 bytes long.
 Data: <    > 2A 00 00 00

```

**Dr. Memory（Windows/Linux）**

```bash
Windows:
drmemory -leak_only -batch -- myapp.exe
```

```bash
Linux:
drmemory -leak_only -- ./myapp
```

| 工具 | 平台 | 开销 | 优势 | 劣势 |
|------|------|------|------|------|
| Valgrind | Linux/Mac | 10-50x | 无需重编译，信息详尽 | 极慢，不支持 Windows |
| ASan | 跨平台 | 2-3x | 速度快，集成度高 | 需重编译 |
| VS CRT | Windows | 极低 | 原生集成，轻量 | 仅限 MSVC |
| Dr. Memory | Win/Linux | 5-10x | 无需重编译 | 不如 Valgrind 详尽 |

### 6. RAII 与智能指针预防泄漏

RAII（Resource Acquisition Is Initialization）是 C++ 防御内存泄漏的核心武器：将资源生命周期绑定到对象生命周期，利用析构函数自动释放。

```cpp
class FileGuard {
    FILE* fp_;
public:
    FileGuard(const char* path, const char* mode)
        : fp_(fopen(path, mode)) {}
    ~FileGuard() { if (fp_) fclose(fp_); }
    FileGuard(const FileGuard&) = delete;
    FileGuard& operator=(const FileGuard&) = delete;
};
```

智能指针是 RAII 在动态内存上的直接应用：

```cpp
#include <memory>

void no_leak() {
    auto p = std::make_unique<int>(42);
    auto arr = std::make_unique<int[]>(1000);
    auto sp = std::make_shared<std::string>("hello");
}
```

三种智能指针的适用场景：

| 智能指针 | 所有权 | 开销 | 适用场景 |
|----------|--------|------|----------|
| `unique_ptr` | 独占 | 极低 | 默认首选，工厂返回 |
| `shared_ptr` | 共享 | 引用计数 | 共享所有权、图结构 |
| `weak_ptr` | 无 | 低 | 打破循环引用、缓存 |

用 `weak_ptr` 打破循环引用：

```cpp
struct Node {
    std::shared_ptr<Node> next;
    std::weak_ptr<Node> prev;
    ~Node() { std::cout << "destroyed\n"; }
};

void no_circular_leak() {
    auto a = std::make_shared<Node>();
    auto b = std::make_shared<Node>();
    a->next = b;
    b->prev = a;
}
```

### 7. 真实泄漏案例与修复

**案例：事件监听器未注销**

```cpp
class EventManager {
    std::vector<Listener*> listeners_;
public:
    void register_listener(Listener* l) {
        listeners_.push_back(l);
    }
};
```

如果 `Listener` 对象被销毁但未从 `EventManager` 注销，将产生悬空指针。正确做法：

```cpp
class EventManager {
    std::unordered_map<int, std::weak_ptr<Listener>> listeners_;
public:
    void register_listener(int id, std::shared_ptr<Listener> l) {
        listeners_[id] = l;
    }
    void notify() {
        for (auto it = listeners_.begin(); it != listeners_.end(); ) {
            if (auto sp = it->second.lock()) {
                sp->on_event();
                ++it;
            } else {
                it = listeners_.erase(it);
            }
        }
    }
};
```

**案例：异常安全缺失**

```cpp
class Widget {
    int* data_;
    char* buf_;
public:
    Widget()
        : data_(new int[100]),
          buf_(new char[1024])
    {}
    ~Widget() { delete[] data_; delete[] buf_; }
};
```

如果 `buf_` 的 `new` 抛出异常，`data_` 已分配但析构函数不会被调用。修复：

```cpp
class Widget {
    std::unique_ptr<int[]> data_;
    std::unique_ptr<char[]> buf_;
public:
    Widget()
        : data_(std::make_unique<int[]>(100)),
          buf_(std::make_unique<char[]>(1024))
    {}
};
```

### 8. 资源泄漏

内存泄漏只是资源泄漏的一种。其他常见资源泄漏：

```cpp
void file_leak() {
    FILE* f = fopen("data.txt", "r");
    if (!f) return;
    if (error_condition) return;
    fclose(f);
}

void fd_leak() {
    int fd = open("data.bin", O_RDONLY);
    if (fd < 0) return;
    if (error_condition) return;
    close(fd);
}
```

通用 RAII 包装器可统一处理所有资源类型：

```cpp
template<typename T, typename Deleter>
class ResourceGuard {
    T resource_;
    Deleter deleter_;
public:
    ResourceGuard(T res, Deleter del)
        : resource_(res), deleter_(del) {}
    ~ResourceGuard() { deleter_(resource_); }
    ResourceGuard(const ResourceGuard&) = delete;
    ResourceGuard& operator=(const ResourceGuard&) = delete;
    T get() const { return resource_; }
};

void safe_file() {
    ResourceGuard<FILE*, decltype(&fclose)> f(fopen("data.txt", "r"), &fclose);
    if (!f.get()) return;
}
```

| 资源类型 | 获取函数 | 释放函数 | 泄漏后果 |
|----------|----------|----------|----------|
| 堆内存 | `new`/`malloc` | `delete`/`free` | 内存增长 |
| 文件描述符 | `open`/`fopen` | `close`/`fclose` | 耗尽 fd |
| socket | `socket()` | `closesocket()` | 耗尽 fd |
| 互斥锁 | `pthread_mutex_lock` | `pthread_mutex_unlock` | 死锁 |
| 数据库连接 | `connect` | `disconnect` | 连接池耗尽 |

### 9. 嵌入式环境下的内存泄漏应对

嵌入式系统通常没有虚拟内存，内存泄漏直接导致 OOM 甚至看门狗复位。

**静态分配替代动态分配：**

```cpp
template<typename T, size_t N>
class StaticPool {
    alignas(T) char storage_[N * sizeof(T)];
    bool used_[N] = {};
public:
    T* allocate() {
        for (size_t i = 0; i < N; ++i) {
            if (!used_[i]) {
                used_[i] = true;
                return reinterpret_cast<T*>(&storage_[i * sizeof(T)]);
            }
        }
        return nullptr;
    }
    void deallocate(T* p) {
        auto offset = reinterpret_cast<char*>(p) - storage_;
        auto idx = offset / sizeof(T);
        if (idx < N) used_[idx] = false;
    }
};
```

**运行时内存监控：**

```cpp
class MemMonitor {
    size_t peak_ = 0;
    size_t current_ = 0;
public:
    void on_alloc(size_t size) {
        current_ += size;
        if (current_ > peak_) peak_ = current_;
    }
    void on_free(size_t size) {
        current_ -= size;
    }
    void report() const {
        std::cout << "Peak: " << peak_
                  << " Current: " << current_ << "\n";
    }
};
```

重载 `new`/`delete` 接入监控：

```cpp
void* operator new(size_t size) {
    void* p = malloc(size);
    g_monitor.on_alloc(size);
    return p;
}

void operator delete(void* p, size_t size) noexcept {
    g_monitor.on_free(size);
    free(p);
}
```

嵌入式环境建议：

| 策略 | 说明 |
|------|------|
| 禁止动态分配 | 编码规范层面禁止 `new`/`malloc` |
| 内存池 | 预分配固定大小池，避免碎片 |
| 运行时监控 | 重载 `new`/`delete` 记录分配情况 |
| 阈值告警 | 内存使用超过阈值时触发告警 |
| 看门狗 | 内存异常时主动复位 |

### 10. 平台差异与工具选择指南

| 维度 | Linux | Windows |
|------|-------|---------|
| 首选工具 | Valgrind / ASan | VS CRT / ASan |
| 编译器支持 | GCC/Clang 均支持 ASan | MSVC 2019+ 支持 ASan |
| 系统级监控 | `/proc/PID/status` | 任务管理器 / Process Explorer |
| 信号辅助 | `SIGUSR1` 触发堆快照 | `SetUnhandledExceptionFilter` |
| 命令行检查 | `valgrind --leak-check=full` | `_CrtDumpMemoryLeaks()` |

**跨平台推荐方案：**

```cpp
#if defined(_MSC_VER)
    #define _CRTDBG_MAP_ALLOC
    #include <crtdbg.h>
    #define INIT_LEAK_CHECK() \
        _CrtSetDbgFlag(_CRTDBG_ALLOC_MEM_DF | _CRTDBG_LEAK_CHECK_DF)
#else
    #define INIT_LEAK_CHECK() ((void)0)
#endif

int main() {
    INIT_LEAK_CHECK();
}
```

编译时启用 ASan 是跨平台最通用的方案：

```bash
Linux:
g++ -fsanitize=address -g -O0 -fno-omit-frame-pointer main.cpp

Windows:
cl /fsanitize=address /Zi /Od main.cpp
```

### 11. 极简总结

| 要点 | 内容 |
|------|------|
| 定义 | 动态分配的内存失去所有引用，无法释放 |
| 根因 | 忘记释放、异常跳过、循环引用、容器堆积 |
| 分类 | 一次性 / 渐进式 / 隐式 / 资源泄漏 |
| 检测 | Valgrind(Linux)、ASan(跨平台)、VS CRT(Windows)、Dr.Memory |
| 预防 | RAII、智能指针、weak_ptr 打破循环 |
| 嵌入式 | 静态分配、内存池、运行时监控、阈值告警 |
| 核心原则 | 资源获取即初始化，析构即释放 |

关键记忆口诀：**new 必 delete，指针归 RAII，shared 防循环，检测靠工具**。
