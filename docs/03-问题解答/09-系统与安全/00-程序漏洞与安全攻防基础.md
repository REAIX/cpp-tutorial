# 程序漏洞与安全攻防基础
> 📖 相关章节：[内存管理](../../01-C语言/09-内存管理.md)、[字符串处理](../../01-C语言/07-字符串处理.md)

> "漏洞=房子墙上的裂缝，后门=建筑师故意留的暗门，溢出=往杯子里倒水倒满了还继续倒。"——理解漏洞类型和攻防原理，是写出安全代码的第一步。

***

### 1. 核心定义

- **漏洞（Vulnerability）** = 程序中的缺陷，可被攻击者利用来执行非预期操作
- **后门（Backdoor）** = 故意留在程序中的隐蔽入口，绕过正常认证
- **溢出攻击（Overflow Attack）** = 向缓冲区写入超出容量的数据，覆盖相邻内存
- **0day漏洞** = 尚未被公开或修补的漏洞，攻击者先于厂商知道
- **提权（Privilege Escalation）** = 从低权限提升到高权限（如普通用户→root）

| 概念 | 一句话定义 | 危害等级 |
|------|-----------|---------|
| 漏洞 | 可被利用的缺陷 | 高——可能导致系统被完全控制 |
| 后门 | 故意留的暗门 | 极高——绕过所有安全机制 |
| 溢出攻击 | 写超缓冲区覆盖相邻内存 | 高——可执行任意代码 |
| 0day漏洞 | 未公开未修补的漏洞 | 极高——无补丁可用 |
| 提权 | 低权限升到高权限 | 高——扩大攻击面 |

***

### 2. 生活类比

| 概念 | 类比 | 说明 |
|------|------|------|
| 漏洞 | 房子墙上的裂缝 | 小偷可以钻进来——程序中的缺陷可被攻击者利用 |
| 后门 | 建筑师故意留的暗门 | 只有他知道——程序作者故意留的隐蔽入口 |
| 溢出攻击 | 往杯子里倒水倒满了还继续倒 | 水流到桌子上，覆盖相邻区域——数据溢出覆盖相邻内存 |
| 0day | 还没人发现的新裂缝 | 连房主都不知道——厂商尚未知晓或修补的漏洞 |
| 提权 | 小偷从窗户进来后找到了保险柜钥匙 | 从有限权限升级到更高权限 |

**具体场景**：

- **漏洞**：你的程序用`gets()`读取输入，攻击者输入超长字符串，覆盖了返回地址——就像墙上有个裂缝，小偷顺着裂缝钻进来了。
- **后门**：程序员在登录函数里写了一个万能密码`"master123"`——就像建筑师在蓝图里藏了一扇暗门。
- **溢出攻击**：你往一个8字节的数组里写了100字节，多出来的92字节覆盖了栈上的返回地址——就像往杯子里倒水倒满了还继续倒，水漫到桌子上。
- **0day**：攻击者发现了一个新漏洞，厂商还不知道，没有补丁——就像房子有个新裂缝，连房主都不知道。
- **提权**：攻击者通过Web漏洞进入服务器，只有`www-data`权限，然后利用内核漏洞获得root——就像小偷从窗户进来后，找到了保险柜钥匙。

### 3. 漏洞分类详解

#### 1. 缓冲区溢出（Buffer Overflow）

**栈溢出**：向栈上数组写入超长数据，覆盖返回地址。

```c
#include <stdio.h>
#include <string.h>

void vulnerable(void) {
    char buf[16];
    gets(buf);
}

void safe(void) {
    char buf[16];
    fgets(buf, sizeof(buf), stdin);
}

int main(void) {
    vulnerable();
    return 0;
}
```

**堆溢出**：向堆上缓冲区写入超长数据，覆盖堆元数据。

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

void heap_overflow(void) {
    char* p1 = malloc(32);
    char* p2 = malloc(32);
    strcpy(p1, "this string is way too long for 32 bytes and will overflow into p2's metadata");
    free(p2);
    free(p1);
}

void safe_heap(void) {
    char* p1 = malloc(32);
    if (!p1) return;
    strncpy(p1, "hello", 31);
    p1[31] = '\0';
    free(p1);
    p1 = NULL;
}
```

**C/C++防护**：

| 防护措施 | 命令/方法 | 原理 |
|---------|----------|------|
| 安全函数 | `strncpy`/`snprintf` | 限制写入长度 |
| 栈保护 | `-fstack-protector-strong` | 函数入口放canary，返回前检查 |
| ASLR | `-fPIE -pie` | 地址空间随机化，攻击者无法预测地址 |
| DEP/NX | 操作系统级 | 标记栈/堆不可执行，阻止代码注入 |

#### 2. 格式化字符串漏洞

**原理**：`printf(user_input)` 让用户控制格式串，可读取栈数据或写入任意地址。

```c
#include <stdio.h>

void vulnerable(const char* user_input) {
    printf(user_input);
}

void safe(const char* user_input) {
    printf("%s", user_input);
}

int main(void) {
    vulnerable("%x %x %x %x");
    return 0;
}
```

| 格式符 | 危险 | 说明 |
|--------|------|------|
| `%x` | 读取栈上十六进制值 | 可泄露地址信息 |
| `%s` | 读取栈上指针指向的字符串 | 可泄露任意内存 |
| `%n` | 向栈上地址写入已输出字节数 | 可修改任意内存 |

#### 3. 整数溢出

**原理**：运算结果超出类型范围，导致逻辑错误。

```c
#include <stdio.h>
#include <stdlib.h>
#include <limits.h>

void vulnerable(int count) {
    int* arr = malloc(count * sizeof(int));
    if (!arr) return;
    for (int i = 0; i < count; i++) {
        arr[i] = i;
    }
    free(arr);
}

void safe(int count) {
    if (count <= 0 || count > INT_MAX / (int)sizeof(int)) {
        fprintf(stderr, "invalid count or integer overflow\n");
        return;
    }
    int* arr = malloc((size_t)count * sizeof(int));
    if (!arr) return;
    for (int i = 0; i < count; i++) {
        arr[i] = i;
    }
    free(arr);
    arr = NULL;
}

int main(void) {
    vulnerable(0x20000001);
    safe(0x20000001);
    return 0;
}
```

**攻击方式**：当`count=0x20000001`时，`count * sizeof(int)`溢出为很小的值，`malloc`分配小缓冲区，但循环写入大量数据→缓冲区溢出。

#### 4. Use-After-Free

**原理**：释放内存后继续使用指针，内存可能已被分配给其他对象。

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

void vulnerable(void) {
    char* ptr = malloc(100);
    strcpy(ptr, "secret data");
    free(ptr);
    printf("%s\n", ptr);
}

void safe_c_style(void) {
    char* ptr = malloc(100);
    if (!ptr) return;
    strcpy(ptr, "secret data");
    printf("%s\n", ptr);
    free(ptr);
    ptr = NULL;
}
```

```cpp
#include <memory>
#include <iostream>

void safe_cpp_style(void) {
    auto ptr = std::make_unique<char[]>(100);
    strncpy(ptr.get(), "secret data", 99);
    std::cout << ptr.get() << "\n";
}
```

**防护**：free后置NULL、用C++智能指针（`unique_ptr`/`shared_ptr`）。

#### 5. 竞态条件（TOCTOU）

**原理**：检查时间（Time of Check）与使用时间（Time of Use）之间状态变化。

```c
#include <stdio.h>
#include <unistd.h>
#include <sys/stat.h>
#include <fcntl.h>

void vulnerable(const char* filename) {
    struct stat st;
    if (lstat(filename, &st) == 0 && S_ISREG(st.st_mode)) {
        FILE* f = fopen(filename, "r");
        if (f) fclose(f);
    }
}

void safe(const char* filename) {
    int fd = open(filename, O_RDONLY | O_NOFOLLOW);
    if (fd < 0) {
        perror("open");
        return;
    }
    struct stat st;
    if (fstat(fd, &st) == 0 && S_ISREG(st.st_mode)) {
        FILE* f = fdopen(fd, "r");
        if (f) fclose(f);
    } else {
        close(fd);
    }
}
```

**防护**：使用原子操作、文件锁、用文件描述符代替文件名操作。

### 4. 后门类型

| 类型 | 说明 | 代码示例 |
|------|------|---------|
| 硬编码密码 | 程序中写死一个万能密码 | `if(strcmp(pwd,"master123")==0)` |
| 隐藏命令 | 特殊输入触发管理员功能 | `if(input=="debug_mode")` |
| 隐蔽通道 | 通过看似正常的接口传递信息 | DNS隧道、ICMP后门 |
| 供应链后门 | 在第三方库中植入恶意代码 | XZ Utils事件(2024) |

**硬编码密码示例**：

```c
#include <stdio.h>
#include <string.h>

int check_password(const char* input) {
    if (strcmp(input, "master123") == 0) {
        return 1;
    }
    return strcmp(input, "user_password") == 0;
}

int main(void) {
    char pwd[64];
    fgets(pwd, sizeof(pwd), stdin);
    pwd[strcspn(pwd, "\n")] = '\0';
    if (check_password(pwd)) {
        printf("access granted\n");
    }
    return 0;
}
```

**隐藏命令示例**：

```c
#include <stdio.h>
#include <string.h>

void process_command(const char* cmd) {
    if (strcmp(cmd, "debug_mode") == 0) {
        printf("admin shell activated\n");
        return;
    }
    printf("executing: %s\n", cmd);
}
```

**供应链后门**：2024年XZ Utils事件——攻击者逐步获得liblzma维护权，在压缩库中植入后门，影响SSH认证流程，几乎波及所有主流Linux发行版。

### 5. 0day漏洞详解

**0day = 厂商0天时间修补**（发现时已被利用）。

**生命周期**：

| 阶段 | 说明 |
|------|------|
| 发现 | 攻击者或研究者发现漏洞 |
| 利用 | 攻击者利用漏洞发起攻击 |
| 公开 | 漏洞被公开披露 |
| 修补 | 厂商发布补丁 |
| 防御 | 用户安装补丁、部署防护 |

**与Nday的区别**：

| | 0day | Nday |
|---|---|---|
| 补丁 | 无补丁 | 已有补丁 |
| 防御 | 只能靠缓解措施 | 安装补丁即可 |
| 利用难度 | 需要自己发现 | 可参考公开信息 |
| 危害 | 极高 | 高（取决于补丁安装率） |

**著名0day案例**：

| 漏洞 | 年份 | 影响 | 类型 |
|------|------|------|------|
| Heartbleed | 2014 | OpenSSL内存泄露，影响数百万网站 | 缓冲区越界读 |
| EternalBlue | 2017 | Windows SMB漏洞，WannaCry勒索病毒利用 | 缓冲区溢出 |
| Log4Shell | 2021 | Log4j远程代码执行，影响无数Java应用 | 注入漏洞 |

### 6. 提权方式

| 类型 | 说明 | 示例 |
|------|------|------|
| 垂直提权 | 低权限→高权限 | 普通用户→root |
| 水平提权 | 同级用户间切换 | 用户A→用户B |
| 内核漏洞提权 | 利用内核bug | DirtyCow(CVE-2016-5195) |
| 配置错误提权 | 利用系统配置不当 | SUID程序漏洞 |
| 服务提权 | 利用运行中的高权限服务 | 数据库UDF提权 |

**SUID提权示例**：

```bash
# 查找SUID程序
find / -perm -4000 -type f 2>/dev/null

# 如果find有SUID权限，可利用它读取任意文件
find /etc/shadow -cat
```

**DirtyCow原理**：Linux内核的写时复制（COW）机制存在竞态条件，攻击者可通过竞态修改只读文件。

**最小权限防护**：

```c
#include <unistd.h>
#include <sys/types.h>

void drop_privileges(void) {
    uid_t ruid = getuid();
    if (setuid(ruid) != 0) {
        return;
    }
}
```

### 7. C/C++安全编码清单

| 防护措施 | 命令/方法 | 防御的攻击 |
|---------|----------|-----------|
| 栈保护 | `-fstack-protector-strong` | 栈溢出 |
| ASLR | `-fPIE -pie` | 地址预测攻击 |
| DEP/NX | 操作系统级 | 代码注入 |
| 栈执行禁用 | `-z noexecstack` | 栈上执行代码 |
| RELRO | `-Wl,-z,relro,-z,now` | GOT覆写 |
| 安全函数 | `strncpy`/`snprintf` | 缓冲区溢出 |
| 输入验证 | 长度/范围/格式检查 | 所有注入攻击 |
| 智能指针 | `unique_ptr`/`shared_ptr` | UAF/Double Free |
| 最小权限 | drop privileges | 提权 |
| 静态分析 | clang-tidy/cppcheck | 所有类型 |

**完整安全编译命令**：

```bash
gcc -std=c11 -Wall -Wextra -Werror \
    -fstack-protector-strong \
    -D_FORTIFY_SOURCE=2 \
    -fPIE -pie \
    -Wl,-z,relro,-z,now \
    -Wformat -Wformat-security \
    -o myapp main.c
```

**静态分析示例**：

```bash
cppcheck --enable=all --error-exitcode=1 main.c
clang-tidy main.c -- -std=c11
```

### 8. 极简总结

**漏洞=可被利用的缺陷，后门=故意留的暗门，溢出=写超缓冲区覆盖相邻内存，0day=未公开未修补的漏洞，提权=低权限升到高权限。C/C++防护核心：用安全函数、开启编译器保护选项、验证输入、用智能指针、最小权限运行。**

| 要点 | 一句话 |
|------|--------|
| 漏洞 | 可被利用的缺陷——墙上的裂缝 |
| 后门 | 故意留的暗门——万能密码、隐藏命令、供应链后门 |
| 溢出 | 写超缓冲区覆盖相邻内存——用安全函数+栈保护+ASLR |
| 0day | 未公开未修补——无补丁可用，危害极高 |
| 提权 | 低权限升到高权限——最小权限运行 |
| 防护核心 | 安全函数+编译器选项+输入验证+智能指针+最小权限 |
