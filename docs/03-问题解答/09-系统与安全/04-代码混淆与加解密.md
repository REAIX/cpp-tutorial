# 代码混淆与加解密指南
> 📖 相关章节：[错误处理与信号](../../01-C语言/13-错误处理与信号.md)、[进程与线程](../../01-C语言/23-进程与线程.md)、[网络编程](../../02-CPP/31-网络编程.md)

## 1. 通俗理解

把你的程序想象成一封信：

- **加密** = 把信的内容变成只有持有钥匙的人才能读懂的密文
- **解密** = 拿到钥匙后把密文还原成原文
- **哈希** = 给信盖一个独一无二的指纹戳，任何改动都会让指纹失效
- **代码混淆** = 把信写成只有你自己能看懂的"天书"，别人拿到也看不明白
- **签名** = 在信上签你的名字，别人能验证确实是你写的，且没被篡改

## 2. 加密与解密基础

### 1. 加密的分类

```
加密算法
├── 对称加密（同一把钥匙加密和解密）
│   ├── 分组密码：AES、DES、3DES、SM4
│   └── 流密码：RC4、ChaCha20
│
└── 非对称加密（公钥加密，私钥解密）
    ├── RSA
    ├── ECC（椭圆曲线）
    ├── DSA
    └── SM2（国密）
```

### 2. 对称加密

**特点**：加密和解密用同一把密钥，速度快，适合大量数据。

| 算法 | 密钥长度 | 安全性 | 速度 | 说明 |
|------|---------|--------|------|------|
| AES-128 | 128位 | 安全 | 快 | 最常用的对称加密 |
| AES-256 | 256位 | 很安全 | 较快 | 金融/军工级别 |
| DES | 56位 | ❌ 已破解 | 快 | 已淘汰，不要用 |
| 3DES | 168位 | 一般 | 慢 | 正在淘汰 |
| ChaCha20 | 256位 | 安全 | 很快 | 移动端优于AES |
| SM4 | 128位 | 安全 | 快 | 中国国密标准 |

**AES加密模式**：

| 模式 | 全称 | 特点 | 是否需要填充 |
|------|------|------|------------|
| ECB | Electronic Codebook | 相同明文→相同密文，❌不安全 | 是 |
| CBC | Cipher Block Chaining | 每块依赖前一块，需要IV | 是 |
| CTR | Counter | 流式加密，可并行 | 否 |
| GCM | Galois/Counter | 认证加密（加密+完整性），✅推荐 | 否 |

**C++实现AES加密（使用OpenSSL）**：

```cpp
#include <openssl/evp.h>
#include <openssl/rand.h>
#include <string>
#include <vector>
#include <cstring>

std::vector<unsigned char> aes256_encrypt(
    const std::string& plaintext,
    const std::vector<unsigned char>& key,
    std::vector<unsigned char>& iv)
{
    iv.resize(16);
    RAND_bytes(iv.data(), 16);

    EVP_CIPHER_CTX* ctx = EVP_CIPHER_CTX_new();
    EVP_EncryptInit_ex(ctx, EVP_aes_256_cbc(), nullptr, key.data(), iv.data());

    std::vector<unsigned char> ciphertext(plaintext.size() + 16);
    int len = 0, ciphertext_len = 0;

    EVP_EncryptUpdate(ctx, ciphertext.data(), &len,
                       reinterpret_cast<const unsigned char*>(plaintext.data()),
                       plaintext.size());
    ciphertext_len = len;

    EVP_EncryptFinal_ex(ctx, ciphertext.data() + len, &len);
    ciphertext_len += len;

    ciphertext.resize(ciphertext_len);
    EVP_CIPHER_CTX_free(ctx);
    return ciphertext;
}

std::string aes256_decrypt(
    const std::vector<unsigned char>& ciphertext,
    const std::vector<unsigned char>& key,
    const std::vector<unsigned char>& iv)
{
    EVP_CIPHER_CTX* ctx = EVP_CIPHER_CTX_new();
    EVP_DecryptInit_ex(ctx, EVP_aes_256_cbc(), nullptr, key.data(), iv.data());

    std::vector<unsigned char> plaintext(ciphertext.size() + 16);
    int len = 0, plaintext_len = 0;

    EVP_DecryptUpdate(ctx, plaintext.data(), &len,
                       ciphertext.data(), ciphertext.size());
    plaintext_len = len;

    EVP_DecryptFinal_ex(ctx, plaintext.data() + len, &len);
    plaintext_len += len;

    EVP_CIPHER_CTX_free(ctx);
    return std::string(reinterpret_cast<char*>(plaintext.data()), plaintext_len);
}
```

### 3. 非对称加密

**特点**：公钥加密、私钥解密（或私钥签名、公钥验证），速度慢，适合小数据和密钥交换。

| 算法 | 密钥长度 | 安全性 | 速度 | 用途 |
|------|---------|--------|------|------|
| RSA-2048 | 2048位 | 安全 | 慢 | 数字签名、密钥交换 |
| RSA-4096 | 4096位 | 很安全 | 很慢 | 高安全场景 |
| ECC-P256 | 256位 | 安全 | 较快 | 同等安全下密钥更短 |
| Ed25519 | 256位 | 安全 | 快 | 签名首选 |
| SM2 | 256位 | 安全 | 较快 | 中国国密标准 |

**典型使用场景**：

```
HTTPS通信流程（RSA密钥交换简化版）：

1. 客户端 → 服务器：你好，我要建立安全连接
2. 服务器 → 客户端：这是我的公钥（证书）
3. 客户端：生成随机AES密钥，用服务器公钥加密
4. 客户端 → 服务器：[AES密钥的RSA密文]
5. 服务器：用私钥解密，得到AES密钥
6. 双方：用AES密钥加密后续通信（对称加密，快）
```

### 4. 对称 vs 非对称对比

| 维度 | 对称加密 | 非对称加密 |
|------|---------|-----------|
| 密钥 | 1把（加密=解密） | 2把（公钥+私钥） |
| 速度 | 快（AES约1GB/s） | 慢（RSA约1MB/s） |
| 安全性 | 密钥分发困难 | 密钥分发容易 |
| 适用场景 | 大量数据加密 | 密钥交换、数字签名 |
| 典型组合 | AES-256-GCM | RSA-2048 + AES-256 |

## 3. 哈希与消息摘要

### 1. 什么是哈希

哈希（Hash）= 把任意长度的数据映射为固定长度的"指纹"。**不可逆**——无法从哈希值还原原文。

| 算法 | 输出长度 | 安全性 | 速度 | 说明 |
|------|---------|--------|------|------|
| MD5 | 128位 | ❌ 已破解 | 很快 | 仅用于校验，不用于安全 |
| SHA-1 | 160位 | ❌ 已破解 | 快 | 已淘汰 |
| SHA-256 | 256位 | ✅ 安全 | 较快 | 最常用 |
| SHA-3 | 256/512位 | ✅ 安全 | 较快 | 新标准 |
| BLAKE3 | 256位 | ✅ 安全 | 很快 | 最快的安全哈希 |
| SM3 | 256位 | ✅ 安全 | 较快 | 中国国密标准 |

### 2. 哈希的用途

```cpp
#include <openssl/sha.h>
#include <iomanip>
#include <sstream>

std::string sha256(const std::string& input)
{
    unsigned char hash[SHA256_DIGEST_LENGTH];
    SHA256(reinterpret_cast<const unsigned char*>(input.c_str()),
           input.size(), hash);

    std::ostringstream oss;
    for (int i = 0; i < SHA256_DIGEST_LENGTH; i++) {
        oss << std::hex << std::setw(2) << std::setfill('0') << (int)hash[i];
    }
    return oss.str();
}

// 用法
std::string hash1 = sha256("hello");      // 2cf24dba5fb0a30e26e83b2ac5b9e29e...
std::string hash2 = sha256("hello!");     // ce0609...（只改一个字符，哈希完全不同）
std::string hash3 = sha256("hello");      // 2cf24dba5fb0a30e26e83b2ac5b9e29e...（确定性）
```

| 用途 | 说明 |
|------|------|
| 密码存储 | 存哈希值而非明文密码，验证时比较哈希 |
| 文件校验 | 下载文件后比较SHA-256，确认未被篡改 |
| 数据完整性 | 传输数据附带哈希，接收方验证 |
| 数字签名 | 对哈希值签名，而非对整个数据签名（效率） |

### 3. 密码存储的正确方式

```cpp
#include <openssl/evp.h>
#include <openssl/rand.h>

// ❌ 错误：直接存MD5/SHA-256
// std::string stored = sha256(password);  // 容易被彩虹表攻击

// ✅ 正确：加盐 + 慢哈希（PBKDF2/bcrypt/Argon2）
std::string hash_password(const std::string& password,
                          std::vector<unsigned char>& salt)
{
    salt.resize(16);
    RAND_bytes(salt.data(), 16);

    unsigned char key[32];
    PKCS5_PBKDF2_HMAC(password.c_str(), password.size(),
                       salt.data(), salt.size(),
                       100000,                    // 迭代10万次，增加暴力破解成本
                       EVP_sha256(),
                       32, key);

    return std::string(reinterpret_cast<char*>(key), 32);
}
```

## 4. 数字签名与证书

### 1. 数字签名

```
签名流程：
原文 → 哈希 → 用私钥加密哈希 → 签名

验证流程：
原文 → 哈希 → 用公钥解密签名 → 比较两个哈希值
```

**签名 = 证明"这是我发的" + "内容没被改过"**

```cpp
#include <openssl/rsa.h>
#include <openssl/pem.h>
#include <openssl/sha.h>

// 签名
std::vector<unsigned char> rsa_sign(const std::string& message,
                                     EVP_PKEY* private_key)
{
    unsigned char hash[SHA256_DIGEST_LENGTH];
    SHA256(reinterpret_cast<const unsigned char*>(message.c_str()),
           message.size(), hash);

    EVP_MD_CTX* ctx = EVP_MD_CTX_new();
    EVP_SignInit_ex(ctx, EVP_sha256(), nullptr);
    EVP_SignUpdate(ctx, hash, SHA256_DIGEST_LENGTH);

    std::vector<unsigned char> signature(EVP_PKEY_size(private_key));
    unsigned int sig_len = 0;
    EVP_SignFinal(ctx, signature.data(), &sig_len, private_key);
    signature.resize(sig_len);

    EVP_MD_CTX_free(ctx);
    return signature;
}

// 验证
bool rsa_verify(const std::string& message,
                const std::vector<unsigned char>& signature,
                EVP_PKEY* public_key)
{
    unsigned char hash[SHA256_DIGEST_LENGTH];
    SHA256(reinterpret_cast<const unsigned char*>(message.c_str()),
           message.size(), hash);

    EVP_MD_CTX* ctx = EVP_MD_CTX_new();
    EVP_VerifyInit_ex(ctx, EVP_sha256(), nullptr);
    EVP_VerifyUpdate(ctx, hash, SHA256_DIGEST_LENGTH);

    int result = EVP_VerifyFinal(ctx, signature.data(), signature.size(), public_key);
    EVP_MD_CTX_free(ctx);

    return result == 1;
}
```

### 2. 数字证书

```
证书链：

根CA证书（自签名，浏览器内置）
  └── 中间CA证书（由根CA签名）
       └── 服务器证书（由中间CA签名）

验证：服务器证书 → 中间CA → 根CA → 信任
```

## 5. 代码混淆

### 1. 什么是代码混淆

代码混淆 = 让编译后的程序难以被逆向工程，同时保持功能不变。

```
源代码 → 编译 → 正常二进制（容易反编译）
源代码 → 混淆编译 → 混淆二进制（难以反编译）
```

### 2. 混淆的层次

| 层次 | 方法 | 效果 | 工具 |
|------|------|------|------|
| **源码混淆** | 变量重命名、控制流平坦化、插入垃圾代码 | 低 | 手动/脚本 |
| **编译期混淆** | 模板元编程、宏展开 | 中 | 编译器 |
| **二进制混淆** | 加壳、代码虚拟化、反调试 | 高 | 专业工具 |
| **架构混淆** | 自定义指令集、虚拟机保护 | 极高 | 定制开发 |

### 3. 源码级混淆技巧

#### 1. 技巧1：标识符重命名

```cpp
// 混淆前
int calculate_total_price(int quantity, double unit_price) {
    double discount = quantity > 10 ? 0.9 : 1.0;
    return (int)(quantity * unit_price * discount);
}

// 混淆后
int _0x3f(int _a, double _b) {
    double _c = _a > 10 ? 0.9 : 1.0;
    return (int)(_a * _b * _c);
}
```

#### 2. 技巧2：控制流平坦化

```cpp
// 混淆前：线性逻辑
void process(int x) {
    if (x > 0) {
        step_a();
    } else {
        step_b();
    }
    step_c();
}

// 混淆后：switch分发
void process(int x) {
    int state = 0;
    while (1) {
        switch(state) {
            case 0: state = (x > 0) ? 1 : 2; break;
            case 1: step_a(); state = 3; break;
            case 2: step_b(); state = 3; break;
            case 3: step_c(); return;
        }
    }
}
```

#### 3. 技巧3：字符串加密

```cpp
// 混淆前：字符串明文出现在二进制中
printf("Secret API Key: ABC123");

// 混淆后：运行时解密
const char* get_key() {
    static char key[] = {0x12, 0x34, 0x56, 0x78, 0x9A, 0xBC,
                         0xDE, 0xF0, 0x11, 0x22, 0x33, 0x44, 0x55, 0x66, 0x00};
    static bool decrypted = false;
    if (!decrypted) {
        for (int i = 0; key[i]; i++) key[i] ^= 0x55;
        decrypted = true;
    }
    return key;
}
```

#### 4. 技巧4：不透明谓词

```cpp
// 插入永远为真/假的条件，干扰静态分析
if ((x * x - x) % 2 == 0) {   // 永远为真（x²-x = x(x-1)，连续两数之积必为偶数）
    real_code();
} else {
    dead_code();               // 永远不会执行，但反编译者会花时间分析
}
```

### 4. 编译期混淆

```bash
# GCC - 去除符号表

# GCC - 优化掉调试信息
```

### 7. 混淆的局限

| 局限 | 说明 |
|------|------|
| **不能防止动态分析** | 运行时抓取内存、hook函数调用仍然有效 |
| **增加维护成本** | 混淆后的代码难以调试和维护 |
| **影响性能** | 控制流平坦化、虚拟化会降低执行速度 |
| **不是加密** | 混淆不等于加密，有经验的逆向工程师仍然可以分析 |
| **可能被脱壳** | UPX等压缩壳可以被轻松脱壳 |

### 1. 库对比

| 库 | 许可证 | 功能 | 大小 | 推荐场景 |
|------|--------|------|------|---------|
| OpenSSL | Apache-2.0 | 全功能（加密/签名/证书/TLS） | 大 | 需要完整加密方案 |

| Crypto++ | Boost | 全功能C++加密库 | 大 | C++项目，算法全面 |
| mbedTLS | Apache-2.0 | 轻量TLS/加密 | 小 | 嵌入式/物联网 |
| wolfSSL | GPL/商业 | 轻量TLS | 小 | 嵌入式 |
| TinyCrypt | BSD | 极简加密 | 极小 | 资源极度受限 |

### 2. libsodium 示例（推荐）

```cpp
#include <sodium.h>
#include <string>
#include <vector>

// 加密认证（AEAD：加密+完整性校验，一步到位）
std::vector<unsigned char> encrypt_authenticated(
    const std::string& message,
    const unsigned char key[crypto_secretbox_KEYBYTES])
{
    unsigned char nonce[crypto_secretbox_NONCEBYTES];
    randombytes_buf(nonce, sizeof(nonce));

    std::vector<unsigned char> ciphertext(
        crypto_secretbox_MACBYTES + message.size());

    crypto_secretbox_easy(ciphertext.data(),
                          reinterpret_cast<const unsigned char*>(message.data()),
                          message.size(),
                          nonce, key);

    // 返回 nonce + ciphertext（nonce必须传给解密方）
    std::vector<unsigned char> result(nonce, nonce + sizeof(nonce));
    result.insert(result.end(), ciphertext.begin(), ciphertext.end());
    return result;
}

// 解密验证
std::string decrypt_authenticated(
    const std::vector<unsigned char>& encrypted,
    const unsigned char key[crypto_secretbox_KEYBYTES])
{
    unsigned char nonce[crypto_secretbox_NONCEBYTES];
    std::memcpy(nonce, encrypted.data(), sizeof(nonce));

    const unsigned char* ciphertext = encrypted.data() + sizeof(nonce);
    size_t ciphertext_len = encrypted.size() - sizeof(nonce);

    std::vector<unsigned char> decrypted(ciphertext_len - crypto_secretbox_MACBYTES);

    if (crypto_secretbox_open_easy(decrypted.data(),
                                    ciphertext, ciphertext_len,
                                    nonce, key) != 0) {
        throw std::runtime_error("解密失败：密文被篡改或密钥错误");
    }

    return std::string(reinterpret_cast<char*>(decrypted.data()),
                       decrypted.size());
}
```

## 7. 常见加密场景与方案选择

### 1. 场景速查表

| 场景 | 推荐方案 | 不要用 |
|------|---------|--------|
| 存储用户密码 | Argon2 / bcrypt / PBKDF2 | ❌ MD5 / SHA-256直接存 |
| 传输加密数据 | AES-256-GCM / ChaCha20-Poly1305 | ❌ AES-ECB / DES |
| 密钥交换 | ECDH / X25519 | ❌ RSA无填充 |
| 数字签名 | Ed25519 / RSA-PSS | ❌ RSA-PKCS1v1.5 |
| 文件完整性校验 | SHA-256 / SHA-3 | ❌ MD5 / SHA-1 |
| TLS通信 | TLS 1.3 | ❌ SSL 3.0 / TLS 1.0 |
| 中国合规 | SM2 + SM3 + SM4 | — |
| 嵌入式轻量 | AES-CCM / ChaCha20-Poly1305 | ❌ RSA（太慢） |

### 2. 不要自己实现加密算法

```
❌ 自己写AES实现
   → 99%会有侧信道漏洞（时序攻击、缓存攻击）

❌ 自己写随机数生成器
   → rand()/srand()不安全，用操作系统提供的CSPRNG

❌ 自己设计加密协议
   → 即使算法正确，协议层面也可能有漏洞

✅ 用经过审计的库（OpenSSL/libsodium/mbedTLS）
✅ 用标准协议（TLS 1.3）
✅ 用AEAD模式（GCM/Poly1305），加密和认证一步到位
```

### 2. std::expected用于错误处理

```cpp
std::expected<std::vector<unsigned char>, std::string> decrypt(
    std::span<const unsigned char> ciphertext,
    std::span<const unsigned char> key)
{
    if (ciphertext.size() < crypto_secretbox_MACBYTES) {
        return std::unexpected("密文太短");
    }
    // ...
    if (crypto_secretbox_open_easy(...) != 0) {
        return std::unexpected("解密失败：密文被篡改");
    }
    return decrypted;
}
```

## 9. 代码混淆 vs 加密 vs 签名对比

| 维度 | 代码混淆 | 加密 | 数字签名 |
|------|---------|------|---------|
| 目的 | 让代码难以被逆向 | 保护数据机密性 | 验证身份和完整性 |
| 保护对象 | 程序本身 | 数据 | 数据来源 |
| 可逆性 | 可被逆向（只是困难） | 有密钥可逆 | 不可逆（只能验证） |
| 强度 | 中等（专业逆向可破） | 极强（无密钥不可破） | 极强 |
| 性能影响 | 运行时变慢 | 加解密开销 | 签名验证开销 |
| 典型工具 | UPX/VMProtect/LLVMObfuscator | OpenSSL/libsodium | OpenSSL/libsodium |

## 10. 常见问题

### 1. Q1：MD5还能用吗？

**不能用于安全场景**。MD5已被破解，可以构造碰撞（两个不同内容产生相同哈希）。但可以用于非安全场景（如文件快速比对、缓存键）。

### 2. Q2：AES-ECB为什么不能用？

ECB模式对相同的明文块产生相同的密文块。攻击者可以看到数据模式，甚至可以替换某些块。

```
明文：[块A][块B][块A]     ← 块A重复
ECB密文：[X1][X2][X1]     ← X1重复，暴露了模式
CBC密文：[X1][X2][X3]     ← 完全不同
```

### 3. Q3：HTTPS够安全吗？

TLS 1.3是安全的。但要确保：
- 使用TLS 1.2以上（禁用TLS 1.0/1.1）
- 证书有效且未被吊销
- 不忽略证书验证错误

### 4. Q4：代码混淆能防止破解吗？

**不能完全防止**，只能增加逆向工程的成本。混淆的目的是让破解成本远高于软件价值。对于高价值软件，建议混淆 + 在线验证 + 法律保护组合使用。

### 5. Q5：国密算法是什么？

中国密码行业标准（GM/T），包括：
- SM1：对称加密（硬件实现）
- SM2：非对称加密（类似ECC）
- SM3：哈希算法（类似SHA-256）
- SM4：对称加密（类似AES-128）

中国金融、政务系统要求使用国密算法。
