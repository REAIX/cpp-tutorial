> "操作系统接口=政府服务窗口——你不需要知道政府内部怎么运作，只需要到窗口提交申请。"——理解系统调用与POSIX标准，是写出跨平台、高性能系统级程序的基础。

## 1. 什么是操作系统接口

### 1. 定义

**操作系统接口**是应用程序与操作系统内核之间的桥梁。应用程序不能直接操作硬件，必须通过操作系统提供的接口向内核提出请求，由内核代为完成。

```
应用程序层
  │
  │  系统调用（syscall）—— 操作系统接口
  ▼
内核层
  │
  │  内核直接操作硬件
  ▼
硬件层
```

### 2. 生活类比

| 概念 | 类比 | 说明 |
|------|------|------|
| 操作系统接口 | 政府服务窗口 | 你不需要知道政府内部怎么运作，只需要到窗口提交申请 |
| 系统调用 | 填申请表 | 你填写申请表（指定系统调用号和参数），窗口工作人员（内核）帮你处理 |
| 用户态 | 办事大厅 | 普通市民（应用程序）只能在大厅等候，不能进入办公室 |
| 内核态 | 政府办公室 | 工作人员（内核）在办公室内处理事务，有权限访问所有资源 |

### 3. 用户态 vs 内核态

| 维度 | 用户态 | 内核态 |
|------|--------|--------|
| 权限 | 受限，不能直接访问硬件 | 完全，可访问所有硬件和内存 |
| 运行内容 | 应用程序、库函数 | 内核代码、驱动程序 |
| 地址空间 | 每个进程独立 | 所有进程共享内核空间 |
| 崩溃影响 | 只影响当前进程 | 整个系统崩溃 |
| 切换开销 | — | 上下文切换、TLB刷新、栈切换 |

```
用户态 → 内核态切换过程：

  用户程序调用 read()
      │
      ▼
  C库包装函数
      │
      ▼
  执行 int 0x80 / syscall 指令  ← 触发软中断/系统调用指令
      │
      ▼
  CPU切换到内核态
      │
      ▼
  内核查找系统调用表，执行对应处理函数
      │
      ▼
  内核完成操作，返回结果
      │
      ▼
  执行 iret / sysret 指令  ← 返回用户态
      │
      ▼
  用户程序获得返回值
```

### 4. 系统调用原理

**x86（32位）**：使用 `int 0x80` 软中断触发系统调用

```asm
mov eax, 3        ; 系统调用号 3 = read
mov ebx, fd       ; 参数1：文件描述符
mov ecx, buf      ; 参数2：缓冲区地址
mov edx, count    ; 参数3：读取字节数
int 0x80          ; 触发软中断，进入内核
```

**x86_64**：使用 `syscall` 指令，比 `int 0x80` 更快

```asm
mov rax, 0        ; 系统调用号 0 = read
mov rdi, fd       ; 参数1：文件描述符
mov rsi, buf      ; 参数2：缓冲区地址
mov rdx, count    ; 参数3：读取字节数
syscall           ; 执行系统调用
```

| 方式 | 架构 | 指令 | 速度 |
|------|------|------|------|
| 软中断 | x86 | `int 0x80` | 较慢 |
| 快速系统调用 | x86_64 | `syscall` | 快 |
| 快速系统调用 | x86_64 | `sysret`（返回） | 快 |
| 专用指令 | ARM | `SVC` | 快 |

## 2. POSIX标准

### 1. 定义

**POSIX**（Portable Operating System Interface）是IEEE定义的一套操作系统接口标准。它规定了操作系统应该为应用程序提供哪些接口，使得符合POSIX的程序可以在任何兼容系统上编译运行。

```
POSIX = 一份"接口合同"

  应用程序 ─── 只调用POSIX定义的接口 ───→ 操作系统
                                           │
                              ┌────────────┼────────────┐
                              ▼            ▼            ▼
                           Linux        macOS       其他Unix
                           （实现）     （实现）     （实现）

  同一份代码，三个系统都能跑——这就是POSIX的价值
```

### 2. 为什么重要

| 不用POSIX | 用POSIX |
|-----------|---------|
| 在Linux上用Linux API写代码 | 用POSIX接口写代码 |
| 移植到macOS要改大量代码 | Linux/macOS/Unix都能跑 |
| 移植到其他Unix又要改 | 写一次，到处运行 |

**核心价值**：写一次代码，Linux/macOS/Unix都能跑。

### 3. POSIX定义的接口分类

| 分类 | 主要接口 | 说明 |
|------|---------|------|
| 文件I/O | `open`/`read`/`write`/`close`/`lseek` | 文件读写操作 |
| 进程管理 | `fork`/`exec`/`wait`/`exit`/`getpid` | 进程创建与控制 |
| 信号处理 | `signal`/`sigaction`/`kill`/`raise` | 异步事件通知 |
| 线程 | `pthread_create`/`pthread_join`/`pthread_mutex` | 多线程编程 |
| 网络 | `socket`/`bind`/`listen`/`accept`/`connect` | 网络通信 |
| 内存映射 | `mmap`/`munmap`/`mprotect` | 内存管理 |
| 进程间通信 | `pipe`/`shmget`/`msgget`/`semget` | IPC机制 |
| 时间 | `clock_gettime`/`gettimeofday`/`nanosleep` | 时间操作 |

## 3. POSIX文件I/O

### 1. 核心函数

| 函数 | 原型 | 说明 |
|------|------|------|
| `open` | `int open(const char *path, int flags, ...)` | 打开文件，返回文件描述符 |
| `read` | `ssize_t read(int fd, void *buf, size_t count)` | 从文件描述符读取数据 |
| `write` | `ssize_t write(int fd, const void *buf, size_t count)` | 向文件描述符写入数据 |
| `close` | `int close(int fd)` | 关闭文件描述符 |
| `lseek` | `off_t lseek(int fd, off_t offset, int whence)` | 设置文件偏移量 |

### 2. 文件描述符

文件描述符（File Descriptor, fd）是内核维护的打开文件的索引，是一个非负整数。

```
每个进程的文件描述符表：

  fd 0 → 标准输入（stdin）
  fd 1 → 标准输出（stdout）
  fd 2 → 标准错误（stderr）
  fd 3 → 第一个打开的文件
  fd 4 → 第二个打开的文件
  ...

规则：
  - 分配最小的可用fd
  - 进程最多打开的fd数量有限制（ulimit -n 查看）
  - fork后子进程继承父进程的fd表
```

### 3. 缓冲I/O vs 无缓冲I/O

```
无缓冲I/O（POSIX）：
  应用程序 ─── read()/write() ───→ 内核缓冲区 ───→ 磁盘
  每次调用都进入内核态

缓冲I/O（C标准库）：
  应用程序 ─── fread()/fwrite() ───→ 用户空间缓冲区 ───→ read()/write() ───→ 内核缓冲区 ───→ 磁盘
  先写到用户空间缓冲区，满了再调用系统调用

对比：
  无缓冲：每次读写都触发系统调用，开销大，但控制精确
  缓冲：减少系统调用次数，性能好，但有数据滞留风险
```

| 维度 | 无缓冲I/O（POSIX） | 缓冲I/O（C标准库） |
|------|-------------------|-------------------|
| 函数 | `open`/`read`/`write` | `fopen`/`fread`/`fwrite` |
| 缓冲 | 无用户空间缓冲 | 有用户空间缓冲 |
| 系统调用 | 每次都触发 | 缓冲满才触发 |
| 粒度 | 按字节/任意大小 | 按缓冲区大小 |
| 适用 | 需要精确控制 | 通用文件读写 |

### 4. 代码示例

```c
#include <fcntl.h>
#include <unistd.h>
#include <stdio.h>

int main(void) {
    int fd = open("test.txt", O_RDWR | O_CREAT, 0644);
    if (fd < 0) {
        perror("open");
        return 1;
    }

    const char *msg = "Hello, POSIX I/O!";
    ssize_t written = write(fd, msg, 18);
    printf("写入了 %zd 字节\n", written);

    lseek(fd, 0, SEEK_SET);

    char buf[64] = {0};
    ssize_t n = read(fd, buf, sizeof(buf) - 1);
    printf("读取了 %zd 字节: %s\n", n, buf);

    close(fd);
    return 0;
}
```

## 4. POSIX进程管理

### 1. 核心函数

| 函数 | 说明 |
|------|------|
| `fork` | 创建子进程（复制当前进程） |
| `exec`系列 | 用新程序替换当前进程映像 |
| `wait`/`waitpid` | 等待子进程结束 |
| `getpid`/`getppid` | 获取进程ID/父进程ID |
| `exit` | 终止当前进程 |

### 2. fork/exec模型

```
fork + exec 创建新进程：

  父进程
    │
    ├── fork() ──→ 创建子进程（是父进程的副本）
    │                 │
    │                 ├── exec() ──→ 用新程序替换子进程
    │                 │               │
    │                 │               ▼
    │                 │             新程序运行
    │                 │
    │                 └── 不exec ──→ 子进程继续执行父进程的代码
    │
    └── wait() ──→ 等待子进程结束
```

### 3. 僵尸进程与孤儿进程

```
僵尸进程（Zombie）：
  子进程已退出，但父进程还没调用wait()回收
  → 子进程的PCB（进程控制块）还留在内核中
  → 占用PID资源，大量僵尸进程会耗尽PID
  → 解决：父进程调用wait()/waitpid()

孤儿进程（Orphan）：
  父进程先于子进程退出
  → 子进程被init进程（PID=1）收养
  → init会自动调用wait()回收
  → 不会造成危害

  父进程 ─── 退出
              │
  子进程 ─── 被init收养 ─── init调用wait()回收

  正常流程：
  父进程 ─── fork() ───→ 子进程
    │                        │
    │                   子进程退出
    │                        │
    └── wait() ←─────────────┘ 回收资源
```

### 4. 守护进程（Daemon）创建步骤

```
守护进程创建5步：

1. fork() + 父进程exit()
   → 让子进程不是进程组首领

2. setsid()
   → 创建新会话，脱离控制终端

3. 再次fork() + 父进程exit()（可选）
   → 确保不会重新打开控制终端

4. chdir("/")
   → 改变工作目录到根目录，避免占用挂载点

5. 关闭标准文件描述符，重定向到 /dev/null
   → 脱离终端I/O

结果：
  守护进程在后台运行，没有控制终端，不受用户登录/注销影响
  例：sshd、nginx、crond
```

### 5. 代码示例

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/wait.h>

int main(void) {
    pid_t pid = fork();

    if (pid < 0) {
        perror("fork");
        return 1;
    }

    if (pid == 0) {
        printf("子进程 PID=%d, 父进程 PID=%d\n", getpid(), getppid());
        execlp("ls", "ls", "-l", NULL);
        perror("exec");
        exit(1);
    } else {
        int status;
        waitpid(pid, &status, 0);
        printf("子进程结束，状态=%d\n", WEXITSTATUS(status));
    }

    return 0;
}
```

守护进程示例：

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/stat.h>

int main(void) {
    pid_t pid = fork();
    if (pid < 0) exit(1);
    if (pid > 0) exit(0);

    setsid();

    pid = fork();
    if (pid < 0) exit(1);
    if (pid > 0) exit(0);

    chdir("/");
    umask(0);

    for (int i = 0; i < 3; i++)
        close(i);

    open("/dev/null", O_RDWR);
    dup(0);
    dup(0);

    while (1) {
        sleep(60);
    }

    return 0;
}
```

## 5. POSIX进程间通信（IPC）

### 1. IPC机制概览

```
进程间通信方式：

  管道（Pipe） ──── 单向字节流，父子进程间
  命名管道（FIFO） ── 有名字的管道，任意进程间
  消息队列 ──────── 消息为单位，有类型
  共享内存 ──────── 最快的IPC，直接读写同一块内存
  信号量 ────────── 计数器，用于同步
  信号 ──────────── 异步通知机制
  Socket ────────── 网络通信，也可本机通信
```

### 2. 管道（Pipe / 命名管道FIFO）

**匿名管道**：只能用于有亲缘关系的进程间通信

```c
#include <stdio.h>
#include <unistd.h>
#include <string.h>

int main(void) {
    int pipefd[2];
    pipe(pipefd);

    pid_t pid = fork();
    if (pid == 0) {
        close(pipefd[1]);
        char buf[128];
        ssize_t n = read(pipefd[0], buf, sizeof(buf) - 1);
        buf[n] = '\0';
        printf("子进程收到: %s\n", buf);
        close(pipefd[0]);
    } else {
        close(pipefd[0]);
        const char *msg = "来自父进程的问候";
        write(pipefd[1], msg, strlen(msg));
        close(pipefd[1]);
        wait(NULL);
    }

    return 0;
}
```

**命名管道（FIFO）**：任意进程间通信

```c
#include <stdio.h>
#include <fcntl.h>
#include <sys/stat.h>
#include <unistd.h>

int main(void) {
    mkfifo("/tmp/myfifo", 0666);

    int fd = open("/tmp/myfifo", O_WRONLY);
    write(fd, "Hello FIFO", 10);
    close(fd);

    unlink("/tmp/myfifo");
    return 0;
}
```

### 3. 消息队列

```c
#include <stdio.h>
#include <sys/msg.h>
#include <string.h>

struct msgbuf {
    long mtype;
    char mtext[128];
};

int main(void) {
    key_t key = ftok("/tmp", 'A');
    int msqid = msgget(key, IPC_CREAT | 0666);

    struct msgbuf snd = {1, "消息队列测试"};
    msgsnd(msqid, &snd, strlen(snd.mtext) + 1, 0);

    struct msgbuf rcv;
    msgrcv(msqid, &rcv, sizeof(rcv.mtext), 1, 0);
    printf("收到: %s\n", rcv.mtext);

    msgctl(msqid, IPC_RMID, NULL);
    return 0;
}
```

### 4. 共享内存

```c
#include <stdio.h>
#include <sys/shm.h>
#include <string.h>

int main(void) {
    key_t key = ftok("/tmp", 'B');
    int shmid = shmget(key, 4096, IPC_CREAT | 0666);

    char *addr = (char *)shmat(shmid, NULL, 0);
    strcpy(addr, "共享内存数据");
    printf("写入: %s\n", addr);

    shmdt(addr);
    shmctl(shmid, IPC_RMID, NULL);
    return 0;
}
```

### 5. 信号量

```c
#include <stdio.h>
#include <sys/sem.h>
#include <sys/ipc.h>

union semun {
    int val;
};

int main(void) {
    key_t key = ftok("/tmp", 'C');
    int semid = semget(key, 1, IPC_CREAT | 0666);

    union semun arg = {1};
    semctl(semid, 0, SETVAL, arg);

    struct sembuf op_p = {0, -1, 0};
    struct sembuf op_v = {0, +1, 0};

    semop(semid, &op_p, 1);
    printf("进入临界区\n");
    semop(semid, &op_v, 1);
    printf("离开临界区\n");

    semctl(semid, 0, IPC_RMID);
    return 0;
}
```

### 6. IPC机制对比

| 机制 | 通信方式 | 速度 | 适用场景 |
|------|---------|------|---------|
| 管道 | 字节流 | 中 | 父子进程间简单通信 |
| FIFO | 字节流 | 中 | 任意进程间简单通信 |
| 消息队列 | 消息（有类型） | 中 | 需要分类消息的场景 |
| 共享内存 | 共享内存区 | 最快 | 大量数据传输 |
| 信号量 | 计数器 | 快 | 同步/互斥 |
| Socket | 字节流 | 较慢 | 网络通信/跨机器 |

## 6. POSIX内存管理

### 1. mmap/munmap——内存映射文件

`mmap`将文件或设备映射到进程的地址空间，映射后可以像访问内存一样访问文件。

```
mmap 原理：

  进程地址空间                物理内存              磁盘文件
  ┌──────────┐            ┌──────────┐         ┌──────────┐
  │ 映射区域  │ ←── 页表 ──→│ 页缓存    │ ←── 块I/O ──→│ 文件内容  │
  └──────────┘            └──────────┘         └──────────┘

  读写映射区域 = 读写文件（通过页缓存）
  不需要read/write系统调用
```

```c
#include <stdio.h>
#include <sys/mman.h>
#include <fcntl.h>
#include <unistd.h>
#include <string.h>

int main(void) {
    int fd = open("mmap_test.txt", O_RDWR | O_CREAT | O_TRUNC, 0644);
    const char *data = "Hello, mmap!";
    write(fd, data, strlen(data));

    size_t len = strlen(data);
    char *addr = mmap(NULL, len, PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);
    if (addr == MAP_FAILED) {
        perror("mmap");
        return 1;
    }

    printf("映射内容: %s\n", addr);
    addr[0] = 'h';
    printf("修改后: %s\n", addr);

    munmap(addr, len);
    close(fd);
    return 0;
}
```

### 2. brk/sbrk——堆内存扩展

`brk`/`sbrk`用于调整进程的数据段末尾地址，是`malloc`的底层实现之一。

```
进程地址空间：

  低地址
  ┌──────────┐
  │ 代码段    │ .text
  ├──────────┤
  │ 数据段    │ .data / .bss
  ├──────────┤
  │ 堆 ↓     │ ← brk指向这里
  │          │    sbrk() 向下扩展
  │          │
  ├──────────┤
  │ ...      │
  ├──────────┤
  │ 栈 ↑     │
  └──────────┘
  高地址

  sbrk(0)  → 返回当前brk位置
  sbrk(n)  → brk增加n字节，返回旧brk位置
  brk(addr)→ 设置brk到指定地址
```

```c
#include <stdio.h>
#include <unistd.h>

int main(void) {
    void *cur = sbrk(0);
    printf("当前brk: %p\n", cur);

    void *new_mem = sbrk(4096);
    if (new_mem == (void *)-1) {
        perror("sbrk");
        return 1;
    }
    printf("分配了4096字节，起始: %p\n", new_mem);

    brk(cur);
    printf("释放了分配的内存\n");
    return 0;
}
```

### 3. mprotect——内存保护

`mprotect`修改内存区域的保护属性（读/写/执行）。

```c
#include <stdio.h>
#include <sys/mman.h>
#include <string.h>
#include <signal.h>
#include <stdlib.h>

static void segv_handler(int sig) {
    printf("捕获段错误！试图写入只读内存\n");
    exit(1);
}

int main(void) {
    signal(SIGSEGV, segv_handler);

    char *addr = mmap(NULL, 4096, PROT_READ | PROT_WRITE,
                      MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    strcpy(addr, "可读写");
    printf("写入成功: %s\n", addr);

    mprotect(addr, 4096, PROT_READ);
    printf("已设为只读，尝试写入...\n");
    addr[0] = 'X';

    munmap(addr, 4096);
    return 0;
}
```

## 7. Windows API编程

### 1. Win32 API概述

Win32 API是Windows操作系统的原生编程接口，提供了窗口管理、文件操作、进程线程、网络通信等功能。

```
Win32 API 层次：

  应用程序
      │
      ▼
  高层API（Shell API / COM / .NET）
      │
      ▼
  Win32 API（User32 / GDI32 / Kernel32）
      │
      ▼
  NT内核（NtXXX 系统调用）
      │
      ▼
  硬件
```

### 2. HANDLE概念

`HANDLE`是Windows API中最核心的概念，是一个void指针，代表内核对象。

```
HANDLE = 内核对象的"句柄"

  类似于POSIX的文件描述符，但更通用：

  文件          → HANDLE (CreateFile返回)
  进程          → HANDLE (CreateProcess返回)
  线程          → HANDLE (CreateThread返回)
  事件          → HANDLE (CreateEvent返回)
  互斥体        → HANDLE (CreateMutex返回)
  信号量        → HANDLE (CreateSemaphore返回)
  管道          → HANDLE (CreateNamedPipe返回)

  规则：
  - 使用后必须 CloseHandle() 关闭
  - 不同类型的HANDLE不能混用
  - HANDLE是内核资源，泄露会导致资源耗尽
```

### 3. 文件操作

```c
#include <windows.h>
#include <stdio.h>

int main(void) {
    HANDLE hFile = CreateFileA(
        "test.txt",
        GENERIC_READ | GENERIC_WRITE,
        0,
        NULL,
        CREATE_ALWAYS,
        FILE_ATTRIBUTE_NORMAL,
        NULL
    );
    if (hFile == INVALID_HANDLE_VALUE) {
        printf("CreateFile 失败: %lu\n", GetLastError());
        return 1;
    }

    const char *data = "Hello, Win32!";
    DWORD written;
    WriteFile(hFile, data, 13, &written, NULL);
    printf("写入了 %lu 字节\n", written);

    SetFilePointer(hFile, 0, NULL, FILE_BEGIN);

    char buf[64] = {0};
    DWORD bytesRead;
    ReadFile(hFile, buf, sizeof(buf) - 1, &bytesRead, NULL);
    printf("读取了 %lu 字节: %s\n", bytesRead, buf);

    CloseHandle(hFile);
    return 0;
}
```

### 4. 进程操作

```c
#include <windows.h>
#include <stdio.h>

int main(void) {
    STARTUPINFOA si = {sizeof(si)};
    PROCESS_INFORMATION pi;

    BOOL ok = CreateProcessA(
        NULL,
        "notepad.exe",
        NULL, NULL,
        FALSE,
        0,
        NULL, NULL,
        &si, &pi
    );

    if (!ok) {
        printf("CreateProcess 失败: %lu\n", GetLastError());
        return 1;
    }

    printf("子进程 PID=%lu\n", pi.dwProcessId);

    WaitForSingleObject(pi.hProcess, INFINITE);

    DWORD exitCode;
    GetExitCodeProcess(pi.hProcess, &exitCode);
    printf("子进程退出码: %lu\n", exitCode);

    CloseHandle(pi.hProcess);
    CloseHandle(pi.hThread);
    return 0;
}
```

### 5. Windows特有的IPC

| 机制 | 函数 | 说明 |
|------|------|------|
| 命名管道 | `CreateNamedPipe`/`ConnectNamedPipe` | 双向通信，类似FIFO但功能更强 |
| 邮槽（Mailslot） | `CreateMailslot` | 一对多广播，单向 |
| COM | `CoCreateInstance` | 组件对象模型，进程间/跨语言调用 |
| WM_COPYDATA | `SendMessage` | 窗口间传递数据 |
| 内存映射文件 | `CreateFileMapping`/`MapViewOfFile` | 类似mmap |

### 6. POSIX vs Windows API对比

| 功能 | POSIX | Windows |
|------|-------|---------|
| 打开文件 | `open()` → int fd | `CreateFile()` → HANDLE |
| 读取 | `read(fd, buf, n)` | `ReadFile(hFile, buf, n, &read, NULL)` |
| 写入 | `write(fd, buf, n)` | `WriteFile(hFile, buf, n, &written, NULL)` |
| 关闭 | `close(fd)` | `CloseHandle(hFile)` |
| 定位 | `lseek(fd, off, whence)` | `SetFilePointer(hFile, off, NULL, method)` |
| 创建进程 | `fork()` + `exec()` | `CreateProcess()` |
| 等待进程 | `waitpid(pid, &st, 0)` | `WaitForSingleObject(hProcess, INFINITE)` |
| 管道 | `pipe(fd[2])` | `CreatePipe(&hRead, &hWrite, NULL, 0)` |
| 共享内存 | `shmget()`/`shmat()` | `CreateFileMapping()`/`MapViewOfFile()` |
| 互斥 | `pthread_mutex_t` | `HANDLE (CreateMutex)` |
| 错误码 | `errno` | `GetLastError()` |
| 句柄类型 | int（文件描述符） | HANDLE（通用句柄） |

### 1. #ifdef平台判断

```cpp
#if defined(_WIN32) || defined(_WIN64)
    #define PLATFORM_WINDOWS 1
    #include <windows.h>
#elif defined(__linux__)
    #define PLATFORM_LINUX 1
    #include <unistd.h>

    #define PLATFORM_MACOS 1
    #include <unistd.h>
    #include <sys/mman.h>
#else
    #error "不支持的平台"
#endif
```

### 2. 条件编译策略——封装平台差异

```cpp
#include <string>

namespace platform {

#if defined(_WIN32)

void sleep_ms(unsigned int ms) {
    Sleep(ms);
}

std::string get_error() {
    DWORD err = GetLastError();
    char buf[256];
    FormatMessageA(FORMAT_MESSAGE_FROM_SYSTEM, NULL, err, 0, buf, 256, NULL);
    return buf;
}

#else

void sleep_ms(unsigned int ms) {
    usleep(ms * 1000);
}

std::string get_error() {
    return strerror(errno);
}

#endif

}
```

### 3. 跨平台库

#include <QFile>
