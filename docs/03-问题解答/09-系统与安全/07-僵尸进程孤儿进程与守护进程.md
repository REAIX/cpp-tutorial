# 僵尸进程、孤儿进程与守护进程详解
> 📖 相关章节：[错误处理与信号](../../01-C语言/13-错误处理与信号.md)、[进程与线程](../../01-C语言/24-进程与线程.md)、[网络编程](../../02-CPP/35-网络编程.md)

> "死了没人收尸，爹没了没人管，主动隐居后台干活"——僵尸进程是子进程死了但父进程不来收尸，孤儿进程是爹没了被init收养，守护进程是主动脱离终端后台运行。本质都是操作系统进程生命周期管理的不同状态。

## 1. 为什么需要理解这些概念？

当你在 Linux 服务器上运行程序，可能会遇到：

```
$ ps aux | grep Z
user  1234  0.0  0.0   0  0  ?  Z  10:00  0:00 [myapp] <defunct>
```

这个 `<defunct>` 就是僵尸进程。不理解这些概念，就无法正确处理进程生命周期问题，严重时会导致系统无法创建新进程。

***

## 2. 僵尸进程（Zombie Process）

### 1. 定义

子进程**已终止**，但父进程**尚未调用 `wait()/waitpid()`** 回收其退出状态，此时子进程的进程控制块（PCB）仍留在内核中，这种进程就是僵尸进程。

### 2. 产生过程

```
子进程退出 → 内核保留其退出信息（PID、退出状态等）→ 父进程未读取 → 僵尸状态
```

### 3. 代码示例：产生僵尸进程

```c
#include <stdio.h>
#include <unistd.h>

int main() {
    pid_t pid = fork();

    if (pid == 0) {
        printf("子进程 %d 退出\n", getpid());
        _exit(0);
    } else {
        printf("父进程 %d 沉睡中...\n", getpid());
        sleep(60);  // 这60秒内，子进程就是僵尸
    }
    return 0;
}
```

用 `ps` 查看可见：

```
PID   STAT  COMMAND
1234  S     ./a.out        ← 父进程（Sleeping）
1235  Z     ./a.out <defunct>  ← 僵尸进程（Zombie）
```

### 4. 为什么危险

- 僵尸进程**不占CPU、不占内存**，但**占用PID号和PCB表项**
- 系统PID数量有限（通常32768个），大量僵尸会耗尽PID
- **导致无法创建新进程**

### 5. 处理方法

**方法一：父进程正确调用 `wait()/waitpid()`**

```c
pid_t pid = fork();
if (pid > 0) {
    int status;
    waitpid(pid, &status, 0);
}
```

**方法二：捕获 SIGCHLD 信号（异步回收，推荐）**

```c
#include <signal.h>

void sigchld_handler(int sig) {
    int status;
    while (waitpid(-1, &status, WNOHANG) > 0) {
        // 循环回收所有已退出的子进程
    }
}

int main() {
    struct sigaction sa;
    sa.sa_handler = sigchld_handler;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = SA_RESTART | SA_NOCLDSTOP;
    sigaction(SIGCHLD, &sa, NULL);

    // 之后fork的子进程退出时会自动被回收
}
```

**方法三：显式忽略 SIGCHLD**

```c
signal(SIGCHLD, SIG_IGN);  // 子进程退出后内核自动回收，不产生僵尸
```

> ⚠️ 注意：`SIG_IGN` 方式在部分 Unix 变体上行为不一致，可移植性不如方法二。

**方法四：杀死僵尸进程的父进程**

```bash
kill -9 <父进程PID>  # 父进程死后，僵尸变成孤儿，被init收养并自动回收
```

## 3. 孤儿进程（Orphan Process）

### 1. 定义

父进程**已终止**，而子进程**仍在运行**，此时子进程成为孤儿进程，被 **init 进程（PID=1）** 或现代系统的 **subreaper** 收养。

### 2. 产生过程

```
父进程退出 → 子进程还在运行 → 被init收养 → 孤儿进程
```

### 3. 代码示例：产生孤儿进程

```c
int main() {
    pid_t pid = fork();

    if (pid == 0) {
        while (1) {
            sleep(1);
        }
    } else {
        printf("父进程退出，子进程 %d 变成孤儿\n", pid);
        _exit(0);
    }
    return 0;
}
```

### 4. 危害

**孤儿进程本身无害！** init/subreaper 会负责在它退出时调用 `wait()` 回收。这是正常的进程生命周期现象。

### 5. 自定义收养逻辑

如果需要自定义收养逻辑，可以设置 subreaper（Linux 3.4+）：

```c
#include <sys/prctl.h>
prctl(PR_SET_CHILD_SUBREAPER, 1, 0, 0, 0);
```

## 4. 守护进程（Daemon Process）

### 1. 定义

守护进程是**在后台运行、没有控制终端、生命周期与系统一致**的特殊进程。名字来源于 "Disk And Execution MONitor"。

### 2. 产生过程（守护进程化步骤）

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/stat.h>
#include <fcntl.h>

int main() {
    // 第1步：fork() 并退出父进程
    pid_t pid = fork();
    if (pid > 0) _exit(0);
    if (pid < 0) exit(1);

    // 第2步：创建新会话，脱离控制终端
    if (setsid() < 0) exit(1);

    // 第3步：再次fork，防止重新打开终端
    pid = fork();
    if (pid > 0) _exit(0);
    if (pid < 0) exit(1);

    // 第4步：设置文件权限掩码
    umask(0);

    // 第5步：改变工作目录到根目录
    chdir("/");

    // 第6步：关闭所有继承的文件描述符
    for (int i = 0; i < sysconf(_SC_OPEN_MAX); i++) {
        close(i);
    }

    // 第7步：重定向 stdin/stdout/stderr 到 /dev/null
    open("/dev/null", O_RDWR);  // stdin  → fd 0
    dup(0);                      // stdout → fd 1
    dup(0);                      // stderr → fd 2

    // 现在是真正的守护进程
    while (1) {
        sleep(60);
        // 执行后台任务...
    }

    return 0;
}
```

### 3. 特征

- PPID = 1（被init收养）
- 没有控制终端（TTY = ?）
- 进程组ID和会话ID自成一组
- 工作目录通常是 `/`

```bash
ps -eo pid,ppid,sid,tty,comm | grep daemon
  PID  PPID   SID TT       COMMAND
 832     1   832 ?        my_daemon
```

## 5. 更多类似的特殊进程/线程

### 1. 僵尸线程（Zombie Thread）

与僵尸进程类似，线程退出后其资源（如返回值、栈信息）未被 `pthread_join()` 回收。

```c
void* thread_func(void* arg) {
    return (void*)42;
}

int main() {
    pthread_t tid;
    pthread_create(&tid, NULL, thread_func, NULL);
    // 不调用 pthread_join(tid, NULL);
    // 线程变成"僵尸线程"，资源不释放
    sleep(10);
    return 0;
}
```

**处理方式一**：调用 `pthread_join()`

```c
void* result;
pthread_join(tid, &result);
```

**处理方式二**：创建时设置 detached 属性

```c
pthread_attr_t attr;
pthread_attr_init(&attr);
pthread_attr_setdetachstate(&attr, PTHREAD_CREATE_DETACHED);
pthread_create(&tid, &attr, thread_func, NULL);
pthread_attr_destroy(&attr);
```

### 2. 会话首领（Session Leader）

创建新会话的进程。如果会话首领退出，其控制终端上的所有进程会收到 `SIGHUP`。

### 3. 进程组组长（Process Group Leader）

PID == PGID 的进程。用于信号分发（如 `kill -SIGINT -PGID` 发给整个进程组）。

### 4. 前台进程组 vs 后台进程组

| 类型 | 特征 | 终端信号 |
|------|------|---------|
| 前台进程组 | 与终端交互 | 接收 Ctrl+C (SIGINT)、Ctrl+Z (SIGTSTP) |
| 后台进程组 | 后台运行 | 不接收终端信号，读终端会被 SIGTTIN 暂停 |

## 6. 跨平台对比

这些概念**不是 Linux 独有**，几乎所有多进程操作系统都会遇到，但实现机制不同。

### 1. 僵尸进程

| 平台 | 情况 |
|------|------|
| Linux/Unix/macOS | 标准概念，子进程退出后PCB保留等待父进程wait() |
| Windows | **不存在传统僵尸进程**，Windows用引用计数管理内核对象，进程退出后所有句柄关闭即自动回收 |
| 嵌入式RTOS | 通常没有，因为进程模型不同 |

Windows 的等价问题：**句柄泄漏**

```c
// Windows: 不 CloseHandle() 导致内核对象残留（类似僵尸）
HANDLE hProcess = OpenProcess(PROCESS_QUERY_INFORMATION, FALSE, pid);
WaitForSingleObject(hProcess, INFINITE);
CloseHandle(hProcess);  // 必须关闭，否则内核对象残留
```

### 2. 孤儿进程

| 平台 | 情况 |
|------|------|
| Linux/Unix | 父进程退出 → 子进程被init(PID=1)收养 |
| macOS | 父进程退出 → 子进程被launchd收养 |
| Windows | **不存在孤儿问题**，进程天然独立，不依赖父进程存活 |

### 3. 守护进程

| 平台 | 等价物 | 启动方式 |
|------|--------|---------|
| Linux | Daemon | 脚本/systemd |
| macOS | launchd Daemon/Agent | plist配置文件 |
| Windows | Windows Service | SCM（服务控制管理器） |
| 嵌入式RTOS | 后台任务 | xTaskCreate() |

### 4. 根本设计差异

```
┌─────────────────────────────────────────────────────┐
│              Unix 进程模型                            │
│                                                       │
│  父进程 ──创建──→ 子进程                              │
│    │                    │                             │
│    │    必须由父进程回收 │                             │
│    │◄───wait()─────────┘                             │
│                                                       │
│  设计理念：进程树，父对子有管理责任                      │
│  副作用：父不负责 → 僵尸                              │
└─────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────┐
│              Windows 进程模型                          │
│                                                       │
│  创建者 ──CreateProcess──→ 新进程                      │
│    │                        │                         │
│    │    引用计数管理         │                         │
│    │    无强制回收义务       │                         │
│                                                       │
│  设计理念：进程独立，通过句柄和引用计数管理               │
│  副作用：句柄泄漏 → 内核对象残留                       │
└─────────────────────────────────────────────────────┘
```

## 7. 全景关系图

```
进程创建 (fork)
    │
    ├── 父进程先退出 ──→ 子进程成为【孤儿进程】──→ 被init收养（无害）
    │
    ├── 子进程先退出 ──→ 父进程未wait() ──→ 子进程成为【僵尸进程】（有害！）
    │                                    └──→ 父进程wait() ──→ 正常回收
    │
    ├── 脱离终端 ──→ 成为【守护进程】（有意为之，无害）
    │
    └── 线程退出 ──→ 未join() ──→ 成为【僵尸线程】（有害！）
```

## 8. 实战排查命令

```bash
# 查找僵尸进程
ps aux | grep 'Z'
ps -eo pid,ppid,stat,cmd | grep 'Z'

# 查找孤儿进程（PPID=1 且不是守护进程）
ps -eo pid,ppid,stat,cmd | awk '$2==1 && $3!~/Ss/'

# 查看守护进程
ps -eo pid,ppid,sid,tty,cmd | awk '$4=="?"'

# 杀死所有僵尸进程的父进程（强制回收）
ps -A -ostat,ppid | grep -e '^[Zz]' | awk '{print $2}' | xargs kill -9

# 统计僵尸进程数量
ps aux | awk '$8=="Z"' | wc -l
```

Windows 平台：

```powershell
# 查看句柄数（可能有句柄泄漏）
Get-Process -Id $pid | Select-Object HandleCount

# 查看服务
Get-Service
```

## 9. 总结对比

| 概念 | 一句话 | 危害 | 处理 |
|------|--------|------|------|
| **僵尸进程** | 死了但没人收尸 | 占PID，可能耗尽 | 父进程 `wait()` / 捕获 `SIGCHLD` |
| **孤儿进程** | 爹没了，被init收养 | **无害** | 无需处理 |
| **守护进程** | 主动脱离终端后台运行 | **无害** | 按需停止 |
| **僵尸线程** | 线程死了但没人join | 占资源 | `pthread_join()` 或 detached |
| **句柄泄漏**(Windows) | 进程死了但句柄没关 | 占内核对象 | `CloseHandle()` |

> **核心记忆**：僵尸有害要回收，孤儿无害init养，守护有意后台跑，线程同理要join。
