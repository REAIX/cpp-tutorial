# 僵尸进程、孤儿进程与守护进程
> 📖 相关章节：[进程与线程](../../01-C语言/23-进程与线程.md)、[多线程基础](../../02-CPP/27-多线程基础.md)

> "死了没人收尸，爹没了没人管，主动隐居后台干活"——三种进程状态，三种命运。

***

### 1. 通俗理解

想象一个家庭：

- **僵尸进程**：孩子已经去世了，但家长迟迟不来办手续领走遗体，遗体只能一直停在太平间占位置
- **孤儿进程**：家长去世了，孩子还在，被福利院（init 进程）收养，正常生活
- **守护进程**：一个人主动脱离家庭，隐居到深山老林，默默为社会做贡献

```
进程家族树：

init (PID=1)
  ├── sshd (守护进程)
  │     └── bash
  │           ├── ls (正常进程)
  │           └── 僵尸子进程 <defunct>  ← 危险！
  └── my_daemon (守护进程)
```

***

### 2. 僵尸进程（Zombie Process）

#### 什么是僵尸进程

子进程**已终止**，但父进程**尚未调用 `wait()/waitpid()`** 回收其退出状态，此时子进程的进程控制块（PCB）仍留在内核中，成为僵尸进程。

```
子进程退出 → 内核保留退出信息（PID、退出状态等）→ 父进程未读取 → 僵尸状态
```

#### 产生僵尸进程的代码

```c
#include <stdio.h>
#include <unistd.h>
#include <stdlib.h>

int main() {
    pid_t pid = fork();

    if (pid == 0) {
        // 子进程：立即退出
        printf("子进程 %d 退出\n", getpid());
        _exit(0);
    } else {
        // 父进程：不调用 wait()，沉睡 60 秒
        printf("父进程 %d 沉睡中...（子进程将变成僵尸）\n", getpid());
        sleep(60);
    }
    return 0;
}
```

运行后用 `ps` 查看：

```bash
PID   STAT  COMMAND
1234  S     ./a.out           ← 父进程（Sleeping）
1235  Z     ./a.out <defunct> ← 僵尸进程（Zombie）
```

#### 僵尸进程的危害

| 危害 | 说明 |
|------|------|
| 占用 PID | 系统PID数量有限（通常 32768 个） |
| 占用 PCB 表项 | 内核的进程表项被占用 |
| 耗尽 PID | 大量僵尸导致无法创建新进程 |
| 不占 CPU 和内存 | 僵尸进程不运行，不占 CPU 时间 |

> 僵尸进程本身不占 CPU 和内存，但它占用了 PID 和 PCB 表项。如果僵尸进程不断积累，最终会耗尽 PID，导致系统无法创建新进程。

#### 如何避免僵尸进程

**方法一：父进程调用 `wait()/waitpid()`**

```c
#include <stdio.h>
#include <unistd.h>
#include <sys/wait.h>

int main() {
    pid_t pid = fork();

    if (pid == 0) {
        printf("子进程 %d 执行任务\n", getpid());
        _exit(0);
    } else {
        int status;
        waitpid(pid, &status, 0);  // 阻塞等待子进程退出
        printf("子进程已回收，退出码: %d\n", WEXITSTATUS(status));
    }
    return 0;
}
```

**方法二：捕获 SIGCHLD 信号（推荐，异步回收）**

```c
#include <stdio.h>
#include <unistd.h>
#include <sys/wait.h>
#include <signal.h>

void sigchld_handler(int sig) {
    int status;
    // 循环回收所有已退出的子进程
    while (waitpid(-1, &status, WNOHANG) > 0) {
        printf("回收了一个子进程，退出码: %d\n", WEXITSTATUS(status));
    }
}

int main() {
    // 注册 SIGCHLD 信号处理器
    struct sigaction sa;
    sa.sa_handler = sigchld_handler;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = SA_RESTART | SA_NOCLDSTOP;
    sigaction(SIGCHLD, &sa, NULL);

    // 创建多个子进程
    for (int i = 0; i < 5; i++) {
        if (fork() == 0) {
            printf("子进程 %d 工作\n", getpid());
            sleep(1);
            _exit(i);
        }
    }

    // 父进程继续做其他事
    for (int i = 0; i < 10; i++) {
        printf("父进程工作中...\n");
        sleep(1);
    }
    return 0;
}
```

**方法三：显式忽略 SIGCHLD**

```c
#include <signal.h>

int main() {
    // 子进程退出后内核自动回收，不产生僵尸
    signal(SIGCHLD, SIG_IGN);

    if (fork() == 0) {
        _exit(0);  // 子进程退出后自动被回收
    }

    sleep(10);  // 不会产生僵尸进程
    return 0;
}
```

> ⚠️ `SIG_IGN` 方式在部分 Unix 变体上行为不一致，可移植性不如方法二。

**方法四：杀死父进程（紧急清理）**

```bash
# 杀死僵尸进程的父进程
kill -9 <父进程PID>
# 父进程死后，僵尸变成孤儿，被 init 收养并自动回收
```

#### 如何清理已有的僵尸进程

```bash
# 查找僵尸进程
ps aux | grep 'Z'
ps -eo pid,ppid,stat,cmd | grep 'Z'

# 统计僵尸进程数量
ps aux | awk '$8=="Z"' | wc -l

# 找到僵尸进程的父进程并杀死
ps -A -ostat,ppid | grep -e '^[Zz]' | awk '{print $2}' | xargs kill -9
```

### 3. 孤儿进程（Orphan Process）

#### 什么是孤儿进程

父进程**已终止**，而子进程**仍在运行**，此时子进程成为孤儿进程，被 **init 进程（PID=1）** 收养。

```
父进程退出 → 子进程还在运行 → 被init收养 → 孤儿进程
```

#### 产生孤儿进程的代码

```c
#include <stdio.h>
#include <unistd.h>
#include <stdlib.h>

int main() {
    pid_t pid = fork();

    if (pid == 0) {
        // 子进程：持续运行
        printf("子进程 %d 开始运行，父进程是 %d\n", getpid(), getppid());
        sleep(2);
        printf("子进程 %d 的父进程变成了 %d（被init收养）\n",
               getpid(), getppid());
        sleep(10);
        printf("子进程正常退出\n");
    } else {
        // 父进程：立即退出
        printf("父进程 %d 退出，子进程 %d 变成孤儿\n", getpid(), pid);
        _exit(0);
    }
    return 0;
}
```

#### 孤儿进程 vs 僵尸进程

| 对比 | 孤儿进程 | 僵尸进程 |
|------|---------|---------|
| 父进程状态 | 已终止 | 仍在运行 |
| 子进程状态 | 仍在运行 | 已终止 |
| 危害 | **无害** | 有害（占PID） |
| 处理方式 | init 自动收养并回收 | 需要父进程 wait() |
| 是否正常 | 正常现象 | 需要避免 |

> **核心区别**：孤儿进程是"爹没了"，init 会管；僵尸进程是"死了没人收尸"，必须等爹来收。

#### 自定义收养逻辑（subreaper）

Linux 3.4+ 支持设置 subreaper，让指定进程（而非 init）收养孤儿：

```c
#include <sys/prctl.h>
#include <signal.h>
#include <sys/wait.h>
#include <stdio.h>
#include <unistd.h>

int main() {
    // 设置当前进程为 subreaper
    prctl(PR_SET_CHILD_SUBREAPER, 1, 0, 0, 0);

    // 现在子进程的子进程如果变成孤儿，会被当前进程收养
    // 而不是被 init 收养

    while (1) {
        int status;
        pid_t pid = waitpid(-1, &status, WNOHANG);
        if (pid > 0) {
            printf("收养了孤儿进程 %d\n", pid);
        }
        sleep(1);
    }
    return 0;
}
```

### 4. 守护进程（Daemon Process）

#### 什么是守护进程

守护进程是**在后台运行、没有控制终端、生命周期与系统一致**的特殊进程。常见守护进程：sshd、nginx、crond、mysqld。

#### 守护进程的特征

| 特征 | 说明 |
|------|------|
| 后台运行 | 不占用终端 |
| 无控制终端 | TTY = ?，不受终端信号影响 |
| 独立会话 | 自成进程组/会话 |
| 父进程为 init | PPID = 1 |
| 工作目录为 `/` | 避免占用挂载点 |
| 文件描述符关闭 | 重定向到 `/dev/null` |

```bash
# 查看系统中的守护进程
ps -eo pid,ppid,sid,tty,comm | awk '$4=="?"'
```

#### 创建守护进程的基本步骤

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/stat.h>
#include <fcntl.h>

int main() {
    // 1. fork 并退出父进程
    pid_t pid = fork();
    if (pid > 0) _exit(0);
    if (pid < 0) exit(1);

    // 2. 创建新会话，脱离控制终端
    if (setsid() < 0) exit(1);

    // 3. 再次 fork，防止重新打开终端
    pid = fork();
    if (pid > 0) _exit(0);
    if (pid < 0) exit(1);

    // 4. 设置文件权限掩码
    umask(0);

    // 5. 改变工作目录到根目录
    chdir("/");

    // 6. 关闭所有继承的文件描述符
    for (int i = 0; i < sysconf(_SC_OPEN_MAX); i++) {
        close(i);
    }

    // 7. 重定向 stdin/stdout/stderr 到 /dev/null
    open("/dev/null", O_RDWR);  // stdin  → fd 0
    dup(0);                      // stdout → fd 1
    dup(0);                      // stderr → fd 2

    // 现在是真正的守护进程
    while (1) {
        sleep(60);
        // 执行后台任务...
    }

    return 0;
}
```

### 5. 信号处理（SIGCHLD）

SIGCHLD 是理解三种进程状态的关键信号：

| 事件 | 触发 SIGCHLD |
|------|-------------|
| 子进程终止 | ✅ |
| 子进程停止（SIGSTOP） | ✅ |
| 子进程继续（SIGCONT） | ✅（部分系统） |

**SIGCHLD 与僵尸进程的关系**：

```
子进程退出
  │
  ▼
内核向父进程发送 SIGCHLD
  │
  ├── 父进程捕获信号并调用 waitpid() → 僵尸被回收 ✅
  ├── 父进程忽略 SIGCHLD (SIG_IGN) → 内核自动回收 ✅
  └── 父进程未处理 → 子进程变成僵尸 ❌
```

**完整的 SIGCHLD 处理模板**：

```c
#include <stdio.h>
#include <unistd.h>
#include <sys/wait.h>
#include <signal.h>
#include <errno.h>

void sigchld_handler(int sig) {
    int saved_errno = errno;  // 保存 errno，防止被 waitpid 覆盖
    int status;

    // WNOHANG：非阻塞，没有子进程退出时返回 0
    while (waitpid(-1, &status, WNOHANG) > 0) {
        if (WIFEXITED(status)) {
            printf("子进程正常退出，退出码: %d\n", WEXITSTATUS(status));
        } else if (WIFSIGNALED(status)) {
            printf("子进程被信号杀死，信号: %d\n", WTERMSIG(status));
        }
    }

    errno = saved_errno;  // 恢复 errno
}

int main() {
    struct sigaction sa;
    sa.sa_handler = sigchld_handler;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = SA_RESTART | SA_NOCLDSTOP;
    // SA_RESTART: 自动重启被中断的系统调用
    // SA_NOCLDSTOP: 子进程停止时不发送 SIGCHLD
    sigaction(SIGCHLD, &sa, NULL);

    // 创建子进程
    for (int i = 0; i < 3; i++) {
        if (fork() == 0) {
            sleep(i + 1);
            _exit(i + 10);
        }
    }

    // 父进程继续工作
    for (int i = 0; i < 10; i++) {
        printf("父进程工作中...\n");
        sleep(1);
    }

    return 0;
}
```

### 6. 实际场景分析

#### 场景一：Web 服务器中的僵尸进程

```
主进程（Master）
  ├── Worker 1 → fork 处理请求 → 请求完成，Worker 退出
  ├── Worker 2 → fork 处理请求 → 请求完成，Worker 退出
  └── Worker 3 → fork 处理请求 → 请求完成，Worker 退出

如果主进程不 wait() → 大量僵尸进程 → PID 耗尽 → 服务器无法接受新连接
```

**正确做法**：

```c
// Nginx 风格：Master 进程捕获 SIGCHLD，回收 Worker
void master_sigchld_handler(int sig) {
    int status;
    pid_t pid;
    while ((pid = waitpid(-1, &status, WNOHANG)) > 0) {
        // Worker 异常退出，重新 fork 一个新的
        if (WIFSIGNALED(status)) {
            spawn_new_worker();
        }
    }
}
```

#### 场景二：Shell 中的后台进程

```bash
$ ./long_task &
[1] 12345

# long_task 的父进程是 bash
# 如果 bash 退出，long_task 变成孤儿，被 init 收养

$ exit
# long_task 继续运行（变成了孤儿进程，无害）
```

#### 场景三：守护进程启动时的双重 fork

```
终端启动 ./my_daemon
  │
  ├── fork() → 子进程1（父进程退出）
  │     │
  │     ├── setsid() → 新会话
  │     │
  │     └── fork() → 子进程2（子进程1退出）
  │           │
  │           └── 真正的守护进程
  │               PPID=1, 无控制终端
  │
  └── 终端可以继续使用
```

双重 fork 的目的：确保守护进程不是会话组长，永远无法重新获取控制终端。

### 7. 全景关系图

```
进程创建 (fork)
    │
    ├── 父进程先退出 ──→ 子进程成为【孤儿进程】──→ 被init收养（无害）
    │
    ├── 子进程先退出 ──→ 父进程未wait() ──→ 子进程成为【僵尸进程】（有害！）
    │                                    └──→ 父进程wait() ──→ 正常回收
    │
    ├── 脱离终端 ──→ 成为【守护进程】（有意为之，无害）
    │
    └── 线程退出 ──→ 未join() ──→ 成为【僵尸线程】（有害！）
```

### 8. 极简总结

| 概念 | 一句话 | 危害 | 处理 |
|------|--------|------|------|
| **僵尸进程** | 死了但没人收尸 | 占PID，可能耗尽 | 父进程 `wait()` / 捕获 `SIGCHLD` |
| **孤儿进程** | 爹没了，被init收养 | **无害** | 无需处理 |
| **守护进程** | 主动脱离终端后台运行 | **无害** | 按需停止 |

**记忆口诀**：僵尸有害要回收，孤儿无害init养，守护有意后台跑。

**排查命令速查**：

```bash
# 僵尸进程
ps aux | grep 'Z'
ps -eo pid,ppid,stat,cmd | grep 'Z'

# 孤儿进程
ps -eo pid,ppid,stat,cmd | awk '$2==1'

# 守护进程
ps -eo pid,ppid,sid,tty,cmd | awk '$4=="?"'
```
