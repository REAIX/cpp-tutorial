# 僵尸进程、孤儿进程与守护进程详解
> 📖 相关章节：[进程与线程](../../01-C语言/23-进程与线程.md)

> "死了没人收尸，爹没了没人管，主动隐居后台干活"——僵尸进程是子进程死了但父进程不来收尸，孤儿进程是爹没了被init收养，守护进程是主动脱离终端后台运行。本质都是操作系统进程生命周期管理的不同状态。

> **📖 本文定位**：聚焦僵尸进程、孤儿进程、守护进程三种进程状态的定义、产生原因、危害和处理方法，守护进程仅作概念介绍，不涉及创建步骤。
> 
> **🔗 相关阅读**：
> - [守护进程创建](10-守护进程创建.md) — 聚焦守护进程创建的7步标准流程、完整代码实现、syslog集成与systemd服务配置，与本文的概念介绍形成互补

***

## 1. 为什么需要理解这些概念？

当你在 Linux 服务器上运行程序，可能会遇到：

```
$ ps aux | grep Z
user  1234  0.0  0.0   0  0  ?  Z  10:00  0:00 [myapp] <defunct>
```

这个 `<defunct>` 就是僵尸进程。不理解这些概念，就无法正确处理进程生命周期问题，严重时会导致系统无法创建新进程。

***

## 2. 僵尸进程（Zombie Process）

### 1. 定义

子进程**已终止**，但父进程**尚未调用 `wait()/waitpid()`** 回收其退出状态，此时子进程的进程控制块（PCB）仍留在内核中，这种进程就是僵尸进程。

### 2. 产生过程

```
子进程退出 → 内核保留其退出信息（PID、退出状态等）→ 父进程未读取 → 僵尸状态
```

### 3. 代码示例：产生僵尸进程

```c
#include <stdio.h>
#include <unistd.h>

int main() {
    pid_t pid = fork();

    if (pid == 0) {
        printf("子进程 %d 退出\n", getpid());
        _exit(0);
    } else {
        printf("父进程 %d 沉睡中...\n", getpid());
        sleep(60);  // 这60秒内，子进程就是僵尸
    }
    return 0;
}
```

用 `ps` 查看可见：

```
PID   STAT  COMMAND
1234  S     ./a.out        ← 父进程（Sleeping）
1235  Z     ./a.out <defunct>  ← 僵尸进程（Zombie）
```

### 4. 为什么危险

- 僵尸进程**不占CPU、不占内存**，但**占用PID号和PCB表项**
- 系统PID数量有限（通常32768个），大量僵尸会耗尽PID
- **导致无法创建新进程**

### 5. 处理方法

**方法一：父进程正确调用 `wait()/waitpid()`**

```c
pid_t pid = fork();
if (pid > 0) {
    int status;
    waitpid(pid, &status, 0);
}
```

**方法二：捕获 SIGCHLD 信号（异步回收，推荐）**

```c
#include <signal.h>

void sigchld_handler(int sig) {
    int status;
    while (waitpid(-1, &status, WNOHANG) > 0) {
        // 循环回收所有已退出的子进程
    }
}

int main() {
    struct sigaction sa;
    sa.sa_handler = sigchld_handler;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = SA_RESTART | SA_NOCLDSTOP;
    sigaction(SIGCHLD, &sa, NULL);

    // 之后fork的子进程退出时会自动被回收
}
```

**方法三：显式忽略 SIGCHLD**

```c
signal(SIGCHLD, SIG_IGN);  // 子进程退出后内核自动回收，不产生僵尸
```

> ⚠️ 注意：`SIG_IGN` 方式在部分 Unix 变体上行为不一致，可移植性不如方法二。

**方法四：杀死僵尸进程的父进程**

```bash
kill -9 <父进程PID>  # 父进程死后，僵尸变成孤儿，被init收养并自动回收
```

## 3. 孤儿进程（Orphan Process）

### 1. 定义

父进程**已终止**，而子进程**仍在运行**，此时子进程成为孤儿进程，被 **init 进程（PID=1）** 或现代系统的 **subreaper** 收养。

### 2. 产生过程

```
父进程退出 → 子进程还在运行 → 被init收养 → 孤儿进程
```

### 3. 代码示例：产生孤儿进程

```c
int main() {
    pid_t pid = fork();

    if (pid == 0) {
        while (1) {
            sleep(1);
        }
    } else {
        printf("父进程退出，子进程 %d 变成孤儿\n", pid);
        _exit(0);
    }
    return 0;
}
```

### 4. 危害

**孤儿进程本身无害！** init/subreaper 会负责在它退出时调用 `wait()` 回收。这是正常的进程生命周期现象。

### 5. 自定义收养逻辑

如果需要自定义收养逻辑，可以设置 subreaper（Linux 3.4+）：

```c
#include <sys/prctl.h>
prctl(PR_SET_CHILD_SUBREAPER, 1, 0, 0, 0);
```

## 4. 守护进程（Daemon Process）

### 1. 定义

守护进程是**在后台运行、没有控制终端、生命周期与系统一致**的特殊进程。名字来源于 "Disk And Execution MONitor"。

### 2. 产生过程（守护进程化步骤）

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/stat.h>
#include <fcntl.h>

int main() {
    // 第1步：fork() 并退出父进程
    pid_t pid = fork();
    if (pid > 0) _exit(0);
    if (pid < 0) exit(1);

    // 第2步：创建新会话，脱离控制终端
    if (setsid() < 0) exit(1);

    // 第3步：再次fork，防止重新打开终端
    pid = fork();
    if (pid > 0) _exit(0);
    if (pid < 0) exit(1);

    // 第4步：设置文件权限掩码
    umask(0);

    // 第5步：改变工作目录到根目录
    chdir("/");

    // 第6步：关闭所有继承的文件描述符
    for (int i = 0; i < sysconf(_SC_OPEN_MAX); i++) {
        close(i);
    }

    // 第7步：重定向 stdin/stdout/stderr 到 /dev/null
    open("/dev/null", O_RDWR);  // stdin  → fd 0
    dup(0);                      // stdout → fd 1
    dup(0);                      // stderr → fd 2

    // 现在是真正的守护进程
    while (1) {
        sleep(60);
        // 执行后台任务...
    }

    return 0;
}
```

### 3. 特征

- PPID = 1（被init收养）
- 没有控制终端（TTY = ?）
- 进程组ID和会话ID自成一组
- 工作目录通常是 `/`

```bash
ps -eo pid,ppid,sid,tty,comm | grep daemon
  PID  PPID   SID TT       COMMAND
 832     1   832 ?        my_daemon
```

## 5. 更多类似的特殊进程/线程

### 1. 僵尸线程（Zombie Thread）

与僵尸进程类似，线程退出后其资源（如返回值、栈信息）未被 `pthread_join()` 回收。

```c
void* thread_func(void* arg) {
    return (void*)42;
}

int main() {
    pthread_t tid;
    pthread_create(&tid, NULL, thread_func, NULL);
    // 不调用 pthread_join(tid, NULL);
    // 线程变成"僵尸线程"，资源不释放
    sleep(10);
    return 0;
}
```

**处理方式一**：调用 `pthread_join()`

```c
void* result;
pthread_join(tid, &result);
```

**处理方式二**：创建时设置 detached 属性

```c
pthread_attr_t attr;
pthread_attr_init(&attr);
pthread_attr_setdetachstate(&attr, PTHREAD_CREATE_DETACHED);
pthread_create(&tid, &attr, thread_func, NULL);
pthread_attr_destroy(&attr);
```

### 2. 会话首领（Session Leader）

创建新会话的进程。如果会话首领退出，其控制终端上的所有进程会收到 `SIGHUP`。

### 3. 进程组组长（Process Group Leader）

PID == PGID 的进程。用于信号分发（如 `kill -SIGINT -PGID` 发给整个进程组）。

### 4. 前台进程组 vs 后台进程组

| 类型 | 特征 | 终端信号 |
|------|------|---------|
| 前台进程组 | 与终端交互 | 接收 Ctrl+C (SIGINT)、Ctrl+Z (SIGTSTP) |
| 后台进程组 | 后台运行 | 不接收终端信号，读终端会被 SIGTTIN 暂停 |

***

## 6. 跨平台对比

这些概念**不是 Linux 独有**，几乎所有多进程操作系统都会遇到，但实现机制不同。

### 1. 僵尸进程

| 平台 | 情况 |
|------|------|
| Linux/Unix/macOS | 标准概念，子进程退出后PCB保留等待父进程wait() |
| Windows | **不存在传统僵尸进程**，Windows用引用计数管理内核对象，进程退出后所有句柄关闭即自动回收 |
| 嵌入式RTOS | 通常没有，因为进程模型不同 |

Windows 的等价问题：**句柄泄漏**

```c
// Windows: 不 CloseHandle() 导致内核对象残留（类似僵尸）
HANDLE hProcess = OpenProcess(PROCESS_QUERY_INFORMATION, FALSE, pid);
WaitForSingleObject(hProcess, INFINITE);
CloseHandle(hProcess);  // 必须关闭，否则内核对象残留
```

### 2. 孤儿进程

| 平台 | 情况 |
|------|------|
| Linux/Unix | 父进程退出 → 子进程被init(PID=1)收养 |
| macOS | 父进程退出 → 子进程被launchd收养 |
| Windows | **不存在孤儿问题**，进程天然独立，不依赖父进程存活 |

### 3. 守护进程

| 平台 | 等价物 | 启动方式 |
|------|--------|---------|
| Linux | Daemon | 脚本/systemd |
| macOS | launchd Daemon/Agent | plist配置文件 |
| Windows | Windows Service | SCM（服务控制管理器） |
| 嵌入式RTOS | 后台任务 | xTaskCreate() |

### 4. 根本设计差异

```
┌─────────────────────────────────────────────────────┐
│              Unix 进程模型                            │
│                                                       │
│  父进程 ──创建──→ 子进程                              │
│    │                    │                             │
│    │    必须由父进程回收 │                             │
│    │◄───wait()─────────┘                             │
│                                                       │
│  设计理念：进程树，父对子有管理责任                      │
│  副作用：父不负责 → 僵尸                              │
└─────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────┐
│              Windows 进程模型                          │
│                                                       │
│  创建者 ──CreateProcess──→ 新进程                      │
│    │                        │                         │
│    │    引用计数管理         │                         │
│    │    无强制回收义务       │                         │
│                                                       │
│  设计理念：进程独立，通过句柄和引用计数管理               │
│  副作用：句柄泄漏 → 内核对象残留                       │
└─────────────────────────────────────────────────────┘
```

## 7. 全景关系图

```
进程创建 (fork)
    │
    ├── 父进程先退出 ──→ 子进程成为【孤儿进程】──→ 被init收养（无害）
    │
    ├── 子进程先退出 ──→ 父进程未wait() ──→ 子进程成为【僵尸进程】（有害！）
    │                                    └──→ 父进程wait() ──→ 正常回收
    │
    ├── 脱离终端 ──→ 成为【守护进程】（有意为之，无害）
    │
    └── 线程退出 ──→ 未join() ──→ 成为【僵尸线程】（有害！）
```

## 8. 实战排查命令

```bash
# 查找僵尸进程
ps aux | grep 'Z'
ps -eo pid,ppid,stat,cmd | grep 'Z'

# 查找孤儿进程（PPID=1 且不是守护进程）
ps -eo pid,ppid,stat,cmd | awk '$2==1 && $3!~/Ss/'

# 查看守护进程
ps -eo pid,ppid,sid,tty,cmd | awk '$4=="?"'

# 杀死所有僵尸进程的父进程（强制回收）
ps -A -ostat,ppid | grep -e '^[Zz]' | awk '{print $2}' | xargs kill -9

# 统计僵尸进程数量
ps aux | awk '$8=="Z"' | wc -l
```

Windows 平台：

```powershell
# 查看句柄数（可能有句柄泄漏）
Get-Process -Id $pid | Select-Object HandleCount

# 查看服务
Get-Service
```

## 9. 总结对比

| 概念 | 一句话 | 危害 | 处理 |
|------|--------|------|------|
| **僵尸进程** | 死了但没人收尸 | 占PID，可能耗尽 | 父进程 `wait()` / 捕获 `SIGCHLD` |
| **孤儿进程** | 爹没了，被init收养 | **无害** | 无需处理 |
| **守护进程** | 主动脱离终端后台运行 | **无害** | 按需停止 |
| **僵尸线程** | 线程死了但没人join | 占资源 | `pthread_join()` 或 detached |
| **句柄泄漏**(Windows) | 进程死了但句柄没关 | 占内核对象 | `CloseHandle()` |

> **核心记忆**：僵尸有害要回收，孤儿无害init养，守护有意后台跑，线程同理要join。

# 什么是守护进程创建步骤详解
> 📖 相关章节：[错误处理与信号](../../01-C语言/13-错误处理与信号.md)、[进程与线程](../../01-C语言/23-进程与线程.md)、[网络编程](../../02-CPP/31-网络编程.md)

> 守护进程是脱离终端、在后台长期运行的服务进程——创建它需要严谨的七步流程。

> **📖 本文定位**：聚焦守护进程创建的7步标准流程、完整代码实现、syslog集成与systemd服务配置，是守护进程的实战开发指南。

***

### 1. 本质速解

守护进程（Daemon）通过 fork 脱离终端、setsid 创建新会话、二次 fork 防止获取控制终端、关闭文件描述符等七步标准化流程，实现脱离终端的后台长期运行。

***

### 2. 守护进程的本质与特征

| 特征 | 说明 |
|------|------|
| 后台运行 | 不占用终端，不与终端交互 |
| 脱离控制终端 | 不受终端信号（SIGHUP 等）影响 |
| 独立会话 | 自成进程组/会话领导者 |
| 根目录 | 工作目录切换到 `/`，避免占用挂载点 |
| 文件描述符 | 关闭 0/1/2，重定向到 `/dev/null` |
| 父进程 | 父进程为 init（PID 1）或 systemd |

```
普通进程                          守护进程
┌──────────┐                  ┌──────────┐
│ 终端控制  │     七步转换     │ 无终端    │
│ 会话组长  │  ──────────→    │ 新会话    │
│ 前台运行  │                  │ 后台运行  │
│ 继承 FD  │                  │ FD 关闭   │
└──────────┘                  └──────────┘
```

***

### 3. 七步创建流程详解

```cpp
#include <cstdlib>
#include <cstdio>
#include <cstring>
#include <unistd.h>
#include <sys/types.h>
#include <sys/stat.h>
#include <signal.h>
#include <fcntl.h>

void daemonize() {
    // 第1步：fork 并退出父进程
    pid_t pid = fork();
    if (pid < 0) {
        perror("fork");
        exit(EXIT_FAILURE);
    }
    if (pid > 0) {
        exit(EXIT_SUCCESS);
    }

    // 第2步：创建新会话
    if (setsid() < 0) {
        perror("setsid");
        exit(EXIT_FAILURE);
    }

    // 第3步：忽略 SIGHUP（防止二次 fork 后终端断开时子进程退出）
    signal(SIGHUP, SIG_IGN);

    // 第4步：二次 fork，确保不会获取控制终端
    pid = fork();
    if (pid < 0) {
        perror("fork2");
        exit(EXIT_FAILURE);
    }
    if (pid > 0) {
        exit(EXIT_SUCCESS);
    }

    // 第5步：切换工作目录到根目录
    if (chdir("/") < 0) {
        perror("chdir");
        exit(EXIT_FAILURE);
    }

    // 第6步：关闭所有打开的文件描述符
    long maxfd = sysconf(_SC_OPEN_MAX);
    if (maxfd < 0) {
        maxfd = 1024;
    }
    for (long fd = 0; fd < maxfd; fd++) {
        close(fd);
    }

    // 第7步：重定向 stdin/stdout/stderr 到 /dev/null
    int fd0 = open("/dev/null", O_RDWR);
    dup2(fd0, STDIN_FILENO);
    dup2(fd0, STDOUT_FILENO);
    dup2(fd0, STDERR_FILENO);
    if (fd0 > 2) {
        close(fd0);
    }

    // 设置文件权限掩码
    umask(0);
}
```

**七步流程图：**

| 步骤 | 操作 | 目的 |
|------|------|------|
| 1 | `fork()` + 父进程退出 | 让子进程不是进程组组长（setsid 的前提） |
| 2 | `setsid()` | 创建新会话，脱离控制终端 |
| 3 | `signal(SIGHUP, SIG_IGN)` | 防止会话领导者退出时子进程收到 SIGHUP |
| 4 | 二次 `fork()` + 父进程退出 | 确保不是会话组长，无法重新获取控制终端 |
| 5 | `chdir("/")` | 避免占用挂载点，阻止卸载 |
| 6 | 关闭所有 FD | 释放继承的文件描述符 |
| 7 | 重定向 0/1/2 到 `/dev/null` | 防止读写操作失败 |

> **Linux 专属**：以上七步流程仅适用于 Linux/Unix 系统。Windows 不支持 fork 和 setsid，需使用 Windows Service API。

***

### 4. 每一步的深层原因

**第1步为什么必须 fork？**

`setsid()` 要求调用者不是进程组组长。从终端启动的进程默认是组长，fork 后的子进程不是组长，满足条件。

**第2步 setsid 做了什么？**

- 创建新会话（新会话 ID = 当前进程 PID）
- 创建新进程组（新进程组 ID = 当前进程 PID）
- 脱离控制终端

**第4步为什么需要二次 fork？**

即使调用了 `setsid()`，会话组长仍然可以通过 `open("/dev/tty", ...)` 重新获取控制终端。二次 fork 后的子进程不是会话组长，永远无法获取控制终端。

**第5步为什么切到根目录？**

如果守护进程工作目录是某个挂载点，会阻止该文件系统被卸载。切到 `/` 可避免此问题。

**第6步为什么关闭 FD？**

从父进程继承的 FD 会浪费资源，且可能导致文件系统无法卸载。

**第7步为什么重定向而非直接关闭？**

许多库函数假设 stdin/stdout/stderr 可用。如果关闭后不加处理，后续 `open()` 可能分配 fd=0，导致 `printf` 写入意外文件。

***

### 5. syslog 日志系统

守护进程脱离终端后无法使用 `printf`，需要通过 syslog 记录日志：

```cpp
#include <syslog.h>

void daemon_main() {
    openlog("mydaemon", LOG_PID | LOG_NDELAY, LOG_DAEMON);

    syslog(LOG_INFO, "守护进程启动, PID=%d", getpid());
    syslog(LOG_WARNING, "这是一条警告");
    syslog(LOG_ERR, "这是一条错误");

    while (true) {
        syslog(LOG_INFO, "执行定时任务...");
        sleep(60);
    }

    closelog();
}
```

| syslog 函数 | 作用 |
|-------------|------|
| `openlog(ident, option, facility)` | 打开日志连接 |
| `syslog(priority, format, ...)` | 写入日志 |
| `closelog()` | 关闭日志连接 |

**日志级别（从高到低）：**

| 级别 | 宏 | 含义 |
|------|-----|------|
| 紧急 | `LOG_EMERG` | 系统不可用 |
| 警报 | `LOG_ALERT` | 必须立即处理 |
| 严重 | `LOG_CRIT` | 严重错误 |
| 错误 | `LOG_ERR` | 错误 |
| 警告 | `LOG_WARNING` | 警告 |
| 通知 | `LOG_NOTICE` | 正常但重要 |
| 信息 | `LOG_INFO` | 信息 |
| 调试 | `LOG_DEBUG` | 调试信息 |

**日志文件位置**：通常在 `/var/log/syslog`（Debian/Ubuntu）或 `/var/log/messages`（CentOS/RHEL）。

### 6. PID 文件管理

PID 文件用于防止守护进程重复启动，并提供进程管理依据：

```cpp
#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <string.h>

int create_pid_file(const char* pid_file) {
    int fd = open(pid_file, O_RDWR | O_CREAT, 0644);
    if (fd < 0) {
        syslog(LOG_ERR, "无法创建 PID 文件: %s", pid_file);
        return -1;
    }

    struct flock fl;
    memset(&fl, 0, sizeof(fl));
    fl.l_type = F_WRLCK;
    fl.l_whence = SEEK_SET;
    fl.l_start = 0;
    fl.l_len = 0;

    if (fcntl(fd, F_SETLK, &fl) < 0) {
        if (errno == EACCES || errno == EAGAIN) {
            syslog(LOG_ERR, "守护进程已在运行");
            close(fd);
            return -1;
        }
    }

    char buf[32];
    snprintf(buf, sizeof(buf), "%d\n", getpid());
    ftruncate(fd, 0);
    write(fd, buf, strlen(buf));

    return 0;
}
```

| PID 文件要点 | 说明 |
|-------------|------|
| 位置 | `/var/run/mydaemon.pid` |
| 内容 | 仅一行，守护进程的 PID |
| 锁机制 | 使用 `flock` 文件锁防止重复启动 |
| 清理 | 进程退出时自动释放文件锁 |

### 7. systemd 服务配置

现代 Linux 推荐使用 systemd 管理守护进程，无需手动实现七步流程：

```ini
[Unit]
Description=My Daemon Service
After=network.target

[Service]
Type=simple
ExecStart=/usr/local/bin/mydaemon
Restart=on-failure
RestartSec=5
StandardOutput=syslog
StandardError=syslog
SyslogIdentifier=mydaemon

[Install]
WantedBy=multi-user.target
```

**systemd 管理命令：**

| 命令 | 作用 |
|------|------|
| `systemctl start mydaemon` | 启动服务 |
| `systemctl stop mydaemon` | 停止服务 |
| `systemctl restart mydaemon` | 重启服务 |
| `systemctl status mydaemon` | 查看状态 |
| `systemctl enable mydaemon` | 开机自启 |
| `journalctl -u mydaemon -f` | 查看实时日志 |

**systemd 下的守护进程简化写法：**

```cpp
#include <unistd.h>
#include <signal.h>
#include <syslog.h>
#include <stdlib.h>

static volatile sig_atomic_t running = 1;

void signal_handler(int sig) {
    if (sig == SIGTERM || sig == SIGINT) {
        running = 0;
    }
}

int main() {
    openlog("mydaemon", LOG_PID, LOG_DAEMON);

    signal(SIGTERM, signal_handler);
    signal(SIGINT, signal_handler);

    syslog(LOG_INFO, "服务启动");

    while (running) {
        syslog(LOG_INFO, "执行任务...");
        sleep(60);
    }

    syslog(LOG_INFO, "服务停止");
    closelog();
    return 0;
}
```

> **关键区别**：systemd 的 `Type=simple` 模式下，进程不需要 fork/setsid，systemd 自动完成守护化。

### 8. Windows 服务创建

Windows 使用完全不同的 Service API：

```cpp
#include <windows.h>
#include <stdio.h>

SERVICE_STATUS g_status;
SERVICE_STATUS_HANDLE g_status_handle;

void report_status(DWORD current_state, DWORD exit_code, DWORD wait_hint) {
    g_status.dwCurrentState = current_state;
    g_status.dwWin32ExitCode = exit_code;
    g_status.dwWaitHint = wait_hint;
    g_status.dwControlsAccepted =
        (current_state == SERVICE_RUNNING) ? SERVICE_ACCEPT_STOP : 0;
    SetServiceStatus(g_status_handle, &g_status);
}

void service_main(DWORD argc, LPSTR* argv) {
    g_status_handle = RegisterServiceCtrlHandlerA("MyService", NULL);
    ZeroMemory(&g_status, sizeof(g_status));
    g_status.dwServiceType = SERVICE_WIN32_OWN_PROCESS;

    report_status(SERVICE_START_PENDING, NO_ERROR, 3000);
    report_status(SERVICE_RUNNING, NO_ERROR, 0);

    while (g_status.dwCurrentState == SERVICE_RUNNING) {
        Sleep(60000);
    }
}

int main() {
    SERVICE_TABLE_ENTRYA table[] = {
        {(LPSTR)"MyService", (LPSERVICE_MAIN_FUNCTIONA)service_main},
        {NULL, NULL}
    };
    StartServiceCtrlDispatcherA(table);
    return 0;
}
```

**Linux vs Windows 守护进程对比：**

| 对比项 | Linux Daemon | Windows Service |
|--------|-------------|-----------------|
| 创建方式 | fork + setsid | RegisterServiceCtrlHandler |
| 日志系统 | syslog | Windows Event Log |
| 服务管理 | systemctl | sc / Services MMC |
| 配置文件 | .service 单元文件 | 注册表 + SCM |
| 信号机制 | SIGTERM/SIGHUP | HandlerEx 回调 |
| PID 管理 | PID 文件 | SCM 自动管理 |
| 自启动 | systemctl enable | sc config start=auto |

> **Windows 注意**：Windows 服务不能直接用 `main()` 运行，必须通过 `StartServiceCtrlDispatcher` 注册，否则 SCM 无法管理。

### 9. 进程监控与自动重启

生产环境需要守护进程的"守护者"：

```cpp
#include <unistd.h>
#include <sys/wait.h>
#include <syslog.h>
#include <stdlib.h>

void supervisor(const char* program) {
    openlog("supervisor", LOG_PID, LOG_DAEMON);

    while (1) {
        pid_t pid = fork();
        if (pid < 0) {
            syslog(LOG_ERR, "fork 失败");
            sleep(10);
            continue;
        }

        if (pid == 0) {
            execl(program, program, NULL);
            syslog(LOG_ERR, "execl 失败");
            exit(EXIT_FAILURE);
        }

        int status;
        waitpid(pid, &status, 0);

        if (WIFEXITED(status) && WEXITSTATUS(status) == 0) {
            syslog(LOG_INFO, "子进程正常退出");
            break;
        }

        syslog(LOG_WARNING, "子进程异常退出, 5秒后重启");
        sleep(5);
    }

    closelog();
}
```

| 监控方案 | 适用场景 |
|---------|---------|
| 自写 supervisor | 简单场景，学习用途 |
| systemd | 现代生产环境首选 |
| supervisord (Python) | 多语言混合服务 |
| Docker restart policy | 容器化部署 |

**systemd 自动重启配置：**

```ini
[Service]
Restart=on-failure
RestartSec=5s
StartLimitIntervalSec=300
StartLimitBurst=5
```

### 10. 常见 Bug 与排查

| Bug | 原因 | 解决方案 |
|-----|------|---------|
| 守护进程启动后立即退出 | 忘记 `setsid()` 或二次 fork 后父进程未退出 | 检查 fork 返回值处理 |
| 日志不输出 | 关闭 FD 前未 openlog，或重定向到 /dev/null | 在关闭 FD 之后再调用 `openlog()` |
| 重复启动 | 无 PID 文件或文件锁 | 使用 `flock` 文件锁 |
| 无法停止 | 未处理 SIGTERM 信号 | 注册信号处理器 |
| 僵尸进程 | 父进程未 waitpid | 忽略 SIGCHLD 或正确 wait |
| 文件系统无法卸载 | 工作目录未切到 `/` | `chdir("/")` |
| 权限错误 | umask 未设置 | `umask(0)` |
| 端口占用 | 前次进程未正常退出 | PID 文件 + 信号检查 |

**调试技巧：**

```bash
# 查看守护进程状态
ps aux | grep mydaemon

# 查看进程会话信息
ps -o pid,sid,tty,cmd -p <PID>

# 查看日志
tail -f /var/log/syslog | grep mydaemon

# 检查 PID 文件锁
fuser /var/run/mydaemon.pid

# strace 跟踪（调试启动问题）
strace -f -e trace=fork,setsid,open,close,dup2 ./mydaemon
```

### 11. 极简总结

| 步骤 | 操作 | 一句话原因 |
|------|------|-----------|
| 1 | fork + 父退出 | 让子进程不是组长，才能 setsid |
| 2 | setsid | 脱离终端，创建新会话 |
| 3 | 忽略 SIGHUP | 防止终端断开时子进程被杀 |
| 4 | 二次 fork + 父退出 | 确保永远无法获取控制终端 |
| 5 | chdir("/") | 避免占用挂载点 |
| 6 | 关闭所有 FD | 释放继承的资源 |
| 7 | 重定向 0/1/2 | 防止 stdio 操作异常 |

**记忆口诀**：一 fork 出子，二 setsid 脱离，三 忽 SIGHUP，四 再 fork 断终端，五 切根目录，六 关描述符，七 重定向空。

**平台选择**：Linux 用 systemd（推荐）或手动七步；Windows 用 Service API；容器环境用 Docker restart policy。
