# [守护进程创建](12-守护进程创建.md)实战
> 📖 相关章节：[进程与线程](../../01-C语言/23-进程与线程.md)、[错误处理与信号](../../01-C语言/13-错误处理与信号.md)

> 守护进程是脱离终端、在后台长期运行的服务进程——创建它需要严谨的七步流程。

***

### 1. 守护进程的概念与用途

守护进程（Daemon）是在后台持续运行、没有控制终端的特殊进程。它的名字来源于 Maxwell 的守护精灵——默默工作，不被注意。

**常见守护进程**：

| 守护进程 | 功能 |
|---------|------|
| sshd | SSH 远程登录服务 |
| nginx | Web 服务器 |
| crond | 定时任务调度 |
| mysqld | 数据库服务 |
| systemd | 系统服务管理 |
| rsyslogd | 系统日志服务 |

**守护进程 vs 普通后台进程**：

| 对比 | 守护进程 | 后台进程（&） |
|------|---------|-------------|
| 控制终端 | 无 | 仍关联终端 |
| 终端关闭后 | 继续运行 | 收到 SIGHUP 退出 |
| 会话 | 独立会话 | 属于原终端会话 |
| 标准输入 | /dev/null | 可操作 |
| 生命周期 | 长期运行 | 随终端关闭 |

```bash
# 后台进程：终端关闭就没了
$ ./my_app &

# 守护进程：终端关闭仍然运行
$ ./my_daemon
```

### 2. 经典创建步骤（七步法）详解

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/types.h>
#include <sys/stat.h>
#include <signal.h>
#include <fcntl.h>
#include <string.h>

void daemonize() {
    // ===== 第1步：fork 并退出父进程 =====
    pid_t pid = fork();
    if (pid < 0) {
        perror("fork");
        exit(EXIT_FAILURE);
    }
    if (pid > 0) {
        exit(EXIT_SUCCESS);  // 父进程退出，让子进程在后台运行
    }
    // 子进程继续

    // ===== 第2步：创建新会话 =====
    if (setsid() < 0) {
        perror("setsid");
        exit(EXIT_FAILURE);
    }
    // 此时子进程成为新会话的会话组长和新进程组的组长，脱离控制终端

    // ===== 第3步：忽略 SIGHUP =====
    signal(SIGHUP, SIG_IGN);
    // 防止第二次 fork 后，会话首领退出时子进程收到 SIGHUP

    // ===== 第4步：二次 fork =====
    pid = fork();
    if (pid < 0) {
        perror("fork2");
        exit(EXIT_FAILURE);
    }
    if (pid > 0) {
        exit(EXIT_SUCCESS);  // 第一次 fork 的子进程退出
    }
    // 第二次 fork 的子进程继续
    // 它不是会话组长，永远无法获取控制终端

    // ===== 第5步：设置文件权限掩码 =====
    umask(0);
    // 清除继承的权限掩码，让[守护进程创建](12-守护进程创建.md)文件时可以自由设置权限

    // ===== 第6步：切换工作目录到根目录 =====
    if (chdir("/") < 0) {
        perror("chdir");
        exit(EXIT_FAILURE);
    }
    // 避免守护进程占用某个挂载点，阻止文件系统卸载

    // ===== 第7步：关闭所有继承的文件描述符 =====
    long maxfd = sysconf(_SC_OPEN_MAX);
    if (maxfd < 0) {
        maxfd = 1024;  // 兜底值
    }
    for (long fd = 0; fd < maxfd; fd++) {
        close(fd);
    }

    // ===== 附加步骤：重定向 stdin/stdout/stderr =====
    int fd0 = open("/dev/null", O_RDWR);
    dup2(fd0, STDIN_FILENO);   // stdin  → /dev/null
    dup2(fd0, STDOUT_FILENO);  // stdout → /dev/null
    dup2(fd0, STDERR_FILENO);  // stderr → /dev/null
    if (fd0 > 2) {
        close(fd0);
    }
}
```

**七步流程图**：

| 步骤 | 操作 | 目的 |
|------|------|------|
| 1 | `fork()` + 父进程退出 | 让子进程不是进程组组长（setsid 的前提） |
| 2 | `setsid()` | 创建新会话，脱离控制终端 |
| 3 | `signal(SIGHUP, SIG_IGN)` | 防止会话领导者退出时子进程收到 SIGHUP |
| 4 | 二次 `fork()` + 父进程退出 | 确保不是会话组长，无法重新获取控制终端 |
| 5 | `umask(0)` | 清除权限掩码，允许自由设置文件权限 |
| 6 | `chdir("/")` | 避免占用挂载点，阻止卸载 |
| 7 | 关闭所有 FD + 重定向 0/1/2 | 释放继承资源，防止 stdio 操作异常 |

### 3. 双重 fork 技术深度解析

**为什么需要双重 fork？**

单次 fork + setsid 后，进程成为新会话的会话组长。会话组长有一个特权：可以通过 `open("/dev/tty", O_RDWR)` 重新获取控制终端。如果守护进程意外打开了终端设备，它就不再是"守护"的了。

```
单次 fork：
  原进程 → fork → 子进程 → setsid → 会话组长（可获取控制终端！）

双重 fork：
  原进程 → fork → 子进程1 → setsid → 会话组长 → fork → 子进程2
                                                          ↑
                                                    不是会话组长
                                                    无法获取控制终端 ✅
```

**验证双重 fork 的必要性**：

```c
#include <stdio.h>
#include <unistd.h>
#include <fcntl.h>

// 单次 fork 后尝试打开控制终端
void single_fork_test() {
    pid_t pid = fork();
    if (pid > 0) _exit(0);
    setsid();

    // 尝试获取控制终端
    int fd = open("/dev/tty", O_RDWR);
    if (fd >= 0) {
        printf("危险！单次 fork 后仍能获取控制终端\n");
        close(fd);
    } else {
        printf("安全，无法获取控制终端\n");
    }
}

// 双重 fork 后尝试打开控制终端
void double_fork_test() {
    pid_t pid = fork();
    if (pid > 0) _exit(0);
    setsid();

    pid = fork();
    if (pid > 0) _exit(0);

    int fd = open("/dev/tty", O_RDWR);
    if (fd >= 0) {
        printf("危险！双重 fork 后仍能获取控制终端\n");
        close(fd);
    } else {
        printf("安全，无法获取控制终端\n");
    }
}
```

### 4. Systemd 服务方式

现代 Linux 推荐使用 systemd 管理守护进程，无需手动实现七步流程。

#### systemd 服务配置文件

```ini
# /etc/systemd/system/mydaemon.service

[Unit]
Description=My Daemon Service
After=network.target        # 网络就绪后启动
Wants=network-online.target

[Service]
Type=simple                 # 主进程不 fork，systemd 自动管理
ExecStart=/usr/local/bin/mydaemon
ExecReload=/bin/kill -HUP $MAINPID
Restart=on-failure          # 异常退出时自动重启
RestartSec=5s               # 重启间隔
StandardOutput=syslog       # stdout 重定向到 syslog
StandardError=syslog        # stderr 重定向到 syslog
SyslogIdentifier=mydaemon

# 安全加固
NoNewPrivileges=true
ProtectSystem=strict
ProtectHome=true
PrivateTmp=true

[Install]
WantedBy=multi-user.target  # 多用户模式下启动
```

#### systemd 下的简化守护进程

```c
#include <unistd.h>
#include <signal.h>
#include <stdio.h>
#include <stdlib.h>

static volatile sig_atomic_t running = 1;

void signal_handler(int sig) {
    if (sig == SIGTERM || sig == SIGINT) {
        running = 0;
    }
}

int main() {
    // systemd 的 Type=simple 模式下，不需要 fork/setsid
    // systemd 自动完成守护化

    signal(SIGTERM, signal_handler);
    signal(SIGINT, signal_handler);

    printf("服务启动 (PID=%d)\n", getpid());

    while (running) {
        // 执行后台任务
        sleep(60);
    }

    printf("服务停止\n");
    return 0;
}
```

#### systemd 管理命令

| 命令 | 作用 |
|------|------|
| `systemctl start mydaemon` | 启动服务 |
| `systemctl stop mydaemon` | 停止服务 |
| `systemctl restart mydaemon` | 重启服务 |
| `systemctl status mydaemon` | 查看状态 |
| `systemctl enable mydaemon` | 开机自启 |
| `systemctl disable mydaemon` | 取消自启 |
| `journalctl -u mydaemon -f` | 查看实时日志 |
| `journalctl -u mydaemon --since "1 hour ago"` | 查看最近1小时日志 |

### 5. 日志系统（syslog）

守护进程脱离终端后无法使用 `printf`，需要通过 syslog 记录日志。

#### syslog 基本使用

```c
#include <syslog.h>
#include <unistd.h>
#include <stdio.h>
#include <signal.h>
#include <stdlib.h>

static volatile sig_atomic_t running = 1;

void signal_handler(int sig) {
    if (sig == SIGTERM || sig == SIGINT) {
        running = 0;
    }
}

int main() {
    // 打开日志连接
    openlog("mydaemon",          // 日志标识（程序名）
            LOG_PID | LOG_NDELAY, // 选项：包含PID，立即打开连接
            LOG_DAEMON);          // 设施类型：守护进程

    signal(SIGTERM, signal_handler);
    signal(SIGINT, signal_handler);

    syslog(LOG_INFO, "守护进程启动, PID=%d", getpid());

    int count = 0;
    while (running) {
        syslog(LOG_INFO, "执行定时任务 #%d", ++count);
        sleep(60);
    }

    syslog(LOG_INFO, "守护进程停止");
    closelog();
    return 0;
}
```

### 6. 信号处理

守护进程需要正确处理信号，才能优雅地停止和重新加载配置。

```c
#include <signal.h>
#include <unistd.h>
#include <syslog.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static volatile sig_atomic_t running = 1;
static volatile sig_atomic_t reload_config = 0;

void daemon_signal_handler(int sig) {
    switch (sig) {
    case SIGTERM:
    case SIGINT:
        running = 0;
        break;
    case SIGHUP:
        reload_config = 1;  // 请求重新加载配置
        break;
    case SIGUSR1:
        // 自定义信号：切换调试模式
        break;
    }
}

void load_config() {
    syslog(LOG_INFO, "加载配置文件");
    // 读取配置文件...
}

int main() {
    openlog("mydaemon", LOG_PID, LOG_DAEMON);

    // 注册信号处理器
    struct sigaction sa;
    memset(&sa, 0, sizeof(sa));
    sa.sa_handler = daemon_signal_handler;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = SA_RESTART;  // 自动重启被中断的系统调用

    sigaction(SIGTERM, &sa, NULL);
    sigaction(SIGINT, &sa, NULL);
    sigaction(SIGHUP, &sa, NULL);
    sigaction(SIGUSR1, &sa, NULL);

    load_config();
    syslog(LOG_INFO, "守护进程启动, PID=%d", getpid());

    while (running) {
        if (reload_config) {
            reload_config = 0;
            load_config();
            syslog(LOG_INFO, "配置已重新加载");
        }

        // 主循环：执行后台任务
        sleep(60);
    }

    syslog(LOG_INFO, "守护进程正常停止");
    closelog();
    return 0;
}
```

**守护进程常见信号处理**：

| 信号 | 含义 | 处理方式 |
|------|------|---------|
| SIGTERM | 请求终止 | 设置退出标志，优雅关闭 |
| SIGINT | Ctrl+C | 同 SIGTERM |
| SIGHUP | 终端断开 / 重新加载 | 重新读取配置文件 |
| SIGUSR1 | 用户自定义1 | 切换调试模式等 |
| SIGUSR2 | 用户自定义2 | 状态报告等 |
| SIGCHLD | 子进程退出 | waitpid 回收 |

### 7. 完整示例代码

以下是一个完整的守护进程示例，包含七步守护化、syslog 日志、信号处理和 PID 文件管理：

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/types.h>
#include <sys/stat.h>
#include <signal.h>
#include <fcntl.h>
#include <string.h>
#include <syslog.h>
#include <errno.h>

#define PID_FILE "/var/run/mydaemon.pid"

static volatile sig_atomic_t running = 1;
static volatile sig_atomic_t reload_config = 0;

void signal_handler(int sig) {
    switch (sig) {
    case SIGTERM:
    case SIGINT:
        running = 0;
        break;
    case SIGHUP:
        reload_config = 1;
        break;
    }
}

// 创建 PID 文件（防止重复启动）
int create_pid_file(const char* pid_file) {
    int fd = open(pid_file, O_RDWR | O_CREAT, 0644);
    if (fd < 0) {
        syslog(LOG_ERR, "无法创建 PID 文件: %s", pid_file);
        return -1;
    }

    // 使用文件锁防止重复启动
    struct flock fl;
    memset(&fl, 0, sizeof(fl));
    fl.l_type = F_WRLCK;
    fl.l_whence = SEEK_SET;
    fl.l_start = 0;
    fl.l_len = 0;

    if (fcntl(fd, F_SETLK, &fl) < 0) {
        if (errno == EACCES || errno == EAGAIN) {
            syslog(LOG_ERR, "守护进程已在运行");
            close(fd);
            return -1;
        }
    }

    char buf[32];
    snprintf(buf, sizeof(buf), "%d\n", getpid());
    ftruncate(fd, 0);
    write(fd, buf, strlen(buf));

    // 不关闭 fd，保持文件锁
    return 0;
}

// 七步守护化
void daemonize() {
    // 第1步：fork 并退出父进程
    pid_t pid = fork();
    if (pid < 0) { perror("fork"); exit(EXIT_FAILURE); }
    if (pid > 0) { exit(EXIT_SUCCESS); }

    // 第2步：创建新会话
    if (setsid() < 0) { perror("setsid"); exit(EXIT_FAILURE); }

    // 第3步：忽略 SIGHUP
    signal(SIGHUP, SIG_IGN);

    // 第4步：二次 fork
    pid = fork();
    if (pid < 0) { perror("fork2"); exit(EXIT_FAILURE); }
    if (pid > 0) { exit(EXIT_SUCCESS); }

    // 第5步：设置权限掩码
    umask(0);

    // 第6步：切换工作目录
    if (chdir("/") < 0) { perror("chdir"); exit(EXIT_FAILURE); }

    // 第7步：关闭所有 FD 并重定向
    long maxfd = sysconf(_SC_OPEN_MAX);
    if (maxfd < 0) maxfd = 1024;
    for (long fd = 0; fd < maxfd; fd++) {
        close(fd);
    }

    int fd0 = open("/dev/null", O_RDWR);
    dup2(fd0, STDIN_FILENO);
    dup2(fd0, STDOUT_FILENO);
    dup2(fd0, STDERR_FILENO);
    if (fd0 > 2) close(fd0);
}

int main() {
    // 守护化
    daemonize();

    // 打开日志（在关闭 FD 之后）
    openlog("mydaemon", LOG_PID | LOG_NDELAY, LOG_DAEMON);

    // 创建 PID 文件
    if (create_pid_file(PID_FILE) < 0) {
        syslog(LOG_ERR, "启动失败：无法创建 PID 文件");
        exit(EXIT_FAILURE);
    }

    // 注册信号处理器
    struct sigaction sa;
    memset(&sa, 0, sizeof(sa));
    sa.sa_handler = signal_handler;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = SA_RESTART;
    sigaction(SIGTERM, &sa, NULL);
    sigaction(SIGINT, &sa, NULL);
    sigaction(SIGHUP, &sa, NULL);

    syslog(LOG_INFO, "守护进程启动, PID=%d", getpid());

    // 主循环
    int task_count = 0;
    while (running) {
        if (reload_config) {
            reload_config = 0;
            syslog(LOG_INFO, "重新加载配置");
        }

        syslog(LOG_INFO, "执行任务 #%d", ++task_count);
        sleep(60);
    }

    // 清理
    unlink(PID_FILE);
    syslog(LOG_INFO, "守护进程停止");
    closelog();
    return 0;
}
```

### 8. 调试技巧

#### 调试守护进程的常见问题

| 问题 | 原因 | 排查方法 |
|------|------|---------|
| 启动后立即退出 | fork/setsid 失败 | `strace -f ./mydaemon` |
| 日志不输出 | 关闭 FD 前调用了 openlog | 在关闭 FD 之后再 openlog |
| 重复启动 | 无 PID 文件锁 | 使用 `flock` 文件锁 |
| 无法停止 | 未处理 SIGTERM | 注册信号处理器 |
| 僵尸子进程 | 未 waitpid | 忽略 SIGCHLD 或正确 wait |
| 文件系统无法卸载 | 工作目录未切到 `/` | `chdir("/")` |

#### 调试命令

```bash
# strace 跟踪系统调用（调试启动问题）
strace -f -e trace=fork,setsid,open,close,dup2 ./mydaemon

# 查看守护进程状态
ps -o pid,ppid,sid,tty,cmd -p <PID>

# 查看日志
tail -f /var/log/syslog | grep mydaemon
journalctl -u mydaemon -f

# 检查 PID 文件锁
fuser /var/run/mydaemon.pid

# 发送信号测试
kill -HUP <PID>   # 测试重新加载
kill -TERM <PID>  # 测试优雅停止

# 查看进程打开的文件
lsof -p <PID>

# 查看进程的工作目录
ls -l /proc/<PID>/cwd
```

#### 调试模式

```c
// 添加调试模式支持
#include <string.h>

int main(int argc, char* argv[]) {
    int debug_mode = 0;

    for (int i = 1; i < argc; i++) {
        if (strcmp(argv[i], "-d") == 0 || strcmp(argv[i], "--debug") == 0) {
            debug_mode = 1;
        }
    }

    if (!debug_mode) {
        daemonize();
        openlog("mydaemon", LOG_PID, LOG_DAEMON);
    } else {
        // 调试模式：前台运行，日志输出到终端
        printf("调试模式：前台运行\n");
        openlog("mydaemon", LOG_PID | LOG_PERROR, LOG_DAEMON);
        // LOG_PERROR: 同时输出到 stderr
    }

    // ... 主循环 ...
}
```

```bash
# 正常模式：后台守护进程
./mydaemon

# 调试模式：前台运行，方便调试
./mydaemon --debug
```

### 9. 极简总结

| 步骤 | 操作 | 一句话原因 |
|------|------|-----------|
| 1 | fork + 父退出 | 让子进程不是组长，才能 setsid |
| 2 | setsid | 脱离终端，创建新会话 |
| 3 | 忽略 SIGHUP | 防止终端断开时子进程被杀 |
| 4 | 二次 fork + 父退出 | 确保永远无法获取控制终端 |
| 5 | umask(0) | 清除权限掩码，自由设置文件权限 |
| 6 | chdir("/") | 避免占用挂载点 |
| 7 | 关闭 FD + 重定向 0/1/2 | 释放资源，防止 stdio 异常 |

**记忆口诀**：一 fork 出子，二 setsid 脱离，三 忽 SIGHUP，四 再 fork 断终端，五 清掩码，六 切根目录，七 关描述符重定向。

| 平台 | 推荐方式 |
|------|---------|
| 现代 Linux | systemd（推荐） |
| 传统 Linux | 手动七步 |
| Windows | Windows Service API |
| 容器环境 | Docker restart policy |
