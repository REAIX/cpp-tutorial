# 跨平台是什么意思
> 📖 相关章节：[编译与链接](../../01-C语言/17-编译与链接.md)、[CMake基础](../../04-工程实践/开发环境/03-CMake基础入门.md)

> **📖 本文定位**：聚焦跨平台的概念与实现方法——条件编译、抽象层、CMake、跨平台库，以及平台检测宏和抽象层设计。
>
> **🔗 相关阅读**：
> - [不同平台C与CPP的区别与可移植性](11-C与CPP的跨平台可移植性.md) — 聚焦不可移植的原因分析与可移植编码原则，与本文的"概念与实现"互补

### 1. 核心提炼

**跨平台** = 同一份代码能在不同操作系统/硬件架构上编译运行。三个层次：**源码级**（重新编译）、**二进制级**（直接运行）、**Web级**（浏览器运行）。C/C++ 是源码级跨平台。

***

### 2. 三个层次

| 层次 | 方式 | 示例 | 原理 |
|------|------|------|------|
| 源码级跨平台 | 同一份源码，不同平台编译 | C/C++ | 编译器为每个平台生成不同的机器码 |
| 二进制级跨平台 | 编译一次，到处运行 | Java | 字节码在虚拟机上运行 |
| Web级跨平台 | 浏览器运行 | JavaScript/WebAssembly | 浏览器屏蔽平台差异 |

C/C++ 是**源码级跨平台**，不是二进制级。Windows 上编译的 `.exe` 无法在 Linux 上运行。

```
源码级：  源码 → [Windows编译器] → Windows可执行文件
          源码 → [Linux编译器]   → Linux可执行文件
          源码 → [macOS编译器]   → macOS可执行文件

二进制级：源码 → [javac] → 字节码 → [Windows JVM] → 运行
                                        [Linux JVM]  → 运行
                                        [macOS JVM]  → 运行
```

### 3. 四种实现方法

#### 1. 方法1：条件编译

用预处理器宏在编译期选择平台相关代码：

```cpp
// 平台检测
#ifdef _WIN32
    #define PLATFORM_WINDOWS 1
#elif defined(__linux__)
    #define PLATFORM_LINUX 1
#elif defined(__APPLE__)
    #define PLATFORM_MACOS 1
#elif defined(__FreeBSD__)
    #define PLATFORM_FREEBSD 1
#else
    #define PLATFORM_UNKNOWN 1
#endif

// 条件编译选择实现
#ifdef PLATFORM_WINDOWS
    #include <windows.h>
    void sleep_ms(unsigned int ms) { Sleep(ms); }

    void create_directory(const std::string& path) {
        CreateDirectoryA(path.c_str(), nullptr);
    }

#elif defined(PLATFORM_LINUX) || defined(PLATFORM_MACOS)
    #include <unistd.h>
    #include <sys/stat.h>
    void sleep_ms(unsigned int ms) { usleep(ms * 1000); }

    void create_directory(const std::string& path) {
        mkdir(path.c_str(), 0755);
    }
#endif
```

**编译器检测**：

```cpp
// 编译器检测
#if defined(_MSC_VER)
    // MSVC
#elif defined(__GNUC__)
    // GCC
#elif defined(__clang__)
    // Clang
#endif

// 架构检测
#if defined(_M_X64) || defined(__x86_64__)
    // x86-64
#elif defined(_M_ARM64) || defined(__aarch64__)
    // ARM64
#elif defined(__arm__)
    // ARM32
#endif
```

#### 2. 方法2：抽象层（Platform Abstraction Layer）

将平台相关代码封装到统一接口后面：

```cpp
// platform.h — 统一接口
#pragma once
#include <string>
#include <vector>

class IFileSystem {
public:
    virtual ~IFileSystem() = default;
    virtual bool exists(const std::string& path) = 0;
    virtual bool create_directory(const std::string& path) = 0;
    virtual std::vector<std::string> list_files(const std::string& dir) = 0;
    virtual std::string read_file(const std::string& path) = 0;
    virtual bool write_file(const std::string& path, const std::string& content) = 0;
};

class IThread {
public:
    virtual ~IThread() = default;
    virtual void start() = 0;
    virtual void join() = 0;
    virtual void sleep_ms(unsigned int ms) = 0;
};

// 工厂函数
std::unique_ptr<IFileSystem> create_filesystem();
std::unique_ptr<IThread> create_thread();
```

```cpp
// platform_windows.cpp
#include "platform.h"
#include <windows.h>

class WinFileSystem : public IFileSystem {
public:
    bool exists(const std::string& path) override {
        return GetFileAttributesA(path.c_str()) != INVALID_FILE_ATTRIBUTES;
    }
    bool create_directory(const std::string& path) override {
        return CreateDirectoryA(path.c_str(), nullptr) != 0;
    }
    // ... 其他实现
};

std::unique_ptr<IFileSystem> create_filesystem() {
    return std::make_unique<WinFileSystem>();
}
```

```cpp
// platform_linux.cpp
#include "platform.h"
#include <sys/stat.h>
#include <dirent.h>

class LinuxFileSystem : public IFileSystem {
public:
    bool exists(const std::string& path) override {
        struct stat st;
        return stat(path.c_str(), &st) == 0;
    }
    bool create_directory(const std::string& path) override {
        return mkdir(path.c_str(), 0755) == 0;
    }
    // ... 其他实现
};

std::unique_ptr<IFileSystem> create_filesystem() {
    return std::make_unique<LinuxFileSystem>();
}
```

**业务代码只依赖抽象接口**：

```cpp
// 业务代码 — 完全不关心平台
void app_init() {
    auto fs = create_filesystem();
    if (!fs->exists("/data/config")) {
        fs->create_directory("/data/config");
    }
}
```

#### 3. 方法3：CMake 跨平台构建

CMake 是 C/C++ 跨平台构建的标准工具：

```cmake
cmake_minimum_required(VERSION 3.20)
project(MyApp VERSION 1.0 LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)

# 源文件
set(SOURCES
    src/main.cpp
    src/app.cpp
)

# 平台相关源文件
if(WIN32)
    list(APPEND SOURCES src/platform_windows.cpp)
elseif(UNIX)
    list(APPEND SOURCES src/platform_linux.cpp)
endif()

add_executable(myapp ${SOURCES})

# 平台相关链接库
if(WIN32)
    target_link_libraries(myapp PRIVATE ws2_32)   # Windows 网络
elseif(UNIX)
    target_link_libraries(myapp PRIVATE pthread)   # Linux 线程
    target_link_libraries(myapp PRIVATE dl)        # 动态加载
endif()

# 平台相关编译选项
if(MSVC)
    target_compile_options(myapp PRIVATE /W4 /utf-8)
else()
    target_compile_options(myapp PRIVATE -Wall -Wextra -Wpedantic)
endif()

# 安装规则（跨平台）
install(TARGETS myapp DESTINATION bin)
```

```cmake
# 跨平台查找库
find_package(Threads REQUIRED)
target_link_libraries(myapp PRIVATE Threads::Threads)

# 条件编译定义
if(CMAKE_BUILD_TYPE STREQUAL "Debug")
    target_compile_definitions(myapp PRIVATE DEBUG_MODE)
endif()

# 跨平台生成文件路径
set(CONFIG_DIR "${CMAKE_CURRENT_SOURCE_DIR}/config")
target_compile_definitions(myapp PRIVATE CONFIG_DIR="${CONFIG_DIR}")
```

#### 4. 方法4：跨平台库

| 库 | 用途 | 跨平台方式 |
|------|------|-----------|
| Qt | GUI + 系统抽象 | 内部封装平台差异 |
| SDL | 游戏开发 | 内部封装平台差异 |
| Boost | 通用库 | 内部封装平台差异 |
| POSIX | 类Unix统一接口 | Linux/macOS 共用 |

| spdlog | 日志 | 纯头文件 |
| fmt | 格式化 | 纯头文件 |

```cpp
// 使用跨平台库替代平台相关代码
#include <filesystem>  // C++17 文件系统，跨平台
#include <thread>      // C++11 线程，跨平台
#include <chrono>      // C++11 时间，跨平台

// 不再需要条件编译！
void cross_platform_code() {
    // 创建目录 — 跨平台
    std::filesystem::create_directory("data");

    // 休眠 — 跨平台
    std::this_thread::sleep_for(std::chrono::milliseconds(100));

    // 获取文件大小 — 跨平台
    auto size = std::filesystem::file_size("config.txt");
}
```

### 4. 常见平台差异

#### 1. 文件系统差异

| 差异 | Windows | Linux/macOS |
|------|---------|-------------|
| 路径分隔符 | `\`（反斜杠） | `/`（斜杠） |
| 换行符 | `\r\n`（CRLF） | `\n`（LF） |
| 绝对路径 | `C:\Users\...` | `/home/user/...` |
| 环境变量分隔符 | `;` | `:` |
| 动态库后缀 | `.dll` | `.so` / `.dylib` |
| 可执行文件后缀 | `.exe` | 无后缀 |
| 文件名大小写 | 不敏感 | 敏感 |

```cpp
// 路径处理：使用 std::filesystem（C++17）
#include <filesystem>

// 正确：使用 path 自动处理分隔符
std::filesystem::path dir = "data";
std::filesystem::path file = dir / "config" / "settings.json";
// Windows: "data\\config\\settings.json"
// Linux:   "data/config/settings.json"

// 错误：硬编码路径分隔符
std::string path = "data\\config\\settings.json";  // Linux 上失败
```

#### 2. 系统 API 差异

| 功能 | Windows | Linux/macOS |
|------|---------|-------------|
| 线程 | `CreateThread` | `pthread_create` |
| 网络 | Winsock (`WSAStartup`) | BSD socket |
| 动态加载 | `LoadLibrary` | `dlopen` |
| 进程 | `CreateProcess` | `fork` + `exec` |
| 共享内存 | `CreateFileMapping` | `shm_open` / `mmap` |
| 互斥锁 | `CRITICAL_SECTION` | `pthread_mutex` |

```cpp
// 网络：Winsock vs BSD socket
#ifdef _WIN32
    #include <winsock2.h>
    #include <ws2tcpip.h>
    #pragma comment(lib, "ws2_32.lib")
#else
    #include <sys/socket.h>
    #include <netinet/in.h>
    #include <arpa/inet.h>
    #include <unistd.h>
#endif

class SocketInit {
public:
    SocketInit() {
    #ifdef _WIN32
        WSADATA wsa;
        WSAStartup(MAKEWORD(2, 2), &wsa);
    #endif
    }
    ~SocketInit() {
    #ifdef _WIN32
        WSACleanup();
    #endif
    }
};

int socket_close(int fd) {
#ifdef _WIN32
    return closesocket(fd);
#else
    return close(fd);
#endif
}
```

#### 3. 编译器差异

| 差异 | MSVC | GCC/Clang |
|------|------|-----------|
| 编译选项 | `/O2`, `/W4` | `-O2`, `-Wall` |
| 导出符号 | `__declspec(dllexport)` | `__attribute__((visibility("default")))` |
| 对齐 | `__declspec(align(16))` | `__attribute__((aligned(16)))` |
| 内联汇编 | `__asm` | `asm()` |
| 警告控制 | `#pragma warning(disable:4996)` | `#pragma GCC diagnostic ignored "-W..."` |

```cpp
// 跨平台导出宏
#ifdef _WIN32
    #ifdef MYLIB_EXPORTS
        #define MYLIB_API __declspec(dllexport)
    #else
        #define MYLIB_API __declspec(dllimport)
    #endif
#else
    #define MYLIB_API __attribute__((visibility("default")))
#endif

class MYLIB_API MyClass {
public:
    void do_something();
};
```

### 5. CMake 跨平台配置完整示例

```cmake
cmake_minimum_required(VERSION 3.20)
project(CrossPlatformApp VERSION 1.0)

# C++ 标准
set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_CXX_EXTENSIONS OFF)

# 源文件
file(GLOB_RECURSE SOURCES "src/*.cpp")

# 平台检测与配置
message(STATUS "Platform: ${CMAKE_SYSTEM_NAME}")
message(STATUS "Compiler: ${CMAKE_CXX_COMPILER_ID}")

# 可执行文件
add_executable(myapp ${SOURCES})

# 包含目录
target_include_directories(myapp PRIVATE
    ${CMAKE_CURRENT_SOURCE_DIR}/include
)

# 平台相关配置
if(WIN32)
    message(STATUS "Configuring for Windows")
    target_compile_definitions(myapp PRIVATE
        PLATFORM_WINDOWS
        WIN32_LEAN_AND_MEAN
        NOMINMAX
    )
    target_link_libraries(myapp PRIVATE
        ws2_32      # 网络
        winmm       # 多媒体
        dbghelp     # 调试
    )
    # Windows 子系统
    if(NOT CMAKE_BUILD_TYPE STREQUAL "Debug")
        set_target_properties(myapp PROPERTIES
            WIN32_EXECUTABLE YES
        )
    endif()

elseif(APPLE)
    message(STATUS "Configuring for macOS")
    target_compile_definitions(myapp PRIVATE PLATFORM_MACOS)
    find_library(FOUNDATION Foundation)
    target_link_libraries(myapp PRIVATE ${FOUNDATION})

elseif(UNIX)
    message(STATUS "Configuring for Linux")
    target_compile_definitions(myapp PRIVATE PLATFORM_LINUX)
    target_link_libraries(myapp PRIVATE
        pthread     # 线程
        dl          # 动态加载
        rt          # 实时扩展
    )
endif()

# 编译器相关选项
if(MSVC)
    target_compile_options(myapp PRIVATE /W4 /utf-8 /permissive-)
    # 静态链接运行时
    set_property(TARGET myapp PROPERTY
        MSVC_RUNTIME_LIBRARY "MultiThreaded$<$<CONFIG:Debug>:Debug>")
else()
    target_compile_options(myapp PRIVATE
        -Wall -Wextra -Wpedantic -Werror
    )
endif()

# 安装
install(TARGETS myapp DESTINATION bin)
install(DIRECTORY include/ DESTINATION include)
```

### 6. Qt 跨平台开发

Qt 是 C++ 跨平台 GUI 开发的首选框架：

```cpp
#include <QApplication>
#include <QPushButton>
#include <QFile>
#include <QDir>
#include <QThread>

int main(int argc, char *argv[]) {
    QApplication app(argc, argv);

    // GUI — 自动适配平台风格
    QPushButton button("Hello Cross-Platform!");
    button.resize(200, 100);
    button.show();

    // 文件操作 — 跨平台
    QString config_path = QDir::homePath() + "/.myapp/config.ini";
    QFile config(config_path);
    if (config.open(QIODevice::ReadOnly)) {
        // 读取配置...
    }

    // 线程 — 跨平台
    QThread* thread = QThread::create([]() {
        QThread::msleep(1000);  // 跨平台休眠
    });
    thread->start();

    return app.exec();
}
```

### 7. 跨平台最佳实践

1. **优先使用标准库**：C++17 `<filesystem>`, `<thread>`, `<chrono>` 已经跨平台
2. **平台代码隔离**：将平台相关代码放在独立文件中
3. **用 CMake 管理**：不要手写 Makefile 或 .sln
4. **CI 多平台测试**：GitHub Actions 支持 Windows/Linux/macOS
5. **避免硬编码路径**：用 `std::filesystem::path` 拼接
6. **注意字节序**：网络传输用大端序，x86 是小端序

```cpp
// 字节序处理
#include <cstdint>
#include <cstring>

// 检测字节序
constexpr bool is_little_endian() {
    uint16_t x = 1;
    return *reinterpret_cast<uint8_t*>(&x) == 1;
}

// 主机序 → 网络序（大端）
uint32_t host_to_network(uint32_t val) {
    if constexpr (is_little_endian()) {
        return ((val & 0xFF000000) >> 24) |
               ((val & 0x00FF0000) >> 8)  |
               ((val & 0x0000FF00) << 8)  |
               ((val & 0x000000FF) << 24);
    }
    return val;
}
```

### 8. 常见陷阱

#### 1. 陷阱1：硬编码路径分隔符

```cpp
// 错误
std::string path = "data\\config\\settings.json";  // Linux 上失败

// 正确
std::filesystem::path path = "data" / "config" / "settings.json";
```

#### 2. 陷阱2：假设文件名大小写

```cpp
// 错误：Windows 不区分大小写，Linux 区分
#include "MyHeader.h"  // Windows 能找到 myheader.h，Linux 找不到

// 正确：文件名大小写与实际文件完全一致
#include "myheader.h"
```

#### 3. 陷阱3：忽略换行符差异

```cpp
// 错误：假设换行符是 \n
while (std::getline(file, line)) {
    // Windows 上行末可能有 \r
    if (!line.empty() && line.back() == '\r') {
        line.pop_back();  // 去掉 \r
    }
}
```

#### 4. 陷阱4：编译器扩展

```cpp
// 错误：使用 MSVC 特有扩展
__int64 big_num = 0;  // GCC 不识别

// 正确：使用标准类型
int64_t big_num = 0;  // #include <cstdint>
```

### 9. 极简总结

**跨平台 = 源码级（C/C++）→ 条件编译 + 抽象层 + CMake + 跨平台库**

| 方法 | 适用场景 | 复杂度 |
|------|----------|--------|
| 条件编译 | 少量平台差异 | 低 |
| 抽象层 | 大量平台差异 | 中 |
| CMake | 构建系统跨平台 | 中 |
| 跨平台库 | 通用功能 | 低 |
| C++17 标准库 | 文件系统/线程/时间 | 最低 |

> "可移植性=写一份代码，到哪都能跑——不可移植=换个平台就编译不过。"

***

### 1. 核心定义

- **平台** = CPU架构 + 操作系统 + 编译器的组合
- **可移植性** = 同一份代码在不同平台上都能正确编译和运行
- C/C++标准定义了"通用"部分，各平台有自己的扩展

***

### 2. 生活类比

**C/C++标准 = 国际驾照规则，各平台差异 = 各国交通法规**。

| 概念 | 类比 | 说明 |
|------|------|------|
| C/C++标准 | 国际驾照规则 | 基本规则统一 |
| 各平台差异 | 各国交通法规 | 靠左/靠右行驶、限速不同 |
| 可移植代码 | 遵守国际规则的驾驶 | 到哪国都能开 |
| 不可移植代码 | 只在本国有效的驾照 | 出国就不能用了 |

***

### 3. 主要平台差异

#### 1. CPU架构差异

| 维度 | x86_64 | ARM64 | RISC-V | 32位(x86) |
|------|--------|-------|--------|-----------|
| 字长 | 64位 | 64位 | 32/64位 | 32位 |
| 字节序 | 小端 | 可配置(通常小端) | 小端 | 小端 |
| 指针大小 | 8字节 | 8字节 | 4/8字节 | 4字节 |
| long大小 | 8字节(Linux)/4字节(Windows) | 8字节 | 8字节 | 4字节 |
| 对齐要求 | 较宽松 | 严格(必须对齐) | 较宽松 | 较宽松 |

#### 2. 操作系统差异

| 维度 | Linux | Windows | macOS |
|------|-------|---------|-------|
| 动态库 | .so | .dll | .dylib |
| 可执行文件 | ELF | PE/COFF | Mach-O |
| 线程API | pthread | Windows线程 | pthread |
| 网络API | POSIX socket | Winsock | POSIX socket |
| 文件路径 | / 分隔 | \ 分隔 | / 分隔 |
| 换行符 | LF(\n) | CRLF(\r\n) | LF(\n) |
| API风格 | POSIX | Win32 API | POSIX + Cocoa |

#### 3. 编译器差异

| 维度 | GCC/Clang | MSVC |
|------|-----------|------|
| 名称改编 | Itanium ABI | MSVC ABI |
| 模板支持 | 完整 | 部分限制 |
| 扩展 | __attribute__ | __declspec |
| 预定义宏 | __GNUC__/__clang__ | _MSC_VER |
| C99/C11支持 | 完整 | 部分支持 |

### 4. 为什么C/C++不通用

#### 1. 原因1：标准留了"实现定义"的空间

- `int`的大小：标准只要求≥16位，实际16/32/64位
- 字节序：标准未规定
- 结构体对齐：标准未规定填充规则

```cpp
#include <iostream>

struct Data {
    char a;
    int  b;
    short c;
};

int main() {
    std::cout << "sizeof(Data) = " << sizeof(Data) << "\n";
    std::cout << "sizeof(int)  = " << sizeof(int) << "\n";
    std::cout << "sizeof(long) = " << sizeof(long) << "\n";
    std::cout << "sizeof(void*)= " << sizeof(void*) << "\n";
    return 0;
}
```

同一结构体在不同平台的大小：

| 平台 | sizeof(Data) | sizeof(int) | sizeof(long) | sizeof(void*) |
|------|-------------|-------------|--------------|---------------|
| Linux x86_64 (GCC) | 12 | 4 | 8 | 8 |
| Windows x86_64 (MSVC) | 12 | 4 | 4 | 8 |
| Linux ARM64 (GCC) | 12 | 4 | 8 | 8 |
| 32位 x86 (GCC) | 12 | 4 | 4 | 4 |

#### 2. 原因2：各平台API不同

| 功能 | Linux/macOS | Windows |
|------|-------------|---------|
| 网络编程 | POSIX socket | Winsock |
| 多线程 | pthread | Windows线程 |
| 文件映射 | mmap | MapViewOfFile |
| 动态加载 | dlopen | LoadLibrary |

```cpp
#ifdef _WIN32
#include <windows.h>
#else
#include <dlfcn.h>
#endif

void* load_library(const char* name) {
#ifdef _WIN32
    return LoadLibraryA(name);
#else
    return dlopen(name, RTLD_LAZY);
#endif
}

void close_library(void* handle) {
#ifdef _WIN32
    FreeLibrary((HMODULE)handle);
#else
    dlclose(handle);
#endif
}
```

#### 3. 原因3：编译器扩展不兼容

```cpp
#ifdef __GNUC__
struct __attribute__((packed)) PackedData {
    char a;
    int  b;
};
#endif

#ifdef _MSC_VER
#pragma pack(push, 1)
struct PackedData {
    char a;
    int  b;
};
#pragma pack(pop)
#endif
```

#### 4. 原因4：ABI不兼容

- 名称改编（Name Mangling）规则不同
- 调用约定（Calling Convention）不同
- 异常处理机制不同
- 虚函数表布局可能不同

```cpp
void foo(int x);

// GCC/Clang改编后: _Z3fooi
// MSVC改编后:      ?foo@@YAXH@Z
```

### 5. 通用的是什么

#### 1. C标准库（跨平台通用）

| 头文件 | 核心函数 | 说明 |
|--------|---------|------|
| stdio.h | printf/fopen/fread | 输入输出 |
| stdlib.h | malloc/free/atoi | 内存与工具函数 |
| string.h | strcpy/memcpy/strlen | 字符串与内存操作 |
| math.h | sin/cos/sqrt | 数学函数 |
| time.h | time/clock | 时间函数 |

#### 2. C++标准库（跨平台通用）

| 类别 | 核心组件 | 说明 |
|------|---------|------|
| STL容器 | vector/map/string | 数据存储与管理 |
| 智能指针 | unique_ptr/shared_ptr | 自动内存管理 |
| 线程 | std::thread/mutex/atomic（C++11） | 多线程支持 |
| 文件系统 | std::filesystem（C++17） | 文件目录操作 |

#### 3. POSIX标准（Linux/macOS通用）

| 头文件 | 说明 |

| sys/socket.h | 网络套接字 |

### 6. 如何编写可移植代码

**原则1：使用标准库而非平台API**

```cpp
#include <filesystem>
#include <fstream>

namespace fs = std::filesystem;

void portable_file_ops() {
    fs::path p = fs::current_path() / "data" / "config.txt";
    fs::create_directories(p.parent_path());

    std::ofstream out(p);
    out << "hello\n";
}
```

**原则2：用条件编译处理平台差异**

```cpp
#ifdef _WIN32
    #define PLATFORM_NAME "Windows"
    #include <windows.h>
#elif defined(__linux__)
    #define PLATFORM_NAME "Linux"
    #include <unistd.h>
#elif defined(__APPLE__)
    #define PLATFORM_NAME "macOS"
    #include <unistd.h>
#else
    #define PLATFORM_NAME "Unknown"
#endif
```

**原则3：用typedef定义平台无关的类型**

```cpp
#include <cstdint>

int32_t  value32 = 42;
uint64_t value64 = 100;
int8_t   byte_val = 'A';
```

**原则4：用CMake等构建系统管理平台差异**

```cmake
cmake_minimum_required(VERSION 3.20)
project(PortableApp LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 17)

if(WIN32)
    target_compile_definitions(myapp PRIVATE WINDOWS_PLATFORM)
    target_link_libraries(myapp PRIVATE ws2_32)
elseif(UNIX)
    target_compile_definitions(myapp PRIVATE UNIX_PLATFORM)
    target_link_libraries(myapp PRIVATE pthread)
endif()
```

**原则5：用跨平台库（Boost/Qt/POCO）**

```cpp
#include <boost/asio.hpp>
#include <boost/filesystem.hpp>

void cross_platform_example() {
    namespace asio = boost::asio;
    namespace fs = boost::filesystem;

    asio::io_context io;
    fs::path p = fs::current_path();
}
```

### 8. 极简总结

**C/C++不通用因为：标准留了"实现定义"空间、各平台API不同、编译器扩展不兼容、ABI不同。通用的是：C/C++标准库、POSIX（Linux/macOS）、跨平台第三方库。可移植原则：用标准库、用int32_t等固定宽度类型、条件编译处理差异、用CMake管理构建。**

| 要点 | 一句话 |
|------|--------|
| 不通用的原因 | 标准留空间 + API不同 + 编译器扩展不兼容 + ABI不同 |
| 通用部分 | C/C++标准库 + POSIX + 跨平台第三方库 |
| 类型安全 | 用int32_t/uint64_t而非int/long |
| 平台差异 | 用条件编译（#ifdef）处理 |
| 构建管理 | 用CMake管理平台差异 |
| 第三方库 | Boost/Qt/libcurl/spdlog/protobuf |
