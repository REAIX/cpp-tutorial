# 如何实现跨语言调用
> 📖 相关章节：[编码规范](../../04-工程实践/00-编码规范.md)、[设计模式](../../04-工程实践/03-设计模式.md)、[单元测试](../../04-工程实践/06-单元测试.md)、[代码审查](../../04-工程实践/08-代码审查.md)

> "语言是工具，不是牢笼"——C ABI 是所有编程语言的通用翻译协议，掌握了它，任何语言都能互相调用。

***

### 1. 核心定义

**跨语言调用** = 一种编程语言调用另一种语言编写的函数/库。

| | 其他语言调 C/C++ | C/C++ 调其他语言 |
|---|---|---|
| 方向 | Python/Rust/Java → C++ 库 | C++ → Python/Rust/Java 等 |
| 常见度 | 非常常见（C++ 性能 + 其他语言生态） | 也完全可以，只是用得少一些 |
| 核心桥梁 | C ABI（调用约定 + 名称约定 + 内存布局） | C ABI + 各语言的嵌入 API |

**关键概念**：

| 概念 | 说明 |
|------|------|
| ABI 约定 | 二进制层面的"语言规则"，包括参数怎么传、返回值怎么收、函数名怎么编 |
| FFI（Foreign Function Interface） | 外部函数接口，一种语言调用另一种语言的机制 |
| Binding | 绑定代码，把一种语言的接口"翻译"成另一种语言能用的形式 |
| 共享库 | `.dll`（Windows）/ `.so`（Linux）/ `.dylib`（macOS），跨语言的"通关口岸" |

***

### 2. 生活类比

**跨语言调用 = 两个国家做生意**

| 概念 | 类比 | 说明 |
|------|------|------|
| C ABI | 国际贸易规则 | 所有国家都认可的通用规则 |
| FFI / Binding 生成器 | 翻译官 | 把一种语言的需求翻译成另一种语言能理解的 |
| 共享库（.dll/.so） | 通关口岸 | 两国交易的物理通道，货物必须从这里过 |
| extern "C" | 用英语签合同 | 英语是国际通用语，C ABI 是编程界的通用语 |

**具体场景**：

- **其他语言调 C++** = 外国公司来中国采购。中国工厂（C++ 库）按国际贸易规则（C ABI）生产商品，外国公司（Python/Rust/Java）通过海关（加载共享库）来进货。
- **C++ 调其他语言** = 中国公司去外国采购。完全可以！中国公司（C++）派翻译官（嵌入 API）去外国工厂（Python/Rust/Java）下单。

### 3. 其他语言调用 C/C++

#### 1. 方式1：extern "C" + 共享库（最通用）

**原理**：C 语言 ABI 是最通用的"国际语言"，几乎所有语言都支持调用 C 接口。

**步骤**：C++ 代码用 `extern "C"` 导出 → 编译为共享库 → 其他语言通过 FFI 加载。

```cpp
// ========== mathlib.h ==========
#pragma once

#ifdef __cplusplus
extern "C" {
#endif

int add(int a, int b);
double multiply(double a, double b);
const char* greet(const char* name);

#ifdef __cplusplus
}
#endif

// ========== mathlib.cpp ==========
#include "mathlib.h"
#include <cstring>

int add(int a, int b) {
    return a + b;
}

double multiply(double a, double b) {
    return a * b;
}

const char* greet(const char* name) {
    static char buf[256];
    snprintf(buf, sizeof(buf), "Hello, %s!", name);
    return buf;
}
```

编译为共享库：

```bash
# Linux
g++ -shared -fPIC -o libmathlib.so mathlib.cpp

# Windows
cl /LD mathlib.cpp /Fe:mathlib.dll

# macOS
g++ -shared -fPIC -o libmathlib.dylib mathlib.cpp
```

**Python 用 ctypes 调用**：

```python
from ctypes import CDLL, c_int, c_double, c_char_p

lib = CDLL("./libmathlib.so")

lib.add.argtypes = [c_int, c_int]
lib.add.restype = c_int
print(lib.add(3, 5))  # 输出: 8

lib.multiply.argtypes = [c_double, c_double]
lib.multiply.restype = c_double
print(lib.multiply(2.5, 4.0))  # 输出: 10.0

lib.greet.argtypes = [c_char_p]
lib.greet.restype = c_char_p
print(lib.greet(b"World"))  # 输出: b'Hello, World!'
```

**Rust 用 bindgen 调用**：

```rust
// build.rs 中用 bindgen 自动生成绑定
// 或者手动声明：
extern "C" {
    fn add(a: i32, b: i32) -> i32;
    fn multiply(a: f64, b: f64) -> f64;
}

fn main() {
    unsafe {
        println!("{}", add(3, 5));           // 输出: 8
        println!("{}", multiply(2.5, 4.0));  // 输出: 10.0
    }
}
```

#### 2. 方式2：SWIG（自动生成绑定）

**原理**：用接口描述文件（`.i`）自动生成 Python/Java/Ruby/C# 等语言的绑定代码。

**适用场景**：需要导出大量 C++ 类和方法，手动写 FFI 太累。

```
// mathlib.i（SWIG 接口文件）
%module mathlib
%{
#include "mathlib.h"
%}

%include "mathlib.h"
```

```bash
swig -python -c++ mathlib.i
# 自动生成 mathlib_wrap.cxx 和 mathlib.py
```

**优缺点**：

| | SWIG | 手写 FFI |
|---|---|---|
| 开发效率 | 高（自动生成） | 低（手动写绑定） |
| 灵活性 | 中（受生成器限制） | 高（完全控制） |
| 维护成本 | 中（改接口文件即可） | 高（每改一处手动更新） |
| 支持语言 | 十几种 | 逐个实现 |

#### 3. 方式3：pybind11（C++ → Python 专用）

**原理**：C++ 头文件 only 库，直接在 C++ 中写 Python 绑定，支持类、异常、STL 容器等。

```cpp
// ========== pybind11_example.cpp ==========
#include <pybind11/pybind11.h>
#include <pybind11/stl.h>
#include <string>
#include <vector>

namespace py = pybind11;

class Calculator {
public:
    Calculator() : result_(0) {}

    int add(int a, int b) {
        result_ = a + b;
        return result_;
    }

    int get_result() const { return result_; }

    void set_history(const std::vector<int>& h) { history_ = h; }
    std::vector<int> get_history() const { return history_; }

private:
    int result_;
    std::vector<int> history_;
};

PYBIND11_MODULE(calc, m) {
    m.doc() = "Calculator module";

    py::class_<Calculator>(m, "Calculator")
        .def(py::init<>())
        .def("add", &Calculator::add)
        .def_property_readonly("result", &Calculator::get_result)
        .def_property("history", &Calculator::get_history, &Calculator::set_history);
}
```

编译后 Python 直接用：

```python
from calc import Calculator

c = Calculator()
print(c.add(3, 5))    # 输出: 8
print(c.result)        # 输出: 8
c.history = [1, 2, 3]
print(c.history)       # 输出: [1, 2, 3]
```

#### 4. 方式4：JNI（C++ → Java 专用）

**原理**：Java Native Interface，Java 标准机制，C++ 实现native 方法。

```java
// HelloJNI.java
public class HelloJNI {
    static {
        System.loadLibrary("hello");
    }

    private native int add(int a, int b);
    private native String greet(String name);

    public static void main(String[] args) {
        HelloJNI jni = new HelloJNI();
        System.out.println(jni.add(3, 5));
        System.out.println(jni.greet("World"));
    }
}
```

```cpp
// hello_jni.cpp
#include <jni.h>
#include <cstring>

extern "C" {

JNIEXPORT jint JNICALL Java_HelloJNI_add(JNIEnv* env, jobject obj, jint a, jint b) {
    return a + b;
}

JNIEXPORT jstring JNICALL Java_HelloJNI_greet(JNIEnv* env, jobject obj, jstring name) {
    const char* cname = env->GetStringUTFChars(name, nullptr);
    char buf[256];
    snprintf(buf, sizeof(buf), "Hello, %s!", cname);
    env->ReleaseStringUTFChars(name, cname);
    return env->NewStringUTF(buf);
}

}
```

#### 5. 方式5：C ABI + 任何语言

只要能加载动态库并按 C 调用约定调用函数就行：

| 语言 | 机制 | 示例库/工具 |
|------|------|------------|
| Node.js | ffi-napi | `const lib = ffi.Library('./mathlib', { 'add': ['int', ['int', 'int']] })` |
| Go | cgo | `// #include "mathlib.h"` + `C.add(3, 5)` |
| C# | P/Invoke | `[DllImport("mathlib")] static extern int add(int a, int b);` |
| Swift | 直接导入 | `import mathlib` + 调用 C 函数 |
| Zig | @cImport | `const c = @cImport(@cInclude("mathlib.h"));` |

### 4. C/C++ 调用其他语言

#### 1. C++ 调用 Python

**方式1：Python C API（官方方式，嵌入 Python 解释器）**

```cpp
#include <Python.h>
#include <iostream>

int main() {
    Py_Initialize();

    PyRun_SimpleString(
        "def add(a, b):\n"
        "    return a + b\n"
    );

    PyObject* mainModule = PyImport_AddModule("__main__");
    PyObject* addFunc = PyObject_GetAttrString(mainModule, "add");

    PyObject* args = PyTuple_Pack(2, PyLong_FromLong(3), PyLong_FromLong(5));
    PyObject* result = PyObject_CallObject(addFunc, args);

    long value = PyLong_AsLong(result);
    std::cout << "3 + 5 = " << value << "\n";

    Py_DECREF(result);
    Py_DECREF(args);
    Py_DECREF(addFunc);
    Py_Finalize();
    return 0;
}
```

编译：`g++ -o call_python main.cpp $(python3-config --cflags --ldflags --embed)`

**方式2：pybind11（双向，也能从 C++ 调 Python）**

```cpp
#include <pybind11/embed.h>
#include <iostream>

namespace py = pybind11;

int main() {
    py::scoped_interpreter guard{};

    py::module_ math = py::module_::import("math");
    double result = math.attr("sqrt")(2.0).cast<double>();
    std::cout << "sqrt(2) = " << result << "\n";

    py::exec(R"(
def greet(name):
    return f"Hello, {name}!"
)");

    py::object greet = py::globals()["greet"];
    std::string msg = greet("C++").cast<std::string>();
    std::cout << msg << "\n";

    return 0;
}
```

#### 2. C++ 调用 Rust

**原理**：Rust 编译为 C ABI 共享库，C++ 通过 `extern "C"` 调用。

```rust
// ========== lib.rs ==========
#[no_mangle]
pub extern "C" fn rust_add(a: i32, b: i32) -> i32 {
    a + b
}

#[no_mangle]
pub extern "C" fn rust_greet(name: *const u8, len: usize) -> *mut u8 {
    let s = unsafe { std::slice::from_raw_parts(name, len) };
    let name_str = std::str::from_utf8(s).unwrap_or("???");
    let result = format!("Hello from Rust, {}!", name_str);
    let bytes = result.into_bytes();
    let ptr = bytes.as_ptr() as *mut u8;
    std::mem::forget(bytes);
    ptr
}
```

编译：`rustc --crate-type cdylib -o librustlib.so lib.rs`

```cpp
// ========== main.cpp ==========
#include <iostream>

extern "C" {
    int rust_add(int a, int b);
    unsigned char* rust_greet(const unsigned char* name, unsigned long len);
}

int main() {
    std::cout << rust_add(3, 5) << "\n";

    const char* name = "C++";
    auto msg = rust_greet(reinterpret_cast<const unsigned char*>(name), 3);
    std::cout << msg << "\n";

    return 0;
}
```

#### 3. C++ 调用 Java

**方式**：JNI 的 Invocation API（在 C++ 中启动 JVM）。

```cpp
#include <jni.h>
#include <iostream>

int main() {
    JavaVMInitArgs vmArgs;
    JavaVMOption options[1];
    options[0].optionString = const_cast<char*>("-Djava.class.path=.");
    vmArgs.version = JNI_VERSION_1_8;
    vmArgs.nOptions = 1;
    vmArgs.options = options;

    JavaVM* jvm;
    JNIEnv* env;
    JNI_CreateJavaVM(&jvm, reinterpret_cast<void**>(&env), &vmArgs);

    jclass cls = env->FindClass("java/lang/Math");
    jmethodID method = env->GetStaticMethodID(cls, "abs", "(I)I");
    jint result = env->CallStaticIntMethod(cls, method, -42);

    std::cout << "Java Math.abs(-42) = " << result << "\n";

    jvm->DestroyJavaVM();
    return 0;
}
```

#### 4. C++ 调用 Go

**原理**：Go 用 `//export` 注释导出 C 兼容函数，编译为共享库。

### 5. 跨语言调用的核心原理

#### 1. C ABI 是通用桥梁

几乎所有语言都理解 C 的调用约定。为什么？

| 原因 | 说明 |
|------|------|
| 历史地位 | C 是最早的系统级语言，操作系统 API 都是 C 接口 |
| 简单稳定 | C 的调用约定极简：参数压栈/走寄存器，返回值放寄存器 |
| 广泛支持 | 每种语言的 FFI 都优先支持 C ABI |

#### 2. 名称改编（Name Mangling）

| | C | C++ |
|---|---|---|
| 函数名 | 原样保留 `add` | 被改编为 `_Z3addii`（GCC）或 `?add@@YAHHH@Z`（MSVC） |
| 原因 | C 不支持重载，函数名唯一 | C++ 支持重载，必须编码参数信息 |
| 跨语言 | 直接按名字找就行 | 不同编译器改编规则不同，根本找不到 |

**所以跨语言调用必须用 `extern "C"` 禁用名称改编**。

#### 3. 内存管理：谁分配谁释放

```cpp
// 错误示范：C++ 分配，Python 释放 → 崩溃！
// C++ 端
char* make_string() {
    return new char[100];  // C++ 的 new 分配
}

// Python 端
lib.free_string(ptr)  // 调了 C 的 free？还是 C++ 的 delete？搞错就崩！
```

**原则**：

| 规则 | 说明 |
|------|------|
| 谁分配谁释放 | C++ 的 `new` 配 C++ 的 `delete`，Python 的 `malloc` 配 Python 的 `free` |
| 跨语言不混用分配器 | 每种语言/运行时有自己的内存管理，不能混用 |
| 提供释放函数 | C++ 库应该同时提供创建和销毁函数 |

```cpp
// 正确做法：C++ 库提供配对的创建/销毁函数
extern "C" {
    char* create_string();     // C++ 内部用 new 分配
    void free_string(char* s); // C++ 内部用 delete 释放
}
```

#### 4. 数据类型映射

| C/C++ 类型 | Python (ctypes) | Java (JNI) | Rust | Go (cgo) |
|------------|-----------------|------------|------|----------|
| int | c_int | jint | i32 | C.int |
| double | c_double | jdouble | f64 | C.double |
| char* | c_char_p | jstring | *const c_char | *C.char |
| void* | c_void_p | jobject | *mut c_void | unsafe.Pointer |
| struct* | Structure 子类 | jobject | 自定义 struct | C.struct_xxx |

**简单类型**（int/float/指针）通常直接通用，**复杂类型**（字符串/容器/对象）需要显式转换。

### 6. 跨语言调用对比表格

| 方向 | 方式 | 难度 | 性能 | 适用场景 |
|------|------|:----:|:----:|---------|
| 其他 → C++ | extern "C" + FFI | 低 | 高 | 通用，最常见 |
| 其他 → C++ | SWIG | 中 | 高 | 大量类导出 |
| Python ↔ C++ | pybind11 | 低 | 高 | Python 生态集成 |
| Java ↔ C++ | JNI | 高 | 中 | Java 生态集成 |
| C++ → Rust | C ABI | 低 | 高 | 安全模块 |
| C++ → Go | C ABI | 低 | 中 | 并发模块 |
| C++ → Python | Python C API | 中 | 低 | 脚本化/插件化 |

**性能说明**：

| 开销来源 | 说明 |
|---------|------|
| 函数调用开销 | FFI 调用比本地调用慢 10-100 倍（参数转换 + 栈切换） |
| 数据转换 | 字符串/容器转换是最大开销 |
| 解释器启动 | C++ 嵌入 Python/Java 需要启动解释器/JVM，一次性开销大 |
| 批量调用 | 尽量减少跨语言调用次数，一次传大量数据比多次传少量数据高效 |

### 7. 常见陷阱

#### 1. 陷阱1：内存管理混乱

```cpp
// C++ 端用 new 分配
extern "C" char* create_msg() {
    return new char[100];
}

// Python 端不能用 free() 释放！必须调用 C++ 提供的销毁函数
extern "C" void free_msg(char* msg) {
    delete[] msg;  // 必须用 delete[]，不能用 free()
}
```

**原则**：谁分配谁释放，跨语言绝不混用分配器。

#### 2. 陷阱2：异常不能跨语言边界传播

```cpp
// C++ 端抛异常
extern "C" int divide(int a, int b) {
    if (b == 0) throw std::runtime_error("division by zero");  // 危险！
    return a / b;
}

// Python 端调用 → 程序直接崩溃，异常无法传播到 Python
```

**正确做法**：用错误码替代异常。

```cpp
extern "C" int divide(int a, int b, int* error) {
    if (b == 0) {
        *error = 1;  // 用错误码通知调用方
        return 0;
    }
    *error = 0;
    return a / b;
}
```

#### 3. 陷阱3：字符串转换

每种语言的字符串表示不同：

| 语言 | 字符串表示 | 编码 |
|------|----------|------|
| C/C++ | `char*`（以 `\0` 结尾的字符数组） | UTF-8 / ASCII |
| Python 3 | `str`（Unicode 对象） | Unicode |
| Java | `jstring`（Java String 对象） | UTF-16 |
| Rust | `String`（Vec\<u8\> + UTF-8 保证） | UTF-8 |
| Go | `string`（slice + 长度，无 `\0`） | UTF-8 |

**跨语言传字符串必须显式转换**，不能直接传。

#### 4. 陷阱4：对象生命周期

```cpp
// C++ 端返回对象指针
extern "C" Calculator* create_calculator() {
    return new Calculator();  // C++ 堆上分配
}

// Python 端拿到指针，但 Python 的 GC 不知道这个对象的存在
// Python 对象被回收时，C++ 对象不会自动释放 → 内存泄漏！
```

**正确做法**：提供销毁函数，或用 pybind11 自动管理生命周期。

```python
from ctypes import CDLL, c_void_p

lib = CDLL("./libcalc.so")
lib.create_calculator.restype = c_void_p
lib.destroy_calculator.argtypes = [c_void_p]

calc = lib.create_calculator()
try:
    # 使用 calc ...
    pass
finally:
    lib.destroy_calculator(calc)  # 显式销毁
```

***

### 8. 极简总结

**C ABI 是跨语言的通用桥梁。其他语言调 C++ 用 `extern "C"` 导出共享库；C++ 调其他语言用各语言的嵌入 API。关键原则：谁分配谁释放，异常不跨边界，字符串要显式转换。**

| 方向 | 核心方法 | 一句话 |
|------|---------|--------|
| 其他 → C++ | extern "C" + 共享库 | C++ 按规则生产，其他语言来采购 |
| C++ → Python | Python C API / pybind11 | C++ 嵌入 Python 解释器 |
| C++ → Rust | C ABI | Rust 编译成 C 共享库 |
| C++ → Java | JNI Invocation API | C++ 启动 JVM |
| C++ → Go | C ABI | Go 导出 C 兼容函数 |
| 通用原则 | 谁分配谁释放 | 内存管理不能混 |
| 通用原则 | 异常用错误码 | 异常不能跨边界 |
| 通用原则 | 字符串显式转换 | 每种语言字符串表示不同 |
