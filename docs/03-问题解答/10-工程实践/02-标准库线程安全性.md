# 标准库线程安全性详解
> 📖 相关章节：[编码规范](../../04-工程实践/00-编码规范.md)、[设计模式](../../04-工程实践/03-设计模式.md)、[单元测试](../../04-工程实践/06-单元测试.md)、[代码审查](../../04-工程实践/08-代码审查.md)

> "标准库不帮你加锁，它只保证不同坑位能同时用。"

***

### 1. 核心定义

- **线程安全** = 多个线程同时访问某个对象，不需要额外同步，行为仍然正确
- C++标准库的线程安全规则非常明确，但很多人误解

***

### 2. 生活类比

**线程安全 = 公共厕所**

| 比喻 | 含义 |
|------|------|
| 线程安全 | 每个隔间有锁（内部同步），多人可以同时用不同隔间 |
| 线程不安全 | 只有一个大坑位没有门（无同步），多人同时用会出事 |
| 标准库的规则 | 同一个坑位不能同时用（同一对象不同线程同时写），但不同坑位可以同时用（不同对象可以并发访问） |

***

### 3. C++标准库线程安全规则（标准原文解读）

#### 1. 规则1：不同对象，安全

多个线程同时操作不同的容器对象，不需要同步。

```cpp
std::vector<int> vec_a;
std::vector<int> vec_b;

void thread1() { vec_a.push_back(1); }
void thread2() { vec_b.push_back(2); }
```

安全：thread1 用 vector A，thread2 用 vector B，互不干扰。

#### 2. 规则2：同一对象只读，安全

多个线程同时读取同一个容器（不修改），不需要同步。

```cpp
std::vector<int> vec = {1, 2, 3};

void thread1() { int x = vec[0]; }
void thread2() { int y = vec.size(); }
```

安全：多个线程同时调用 `vec.size()`、`vec[i]`，全是只读。

#### 3. 规则3：同一对象有写操作，不安全

只要有一个线程在修改（插入/删除/修改元素），其他线程同时访问（哪怕只读）都不安全。

```cpp
std::vector<int> vec = {1, 2, 3};

void thread1() { vec.push_back(4); }
void thread2() { int x = vec.size(); }
```

不安全！thread1 做 `push_back`，thread2 做 `size()`，可能读到中间状态。

#### 4. 规则4：标准库流对象，部分安全

| 流对象 | 线程安全性 | 说明 |
|--------|-----------|------|
| `cout`/`cerr` | ⚠️ 部分安全 | C++11 起，不同线程输出字符不会交错，但输出顺序不可预测 |
| `cin` | ❌ 不安全 | 需要同步 |
| 文件流 | ❌ 不安全 | 同一 stream 对象不安全 |

```cpp
void thread1() { std::cout << "hello"; }
void thread2() { std::cout << "world"; }
```

输出可能是 `helloworld`，也可能是 `worldhello`，但不会出现 `hweolrllod` 这种字符交错。

### 4. 各标准库组件的线程安全性

| 组件 | 不同对象 | 同一对象只读 | 同一对象有写 | 说明 |
|------|:---:|:---:|:---:|------|
| `vector` | ✅ 安全 | ✅ 安全 | ❌ 不安全 | `push_back` 可能导致重新分配，所有迭代器失效 |
| `map` | ✅ 安全 | ✅ 安全 | ❌ 不安全 | 插入/删除会修改红黑树 |
| `string` | ✅ 安全 | ✅ 安全 | ❌ 不安全 | COW 实现有特殊规则（C++11 后禁止 COW） |
| `cout` | - | - | ⚠️ 部分安全 | 字符不交错但顺序不确定 |
| `shared_ptr` | ✅ 安全 | ✅ 安全 | ✅ 引用计数安全 | 引用计数是原子的，但指向的对象不是 |
| `mutex` | ✅ 安全 | - | ✅ 安全 | 本身就是同步原语 |
| `atomic` | ✅ 安全 | ✅ 安全 | ✅ 安全 | 原子操作保证 |
| `function` | ✅ 安全 | ✅ 安全 | ❌ 不安全 | 调用和赋值不能并发 |

### 5. 如何判断线程安全性

**三步判断法：**

```
1. 是不是同一个对象？  → 不同对象 → 安全
2. 有没有写操作？      → 全部只读 → 安全
3. 有没有特殊保证？    → 查文档（如 shared_ptr 引用计数、atomic）
```

#### 1. 代码示例：安全和不安全的场景对比

```cpp
#include <iostream>
#include <vector>
#include <thread>
#include <mutex>
#include <atomic>
#include <memory>

std::vector<int> shared_vec;
std::mutex vec_mtx;

void safe_different_objects() {
    std::vector<int> local_vec;
    local_vec.push_back(42);
}

void safe_read_only() {
    std::vector<int> vec = {1, 2, 3};
    auto f1 = [&]() { int x = vec[0]; };
    auto f2 = [&]() { int y = vec.size(); };
    std::thread t1(f1);
    std::thread t2(f2);
    t1.join();
    t2.join();
}

void unsafe_concurrent_write() {
    auto writer = [&]() {
        for (int i = 0; i < 1000; ++i) {
            std::lock_guard<std::mutex> lock(vec_mtx);
            shared_vec.push_back(i);
        }
    };
    std::thread t1(writer);
    std::thread t2(writer);
    t1.join();
    t2.join();
}

int main() {
    safe_different_objects();
    safe_read_only();
    unsafe_concurrent_write();
    return 0;
}
```

### 6. 常见误区

#### 1. 误区1："const 方法就是线程安全的"

错！`const` 方法内部可能有 `mutable` 成员（如缓存），多线程调用仍不安全。

```cpp
class Cache {
    mutable int cache_value_ = 0;
    mutable bool cached_ = false;
    int expensive_compute() const { return 42; }
public:
    int get() const {
        if (!cached_) {
            cache_value_ = expensive_compute();
            cached_ = true;
        }
        return cache_value_;
    }
};

Cache c;
auto f1 = [&]() { c.get(); };
auto f2 = [&]() { c.get(); };
```

`get()` 是 `const`，但修改了 `mutable` 成员，两个线程同时调用会产生数据竞争。

#### 2. 误区2："shared_ptr 是线程安全的"

半对半错：引用计数的增减是原子的（安全），但指向的对象的并发访问不是（不安全）。

```cpp
auto ptr = std::make_shared<int>(42);

auto f1 = [&]() { *ptr = 100; };
auto f2 = [&]() { *ptr = 200; };
```

两个线程同时修改 `*ptr` 不安全。但 `ptr` 的拷贝/销毁（引用计数操作）是安全的：

```cpp
auto f3 = [&]() { auto local = ptr; };
auto f4 = [&]() { auto local = ptr; };
```

安全：引用计数的增减是原子操作。

#### 3. 误区3："读操作总是安全的"

错！如果另一个线程在写，读也不安全。

```cpp
std::vector<int> vec = {1, 2, 3};

auto writer = [&]() { vec.push_back(4); };
auto reader = [&]() { int x = vec[0]; };
```

`push_back` 可能导致 vector 重新分配内存，此时 reader 拿到的迭代器/指针可能已失效，崩溃或读到垃圾值。

#### 4. 误区4："标准库内部有锁"

错！标准库容器内部没有锁（性能原因），需要用户自己加锁。

```cpp
std::vector<int> vec;

auto f1 = [&]() { vec.push_back(1); };
auto f2 = [&]() { vec.push_back(2); };
```

标准库不会帮你加锁，必须自己保护：

```cpp
std::mutex mtx;

auto f1 = [&]() {
    std::lock_guard<std::mutex> lock(mtx);
    vec.push_back(1);
};
auto f2 = [&]() {
    std::lock_guard<std::mutex> lock(mtx);
    vec.push_back(2);
};
```

### 7. 如何让标准库操作线程安全

#### 1. 方案1：std::mutex 加锁（最常用）

```cpp
#include <mutex>
#include <vector>

class SafeVector {
    std::vector<int> vec_;
    std::mutex mtx_;
public:
    void push_back(int val) {
        std::lock_guard<std::mutex> lock(mtx_);
        vec_.push_back(val);
    }

    int at(size_t idx) const {
        std::lock_guard<std::mutex> lock(mtx_);
        return vec_.at(idx);
    }

    size_t size() const {
        std::lock_guard<std::mutex> lock(mtx_);
        return vec_.size();
    }
};
```

#### 2. 方案2：读写锁 shared_mutex（读多写少场景）

```cpp
#include <shared_mutex>
#include <vector>

class ReadHeavyCache {
    mutable std::shared_mutex rw_mtx_;
    std::vector<std::string> data_;
public:
    std::string get(size_t idx) const {
        std::shared_lock<std::shared_mutex> lock(rw_mtx_);
        return data_.at(idx);
    }

    void set(size_t idx, const std::string& val) {
        std::unique_lock<std::shared_mutex> lock(rw_mtx_);
        data_.at(idx) = val;
    }
};
```

多个线程可以同时 `get()`，但 `set()` 时独占。

#### 3. 方案3：无锁方案（atomic / lock-free 数据结构）

```cpp
#include <atomic>

std::atomic<int> counter(0);

void increment() {
    counter.fetch_add(1, std::memory_order_relaxed);
}
```

适合简单计数器、标志位等场景，不适合复杂容器。

#### 4. 方案4：线程局部存储 thread_local（每个线程独立副本）

```cpp
#include <iostream>
#include <thread>
#include <vector>

thread_local std::vector<int> local_vec;

void worker() {
    local_vec.push_back(42);
    std::cout << "thread " << std::this_thread::get_id()
              << " size=" << local_vec.size() << std::endl;
}

int main() {
    std::vector<std::thread> threads;
    for (int i = 0; i < 4; ++i) {
        threads.emplace_back(worker);
    }
    for (auto& t : threads) {
        t.join();
    }
    return 0;
}
```

每个线程有独立的 `local_vec`，完全无竞争。

***

### 8. 极简总结

**标准库线程安全三规则：不同对象安全、同一对象只读安全、同一对象有写则不安全。`const` ≠ 线程安全，`shared_ptr` 引用计数安全但指向对象不安全。需要并发写时，自己加锁或用 `atomic`。**

| 要点 | 说明 |
|------|------|
| 不同对象 | ✅ 安全，互不干扰 |
| 同一对象只读 | ✅ 安全，无修改无竞争 |
| 同一对象有写 | ❌ 不安全，必须同步 |
| `const` 方法 | ❌ 不等于线程安全，`mutable` 可能有竞争 |
| `shared_ptr` | 引用计数安全，指向对象不安全 |
| 标准库容器 | 内部无锁，用户自己加锁 |
| 解决方案 | mutex / shared_mutex / atomic / thread_local |
