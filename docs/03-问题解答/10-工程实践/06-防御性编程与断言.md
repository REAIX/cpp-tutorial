# 防御性编程与断言
> 📖 相关章节：[错误处理与信号](../../01-C语言/13-错误处理与信号.md)、[编码规范](../../04-工程实践/00-编码规范.md)

> "开车系安全带不是因为你一定会出事，而是万一出事能保命"——防御性编程就是给代码系安全带。

***

### 1. 核心定义

| 概念 | 定义 | 侧重点 |
|------|------|--------|
| 防御性编程 | 假设一切外部输入和调用都可能出错，在代码中加入检查和保护 | 防止"可能发生"的错误 |
| 断言（assert） | 在开发阶段检查"不应该发生"的情况，如果发生则立即终止 | 暴露"不该发生"的编程错误 |

**关键区分**：

- **防御性编程**针对的是"外部世界可能出问题"→ 用 `if` 检查并处理
- **断言**针对的是"我的代码不应该出问题"→ 用 `assert` 暴露 bug

***

### 2. 生活类比

| 概念 | 类比 | 说明 |
|------|------|------|
| 防御性编程 | 开车系安全带 + 买保险 | 不是因为你一定会出事，而是万一出事能保命 |
| 断言 | 工厂质检 | 正常产品不应该有缺陷，发现一个就停线检查 |

**具体场景**：

- **防御性编程**：你开车出门，系好安全带、买好保险。不是因为计划出车祸，而是别人可能撞你。你无法控制外部环境，但可以保护自己。
- **断言**：工厂流水线上，质检员检查产品。如果发现零件装反了，说明上游工序出了 bug，必须停线排查，不能让次品流出去。

### 3. assert 详解

#### 1. assert 宏的工作原理

```cpp
#include <cassert>

void process(int* ptr, int size) {
    assert(ptr != nullptr);       // 条件为假 → 打印信息 → 调用 abort()
    assert(size > 0);
    // ... 正常逻辑
}
```

**assert 触发时的输出**：

```
test.cpp:5: int process(int*, int): Assertion `ptr != nullptr' failed.
Aborted
```

包含：文件名、行号、函数名、失败的条件表达式。

#### 2. NDEBUG 宏

```cpp
// 定义 NDEBUG 后，assert 变为空操作
#define NDEBUG
#include <cassert>

assert(ptr != nullptr);  // 编译后这行代码消失，零开销
```

**典型用法**：Release 构建时通过编译选项定义 NDEBUG：

```bash
# Debug 构建：assert 生效
g++ -g -o app_debug main.cpp

# Release 构建：assert 被移除
g++ -DNDEBUG -O2 -o app_release main.cpp
```

#### 3. assert vs if 的区分

| | assert | if |
|---|---|---|
| 检查对象 | "不应该发生"的情况（编程错误） | "可能发生"的情况（运行时错误） |
| 处理方式 | 立即终止程序 | 优雅处理错误 |
| Release 中 | 被移除（零开销） | 始终存在 |
| 语义 | "如果走到这里，说明有 bug" | "这种情况是正常的，需要处理" |

```cpp
void setAge(int age) {
    // assert：年龄不可能是负数，如果出现说明调用方有 bug
    assert(age >= 0);

    // if：年龄可能超出合理范围，需要处理
    if (age > 150) {
        throw std::invalid_argument("age out of range");
    }

    age_ = age;
}
```

**原则**：`assert` 检查的是"我的代码是否有 bug"，`if` 检查的是"外部输入是否合法"。

### 4. 防御性编程的核心原则

| 原则 | 说明 | 示例 |
|------|------|------|
| 永远不信任输入 | 所有外部数据都要校验 | 检查指针参数、数组索引、数值范围 |
| 永远不假设调用者会正确使用 | API 要自我保护 | 构造函数校验参数、setter 拒绝非法值 |
| 失败时安全退出而非继续执行 | 宁可报错也不要产生错误结果 | 返回错误码/异常，不返回垃圾值 |
| 错误信息要明确 | 谁、什么、为什么 | "config.cpp:42: port must be > 0, got -1" |
| 最小权限原则 | 只暴露必要的接口 | 私有成员变量、最小化 public 接口 |

```cpp
class BankAccount {
    double balance_;
public:
    BankAccount(double initial) : balance_(initial) {
        if (initial < 0) {
            throw std::invalid_argument(
                "BankAccount: initial balance must be >= 0, got " +
                std::to_string(initial));
        }
    }

    void withdraw(double amount) {
        if (amount < 0) {
            throw std::invalid_argument(
                "withdraw: amount must be >= 0, got " +
                std::to_string(amount));
        }
        if (amount > balance_) {
            throw std::runtime_error(
                "withdraw: insufficient balance (" +
                std::to_string(balance_) + " < " +
                std::to_string(amount) + ")");
        }
        balance_ -= amount;
    }
};
```

### 5. 函数参数校验

#### 1. 检查指针参数是否为 NULL

```cpp
// C 语言风格
void print_string(const char* str) {
    if (str == NULL) {
        fprintf(stderr, "print_string: NULL pointer\n");
        return;
    }
    printf("%s\n", str);
}

// C++ 风格：用引用避免空指针
void printString(const std::string& str) {
    std::cout << str << "\n";
}
```

#### 2. 检查数组索引是否越界

```cpp
// C 语言风格
int get_element(int* arr, int size, int index) {
    if (arr == NULL) return -1;
    if (index < 0 || index >= size) return -1;
    return arr[index];
}

// C++ 风格：用 at() 自动边界检查
int getElement(const std::vector<int>& v, int index) {
    return v.at(index);  // 越界抛 std::out_of_range
}
```

#### 3. 检查数值范围是否合法

```cpp
void setVolume(int vol) {
    if (vol < 0 || vol > 100) {
        throw std::out_of_range(
            "setVolume: volume must be [0, 100], got " +
            std::to_string(vol));
    }
    volume_ = vol;
}
```

### 6. 错误处理模式

#### 1. C 语言：返回值 + errno

```cpp
#include <cerrno>
#include <cstring>

int divide(int a, int b, int* result) {
    if (b == 0) {
        errno = EINVAL;
        return -1;
    }
    *result = a / b;
    return 0;
}

int main() {
    int result;
    if (divide(10, 0, &result) != 0) {
        printf("Error: %s\n", strerror(errno));
    }
}
```

**问题**：容易忘记检查返回值，errno 是全局变量可能被覆盖。

#### 2. C++：异常

```cpp
int divide(int a, int b) {
    if (b == 0) {
        throw std::invalid_argument("division by zero");
    }
    return a / b;
}

int main() {
    try {
        int result = divide(10, 0);
    } catch (const std::invalid_argument& e) {
        std::cerr << "Error: " << e.what() << "\n";
    }
}
```

详见 [02-异常处理.md](../../02-CPP/07-异常处理.md)。

#### 3. C++：std::optional / std::expected

```cpp
#include <optional>
#include <expected>

std::optional<int> divide_opt(int a, int b) {
    if (b == 0) return std::nullopt;
    return a / b;
}

std::expected<int, std::string> divide_exp(int a, int b) {
    if (b == 0) return std::unexpected("division by zero");
    return a / b;
}
```

详见 [FAQ 91](../07-现代CPP标准库/07-optional与nullptr.md) 和 [FAQ 106](../07-现代CPP标准库/08-expected与optional.md)。

#### 4. 三种模式对比

| 特性 | 返回值 + errno | 异常 | optional / expected |
|------|:---:|:---:|:---:|
| 强制检查 | 否 | 是（try/catch） | 隐式（bool 检查） |
| 错误信息 | 有限（整数） | 丰富（exception 对象） | optional 无 / expected 丰富 |
| 性能开销 | 无 | 可能较大 | 极小 |
| 控制流 | 透明 | 跳跃（栈展开） | 透明 |
| 适用场景 | C 语言 / 嵌入式 | C++ 通用 | C++17/23 轻量错误 |

### 7. 静态断言（C11 / C++）

#### 1. _Static_assert（C11）/ static_assert（C++11）

```cpp
// C++11
static_assert(sizeof(int) == 4, "int must be 4 bytes");
static_assert(sizeof(void*) == 8, "64-bit platform required");

// C11
_Static_assert(sizeof(int) == 4, "int must be 4 bytes");
```

**特点**：编译期检查，零运行时开销。如果条件不满足，编译直接报错。

#### 2. 检查结构体大小

```cpp
struct PacketHeader {
    uint32_t magic;
    uint16_t version;
    uint16_t flags;
    uint32_t length;
};

static_assert(sizeof(PacketHeader) == 12, "PacketHeader must be 12 bytes for protocol compatibility");
```

#### 3. 检查数组大小

```cpp
template<typename T, size_t N>
void processArray(T (&arr)[N]) {
    static_assert(N >= 3, "Array must have at least 3 elements");
}
```

#### 4. 检查类型特性

```cpp
#include <type_traits>

template<typename T>
void serialize(const T& obj) {
    static_assert(std::is_trivially_copyable_v<T>,
                  "T must be trivially copyable for binary serialization");
    static_assert(!std::is_pointer_v<T>,
                  "T must not be a pointer type");
}
```

### 8. 常见防御性编程技巧

#### 1. 卫语句（Early Return）：减少嵌套

```cpp
// 不好的写法：深层嵌套
void process(const std::vector<int>& data) {
    if (!data.empty()) {
        if (isValid(data)) {
            if (hasPermission()) {
                doProcess(data);
            } else {
                logError("no permission");
            }
        } else {
            logError("invalid data");
        }
    } else {
        logError("empty data");
    }
}

// 好的写法：卫语句，提前返回
void process(const std::vector<int>& data) {
    if (data.empty()) {
        logError("empty data");
        return;
    }
    if (!isValid(data)) {
        logError("invalid data");
        return;
    }
    if (!hasPermission()) {
        logError("no permission");
        return;
    }
    doProcess(data);
}
```

#### 2. 资源获取即初始化（RAII）

详见 [FAQ 05](../01-基础概念/12-什么是RAII.md)。

```cpp
// 不好的写法：手动管理，异常时泄漏
void bad() {
    FILE* f = fopen("data.txt", "r");
    if (!f) return;
    processFile(f);
    fclose(f);  // 如果 processFile 抛异常，fclose 永远不会执行
}

// 好的写法：RAII，异常安全
void good() {
    std::ifstream f("data.txt");
    if (!f) return;
    processFile(f);
}
```

#### 3. 智能指针替代裸指针

```cpp
// 不好的写法：裸指针，容易忘记 delete
void bad() {
    Widget* p = new Widget();
    use(p);
    delete p;  // 如果 use 抛异常，泄漏
}

// 好的写法：智能指针
void good() {
    auto p = std::make_unique<Widget>();
    use(p.get());
}
```

#### 4. 边界检查容器（at() vs []）

```cpp
std::vector<int> v = {1, 2, 3};

// 不安全的写法：[] 不检查边界，越界是 UB
int x = v[10];  // UB，可能崩溃也可能返回垃圾值

// 安全的写法：at() 检查边界，越界抛异常
try {
    int y = v.at(10);  // 抛 std::out_of_range
} catch (const std::out_of_range& e) {
    std::cerr << "Index out of range: " << e.what() << "\n";
}
```

### 9. 极简总结

**防御性编程 = 系安全带。assert 检查"不该发生"的事，if 检查"可能发生"的事。核心原则：不信任输入、不假设调用者、失败安全退出、错误信息明确。**

| 要点 | 说明 |
|------|------|
| assert | 检查编程错误，Release 中被移除 |
| if | 检查运行时错误，始终存在 |
| static_assert | 编译期检查，零运行时开销 |
| 核心原则 | 不信任输入、不假设调用者、失败安全退出、错误信息明确、最小权限 |
| 常用技巧 | 卫语句、RAII、智能指针、at() 代替 [] |
