# 异常安全等级详解
> 📖 相关章节：[编码规范](../../04-工程实践/00-编码规范.md)、[设计模式](../../04-工程实践/03-设计模式.md)、[单元测试](../../04-工程实践/06-单元测试.md)、[代码审查](../../04-工程实践/08-代码审查.md)

> "出车祸后人还活着（基本保证），出车祸后时间倒流（强保证），这辆车永远不会出车祸（不抛出保证）"——三个等级，层层递进。

***

### 1. 核心定义

| 概念 | 定义 |
|------|------|
| 异常安全 | 当异常抛出时，程序仍然处于有效状态 |
| 基本保证（Basic Guarantee） | 异常抛出后：不泄漏资源，不损坏数据，但对象可能处于"有效但未指定"的状态 |
| 强保证（Strong Guarantee） | 异常抛出后：程序状态回滚到操作之前（事务性语义），要么完全成功，要么完全不变 |
| 不抛出保证（Nothrow Guarantee） | 操作永远不会抛出异常 |

**三个等级的关系**：

```
基本保证 ← 强保证 ← 不抛出保证
  弱 ────────────────────→ 强
  易实现 ────────────────→ 难实现
  大多数函数              析构/swap/释放
```

***

### 2. 生活类比

| 等级 | 类比 | 说明 |
|------|------|------|
| 基本保证 | 出车祸后人还活着 | 可能受伤，但不会死。程序还在运行，但数据可能变了 |
| 强保证 | 出车祸后回到出发前的状态 | 时间倒流，就像车祸没发生过。要么安全到达，要么回到起点 |
| 不抛出保证 | 这辆车永远不会出车祸 | 车本身不可能出事，不需要任何保护措施 |

**具体场景**：

- **基本保证**：你去银行转账，系统崩溃了。你的钱没有丢，账户也没有损坏，但你不确定转账是否完成——可能转了，也可能没转，你需要查一下。
- **强保证**：你去银行转账，系统崩溃了。系统自动回滚到转账前的状态，你的余额和转账前一模一样，就像你从未来过。
- **不抛出保证**：你查余额，这个操作不可能失败，永远能查到。

***

### 3. 三个等级详解

#### 1. 基本保证（Basic Guarantee）

异常抛出后：程序处于有效状态，没有资源泄漏，没有数据损坏。但对象可能处于"有效但未指定"的状态。

```cpp
#include <vector>
#include <string>
#include <iostream>

class NameList {
    std::vector<std::string> names_;
public:
    void addName(const std::string& name) {
        names_.push_back(name);  // push_back 可能抛 bad_alloc
        // 如果 push_back 抛异常：
        // - names_ 仍然有效（vector 保证基本异常安全）
        // - 但 names_ 可能处于任何有效状态
        // - 没有内存泄漏
    }
};

int main() {
    NameList list;
    try {
        list.addName("Alice");
        list.addName("Bob");
    } catch (const std::bad_alloc& e) {
        // list 仍然有效，可以继续使用
        // 但不确定 "Alice" 是否已经添加成功
    }
}
```

**要点**：基本保证是最低要求——每个函数至少应该提供基本保证。

#### 2. 强保证（Strong Guarantee）

异常抛出后：程序状态回滚到操作之前（事务性语义），要么完全成功，要么完全不变。

```cpp
#include <vector>
#include <string>
#include <algorithm>

class NameList {
    std::vector<std::string> names_;
public:
    void sortNames() {
        // 先排序临时副本
        std::vector<std::string> temp = names_;
        std::sort(temp.begin(), temp.end());

        // 不抛异常地交换
        temp.swap(names_);  // swap 不抛异常
    }
};

int main() {
    NameList list;
    // list 中已有数据...

    try {
        list.sortNames();
    } catch (...) {
        // 如果排序失败，list 的内容和排序前一模一样
        // 要么排序成功，要么完全不变
    }
}
```

**要点**：强保证通过"先操作副本，再 swap"实现——这就是 copy-and-swap 惯用法。

#### 3. 不抛出保证（Nothrow Guarantee）

操作永远不会抛出异常。标记为 `noexcept`。

```cpp
class Widget {
    int* data_;
    size_t size_;
public:
    void swap(Widget& other) noexcept {
        using std::swap;
        swap(data_, other.data_);
        swap(size_, other.size_);
    }

    ~Widget() noexcept {
        delete[] data_;
    }
};

void nonThrowingFunction() noexcept {
    // 这个函数保证不抛异常
    // 如果真的抛了，std::terminate() 会被调用
}
```

**要点**：析构函数、内存释放、swap 等必须提供不抛出保证。

***

### 4. 等级对比表格

| 等级 | 异常后状态 | 实现难度 | 适用场景 | 示例 |
|------|-----------|---------|---------|------|
| 基本保证 | 有效但可能改变 | 低 | 大多数函数 | `vector::push_back` |
| 强保证 | 回滚到操作前 | 中 | 关键操作 | 数据库事务、配置修改 |
| 不抛出 | 永远不抛异常 | 高 | 析构/swap/释放 | `delete`、`swap`、析构函数 |

**选择原则**：

- 默认追求**基本保证**（最低要求）
- 关键操作追求**强保证**（用户可感知的操作）
- 析构/swap/释放必须**不抛出保证**（基础设施）

***

### 5. copy-and-swap 惯用法

实现强异常安全的标准方法。

**步骤**：先创建副本 → 在副本上操作 → 不抛异常地 swap

```cpp
#include <vector>
#include <string>
#include <utility>

class UserProfile {
    std::string name_;
    std::vector<std::string> friends_;
    int age_;
public:
    UserProfile(const std::string& name, int age)
        : name_(name), age_(age) {}

    // copy-and-swap 实现强异常安全的赋值
    UserProfile& operator=(UserProfile other) noexcept {
        // 1. other 是按值传递的副本（拷贝构造可能抛异常，但发生在函数体外）
        // 2. swap 不抛异常
        swap(other);
        // 3. other 离开作用域时自动释放旧资源
        return *this;
    }

    void swap(UserProfile& other) noexcept {
        using std::swap;
        swap(name_, other.name_);
        swap(friends_, other.friends_);
        swap(age_, other.age_);
    }

    void addFriend(const std::string& name) {
        // 强保证：先操作副本，再 swap
        std::vector<std::string> temp = friends_;
        temp.push_back(name);  // 可能抛 bad_alloc
        friends_.swap(temp);   // 不抛异常
    }
};

namespace std {
template<>
void swap(UserProfile& a, UserProfile& b) noexcept {
    a.swap(b);
}
}
```

**为什么 copy-and-swap 能提供强保证**：

1. 拷贝构造在函数体外完成——如果失败，`this` 没有任何改变
2. swap 是 noexcept 的——不可能失败
3. 旧资源由临时对象析构自动释放——不可能泄漏

**执行流程**：

```
operator=(other) 调用时：
  1. 拷贝构造 other（可能抛异常，但 this 未变）
  2. swap(*this, other)（noexcept，不可能失败）
  3. other 析构，释放旧资源（noexcept，不可能失败）

结果：要么拷贝成功 → 赋值成功，要么拷贝失败 → this 不变
```

### 6. 哪些函数必须异常安全

#### 1. 析构函数：必须不抛出

详见 [FAQ 88](../04-CPP核心特性/25-为什么不能从析构函数抛异常.md)。

```cpp
class Resource {
    FILE* file_;
public:
    ~Resource() noexcept {
        if (file_) {
            if (fclose(file_) != 0) {
                // 不能抛异常！只能记录日志
                std::cerr << "Warning: fclose failed\n";
            }
        }
    }
};
```

**原因**：栈展开期间如果析构函数抛异常，`std::terminate()` 会被调用，程序直接终止。

#### 2. swap 函数：应该不抛出

```cpp
class Buffer {
    int* data_;
    size_t size_;
public:
    void swap(Buffer& other) noexcept {
        using std::swap;
        swap(data_, other.data_);   // 指针 swap：noexcept
        swap(size_, other.size_);   // 整数 swap：noexcept
    }
};
```

**原因**：swap 是 copy-and-swap 惯用法的核心，如果 swap 抛异常，强保证就无法实现。

#### 3. 移动构造/移动赋值：应该不抛出

```cpp
class Buffer {
    int* data_;
    size_t size_;
public:
    Buffer(Buffer&& other) noexcept
        : data_(other.data_), size_(other.size_) {
        other.data_ = nullptr;
        other.size_ = 0;
    }

    Buffer& operator=(Buffer&& other) noexcept {
        if (this != &other) {
            delete[] data_;
            data_ = other.data_;
            size_ = other.size_;
            other.data_ = nullptr;
            other.size_ = 0;
        }
        return *this;
    }
};
```

**原因**：标记 `noexcept` 后，标准库容器会优化。例如 `std::vector` 扩容时，如果移动构造是 `noexcept`，就用移动；否则用拷贝（保证强异常安全）。

```cpp
// vector 扩容时的选择逻辑（简化）
if constexpr (std::is_nothrow_move_constructible_v<T>) {
    // 用移动：快，不会抛异常
} else {
    // 用拷贝：慢，但提供强保证
}
```

#### 4. 内存释放：必须不抛出

```cpp
void operator delete(void* ptr) noexcept;
void operator delete[](void* ptr) noexcept;
```

**原因**：如果 `delete` 抛异常，资源永远无法释放，内存泄漏不可避免。

### 7. RAII 与异常安全

RAII 是异常安全的基础。详见 [FAQ 05](../01-基础概念/05-什么是RAII.md)。

**核心思想**：每个资源都用对象管理 → 异常发生时自动清理。

#### 1. 不用 RAII：异常时泄漏

```cpp
void bad() {
    int* p1 = new int(42);
    int* p2 = new int(100);  // 如果这里抛 bad_alloc

    process(p1, p2);

    delete p1;  // 永远走不到
    delete p2;  // 永远走不到
}
```

**问题**：如果第二个 `new` 抛异常，`p1` 已经分配但永远不会被 `delete`，内存泄漏。

#### 2. 用 RAII：异常安全

```cpp
void good() {
    auto p1 = std::make_unique<int>(42);
    auto p2 = std::make_unique<int>(100);  // 如果抛 bad_alloc

    process(p1.get(), p2.get());

    // 无论是否抛异常，p1 和 p2 都会自动释放
}
```

**为什么安全**：

1. `p1` 构造成功 → 即使后续代码抛异常，`p1` 析构时自动 `delete`
2. `p2` 构造失败（抛 `bad_alloc`）→ `p2` 未构造，无需析构
3. 栈展开时，已构造的 `p1` 自动析构 → 无泄漏

#### 3. RAII 保证异常安全的通用模式

```cpp
class LockGuard {
    std::mutex& mtx_;
public:
    explicit LockGuard(std::mutex& mtx) : mtx_(mtx) { mtx_.lock(); }
    ~LockGuard() noexcept { mtx_.unlock(); }

    LockGuard(const LockGuard&) = delete;
    LockGuard& operator=(const LockGuard&) = delete;
};

void safeOperation() {
    std::mutex mtx;
    LockGuard guard(mtx);  // 加锁
    criticalSection();     // 如果抛异常，guard 析构自动解锁
}
```

**对比**：

| | 不用 RAII | 用 RAII |
|---|---|---|
| 异常时资源释放 | 忘记/无法释放 | 自动释放 |
| 代码复杂度 | 每个 throw 前都要手动释放 | 无需手动管理 |
| 泄漏风险 | 高 | 极低 |

***

### 8. 极简总结

**异常安全三等级：基本保证（不泄漏不损坏）→ 强保证（要么成功要么不变）→ 不抛出（永不抛异常）。析构/swap/释放必须不抛出。copy-and-swap 实现强保证，RAII 是基础。**

| 要点 | 说明 |
|------|------|
| 基本保证 | 最低要求：不泄漏、不损坏，但状态可能改变 |
| 强保证 | 关键操作：事务性，要么成功要么不变 |
| 不抛出保证 | 基础设施：析构、swap、释放、移动操作 |
| copy-and-swap | 实现强保证的标准方法 |
| RAII | 异常安全的基础，自动资源管理 |
| noexcept | 标记不抛出，容器会优化 |
