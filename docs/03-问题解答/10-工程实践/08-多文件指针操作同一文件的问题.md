# 多文件指针操作同一文件的问题
> 📖 相关章节：[文件操作](../../01-C语言/15-文件操作.md)

> "一份文件多人动，不协调就出乱"——多个 FILE*/fd 操作同一个文件，看似各自独立，实则暗藏数据覆盖、不一致、偏移量混乱等陷阱。

***

### 1. 核心定义

**多文件指针操作同一文件** = 多个 `FILE*` 或文件描述符（fd）打开同一个文件，同时或异步读写，可能导致数据不一致、丢失、交错等问题。

核心矛盾：**文件是共享资源，多个访问者没有协调就会冲突**。

| 概念 | 说明 |
|------|------|
| FILE* | C 标准库的文件句柄，带用户态缓冲区 |
| fd（文件描述符） | 操作系统内核的文件句柄，带内核态偏移量 |
| 共享资源 | 文件本身的数据，多个句柄都能访问 |
| 冲突 | 多个句柄同时写/读写交叉，结果不可预测 |

***

### 2. 生活类比

**多人同时编辑同一份纸质文件**：

| 场景 | 类比 | 对应问题 |
|------|------|---------|
| 两个人同时写 | 字叠在一起 | 数据覆盖 |
| 一个人写一个人读 | 读到半新半旧的数据 | 数据不一致 |
| 两个人同时追加 | 内容交错 | 数据混乱 |
| 两个人共用同一支笔 | 互相抢，谁先写不确定 | 偏移量混乱 |

***

### 3. 会出什么问题

#### 1. 问题1：数据覆盖

两个指针同时写入不同位置，后写的覆盖先写的：

```cpp
#include <cstdio>
#include <cstring>

int main() {
    FILE* f1 = fopen("data.txt", "w");
    FILE* f2 = fopen("data.txt", "w");

    fprintf(f1, "AAAA");
    fprintf(f2, "BBBB");

    fclose(f1);
    fclose(f2);

    // data.txt 内容可能是 "BBBB" 或 "AAAA" 或 "ABBA"...
    // 两个 FILE* 各自有缓冲区，刷新顺序不确定
}
```

#### 2. 问题2：读到不一致的数据

一个线程写，另一个线程读，读到"半写"状态：

```cpp
#include <cstdio>
#include <thread>
#include <cstring>

void writer() {
    FILE* f = fopen("data.txt", "w");
    for (int i = 0; i < 1000; ++i) {
        fprintf(f, "Record_%04d\n", i);
        fflush(f);
    }
    fclose(f);
}

void reader() {
    FILE* f = fopen("data.txt", "r");
    char buf[256];
    while (fgets(buf, sizeof(buf), f)) {
        // 可能读到不完整的行，如 "Record_004" 后面被截断
        // 或者读到写了一半的数据
    }
    fclose(f);
}

int main() {
    std::thread t1(writer);
    std::thread t2(reader);
    t1.join();
    t2.join();
}
```

#### 3. 问题3：追加内容交错

两个指针以追加模式写入，内容可能交错：

```cpp
#include <cstdio>
#include <thread>

void append_thread(int id) {
    FILE* f = fopen("log.txt", "a");
    for (int i = 0; i < 100; ++i) {
        fprintf(f, "[Thread%d] Line %d\n", id, i);
    }
    fclose(f);
}

int main() {
    std::thread t1(append_thread, 1);
    std::thread t2(append_thread, 2);
    t1.join();
    t2.join();

    // log.txt 中可能出现：
    // [Thread1] Line 0[Thread2] Line 0
    // 内容交错！
}
```

**O_APPEND 的行为**：POSIX 规定 `O_APPEND` 保证每次 `write()` 原子地移到文件末尾再写入，但 `fprintf` 可能分多次 `write()` 调用，中间可能被其他线程的写入打断。

#### 4. 问题4：文件偏移量混乱

两个 `FILE*` 共享同一个文件描述符（dup/fork），偏移量互相影响：

```cpp
#include <cstdio>
#include <unistd.h>

int main() {
    FILE* f1 = fopen("data.txt", "r");
    int fd = fileno(f1);
    int fd2 = dup(fd);
    FILE* f2 = fdopen(fd2, "r");

    // f1 和 f2 共享同一个内核文件偏移量！
    char buf[64];
    fgets(buf, sizeof(buf), f1);  // 读一行，偏移量移动
    fgets(buf, sizeof(buf), f2);  // 从 f1 读完后位置继续读，不是从头开始

    fclose(f1);
    fclose(f2);
}
```

**fork 后偏移量共享**：

```cpp
#include <cstdio>
#include <unistd.h>
#include <sys/wait.h>

int main() {
    FILE* f = fopen("output.txt", "w");

    pid_t pid = fork();

    if (pid == 0) {
        fprintf(f, "Child writes\n");
        fclose(f);
    } else {
        fprintf(f, "Parent writes\n");
        fclose(f);
        waitpid(pid, nullptr, 0);
    }

    // output.txt 内容可能是：
    // "Parent writes\nChild writes\n"
    // 或 "Child writes\nParent writes\n"
    // 两个进程共享同一个文件偏移量，写入顺序不确定
    // 但不会互相覆盖（偏移量是共享的，会自动推进）
}
```

#### 5. 问题5：缓冲区刷新问题

`FILE*` 有用户态缓冲区，`fwrite` 不一定立即写入文件：

```cpp
#include <cstdio>

int main() {
    FILE* f1 = fopen("data.txt", "w");
    FILE* f2 = fopen("data.txt", "w");

    setvbuf(f1, nullptr, _IOFBF, 4096);  // 全缓冲，4096 字节
    setvbuf(f2, nullptr, _IOFBF, 4096);

    fprintf(f1, "From f1");
    // 数据在 f1 的缓冲区中，还没写入文件

    fprintf(f2, "From f2");
    // 数据在 f2 的缓冲区中，还没写入文件

    // 刷新顺序决定最终内容
    fflush(f1);  // "From f1" 写入文件
    fflush(f2);  // "From f2" 写入文件，可能覆盖或追加

    fclose(f1);
    fclose(f2);

    // 结果取决于缓冲区大小、刷新时机、偏移量位置
    // 完全不可预测！
}
```

### 4. 不同场景分析

#### 1. 场景1：多个 FILE* 独立打开同一文件（各自 open）

```cpp
FILE* f1 = fopen("data.txt", "r+");  // 独立的 fd，独立的偏移量
FILE* f2 = fopen("data.txt", "r+");  // 独立的 fd，独立的偏移量
```

- 各自有独立的文件偏移量
- 写入时互相覆盖（取决于偏移量位置）
- 读取时可能读到旧数据（缓冲区未刷新）

#### 2. 场景2：dup/fork 共享文件描述符

```cpp
int fd = open("data.txt", O_RDWR);
int fd2 = dup(fd);  // 共享偏移量
```

- 共享同一个文件偏移量
- 一个读写后偏移量移动，影响另一个
- fork 后父子进程共享偏移量（但各自有 FILE* 缓冲区）

```cpp
#include <unistd.h>
#include <cstdio>

int main() {
    FILE* f = fopen("data.txt", "r");
    char buf[64];

    pid_t pid = fork();
    if (pid == 0) {
        fgets(buf, sizeof(buf), f);
        // 子进程读了一行，但内核偏移量可能还没更新（FILE* 缓冲区）
    } else {
        fgets(buf, sizeof(buf), f);
        // 父进程可能读到同一行（FILE* 缓冲区是各自独立的）
    }
    fclose(f);
}
```

#### 3. 场景3：多线程共享同一个 FILE*

```cpp
#include <cstdio>
#include <thread>

FILE* g_file;

void thread_func(int id) {
    for (int i = 0; i < 100; ++i) {
        fprintf(g_file, "[Thread%d] %d\n", id, i);
        // 完全不安全！偏移量和缓冲区都没有同步
        // 可能出现：内容交错、数据丢失、缓冲区损坏
    }
}

int main() {
    g_file = fopen("output.txt", "w");

    std::thread t1(thread_func, 1);
    std::thread t2(thread_func, 2);

    t1.join();
    t2.join();

    fclose(g_file);
}
```

#### 4. 场景4：多进程打开同一文件

```cpp
// 进程 A
FILE* f = fopen("data.txt", "r+");
fprintf(f, "Process A");
fclose(f);

// 进程 B（同时运行）
FILE* f = fopen("data.txt", "r+");
fprintf(f, "Process B");
fclose(f);
```

- 各有独立偏移量，但写入可能互相覆盖
- 需要文件锁协调

| 场景 | 偏移量 | 缓冲区 | 安全性 |
|------|--------|--------|--------|
| 各自 open | 独立 | 独立 | 写入可能覆盖 |
| dup/fork | 共享 | 独立 | 偏移量互相影响 |
| 共享 FILE* | 共享 | 共享 | 完全不安全 |
| 多进程各自 open | 独立 | 独立 | 写入可能覆盖 |

***

### 5. 解决方案

#### 1. 方案1：文件锁（flock/fcntl）

**共享锁（读锁）+ 排他锁（写锁）**：

```cpp
#include <sys/file.h>
#include <fcntl.h>
#include <unistd.h>
#include <cstdio>

void safe_write_with_flock() {
    int fd = open("data.txt", O_RDWR | O_CREAT, 0644);

    flock(fd, LOCK_EX);  // 排他锁（写锁）
    // 其他进程在此阻塞，直到锁释放

    const char* msg = "Safe write\n";
    write(fd, msg, strlen(msg));

    flock(fd, LOCK_UN);  // 释放锁
    close(fd);
}

void safe_read_with_flock() {
    int fd = open("data.txt", O_RDONLY);

    flock(fd, LOCK_SH);  // 共享锁（读锁）
    // 多个读者可以同时持有共享锁
    // 但写者必须等所有读者释放

    char buf[256];
    read(fd, buf, sizeof(buf));

    flock(fd, LOCK_UN);  // 释放锁
    close(fd);
}
```

**flock 锁的规则**：

| 锁类型 | 与共享锁兼容 | 与排他锁兼容 |
|--------|:---:|:---:|
| 共享锁（LOCK_SH） | 是 | 否 |
| 排他锁（LOCK_EX） | 否 | 否 |

#### 2. 方案2：追加模式（O_APPEND）

原子追加，每次写入自动移到文件末尾：

```cpp
#include <fcntl.h>
#include <unistd.h>
#include <thread>

void append_with_O_APPEND(int id) {
    int fd = open("log.txt", O_WRONLY | O_APPEND | O_CREAT, 0644);

    for (int i = 0; i < 100; ++i) {
        char buf[64];
        int len = snprintf(buf, sizeof(buf), "[Thread%d] Line %d\n", id, i);
        write(fd, buf, len);  // O_APPEND 保证原子追加
        // 每次 write() 调用：lseek 到末尾 + 写入，是原子操作
    }

    close(fd);
}

int main() {
    std::thread t1(append_with_O_APPEND, 1);
    std::thread t2(append_with_O_APPEND, 2);
    t1.join();
    t2.join();

    // log.txt 中每行完整，不会交错
    // 但行的顺序不确定
}
```

**注意**：`O_APPEND` 只保证单次 `write()` 的原子性，`fprintf` 可能分多次 `write()`，不保证整行原子。

#### 3. 方案3：独立文件描述符 + 区域锁

每个访问者独立打开文件，用 fcntl 的 `F_SETLKW` 对操作区域加锁：

```cpp
#include <fcntl.h>
#include <unistd.h>
#include <cstdio>

void write_region(int fd, off_t offset, size_t len, const char* data) {
    struct flock fl;
    fl.l_type = F_WRLCK;       // 写锁
    fl.l_whence = SEEK_SET;
    fl.l_start = offset;       // 锁定区域起始
    fl.l_len = len;            // 锁定区域长度

    fcntl(fd, F_SETLKW, &fl);  // 阻塞等待获取锁

    lseek(fd, offset, SEEK_SET);
    write(fd, data, len);

    fl.l_type = F_UNLCK;       // 解锁
    fcntl(fd, F_SETLK, &fl);
}

void read_region(int fd, off_t offset, size_t len, char* buf) {
    struct flock fl;
    fl.l_type = F_RDLCK;       // 读锁
    fl.l_whence = SEEK_SET;
    fl.l_start = offset;
    fl.l_len = len;

    fcntl(fd, F_SETLKW, &fl);  // 阻塞等待获取锁

    lseek(fd, offset, SEEK_SET);
    read(fd, buf, len);

    fl.l_type = F_UNLCK;
    fcntl(fd, F_SETLK, &fl);
}

int main() {
    int fd = open("database.dat", O_RDWR | O_CREAT, 0644);

    write_region(fd, 0, 10, "AAAAAAAAAA");
    write_region(fd, 10, 10, "BBBBBBBBBB");

    char buf[11] = {};
    read_region(fd, 0, 10, buf);

    close(fd);
}
```

#### 4. 方案4：单写多读模式

只允许一个写者，多个读者：

```cpp
#include <shared_mutex>
#include <fstream>
#include <thread>

class SafeFileAccess {
    std::shared_mutex mtx;
    std::string filename;

public:
    SafeFileAccess(const std::string& fname) : filename(fname) {}

    std::string read() {
        std::shared_lock lock(mtx);  // 共享锁，多个读者可以同时持有
        std::ifstream f(filename);
        std::string content((std::istreambuf_iterator<char>(f)),
                            std::istreambuf_iterator<char>());
        return content;
    }

    void write(const std::string& data) {
        std::unique_lock lock(mtx);  // 排他锁，只有一个写者
        std::ofstream f(filename);
        f << data;
    }

    void append(const std::string& data) {
        std::unique_lock lock(mtx);
        std::ofstream f(filename, std::ios::app);
        f << data;
    }
};

int main() {
    SafeFileAccess sfa("data.txt");

    sfa.write("Initial data\n");

    auto reader = [&sfa]() {
        for (int i = 0; i < 5; ++i) {
            std::cout << sfa.read().size() << " bytes\n";
        }
    };

    auto writer = [&sfa]() {
        for (int i = 0; i < 5; ++i) {
            sfa.append("More data\n");
        }
    };

    std::thread t1(reader);
    std::thread t2(writer);
    std::thread t3(reader);

    t1.join();
    t2.join();
    t3.join();
}
```

#### 5. 方案5：内存映射 + 同步（mmap）

用 mmap 映射文件到内存，用 msync 同步：

```cpp
#include <sys/mman.h>
#include <sys/stat.h>
#include <fcntl.h>
#include <unistd.h>
#include <cstring>
#include <iostream>

int main() {
    int fd = open("mmap_data.dat", O_RDWR | O_CREAT, 0644);
    ftruncate(fd, 4096);

    void* addr = mmap(nullptr, 4096, PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);

    // 写入数据
    const char* msg = "Hello, mmap!";
    memcpy(addr, msg, strlen(msg) + 1);

    // 同步到文件
    msync(addr, 4096, MS_SYNC);

    // 读取数据
    std::cout << "mmap 内容: " << static_cast<char*>(addr) << "\n";

    munmap(addr, 4096);
    close(fd);
}
```

**mmap + 多进程同步**：

```cpp
#include <sys/mman.h>
#include <fcntl.h>
#include <unistd.h>
#include <cstring>
#include <pthread.h>

struct SharedData {
    pthread_mutex_t mtx;
    char content[4096];
};

int main() {
    int fd = open("shared.dat", O_RDWR | O_CREAT, 0644);
    ftruncate(fd, sizeof(SharedData));

    SharedData* shared = static_cast<SharedData*>(
        mmap(nullptr, sizeof(SharedData), PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0));

    pthread_mutexattr_t attr;
    pthread_mutexattr_init(&attr);
    pthread_mutexattr_setpshared(&attr, PTHREAD_PROCESS_SHARED);
    pthread_mutex_init(&shared->mtx, &attr);

    pthread_mutex_lock(&shared->mtx);
    strncpy(shared->content, "Hello from process", sizeof(shared->content));
    pthread_mutex_unlock(&shared->mtx);

    msync(shared, sizeof(SharedData), MS_SYNC);

    munmap(shared, sizeof(SharedData));
    close(fd);
}
```

### 6. Windows 下的文件锁

#### 1. LockFile/UnlockFile

```cpp
#include <windows.h>
#include <cstdio>

void windows_lock_file() {
    HANDLE hFile = CreateFileA(
        "data.txt",
        GENERIC_READ | GENERIC_WRITE,
        FILE_SHARE_READ | FILE_SHARE_WRITE,
        nullptr,
        OPEN_ALWAYS,
        FILE_ATTRIBUTE_NORMAL,
        nullptr);

    if (hFile == INVALID_HANDLE_VALUE) {
        printf("打开文件失败\n");
        return;
    }

    OVERLAPPED overlapped = {};
    overlapped.Offset = 0;
    overlapped.OffsetHigh = 0;

    BOOL result = LockFileEx(
        hFile,
        LOCKFILE_EXCLUSIVE_LOCK,  // 排他锁
        0,
        0,
        0xFFFFFFFF,
        &overlapped);

    if (result) {
        DWORD written;
        WriteFile(hFile, "Locked write\n", 13, &written, nullptr);

        UnlockFile(hFile, 0, 0, 0, 0xFFFFFFFF);
    }

    CloseHandle(hFile);
}
```

#### 2. LockFileEx（支持共享锁/排他锁）

```cpp
#include <windows.h>

void windows_read_with_shared_lock() {
    HANDLE hFile = CreateFileA(
        "data.txt",
        GENERIC_READ,
        FILE_SHARE_READ,
        nullptr,
        OPEN_EXISTING,
        FILE_ATTRIBUTE_NORMAL,
        nullptr);

    OVERLAPPED overlapped = {};
    overlapped.Offset = 0;
    overlapped.OffsetHigh = 0;

    LockFileEx(
        hFile,
        0,                          // 共享锁（不加 LOCKFILE_EXCLUSIVE_LOCK）
        0,
        0,
        0xFFFFFFFF,
        &overlapped);

    char buf[256];
    DWORD read;
    ReadFile(hFile, buf, sizeof(buf), &read, nullptr);

    UnlockFile(hFile, 0, 0, 0, 0xFFFFFFFF);
    CloseHandle(hFile);
}

void windows_write_with_exclusive_lock() {
    HANDLE hFile = CreateFileA(
        "data.txt",
        GENERIC_WRITE,
        0,
        nullptr,
        OPEN_EXISTING,
        FILE_ATTRIBUTE_NORMAL,
        nullptr);

    OVERLAPPED overlapped = {};
    overlapped.Offset = 0;
    overlapped.OffsetHigh = 0;

    LockFileEx(
        hFile,
        LOCKFILE_EXCLUSIVE_LOCK,    // 排他锁
        0,
        0,
        0xFFFFFFFF,
        &overlapped);

    DWORD written;
    WriteFile(hFile, "Exclusive write\n", 16, &written, nullptr);

    UnlockFile(hFile, 0, 0, 0, 0xFFFFFFFF);
    CloseHandle(hFile);
}
```

| Windows 锁标志 | 说明 |
|----------------|------|
| `0` | 共享锁（读锁），多个读者可同时持有 |
| `LOCKFILE_EXCLUSIVE_LOCK` | 排他锁（写锁），独占访问 |
| `LOCKFILE_FAIL_IMMEDIATELY` | 非阻塞，获取不到锁立即返回 |

### 7. 对比表格

| 方案 | 粒度 | 跨进程 | 平台 | 适用场景 |
|------|------|--------|------|---------|
| flock | 整文件 | 是 | Linux/macOS | 简单互斥 |
| fcntl F_SETLKW | 区域 | 是 | Linux/macOS | 精确控制 |
| O_APPEND | 追加原子 | 是 | POSIX | 日志追加 |
| LockFile | 区域 | 是 | Windows | Windows 开发 |
| 单 FILE* + 锁 | 整文件 | 否 | 全平台 | 多线程 |

**选择建议**：

| 需求 | 推荐方案 |
|------|---------|
| 多线程写日志 | O_APPEND + write() |
| 多进程互斥访问 | flock（Linux）/ LockFileEx（Windows） |
| 多进程读写同一文件不同区域 | fcntl 区域锁（Linux）/ LockFileEx 区域锁（Windows） |
| 多线程共享文件操作 | 单 FILE* + std::shared_mutex |
| 高性能共享内存 | mmap + 进程间互斥锁 |

***

### 8. 极简总结

**多指针操作同一文件会出问题：数据覆盖、不一致、偏移量混乱。解决方案：文件锁（flock/fcntl）、O_APPEND 原子追加、区域锁。核心原则：写必须互斥，读可以共享，追加用 O_APPEND。**

| 要点 | 说明 |
|------|------|
| 核心问题 | 多个句柄操作同一文件 = 共享资源无协调 |
| 五大问题 | 覆盖、不一致、交错、偏移量混乱、缓冲区刷新 |
| 最佳实践 | 写用排他锁，读用共享锁，追加用 O_APPEND |
| Linux 锁 | flock（整文件）、fcntl（区域锁） |
| Windows 锁 | LockFileEx（支持共享/排他） |
| 一句话 | 写必须互斥，读可以共享，追加用 O_APPEND |
