# 序列化与反序列化 — 对象与字节流的桥梁
> 📖 相关章节：[序列化与日志](../../02-CPP/32-序列化与日志.md)

> "序列化是拆家具搬家，反序列化是到新家再组装。" — 理解序列化，就是理解数据如何穿越时间和空间。

---

## 1. 什么是序列化/反序列化

### 1. 定义

- **序列化（Serialization）**：将内存中的对象转换为可存储/可传输的字节流
- **反序列化（Deserialization）**：将字节流还原为内存中的对象

```
序列化：
  内存中的对象 ──→ 字节流（可存储/可传输）

反序列化：
  字节流 ──→ 内存中的对象

完整流程：
  对象A ──序列化──→ 字节流 ──网络/文件──→ 字节流 ──反序列化──→ 对象B
  （A和B内容相同，但内存地址不同）
```

### 2. 比喻

```
搬家：
  原来的家：一套完整的家具（内存中的对象）
     │
     ▼ 序列化
  拆成零件装车：家具变成可运输的零件包（字节流）
     │
     ▼ 运输
  搬到新家：零件包运到目的地（网络传输/文件存储）
     │
     ▼ 反序列化
  重新组装：按说明书把零件组装回家具（还原对象）

  序列化   = 把家具拆成零件
  反序列化 = 到新家再组装
  字节流   = 零件包 + 说明书
```

### 3. 为什么需要序列化

| 场景 | 说明 | 例子 |
|------|------|------|
| **网络传输** | 数据必须变成字节流才能在网络上传输 | HTTP请求体、RPC调用 |
| **持久化存储** | 把对象保存到文件/数据库，程序重启后恢复 | 存档系统、配置文件 |
| **跨进程通信** | 不同进程间传递结构化数据 | IPC、管道、共享内存 |
| **跨语言通信** | 不同编程语言之间交换数据 | 微服务、前后端交互 |

## 3. C/C++序列化方案

### 1. JSON库

| 库 | 特点 | 头文件 | 适用场景 |
|----|------|--------|----------|
| **nlohmann/json** | API最友好，仅头文件 | 单文件 | 快速开发、中小项目 |
| **rapidjson** | 高性能，内存占用小 | 多文件 | 高性能场景 |
| **cJSON** | C语言，轻量小巧 | 单文件 | 嵌入式、C项目 |

```cpp
// nlohmann/json 示例
#include <nlohmann/json.hpp>
#include <iostream>
#include <string>

using json = nlohmann::json;

struct User {
    std::string name;
    int age;
    std::vector<std::string> hobbies;
};

// 序列化
json to_json(const User& u) {
    return json{{"name", u.name}, {"age", u.age}, {"hobbies", u.hobbies}};
}

// 反序列化
User from_json(const json& j) {
    return User{
        j.at("name").get<std::string>(),
        j.at("age").get<int>(),
        j.at("hobbies").get<std::vector<std::string>>()
    };
}

int main() {
    User u{"张三", 25, {"C++", "游戏"}};

    // 序列化
    json j = to_json(u);
    std::string data = j.dump();  // → {"age":25,"hobbies":["C++","游戏"],"name":"张三"}

    // 反序列化
    json j2 = json::parse(data);
    User u2 = from_json(j2);
}
```

### 3. FlatBuffers

```
FlatBuffers 核心优势：零拷贝反序列化

普通序列化：
  字节流 ──解析──→ 临时对象 ──拷贝──→ 业务对象
  需要解析和拷贝，有额外开销

FlatBuffers：
  字节流 ──直接访问──→ 业务数据
  不需要解析，直接在字节流上读取
  适合游戏、实时系统等对延迟敏感的场景
```

### 4. MessagePack

```cpp
#include <msgpack.hpp>
#include <string>
#include <vector>
#include <iostream>

struct User {
    std::string name;
    int age;
    std::vector<std::string> hobbies;
    MSGPACK_DEFINE(name, age, hobbies);  // 宏定义序列化
};

int main() {
    User u{"张三", 25, {"C++", "游戏"}};

    // 序列化
    std::stringstream ss;
    msgpack::pack(ss, u);

    // 反序列化
    std::string str = ss.str();
    msgpack::object_handle oh = msgpack::unpack(str.data(), str.size());
    User u2 = oh.get().as<User>();
}
```

### 5. 自定义二进制

```cpp
// 直接memcpy的坑
#include <cstring>

struct BadPacket {
    int8_t  type;
    int32_t length;   // 对齐填充！sizeof不是5而是8
    int64_t timestamp;
};

void bad_serialize() {
    BadPacket pkt{1, 100, 1700000000};

    // 错误：直接memcpy会包含填充字节
    char buf[sizeof(BadPacket)];
    std::memcpy(buf, &pkt, sizeof(BadPacket));
    // 不同编译器/平台的填充可能不同，反序列化会出错
}

// 正确做法：逐字段序列化，手动处理字节序和对齐
#include <cstdint>

void write_be32(char* buf, uint32_t val) {
    buf[0] = (val >> 24) & 0xFF;
    buf[1] = (val >> 16) & 0xFF;
    buf[2] = (val >> 8)  & 0xFF;
    buf[3] =  val        & 0xFF;
}

uint32_t read_be32(const char* buf) {
    return (static_cast<uint8_t>(buf[0]) << 24) |
           (static_cast<uint8_t>(buf[1]) << 16) |
           (static_cast<uint8_t>(buf[2]) << 8)  |
            static_cast<uint8_t>(buf[3]);
}

void good_serialize(const BadPacket& pkt, char* buf) {
    buf[0] = pkt.type;
    write_be32(buf + 1, static_cast<uint32_t>(pkt.length));    // 固定偏移
    // int64_t同理，写8字节大端
}
```

```
struct内存布局示例（64位系统）：

BadPacket 内存布局：
  偏移 0: type      (1字节)
  偏移 1: [填充3字节]  ← 编译器自动填充，为了4字节对齐
  偏移 4: length    (4字节)
  偏移 8: timestamp (8字节)
  总大小: 16字节（不是13字节！）

直接memcpy的问题：
  ├── 填充字节内容不确定（垃圾值）
  ├── 不同平台对齐规则不同
  ├── 不同平台字节序不同
  └── 版本升级后结构体变化无法兼容
```

## 4. 序列化的关键问题

### 1. 字节序

```
大端序（Big-Endian / Network Byte Order）：
  高位字节在低地址
  值 0x12345678 存储为：12 34 56 78
  网络传输标准字节序

小端序（Little-Endian）：
  低位字节在低地址
  值 0x12345678 存储为：78 56 34 12
  x86/ARM默认字节序

网络传输必须统一字节序！
  发送方：主机序 → 网络序（大端）
  接收方：网络序 → 主机序
```

```cpp
#include <cstdint>
#include <cstring>

// 检测当前系统字节序
bool is_little_endian() {
    uint16_t val = 0x0001;
    return *reinterpret_cast<uint8_t*>(&val) == 1;
}

// 使用标准库函数（POSIX）
#include <arpa/inet.h>  // Linux/macOS
// #include <winsock2.h>  // Windows

uint32_t host_to_network(uint32_t val) { return htonl(val); }
uint32_t network_to_host(uint32_t val) { return ntohl(val); }
```

### 2. 内存对齐与填充

```cpp
#include <cstddef>
#include <iostream>

struct Example {
    char    a;   // 1字节
    // 填充3字节
    int     b;   // 4字节
    short   c;   // 2字节
    // 填充2字节
    double  d;   // 8字节
};
// sizeof(Example) = 24（不是15）

// 查看偏移
int main() {
    std::cout << "offset a: " << offsetof(Example, a) << std::endl;  // 0
    std::cout << "offset b: " << offsetof(Example, b) << std::endl;  // 4
    std::cout << "offset c: " << offsetof(Example, c) << std::endl;  // 8
    std::cout << "offset d: " << offsetof(Example, d) << std::endl;  // 16
    std::cout << "sizeof:   " << sizeof(Example) << std::endl;       // 24
}

// 序列化时必须逐字段处理，不能依赖内存布局
// 或者使用 #pragma pack(1) 消除填充（但可能影响性能）
```

### 3. 版本兼容

```
向前兼容（新代码读旧数据）：
  旧版本数据 ──→ 新版本代码
  新代码能识别旧格式，缺失字段使用默认值

向后兼容（旧代码读新数据）：
  新版本数据 ──→ 旧版本代码
  旧代码能忽略新增字段，不崩溃

版本兼容策略：
  ├── Protobuf：字段编号 + 可选/默认值 → 天然兼容
  ├── JSON：缺失字段用默认值 → 较易兼容
  ├── 自定义二进制：需要版本号 + 长度前缀 → 手动处理
  └── FlatBuffers：字段可选 → 天然兼容
```

### 4. 循环引用

```
循环引用问题：
  对象A ──引用──→ 对象B ──引用──→ 对象A
  序列化时会无限递归！

解决方案：
  ├── JSON：用ID引用代替对象引用 {"ref": "obj_b_id"}
  ├── Protobuf：不支持循环引用，需手动处理
  ├── 自定义二进制：记录已序列化对象的偏移量
  └── 通用：序列化时给每个对象分配ID，引用用ID代替
```

### 5. 指针序列化

```cpp
// 指针不能直接序列化！
struct Node {
    int value;
    Node* next;  // 指针是内存地址，序列化无意义
};

// 正确做法：用索引/ID代替指针
struct SerializedNode {
    int value;
    int32_t next_index;  // -1表示无后继，否则是数组下标
};

// 反序列化时重建指针关系
std::vector<std::unique_ptr<Node>> nodes;
for (auto& sn : serialized_nodes) {
    nodes.push_back(std::make_unique<Node>());
    nodes.back()->value = sn.value;
}
for (size_t i = 0; i < nodes.size(); ++i) {
    int32_t next = serialized_nodes[i].next_index;
    if (next >= 0) {
        nodes[i]->next = nodes[next].get();
    }
}
```

## 5. C++代码示例

### 1. JSON序列化示例

```cpp
#include <nlohmann/json.hpp>
#include <fstream>
#include <iostream>
#include <string>
#include <vector>

using json = nlohmann::json;

struct Config {
    std::string app_name;
    int port;
    bool debug;
    std::vector<std::string> allowed_hosts;
};

void save_config(const Config& cfg, const std::string& path) {
    json j = {
        {"app_name", cfg.app_name},
        {"port", cfg.port},
        {"debug", cfg.debug},
        {"allowed_hosts", cfg.allowed_hosts}
    };
    std::ofstream f(path);
    f << j.dump(4);  // 缩进4空格，方便阅读
}

Config load_config(const std::string& path) {
    std::ifstream f(path);
    json j = json::parse(f);
    return Config{
        j.at("app_name").get<std::string>(),
        j.at("port").get<int>(),
        j.value("debug", false),
        j.value("allowed_hosts", std::vector<std::string>{})
    };
}

int main() {
    Config cfg{"MyApp", 8080, true, {"localhost", "127.0.0.1"}};
    save_config(cfg, "config.json");
    Config loaded = load_config("config.json");
    std::cout << loaded.app_name << ":" << loaded.port << std::endl;
}
```

### 2. 二进制序列化示例（含字节序处理）

```cpp
#include <cstdint>
#include <cstring>
#include <iostream>
#include <sstream>
#include <string>
#include <vector>

class BinaryWriter {
    std::vector<char> buf_;
public:
    void write_u8(uint8_t val) {
        buf_.push_back(static_cast<char>(val));
    }

    void write_u16_be(uint16_t val) {
        buf_.push_back(static_cast<char>((val >> 8) & 0xFF));
        buf_.push_back(static_cast<char>(val & 0xFF));
    }

    void write_u32_be(uint32_t val) {
        buf_.push_back(static_cast<char>((val >> 24) & 0xFF));
        buf_.push_back(static_cast<char>((val >> 16) & 0xFF));
        buf_.push_back(static_cast<char>((val >> 8) & 0xFF));
        buf_.push_back(static_cast<char>(val & 0xFF));
    }

    void write_string(const std::string& s) {
        write_u16_be(static_cast<uint16_t>(s.size()));
        for (char c : s) buf_.push_back(c);
    }

    const std::vector<char>& data() const { return buf_; }
};

class BinaryReader {
    const char* data_;
    size_t size_;
    size_t pos_ = 0;
public:
    BinaryReader(const char* data, size_t size) : data_(data), size_(size) {}

    uint8_t read_u8() {
        return static_cast<uint8_t>(data_[pos_++]);
    }

    uint16_t read_u16_be() {
        uint16_t val = (static_cast<uint8_t>(data_[pos_]) << 8) |
                       static_cast<uint8_t>(data_[pos_ + 1]);
        pos_ += 2;
        return val;
    }

    uint32_t read_u32_be() {
        uint32_t val = (static_cast<uint8_t>(data_[pos_]) << 24) |
                       (static_cast<uint8_t>(data_[pos_ + 1]) << 16) |
                       (static_cast<uint8_t>(data_[pos_ + 2]) << 8) |
                       static_cast<uint8_t>(data_[pos_ + 3]);
        pos_ += 4;
        return val;
    }

    std::string read_string() {
        uint16_t len = read_u16_be();
        std::string s(data_ + pos_, len);
        pos_ += len;
        return s;
    }
};

struct Message {
    uint8_t type;
    uint32_t id;
    std::string content;
};

int main() {
    Message msg{42, 1001, "Hello, Binary!"};

    // 序列化
    BinaryWriter writer;
    writer.write_u8(msg.type);
    writer.write_u32_be(msg.id);
    writer.write_string(msg.content);

    // 反序列化
    auto& data = writer.data();
    BinaryReader reader(data.data(), data.size());
    Message msg2;
    msg2.type = reader.read_u8();
    msg2.id = reader.read_u32_be();
    msg2.content = reader.read_string();

    std::cout << "type=" << (int)msg2.type
              << " id=" << msg2.id
              << " content=" << msg2.content << std::endl;
}
```

## 6. 场景选型

```
场景选型决策树：

你的需求是什么？
  │
  ├── 配置文件
  │     ├── 需要注释？→ YAML / TOML
  │     └── 简单键值？→ JSON
  │
  ├── API通信
  │     ├── 需要可读性？→ JSON
  │     └── 追求性能？→ Protobuf
  │
  ├── 高性能场景
  │     ├── 需要零拷贝？→ FlatBuffers
  │     └── 可接受解析？→ Protobuf / 自定义二进制
  │
  ├── 跨语言
  │     ├── 有schema？→ Protobuf
  │     └── 无schema？→ MessagePack / JSON
  │
  └── 嵌入式/协议开发
        ├── 资源极度受限？→ 自定义二进制
        └── 需要调试？→ MessagePack
```

| 场景 | 推荐格式 | 理由 |
|------|----------|------|
| 配置文件 | TOML / YAML | 可读性好，支持注释 |
| Web API | JSON | 通用标准，前后端友好 |
| 微服务通信 | Protobuf | 高性能，强类型，代码生成 |
| 游戏通信 | FlatBuffers | 零拷贝，低延迟 |
| 缓存存储 | MessagePack | 比JSON小，无需schema |
| 嵌入式协议 | 自定义二进制 | 最紧凑，完全可控 |
| 日志存储 | JSON / MessagePack | 可读性与性能的平衡 |

## 7. 安全注意事项

### 1. 反序列化漏洞（CWE-502）

```
反序列化漏洞原理：
  攻击者 ──构造恶意字节流──→ 反序列化器 ──执行恶意代码──→ 系统被入侵

  反序列化时，程序会根据字节流创建对象
  如果反序列化器允许创建任意类型，攻击者可以：
    ├── 创建危险对象（如执行命令的对象）
    ├── 修改内部状态（绕过权限检查）
    └── 触发副作用（如删除文件）

  这就是 CWE-502：不可信数据的反序列化漏洞
```

### 2. 不受信数据的风险

```cpp
// 危险示例：Java的readObject()可以执行任意代码
// C++中类似风险：通过类型名字符串动态创建对象

// 危险：根据数据中的类型名创建对象
void dangerous_deserialize(const std::string& type_name, const char* data) {
    if (type_name == "CommandExecutor") {
        // 如果攻击者传入这个类型名，可能执行任意命令
        auto* obj = new CommandExecutor(data);  // 危险！
    }
}

// 安全：只允许预定义类型
enum class SafeType : uint8_t {
    User = 1,
    Config = 2,
    Message = 3
};

void safe_deserialize(SafeType type, const char* data, size_t len) {
    switch (type) {
        case SafeType::User:    /* 按User解析 */ break;
        case SafeType::Config:  /* 按Config解析 */ break;
        case SafeType::Message: /* 按Message解析 */ break;
        default:
            throw std::runtime_error("未知类型");  // 拒绝未知类型
    }
}
```

### 3. 防御措施

| 防御措施 | 说明 |
|----------|------|
| **输入验证** | 反序列化前验证数据长度、格式、校验和 |
| **类型白名单** | 只允许反序列化预定义的类型，拒绝未知类型 |
| **深度限制** | 限制嵌套层级，防止栈溢出 |
| **长度限制** | 限制反序列化数据的最大长度 |
| **签名验证** | 对序列化数据做数字签名，防止篡改 |
| **最小权限** | 反序列化代码运行在最小权限环境中 |
| **避免动态类型创建** | 不要根据数据内容决定创建哪种对象 |

```cpp
// 安全的反序列化模板
#include <cstdint>
#include <stdexcept>
#include <vector>

class SafeDeserializer {
    static constexpr size_t MAX_DEPTH = 16;
    static constexpr size_t MAX_SIZE = 1024 * 1024;  // 1MB

    const char* data_;
    size_t size_;
    size_t pos_ = 0;
    size_t depth_ = 0;

    void check_remaining(size_t need) {
        if (pos_ + need > size_)
            throw std::runtime_error("数据不足");
    }

    void check_depth() {
        if (++depth_ > MAX_DEPTH)
            throw std::runtime_error("嵌套过深");
    }
public:
    SafeDeserializer(const char* data, size_t size)
        : data_(data), size_(size) {
        if (size > MAX_SIZE)
            throw std::runtime_error("数据过大");
    }

    uint8_t read_u8() {
        check_remaining(1);
        return static_cast<uint8_t>(data_[pos_++]);
    }

    std::string read_string() {
        check_depth();
        uint16_t len = read_u16_be();
        check_remaining(len);
        std::string s(data_ + pos_, len);
        pos_ += len;
        depth_--;
        return s;
    }

    // ... 其他读取方法同理
};
```
