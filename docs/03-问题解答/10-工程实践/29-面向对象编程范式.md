# 面向对象编程范式详解
> 📖 相关章节：[编码规范](../../04-工程实践/00-编码规范.md)、[设计模式](../../04-工程实践/03-设计模式.md)、[单元测试](../../04-工程实践/05-单元测试.md)、[代码审查](../../04-工程实践/07-代码审查.md)

> **Objects are the nouns, methods are the verbs.** — 对象是名词，方法是动词。

***

### 1. 精髓速览

面向对象编程（OOP）的核心公式：**程序 = 对象的协作**。每个对象负责自己的数据和行为，对象之间通过消息（方法调用）进行交互。四大原则：封装、继承、多态、抽象。

***

### 2. 面向对象核心思想

```
程序 = 对象的协作
```

每个对象负责自己的数据和行为，对象之间通过消息（方法调用）进行交互。

类比：**公司**——销售部负责卖、技术部负责开发、财务部负责算账。各部门封装自己的知识和能力，通过内部流程协作完成业务。你不需要知道财务部怎么算账，只需要提交报销单。

### 3. 封装 — 隐藏内部细节

封装的核心：外部代码不能直接修改内部数据，只能通过公开方法操作，保证数据一致性。

```cpp
#include <iostream>
#include <string>

class BankAccount {
private:
    std::string owner_;
    double balance_;

public:
    BankAccount(const std::string& owner, double initial)
        : owner_(owner), balance_(initial) {}

    void deposit(double amount) {
        if (amount <= 0) {
            std::cout << "存款金额必须大于0" << std::endl;
            return;
        }
        balance_ += amount;
    }

    bool withdraw(double amount) {
        if (amount <= 0 || amount > balance_) {
            std::cout << "余额不足或金额无效" << std::endl;
            return false;
        }
        balance_ -= amount;
        return true;
    }

    double get_balance() const { return balance_; }
    const std::string& get_owner() const { return owner_; }
};

int main() {
    BankAccount account("张三", 1000.0);
    account.deposit(500.0);
    account.withdraw(200.0);
    std::cout << account.get_owner() << "的余额: "
              << account.get_balance() << std::endl;
}
```

封装的三层含义：

| 层次 | 说明 | C++机制 |
|------|------|---------|
| 数据隐藏 | 外部不能直接访问内部数据 | `private`/`protected` |
| 行为暴露 | 只暴露必要的操作接口 | `public` 方法 |
| 不变式维护 | 方法内部保证数据一致性 | 构造函数初始化 + 方法校验 |

### 4. 继承 — 复用和扩展

继承的关键：子类复用父类的接口和通用逻辑，只需实现自己的特化部分。

```cpp
#include <iostream>
#include <string>

class Shape {
public:
    virtual ~Shape() = default;
    virtual double area() const = 0;
    virtual std::string name() const = 0;

    void describe() const {
        std::cout << name() << "的面积: " << area() << std::endl;
    }
};

class Circle : public Shape {
    double radius_;
public:
    explicit Circle(double r) : radius_(r) {}
    double area() const override {
        return 3.14159265 * radius_ * radius_;
    }
    std::string name() const override { return "圆形"; }
};

class Rectangle : public Shape {
    double width_;
    double height_;
public:
    Rectangle(double w, double h) : width_(w), height_(h) {}
    double area() const override { return width_ * height_; }
    std::string name() const override { return "矩形"; }
};

int main() {
    Circle c(5.0);
    Rectangle r(4.0, 6.0);
    c.describe();
    r.describe();
}
```

继承的注意事项：

| 要点 | 说明 |
|------|------|
| 继承层级不超过3层 | 过深继承导致代码脆弱 |
| 虚析构函数 | 基类析构函数必须为virtual |
| override关键字 | C++11起始终使用override标记重写 |
| 区分is-a和has-a | is-a用继承，has-a用组合 |

### 5. 多态 — 同一接口不同行为

多态的关键：调用方不需要知道具体类型，只依赖基类接口。新增子类时，不需要修改调用方代码。

```cpp
#include <iostream>
#include <vector>
#include <memory>

class Animal {
public:
    virtual ~Animal() = default;
    virtual void speak() const = 0;
};

class Dog : public Animal {
public:
    void speak() const override { std::cout << "汪汪！" << std::endl; }
};

class Cat : public Animal {
public:
    void speak() const override { std::cout << "喵喵！" << std::endl; }
};

class Duck : public Animal {
public:
    void speak() const override { std::cout << "嘎嘎！" << std::endl; }
};

void make_concert(const std::vector<std::unique_ptr<Animal>>& animals) {
    for (const auto& animal : animals) {
        animal->speak();
    }
}

int main() {
    std::vector<std::unique_ptr<Animal>> zoo;
    zoo.push_back(std::make_unique<Dog>());
    zoo.push_back(std::make_unique<Cat>());
    zoo.push_back(std::make_unique<Duck>());
    make_concert(zoo);
}
```

多态的两种形式：

| 形式 | 机制 | 绑定时机 | 示例 |
|------|------|----------|------|
| 动态多态 | 虚函数 + 继承 | 运行时 | `animal->speak()` |
| 静态多态 | 模板 | 编译时 | `template<T> void foo(T obj)` |

### 6. 抽象 — 提取本质忽略细节

抽象的关键：调用方只依赖抽象接口，不关心具体实现。具体实现可以被替换，不影响调用方。

```cpp
#include <iostream>
#include <string>

class Logger {
public:
    virtual ~Logger() = default;
    virtual void log(const std::string& message) = 0;
};

class FileLogger : public Logger {
    std::string filepath_;
public:
    explicit FileLogger(const std::string& path) : filepath_(path) {}
    void log(const std::string& message) override {
        std::cout << "[文件:" << filepath_ << "] " << message << std::endl;
    }
};

class ConsoleLogger : public Logger {
    void log(const std::string& message) override {
        std::cout << "[控制台] " << message << std::endl;
    }
};

class Application {
    Logger& logger_;
public:
    explicit Application(Logger& logger) : logger_(logger) {}
    void run() {
        logger_.log("应用启动");
        logger_.log("正在处理数据...");
        logger_.log("应用结束");
    }
};

int main() {
    ConsoleLogger console_log;
    Application app(console_log);
    app.run();
}
```

### 7. OOP设计原则

#### 1. 组合优于继承

```cpp
#include <iostream>
#include <string>
#include <memory>

class FlyBehavior {
public:
    virtual ~FlyBehavior() = default;
    virtual void fly() const = 0;
};

class SwimBehavior {
public:
    virtual ~SwimBehavior() = default;
    virtual void swim() const = 0;
};

class CanFly : public FlyBehavior {
public:
    void fly() const override { std::cout << "展翅高飞！" << std::endl; }
};

class CannotFly : public FlyBehavior {
public:
    void fly() const override { std::cout << "不会飞..." << std::endl; }
};

class CanSwim : public SwimBehavior {
public:
    void swim() const override { std::cout << "畅游水中！" << std::endl; }
};

class Bird {
    std::string name_;
    std::unique_ptr<FlyBehavior> fly_;
    std::unique_ptr<SwimBehavior> swim_;
public:
    Bird(const std::string& name,
         std::unique_ptr<FlyBehavior> fly,
         std::unique_ptr<SwimBehavior> swim)
        : name_(name)
        , fly_(std::move(fly))
        , swim_(std::move(swim)) {}

    void perform_fly() const { fly_->fly(); }
    void perform_swim() const { swim_->swim(); }
    void introduce() const {
        std::cout << "我是" << name_ << std::endl;
    }
};

int main() {
    Bird duck("鸭子", std::make_unique<CanFly>(), std::make_unique<CanSwim>());
    Bird penguin("企鹅", std::make_unique<CannotFly>(), std::make_unique<CanSwim>());
    duck.introduce();
    duck.perform_fly();
    duck.perform_swim();
    penguin.introduce();
    penguin.perform_fly();
    penguin.perform_swim();
}
```

#### 2. 依赖倒置 — 依赖抽象而非具体

```cpp
#include <iostream>
#include <memory>
#include <string>

class IDataStorage {
public:
    virtual ~IDataStorage() = default;
    virtual void save(const std::string& data) = 0;
    virtual std::string load() = 0;
};

class DatabaseStorage : public IDataStorage {
public:
    void save(const std::string& data) override {
        std::cout << "保存到数据库: " << data << std::endl;
    }
    std::string load() override { return "来自数据库的数据"; }
};

class FileStorage : public IDataStorage {
public:
    void save(const std::string& data) override {
        std::cout << "保存到文件: " << data << std::endl;
    }
    std::string load() override { return "来自文件的数据"; }
};

class UserService {
    std::shared_ptr<IDataStorage> storage_;
public:
    explicit UserService(std::shared_ptr<IDataStorage> storage)
        : storage_(storage) {}

    void save_user(const std::string& name) {
        storage_->save("用户:" + name);
    }
};

int main() {
    auto db_service = std::make_shared<UserService>(
        std::make_shared<DatabaseStorage>());
    auto file_service = std::make_shared<UserService>(
        std::make_shared<FileStorage>());
    db_service->save_user("张三");
    file_service->save_user("李四");
}
```

SOLID原则速查：

| 原则 | 含义 | 核心思想 |
|------|------|----------|
| S — 单一职责 | 一个类只有一个变化原因 | 拆分职责 |
| O — 开闭原则 | 对扩展开放，对修改关闭 | 用多态扩展 |
| L — 里氏替换 | 子类能替换父类 | 继承规范 |
| I — 接口隔离 | 不要强迫依赖不需要的接口 | 拆分接口 |
| D — 依赖倒置 | 依赖抽象而非具体 | 面向接口编程 |

### 8. 常见OOP错误

#### 1. 过度继承

```cpp
#include <iostream>
#include <memory>
#include <string>

class Engine {
public:
    virtual ~Engine() = default;
    virtual std::string type() const = 0;
};

class CombustionEngine : public Engine {
public:
    std::string type() const override { return "燃油引擎"; }
};

class ElectricMotor : public Engine {
public:
    std::string type() const override { return "电动马达"; }
};

class Vehicle {
    std::unique_ptr<Engine> engine_;
    std::string brand_;
public:
    Vehicle(const std::string& brand, std::unique_ptr<Engine> engine)
        : engine_(std::move(engine)), brand_(brand) {}

    void describe() const {
        std::cout << brand_ << "，动力: " << engine_->type() << std::endl;
    }
};

int main() {
    Vehicle car("丰田卡罗拉", std::make_unique<CombustionEngine>());
    Vehicle ev("特斯拉Model S", std::make_unique<ElectricMotor>());
    car.describe();
    ev.describe();
}
```

#### 2. 贫血模型 vs 充血模型

```cpp
#include <iostream>
#include <string>

struct AnemicOrder {
    std::string id;
    double total;
    std::string status;
};

class Order {
    std::string id_;
    double total_;
    std::string status_;
public:
    Order(const std::string& id, double total)
        : id_(id), total_(total), status_("待支付") {}

    void cancel() {
        if (status_ == "已发货") {
            std::cout << "已发货的订单无法取消" << std::endl;
            return;
        }
        status_ = "已取消";
        std::cout << "订单 " << id_ << " 已取消" << std::endl;
    }

    void pay() {
        if (status_ != "待支付") {
            std::cout << "订单状态不允许支付" << std::endl;
            return;
        }
        status_ = "已支付";
        std::cout << "订单 " << id_ << " 已支付，金额: "
                  << total_ << std::endl;
    }

    void ship() {
        if (status_ != "已支付") {
            std::cout << "订单未支付，无法发货" << std::endl;
            return;
        }
        status_ = "已发货";
        std::cout << "订单 " << id_ << " 已发货" << std::endl;
    }
};

int main() {
    Order order("ORD-001", 299.9);
    order.pay();
    order.ship();
    order.cancel();
}
```

| 反模式 | 问题 | 正确做法 |
|--------|------|----------|
| 过度继承 | 继承层级过深，修改基类影响巨大 | 扁平化 + 组合 |
| 贫血模型 | 对象只有数据没有行为 | 充血模型：对象自己管理行为 |
| 上帝类 | 一个类承担过多职责 | 单一职责，拆分为多个类 |

### 9. 什么时候用面向对象

| 场景 | 原因 |
|------|------|
| 业务系统 | 业务实体天然有属性和行为，对象模型最直观 |
| UI框架 | 界面元素是对象，事件处理是消息传递 |
| 游戏开发 | 游戏角色、道具、场景都是对象 |
| 模拟系统 | 模拟实体之间的交互关系 |

### 10. 极简总结

**OOP = 对象协作 → 封装隐藏细节 → 继承复用扩展 → 多态同一接口 → 抽象提取本质 → 组合优于继承 → 依赖抽象而非具体**
