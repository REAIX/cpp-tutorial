# 编程思维方法论
> 📖 相关章节：[编程入门](../../01-C语言/导学/00-编程入门.md)、[设计原则SOLID](../../04-工程实践/02-设计原则SOLID.md)

> 编程不只是写代码，更是一种思维方式——掌握正确的思维方法，比掌握一百个语法特性更重要。

***

### 1. 为什么需要[思维方法论](32-思维方法论.md)

很多初学者学会了语法，却不知道怎么把需求变成代码。这不是语法不够，而是缺乏思维方法。就像学会了所有汉字，不等于能写出好文章——关键在于思维框架。

```
需求 → ??? → 代码
       ↑
    这一步靠[思维方法论](32-思维方法论.md)
```

以下七种编程思维，覆盖了从需求分析到代码实现的全过程：

| 思维方法 | 核心问题 | 一句话 |
|---------|---------|--------|
| 分解思维 | 问题太大怎么办？ | 大问题拆小问题 |
| 抽象思维 | 细节太多怎么办？ | 提取共性，隐藏细节 |
| 递归思维 | 问题自相似怎么办？ | 大问题化小，小到直接解 |
| 模式思维 | 重复劳动怎么办？ | 识别重复，提取模式 |
| 权衡思维 | 方案冲突怎么办？ | 没有银弹，只有取舍 |
| 渐进思维 | 一次写不好怎么办？ | 先跑通，再优化 |
| 调试思维 | 出了Bug怎么办？ | 假设驱动，逐步排除 |

### 2. 分解思维——大问题拆小问题

#### 核心思想

面对一个复杂问题，不要试图一次性解决，而是把它拆成若干小问题，逐个击破。

```
"开发一个学生管理系统"
         │
    ┌────┼────┐
    ▼    ▼    ▼
 数据管理  成绩管理  界面展示
    │      │      │
  ┌─┴─┐  ┌─┴─┐  ┌─┴─┐
  ▼   ▼  ▼   ▼  ▼   ▼
 增  删  录入 统计 菜单 报表
 改  查  修改 排名 交互 导出
```

#### 编程实例：文件统计工具

需求：统计一个文本文件中的字符数、单词数、行数。

```cpp
#include <iostream>
#include <fstream>
#include <string>

// ❌ 不分解：一个函数搞定所有事
void count_all_bad(const std::string& filename) {
    std::ifstream file(filename);
    int chars = 0, words = 0, lines = 0;
    bool in_word = false;
    char c;
    while (file.get(c)) {
        chars++;
        if (c == '\n') lines++;
        if (isspace(c)) {
            in_word = false;
        } else if (!in_word) {
            words++;
            in_word = true;
        }
    }
    std::cout << "字符: " << chars << " 单词: " << words
              << " 行: " << lines << "\n";
}

// ✅ 分解后：每个函数只做一件事
int count_chars(const std::string& content) {
    return static_cast<int>(content.size());
}

int count_words(const std::string& content) {
    int count = 0;
    bool in_word = false;
    for (char c : content) {
        if (isspace(c)) {
            in_word = false;
        } else if (!in_word) {
            count++;
            in_word = true;
        }
    }
    return count;
}

int count_lines(const std::string& content) {
    int count = 0;
    for (char c : content) {
        if (c == '\n') count++;
    }
    return count + 1;  // 最后一行可能没有换行符
}

std::string read_file(const std::string& filename) {
    std::ifstream file(filename);
    return std::string(std::istreambuf_iterator<char>(file),
                       std::istreambuf_iterator<char>());
}

void count_all_good(const std::string& filename) {
    std::string content = read_file(filename);
    std::cout << "字符: " << count_chars(content)
              << " 单词: " << count_words(content)
              << " 行: " << count_lines(content) << "\n";
}
```

**分解的好处**：
- 每个函数可以独立测试
- 可以单独复用（比如只统计单词数）
- 修改一个统计逻辑不影响其他

### 3. 抽象思维——提取共性，隐藏细节

#### 核心思想

从具体事物中提取共同特征，忽略不重要的细节，形成通用模型。

```
具体的猫、狗、鸟
    ↓ 提取共性
"动物"（抽象）
    ↓ 隐藏细节
名字、年龄、叫声（接口）
```

#### 编程实例：日志系统

```cpp
#include <string>
#include <memory>
#include <iostream>

// ❌ 没有抽象：直接硬编码输出方式
void log_to_console(const std::string& msg) {
    std::cout << "[LOG] " << msg << "\n";
}
// 如果要加文件日志、网络日志，就要改调用方

// ✅ 抽象后：定义接口，隐藏实现细节
class Logger {
public:
    virtual ~Logger() = default;
    virtual void log(const std::string& msg) = 0;
};

class ConsoleLogger : public Logger {
public:
    void log(const std::string& msg) override {
        std::cout << "[LOG] " << msg << "\n";
    }
};

class FileLogger : public Logger {
    std::string filepath_;
public:
    FileLogger(const std::string& path) : filepath_(path) {}
    void log(const std::string& msg) override {
        // 写入文件的具体细节被隐藏
        FILE* f = fopen(filepath_.c_str(), "a");
        if (f) {
            fprintf(f, "[LOG] %s\n", msg.c_str());
            fclose(f);
        }
    }
};

// 调用方只依赖抽象接口
class Application {
    std::shared_ptr<Logger> logger_;
public:
    Application(std::shared_ptr<Logger> logger) : logger_(logger) {}
    void run() {
        logger_->log("应用启动");
        logger_->log("执行任务");
        logger_->log("应用退出");
    }
};

int main() {
    // 可以随时替换日志实现，调用方无需修改
    auto app = Application(std::make_shared<ConsoleLogger>());
    app.run();
    return 0;
}
```

**抽象的好处**：
- 调用方不需要知道实现细节
- 可以轻松替换实现（Console → File → Network）
- 新增实现不影响已有代码

### 4. 递归思维——自顶向下，自底向上

#### 核心思想

如果一个问题的结构和它的子问题结构相同，就可以用递归：把大问题化为同构的小问题，直到小到可以直接解决。

```
计算阶乘 n!:
  n! = n × (n-1)!    ← 大问题化为小问题
  0! = 1              ← 基准情况（直接解决）
```

#### 编程实例：目录遍历

```cpp
#include <iostream>
#include <filesystem>
#include <vector>

namespace fs = std::filesystem;

// 递归思维：遍历目录 = 遍历当前项 + 遍历子目录
std::vector<std::string> find_files(const fs::path& dir,
                                     const std::string& ext) {
    std::vector<std::string> result;

    for (const auto& entry : fs::directory_iterator(dir)) {
        if (entry.is_regular_file()) {
            if (entry.path().extension() == ext) {
                result.push_back(entry.path().string());
            }
        } else if (entry.is_directory()) {
            // 递归：子目录是同构的更小问题
            auto sub = find_files(entry.path(), ext);
            result.insert(result.end(), sub.begin(), sub.end());
        }
    }

    return result;
}

int main() {
    auto cpp_files = find_files(".", ".cpp");
    for (const auto& f : cpp_files) {
        std::cout << f << "\n";
    }
    return 0;
}
```

#### 自顶向下 vs 自底向上

| 策略 | 思路 | 适用场景 |
|------|------|---------|
| 自顶向下 | 先处理当前层，再递归处理子层 | 目录遍历、树的先序遍历 |
| 自底向上 | 先递归处理子层，再合并结果 | 归并排序、树的后序遍历 |

```cpp
#include <vector>
#include <algorithm>
#include <iostream>

// 自顶向下：归并排序
void merge_sort(std::vector<int>& arr, int left, int right) {
    if (left >= right) return;  // 基准情况

    int mid = left + (right - left) / 2;
    merge_sort(arr, left, mid);      // 先递归左半
    merge_sort(arr, mid + 1, right); // 再递归右半

    // 合并两个有序子数组
    std::vector<int> tmp(right - left + 1);
    std::merge(arr.begin() + left, arr.begin() + mid + 1,
               arr.begin() + mid + 1, arr.begin() + right + 1,
               tmp.begin());
    std::copy(tmp.begin(), tmp.end(), arr.begin() + left);
}
```

**递归思维要点**：
- 先找基准情况（什么时候直接返回）
- 假设子问题已经解决，只处理当前层
- 注意递归深度，必要时转为迭代

### 5. 模式思维——识别重复，提取模式

#### 核心思想

当你发现自己在写重复的代码时，停下来想想：这些代码有什么共同模式？能否提取成通用的解决方案？

```
写了一遍排序 → 又写了一遍搜索 → 又写了一遍遍历
         ↓ 识别模式
"迭代器模式"——统一遍历方式
```

#### 编程实例：资源管理模式

```cpp
#include <iostream>
#include <fstream>
#include <memory>

// 模式识别：打开→使用→关闭，反复出现
// C 语言手动管理：
void old_style() {
    FILE* f = fopen("data.txt", "r");  // 打开
    if (!f) return;
    // ... 使用 ...
    fclose(f);  // 关闭（容易忘记！）
}

// C++ 提取模式：RAII（资源获取即初始化）
class FileHandle {
    FILE* file_;
public:
    FileHandle(const char* path, const char* mode)
        : file_(fopen(path, mode)) {
        if (!file_) throw std::runtime_error("无法打开文件");
    }
    ~FileHandle() {
        if (file_) fclose(file_);  // 析构自动关闭
    }
    FILE* get() { return file_; }

    // 禁止拷贝
    FileHandle(const FileHandle&) = delete;
    FileHandle& operator=(const FileHandle&) = delete;
};

void new_style() {
    FileHandle f("data.txt", "r");  // 打开
    // ... 使用 f.get() ...
    // 无需手动关闭，离开作用域自动析构
}

// 更进一步：识别出 RAII 是通用模式
// std::unique_ptr、std::lock_guard、std::fstream 都是 RAII
void modern_style() {
    auto f = std::make_unique<FILE*>(fopen("data.txt", "r"));
    std::ifstream file("data.txt");  // 标准 RAII
}
```

#### 常见编程模式

| 模式 | 识别信号 | 解决方案 |
|------|---------|---------|
| RAII | 打开→使用→关闭 | 构造获取，析构释放 |
| 策略模式 | 多个 if-else 选择算法 | 提取算法接口，运行时切换 |
| 观察者模式 | 一处变化需要通知多处 | 事件订阅/回调 |
| 工厂模式 | 根据条件创建不同对象 | 统一创建接口 |
| 迭代器模式 | 不同容器需要统一遍历 | 提供统一的 begin/end |

```cpp
#include <vector>
#include <algorithm>
#include <iostream>

// 模式思维实例：策略模式
class SortStrategy {
public:
    virtual ~SortStrategy() = default;
    virtual void sort(std::vector<int>& data) = 0;
};

class BubbleSort : public SortStrategy {
public:
    void sort(std::vector<int>& data) override {
        for (size_t i = 0; i < data.size(); i++)
            for (size_t j = 0; j + 1 < data.size() - i; j++)
                if (data[j] > data[j + 1])
                    std::swap(data[j], data[j + 1]);
    }
};

class StdSort : public SortStrategy {
public:
    void sort(std::vector<int>& data) override {
        std::sort(data.begin(), data.end());
    }
};

class Sorter {
    SortStrategy* strategy_;
public:
    Sorter(SortStrategy* s) : strategy_(s) {}
    void sort(std::vector<int>& data) { strategy_->sort(data); }
};
```

### 6. 权衡思维——没有银弹，只有取舍

#### 核心思想

编程中几乎所有决策都是权衡。没有"完美"的方案，只有"在当前约束下最合适"的方案。

```
时间 vs 空间
简洁 vs 可读
安全 vs 性能
灵活 vs 简单
通用 vs 高效
```

#### 编程实例：查找的权衡

```cpp
#include <vector>
#include <unordered_map>
#include <algorithm>
#include <iostream>
#include <chrono>

// 权衡一：时间 vs 空间

// 空间优先（省内存，慢）
int find_in_vector(const std::vector<int>& data, int target) {
    auto it = std::find(data.begin(), data.end(), target);
    return (it != data.end()) ? static_cast<int>(it - data.begin()) : -1;
    // 时间 O(n)，空间 O(1)
}

// 时间优先（快，费内存）
class FastFinder {
    std::unordered_map<int, int> index_;
public:
    FastFinder(const std::vector<int>& data) {
        for (int i = 0; i < static_cast<int>(data.size()); i++) {
            index_[data[i]] = i;
        }
    }
    int find(int target) const {
        auto it = index_.find(target);
        return (it != index_.end()) ? it->second : -1;
        // 时间 O(1)，空间 O(n)
    }
};

// 权衡二：简洁 vs 可读

// 简洁但难读
int fibonacci_compact(int n) {
    return (n <= 1) ? n : fibonacci_compact(n - 1) + fibonacci_compact(n - 2);
}

// 冗长但好读
int fibonacci_readable(int n) {
    if (n <= 1) {
        return n;
    }
    int prev = 0;
    int curr = 1;
    for (int i = 2; i <= n; i++) {
        int next = prev + curr;
        prev = curr;
        curr = next;
    }
    return curr;
}

// 权衡三：安全 vs 性能

// 安全：边界检查
int safe_access(const std::vector<int>& v, size_t index) {
    return v.at(index);  // 越界抛异常
}

// 性能：无检查
int fast_access(const std::vector<int>& v, size_t index) {
    return v[index];  // 越界是未定义行为
}
```

**常见权衡决策表**：

| 场景 | 选择 | 原因 |
|------|------|------|
| 原型开发 | 简洁优先 | 快速验证想法 |
| 生产代码 | 可读优先 | 长期维护成本高 |
| 嵌入式系统 | 空间优先 | 内存受限 |
| 高频交易 | 时间优先 | 纳秒级延迟要求 |
| 用户输入处理 | 安全优先 | 永远不信任输入 |
| 内部数据结构 | 性能优先 | 已验证的数据 |

### 7. 渐进思维——先跑通，再优化

#### 核心思想

不要试图一次写出完美的代码。先让程序跑通，再逐步优化。过早优化是万恶之源。

```
第一步：让它工作（Make it work）
第二步：让它正确（Make it right）
第三步：让它快速（Make it fast）
```

#### 编程实例：排序功能

```cpp
#include <vector>
#include <algorithm>
#include <iostream>

// 第一步：让它工作——用最简单的方式实现
void sort_v1(std::vector<int>& data) {
    // 冒泡排序，最直观
    for (size_t i = 0; i < data.size(); i++) {
        for (size_t j = 0; j + 1 < data.size() - i; j++) {
            if (data[j] > data[j + 1]) {
                std::swap(data[j], data[j + 1]);
            }
        }
    }
}

// 第二步：让它正确——处理边界情况
void sort_v2(std::vector<int>& data) {
    if (data.size() <= 1) return;  // 边界情况
    for (size_t i = 0; i < data.size(); i++) {
        bool swapped = false;
        for (size_t j = 0; j + 1 < data.size() - i; j++) {
            if (data[j] > data[j + 1]) {
                std::swap(data[j], data[j + 1]);
                swapped = true;
            }
        }
        if (!swapped) break;  // 提前终止
    }
}

// 第三步：让它快速——使用更高效的算法
void sort_v3(std::vector<int>& data) {
    std::sort(data.begin(), data.end());  // O(n log n)
}

// 渐进开发流程示例
int main() {
    std::vector<int> data = {5, 3, 1, 4, 2};

    // 阶段一：验证逻辑正确
    sort_v1(data);
    for (int v : data) std::cout << v << " ";
    std::cout << "\n";

    // 阶段二：处理边界
    std::vector<int> empty;
    sort_v2(empty);  // 不会崩溃

    // 阶段三：性能优化
    std::vector<int> big(100000);
    sort_v3(big);  // 快速排序

    return 0;
}
```

**渐进开发的节奏**：

```
写代码 → 测试 → 重构 → 测试 → 优化 → 测试
  ↑                                    │
  └────────────────────────────────────┘
```

> 每一步都有测试保护，确保优化没有引入 Bug。

### 8. 调试思维——假设驱动的排查方法

#### 核心思想

调试不是随机尝试，而是科学方法：观察现象 → 提出假设 → 设计实验 → 验证假设 → 修正或确认。

```
Bug 出现
  │
  ▼
观察现象（什么输入？什么输出？什么错误？）
  │
  ▼
提出假设（"可能是数组越界"）
  │
  ▼
设计实验（加边界检查打印）
  │
  ▼
验证假设 ──假设正确──→ 修复 Bug
  │
  │ 假设错误
  ▼
提出新假设（"可能是空指针"）
  │
  ▼
继续循环...
```

#### 编程实例：段错误排查

```cpp
#include <iostream>
#include <vector>

// Bug：程序偶尔崩溃
class DataProcessor {
    std::vector<int>* data_;
    int last_result_;
public:
    DataProcessor() : data_(nullptr), last_result_(0) {}

    void set_data(std::vector<int>* data) {
        data_ = data;
    }

    int process() {
        // ❌ Bug：data_ 可能是空指针或悬空指针
        int sum = 0;
        for (int v : *data_) {
            sum += v;
        }
        last_result_ = sum;
        return sum;
    }
};

// 调试思维：假设驱动排查

// 假设1："data_ 是空指针"
// 实验：加空指针检查
int process_safe_v1() {
    // 验证假设1
    if (!data_) {
        std::cerr << "假设1确认：data_ 是空指针\n";
        return 0;
    }
    int sum = 0;
    for (int v : *data_) {
        sum += v;
    }
    return sum;
}

// 如果假设1不成立（崩溃仍在发生）
// 假设2："data_ 指向已释放的内存"
// 实验：使用智能指针，避免悬空指针
#include <memory>

class DataProcessorV2 {
    std::shared_ptr<std::vector<int>> data_;
public:
    void set_data(std::shared_ptr<std::vector<int>> data) {
        data_ = data;
        std::cout << "数据设置完成, use_count=" << data_.use_count() << "\n";
    }

    int process() {
        if (!data_) {
            std::cerr << "假设1确认：data_ 是空指针\n";
            return 0;
        }
        std::cout << "处理数据, 大小=" << data_->size() << "\n";
        int sum = 0;
        for (int v : *data_) {
            sum += v;
        }
        return sum;
    }
};
```

**调试思维的核心原则**：

| 原则 | 说明 |
|------|------|
| 不要猜测 | 先观察，再假设 |
| 一次只改一个变量 | 同时改多处，无法定位原因 |
| 二分法 | 注释掉一半代码，看 Bug 是否消失 |
| 最小复现 | 找到触发 Bug 的最小输入 |
| 日志先行 | 在关键位置打印状态，而非盲目修改 |

```cpp
// 二分法调试示例
void complex_function() {
    step_1();  // 注释掉 step_1~3，Bug 还在吗？
    step_2();  // 注释掉 step_2~3，Bug 还在吗？
    step_3();  // 注释掉 step_3，Bug 还在吗？
    step_4();  // Bug 在这里！
    step_5();
}
```

### 9. 七种思维的协作关系

```
收到需求
  │
  ▼
【分解思维】拆成小任务
  │
  ▼
【抽象思维】提取接口，隐藏细节
  │
  ▼
【递归思维】处理自相似的子问题
  │
  ▼
【模式思维】识别重复，提取通用方案
  │
  ▼
【权衡思维】在约束下选择最优方案
  │
  ▼
【渐进思维】先跑通，再优化
  │
  ▼
【调试思维】Bug 出了，科学排查
```

七种思维不是孤立的，而是相互配合：

| 组合 | 效果 |
|------|------|
| 分解 + 抽象 | 拆分后对每个子问题抽象接口 |
| 递归 + 模式 | 递归结构中识别通用模式 |
| 权衡 + 渐进 | 先用简单方案跑通，再根据瓶颈权衡优化 |
| 渐进 + 调试 | 每步都有测试，Bug 容易定位 |

***

### 10. 极简总结

| 思维 | 一句话 | 关键动作 |
|------|--------|---------|
| 分解 | 大问题拆小 | 函数不超过 30 行 |
| 抽象 | 提取共性隐藏细节 | 面向接口编程 |
| 递归 | 自相似问题化小 | 找基准情况 |
| 模式 | 识别重复提取模式 | DRY（Don't Repeat Yourself） |
| 权衡 | 没有银弹只有取舍 | 明确约束再决策 |
| 渐进 | 先跑通再优化 | 红-绿-重构 |
| 调试 | 假设驱动科学排查 | 观察→假设→实验→验证 |

> **核心公式**：好代码 = 分解问题 + 抽象接口 + 识别模式 + 合理权衡 + 渐进实现 + 科学调试。
