编译通过了但链接失败了？链接错误往往比编译错误更令人困惑。本文汇总了 10 个最常见的链接错误及其解决方法。

## 编译与链接的关系

在理解链接错误之前，先了解编译的三个阶段：

| 阶段 | 工作内容 | 产生的错误类型 |
|------|---------|-------------|
| 预处理 | 展开宏、处理 `#include` | 预处理错误 |
| 编译 | 将源码翻译为目标文件（`.o`/`.obj`） | 编译错误 |
| 链接 | 将目标文件和库合并为可执行文件 | 链接错误 |

链接错误的核心原因：**编译器看到了声明，但链接器找不到定义。**

## 1. 未定义的引用 `undefined reference`

**错误信息：** `undefined reference to 'xxx'`

**含义：** 链接器找不到函数或变量的定义。

**这是最常见的链接错误，原因有多种：**

### 原因一：只声明了函数但没有实现

```cpp
// ❌ 错误：声明了但没实现
// main.cpp
void printHello();  // 声明
int main() {
    printHello();   // 链接时找不到定义
    return 0;
}

// ✅ 正确：提供实现
// main.cpp
void printHello();  // 声明
int main() {
    printHello();
    return 0;
}
void printHello() {  // 定义
    std::cout << "Hello" << std::endl;
}
```

### 原因二：忘记链接源文件

```cpp
// ❌ 错误：只编译了 main.cpp，没编译 utils.cpp
// utils.cpp
void helper() { /* ... */ }
// main.cpp
void helper();  // 声明
int main() { helper(); }  // 链接错误！

// ✅ 正确：编译时包含所有源文件
// g++ main.cpp utils.cpp -o main
```

### 原因三：忘记链接库

```cpp
// ❌ 错误：使用了数学函数但没链接数学库
#include <cmath>
int main() {
    double x = sin(3.14);  // 链接错误
}

// ✅ 正确：链接时加上 -lm
// g++ main.cpp -lm -o main
```

## 2. 多重定义 `multiple definition`

**错误信息：** `multiple definition of 'xxx'`

**含义：** 同一个符号在多个目标文件中被定义了。

**原因：** 在头文件中定义了变量或非 `inline` 函数，然后被多个源文件包含。

```cpp
// ❌ 错误：头文件中定义变量
// global.h
int g_count = 0;  // 这是定义，不是声明！
// a.cpp
#include "global.h"  // g_count 定义一次
// b.cpp
#include "global.h"  // g_count 又定义一次 → 多重定义！

// ✅ 正确：头文件中声明，源文件中定义
// global.h
extern int g_count;  // 声明
// global.cpp
int g_count = 0;     // 定义
// a.cpp 和 b.cpp 只需 #include "global.h"
```

```cpp
// ❌ 错误：头文件中定义非 inline 函数
// utils.h
void helper() { /* ... */ }  // 非 inline 定义

// ✅ 正确：方式一，加 inline
// utils.h
inline void helper() { /* ... */ }

// ✅ 正确：方式二，声明与定义分离
// utils.h
void helper();       // 声明
// utils.cpp
void helper() { /* ... */ }  // 定义
```

## 3. 找不到库 `cannot find -lXXX`

**错误信息：** `/usr/bin/ld: cannot find -lXXX`

**含义：** 链接器找不到指定的库文件。

**原因：** 库未安装、库路径未指定、库名拼写错误。

```bash
# ❌ 错误：库未安装
g++ main.cpp -lpthread -o main
# 如果系统没有 libpthread.so，就会报错

# ✅ 正确：安装库后重试
# Ubuntu/Debian: sudo apt-get install libpthread-stubs0-dev
# 然后重新编译
```

```bash
# ✅ 正确：指定库搜索路径
g++ main.cpp -L/usr/local/lib -lmylib -o main
```

| 解决方法 | 命令示例 |
|---------|---------|
| 安装缺失的库 | `sudo apt install libxxx-dev` |
| 指定库路径 | `-L/path/to/lib` |
| 检查库名拼写 | `ldconfig -p | grep xxx` |
| 查找库文件位置 | `locate libxxx` |

## 4. 未定义符号 `undefined symbol`

**错误信息：** `undefined symbol: xxx`（运行时）

**含义：** 动态链接时找不到符号，通常在运行时才报错。

**原因：** 动态库缺失或版本不匹配。

```bash
# 查看程序依赖的动态库
ldd ./myprogram

# 查看动态库提供的符号
nm -D libmylib.so
```

## 5. 重复符号 `duplicate symbol`

**错误信息：** `duplicate symbol 'xxx' in: yyy.o zzz.o`

**含义：** 与 `multiple definition` 类似，同一个符号在多个目标文件中重复。

**常见原因：** 在头文件中定义了全局变量或非 `inline` 函数。

```cpp
// ❌ 错误
// types.h
struct Config {
    int value = 42;
};
Config defaultConfig;  // 每个包含此头文件的 .cpp 都会生成一个定义

// ✅ 正确
// types.h
struct Config {
    int value = 42;
};
extern Config defaultConfig;  // 声明
// types.cpp
Config defaultConfig;  // 定义
```

## 6. 无法解析的外部符号 `unresolved external symbol`

**错误信息：** `unresolved external symbol "xxx"` （MSVC）

**含义：** 这是 MSVC 编译器对 `undefined reference` 的说法，含义完全相同。

**常见原因：**

| 原因 | 解决方法 |
|------|---------|
| 忘记添加 `.cpp` 文件到项目 | 在 IDE 中将源文件加入项目 |
| 忘记链接 `.lib` 文件 | 项目属性 → 链接器 → 输入 → 附加依赖项 |
| C/C++ 混编缺少 `extern "C"` | 添加 `extern "C"` 声明 |
| 模板类实现写在 `.cpp` 中 | 模板实现应放在头文件中 |

## 7. ld 返回 1 `ld returned 1 exit status`

**错误信息：** `collect2: error: ld returned 1 exit status`

**含义：** 链接器执行失败，这是一个通用错误，需要看上面的具体错误信息。

**常见原因：**

- 程序已经在运行，无法覆盖可执行文件
- 缺少库或目标文件
- 之前的编译错误导致目标文件不完整

```bash
# ❌ 常见场景：程序正在运行
# 修改代码后重新编译，但旧程序还在运行
g++ main.cpp -o main  # 无法写入 main，因为被占用

# ✅ 解决：先关闭正在运行的程序，再重新编译
```

## 8. 重定位截断 `relocation truncated to fit`

**错误信息：** `relocation truncated to fit: R_X86_64_PC32 against symbol 'xxx'`

**含义：** 地址空间不够，通常是因为编译为 32 位但数据量太大。

**解决方法：** 编译为 64 位或使用 `-mcmodel=medium`/`-mcmodel=large`。

```bash
# ✅ 使用更大的内存模型
g++ -mcmodel=large main.cpp -o main
```

## 9. 虚表未定义 `undefined reference to vtable`

**错误信息：** `undefined reference to 'vtable for xxx'`

**含义：** 类声明了虚函数但没有提供实现。

**原因：** 声明了虚函数但忘记实现，或者虚析构函数没有实现。

```cpp
// ❌ 错误：虚函数没有实现
class Animal {
public:
    virtual void speak();  // 声明了但没实现
    virtual ~Animal();     // 析构函数也没实现
};

// ✅ 正确：提供所有虚函数的实现
class Animal {
public:
    virtual void speak() { std::cout << "..." << std::endl; }
    virtual ~Animal() {}
};
```

**注意：** 即使是纯虚函数，析构函数也必须实现：

```cpp
// ✅ 正确：纯虚类也需要实现析构函数
class Animal {
public:
    virtual void speak() = 0;  // 纯虚函数
    virtual ~Animal() {}        // 必须实现！
};
```

## 10. 无法打开输出文件 `cannot open output file`

**错误信息：** `cannot open output file 'xxx': Permission denied`

**含义：** 链接器无法写入输出文件。

**原因：** 文件被占用、权限不足、路径不存在。

```bash
# ✅ 解决方法
# 1. 关闭正在运行的程序
# 2. 检查文件权限
# 3. 确保输出目录存在
```

## C/C++ 混编导致的链接错误

这是一个非常常见的特殊场景：

```cpp
// ❌ 错误：C++ 调用 C 函数时没有 extern "C"
// mylib.c（C 文件）
int add(int a, int b) { return a + b; }
// main.cpp（C++ 文件）
int add(int a, int b);  // C++ 会做 name mangling，找不到 C 的 add
int main() { add(1, 2); }  // 链接错误！

// ✅ 正确：使用 extern "C"
// main.cpp
extern "C" int add(int a, int b);  // 告诉编译器这是 C 函数
int main() { add(1, 2); }
```

```cpp
// ✅ 更通用的写法（头文件中）
#ifdef __cplusplus
extern "C" {
#endif
int add(int a, int b);
#ifdef __cplusplus
}
#endif
```

## 调试链接错误的通用技巧

| 技巧 | 命令/方法 |
|------|----------|
| 查看符号表 | `nm xxx.o` 或 `objdump -t xxx.o` |
| 查看未定义符号 | `nm -u xxx.o` |
| 查看动态库依赖 | `ldd xxx` |
| 查看库中的符号 | `nm -D libxxx.so` |
| 开启详细链接输出 | `g++ ... -Wl,--verbose` |
| 检查编译所有源文件 | 确保 `.cpp` 文件都在编译命令中 |
