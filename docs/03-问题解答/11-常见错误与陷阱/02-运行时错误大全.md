# 运行时错误大全
> 📖 相关章节：[陷阱与技巧](../../04-工程实践/11-陷阱与技巧.md)、[内存管理](../../01-C语言/09-内存管理.md)

编译和链接都通过了，但程序运行时崩溃？运行时错误是最难调试的错误类型之一。本文汇总了 10 个最常见的运行时错误及其解决方法。

## 运行时错误的特点

| 特点 | 说明 |
|------|------|
| **不可预测** | 编译器无法检测，只在特定输入或条件下触发 |
| **难以复现** | 可能只在特定平台、特定数据下出现 |
| **后果严重** | 可能导致程序崩溃、数据损坏、安全漏洞 |
| **调试困难** | 需要运行时工具辅助定位 |

## 1. 段错误 `Segmentation Fault`

**错误信息：** `Segmentation fault (core dumped)`

**含义：** 程序试图访问不属于它的内存区域。

**常见原因：** 空指针解引用、数组越界、使用已释放的内存、栈溢出。

```cpp
// ❌ 错误：空指针解引用
int* ptr = nullptr;
*ptr = 10;  // 段错误！

// ❌ 错误：数组越界
int arr[5];
arr[100] = 42;  // 可能段错误

// ❌ 错误：使用已释放的内存
int* p = new int(10);
delete p;
*p = 20;  // 段错误或更隐蔽的问题

// ✅ 正确：始终检查指针有效性
int* ptr = getPointer();
if (ptr != nullptr) {
    *ptr = 10;
}
```

**调试方法：**

```bash
# 使用 GDB 调试
g++ -g main.cpp -o main    # 编译时加 -g 生成调试信息
gdb ./main                  # 启动 GDB
(gdb) run                   # 运行程序
# 崩溃后
(gdb) bt                    # 查看调用栈
```

## 2. 栈溢出 `Stack Overflow`

**错误信息：** `Segmentation fault`（与段错误相同的表现）

**含义：** 栈空间被耗尽，通常由无限递归或过大的局部变量引起。

**原因一：无限递归**

```cpp
// ❌ 错误：缺少递归终止条件
int factorial(int n) {
    return n * factorial(n - 1);  // n=0 时继续递归
}

// ✅ 正确：添加终止条件
int factorial(int n) {
    if (n <= 1) return 1;  // 终止条件
    return n * factorial(n - 1);
}
```

**原因二：局部变量过大**

```cpp
// ❌ 错误：栈上分配过大数组
void func() {
    int bigArray[10000000];  // 约 40MB，远超栈大小
}

// ✅ 正确：使用堆分配
void func() {
    int* bigArray = new int[10000000];
    // 使用 bigArray...
    delete[] bigArray;
}

// ✅ 正确：使用 std::vector
void func() {
    std::vector<int> bigArray(10000000);
}
```

| 栈大小参考 | 平台 | 默认大小 |
|-----------|------|---------|
| Linux | x86_64 | 8 MB |
| Windows | MSVC | 1 MB |
| macOS | x86_64 | 8 MB |

## 3. 数组越界

**错误信息：** 通常没有错误信息！这是最危险的地方。

**含义：** 访问数组时下标超出有效范围。

```cpp
// ❌ 错误：越界访问
int arr[5] = {1, 2, 3, 4, 5};
arr[5] = 10;  // 越界！有效下标是 0-4
arr[-1] = 20; // 越界！

// ✅ 正确：检查下标范围
for (int i = 0; i < 5; i++) {  // i < 5，不是 i <= 5
    arr[i] = i;
}

// ✅ 正确：使用 std::array 并用 at()
std::array<int, 5> arr = {1, 2, 3, 4, 5};
arr.at(5);  // 抛出 std::out_of_range 异常，而不是静默越界
```

## 4. 除以零

**错误信息：** `Floating point exception (core dumped)`（整数除以零）

**含义：** 整数除以零或对零取模。

```cpp
// ❌ 错误：整数除以零
int a = 10;
int b = 0;
int c = a / b;  // 浮点异常！

// ❌ 错误：取模零
int d = 10 % 0;  // 同样错误！

// ✅ 正确：检查除数
int divide(int a, int b) {
    if (b == 0) {
        std::cerr << "Error: division by zero" << std::endl;
        return 0;
    }
    return a / b;
}
```

**注意：** 浮点数除以零不会崩溃，而是产生 `inf` 或 `nan`：

```cpp
double x = 1.0 / 0.0;   // x = inf
double y = 0.0 / 0.0;   // y = nan
```

## 5. 空指针解引用

**错误信息：** `Segmentation fault`

**含义：** 对空指针进行解引用操作。

```cpp
// ❌ 错误：未检查返回值
int* findValue(std::vector<int>& v, int target) {
    for (auto& elem : v) {
        if (elem == target) return &elem;
    }
    return nullptr;  // 没找到返回空
}

int main() {
    std::vector<int> v = {1, 2, 3};
    int* p = findValue(v, 99);
    *p = 10;  // p 是 nullptr，段错误！
}

// ✅ 正确：检查指针
int* p = findValue(v, 99);
if (p != nullptr) {
    *p = 10;
} else {
    std::cout << "Value not found" << std::endl;
}
```

## 6. 堆内存损坏

**错误信息：** 可能是 `malloc: *** error` 或 `double free or corruption`

**含义：** 堆管理数据结构被破坏。

**常见原因：** 多次 `delete`、越界写入堆内存、`delete[]` 与 `delete` 混用。

```cpp
// ❌ 错误：重复释放
int* p = new int(10);
delete p;
delete p;  // 双重释放！

// ❌ 错误：new/delete[] 混用
int* p = new int(10);
delete[] p;  // 应该用 delete p

// ❌ 错误：堆缓冲区溢出
int* arr = new int[5];
arr[10] = 42;  // 堆溢出，破坏堆管理结构
delete[] arr;  // 可能崩溃

// ✅ 正确：使用智能指针和容器
auto p = std::make_unique<int>(10);  // 自动释放
std::vector<int> arr(5);              // 自动管理
```

## 7. 使用已释放的内存（Use After Free）

**错误信息：** 可能无错误信息，或产生不可预测的行为。

**含义：** 访问已经被 `delete` 或 `free` 的内存。

```cpp
// ❌ 错误：使用已释放的内存
int* p = new int(10);
delete p;
std::cout << *p << std::endl;  // 未定义行为！可能打印 10，也可能崩溃

// ❌ 错误：引用已释放的内存
int& ref = *new int(10);
delete &ref;
std::cout << ref << std::endl;  // 悬挂引用

// ❌ 错误：容器迭代器失效
std::vector<int> v = {1, 2, 3, 4, 5};
auto it = v.begin();
v.push_back(6);  // 可能导致重新分配，it 失效
*it;  // 未定义行为！

// ✅ 正确：使用智能指针
auto p = std::make_shared<int>(10);
auto q = p;  // 引用计数 +1
// 不需要手动 delete，引用计数为 0 时自动释放
```

## 8. 死循环/无限递归

**错误信息：** 程序卡住不响应。

**含义：** 循环条件永远为真或递归没有终止。

```cpp
// ❌ 错误：循环条件永远为真
for (int i = 0; i < 10; i--) {  // i-- 应该是 i++
    // 永远不会结束
}

// ❌ 错误：while 条件写错
int x = 10;
while (x = 1) {  // = 是赋值，不是 ==！永远为真
    x++;
}

// ✅ 正确
for (int i = 0; i < 10; i++) {
    // 正确递增
}

while (x == 1) {  // 使用 ==
    // ...
}
```

## 9. 未初始化变量读取

**错误信息：** 通常没有错误信息，但值是不确定的。

**含义：** 读取了未初始化的局部变量。

```cpp
// ❌ 错误：使用未初始化的变量
int main() {
    int x;  // 未初始化，值是随机的
    std::cout << x << std::endl;  // 输出不确定的值

    int arr[10];  // 未初始化
    if (arr[0] > 0) {  // 条件判断不确定
        // 可能执行也可能不执行
    }
}

// ✅ 正确：始终初始化变量
int x = 0;
int arr[10] = {};  // 全部初始化为 0
std::string s;     // 类类型有默认构造函数，自动初始化
```

**编译器警告：** 使用 `-Wuninitialized` 可以检测部分未初始化使用。

## 10. 纯虚函数调用

**错误信息：** `pure virtual method called` 或 `R6025 - pure virtual function call`

**含义：** 在构造或析构函数中调用了纯虚函数。

```cpp
// ❌ 错误：构造函数中调用纯虚函数
class Base {
public:
    Base() {
        init();  // 调用纯虚函数！
    }
    virtual void init() = 0;
};

class Derived : public Base {
public:
    void init() override { std::cout << "Derived init" << std::endl; }
};

// 创建 Derived 对象时：
// 1. 先调用 Base 构造函数
// 2. 此时 vtable 还是 Base 的，init() 是纯虚的
// 3. 调用纯虚函数 → 崩溃！

// ✅ 正确：不在构造/析构函数中调用虚函数
class Base {
public:
    Base() {
        // 不要在这里调用虚函数
    }
    void init() {  // 非虚函数
        doInit();
    }
protected:
    virtual void doInit() = 0;
};

// 在对象构造完成后再调用 init()
Derived d;
d.init();
```

## 调试运行时错误的工具

| 工具 | 用途 | 使用方法 |
|------|------|---------|
| **GDB** | 调试崩溃 | `gdb ./program` → `run` → `bt` |
| **Valgrind** | 检测内存错误 | `valgrind ./program` |
| **AddressSanitizer** | 检测内存错误 | `g++ -fsanitize=address -g main.cpp` |
| **UBSanitizer** | 检测未定义行为 | `g++ -fsanitize=undefined -g main.cpp` |
| **LLDB** | macOS 调试器 | `lldb ./program` |
| **Dr. Memory** | Windows 内存检测 | `drmemory -batch -quiet -- ./program.exe` |

## 预防运行时错误的最佳实践

1. **始终初始化变量** — 不要依赖默认值
2. **检查指针** — 解引用前确认非空
3. **检查数组边界** — 使用 `at()` 或手动检查
4. **使用智能指针** — 避免 `new`/`delete` 的手动管理
5. **使用容器而非原始数组** — `std::vector`、`std::array`
6. **编译时开启警告和 Sanitizer** — `-Wall -Wextra -fsanitize=address`
7. **编写单元测试** — 覆盖边界条件
