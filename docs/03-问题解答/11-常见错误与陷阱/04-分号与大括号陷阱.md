# 分号与大括号陷阱
> 📖 相关章节：[陷阱与技巧](../../04-工程实践/10-陷阱与技巧.md)、[内存管理](../../01-C语言/09-内存管理.md)

分号和大括号看似简单，却是 C/C++ 初学者最容易踩坑的地方。一个多余的分号或一个缺失的大括号，可能导致程序行为完全不同，而且编译器不会报错！

## 分号陷阱

### 1. 缺少分号

最常见的错误，但编译器会明确报错。

```cpp
// ❌ 错误：缺少分号
int x = 10   // 缺少分号
int y = 20   // 编译器在下一行才发现错误

// ✅ 正确
int x = 10;
int y = 20;
```

**注意：** 编译器报错的行号通常是缺少分号的**下一行**，因为编译器在下一行开头才意识到上一行没有结束。

### 2. `if` 后面多余的分号（最危险的陷阱！）

```cpp
// ❌ 错误：if 后面多了分号
int x = 5;
if (x > 10);   // 注意这个分号！相当于 if (x > 10) { } 空语句
{
    std::cout << "x is greater than 10" << std::endl;
    // 这段代码总是会执行！因为大括号是独立的代码块
}

// ✅ 正确：if 后面不要分号
if (x > 10) {
    std::cout << "x is greater than 10" << std::endl;
}
```

**为什么危险？** 编译器不会报错，程序正常运行，但逻辑完全错误。这种 bug 极难发现。

### 3. `for` 后面多余的分号

```cpp
// ❌ 错误：for 后面多了分号
for (int i = 0; i < 10; i++);  // 循环体是空语句！
{
    std::cout << i << std::endl;  // i 不在此作用域，且只执行一次
}

// ✅ 正确
for (int i = 0; i < 10; i++) {
    std::cout << i << std::endl;
}
```

### 4. `while` 后面多余的分号

```cpp
// ❌ 错误：while 后面多了分号 → 无限循环！
int x = 0;
while (x < 10);  // 循环体是空语句，x 永远不变 → 死循环！
{
    x++;
}

// ✅ 正确
while (x < 10) {
    x++;
}
```

### 5. 类定义后缺少分号

```cpp
// ❌ 错误：类定义后缺少分号
class MyClass {
    int data;
}  // 缺少分号！

// ✅ 正确：类定义后必须有分号
class MyClass {
    int data;
};
```

### 6. 结构体定义后缺少分号

```cpp
// ❌ 错误：结构体定义后缺少分号
struct Point {
    int x, y;
}  // 缺少分号！

// ✅ 正确
struct Point {
    int x, y;
};
```

## 大括号陷阱

### 7. 大括号不匹配

```cpp
// ❌ 错误：大括号不匹配
int main() {
    if (true) {
        for (int i = 0; i < 10; i++) {
            std::cout << i << std::endl;
        // 忘记关闭 for 的 }
    }  // 这个 } 关闭了 if
    // 缺少 main 的 }
```

**建议：** 写代码时先写出成对的大括号，再填充内容。

```cpp
// ✅ 好习惯：先写框架再填充
int main()
{
    if (true)
    {

    }
    return 0;
}
```

### 8. 悬挂 else 问题（Dangling Else）

这是 C/C++ 经典陷阱：`else` 与最近的 `if` 匹配，而不是与缩进对应的 `if` 匹配。

```cpp
// ❌ 错误：else 匹配内层 if，但缩进暗示匹配外层
int x = 5, y = 0;
if (x > 0)
    if (y > 0)
        std::cout << "both positive" << std::endl;
else
    std::cout << "x not positive" << std::endl;  // 实际匹配内层 if(y>0)！
    // x=5>0, y=0 不大于0，所以会执行 else → 输出 "x not positive"
    // 但实际上 x 是正数！

// ✅ 正确：使用大括号明确意图
if (x > 0) {
    if (y > 0) {
        std::cout << "both positive" << std::endl;
    }
} else {
    std::cout << "x not positive" << std::endl;
}
```

### 9. 单行 if/else 不加大括号导致错误

```cpp
// ❌ 危险：单行 if 不加大括号
if (condition)
    doSomething();
    doAnotherThing();  // 看起来属于 if，实际上总是执行！

// ✅ 正确：始终使用大括号
if (condition) {
    doSomething();
    doAnotherThing();
}
```

**更危险的场景——宏展开：**

```cpp
// ❌ 错误：宏中的 if 不加大括号
#define SAFE_DELETE(p) if (p != nullptr) delete p

if (condition)
    SAFE_DELETE(ptr);   // 展开后变成 if(condition) if(ptr!=nullptr) delete ptr;
else                     // 这个 else 匹配宏里的 if！
    doSomething();

// ✅ 正确：宏中使用 do-while(0)
#define SAFE_DELETE(p) do { if (p != nullptr) { delete p; p = nullptr; } } while(0)
```

### 10. `switch-case` 中的大括号与变量声明

```cpp
// ❌ 错误：在 case 中直接声明变量
switch (x) {
    case 1:
        int y = 10;  // 可能报错：不能跳过变量初始化
        std::cout << y << std::endl;
        break;
    case 2:
        // y 在此作用域可见，但可能未初始化
        break;
}

// ✅ 正确：在 case 中使用大括号创建作用域
switch (x) {
    case 1: {
        int y = 10;
        std::cout << y << std::endl;
        break;
    }
    case 2: {
        int y = 20;
        std::cout << y << std::endl;
        break;
    }
}
```

## 其他标点陷阱

### 11. 逗号与分号在 for 循环中的区别

```cpp
// ❌ 错误：用分号代替逗号
for (int i = 0; int j = 10; i < 10; i++, j--) {  // 语法错误
    // ...
}

// ✅ 正确：用逗号分隔同类型的表达式
for (int i = 0, j = 10; i < 10 && j > 0; i++, j--) {
    std::cout << i << " " << j << std::endl;
}
```

### 12. 逗号运算符陷阱

```cpp
// ❌ 错误：误用逗号运算符
int x = (1, 2, 3);  // x = 3，逗号运算符返回最后一个值
// 这不是把 1,2,3 赋给 x！

// ❌ 错误：函数调用中误用逗号
int a = 1, b = 2;
func(a, b);    // 调用 func，两个参数
func((a, b));  // 调用 func，一个参数！逗号运算符，值为 b

// ✅ 正确
func(a, b);  // 两个参数
```

### 13. 条件运算符中的分号陷阱

```cpp
// ❌ 错误：条件运算符中使用了语句而非表达式
int x = flag ? doA(); : doB();  // 语法错误

// ✅ 正确：条件运算符需要表达式
int x = flag ? a : b;
```

## 速查表：分号与大括号规则

| 场景 | 需要分号？ | 需要大括号？ |
|------|----------|------------|
| 普通语句 | ✅ | ❌ |
| `if` 条件后 | ❌ | ✅ 推荐 |
| `for` 条件后 | ❌ | ✅ 推荐 |
| `while` 条件后 | ❌ | ✅ 推荐 |
| `class` 定义后 | ✅ | — |
| `struct` 定义后 | ✅ | — |
| `enum` 定义后 | ✅ | — |
| `namespace` 后 | ❌ | ✅ |
| 函数定义后 | ❌ | ✅ |
| 函数声明后 | ✅ | ❌ |

## 最佳实践

1. **始终使用大括号** — 即使只有一行代码，也用大括号包裹
2. **先写成对的大括号** — 再填充内容，避免遗漏
3. **使用自动格式化** — 让工具帮你对齐大括号
4. **开启编译器警告** — `-Wempty-body` 可以检测空循环体
5. **代码审查** — 多余的分号很难自己发现，让同事帮忙检查
