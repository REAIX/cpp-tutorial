# 数组越界与缓冲区溢出
> 📖 相关章节：[陷阱与技巧](../../04-工程实践/11-陷阱与技巧.md)、[内存管理](../../01-C语言/09-内存管理.md)

数组越界和缓冲区溢出是 C/C++ 中最危险、最常见的安全漏洞来源。它们不仅会导致程序崩溃，还可能被攻击者利用来执行恶意代码。本文详细讲解这两类问题的原理、场景和防范方法。

## 基本概念

### 什么是数组越界？

数组越界是指访问数组时，下标超出了合法范围（0 到 N-1）。

### 什么是缓冲区溢出？

缓冲区溢出是数组越界的一种特殊形式，指写入数据超过了缓冲区的容量，覆盖了相邻的内存区域。

| 类型 | 方向 | 后果 |
|------|------|------|
| 栈缓冲区溢出 | 写入超过栈上数组大小 | 覆盖返回地址，可能被利用执行恶意代码 |
| 堆缓冲区溢出 | 写入超过堆上分配的大小 | 破坏堆管理结构，可能被利用 |
| 越界读取 | 读取超出数组范围 | 信息泄露 |

## 常见越界场景

### 1. 经典差一错误（Off-by-One）

```cpp
// ❌ 错误：循环条件多了一次
int arr[10];
for (int i = 0; i <= 10; i++) {  // i=10 时越界！
    arr[i] = i;
}

// ✅ 正确：i < 10
for (int i = 0; i < 10; i++) {
    arr[i] = i;
}
```

### 2. 字符串操作越界

```cpp
// ❌ 错误：strcpy 不检查目标缓冲区大小
char buf[10];
strcpy(buf, "Hello, World!");  // 14 字节（含 \0）> 10 字节，溢出！

// ✅ 正确：使用 strncpy 并手动添加终止符
char buf[10];
strncpy(buf, "Hello, World!", sizeof(buf) - 1);
buf[sizeof(buf) - 1] = '\0';

// ✅ 更好：使用 C++ string
std::string buf = "Hello, World!";  // 自动管理大小
```

### 3. `gets()` 函数——最危险的函数

```cpp
// ❌ 错误：gets() 不检查输入长度，永远不要使用！
char buf[100];
gets(buf);  // 如果输入超过 99 个字符，缓冲区溢出！

// ✅ 正确：使用 fgets
char buf[100];
fgets(buf, sizeof(buf), stdin);  // 限制读取长度

// ✅ 更好：使用 C++ cin
std::string line;
std::getline(std::cin, line);  // 自动扩展
```

### 4. `scanf` 格式字符串越界

```cpp
// ❌ 错误：scanf 读取字符串不限制长度
char name[20];
scanf("%s", name);  // 输入超过 19 字符就溢出！

// ✅ 正确：限制读取长度
scanf("%19s", name);  // 最多读 19 个字符，留一个给 \0

// ✅ 更好：使用 C++ cin
std::string name;
std::cin >> name;  // 自动扩展
```

### 5. 多维数组越界

```cpp
// ❌ 错误：行列索引搞混
int matrix[3][4];  // 3行4列
matrix[4][3] = 10;  // 行索引越界！有效范围是 0-2

// ✅ 正确
matrix[2][3] = 10;  // 最后一行最后一列
```

## 缓冲区溢出详解

### 6. 栈缓冲区溢出原理

```
高地址
┌──────────────┐
│  返回地址     │  ← 被溢出数据覆盖后，函数返回时跳转到攻击者指定的地址
├──────────────┤
│  旧的 EBP    │
├──────────────┤
│  局部变量     │
│  char buf[16]│  ← 缓冲区从这里开始
│              │  ← 溢出数据向高地址增长，覆盖返回地址
├──────────────┤
│  函数参数     │
└──────────────┘
低地址
```

```cpp
// ❌ 危险示例：栈缓冲区溢出
void vulnerable() {
    char buf[16];
    // 如果用户输入超过 15 个字符，就会溢出 buf
    // 覆盖栈上的返回地址
    gets(buf);  // 绝对不要用 gets！
}
```

### 7. 堆缓冲区溢出

```cpp
// ❌ 错误：堆缓冲区溢出
int* arr = new int[5];
for (int i = 0; i <= 5; i++) {  // i=5 时越界写入
    arr[i] = i * 10;
}
// 可能破坏堆管理结构，后续 new/delete 操作崩溃

// ✅ 正确
int* arr = new int[5];
for (int i = 0; i < 5; i++) {
    arr[i] = i * 10;
}

// ✅ 更好：使用 vector
std::vector<int> arr(5);
for (int i = 0; i < 5; i++) {
    arr[i] = i * 10;
}
```

### 8. 格式化字符串漏洞

```cpp
// ❌ 危险：用户输入作为格式字符串
char input[100];
fgets(input, sizeof(input), stdin);
printf(input);  // 如果输入包含 %s %x %n，可能泄露或修改内存！

// ✅ 正确：使用固定格式字符串
printf("%s", input);
```

## 越界读取

### 9. 越界读取导致信息泄露

```cpp
// ❌ 错误：越界读取可能泄露敏感信息
int secret = 123456;
int arr[3] = {1, 2, 3};
// arr[3] 可能读到 secret 的值
// arr[-1] 可能读到栈上其他数据

// ✅ 正确：始终检查边界
int index = getUserInput();
if (index >= 0 && index < 3) {
    std::cout << arr[index] << std::endl;
} else {
    std::cerr << "Invalid index" << std::endl;
}
```

## 安全替代方案

### 10. 使用安全函数替代危险函数

| 危险函数 | 安全替代 | 说明 |
|---------|---------|------|
| `gets()` | `fgets()` | 限制读取长度 |
| `strcpy()` | `strncpy()` / `strlcpy()` | 限制拷贝长度 |
| `strcat()` | `strncat()` / `strlcat()` | 限制拼接长度 |
| `sprintf()` | `snprintf()` | 限制输出长度 |
| `scanf("%s")` | `scanf("%Ns")` | 限制读取长度 |
| `printf(user_input)` | `printf("%s", user_input)` | 防止格式化字符串攻击 |

### 11. 使用 C++ 安全容器

```cpp
// ❌ C 风格：手动管理大小，容易出错
int* arr = new int[n];
arr[index] = value;  // 不检查边界
delete[] arr;

// ✅ C++ 风格：自动管理
std::vector<int> arr(n);
arr.at(index) = value;  // at() 会检查边界，越界抛出异常

// ✅ C++11：std::array 固定大小数组
std::array<int, 10> arr;
arr.at(index) = value;  // 边界检查
arr[index] = value;     // 不检查（与 C 数组相同）
```

### 12. 使用安全字符串

```cpp
// ❌ C 风格字符串
char buf[100];
strcat(buf, "hello");  // 可能溢出

// ✅ C++ string：自动管理内存
std::string s;
s += "hello";  // 自动扩展，不会溢出
```

## 检测工具

| 工具 | 类型 | 使用方法 |
|------|------|---------|
| **AddressSanitizer** | 编译时插桩 | `g++ -fsanitize=address -g main.cpp` |
| **Valgrind** | 运行时检测 | `valgrind ./program` |
| **Stack Canary** | 编译器保护 | `g++ -fstack-protector-all main.cpp` |
| **FORTIFY_SOURCE** | 编译时替换 | `g++ -D_FORTIFY_SOURCE=2 -O2 main.cpp` |
| **BoundChecker** | 运行时检测 | Windows 平台商业工具 |

### AddressSanitizer 示例

```bash
# 编译时开启 ASan
g++ -fsanitize=address -g -fno-omit-frame-pointer main.cpp -o main
./main
# 如果发生越界，ASan 会打印详细报告：
# ==12345==ERROR: AddressSanitizer: stack-buffer-overflow on address 0x...
# WRITE of size 4 at 0x... thread T0
```

## 编译器保护机制

| 机制 | GCC 选项 | 说明 |
|------|---------|------|
| 栈保护（Stack Canary） | `-fstack-protector-all` | 在栈上放置哨兵值，检测溢出 |
| FORTIFY_SOURCE | `-D_FORTIFY_SOURCE=2` | 编译时替换危险函数为安全版本 |
| 栈不可执行 | `-z noexecstack` | 防止在栈上执行代码 |
| PIE | `-fPIE -pie` | 地址随机化 |
| RELRO | `-Wl,-z,relro,-z,now` | 只读重定位 |

## 预防最佳实践

1. **使用 C++ 容器** — `std::vector`、`std::string`、`std::array`
2. **使用 `at()` 方法** — 带边界检查的下标访问
3. **永远不要用 `gets()`** — 已在 C11 中被移除
4. **限制输入长度** — `fgets`、`snprintf`、`scanf("%Ns")`
5. **开启编译器保护** — `-fstack-protector-all -D_FORTIFY_SOURCE=2`
6. **使用 Sanitizer 测试** — 开发时用 ASan 检测越界
7. **代码审查** — 特别关注数组操作和字符串操作
8. **静态分析** — 使用 `clang-tidy`、`cppcheck` 等工具
