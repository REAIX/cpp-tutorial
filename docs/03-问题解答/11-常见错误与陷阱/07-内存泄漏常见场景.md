# 内存泄漏常见场景
> 📖 相关章节：[陷阱与技巧](../../04-工程实践/11-陷阱与技巧.md)、[内存管理](../../01-C语言/09-内存管理.md)

内存泄漏是 C/C++ 程序中最常见的问题之一。程序分配了内存但忘记释放，导致可用内存逐渐减少，最终可能耗尽系统内存。本文详细讲解内存泄漏的常见场景、检测方法和预防措施。

## 什么是内存泄漏？

内存泄漏（Memory Leak）是指程序动态分配了内存，但在不再使用时没有释放，导致这部分内存无法被回收利用。

```
正常流程：malloc/new → 使用 → free/delete
内存泄漏：malloc/new → 使用 → 忘记释放！
```

## 内存泄漏的危害

| 危害 | 说明 |
|------|------|
| 内存逐渐增长 | 程序占用的内存越来越多 |
| 性能下降 | 系统可用内存减少，频繁换页 |
| 程序崩溃 | 最终耗尽内存，`new` 抛出异常 |
| 系统不稳定 | 影响其他程序运行 |
| 长时间运行程序致命 | 服务器程序可能运行数月，泄漏会累积 |

## 常见泄漏场景

### 1. 最简单：忘记 `delete`

```cpp
// ❌ 错误：忘记释放
void func() {
    int* p = new int(42);
    std::cout << *p << std::endl;
    // 函数结束，p 超出作用域，但内存没有释放！
}

// ✅ 正确：确保释放
void func() {
    int* p = new int(42);
    std::cout << *p << std::endl;
    delete p;
}

// ✅ 更好：使用智能指针
void func() {
    auto p = std::make_unique<int>(42);
    std::cout << *p << std::endl;
    // 自动释放，即使发生异常
}
```

### 2. 异常导致跳过 `delete`

```cpp
// ❌ 错误：异常导致内存泄漏
void func() {
    int* p = new int(42);
    mightThrow();    // 如果抛出异常，delete 不会执行！
    delete p;
}

// ✅ 正确：使用智能指针
void func() {
    auto p = std::make_unique<int>(42);
    mightThrow();    // 即使抛出异常，p 也会自动释放
}

// ✅ 正确：使用 try-catch
void func() {
    int* p = new int(42);
    try {
        mightThrow();
    } catch (...) {
        delete p;
        throw;  // 重新抛出
    }
    delete p;
}
```

### 3. `new[]` 与 `delete` 不匹配

```cpp
// ❌ 错误：new[] 但用 delete（不是 delete[]）
int* arr = new int[10];
delete arr;    // 未定义行为！只调用了第一个元素的析构

// ❌ 错误：new 但用 delete[]
int* p = new int(42);
delete[] p;    // 未定义行为！

// ✅ 正确：配对使用
int* arr = new int[10];
delete[] arr;

int* p = new int(42);
delete p;

// ✅ 更好：使用容器
std::vector<int> arr(10);  // 自动管理
auto p = std::make_unique<int>(42);  // 自动管理
```

### 4. 提前返回导致泄漏

```cpp
// ❌ 错误：多个 return 路径，某个路径忘记 delete
void process(const std::string& input) {
    int* data = new int[1000];

    if (input.empty()) {
        return;  // 泄漏！没有 delete
    }

    if (input.size() > 500) {
        return;  // 泄漏！没有 delete
    }

    // 处理 data...
    delete[] data;
}

// ✅ 正确：使用智能指针，所有路径都自动释放
void process(const std::string& input) {
    auto data = std::make_unique<int[]>(1000);

    if (input.empty()) {
        return;  // 自动释放
    }

    if (input.size() > 500) {
        return;  // 自动释放
    }

    // 处理 data...
}
```

### 5. 容器中的指针

```cpp
// ❌ 错误：容器存储裸指针，清空容器时没有释放
std::vector<int*> vec;
vec.push_back(new int(1));
vec.push_back(new int(2));
vec.clear();  // 只清除了指针，没有 delete 指向的内存！

// ✅ 正确：手动释放
for (auto p : vec) {
    delete p;
}
vec.clear();

// ✅ 更好：存储智能指针
std::vector<std::unique_ptr<int>> vec;
vec.push_back(std::make_unique<int>(1));
vec.push_back(std::make_unique<int>(2));
vec.clear();  // 自动释放

// ✅ 更好：存储值而非指针
std::vector<int> vec;
vec.push_back(1);
vec.push_back(2);
vec.clear();  // 无需担心内存
```

### 6. 重新赋值导致泄漏

```cpp
// ❌ 错误：重新赋值前没有释放旧内存
int* p = new int(10);
p = new int(20);  // 第一个 new 的内存泄漏了！

// ✅ 正确：先释放再赋值
int* p = new int(10);
delete p;
p = new int(20);

// ✅ 更好：使用智能指针
auto p = std::make_unique<int>(10);
p = std::make_unique<int>(20);  // 旧的自动释放
```

### 7. 循环中的泄漏

```cpp
// ❌ 错误：循环中每次 new 但只保留最后一个
int* p;
for (int i = 0; i < 100; i++) {
    p = new int(i);  // 前 99 次的都泄漏了！
}

// ✅ 正确：每次循环释放
int* p;
for (int i = 0; i < 100; i++) {
    p = new int(i);
    // 使用 p...
    delete p;
}

// ✅ 更好：使用栈变量
for (int i = 0; i < 100; i++) {
    int value = i;  // 栈上分配，自动释放
    // 使用 value...
}
```

### 8. 循环引用（智能指针）

```cpp
// ❌ 错误：shared_ptr 循环引用
class Node {
public:
    std::shared_ptr<Node> next;
    ~Node() { std::cout << "Node destroyed" << std::endl; }
};

auto a = std::make_shared<Node>();
auto b = std::make_shared<Node>();
a->next = b;  // a 引用 b
b->next = a;  // b 引用 a → 循环引用！
// a 和 b 的引用计数都是 2，离开作用域后都变为 1
// 永远不会降为 0，内存泄漏！

// ✅ 正确：使用 weak_ptr 打破循环
class Node {
public:
    std::shared_ptr<Node> next;
    std::weak_ptr<Node> prev;  // 用 weak_ptr 打破循环
    ~Node() { std::cout << "Node destroyed" << std::endl; }
};

auto a = std::make_shared<Node>();
auto b = std::make_shared<Node>();
a->next = b;
b->prev = a;  // weak_ptr 不增加引用计数
// 离开作用域后，引用计数正确降为 0，自动释放
```

### 9. 基类析构函数不是虚函数

```cpp
// ❌ 错误：基类析构函数不是虚函数
class Base {
public:
    ~Base() { std::cout << "Base dtor" << std::endl; }  // 非虚！
};

class Derived : public Base {
    int* data;
public:
    Derived() : data(new int[100]) {}
    ~Derived() { delete[] data; std::cout << "Derived dtor" << std::endl; }
};

Base* obj = new Derived();
delete obj;  // 只调用 Base 析构，Derived 析构不调用 → data 泄漏！

// ✅ 正确：基类析构函数声明为虚函数
class Base {
public:
    virtual ~Base() { std::cout << "Base dtor" << std::endl; }
};
```

### 10. C 风格 `malloc`/`free` 与 C++ `new`/`delete` 混用

```cpp
// ❌ 错误：混用 malloc/free 和 new/delete
int* p1 = (int*)malloc(sizeof(int));
delete p1;    // 未定义行为！应该用 free

int* p2 = new int(42);
free(p2);     // 未定义行为！应该用 delete

// ✅ 正确：配对使用
int* p1 = (int*)malloc(sizeof(int));
free(p1);

int* p2 = new int(42);
delete p2;
```

## 智能指针选择指南

| 智能指针 | 所有权 | 开销 | 使用场景 |
|---------|-------|------|---------|
| `unique_ptr` | 独占 | 极小 | 默认选择，单一所有权 |
| `shared_ptr` | 共享 | 较大（引用计数） | 需要共享所有权时 |
| `weak_ptr` | 无 | 小 | 打破 `shared_ptr` 循环引用 |

```cpp
// ✅ 默认使用 unique_ptr
auto p = std::make_unique<int>(42);

// ✅ 需要共享时用 shared_ptr
auto p1 = std::make_shared<int>(42);
auto p2 = p1;  // 共享所有权

// ✅ 打破循环用 weak_ptr
std::weak_ptr<int> wp = p1;
auto sp = wp.lock();  // 获取 shared_ptr
```

## 内存泄漏检测工具

| 工具 | 平台 | 使用方法 |
|------|------|---------|
| **Valgrind** | Linux/macOS | `valgrind --leak-check=full ./program` |
| **AddressSanitizer** | 全平台 | `g++ -fsanitize=address -g main.cpp` |
| **LeakSanitizer** | Linux | `g++ -fsanitize=leak -g main.cpp` |
| **Visual Studio** | Windows | 调试器 → 诊断工具 → 内存使用率 |
| **Dr. Memory** | Windows | `drmemory -batch -quiet -- ./program.exe` |
| **Valgrind Massif** | Linux | `valgrind --tool=massif ./program` |

### Valgrind 使用示例

```bash
# 编译时加 -g 生成调试信息
g++ -g main.cpp -o main

# 运行 Valgrind
valgrind --leak-check=full --show-leak-kinds=all ./main

# 输出示例：
# ==12345== HEAP SUMMARY:
# ==12345==     in use at exit: 40 bytes in 1 blocks
# ==12345==   total heap usage: 2 allocs, 1 frees, 1,064 bytes allocated
# ==12345==
# ==12345== 40 bytes in 1 blocks are definitely lost in loss record 1 of 1
# ==12345==    at 0x4C2E0EF: operator new[](unsigned long)
# ==12345==    by 0x4008A3: func() (main.cpp:5)
```

### AddressSanitizer 使用示例

```bash
# 编译
g++ -fsanitize=address -g -fno-omit-frame-pointer main.cpp -o main

# 运行
./main

# 泄漏检测（需要 LeakSanitizer）
ASAN_OPTIONS=detect_leaks=1 ./main
```

## 预防内存泄漏的最佳实践

1. **使用智能指针** — `unique_ptr` 为默认选择
2. **使用 STL 容器** — `vector`、`string`、`map` 自动管理内存
3. **遵循 RAII 原则** — 资源获取即初始化，析构时释放
4. **避免裸 `new`/`delete`** — 封装在类中管理
5. **基类析构函数声明为 `virtual`** — 确保正确释放派生类资源
6. **注意 `shared_ptr` 循环引用** — 用 `weak_ptr` 打破
7. **开发时开启 Sanitizer** — 及早发现泄漏
8. **定期使用 Valgrind 检查** — 尤其是长时间运行的程序
