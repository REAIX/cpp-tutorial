# 编辑器与IDE怎么选
> 📖 相关章节：[VSCode配置](../../04-工程实践/开发环境/00-VSCode核心配置.md)、[CMake基础](../../04-工程实践/开发环境/03-CMake基础入门.md)、[GCC编译器](../../04-工程实践/开发环境/07-GCC编译器基础.md)

## 一个生活类比

想象你要做饭。你可以只用一把菜刀和一个灶台（文本编辑器），也可以用一整套厨房设备——烤箱、微波炉、洗碗机、料理机全都有（IDE）。前者轻便灵活，但事事亲力亲为；后者功能齐全，但占地方、启动慢。选哪个，取决于你要做什么菜、你的厨房有多大、以及你的烹饪水平。

编程工具的选择也是一样：**文本编辑器**轻量灵活，**IDE**（Integrated Development Environment，集成开发环境）功能全面。没有绝对的好坏，只有适不适合。

## 编辑器 vs IDE：核心区别

| 特性 | 文本编辑器 | IDE |
|------|-----------|-----|
| 启动速度 | 极快（秒开） | 较慢（需加载项目） |
| 内存占用 | 很小 | 较大 |
| 代码补全 | 基础或需插件 | 内置且强大 |
| 调试功能 | 无或需插件 | 内置图形化调试 |
| 项目管理 | 弱 | 强（项目级支持） |
| 可扩展性 | 高（插件生态丰富） | 中（部分可扩展） |
| 学习曲线 | 低 | 中等 |
| 适用场景 | 小文件编辑、快速修改 | 大型项目开发 |

简单来说：**编辑器是"记事本增强版"，IDE是"开发工作台"**。

## 主流工具横向对比

### VS Code

`VS Code`（Visual Studio Code）是微软推出的免费、开源的代码编辑器。它介于编辑器和IDE之间——本体是编辑器，但通过插件可以变成"准IDE"。

**优点：**
- 启动快，界面清爽
- 插件生态极其丰富（`C/C++`、`CMake Tools`、`Code Runner`等）
- 内置终端、`Git` 集成
- 跨平台（`Windows`、`Linux`、`macOS`）
- 完全免费

**缺点：**
- 调试配置稍复杂（需要写 `launch.json`）
- 大型项目不如专业IDE流畅
- 插件装多了会变慢

**适合人群：** 初学者、轻量级开发者、喜欢自定义工具链的人

### Visual Studio

`Visual Studio`（简称 VS）是微软的专业IDE，注意它和 `VS Code` 是两个完全不同的产品！

**优点：**
- `Windows` 平台最强 `C++` IDE，没有之一
- 调试器极其强大（内存查看、性能分析等）
- 内置 `MSVC` 编译器，开箱即用
- `IntelliSense` 代码补全非常智能
- 社区版免费

**缺点：**
- 仅限 `Windows`（`VS for Mac` 已停止更新）
- 安装体积巨大（10GB+）
- 启动慢，对电脑配置有要求
- 界面复杂，初学者容易迷失

**适合人群：** `Windows` 上的 `C++` 开发者、做大型项目的人

### CLion

`CLion` 是 `JetBrains` 推出的跨平台 `C/C++` 专业IDE。

**优点：**
- 跨平台（`Windows`、`Linux`、`macOS`）
- 代码分析和重构功能极强
- 内置 `CMake` 支持
- 调试体验优秀
- `JetBrains` 家族统一风格

**缺点：**
- **收费**（学生可申请免费教育版）
- 内存占用大
- 启动较慢
- 对小项目来说"杀鸡用牛刀"

**适合人群：** 专业 `C++` 开发者、跨平台开发者、学生（免费版）

### Dev-C++

`Dev-C++` 是一个老旧的 `Windows` 下的 `C/C++` IDE，国内很多学校仍在使用。

**优点：**
- 安装包小，启动快
- 界面简单，上手容易
- 自带 `MinGW` 编译器

**缺点：**
- **已经停止维护**（最后正式版2005年，虽有 `Orwell` 和 `Embarcadero` 续命版）
- 代码补全极其简陋
- 调试功能基本不可用
- 不支持现代 `C++` 标准
- 界面丑陋，编码体验差

**适合人群：** 仅限学校强制要求使用的情况。**强烈建议换掉。**

### Vim / Emacs

`Vim` 和 `Emacs` 是两大传奇编辑器，被称为"编辑器之神"和"神的编辑器"。

**优点：**
- 终端中运行，无需图形界面
- 操作效率极高（熟练后）
- 可定制性极强
- 远程开发利器

**缺点：**
- 学习曲线极其陡峭
- 需要大量配置才能用于 `C++` 开发
- 不适合初学者

**适合人群：** 有经验的开发者、需要在服务器上编辑代码的人

## 不同阶段的推荐

### 刚入门（0-3个月）

推荐 **`VS Code`**。理由：
- 免费且跨平台，不用担心环境问题
- 安装 `C/C++` 插件后就能用，配置简单
- 界面友好，不会让你被复杂功能吓到
- 网上教程最多，遇到问题容易搜到答案

### 进阶学习（3-12个月）

继续用 **`VS Code`**，或者尝试 **`Visual Studio`**（`Windows`用户）/ **`CLion`**（学生免费版）。

理由：
- 开始接触调试，专业IDE的调试体验更好
- 项目变大，需要更好的代码导航
- 可以同时保留 `VS Code` 做轻量编辑

### 实际项目开发

根据平台选择：
- `Windows` → `Visual Studio` 或 `CLion`
- `Linux` → `CLion` 或 `VS Code` + 插件
- `macOS` → `CLion` 或 `VS Code` + 插件
- 服务器远程开发 → `Vim` / `VS Code Remote`

## 常见误区

### "IDE越强大越好"

不一定。小项目用IDE反而拖慢效率。就像去楼下便利店买菜，不需要开货车。

### "高手都用Vim"

这是幸存者偏差。高手用Vim是因为他们已经投入了大量时间学习，而且经常在服务器上工作。对初学者来说，先学会编程，再学高级工具。

### "Dev-C++够用了"

不够用。现代 `C++` 的很多特性它不支持，调试功能几乎为零，用它学习就像用算盘学数学——不是不行，但何必呢？

### "VS Code和Visual Studio是一样的"

完全不同！`VS Code` 是轻量编辑器，`Visual Studio` 是重量级IDE。名字像但东西不一样，别搞混了。

## 总结

选工具就像选鞋子——合脚最重要。初学者从 `VS Code` 开始，随着水平提升再尝试更专业的工具。**工具只是手段，写好代码才是目的。** 不要在工具选择上纠结太久，选一个开始写代码才是正经事。
