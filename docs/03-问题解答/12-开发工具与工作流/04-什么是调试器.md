# 什么是调试器
> 📖 相关章节：[VSCode配置](../../05-开发环境与IDE/00-VSCode核心配置.md)、[CMake基础](../../05-开发环境与IDE/03-CMake基础入门.md)、[GCC编译器](../../05-开发环境与IDE/07-GCC编译器基础.md)

## 一个生活类比

你的汽车突然熄火了。你可以凭猜测换零件——也许是火花塞？也许是油泵？——然后一次次试，费时费力还可能越修越坏。或者，你可以接上汽车诊断仪（OBD），它直接告诉你"3号气缸点火失败"，你立刻知道问题在哪。

**调试器就是代码的"诊断仪"。** 它让你暂停程序、查看变量值、一步步执行代码，精确定位问题所在，而不是靠猜。

## 为什么需要调试器

### 没有 debugger 的调试方式

```cpp
std::cout << "到这里了1" << std::endl;
std::cout << "x = " << x << std::endl;
std::cout << "到这里了2" << std::endl;
// ... 满屏的 cout ...
```

这就是著名的 `printf` 调试法（或 `cout` 调试法）。它有用，但：
- 需要反复修改代码、重新编译
- 输出太多，淹没关键信息
- 无法暂停程序交互式查看
- 多线程程序基本没法用
- 忘记删调试代码可能影响性能

### 有 debugger 的调试方式

- 在任意行设置断点，程序自动暂停
- 暂停时查看任意变量的值
- 逐行执行，观察每一步的变化
- 查看函数调用栈，知道"怎么走到这里的"
- 条件断点：只有满足条件才暂停

## GDB：最经典的调试器

`GDB`（GNU Debugger）是 `GNU` 项目推出的调试器，支持 `C`、`C++`、`Fortran` 等语言。

### 准备工作

编译时必须加 `-g` 选项生成调试信息：

```bash
g++ -std=c++17 -Wall -g main.cpp -o myapp
```

没有 `-g`，`GDB` 看不到源代码行号和变量名，基本没法用。

### 启动 GDB

```bash
gdb ./myapp
```

进入 `GDB` 的交互界面后，你就可以使用各种命令了。

### GDB 核心命令

| 命令 | 缩写 | 作用 | 示例 |
|------|------|------|------|
| `break` | `b` | 设置断点 | `b main.cpp:42` |
| `run` | `r` | 运行程序 | `r` |
| `step` | `s` | 单步执行（进入函数） | `s` |
| `next` | `n` | 单步执行（跳过函数） | `n` |
| `print` | `p` | 打印变量值 | `p x` |
| `continue` | `c` | 继续运行到下一个断点 | `c` |
| `backtrace` | `bt` | 显示调用栈 | `bt` |
| `list` | `l` | 显示源代码 | `l` |
| `watch` | `w` | 监视变量变化 | `w x` |
| `quit` | `q` | 退出GDB | `q` |

### 实战：调试一个崩溃程序

假设有以下程序在运行时崩溃：

```cpp
#include <iostream>
#include <vector>

int main() {
    std::vector<int> nums = {1, 2, 3};
    for (int i = 0; i <= 3; i++) {  // bug: <= 应该是 <
        std::cout << nums[i] << std::endl;
    }
    return 0;
}
```

用 `GDB` 调试：

```
(gdb) b main.cpp:6          # 在第6行设断点
Breakpoint 1 at 0x...: file main.cpp, line 6.

(gdb) r                      # 运行程序
Breakpoint 1, main() at main.cpp:6
6           for (int i = 0; i <= 3; i++) {

(gdb) n                      # 单步执行
1

(gdb) p i                    # 查看变量 i 的值
$1 = 0

(gdb) c                      # 继续运行
2
3
Program received signal SIGSEGV, Segmentation fault.
0x... in main() at main.cpp:7
7               std::cout << nums[i] << std::endl;

(gdb) p i                    # 查看崩溃时 i 的值
$2 = 3

(gdb) bt                     # 查看调用栈
#0  0x... in main() at main.cpp:7
```

发现问题：`i = 3` 时越界访问了 `nums[3]`，而 `nums` 只有3个元素（索引0-2）。

### 条件断点

只在特定条件下暂停：

```
(gdb) b main.cpp:7 if i == 3
```

这在循环中特别有用——不用一次次按 `c` 跳过不关心的迭代。

### 监视点

当变量的值被修改时暂停：

```
(gdb) watch total
```

适合追踪"这个变量什么时候被改坏了"的问题。

## LLDB

`LLDB` 是 `LLVM` 项目的调试器，`macOS` 上 `Xcode` 默认使用它。命令和 `GDB` 高度相似：

| GDB | LLDB |
|-----|------|
| `b main.cpp:10` | `b main.cpp:10` |
| `r` | `r` |
| `n` | `n` |
| `p x` | `p x` |
| `bt` | `bt` |
| `q` | `q` |

大部分命令可以直接替换使用。

## IDE 中的调试器

现代 `IDE` 提供了图形化的调试界面，比命令行更直观：

### VS Code

1. 安装 `C/C++` 插件
2. 创建 `.vscode/launch.json`：
```json
{
    "version": "0.2.0",
    "configurations": [
        {
            "name": "Debug C++",
            "type": "cppdbg",
            "request": "launch",
            "program": "${workspaceFolder}/myapp",
            "cwd": "${workspaceFolder}",
            "MIMode": "gdb"
        }
    ]
}
```
3. 在代码行号旁点击设置断点（红点）
4. 按 `F5` 启动调试

### Visual Studio

最简单的调试体验：
- 点击行号旁设置断点
- 按 `F5` 启动调试
- `F10` 单步跳过，`F11` 单步进入
- 鼠标悬停在变量上即可查看值

### CLion

- 同样点击设置断点，`Shift+F9` 启动调试
- 底部面板显示变量、调用栈、内存视图
- 支持 `CMake` 项目开箱即用

### IDE调试 vs 命令行调试

| 特性 | 命令行GDB | IDE调试器 |
|------|----------|----------|
| 上手难度 | 高 | 低 |
| 可视化 | 无 | 丰富 |
| 灵活性 | 极高 | 中等 |
| 远程调试 | 方便 | 需配置 |
| 适合场景 | 服务器、嵌入式 | 日常开发 |

**建议：日常开发用IDE调试器，遇到复杂问题或服务器环境再用命令行GDB。**

## 调试工作流

1. **复现问题**：先确认能稳定复现
2. **定位范围**：通过断点缩小问题区域
3. **假设验证**：查看变量值，验证或推翻假设
4. **逐层深入**：用 `step` 进入可疑函数
5. **回溯原因**：用 `backtrace` 查看调用链
6. **修复验证**：修改代码，确认问题解决

## 常见调试技巧

### 二分法定位

不知道哪行代码有问题？在中间设断点，看前半段是否正常，然后继续二分——像二分查找一样快速缩小范围。

### 查看内存

```
(gdb) p *ptr          # 查看指针指向的值
(gdb) p arr[0]@5      # 查看数组前5个元素
(gdb) x/10x 0x7fff   # 查看内存地址的十六进制内容
```

### 多线程调试

```
(gdb) info threads     # 列出所有线程
(gdb) thread 2         # 切换到2号线程
(gdb) bt               # 查看当前线程的调用栈
```

## 总结

调试器是程序员最重要的工具之一。**学会使用调试器，你的排错效率会提升十倍。**

初学者建议：
1. 先从 `IDE` 的图形化调试器开始
2. 掌握四个核心操作：**设断点、单步执行、查看变量、查看调用栈**
3. 遇到 `IDE` 解决不了的问题时，再学习命令行 `GDB`

记住：**不要靠猜来调试，让调试器告诉你真相。**
