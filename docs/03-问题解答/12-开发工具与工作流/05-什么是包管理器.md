# 什么是包管理器
> 📖 相关章节：[包管理工具](../../02-CPP/33-包管理工具.md)

## 一个生活类比

你做菜需要酱油、醋、盐、糖……你可以自己去超市一样一样找、一瓶一瓶买（手动下载库），但更方便的做法是打开手机App，搜索"酱油"，一键下单，自动配送到家。

**包管理器就是代码世界的"买菜App"。** 你告诉它"我需要 `fmt` 库"，它自动下载、编译、配置，你直接 `#include <fmt/format.h>` 就能用。

## 为什么C/C++需要包管理器

### C/C++的"依赖地狱"

与其他语言相比，`C/C++` 的依赖管理一直是个痛点：

| 语言 | 包管理器 | 一行命令安装库 |
|------|---------|--------------|
| `Python` | `pip` | `pip install requests` |
| `JavaScript` | `npm` | `npm install axios` |
| `Rust` | `cargo` | `cargo add serde` |
| `Go` | `go mod` | `go get github.com/...` |
| `C/C++` | ？ | 😫 |

长期以来，`C/C++` 没有统一的包管理器，开发者需要：
1. 去官网下载源码或预编译库
2. 手动编译（可能还要解决编译依赖）
3. 配置头文件路径（`-I`）
4. 配置库文件路径（`-L`）
5. 指定链接库（`-l`）
6. 不同平台还要分别处理

**这个过程繁琐、易错、不可重复。** 包管理器就是为了解决这个问题。

## 主流C/C++包管理器

### vcpkg

`vcpkg` 是微软推出的 `C/C++` 包管理器，目前最流行。

**安装：**
```bash
git clone https://github.com/microsoft/vcpkg.git
cd vcpkg
bootstrap-vcpkg.bat      # Windows
# 或 bootstrap-vcpkg.sh  # Linux/macOS
```

**基本使用：**
```bash
# 搜索库
vcpkg search fmt

# 安装库
vcpkg install fmt

# 安装特定平台版本
vcpkg install fmt:x64-windows
vcpkg install fmt:x64-linux

# 查看已安装的库
vcpkg list
```

**与 `CMake` 集成：**

方式一：`CMake Preset`（推荐）
```json
// CMakePresets.json
{
    "configurePresets": [
        {
            "name": "default",
            "cacheVariables": {
                "CMAKE_TOOLCHAIN_FILE": "$env{VCPKG_ROOT}/scripts/buildsystems/vcpkg.cmake"
            }
        }
    ]
}
```

方式二：命令行参数
```bash
cmake -B build -DCMAKE_TOOLCHAIN_FILE=path/to/vcpkg/scripts/buildsystems/vcpkg.cmake
```

然后在 `CMakeLists.txt` 中：
```cmake
find_package(fmt CONFIG REQUIRED)
target_link_libraries(myapp PRIVATE fmt::fmt)
```

**清单模式（manifest mode）：**

在项目根目录创建 `vcpkg.json`：
```json
{
    "name": "myapp",
    "version": "1.0.0",
    "dependencies": [
        "fmt",
        "nlohmann-json"
    ]
}
```

这样任何人克隆项目后，`CMake` 配置时会自动安装依赖——就像 `npm install` 一样！

### Conan

`Conan` 是另一个流行的 `C/C++` 包管理器，更灵活，去中心化。

**安装：**
```bash
pip install conan
```

**基本使用：**
```bash
# 搜索库
conan search fmt

# 安装库
conan install fmt/10.1.1@
```

**配置文件 `conanfile.txt`：**
```ini
[requires]
fmt/10.1.1
nlohmann_json/3.11.2

[generators]
CMakeDeps
CMakeToolchain
```

**与 `CMake` 集成：**
```cmake
find_package(fmt REQUIRED)
target_link_libraries(myapp PRIVATE fmt::fmt)
```

### vcpkg vs Conan 对比

| 特性 | `vcpkg` | `Conan` |
|------|---------|---------|
| 维护方 | 微软 | 社区（Jfrog支持） |
| 安装方式 | 源码编译 | 预编译二进制+源码编译 |
| 仓库 | 集中式 | 去中心化（可自建） |
| 学习曲线 | 较低 | 中等 |
| `CMake` 集成 | 非常简单 | 简单 |
| 平台支持 | 全平台 | 全平台 |
| 社区活跃度 | 非常高 | 高 |
| 推荐场景 | 初学者、通用项目 | 企业级、需要私有仓库 |

## 包管理器的工作流程

```
1. 声明依赖（vcpkg.json / conanfile.txt）
      ↓
2. 包管理器下载源码或二进制
      ↓
3. 编译（如需要）并安装到本地缓存
      ↓
4. 生成 CMake 配置文件
      ↓
5. CMake 通过 find_package 找到库
      ↓
6. 正常编译链接
```

## 实战：用vcpkg添加fmt库

### 1. 创建项目

```
myapp/
├── CMakeLists.txt
├── vcpkg.json
└── src/
    └── main.cpp
```

### 2. 声明依赖

```json
// vcpkg.json
{
    "name": "myapp",
    "version": "1.0.0",
    "dependencies": ["fmt"]
}
```

### 3. 编写代码

```cpp
// src/main.cpp
#include <fmt/format.h>

int main() {
    fmt::print("Hello, {}!\n", "世界");
    return 0;
}
```

### 4. 配置CMake

```cmake
cmake_minimum_required(VERSION 3.16)
project(myapp)

set(CMAKE_CXX_STANDARD 17)

find_package(fmt CONFIG REQUIRED)

add_executable(myapp src/main.cpp)
target_link_libraries(myapp PRIVATE fmt::fmt)
```

### 5. 构建运行

```bash
cmake -B build -DCMAKE_TOOLCHAIN_FILE=$VCPKG_ROOT/scripts/buildsystems/vcpkg.cmake
cmake --build build
./build/myapp
```

输出：`Hello, 世界!`

**注意：** 首次构建时 `vcpkg` 会自动下载并编译 `fmt` 库，之后会使用缓存，速度很快。

## 常见问题

### "vcpkg install很慢"

首次安装需要从源码编译，确实较慢。后续会使用缓存。可以设置代理加速下载：
```bash
set VCPKG_BINARY_SOURCES=clear;x-azurl,https://your-mirror,,readwrite
```

### "找不到VCPKG_ROOT"

设置环境变量：
```bash
# Windows
setx VCPKG_ROOT "C:\path\to\vcpkg"

# Linux/macOS
export VCPKG_ROOT=/path/to/vcpkg
```

### "find_package找不到库"

确保：
1. `CMAKE_TOOLCHAIN_FILE` 正确指向 `vcpkg` 的工具链文件
2. `vcpkg.json` 中声明了该依赖
3. 已成功安装（`vcpkg list` 可查看）

### "公司内网无法访问GitHub"

`Conan` 支持自建私有仓库，更适合企业内网环境。`vcpkg` 也可以通过镜像或人工方式处理。

## 与其他语言的对比

| 特性 | `pip`/`npm` | `vcpkg`/`Conan` |
|------|------------|-----------------|
| 安装方式 | 下载预编译包 | 通常从源码编译 |
| 速度 | 快 | 慢（首次编译） |
| 平台兼容 | 基本一致 | 需要考虑平台差异 |
| ABI兼容 | 不存在此问题 | 需要注意编译器/标准库版本 |
| 依赖冲突 | 版本约束解决 | 更复杂（ABI问题） |

`C/C++` 包管理器更复杂，是因为 `C/C++` 本身没有统一的二进制接口（ABI），不同编译器、不同版本编译的库可能不兼容。这是历史包袱，不是包管理器的问题。

## 总结

`C/C++` 的包管理器虽然不如其他语言成熟，但已经能大幅简化依赖管理。初学者建议：

1. **从 `vcpkg` 开始**——微软维护，生态最好，学习成本最低
2. **使用清单模式**——在 `vcpkg.json` 中声明依赖，项目可重复构建
3. **配合 `CMake` 使用**——`find_package` + `target_link_libraries` 是标准模式

**不要再手动下载库了，让包管理器帮你做这些脏活累活。**
