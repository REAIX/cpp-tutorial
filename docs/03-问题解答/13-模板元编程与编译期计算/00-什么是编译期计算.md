# 什么是编译期计算
> 📖 相关章节：[模板进阶](../../02-CPP/11-模板进阶.md)、[编译期计算基础](../../07-模板元编程与编译期计算/00-编译期计算基础.md)、[Type Traits](../../07-模板元编程与编译期计算/01-Type-Traits与类型操作.md)

## 本质速解

**编译期计算就是把本该在程序运行时做的计算工作，提前挪到编译阶段完成，让编译器充当"预计算器"，从而在运行时零开销地获得结果——但天下没有免费的午餐，代价是更长的编译时间和更难读的错误信息。**

---

## 1. 从一个直观的例子说起

想象你需要计算斐波那契数列的第20项。传统的做法是在运行时计算：

```cpp
// 运行期计算斐波那契数列 —— 每次程序启动都要重新算
#include <iostream>

int fibonacci(int n) {
    if (n <= 1) return n;
    return fibonacci(n - 1) + fibonacci(n - 2);
}

int main() {
    int result = fibonacci(20);  // 运行时才计算，每次执行都要花时间
    std::cout << "fib(20) = " << result << '\n';
}
```

而使用编译期计算，这个值在编译时就确定了：

```cpp
// 编译期计算 —— 结果在编译时就"算好了"，直接嵌入二进制
#include <iostream>

constexpr int fibonacci(int n) {   // constexpr 关键字告诉编译器：
    if (n <= 1) return n;          // "如果参数是编译期常量，请在编译期求值"
    return fibonacci(n - 1) + fibonacci(n - 2);
}

int main() {
    constexpr int result = fibonacci(20);  // 编译期完成！
    // 编译后的代码等价于：mov eax, 6765
    std::cout << "fib(20) = " << result << '\n';
}
```

**核心区别**：前者每次运行都要递归调用上万次；后者编译器直接把 `6765` 塞进机器码，运行时连一次函数调用都没有。

## 2. constexpr 与运行期计算的详细对比

### 2.1 基本语法对比

```cpp
#include <iostream>
#include <array>

// ========== 普通函数：只能在运行期计算 ==========
int square(int x) {
    return x * x;
}

// ========== constexpr 函数：编译期和运行期都能用 ==========
constexpr int constexpr_square(int x) {
    return x * x;
}

// ========== consteval 函数（C++20）：强制编译期计算 ==========
consteval int compile_only_square(int x) {
    return x * x;
}

void demonstrate_differences() {
    // --- 普通函数 ---
    int a = square(5);           // ✅ 运行期调用
    // int b[square(3)];         // ❌ 错误！数组大小必须是编译期常量

    // --- constexpr 函数 ---
    constexpr int c1 = constexpr_square(5);  // ✅ 编译期计算
    int c2 = constexpr_square(5);            // ✅ 也可以运行期计算（退化成普通函数）
    std::array<int, constexpr_square(3)> arr; // ✅ 可用于编译期上下文

    // --- consteval 函数 ---
    constexpr int e1 = compile_only_square(5);  // ✅ 必须在编译期计算
    // int e2 = compile_only_square(5);          // ❌ 错误！不允许运行期调用
    // 即使写成变量形式也不行，consteval 是"立即函数"
}
```

### 2.2 constexpr 变量 vs 普通变量

```cpp
#include <array>
#include <cassert>

constexpr int MAX_SIZE = 100;     // 编译期常量，可用于任何地方
const int RUNTIME_SIZE = 100;     // 在 C++ 中通常也是编译期常量（整型）
const volatile int VOLATILE_SIZE = 100;  // ⚠️ volatile 阻止编译期优化

void variable_differences() {
    // constexpr 变量的超能力
    std::array<int, MAX_SIZE> arr1;        // ✅ 可以做数组大小
    static_assert(MAX_SIZE == 100);        // ✅ 可以做 static_assert
    switch (MAX_SIZE) {}                   // ✅ 可以做 case 标签（虽然不常见）

    // const 整型变量的能力（C++ 中 const 整型默认是编译期常量）
    std::array<int, RUNTIME_SIZE> arr2;    // ✅ 通常也可以
    static_assert(RUNTIME_SIZE == 100);    // ✅ 通常也可以

    // 但如果 const 的初始化不是常量表达式呢？
    int input = 50;
    const int DYNAMIC_SIZE = input * 2;    // 初始化依赖运行期值
    // std::array<int, DYNAMIC_SIZE> arr3; // ❌ 错误！不是编译期常量
}
```

## 3. 编译期计算的边界：什么能做、什么不能做

### 3.1 C++11/14 的严格限制

```cpp
// C++11 的 constexpr 限制非常严格：
constexpr int old_style_sum(int n) {
    // ❌ 不能有局部变量（C++11）
    // int sum = 0;

    // ❌ 不能有 for/while 循环（C++11），只能用递归
    // for (int i = 0; i <= n; ++i) { ... }

    // ❌ 不能有 if 语句（C++11），只能用三元运算符
    // if (n <= 0) return 0;

    return (n <= 0) ? 0 : n + old_style_sum(n - 1);  // 只能用递归+三元
}
```

### 3.2 C++14/17/20 的逐步放宽

```cpp
// C++14 开始大幅放宽限制
#include <string_view>

constexpr int modern_sum(int n) {
    int sum = 0;              // ✅ 允许局部变量
    for (int i = 1; i <= n; ++i) {  // ✅ 允许 for 循环
        sum += i;
    }
    if (sum > 1000) {         // ✅ 允许 if 语句
        sum = 1000;           // ✅ 允许修改局部变量
    }
    return sum;
}

// C++17: if constexpr 让模板中的条件分支更清晰
template<typename T>
constexpr auto get_value(T&& val) {
    if constexpr (std::is_same_v<std::decay_t<T>, std::string>) {
        return val.length();          // 仅当 T 是 string 时编译此分支
    } else {
        return val;                   // 其他类型走这里
    }
}

// C++20: 允许更多操作
constexpr void modify_string() {
    // C++20 允许在 constexpr 中修改某些类型
    // 但仍然不能做 I/O、不能动态分配内存后释放（大部分情况）等
}
```

### 3.3 编译期计算的绝对禁区

```cpp
#include <cstdio>

constexpr int forbidden_operations() {
    // ====== 绝对不允许的操作 ======

    // ❌ 1. ASM 内联汇编
    // asm("nop");

    // ❌ 2. I/O 操作
    // std::printf("hello");      // 不允许
    // std::cin >> x;             // 不允许

    // ❌ 3. 动态内存管理（C++20 之前完全禁止，之后有限支持）
    // int* p = new int(42);
    // delete p;

    // ❌ 4. 访问未定义行为
    // int x = 0;
    // return 10 / x;              // 除以零，编译期就能检测出来！

    // ❌ 5. 类型转换到非字面量类型的大部分情况
    // （具体规则较复杂，取决于标准版本）

    // ✅ 允许的操作
    int a = 10;
    int b = 20;
    return a + b;                  // 算术运算没问题
}

// 编译期 UB 检测的威力
constexpr int detect_ub(int x) {
    return x / (x - x);  // 如果 x 不是编译期常量，运行期会崩溃
                          // 如果 x 是编译期常量，编译器直接报错！
}

// static_assert(detect_ub(5));  // 编译错误：除以零（编译期就抓住了！）
```

## 4. 编译期计算的实战场景

### 4.1 数学常量与查表

```cpp
#include <array>
#include <cmath>    // 注意：C++23 之前 std::sqrt 等可能不是 constexpr
                     // C++26 将使大部分 <cmath> 成为 constexpr

// 编译期生成幂次表
template<int BASE, int N>
struct PowerTable {
    std::array<int, N + 1> values{};

    constexpr PowerTable() {
        for (int i = 0; i <= N; ++i) {
            long long result = 1;
            for (int j = 0; j < i; ++j) {
                result *= BASE;
            }
            values[i] = static_cast<int>(result);
        }
    }

    constexpr int operator[](int i) const { return values[i]; }
};

// 编译期就生成好的表
constexpr PowerTable<2, 10> powers_of_2;  // 2^0 到 2^10

void use_power_table() {
    // 运行时直接查表，O(1)，无计算开销
    int x = powers_of_2[8];  // 编译期已知为 256
    static_assert(powers_of_2[10] == 1024);  // 编译期验证
}
```

### 4.2 编译期字符串处理

```cpp
#include <string_view>

// 编译期字符串哈希（常用于优化 switch-case 字符串比较）
constexpr uint32_t djb2_hash(std::string_view str) {
    uint32_t hash = 5381;
    for (char c : str) {
        hash = ((hash << 5) + hash) + static_cast<uint32_t>(c);
    }
    return hash;
}

// 编译期字符串反转
constexpr std::string_view reverse_string_impl(
    char* buffer, std::string_view src, size_t pos
) {
    if (pos < src.size()) {
        buffer[src.size() - 1 - pos] = src[pos];
        return reverse_string_impl(buffer, src, pos + 1);
    }
    return std::string_view(buffer, src.size());
}

// 使用示例
void string_processing_demo() {
    // 这些都在编译期完成
    constexpr uint32_t hello_hash = djb2_hash("hello");
    constexpr uint32_t world_hash = djb2_hash("world");

    // 编译期字符串比较变成了整数比较
    static_assert(hello_hash != world_hash);

    // 可以用于编译期分发
    switch (djb2_hash("test")) {
        case djb2_hash("hello"): /* 处理 hello */ break;
        case djb2_hash("world"): /* 处理 world */ break;
        default: break;
    }
}
```

### 4.3 编译期解析与验证

```cpp
#include <charconv>
#include <stdexcept>

// 编译期解析 IPv4 地址
constexpr uint32_t parse_ipv4(const char* str) {
    uint32_t result = 0;
    int octet = 0;
    int dot_count = 0;

    for (int i = 0; str[i] != '\0'; ++i) {
        if (str[i] == '.') {
            if (octet > 255) throw "无效的 IP 八位组";
            result = (result << 8) | octet;
            octet = 0;
            ++dot_count;
            if (dot_count > 3) throw "太多的点";
        } else if (str[i] >= '0' && str[i] <= '9') {
            octet = octet * 10 + (str[i] - '0');
        } else {
            throw "非法字符";
        }
    }

    // 最后一个八位组
    if (dot_count != 3) throw "IP 格式错误";
    if (octet > 255) throw "无效的最后八位组";
    result = (result << 8) | octet;

    return result;
}

// 编译期确保 IP 合法
constexpr uint32_t SERVER_IP = parse_ipv4("192.168.1.1");
// constexpr uint32_t BAD_IP = parse_ipv4("999.999.999.999");  // 编译期报错！

static_assert(SERVER_IP == 0xC0A80101);  // 192.168.1.1 的十六进制表示
```

### 4.4 编译期数据结构

```cpp
// 编译期链表（展示编译期能力的极限玩法）
template<int... Values>
struct ConstexprList {};

template<typename List, int NewValue>
struct PushFront;

template<int... Values, int NewValue>
struct PushFront<ConstexprList<Values...>, NewValue> {
    using type = ConstexprList<NewValue, Values...>;
};

// 编译期链表长度
template<typename List>
struct Length;

template<int... Values>
struct Length<ConstexprList<Values...>> {
    static constexpr size_t value = sizeof...(Values);
};

// 编译期链表求和
template<typename List>
struct Sum;

template<>
struct Sum<ConstexprList<>> {
    static constexpr int value = 0;
};

template<int First, int... Rest>
struct Sum<ConstexprList<First, Rest...>> {
    static constexpr int value = First + Sum<ConstexprList<Rest...>>::value;
};

// 使用编译期链表
using MyList = ConstexprList<1, 2, 3, 4, 5>;
static_assert(Length<MyList>::value == 5);
static_assert(Sum<MyList>::value == 15);
```

## 5. 编译期计算的代价

### 5.1 编译时间膨胀

```cpp
// 这个看似无害的 constexpr 函数可能导致严重的编译时间问题
constexpr int heavy_computation(int n) {
    int count = 0;
    for (int i = 0; i < n; ++i) {
        for (int j = 0; j < n; ++j) {
            for (int k = 0; k < n; ++k) {
                // O(n³) 复杂度的计算
                if (i * j + j * k + k * i > 0) {
                    ++count;
                }
            }
        }
    }
    return count;
}

// 小规模没问题
constexpr int small_result = heavy_computation(10);     // 很快

// 大规模可能让编译器"思考"很久
// constexpr int large_result = heavy_computation(500);  // ⚠️ 编译时间爆炸！
                                                          // 编译器要模拟执行 125M 次循环迭代

// 实际影响：
// - 开发时的增量编译变慢 → 反馈循环拉长
// - CI/CD 流水线耗时增加 → 成本上升
// - 团队协作中"编译慢"成为日常抱怨
```

### 5.2 错误信息的可读性灾难

```cpp
// 当编译期计算出错时，错误信息可能非常晦涩
#include <vector>

constexpr bool validate_config(int threads, int buffer_size) {
    if (threads <= 0) return false;
    if (buffer_size <= 0) return false;
    if (threads > 256) return false;
    if (buffer_size > 1024 * 1024) return false;
    if (buffer_size % threads != 0) return false;  // 要求能均分
    return true;

    // 问题：当校验失败时，错误信息只是
    // "error: the value of 'validate_config' is not usable in a constant expression"
    // 你根本不知道是哪条规则没满足！
}

// 改进方案：使用 static_assert 分步检查
constexpr int CONFIG_THREADS = 10;
constexpr int CONFIG_BUFFER = 1005;  // 不能被 10 整除！

// static_assert(validate_config(CONFIG_THREADS, CONFIG_BUFFER));
// ↑ 错误信息："不是常量表达式" —— 完全没用

// 更好的方式：
static_assert(CONFIG_THREADS > 0, "线程数必须为正");
static_assert(CONFIG_THREADS <= 256, "线程数不超过256");
static_assert(CONFIG_BUFFER > 0, "缓冲区大小必须为正");
static_assert(CONFIG_BUFFER <= 1024 * 1024, "缓冲区过大");
static_assert(CONFIG_BUFFER % CONFIG_THREADS == 0,
              "缓冲区大小必须能被线程数整除");
// ↑ 每条都有清晰的错误提示！
```

### 5.3 调试困难

```cpp
// 运行期调试：可以用 GDB/LLDB 单步、看变量、设断点
// 编译期调试：你只能盯着编译器错误输出猜发生了什么

constexpr int complex_logic(int x) {
    int result = x;
    result *= 2;
    result += 10;
    result /= 3;
    // 如果中间某步出了问题...
    // 你无法在这里打断点！
    // 你无法打印中间值！（C++26 之前）
    return result;
}

// C++26 的改进：std::print 允许在 constexpr 中使用（仅诊断用途）
#if __cplusplus >= 202603L
constexpr int debuggable_logic(int x) {
    int result = x * 2;
    std::println("debug: step1 result = {}", result);  // C++26 允许！
    result += 10;
    std::println("debug: step2 result = {}", result);
    return result;
}
#endif
```

## 6. 编译期计算 vs 运行期计算：决策指南

### 6.1 选择矩阵

| 场景 | 推荐方式 | 理由 |
|------|---------|------|
| 数学常量（π、e 等） | **编译期** | 只算一次，到处复用 |
| 配置参数校验 | **编译期** | 尽早发现配置错误 |
| 查找表生成 | **编译期** | 避免运行时初始化开销 |
| 用户输入处理 | **运行期** | 输入在编译期未知 |
| 大规模数据计算 | **运行期** | 编译时间不可接受 |
| 依赖外部数据的算法 | **运行期** | 文件/网络 I/O 不可能在编译期 |
| 简单的类型相关计算 | **编译期** | sizeof、alignof 等本来就是编译期的 |
| 加密/哈希（固定密钥） | **编译期** | 密钥不泄露在二进制中...等等，实际上还是会 |

### 6.2 实战建议

```cpp
// 建议 1：优先使用 constexpr，但不强求所有路径都编译期可求值
constexpr int safe_divide(int a, int b) {
    // 这个函数既能在编译期用，也能在运行期用
    // 不要为了"纯编译期"而牺牲运行期的灵活性
    return (b != 0) ? a / b : 0;  // 运行期安全降级
}

// 建议 2：复杂逻辑拆分成小的 constexpr 函数
constexpr bool is_leap_year(int year) {
    return (year % 400 == 0) ||
           (year % 100 != 0 && year % 4 == 0);
}

constexpr int days_in_month(int year, int month) {
    constexpr int DAYS[] = {31, 28, 31, 30, 31, 30,
                            31, 31, 30, 31, 30, 31};
    if (month == 2 && is_leap_year(year)) return 29;
    return DAYS[month - 1];
}

// 建议 3：对性能敏感且输入已知的路径使用编译期计算
class FastPath {
    static constexpr int PRECOMPUTED_TABLE[256] = []{
        int table[256] = {};
        for (int i = 0; i < 256; ++i) {
            table[i] = i * i % 257;  // 示例：某种哈希
        }
        return table;
    }();  // C++14 lambda 立即求值

public:
    int lookup(uint8_t key) const {
        return PRECOMPUTED_TABLE[key];  // 直接查表，无分支
    }
};
```

## 7. 进阶：编译期多态与类型级编程

```cpp
// 编译期计算不仅仅是数值计算，还包括"类型计算"

// 编译期条件选择类型
template<bool Condition, typename TrueType, typename FalseType>
struct conditional_type {
    using type = TrueType;
};

template<typename TrueType, typename FalseType>
struct conditional_type<False, TrueType, FalseType> {
    using type = FalseType;
};

// 根据平台选择最优实现
#ifdef _WIN64
using optimal_int = long long;       // Windows 64 位
#elif defined(__linux__)
using optimal_int = long;            // Linux 64 位
#else
using optimal_int = int;             // 其他平台
#endif

// 根据大小自动选择存储类型
template<size_t Size>
struct sized_integer;

template<> struct sized_integer<1> { using type = uint8_t; };
template<> struct sized_integer<2> { using type = uint16_t; };
template<> struct sized_integer<4> { using type = uint32_t; };
template<> struct sized_integer<8> { using type = uint64_t; };

// 自动选择足够存下某个范围的最小整数类型
template<int Min, int Max>
struct smallest_fitting_int {
    static constexpr auto abs_max = (std::abs(Min) > Max) ?
                                     std::abs(Min) : Max;
    static constexpr size_t needed_bytes =
        (abs_max <= 0xFF)  ? 1 :
        (abs_max <= 0xFFFF) ? 2 :
        (abs_max <= 0xFFFFFFFF) ? 4 : 8;
    using type = typename sized_integer<needed_bytes>::type;
};

static_assert(std::is_same_v<smallest_fitting_int<0, 100>::type, uint8_t>);
static_assert(std::is_same_v<smallest_fitting_int<-1000, 50000>::type, uint16_t>);
```

## 8. 总结

编译期计算是 C++ 元编程能力的核心体现，它让我们能够：

1. **消除运行时开销**：把确定性的计算提前到编译阶段
2. **增强类型安全**：在编译期捕获更多错误
3. **实现零成本抽象**：高级语义不带来运行时代价

但同时也要清醒认识到其代价：

- **编译时间是真金白银**：复杂的编译期计算会显著拖慢构建速度
- **错误信息往往晦涩难懂**：需要额外的设计来改善诊断体验
- **调试体验较差**：虽然 C++26 正在改善这一点
- **学习曲线陡峭**：需要理解编译器的"思维方式"

**最佳实践**：在确实能带来明显收益的地方使用编译期计算（常量、查表、类型推导、配置校验），不要为了炫技而滥用。记住 Knuth 的名言——"过早优化是万恶之源"，编译期优化也不例外。
