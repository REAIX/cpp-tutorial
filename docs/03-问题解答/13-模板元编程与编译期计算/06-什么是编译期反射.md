# 什么是编译期反射
> 📖 相关章节：[模板进阶](../../02-CPP/11-模板进阶.md)、[编译期计算基础](../../07-模板元编程与编译期计算/00-编译期计算基础.md)、[Type Traits](../../07-模板元编程与编译期计算/01-Type-Traits与类型操作.md)

## 一句话概括

**编译期反射就是在编译阶段"审视"类型的内部结构——自动枚举一个结构体有哪些字段、每个字段叫什么名字、是什么类型、有哪些方法，而不需要手写任何样板代码——目前 C++ 还没有语言级支持，但通过宏、结构化绑定、PFR 等技巧已经可以实现大部分功能，C++26 的静态反射提案有望从根本上解决这个问题。**

## 1. 为什么需要编译期反射

### 1.1 没有反射的世界有多痛苦

```cpp
#include <string>
#include <iostream>

// 一个简单的用户结构体
struct User {
    int id;
    std::string name;
    std::string email;
    int age;
};

// 需求 1：序列化为 JSON
std::string to_json(const User& u) {
    // 必须手写每个字段！
    return "{ \"id\": " + std::to_string(u.id) +
           ", \"name\": \"" + u.name + "\"" +
           ", \"email\": \"" + u.email + "\"" +
           ", \"age\": " + std::to_string(u.age) + " }";
}

// 需求 2：从数据库结果集构造
User from_row(const DbRow& row) {
    // 又要手写每个字段！
    User u;
    u.id = row.get_int("id");
    u.name = row.get_string("name");
    u.email = row.get_string("email");
    u.age = row.get_int("age");
    return u;
}

// 需求 3：打印所有字段
void print(const User& u) {
    // 还是要手写每个字段！
    std::cout << "id: " << u.id << "\n";
    std::cout << "name: " << u.name << "\n";
    std::cout << "email: " << u.email << "\n";
    std::cout << "age: " << u.age << "\n";
}

// 问题：
// 1. 每增加一个功能就要写一遍所有字段
// 2. 新增字段时容易遗漏（忘记在某个函数中添加）
// 3. 字段名是字符串硬编码，容易拼错
// 4. 如果有 100 个结构体，每个都要重复上述工作
```

### 1.2 有反射的世界有多美好

```cpp
// 假设 C++ 有了完美的编译期反射（伪代码，展示理想状态）

struct User {
    int id;
    std::string name;
    std::string email;
    int age;
};

// 需求 1：序列化 —— 通用，不需要手写字段
template<Reflectable T>
std::string to_json(const T& obj) {
    std::string result = "{ ";
    bool first = true;
    for_each_field(obj, [&](const auto& field) {
        if (!first) result += ", ";
        result += "\"" + field.name() + "\": ";
        result += value_to_json(field.value());
        first = false;
    });
    result += " }";
    return result;
}

// 需求 2：通用打印 —— 一行代码搞定
template<Reflectable T>
void print(const T& obj) {
    for_each_field(obj, [](const auto& field) {
        std::cout << field.name() << ": " << field.value() << "\n";
    });
}

// 新增字段？不需要修改任何已有函数！
struct UserV2 {
    int id;
    std::string name;
    std::string email;
    int age;
    std::string phone;   // 新增字段
    bool active;         // 新增字段
    // to_json、print 等函数自动支持新字段！
};
```

## 2. 手动反射实现方式

### 2.1 宏 + 元组方式（最常见）

```cpp
#include <tuple>
#include <string>
#include <iostream>

// ========== 定义反射宏 ==========
// 用宏将字段名和成员指针配对

#define REFLECT_FIELDS(...) \
    static constexpr auto reflect_fields() { \
        return std::make_tuple(__VA_ARGS__); \
    }

#define FIELD(name) \
    std::pair{#name, &SelfType::name}

// ========== 使用宏定义可反射的结构体 ==========
struct User {
    using SelfType = User;  // 宏需要知道自身类型

    int id;
    std::string name;
    std::string email;
    int age;

    REFLECT_FIELDS(
        FIELD(id),
        FIELD(name),
        FIELD(email),
        FIELD(age)
    )
};

// ========== 遍历字段的通用函数 ==========
template<typename T, typename Func>
void for_each_field(const T& obj, Func&& func) {
    constexpr auto fields = T::reflect_fields();
    std::apply([&](const auto&... field_pair) {
        (func(field_pair.first, obj.*(field_pair.second)), ...);
    }, fields);
}

// ========== 通用序列化 ==========
template<typename T>
std::string to_json(const T& obj) {
    std::string result = "{ ";
    bool first = true;

    for_each_field(obj, [&](const char* name, const auto& value) {
        if (!first) result += ", ";
        result += "\"";
        result += name;
        result += "\": ";

        using ValueType = std::decay_t<decltype(value)>;
        if constexpr (std::is_same_v<ValueType, std::string>) {
            result += "\"" + value + "\"";
        } else if constexpr (std::is_same_v<ValueType, int>) {
            result += std::to_string(value);
        } else if constexpr (std::is_same_v<ValueType, double>) {
            result += std::to_string(value);
        } else if constexpr (std::is_same_v<ValueType, bool>) {
            result += value ? "true" : "false";
        }
        first = false;
    });

    result += " }";
    return result;
}

// ========== 通用打印 ==========
template<typename T>
void print_fields(const T& obj) {
    for_each_field(obj, [](const char* name, const auto& value) {
        std::cout << name << " = " << value << "\n";
    });
}

// 使用
void demo_macro_reflection() {
    User u{1, "张三", "zhangsan@example.com", 25};

    std::cout << to_json(u) << "\n";
    // 输出: { "id": 1, "name": "张三", "email": "zhangsan@example.com", "age": 25 }

    print_fields(u);
    // 输出:
    // id = 1
    // name = 张三
    // email = zhangsan@example.com
    // age = 25
}
```

### 2.2 更优雅的宏方案

```cpp
#include <tuple>
#include <string>
#include <string_view>

// 改进版宏：自动推导类型，减少样板代码

// 定义整个结构体的宏
#define REFLECTABLE(StructName, ...) \
    struct StructName { \
        using SelfType = StructName; \
        __VA_ARGS__ \
        static constexpr auto reflect_fields() { \
            return std::make_tuple( \
                REFLECT_EXPAND_FIELDS(__VA_ARGS__) \
            ); \
        } \
    };

// 辅助宏：提取字段名
#define REFLECT_EXPAND_FIELDS(...) \
    REFLECT_GET_FIELDS(__VA_ARGS__)

#define REFLECT_GET_FIELDS(field, ...) \
    std::pair{#field, &SelfType::field} \
    REFLECT_NEXT_FIELD(__VA_ARGS__)

#define REFLECT_NEXT_FIELD(field, ...) \
    , std::pair{#field, &SelfType::field} \
    REFLECT_NEXT_FIELD(__VA_ARGS__)

// 终止递归
#define REFLECT_NEXT_FIELD(...)

// 使用（更简洁！）
REFLECTABLE(Product,
    int id;
    std::string name;
    double price;
    int stock;
)

// 但宏方案的根本问题：
// 1. 宏是文本替换，容易出错
// 2. 调试困难，宏展开后的代码不可读
// 3. 不能处理复杂场景（继承、嵌套等）
// 4. IDE 支持差（代码补全、跳转等不工作）
```

### 2.3 结构化绑定方式（C++17）

```cpp
#include <tuple>
#include <string>
#include <iostream>
#include <type_traits>

// C++17 结构化绑定可以"解包"结构体
// 但需要知道字段数量

// 为不同字段数量定义反射入口
template<typename T>
constexpr auto reflect(const T& obj) {
    // 需要针对每种字段数量特化
    // 这里展示 2 字段和 3 字段的版本
}

// 2 字段结构体
struct Point2D {
    double x, y;
};

constexpr auto reflect(const Point2D& p) {
    // 利用结构化绑定获取字段
    const auto& [f1, f2] = p;
    return std::make_tuple(
        std::pair{"x", f1},
        std::pair{"y", f2}
    );
}

// 3 字段结构体
struct Point3D {
    double x, y, z;
};

constexpr auto reflect(const Point3D& p) {
    const auto& [f1, f2, f3] = p;
    return std::make_tuple(
        std::pair{"x", f1},
        std::pair{"y", f2},
        std::pair{"z", f3}
    );
}

// 通用遍历
template<typename T>
void print_struct(const T& obj) {
    auto fields = reflect(obj);
    std::apply([](const auto&... pairs) {
        ((std::cout << pairs.first << " = " << pairs.second << "\n"), ...);
    }, fields);
}

void demo_structured_binding() {
    Point2D p{1.0, 2.0};
    print_struct(p);
    // x = 1
    // y = 2

    Point3D p3{1.0, 2.0, 3.0};
    print_struct(p3);
    // x = 1
    // y = 2
    // z = 3
}

// 局限：需要为每种字段数量手写结构化绑定
// 不够通用
```

## 3. PFR / magic_get 原理

### 3.1 PFR 是什么

```cpp
// PFR (Boost.PFR，原名 magic_get) 是 Antony Polukhin 开发的库
// 它能在不使用宏的情况下自动获取聚合类型的字段信息

// 核心原理：利用 C++17 的结构化绑定 + SFINAE 自动检测字段数量

#include <boost/pfr.hpp>
#include <iostream>
#include <string>

struct Person {
    std::string first_name;
    std::string last_name;
    int age;
};

void demo_pfr() {
    Person p{"Albert", "Einstein", 76};

    // PFR 自动获取字段数量
    constexpr size_t field_count = boost::pfr::tuple_size_v<Person>;
    std::cout << "字段数量: " << field_count << "\n";  // 输出: 3

    // PFR 按索引访问字段
    std::cout << "第0个字段: " << boost::pfr::get<0>(p) << "\n";  // Albert
    std::cout << "第1个字段: " << boost::pfr::get<1>(p) << "\n";  // Einstein
    std::cout << "第2个字段: " << boost::pfr::get<2>(p) << "\n";  // 76

    // PFR 遍历所有字段
    boost::pfr::for_each_field(p, [](const auto& field) {
        std::cout << "字段值: " << field << "\n";
    });

    // PFR 获取字段名（C++20 需要）
    boost::pfr::for_each_field_with_name(p, [](const auto& name, const auto& value) {
        std::cout << name << " = " << value << "\n";
    });
    // first_name = Albert
    // last_name = Einstein
    // age = 76
}
```

### 3.2 PFR 的核心原理揭秘

```cpp
// PFR 的魔法：如何在不使用宏的情况下自动检测字段数量？

// 第一步：检测结构体是否是聚合类型（aggregate）
// 聚合类型 = 没有自定义构造函数、没有虚函数、所有成员都是 public 的

// 第二步：利用结构化绑定尝试不同字段数量
// 编译器通过 SFINAE 找到正确的字段数量

// 简化版实现：
template<typename T, typename = void>
struct fields_count;

// 尝试 N 个字段的结构化绑定
template<typename T>
constexpr auto try_bind() {
    // 生成从 1 到 N 的尝试代码
    // 哪个能编译通过，就是正确的字段数量
}

// 第三步：将结构体转换为 tuple 引用
template<typename T>
auto structure_to_tuple(T& obj) {
    // 利用已知的字段数量，用结构化绑定解包
    // 然后重新打包为 tuple
}

// 具体实现（简化版，展示核心思路）：

// 检测 T 是否可以用 1 个字段的结构化绑定
template<typename T>
auto try_1_fields(T& obj)
    -> decltype(auto [f1] = obj, std::size_t{}) { return 1; }

// 检测 T 是否可以用 2 个字段的结构化绑定
template<typename T>
auto try_2_fields(T& obj)
    -> decltype(auto [f1, f2] = obj, std::size_t{}) { return 2; }

// ... 一直到 N 个字段

// 通过 SFINAE 找到正确的数量
template<typename T>
constexpr size_t count_fields() {
    // 尝试从 1 开始，找到第一个能编译通过的
    if constexpr (requires(T t) { auto [f1] = t; }) return 1;
    else if constexpr (requires(T t) { auto [f1, f2] = t; }) return 2;
    else if constexpr (requires(T t) { auto [f1, f2, f3] = t; }) return 3;
    // ... 依此类推
}

// PFR 实际实现更复杂，需要处理：
// - 位域（bit fields）
// - 引用字段
// - C 数组成员
// - 继承的聚合类型
// - 各种编译器的不同行为
```

### 3.3 PFR 的局限性

```cpp
// PFR 只支持聚合类型（aggregate types）
// 以下类型不支持：

struct NotAggregate1 {
    int x;
    NotAggregate1(int x) : x(x) {}  // 自定义构造函数 → 不是聚合
};

struct NotAggregate2 {
    virtual void foo() = 0;  // 虚函数 → 不是聚合
    int x;
};

struct NotAggregate3 {
private:
    int x;  // 私有成员 → 不是聚合
};

// 这些类型都无法使用 PFR 的自动反射
// 需要回退到宏方案或手动注册
```

## 4. 手动注册反射系统

### 4.1 类型注册表方式

```cpp
#include <tuple>
#include <string>
#include <string_view>
#include <functional>
#include <unordered_map>
#include <any>
#include <iostream>

// ========== 反射字段描述 ==========
struct FieldInfo {
    std::string_view name;
    std::function<std::any(const void*)> getter;  // 通用获取器
    std::function<void(void*, const std::any&)> setter;  // 通用设置器
    std::string_view type_name;
};

// ========== 类型描述 ==========
struct TypeInfo {
    std::string_view name;
    std::vector<FieldInfo> fields;
};

// ========== 全局类型注册表 ==========
class ReflectionRegistry {
    static std::unordered_map<std::string_view, TypeInfo>& registry() {
        static std::unordered_map<std::string_view, TypeInfo> r;
        return r;
    }

public:
    static void register_type(std::string_view name, TypeInfo info) {
        registry()[name] = std::move(info);
    }

    static const TypeInfo* get_type(std::string_view name) {
        auto it = registry().find(name);
        return it != registry().end() ? &it->second : nullptr;
    }
};

// ========== 注册宏 ==========
#define BEGIN_REFLECT(Type) \
    namespace reflect_registration { \
    struct Type##_Registrar { \
        Type##_Registrar() { \
            TypeInfo info; \
            info.name = #Type;

#define REFLECT_FIELD(Type, field) \
            info.fields.push_back({ \
                #field, \
                [](const void* obj) -> std::any { \
                    return static_cast<const Type*>(obj)->field; \
                }, \
                [](void* obj, const std::any& val) { \
                    static_cast<Type*>(obj)->field = \
                        std::any_cast<std::decay_t<decltype(Type::field)>>(val); \
                }, \
                typeid(std::decay_t<decltype(Type::field)>).name() \
            });

#define END_REFLECT(Type) \
            ReflectionRegistry::register_type(#Type, std::move(info)); \
        } \
    }; \
    static Type##_Registrar Type##_registrar_instance; \
    }

// ========== 使用 ==========
struct Employee {
    int id;
    std::string name;
    double salary;
};

BEGIN_REFLECT(Employee)
    REFLECT_FIELD(Employee, id)
    REFLECT_FIELD(Employee, name)
    REFLECT_FIELD(Employee, salary)
END_REFLECT(Employee)

// ========== 运行时反射使用 ==========
void demo_runtime_reflection() {
    Employee emp{1, "李四", 15000.0};

    // 通过反射获取类型信息
    const TypeInfo* type = ReflectionRegistry::get_type("Employee");
    if (!type) return;

    std::cout << "类型: " << type->name << "\n";
    std::cout << "字段:\n";

    for (const auto& field : type->fields) {
        std::any value = field.getter(&emp);
        std::cout << "  " << field.name
                  << " (类型: " << field.type_name << ") = ";

        // 根据 type_name 输出值
        if (value.type() == typeid(int)) {
            std::cout << std::any_cast<int>(value);
        } else if (value.type() == typeid(std::string)) {
            std::cout << std::any_cast<std::string>(value);
        } else if (value.type() == typeid(double)) {
            std::cout << std::any_cast<double>(value);
        }
        std::cout << "\n";
    }

    // 通过反射修改字段
    for (auto& field : type->fields) {
        if (field.name == "salary") {
            field.setter(&emp, std::any(20000.0));
        }
    }
    std::cout << "涨薪后: " << emp.salary << "\n";  // 20000
}
```

## 5. C++26 反射提案

### 5.1 提案概览

```cpp
// C++26 反射提案（P2996）是目前最有可能进入标准的反射方案
// 核心概念：meta::info —— 一个可以表示任何语言实体的类型

// 注意：以下代码基于提案草案，最终语法可能有变化

#include <meta>

// meta::info 可以表示：
// - 类型（type）
// - 函数（function）
// - 变量（variable）
// - 命名空间（namespace）
// - 模板（template）
// - 枚举值（enumerator）
// - 基类（base class）
// - 等等

// 基本用法
void basic_reflection() {
    // 获取类型的反射信息
    constexpr auto type_info = ^User;  // ^User 是对 User 类型的反射

    // 获取类型名称
    static_assert(name_of(type_info) == "User");

    // 获取所有数据成员
    template for (constexpr auto member : members_of(type_info)) {
        if (is_data_member(member)) {
            // 编译期遍历每个字段
            std::cout << name_of(member) << "\n";
        }
    }
}
```

### 5.2 编译期字段遍历

```cpp
#include <meta>

// C++26 反射：真正的编译期字段遍历
struct User {
    int id;
    std::string name;
    std::string email;
    int age;
};

// 通用序列化函数（使用 C++26 反射）
template<typename T>
std::string to_json_reflect(const T& obj) {
    std::string result = "{ ";

    bool first = true;
    template for (constexpr auto member : members_of(^T)) {
        if (!is_data_member(member)) continue;

        if (!first) result += ", ";
        first = false;

        // 获取字段名
        result += "\"" + std::string(name_of(member)) + "\": ";

        // 获取字段值
        // obj.[member] 语法：通过反射成员访问实际值
        constexpr auto member_type = type_of(member);
        result += value_to_json(obj.[member]);
    }

    result += " }";
    return result;
}

// 通用打印函数
template<typename T>
void print_reflect(const T& obj) {
    template for (constexpr auto member : members_of(^T)) {
        if (is_data_member(member)) {
            std::cout << name_of(member) << " = "
                      << obj.[member] << "\n";
        }
    }
}
```

### 5.3 编译期代码生成

```cpp
#include <meta>

// C++26 反射最强大的能力：编译期代码生成

// 自动生成比较运算符
template<typename T>
bool operator==(const T& a, const T& b) {
    bool result = true;
    template for (constexpr auto member : members_of(^T)) {
        if (is_data_member(member)) {
            result = result && (a.[member] == b.[member]);
        }
    }
    return result;
}

// 自动生成哈希函数
template<typename T>
size_t hash_value(const T& obj) {
    size_t h = 0;
    template for (constexpr auto member : members_of(^T)) {
        if (is_data_member(member)) {
            h ^= std::hash<decltype(obj.[member])>{}(obj.[member])
                 + 0x9e3779b9 + (h << 6) + (h >> 2);
        }
    }
    return h;
}

// 自动生成 ORM 映射
template<typename T>
std::string generate_create_table_sql() {
    std::string sql = "CREATE TABLE " + std::string(name_of(^T)) + " (";

    bool first = true;
    template for (constexpr auto member : members_of(^T)) {
        if (!is_data_member(member)) continue;
        if (!first) sql += ", ";
        first = false;

        sql += name_of(member);
        sql += " " + type_to_sql(type_of(member));
    }

    sql += ");";
    return sql;
}

// 使用
struct Product {
    int id;           // → INTEGER PRIMARY KEY
    std::string name; // → TEXT
    double price;     // → REAL
    int stock;        // → INTEGER
};

// generate_create_table_sql<Product>()
// → "CREATE TABLE Product (id INTEGER, name TEXT, price REAL, stock INTEGER);"
```

### 5.4 反射与序列化的终极方案

```cpp
#include <meta>
#include <string>

// C++26 反射 + 编译期字符串处理 = 完美的序列化方案

// 自动处理嵌套结构
struct Address {
    std::string city;
    std::string street;
    int zip_code;
};

struct Company {
    std::string name;
    Address headquarters;  // 嵌套结构
    int employee_count;
};

template<typename T>
std::string to_json_ultimate(const T& obj) {
    std::string result = "{ ";

    bool first = true;
    template for (constexpr auto member : members_of(^T)) {
        if (!is_data_member(member)) continue;
        if (!first) result += ", ";
        first = false;

        result += "\"" + std::string(name_of(member)) + "\": ";

        // 递归处理嵌套结构
        constexpr auto member_type = type_of(member);
        if constexpr (is_class_type(member_type) && !is_std_string(member_type)) {
            result += to_json_ultimate(obj.[member]);  // 递归！
        } else {
            result += primitive_to_json(obj.[member]);
        }
    }

    result += " }";
    return result;
}

// 使用
void demo_cpp26_reflection() {
    Company c{"Acme Corp", {"北京", "长安街1号", 100000}, 500};

    std::cout << to_json_ultimate(c) << "\n";
    // 输出:
    // { "name": "Acme Corp",
    //   "headquarters": { "city": "北京", "street": "长安街1号", "zip_code": 100000 },
    //   "employee_count": 500 }
}
```

## 7. 总结

编译期反射是 C++ 长期以来最渴望的语言特性之一：

**现状**：
1. **没有语言级支持**：C++26 之前没有标准反射
2. **手动方案可行**：宏、PFR、结构化绑定都能部分解决问题
3. **各有局限**：宏侵入性强、PFR 仅支持聚合、手动注册繁琐

**未来（C++26）**：
1. `meta::info` 统一表示语言实体
2. `template for` 编译期遍历
3. `^Type` 反射运算符
4. 自动生成比较、哈希、序列化等样板代码

**核心价值**：
- 消除重复的样板代码
- 新增字段自动生效，减少遗漏 bug
- 通用库（ORM、序列化、UI 绑定）成为可能
- 提升开发效率和代码质量

在 C++26 反射正式落地之前，建议根据项目需求选择合适的过渡方案，同时保持代码结构对反射友好的设计。
