# 什么是模板递归实例化
> 📖 相关章节：[模板进阶](../../02-CPP/11-模板进阶.md)、[编译期计算基础](../../07-模板元编程与编译期计算/00-编译期计算基础.md)、[Type Traits](../../07-模板元编程与编译期计算/01-Type-Traits与类型操作.md)

## 核心速览

**模板递归实例化是 C++ 在编译期实现"循环"的唯一方式——用模板的递归特化代替运行时的 for/while 循环，每次递归产生一个新的模板实例，直到触及终止条件；虽然强大，但递归深度有限制、编译时间随深度指数增长，C++14 的 constexpr 函数已经可以在大多数场景替代这种古老的技巧。**

---

## 1. 模板递归的原理

### 1.1 从运行时循环到编译期递归

```cpp
// ========== 运行时循环：计算 1 到 N 的和 ==========
int runtime_sum(int n) {
    int result = 0;
    for (int i = 1; i <= n; ++i) {
        result += i;
    }
    return result;
}

// 问题：这个值在编译期是算不出来的
// 因为 n 可能是运行时输入

// ========== 编译期递归：用模板模拟循环 ==========
template<int N>
struct CompileTimeSum {
    // 递归定义：Sum<N> = N + Sum<N-1>
    static constexpr int value = N + CompileTimeSum<N - 1>::value;
};

// 终止条件：Sum<0> = 0
template<>
struct CompileTimeSum<0> {
    static constexpr int value = 0;
};

// 使用
static_assert(CompileTimeSum<5>::value == 15);   // 1+2+3+4+5 = 15
static_assert(CompileTimeSum<10>::value == 55);  // 1+2+...+10 = 55

// 编译器的工作过程：
// CompileTimeSum<5>::value
// = 5 + CompileTimeSum<4>::value
// = 5 + 4 + CompileTimeSum<3>::value
// = 5 + 4 + 3 + CompileTimeSum<2>::value
// = 5 + 4 + 3 + 2 + CompileTimeSum<1>::value
// = 5 + 4 + 3 + 2 + 1 + CompileTimeSum<0>::value
// = 5 + 4 + 3 + 2 + 1 + 0
// = 15

// 编译器实例化了 6 个结构体：
// CompileTimeSum<5>, <4>, <3>, <2>, <1>, <0>
```

### 1.2 模板递归的三要素

```cpp
// 每个模板递归都需要三个要素：

// 1. 递归模板（一般情况）
template<int N>
struct Factorial {
    static constexpr int value = N * Factorial<N - 1>::value;
};

// 2. 终止条件（特化/偏特化）
template<>
struct Factorial<0> {
    static constexpr int value = 1;
};

// 3. 初始调用
static_assert(Factorial<5>::value == 120);

// 类比运行时递归：
// int factorial(int n) {           ← 递归模板
//     if (n == 0) return 1;        ← 终止条件
//     return n * factorial(n-1);   ← 递归调用
// }
```

### 1.3 经典示例：编译期斐波那契

```cpp
// 编译期斐波那契数列
template<int N>
struct Fibonacci {
    static constexpr int value = Fibonacci<N - 1>::value + Fibonacci<N - 2>::value;
};

template<>
struct Fibonacci<0> {
    static constexpr int value = 0;
};

template<>
struct Fibonacci<1> {
    static constexpr int value = 1;
};

static_assert(Fibonacci<0>::value == 0);
static_assert(Fibonacci<1>::value == 1);
static_assert(Fibonacci<5>::value == 5);
static_assert(Fibonacci<10>::value == 55);
static_assert(Fibonacci<20>::value == 6765);

// ⚠️ 注意：这个实现有严重的性能问题！
// Fibonacci<5> 的实例化过程：
//
//                    Fib<5>
//                   /      \
//              Fib<4>      Fib<3>
//             /     \      /    \
//         Fib<3>   Fib<2> Fib<2> Fib<1>
//         /   \    /   \   /  \
//     Fib<2> Fib<1> Fib<1> Fib<0> ...
//     /   \
// Fib<1> Fib<0>
//
// 大量重复实例化！Fib<3> 被实例化了 2 次，Fib<2> 被实例化了 3 次
// 时间复杂度：O(2^n) —— 指数级！
```

## 2. 编译期循环的实现方式

### 2.1 类型列表的遍历

```cpp
#include <iostream>
#include <type_traits>

// 编译期类型列表
template<typename... Types>
struct TypeList {};

// 获取列表长度
template<typename List>
struct Length;

template<typename... Types>
struct Length<TypeList<Types...>> {
    static constexpr size_t value = sizeof...(Types);
};

static_assert(Length<TypeList<int, double, char>>::value == 3);

// 获取第 N 个类型
template<size_t N, typename List>
struct TypeAt;

template<typename Head, typename... Tail>
struct TypeAt<0, TypeList<Head, Tail...>> {
    using type = Head;
};

template<size_t N, typename Head, typename... Tail>
struct TypeAt<N, TypeList<Head, Tail...>> {
    using type = typename TypeAt<N - 1, TypeList<Tail...>>::type;
};

static_assert(std::is_same_v<TypeAt<0, TypeList<int, double, char>>::type, int>);
static_assert(std::is_same_v<TypeAt<1, TypeList<int, double, char>>::type, double>);
static_assert(std::is_same_v<TypeAt<2, TypeList<int, double, char>>::type, char>);

// 对每个类型执行操作
template<typename List, typename Func>
void for_each_type(Func&& func);

template<typename Head, typename... Tail, typename Func>
void for_each_type_impl(Func&& func) {
    func(Head{});  // 对当前类型执行操作
    if constexpr (sizeof...(Tail) > 0) {
        for_each_type_impl<Tail...>(std::forward<Func>(func));  // 递归
    }
}

template<typename... Types, typename Func>
void for_each_type(TypeList<Types...>, Func&& func) {
    for_each_type_impl<Types...>(std::forward<Func>(func));
}

// 使用
void demo_type_list() {
    using MyTypes = TypeList<int, double, std::string>;

    for_each_type(MyTypes{}, [](auto val) {
        using T = decltype(val);
        std::cout << "类型大小: " << sizeof(T) << " 字节\n";
    });
}
```

### 2.2 编译期循环展开

```cpp
// 编译期循环展开：将循环在编译期展开为顺序代码
// 避免运行时的循环判断和跳转

template<int Start, int End, typename Func>
struct CompileTimeLoop {
    static void execute(Func& func) {
        func(Start);
        CompileTimeLoop<Start + 1, End, Func>::execute(func);
    }
};

template<int End, typename Func>
struct CompileTimeLoop<End, End, Func> {
    static void execute(Func&) {
        // 终止条件：什么都不做
    }
};

// C++14 更简洁的方式：使用 constexpr 函数
template<int Start, int End, typename Func>
constexpr void constexpr_for(Func&& func) {
    if constexpr (Start < End) {
        func(std::integral_constant<int, Start>{});
        constexpr_for<Start + 1, End>(std::forward<Func>(func));
    }
}

// 使用
void demo_loop_unroll() {
    // 编译期展开 5 次迭代
    constexpr_for<0, 5>([](auto idx) {
        constexpr int i = decltype(idx)::value;
        std::cout << "迭代 " << i << "\n";
        // 编译器可能完全展开这个循环
    });
}

// 实际应用：编译期初始化数组
template<typename T, size_t N>
struct LookupTable {
    T data[N];

    constexpr LookupTable() : data{} {
        constexpr_for<0, N>([this](auto idx) {
            constexpr size_t i = decltype(idx)::value;
            data[i] = compute(i);
        });
    }

    static constexpr T compute(size_t i) {
        return i * i;  // 示例：平方表
    }
};

constexpr LookupTable<int, 10> squares;
static_assert(squares.data[5] == 25);
static_assert(squares.data[9] == 81);
```

### 2.3 编译期字符串处理

```cpp
// 编译期字符串反转（模板递归方式）
template<typename Char, Char... Chars>
struct CompileTimeString {};

// 递归反转
template<typename Char, Char First, Char... Rest>
struct ReverseString {
    using type = typename AppendChar<
        Char,
        First,
        typename ReverseString<Char, Rest...>::type
    >::type;
};

template<typename Char, Char Single>
struct ReverseString<Char, Single> {
    using type = CompileTimeString<Char, Single>;
};

// 追加字符到字符串末尾
template<typename Char, Char C, typename Str>
struct AppendChar;

template<typename Char, Char C, Char... Chars>
struct AppendChar<Char, C, CompileTimeString<Char, Chars...>> {
    using type = CompileTimeString<Char, Chars..., C>;
};
```

## 3. 递归深度限制

### 3.1 编译器的递归深度限制

```cpp
// 各编译器的默认模板递归深度限制：
// GCC:    900（可通过 -ftemplate-depth=N 修改）
// Clang:  1024（可通过 -ftemplate-depth=N 修改）
// MSVC:   无明确限制，但通常在几百到几千

// 测试递归深度限制
template<int N>
struct DeepRecursion {
    static constexpr int value = N + DeepRecursion<N - 1>::value;
};

template<>
struct DeepRecursion<0> {
    static constexpr int value = 0;
};

// 在默认设置下：
static_assert(DeepRecursion<100>::value == 5050);   // ✅ 通常没问题
static_assert(DeepRecursion<500>::value == 125250); // ✅ 大多数编译器可以
// static_assert(DeepRecursion<2000>::value == ...); // ❌ 可能超出限制！

// 编译错误示例：
// "template instantiation depth exceeded maximum of 900"
// "(use -ftemplate-depth= to increase the maximum)"
```

### 3.2 增加递归深度限制

```bash
# GCC / Clang：增加模板递归深度
g++ -ftemplate-depth=2000 source.cpp
clang++ -ftemplate-depth=2000 source.cpp

# CMake 中设置
if(CMAKE_CXX_COMPILER_ID MATCHES "GNU|Clang")
    add_compile_options(-ftemplate-depth=2000)
endif()
```

### 3.3 为什么不应该随意增加深度限制

```cpp
// 原因 1：编译时间指数增长
// 递归深度 N → 编译器要实例化 N 个模板
// 每个实例化都要解析和生成代码

// 原因 2：内存消耗
// 每个模板实例都占用编译器内存
// 深度 10000 → 可能消耗数 GB 内存

// 原因 3：错误信息爆炸
// 递归深度 100 → 错误信息可能有几百行
// 递归深度 1000 → 错误信息可能超过 10000 行

// 原因 4：可能掩盖设计问题
// 需要深度递归通常意味着算法设计不合理
// 应该寻找非递归的替代方案
```

## 4. 如何避免递归实例化爆炸

### 4.1 用 constexpr 函数替代模板递归

```cpp
// ========== 旧方式：模板递归 ==========
template<int N>
struct FactorialOld {
    static constexpr int value = N * FactorialOld<N - 1>::value;
};
template<>
struct FactorialOld<0> {
    static constexpr int value = 1;
};

// ========== 新方式：constexpr 函数（C++14）==========
constexpr int factorial(int n) {
    int result = 1;
    for (int i = 2; i <= n; ++i) {
        result *= i;
    }
    return result;
}

// 效果完全相同，但：
// 1. 不会产生 N 个模板实例
// 2. 编译时间大幅减少
// 3. 代码更简洁、更易读
// 4. 没有递归深度限制

static_assert(factorial(5) == 120);
static_assert(factorial(10) == 3628800);
// static_assert(factorial(100) > 0);  // ✅ 也能工作！
```

### 4.2 对数深度递归

```cpp
// 当必须使用模板递归时，可以用对数深度策略

// 线性递归：O(N) 深度
template<int N>
struct LinearPower {
    static constexpr int value = N * LinearPower<N - 1>::value;
};

// 对数递归：O(log N) 深度
template<int Base, int Exp>
struct LogPower {
    static constexpr int half = LogPower<Base, Exp / 2>::value;
    static constexpr int value = (Exp % 2 == 0) ? half * half : half * half * Base;
};

template<int Base>
struct LogPower<Base, 0> {
    static constexpr int value = 1;
};

template<int Base>
struct LogPower<Base, 1> {
    static constexpr int value = Base;
};

// 对比：
// 计算 2^1024
// 线性递归：1024 层实例化
// 对数递归：log2(1024) = 10 层实例化！

static_assert(LogPower<2, 10>::value == 1024);
static_assert(LogPower<3, 5>::value == 243);
```

### 4.3 分治策略

```cpp
// 编译期求和：分治法
// 将 N 个数的求和分成两半，递归求解

template<int From, int To>
struct DivideSum {
    static constexpr int Mid = (From + To) / 2;
    static constexpr int value =
        DivideSum<From, Mid>::value + DivideSum<Mid + 1, To>::value;
};

template<int N>
struct DivideSum<N, N> {
    static constexpr int value = N;
};

// 对比：
// 线性递归 Sum<1000> → 1000 层
// 分治递归 DivideSum<1, 1000> → log2(1000) ≈ 10 层

static_assert(DivideSum<1, 10>::value == 55);
static_assert(DivideSum<1, 100>::value == 5050);
```

### 4.4 使用可变参数模板减少递归

```cpp
// 旧方式：逐个处理类型列表，线性递归
template<typename List>
struct OldLength;

template<typename Head, typename... Tail>
struct OldLength<TypeList<Head, Tail...>> {
    static constexpr size_t value = 1 + OldLength<TypeList<Tail...>>::value;
};

template<>
struct OldLength<TypeList<>> {
    static constexpr size_t value = 0;
};

// 新方式：直接使用 sizeof...，零递归
template<typename... Types>
struct NewLength {
    static constexpr size_t value = sizeof...(Types);
};

static_assert(NewLength<int, double, char>::value == 3);

// 另一个例子：编译期求和（使用可变参数）
template<int... Values>
struct VariadicSum;

template<>
struct VariadicSum<> {
    static constexpr int value = 0;
};

template<int First, int... Rest>
struct VariadicSum<First, Rest...> {
    static constexpr int value = First + VariadicSum<Rest...>::value;
};

// 但 C++17 折叠表达式更好：
template<int... Values>
constexpr int fold_sum() {
    return (Values + ... + 0);  // 一行搞定！
}

static_assert(fold_sum<1, 2, 3, 4, 5>() == 15);
```

### 4.5 记忆化（Memoization）

```cpp
// 斐波那契的记忆化：避免重复实例化

// 原始版本：指数级实例化
template<int N>
struct FibSlow {
    static constexpr int value = FibSlow<N-1>::value + FibSlow<N-2>::value;
    // FibSlow<5> 会实例化 FibSlow<4> 和 FibSlow<3>
    // FibSlow<4> 又会实例化 FibSlow<3> 和 FibSlow<2>
    // FibSlow<3> 被实例化了两次！
};

// 记忆化版本：线性实例化
template<int N>
struct FibMemo {
private:
    // 辅助结构：同时计算 Fib<N-1> 和 Fib<N-2>
    // 避免重复实例化
    static constexpr int compute() {
        if constexpr (N == 0) return 0;
        else if constexpr (N == 1) return 1;
        else return FibMemo<N-1>::value + FibMemo<N-2>::value;
        // 注意：由于模板实例化会缓存结果
        // FibMemo<N-2> 在 FibMemo<N-1> 的实例化过程中已经被实例化
        // 所以不会重复实例化
    }

public:
    static constexpr int value = compute();
};

// 但最简单的方案还是用 constexpr 函数：
constexpr int fib(int n) {
    if (n <= 1) return n;
    int a = 0, b = 1;
    for (int i = 2; i <= n; ++i) {
        int temp = a + b;
        a = b;
        b = temp;
    }
    return b;
}

static_assert(fib(20) == 6765);
// 零模板实例化，O(n) 时间，O(1) 空间
```

## 5. 模板递归实例化的实际应用

### 5.1 编译期类型分发

```cpp
#include <type_traits>
#include <iostream>

// 编译期根据类型列表分发处理
template<typename T>
void process_single_type() {
    if constexpr (std::is_integral_v<T>) {
        std::cout << "整型\n";
    } else if constexpr (std::is_floating_point_v<T>) {
        std::cout << "浮点型\n";
    } else {
        std::cout << "其他类型\n";
    }
}

// 递归处理类型列表
template<typename... Types>
void process_all_types() {
    (process_single_type<Types>(), ...);  // C++17 折叠表达式
}

// 使用
void demo_type_dispatch() {
    process_all_types<int, double, std::string>();
    // 输出:
    // 整型
    // 浮点型
    // 其他类型
}
```

### 5.2 编译期策略选择

```cpp
// 编译期根据条件选择算法
template<int DataSize, bool PreferSpeedOverSize>
struct SortStrategy {
    using type = typename std::conditional_t<
        PreferSpeedOverSize,
        QuickSort<DataSize>,    // 快速排序
        HeapSort<DataSize>      // 堆排序
    >;
};

// 编译期根据数据大小选择排序算法
template<size_t N>
struct AutoSortStrategy {
    using type = typename std::conditional_t<
        (N <= 64),
        InsertionSort<N>,       // 小数据：插入排序
        typename std::conditional_t<
            (N <= 10000),
            QuickSort<N>,       // 中等数据：快速排序
            MergeSort<N>        // 大数据：归并排序
        >
    >;
};
```

### 5.3 编译期状态机

```cpp
// 编译期字符串校验：用模板递归实现状态机

// 状态：初始、数字、小数点、小数位
enum class State { Start, Integer, Dot, Decimal };

// 状态转移函数
constexpr State next_state(State current, char c) {
    switch (current) {
        case State::Start:
            if (c >= '0' && c <= '9') return State::Integer;
            return State::Start;  // 无效
        case State::Integer:
            if (c >= '0' && c <= '9') return State::Integer;
            if (c == '.') return State::Dot;
            return State::Start;  // 无效
        case State::Dot:
            if (c >= '0' && c <= '9') return State::Decimal;
            return State::Start;  // 无效
        case State::Decimal:
            if (c >= '0' && c <= '9') return State::Decimal;
            return State::Start;  // 无效
    }
    return State::Start;
}

// 编译期字符串校验
constexpr bool is_valid_number(std::string_view str) {
    State state = State::Start;
    for (char c : str) {
        state = next_state(state, c);
    }
    return state == State::Integer || state == State::Decimal;
}

static_assert(is_valid_number("123"));
static_assert(is_valid_number("3.14"));
static_assert(!is_valid_number("3."));
static_assert(!is_valid_number(".5"));
static_assert(is_valid_number("0.5"));
```

## 6. 总结

模板递归实例化是 C++ 模板元编程的基础技术，但在现代 C++ 中其重要性正在下降：

**历史地位**：
- C++11 之前：唯一的编译期计算方式
- C++14 之后：大多数场景被 constexpr 函数替代
- 仍然重要：类型级计算、SFINAE、编译期类型列表操作

**核心要点**：
1. 每个模板递归都需要递归模板 + 终止条件
2. 递归深度受编译器限制（通常 900-1024）
3. 重复实例化导致指数级编译时间增长
4. 对数深度、分治、记忆化可以缓解问题

**现代替代方案**：
1. `constexpr` 函数替代数值递归
2. `if constexpr` 替代 SFINAE 递归
3. 折叠表达式替代可变参数递归
4. `consteval` 确保编译期执行

**最佳实践**：能用 constexpr 函数就不要用模板递归。模板递归应该只用于类型级计算（类型列表操作、条件类型选择等），而不是数值计算。
