# 模板元编程与代码膨胀
> 📖 相关章节：[模板进阶](../../02-CPP/11-模板进阶.md)、[编译期计算基础](../../07-模板元编程与编译期计算/00-编译期计算基础.md)、[Type Traits](../../07-模板元编程与编译期计算/01-Type-Traits与类型操作.md)

## 要点直击

**代码膨胀是模板最被诟病的副作用——每种不同的模板参数组合都会生成一份独立的机器码，`vector<int>` 和 `vector<double>` 是两套完全独立的代码，当类型组合爆炸时，二进制体积可能膨胀数倍甚至数十倍；但通过 Thin Template Idiom、类型擦除、显式实例化等策略，可以在保持泛型优势的同时将膨胀控制在可接受范围内。**

## 1. 什么是代码膨胀

### 1.1 直观理解

```cpp
#include <vector>
#include <set>
#include <map>
#include <string>

// 每种类型参数组合都会生成独立的代码
std::vector<int>       vi;   // 生成 vector<int> 的全部代码
std::vector<double>    vd;   // 生成 vector<double> 的全部代码
std::vector<float>     vf;   // 生成 vector<float> 的全部代码
std::vector<std::string> vs; // 生成 vector<string> 的全部代码

// vector 的实现大约有 3000-5000 行
// 4 种类型 → 4 × 4000 = 16000 行实例化代码
// 如果用 20 种类型 → 80000 行！

// 更糟糕的情况：嵌套模板
std::map<std::string, std::vector<int>>       m1;  // 一套代码
std::map<std::string, std::vector<double>>    m2;  // 又一套代码
std::map<int, std::vector<std::string>>       m3;  // 再一套代码
// map 本身就是模板，vector 也是模板
// 组合起来代码量惊人
```

### 1.2 代码膨胀的量化分析

```cpp

// 二进制大小对比（典型情况）：
// 0 种实例化（只有非模板代码）: 100 KB
// 5 种实例化:  200 KB (+100 KB)
// 10 种实例化: 350 KB (+250 KB)
// 50 种实例化: 1.5 MB (+1.4 MB)
// 100 种实例化: 3 MB (+2.9 MB)
```

## 2. 模板实例化如何导致代码膨胀

### 2.1 水平膨胀详解

```cpp
// 水平膨胀：同一模板，不同类型参数 → 不同代码

template<typename T>
T max_value(T a, T b) {
    return (a > b) ? a : b;
}

// 实例化 3 种类型
int x = max_value(1, 2);           // 生成 max_value<int>
double y = max_value(1.0, 2.0);    // 生成 max_value<double>
std::string z = max_value(s1, s2); // 生成 max_value<string>

// 编译器生成了 3 份函数体
// 即使逻辑完全相同（比较两个值返回较大的）
// 只是操作的数据类型不同

// 汇编层面：
// max_value<int>:    cmp, jle, mov     （3-4 条指令）
// max_value<double>: ucomisd, jbe, mov （3-4 条指令）
// max_value<string>: call operator>, call copy, ... （很多指令）

// 对于 int 和 double，逻辑几乎相同
// 但编译器仍然生成了两份代码
```

### 2.2 垂直膨胀详解

```cpp
// 垂直膨胀：模板嵌套 → 代码层层叠加

template<typename T>
class Wrapper {
    T value_;
public:
    void set(const T& v) { value_ = v; }
    T get() const { return value_; }
};

template<typename T>
class Container {
    Wrapper<T> wrapper_;  // 内嵌另一个模板
public:
    void set(const T& v) { wrapper_.set(v); }
    T get() const { return wrapper_.get(); }
};

template<typename T>
class Manager {
    Container<T> container_;  // 再嵌套一层
public:
    void set(const T& v) { container_.set(v); }
    T get() const { return container_.get(); }
};

// Manager<int> 的实例化导致：
// 1. Manager<int> 的代码
// 2. Container<int> 的代码
// 3. Wrapper<int> 的代码
// 三层嵌套，每层都生成代码

// 如果 Manager 有 5 种类型参数
// 每层有 5 种类型参数
// 总实例化数 = 5 × 5 × 5 = 125 份代码！
```

### 2.3 间接膨胀详解

```cpp
// 间接膨胀：内联导致的代码复制

template<typename T>
inline T square(T x) { return x * x; }

void process() {
    // 如果编译器内联了 square
    int a = square(1);     // 展开为：int a = 1 * 1;
    int b = square(2);     // 展开为：int b = 2 * 2;
    int c = square(3);     // 展开为：int c = 3 * 3;
    double d = square(1.5); // 展开为：double d = 1.5 * 1.5;

    // 每个调用点都有一份展开后的代码
    // 如果 square 被调用 1000 次
    // 就有 1000 份内联代码

    // 这通常是有益的（内联提升性能）
    // 但在极端情况下会导致代码膨胀
    // 特别是当内联函数本身很大时
}
```

## 3. 减少代码膨胀的策略

### 3.1 Thin Template Idiom（瘦模板惯用法）

```cpp
// 核心思想：将类型无关的代码提取到非模板基类中
// 模板派生类只包含类型相关的薄层代码

// ========== 反面教材：所有代码都在模板中 ==========
template<typename T>
class FatVector {
    T* data_;           // 类型相关
    size_t size_;       // 类型无关
    size_t capacity_;   // 类型无关

public:
    FatVector() : data_(nullptr), size_(0), capacity_(0) {}

    void push_back(const T& val) {
        if (size_ >= capacity_) {
            reserve(capacity_ ? capacity_ * 2 : 4);
        }
        data_[size_++] = val;  // 类型相关
    }

    void reserve(size_t new_cap) {
        // 大量类型无关的内存管理代码
        T* new_data = static_cast<T*>(::operator new(new_cap * sizeof(T)));
        for (size_t i = 0; i < size_; ++i) {
            new (&new_data[i]) T(std::move(data_[i]));  // 类型相关
        }
        for (size_t i = 0; i < size_; ++i) {
            data_[i].~T();  // 类型相关
        }
        ::operator delete(data_);
        data_ = new_data;
        capacity_ = new_cap;
    }

    size_t size() const { return size_; }        // 类型无关
    size_t capacity() const { return capacity_; } // 类型无关
    bool empty() const { return size_ == 0; }    // 类型无关
    void clear() { size_ = 0; }                  // 类型无关（简化版）

    T& operator[](size_t i) { return data_[i]; } // 类型相关
};

// FatVector<int> 和 FatVector<double> 各有一份完整的代码
// 包括 reserve() 中的内存管理逻辑（完全相同！）

// ========== 正面教材：Thin Template Idiom ==========

// 非模板基类：包含所有类型无关的代码
class VectorBase {
protected:
    void* data_;        // 用 void* 代替 T*
    size_t size_;
    size_t capacity_;
    size_t element_size_;  // 存储元素大小

    VectorBase(size_t elem_size)
        : data_(nullptr), size_(0), capacity_(0), element_size_(elem_size) {}

    // 类型无关的核心操作
    void reserve_base(size_t new_cap);
    void* element_at(size_t i) const {
        return static_cast<char*>(data_) + i * element_size_;
    }

public:
    size_t size() const { return size_; }
    size_t capacity() const { return capacity_; }
    bool empty() const { return size_ == 0; }
    void clear_base() { size_ = 0; }

    ~VectorBase();
};

// VectorBase 的实现（只生成一份代码！）
void VectorBase::reserve_base(size_t new_cap) {
    void* new_data = ::operator new(new_cap * element_size_);
    // 使用 memcpy 而不是移动构造（假设类型是 trivially copyable）
    // 或者使用回调函数处理非 trivial 类型
    if (data_) {
        std::memcpy(new_data, data_, size_ * element_size_);
        ::operator delete(data_);
    }
    data_ = new_data;
    capacity_ = new_cap;
}

VectorBase::~VectorBase() {
    if (data_) ::operator delete(data_);
}

// 模板派生类：只包含类型相关的薄层
template<typename T>
class ThinVector : private VectorBase {
public:
    ThinVector() : VectorBase(sizeof(T)) {}

    void push_back(const T& val) {
        if (size_ >= capacity_) {
            reserve_base(capacity_ ? capacity_ * 2 : 4);
        }
        new (element_at(size_)) T(val);  // placement new，类型相关
        ++size_;
    }

    void reserve(size_t n) { reserve_base(n); }

    T& operator[](size_t i) {
        return *static_cast<T*>(element_at(i));
    }

    const T& operator[](size_t i) const {
        return *static_cast<const T*>(element_at(i));
    }

    using VectorBase::size;
    using VectorBase::capacity;
    using VectorBase::empty;
};

// 效果：
// VectorBase 的代码只生成一份
// ThinVector<int> 和 ThinVector<double> 只有薄薄的类型相关代码
// 代码膨胀大幅减少！
```

### 3.2 类型擦除

```cpp
#include <functional>
#include <memory>
#include <iostream>

// 类型擦除：隐藏具体类型，用统一接口操作

// ========== 示例：可调用对象的类型擦除 ==========
class Task {
    struct Concept {
        virtual ~Concept() = default;
        virtual void execute() = 0;
        virtual std::unique_ptr<Concept> clone() const = 0;
    };

    template<typename F>
    struct Model : Concept {
        F func_;
        Model(F func) : func_(std::move(func)) {}
        void execute() override { func_(); }
        std::unique_ptr<Concept> clone() const override {
            return std::make_unique<Model>(func_);
        }
    };

    std::unique_ptr<Concept> impl_;

public:
    template<typename F>
    Task(F func) : impl_(std::make_unique<Model<F>>(std::move(func))) {}

    Task(const Task& other) : impl_(other.impl_->clone()) {}
    Task(Task&&) = default;
    Task& operator=(const Task& other) {
        impl_ = other.impl_->clone();
        return *this;
    }

    void execute() { impl_->execute(); }
};

// 使用
void demo_type_erasure() {
    // 不需要为每种可调用类型实例化不同的模板
    std::vector<Task> tasks;

    tasks.emplace_back([] { std::cout << "Lambda 1\n"; });
    tasks.emplace_back([] { std::cout << "Lambda 2\n"; });
    tasks.emplace_back([](int x) { std::cout << "x=" << x << "\n"; });  // ❌ 签名不同

    // 如果不用类型擦除，需要：
    // std::vector<std::function<void()>>  → 标准库的类型擦除
    // 或者模板版本 → 每种 lambda 类型都实例化一份代码
}
```

### 3.3 void* + 回调函数模式

```cpp
#include <cstring>
#include <functional>

// 类似 C 标准库 qsort 的方式：用 void* 和函数指针避免模板

// 通用排序函数（非模板，只生成一份代码）
void generic_sort(
    void* base,
    size_t num,
    size_t element_size,
    int (*compare)(const void*, const void*)
) {
    // 使用简单的冒泡排序（示例）
    char* arr = static_cast<char*>(base);
    char* temp = new char[element_size];

    for (size_t i = 0; i < num - 1; ++i) {
        for (size_t j = 0; j < num - i - 1; ++j) {
            char* a = arr + j * element_size;
            char* b = arr + (j + 1) * element_size;
            if (compare(a, b) > 0) {
                std::memcpy(temp, a, element_size);
                std::memcpy(a, b, element_size);
                std::memcpy(b, temp, element_size);
            }
        }
    }

    delete[] temp;
}

// 使用
int compare_int(const void* a, const void* b) {
    return *static_cast<const int*>(a) - *static_cast<const int*>(b);
}

int compare_double(const void* a, const void* b) {
    double da = *static_cast<const double*>(a);
    double db = *static_cast<const double*>(b);
    return (da > db) - (da < db);
}

void demo_void_star() {
    int ints[] = {3, 1, 4, 1, 5, 9};
    generic_sort(ints, 6, sizeof(int), compare_int);

    double doubles[] = {3.14, 2.71, 1.41};
    generic_sort(doubles, 3, sizeof(double), compare_double);

    // generic_sort 只有一份代码！
    // 代价：类型安全性降低，性能可能不如模板版本
}
```

## 5. Thin Template Idiom 详解

### 5.1 完整的实现示例

```cpp
#include <cstring>
#include <stdexcept>
#include <memory>

// ========== 非模板基类：所有类型无关的代码 ==========
class VectorImpl {
protected:
    void* data_;
    size_t size_;
    size_t capacity_;
    size_t element_size_;

    // 构造/析构回调（由派生类设置）
    using ConstructFunc = void(*)(void* dst, const void* src);
    using DestroyFunc = void(*)(void* obj);
    using MoveFunc = void(*)(void* dst, void* src);

    ConstructFunc construct_;
    DestroyFunc destroy_;
    MoveFunc move_;

    VectorImpl(size_t elem_size,
               ConstructFunc ctor,
               DestroyFunc dtor,
               MoveFunc mover)
        : data_(nullptr)
        , size_(0)
        , capacity_(0)
        , element_size_(elem_size)
        , construct_(ctor)
        , destroy_(dtor)
        , move_(mover)
    {}

    // 类型无关的内存管理
    void grow(size_t min_cap) {
        size_t new_cap = capacity_ ? capacity_ * 2 : 4;
        if (new_cap < min_cap) new_cap = min_cap;

        void* new_data = ::operator new(new_cap * element_size_);

        // 移动旧元素到新内存
        for (size_t i = 0; i < size_; ++i) {
            void* old_elem = static_cast<char*>(data_) + i * element_size_;
            void* new_elem = static_cast<char*>(new_data) + i * element_size_;
            move_(new_elem, old_elem);
        }

        // 释放旧内存
        if (data_) ::operator delete(data_);

        data_ = new_data;
        capacity_ = new_cap;
    }

    void* element_ptr(size_t i) const {
        return static_cast<char*>(data_) + i * element_size_;
    }

public:
    size_t size() const { return size_; }
    size_t capacity() const { return capacity_; }
    bool empty() const { return size_ == 0; }

    void clear() {
        for (size_t i = 0; i < size_; ++i) {
            destroy_(element_ptr(i));
        }
        size_ = 0;
    }

    ~VectorImpl() {
        clear();
        if (data_) ::operator delete(data_);
    }

    // 禁止拷贝
    VectorImpl(const VectorImpl&) = delete;
    VectorImpl& operator=(const VectorImpl&) = delete;
};

// ========== 模板派生类：类型相关的薄层 ==========
template<typename T>
class ThinVector : private VectorImpl {
    // 类型相关的回调函数
    static void construct(void* dst, const void* src) {
        new (dst) T(*static_cast<const T*>(src));
    }

    static void destroy(void* obj) {
        static_cast<T*>(obj)->~T();
    }

    static void move(void* dst, void* src) {
        new (dst) T(std::move(*static_cast<T*>(src)));
        static_cast<T*>(src)->~T();
    }

public:
    ThinVector()
        : VectorImpl(sizeof(T), &construct, &destroy, &move) {}

    void push_back(const T& val) {
        if (size_ >= capacity_) grow(size_ + 1);
        construct(element_ptr(size_), &val);
        ++size_;
    }

    void push_back(T&& val) {
        if (size_ >= capacity_) grow(size_ + 1);
        new (element_ptr(size_)) T(std::move(val));
        ++size_;
    }

    void pop_back() {
        --size_;
        destroy(element_ptr(size_));
    }

    T& operator[](size_t i) {
        return *static_cast<T*>(element_ptr(i));
    }

    const T& operator[](size_t i) const {
        return *static_cast<const T*>(element_ptr(i));
    }

    T* data() { return static_cast<T*>(data_); }
    const T* data() const { return static_cast<const T*>(data_); }

    using VectorImpl::size;
    using VectorImpl::capacity;
    using VectorImpl::empty;
    using VectorImpl::clear;

    // 迭代器支持
    T* begin() { return data(); }
    T* end() { return data() + size_; }
    const T* begin() const { return data(); }
    const T* end() const { return data() + size_; }
};

// 效果：
// VectorImpl 的代码只生成一份（包括 grow、clear 等复杂逻辑）
// ThinVector<int> 和 ThinVector<double> 只有薄薄的 push_back、operator[] 等
// 代码膨胀大幅减少！
```

## 6. 总结

代码膨胀是模板元编程不可回避的副作用，但可以通过多种策略控制：

**膨胀根源**：
1. 水平膨胀：不同类型参数 → 不同代码
2. 垂直膨胀：模板嵌套 → 代码叠加
3. 间接膨胀：内联 → 代码复制

**控制策略**（按推荐优先级）：
1. **Thin Template Idiom** —— 最有效的减少膨胀手段
2. **类型擦除** —— 隐藏具体类型，统一接口
3. **显式实例化** —— 控制实例化种类
4. **公共基类提取** —— 类型无关代码只生成一份
5. **void* + 回调** —— C 风格，牺牲类型安全
6. **链接器优化** —— gc-sections 删除未使用代码

**权衡原则**：
- 代码膨胀不是绝对的恶——有时用空间换时间是合理的
- 关注膨胀比例而非绝对大小
- 嵌入式和移动端对膨胀更敏感
- 桌面和服务器端可以更宽容

**最佳实践**：在设计模板库时就考虑代码膨胀问题，而不是等到二进制爆炸后再补救。对于公共 API，优先考虑 Thin Template；对于内部实现，直接用模板即可。
