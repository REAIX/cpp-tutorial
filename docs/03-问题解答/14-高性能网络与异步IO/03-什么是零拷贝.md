# 什么是零拷贝
> 📖 相关章节：[网络编程](../../02-CPP/35-网络编程.md)、[IO多路复用](../../08-高性能网络与异步IO/01-IO多路复用深入.md)、[Reactor模式](../../08-高性能网络与异步IO/02-Reactor模式.md)

> "核心要义：零拷贝=让数据直接从文件到网卡，不在CPU/内存之间来回搬。传统传输4次拷贝+4次上下文切换，零拷贝只需2次拷贝+2次切换，甚至可以0次拷贝。"

***

### 1. 通俗理解

- **零拷贝** = 减少或消除数据在内核缓冲区和用户缓冲区之间的来回拷贝
- 传统read+write：数据从磁盘→内核缓冲区→用户缓冲区→内核socket缓冲区→网卡，4次拷贝
- 零拷贝：数据直接从磁盘→内核缓冲区→网卡，跳过用户态

| 概念 | 类比 | 说明 |
|------|------|------|
| 传统拷贝 | 快递先到分拣中心→你手上→你送到另一个分拣中心→再发出 | 数据经过用户态 |
| 零拷贝 | 快递直接从分拣中心转到发出，不经过你手 | 数据不经过用户态 |
| mmap | 你直接去分拣中心取件 | 共享内存，不需要拷贝 |
| sendfile | 分拣中心直接转发 | 内核直接传输 |
| MSG_ZEROCOPY | 整车直接开走 | 网卡直接从内存DMA |

***

### 2. 技术说明

#### 1. 传统数据传输的拷贝次数

**场景：从文件读取数据，通过socket发送**

```c
// 传统方式
read(file_fd, buf, len);      // 读文件到用户缓冲区
write(socket_fd, buf, len);   // 从用户缓冲区写到socket
```

**4次数据拷贝**：

```
┌──────────┐    ┌──────────────┐    ┌──────────┐    ┌──────────────┐    ┌──────────┐
│   磁盘    │    │ 内核Page     │    │ 用户      │    │ 内核Socket   │    │  网卡     │
│   文件    │    │ Cache        │    │ 缓冲区    │    │ 缓冲区       │    │          │
│          │    │              │    │          │    │              │    │          │
│  数据 ───┼──→ │  拷贝1(DMA)  │──→ │ 拷贝2(CPU)│──→ │ 拷贝3(CPU)  │──→ │ 拷贝4(DMA)│
│          │    │              │    │          │    │              │    │          │
└──────────┘    └──────────────┘    └──────────┘    └──────────────┘    └──────────┘

拷贝1: 磁盘 → 内核Page Cache（DMA拷贝，不占CPU）
拷贝2: 内核Page Cache → 用户缓冲区（CPU拷贝）
拷贝3: 用户缓冲区 → 内核Socket缓冲区（CPU拷贝）
拷贝4: 内核Socket缓冲区 → 网卡（DMA拷贝，不占CPU）
```

**4次上下文切换**：

```
用户态 → 内核态（read系统调用）
内核态 → 用户态（read返回）
用户态 → 内核态（write系统调用）
内核态 → 用户态（write返回）
```

**总结**：2次CPU拷贝 + 2次DMA拷贝 + 4次上下文切换 + 数据冗余（用户缓冲区只是中转）

#### 2. sendfile原理

```c
// sendfile方式
ssize_t sendfile(int out_fd, int in_fd, off_t *offset, size_t count);
```

**2次数据拷贝**（带DMA scatter-gather）：

```
┌──────────┐    ┌──────────────┐    ┌──────────────┐    ┌──────────┐
│   磁盘    │    │ 内核Page     │    │ 内核Socket   │    │  网卡     │
│   文件    │    │ Cache        │    │ 缓冲区       │    │          │
│          │    │              │    │              │    │          │
│  数据 ───┼──→ │  拷贝1(DMA)  │    │              │    │          │
│          │    │     │        │    │              │    │          │
│          │    │     │描述符   │    │  拷贝2(仅    │    │          │
│          │    │     └────────┼──→ │  位置/长度)  │──→ │ 拷贝3(DMA)│
│          │    │              │    │              │    │          │
└──────────┘    └──────────────┘    └──────────────┘    └──────────┘

拷贝1: 磁盘 → 内核Page Cache（DMA）
拷贝2: Page Cache → Socket缓冲区（仅拷贝描述符，不是数据！）
拷贝3: Socket缓冲区描述符 → 网卡直接从Page Cache DMA读取
```

**关键**：支持scatter-gather的网卡可以直接从Page Cache读取数据，不需要将数据拷贝到Socket缓冲区。此时只有1次CPU拷贝（描述符信息），实际数据0次CPU拷贝。

**2次上下文切换**：

```
用户态 → 内核态（sendfile系统调用）
内核态 → 用户态（sendfile返回）
```

**sendfile的限制**：

| 限制 | 说明 |
|------|------|
| in_fd必须是文件 | 不能是socket或pipe |
| out_fd必须是socket | Linux 2.6.33之前，之后可以是任意文件 |
| 不能对数据进行修改 | 数据不经过用户态，无法加密/压缩 |
| 不适合小文件 | 系统调用开销可能超过拷贝节省 |

#### 3. splice原理

```c
// splice方式
ssize_t splice(int fd_in, loff_t *off_in, int fd_out, loff_t *off_out,
               size_t len, unsigned int flags);
```

**0次CPU拷贝**：

```
┌──────────┐    ┌──────────────┐    ┌──────────────┐    ┌──────────┐
│   管道     │    │ 内核Pipe     │    │ 内核Socket   │    │  网卡     │
│   读端    │    │ Buffer       │    │ 缓冲区       │    │          │
│          │    │              │    │              │    │          │
│  数据 ───┼──→ │  拷贝1(DMA)  │    │              │    │          │
│          │    │     │        │    │              │    │          │
│          │    │     └────────┼──→ │  描述符      │──→ │ 拷贝2(DMA)│
│          │    │              │    │              │    │          │
└──────────┘    └──────────────┘    └──────────────┘    └──────────┘
```

**splice的特点**：

| 特点 | 说明 |
|------|------|
| 零CPU拷贝 | 数据只在内核态移动，通过管道缓冲区传递 |
| 至少一端是管道 | fd_in或fd_out必须有一个是pipe |
| 灵活 | 可以实现socket到socket的零拷贝转发 |

**splice实现代理服务器**：

```c
// 代理服务器核心：客户端socket ↔ 服务器socket
int pipefd[2];
pipe(pipefd);

// 客户端数据 → 管道
splice(client_fd, NULL, pipefd[1], NULL, len, SPLICE_F_MOVE);
// 管道 → 服务器socket
splice(pipefd[0], NULL, server_fd, NULL, len, SPLICE_F_MOVE);
```

#### 4. mmap原理

```c
// mmap方式
void *mmap(void *addr, size_t length, int prot, int flags,
           int fd, off_t offset);
```

**原理**：将文件映射到用户态内存地址空间，访问该内存等于访问文件。

```
┌──────────┐    ┌──────────────┐    ┌──────────┐
│   磁盘    │    │ 内核Page     │    │ 用户      │
│   文件    │    │ Cache        │    │ 映射区    │
│          │    │              │    │          │
│  数据 ───┼──→ │  拷贝1(DMA)  │    │          │
│          │    │     ↕        │    │   ↕      │
│          │    │  共享同一块   │←──→│  物理内存  │
│          │    │  物理内存    │    │          │
└──────────┘    └──────────────┘    └──────────┘

mmap后：用户态和内核态共享同一块物理内存
读文件 = 直接读映射区（不需要read系统调用）
write到socket = 从映射区write（仍需1次CPU拷贝）
```

**mmap的拷贝次数**：

| 操作 | CPU拷贝 | DMA拷贝 | 上下文切换 |
|------|---------|---------|-----------|
| mmap + write | 1次 | 2次 | 2次 |
| 传统read + write | 2次 | 2次 | 4次 |

**mmap的优势**：

| 优势 | 说明 |
|------|------|
| 减少一次CPU拷贝 | 不需要从内核拷贝到用户态 |
| 随机访问高效 | 像访问内存一样访问文件 |
| 多进程共享 | 同一文件映射可被多进程共享 |

**mmap的局限**：

| 局限 | 说明 |
|------|------|
| 映射开销 | 建立映射需要修改页表，有TLB flush开销 |
| 信号处理 | 访问不存在的映射会触发SIGBUS |
| 大小限制 | 32位系统地址空间有限 |
| 不适合小文件 | 映射开销可能超过收益 |

#### 5. MSG_ZEROCOPY

Linux 4.14引入，真正的零拷贝发送：

```c
// MSG_ZEROCOPY方式
send(socket_fd, buf, len, MSG_ZEROCOPY);
```

**原理**：

```
传统send:  用户缓冲区 → 内核Socket缓冲区 → 网卡（CPU拷贝）
MSG_ZEROCOPY: 用户缓冲区 ──────────────────→ 网卡（DMA直接读取用户内存）
```

**使用方式**：

```c
// 1. 设置socket选项启用零拷贝
int optval = 1;
setsockopt(socket_fd, SOL_SOCKET, SO_ZEROCOPY, &optval, sizeof(optval));

// 2. 发送时使用MSG_ZEROCOPY标志
ssize_t ret = send(socket_fd, data, len, MSG_ZEROCOPY);

// 3. 等待内核通知完成（数据已发送，缓冲区可释放）
// 通过socket的错误队列接收完成通知
struct msghdr msg;
recvmsg(socket_fd, &msg, MSG_ERRQUEUE);
```

**MSG_ZEROCOPY的限制**：

| 限制 | 说明 |
|------|------|
| 内核版本 | 需要4.14+ |
| 网卡支持 | 需要支持scatter-gather的网卡 |
| 缓冲区不可修改 | 发送完成前不能修改数据 |
| 完成通知 | 需要额外处理完成通知 |
| 大数据才划算 | 小包（<10KB）开销可能更大 |

#### 6. 各方案对比

| 方案 | CPU拷贝 | DMA拷贝 | 上下文切换 | 适用场景 |
|------|---------|---------|-----------|---------|
| read+write | 2 | 2 | 4 | 通用 |
| mmap+write | 1 | 2 | 2 | 随机访问大文件 |
| sendfile | 0~1 | 2 | 2 | 文件到socket |
| splice | 0 | 2 | 2 | socket到socket |
| MSG_ZEROCOPY | 0 | 1 | 1 | 大块数据发送 |

### 3. 代码示例

#### 1. 传统方式 vs sendfile

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <fcntl.h>
#include <sys/socket.h>
#include <netinet/in.h>
#include <sys/sendfile.h>
#include <time.h>

#define PORT         8080
#define FILE_PATH    "large_file.dat"
#define BUF_SIZE     8192

// 传统方式：read + write
void transfer_traditional(int client_fd, int file_fd, off_t file_size) {
    char buf[BUF_SIZE];
    ssize_t n;

    while ((n = read(file_fd, buf, BUF_SIZE)) > 0) {
        ssize_t written = 0;
        while (written < n) {
            ssize_t w = write(client_fd, buf + written, n - written);
            if (w <= 0) break;
            written += w;
        }
    }
}

// sendfile方式
void transfer_sendfile(int client_fd, int file_fd, off_t file_size) {
    off_t offset = 0;
    while (offset < file_size) {
        // sendfile: 内核直接传输，数据不经过用户态
        ssize_t sent = sendfile(client_fd, file_fd, &offset, file_size - offset);
        if (sent <= 0) break;
    }
}

int main(void) {
    // 创建测试文件
    int file_fd = open(FILE_PATH, O_RDONLY);
    if (file_fd < 0) {
        // 如果文件不存在，创建一个
        file_fd = open(FILE_PATH, O_CREAT | O_WRONLY | O_TRUNC, 0644);
        char buf[BUF_SIZE];
        memset(buf, 'A', BUF_SIZE);
        for (int i = 0; i < 1000; i++) {  // ~8MB文件
            write(file_fd, buf, BUF_SIZE);
        }
        close(file_fd);
        file_fd = open(FILE_PATH, O_RDONLY);
    }

    off_t file_size = lseek(file_fd, 0, SEEK_END);
    lseek(file_fd, 0, SEEK_SET);
    printf("文件大小: %ld 字节\n", (long)file_size);

    int listen_fd = socket(AF_INET, SOCK_STREAM, 0);
    int opt = 1;
    setsockopt(listen_fd, SOL_SOCKET, SO_REUSEADDR, &opt, sizeof(opt));

    struct sockaddr_in addr = {
        .sin_family = AF_INET,
        .sin_addr.s_addr = INADDR_ANY,
        .sin_port = htons(PORT)
    };
    bind(listen_fd, (struct sockaddr*)&addr, sizeof(addr));
    listen(listen_fd, 5);

    printf("服务器启动，端口: %d\n", PORT);

    while (1) {
        int client_fd = accept(listen_fd, NULL, NULL);
        if (client_fd < 0) continue;

        // 接收客户端选择的方式
        char mode;
        read(client_fd, &mode, 1);

        struct timespec start, end;
        clock_gettime(CLOCK_MONOTONIC, &start);

        if (mode == '0') {
            // 传统方式
            lseek(file_fd, 0, SEEK_SET);
            transfer_traditional(client_fd, file_fd, file_size);
        } else {
            // sendfile方式
            lseek(file_fd, 0, SEEK_SET);
            transfer_sendfile(client_fd, file_fd, file_size);
        }

        clock_gettime(CLOCK_MONOTONIC, &end);
        double elapsed = (end.tv_sec - start.tv_sec) +
                        (end.tv_nsec - start.tv_nsec) / 1e9;
        printf("传输完成，模式=%c，耗时=%.3f秒\n", mode, elapsed);

        close(client_fd);
    }

    close(file_fd);
    close(listen_fd);
    return 0;
}
```

#### 2. mmap文件访问

```cpp
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <fcntl.h>
#include <unistd.h>
#include <sys/mman.h>
#include <sys/stat.h>

int main(int argc, char* argv[]) {
    const char* filepath = "test_file.dat";

    // 创建测试文件
    int fd = open(filepath, O_RDWR | O_CREAT | O_TRUNC, 0644);
    const char* msg = "Hello, mmap! 这是通过内存映射写入的数据。";
    write(fd, msg, strlen(msg));

    // 获取文件大小
    struct stat st;
    fstat(fd, &st);
    size_t size = st.st_size;

    // mmap映射文件到内存
    void* mapped = mmap(NULL, size, PROT_READ | PROT_WRITE,
                        MAP_SHARED, fd, 0);
    if (mapped == MAP_FAILED) {
        perror("mmap");
        close(fd);
        return 1;
    }

    // 像访问内存一样访问文件
    printf("文件内容: %s\n", (char*)mapped);

    // 修改映射区 = 修改文件（MAP_SHARED时）
    char* data = (char*)mapped;
    data[0] = 'h';  // 修改第一个字符
    printf("修改后: %s\n", data);

    // 解除映射
    munmap(mapped, size);
    close(fd);

    // 验证文件已被修改
    fd = open(filepath, O_RDONLY);
    char buf[256];
    int n = read(fd, buf, sizeof(buf) - 1);
    buf[n] = '\0';
    printf("文件验证: %s\n", buf);
    close(fd);

    return 0;
}
```

#### 3. splice实现数据转发

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <fcntl.h>
#include <sys/socket.h>
#include <netinet/in.h>
#include <errno.h>

#define PORT         8080
#define BUF_SIZE     65536

// 使用splice实现零拷贝转发
int splice_transfer(int from_fd, int to_fd) {
    int pipefd[2];
    if (pipe(pipefd) < 0) {
        perror("pipe");
        return -1;
    }

    int total = 0;
    while (1) {
        // from_fd → 管道写端（零拷贝）
        int n = splice(from_fd, NULL, pipefd[1], NULL, BUF_SIZE,
                      SPLICE_F_MOVE | SPLICE_F_NONBLOCK);
        if (n <= 0) {
            if (n == 0) break;  // EOF
            if (errno == EAGAIN || errno == EWOULDBLOCK) break;
            perror("splice read");
            break;
        }

        // 管道读端 → to_fd（零拷贝）
        int remaining = n;
        while (remaining > 0) {
            int w = splice(pipefd[0], NULL, to_fd, NULL, remaining,
                          SPLICE_F_MOVE);
            if (w <= 0) {
                perror("splice write");
                break;
            }
            remaining -= w;
            total += w;
        }
    }

    close(pipefd[0]);
    close(pipefd[1]);
    return total;
}

int main(void) {
    int listen_fd = socket(AF_INET, SOCK_STREAM, 0);
    int opt = 1;
    setsockopt(listen_fd, SOL_SOCKET, SO_REUSEADDR, &opt, sizeof(opt));

    struct sockaddr_in addr = {
        .sin_family = AF_INET,
        .sin_addr.s_addr = INADDR_ANY,
        .sin_port = htons(PORT)
    };
    bind(listen_fd, (struct sockaddr*)&addr, sizeof(addr));
    listen(listen_fd, 5);

    printf("splice转发服务器启动，端口: %d\n", PORT);

    while (1) {
        int client_fd = accept(listen_fd, NULL, NULL);
        if (client_fd < 0) continue;

        printf("新连接，使用splice零拷贝转发\n");
        int total = splice_transfer(client_fd, client_fd);  // 回显
        printf("转发完成，共%d字节\n", total);

        close(client_fd);
    }

    close(listen_fd);
    return 0;
}
```

#### 4. MSG_ZEROCOPY示例

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <fcntl.h>
#include <sys/socket.h>
#include <netinet/in.h>
#include <errno.h>

#define PORT         8080
#define DATA_SIZE    (1 << 20)  // 1MB数据

int main(void) {
    int sock_fd = socket(AF_INET, SOCK_STREAM, 0);

    // 启用零拷贝
    int optval = 1;
    if (setsockopt(sock_fd, SOL_SOCKET, SO_ZEROCOPY,
                   &optval, sizeof(optval)) < 0) {
        perror("setsockopt SO_ZEROCOPY");
        printf("当前内核不支持MSG_ZEROCOPY，需要4.14+\n");
        close(sock_fd);
        return 1;
    }

    struct sockaddr_in addr = {
        .sin_family = AF_INET,
        .sin_addr.s_addr = htonl(INADDR_LOOPBACK),
        .sin_port = htons(PORT)
    };

    if (connect(sock_fd, (struct sockaddr*)&addr, sizeof(addr)) < 0) {
        perror("connect");
        close(sock_fd);
        return 1;
    }

    // 分配并发送数据
    char* data = aligned_alloc(4096, DATA_SIZE);  // 页对齐
    memset(data, 'X', DATA_SIZE);

    // 使用MSG_ZEROCOPY发送
    ssize_t sent = send(sock_fd, data, DATA_SIZE, MSG_ZEROCOPY);
    if (sent < 0) {
        perror("send MSG_ZEROCOPY");
    } else {
        printf("MSG_ZEROCOPY发送: %zd 字节\n", sent);
    }

    // 等待完成通知（重要！发送完成前不能修改data）
    struct msghdr msg = {0};
    char cbuf[CMSG_SPACE(sizeof(struct sock_extended_err))];
    msg.msg_control = cbuf;
    msg.msg_controllen = sizeof(cbuf);

    // 从错误队列读取完成通知
    if (recvmsg(sock_fd, &msg, MSG_ERRQUEUE) < 0) {
        perror("recvmsg");
    } else {
        printf("零拷贝传输完成通知已收到\n");
    }

    // 现在可以安全释放data了
    free(data);
    close(sock_fd);
    return 0;
}
```

***

### 4. 零拷贝的局限

| 局限 | 说明 |
|------|------|
| 不能修改数据 | 数据不经过用户态，无法加密/压缩/转换 |
| 硬件依赖 | scatter-gather需要网卡支持 |
| 内核版本 | MSG_ZEROCOPY需要4.14+，io_uring需要5.1+ |
| 小数据不划算 | 系统调用和映射开销可能超过拷贝开销 |
| 调试困难 | 数据不经过用户态，难以用常规手段检查 |

**何时不用零拷贝**：

- 需要对数据进行加工（加密、压缩、格式转换）
- 数据量很小（<4KB）
- 需要检查或修改数据内容
- 跨平台兼容性要求高

### 5. 总结

零拷贝的核心思想是**让数据尽量少地在内存中搬来搬去**。从read+write的4次拷贝，到sendfile的2次拷贝，到splice的0次CPU拷贝，再到MSG_ZEROCOPY的真正零拷贝——每一步优化都在减少CPU参与和内存带宽消耗。选择哪种方案取决于你的场景：静态文件服务用sendfile，代理转发用splice，大数据发送用MSG_ZEROCOPY，需要修改数据就用mmap。
