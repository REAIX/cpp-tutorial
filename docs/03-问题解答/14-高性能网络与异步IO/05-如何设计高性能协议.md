### 1. 通俗理解

- **协议** = 通信双方约定的数据格式和交互规则
- 高性能协议的核心：解析快、传输小、扩展易、兼容好
- 就像两个人对话：用什么语言（编码）、怎么断句（定帧）、怎么理解新词（版本化）

| 概念 | 类比 | 说明 |
|------|------|------|
| 二进制协议 | 摩斯密码 | 紧凑高效，但人不可读 |
| 文本协议 | 英语 | 可读性好，但冗余多 |
| 帧格式 | 信封格式 | 怎么区分一条完整消息 |
| TLV | 类型-长度-值 | 灵活的消息编码方式 |
| 版本化 | 字典版本 | 新旧版本如何兼容 |

### 2. 技术说明

#### 1. 二进制 vs 文本协议

| 维度 | 二进制协议 | 文本协议 |
|------|-----------|---------|
| 体积 | 小（1-5字节/字段） | 大（5-20字节/字段） |
| 解析速度 | 快（直接内存映射） | 慢（需要字符串解析） |
| 可读性 | 差（需要工具） | 好（直接看） |
| 调试 | 需要协议分析器 | 直接看文本 |
| 扩展性 | 需要设计 | 天然灵活 |
| 代表 | Protobuf、FlatBuffers | HTTP/1.1、Redis协议 |

**性能对比**：

```
编码1万个整数(0-9999)：
  文本(JSON):     ~50KB，解析 ~500μs
  二进制(Protobuf): ~25KB，解析 ~50μs
  二进制(FlatBuffers): ~20KB，解析 ~5μs（零解析）
```

**什么时候用文本协议**：

- 调试阶段（快速验证逻辑）
- 内部工具（不需要极致性能）
- REST API（兼容性优先）
- 人机交互场景

**什么时候必须用二进制协议**：

- 高频交易（微秒级延迟）
- 游戏服务器（大量实时消息）
- IoT设备（带宽受限）
- 微服务间RPC（吞吐量优先）

#### 2. 帧格式设计

**为什么需要定帧**：

TCP是字节流协议，没有消息边界。发送"Hello""World"可能被接收为"HelloWorld"或"Hel""loWorld"——必须定义消息边界。

**方案1：定长帧**

```
┌──────────────────────────────┐
│       固定长度 = 64字节       │
│  不足部分用0填充              │
└──────────────────────────────┘
```

| 优点 | 缺点 |
|------|------|
| 实现最简单 | 浪费带宽 |
| 不需要解析 | 长度不可变 |
| 随机访问 | 不灵活 |

**方案2：分隔符定帧**

```
┌─────────────────┬───┬─────────────────┬───┐
│    消息1         │ \n│    消息2         │ \n│
└─────────────────┴───┴─────────────────┴───┘
```

| 优点 | 缺点 |
|------|------|
| 简单直观 | 需要转义分隔符 |
| 文本友好 | 二进制数据不适用 |
| Redis协议用此方式 | 需要逐字节扫描 |

**方案3：长度前缀（最常用）**

```
┌──────────┬───────────────────────────────┐
│ 长度字段  │         消息体                │
│ (4字节)  │      (N字节)                  │
└──────────┴───────────────────────────────┘
```

| 优点 | 缺点 |
|------|------|
| 高效（直接读长度） | 需要处理长度字段本身的粘包 |
| 支持变长消息 | 长度字段大小需权衡 |
| 二进制友好 | 需要字节序约定 |

**方案4：TLV（Type-Length-Value）**

```
┌──────────┬──────────┬───────────────────┐
│  Type    │  Length  │      Value        │
│ (1-4字节)│ (1-4字节)│    (N字节)        │
└──────────┴──────────┴───────────────────┘

消息示例：
┌──────┬──────┬──────────────────────────────────┐
│ 0x01 │ 0x08 │ "username"                        │  ← 字段1: 用户名
│ 0x02 │ 0x04 │ 0x00000064                        │  ← 字段2: 年龄(100)
│ 0x03 │ 0x0C │ "hello world!"                    │  ← 字段3: 消息
└──────┴──────┴──────────────────────────────────┘
```

| 优点 | 缺点 |
|------|------|
| 字段可跳过（按Length跳） | 每个字段有额外开销 |
| 字段顺序无关 | 解析需要多次间接寻址 |
| 可扩展（新Type） | 实现稍复杂 |
| 支持可选字段 | - |

**推荐的帧格式设计**：

```
┌──────────┬──────────┬──────────┬───────────────────────────┐
│  Magic   │ Version  │  Length  │       Payload             │
│ (2字节)  │ (2字节)   │ (4字节)  │       (N字节)             │
│  0xABCD  │  0x0001  │  网络序  │   TLV编码的消息体          │
└──────────┴──────────┴──────────┴───────────────────────────┘
```

- **Magic**：快速识别协议，防止误读
- **Version**：版本号，支持协议升级
- **Length**：Payload长度，网络字节序（大端）
- **Payload**：TLV编码的消息体

#### 3. 版本化与兼容性

**版本化策略**：

| 策略 | 说明 | 优点 | 缺点 |
|------|------|------|------|
| 字段编号 | 每个字段有唯一编号 | 新增字段不影响旧版本 | 需要维护编号分配 |
| 版本号 | 消息头带版本号 | 明确的版本管理 | 版本间可能不兼容 |
| 可选字段 | 新字段标记为可选 | 向前兼容 | 旧代码忽略新字段 |
| 默认值 | 新字段有默认值 | 旧消息仍可解析 | 需要合理的默认值 |

**Protobuf的兼容性设计**：

```protobuf
message Person {
    int32 id = 1;          // 字段编号1
    string name = 2;       // 字段编号2
    // 新增字段：旧代码会忽略
    string email = 3;      // 字段编号3
    // 删除字段：编号不能复用！
    reserved 4;            // 保留编号4，防止复用
}
```

**兼容性铁律**：

| 规则 | 说明 |
|------|------|
| 字段编号不能改 | 一旦分配，不能修改 |
| 删除字段用reserved | 防止编号被复用 |
| 新增字段用新编号 | 旧代码自动忽略 |
| 不能修改字段类型 | int32不能改成string |
| 不能修改字段编号 | 2就是2，不能改成3 |

#### 4. Protobuf vs FlatBuffers

| 维度 | Protobuf | FlatBuffers |
|------|----------|-------------|
| 解析方式 | 需要反序列化 | 零拷贝直接访问 |
| 解析速度 | 快（~50μs/1万字段） | 极快（~5μs/1万字段） |
| 编码大小 | 小（变长编码） | 较大（偏移量表） |
| 修改数据 | 反序列化→修改→序列化 | 可以原地修改 |
| 前向兼容 | 好 | 好 |
| 语言支持 | 20+ | 10+ |
| 使用复杂度 | 低 | 中 |
| 适用场景 | RPC、存储 | 游戏、实时系统 |

**Protobuf编码原理**：

```
字段编码 = (字段编号 << 3) | 类型

例如：int32 id = 1; 值为150
编码：0x08 0x96 0x01
  0x08 = (1 << 3) | 0 (varint类型)
  0x96 0x01 = 150的varint编码

varint编码：小数字用更少字节
  1 → 0x01 (1字节)
  300 → 0xAC 0x02 (2字节)
  100000 → 0xC0 0x8D 0x06 (3字节)
```

**FlatBuffers编码原理**：

```
┌──────────────────────────────────────────┐
│             FlatBuffer 结构               │
│                                          │
│  ┌──────────┐                            │
│  │ 根表偏移  │ ──→ ┌──────────┐          │
│  └──────────┘     │ 字段偏移表│          │
│                   │ [0] ──→ "hello"      │
│                   │ [1] ──→ 42           │
│                   │ [2] ──→ 子表偏移      │
│                   └──────────┘           │
│                                          │
│  访问路径：根偏移→字段偏移表→字段值        │
│  不需要解析！直接按偏移读取               │
└──────────────────────────────────────────┘
```

### 3. 代码示例

#### 1. 自定义二进制协议

```cpp
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <stdint.h>
#include <arpa/inet.h>

// 协议常量
constexpr uint16_t MAGIC = 0xABCD;
constexpr uint16_t VERSION = 0x0001;
constexpr size_t HEADER_SIZE = 8;  // magic(2) + version(2) + length(4)

// TLV类型定义
enum class FieldType : uint8_t {
    INT32   = 0x01,
    INT64   = 0x02,
    STRING  = 0x03,
    FLOAT   = 0x04,
    BOOL    = 0x05,
    BINARY  = 0x06,
};

// TLV字段
struct TLVField {
    FieldType type;
    uint16_t length;  // 值的长度
    const void* value;
};

// 消息头
struct MessageHeader {
    uint16_t magic;
    uint16_t version;
    uint32_t length;  // payload长度
};

// 编码TLV字段到缓冲区，返回写入的字节数
static size_t encode_tlv(uint8_t* buf, const TLVField& field) {
    size_t offset = 0;

    // Type (1字节)
    buf[offset++] = static_cast<uint8_t>(field.type);

    // Length (2字节，大端)
    uint16_t len_be = htons(field.length);
    memcpy(buf + offset, &len_be, 2);
    offset += 2;

    // Value
    memcpy(buf + offset, field.value, field.length);
    offset += field.length;

    return offset;
}

// 解码TLV字段
static size_t decode_tlv(const uint8_t* buf, size_t buf_len, TLVField& field) {
    if (buf_len < 3) return 0;  // 至少需要type(1)+length(2)

    size_t offset = 0;

    // Type
    field.type = static_cast<FieldType>(buf[offset++]);

    // Length
    uint16_t len_be;
    memcpy(&len_be, buf + offset, 2);
    field.length = ntohs(len_be);
    offset += 2;

    // Value
    if (offset + field.length > buf_len) return 0;
    field.value = buf + offset;
    offset += field.length;

    return offset;
}

// 编码完整消息
static size_t encode_message(uint8_t* buf, size_t buf_size,
                              const TLVField* fields, int field_count) {
    // 计算payload大小
    size_t payload_size = 0;
    for (int i = 0; i < field_count; i++) {
        payload_size += 3 + fields[i].length;  // type(1) + length(2) + value
    }

    if (HEADER_SIZE + payload_size > buf_size) return 0;

    size_t offset = 0;

    // 写入消息头
    uint16_t magic_be = htons(MAGIC);
    memcpy(buf + offset, &magic_be, 2);
    offset += 2;

    uint16_t version_be = htons(VERSION);
    memcpy(buf + offset, &version_be, 2);
    offset += 2;

    uint32_t length_be = htonl(static_cast<uint32_t>(payload_size));
    memcpy(buf + offset, &length_be, 4);
    offset += 4;

    // 写入TLV字段
    for (int i = 0; i < field_count; i++) {
        offset += encode_tlv(buf + offset, fields[i]);
    }

    return offset;
}

// 解码消息头
static bool decode_header(const uint8_t* buf, size_t buf_len, MessageHeader& header) {
    if (buf_len < HEADER_SIZE) return false;

    uint16_t magic_be;
    memcpy(&magic_be, buf, 2);
    header.magic = ntohs(magic_be);

    uint16_t version_be;
    memcpy(&version_be, buf + 2, 2);
    header.version = ntohs(version_be);

    uint32_t length_be;
    memcpy(&length_be, buf + 4, 4);
    header.length = ntohl(length_be);

    return header.magic == MAGIC;
}

// 使用示例
int main(void) {
    // 准备数据
    int32_t user_id = 42;
    const char* username = "张三";
    float score = 95.5f;
    bool is_vip = true;

    TLVField fields[] = {
        {FieldType::INT32,  sizeof(int32_t), &user_id},
        {FieldType::STRING, (uint16_t)strlen(username), username},
        {FieldType::FLOAT,  sizeof(float), &score},
        {FieldType::BOOL,   1, &is_vip},
    };

    // 编码
    uint8_t send_buf[1024];
    size_t msg_len = encode_message(send_buf, sizeof(send_buf),
                                     fields, 4);
    printf("编码消息: %zu字节\n", msg_len);

    // 解码
    MessageHeader header;
    if (!decode_header(send_buf, msg_len, header)) {
        printf("无效消息!\n");
        return 1;
    }
    printf("Magic: 0x%04X, Version: %d, Length: %u\n",
           header.magic, header.version, header.length);

    // 解码TLV字段
    const uint8_t* payload = send_buf + HEADER_SIZE;
    size_t payload_len = header.length;
    size_t offset = 0;

    while (offset < payload_len) {
        TLVField field;
        size_t consumed = decode_tlv(payload + offset,
                                      payload_len - offset, field);
        if (consumed == 0) break;

        switch (field.type) {
            case FieldType::INT32: {
                int32_t val;
                memcpy(&val, field.value, sizeof(val));
                printf("  INT32: %d\n", val);
                break;
            }
            case FieldType::STRING: {
                char str[256];
                size_t copy_len = field.length < 255 ? field.length : 255;
                memcpy(str, field.value, copy_len);
                str[copy_len] = '\0';
                printf("  STRING: %s\n", str);
                break;
            }
            case FieldType::FLOAT: {
                float val;
                memcpy(&val, field.value, sizeof(val));
                printf("  FLOAT: %.1f\n", val);
                break;
            }
            case FieldType::BOOL: {
                bool val;
                memcpy(&val, field.value, 1);
                printf("  BOOL: %s\n", val ? "true" : "false");
                break;
            }
            default:
                printf("  未知类型: 0x%02X\n", (uint8_t)field.type);
        }

        offset += consumed;
    }

    return 0;
}
```

#### 2. 基于长度前缀的帧解码器

```cpp
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <stdint.h>
#include <vector>
#include <arpa/inet.h>

// 帧解码器：处理TCP粘包/拆包
class FrameDecoder {
public:
    // 输入新数据，返回完整的帧列表
    std::vector<std::vector<uint8_t>> feed(const uint8_t* data, size_t len) {
        std::vector<std::vector<uint8_t>> frames;

        // 将新数据追加到缓冲区
        buffer_.insert(buffer_.end(), data, data + len);

        // 尝试从缓冲区中提取完整帧
        while (buffer_.size() >= 4) {
            // 读取长度字段（4字节，大端）
            uint32_t frame_len;
            memcpy(&frame_len, buffer_.data(), 4);
            frame_len = ntohl(frame_len);

            // 安全检查：防止恶意大帧
            if (frame_len > MAX_FRAME_SIZE) {
                printf("帧过大: %u字节，断开连接\n", frame_len);
                buffer_.clear();
                break;
            }

            // 检查是否收到完整帧
            size_t total_len = 4 + frame_len;
            if (buffer_.size() < total_len) break;  // 数据不完整，等待更多

            // 提取完整帧
            frames.emplace_back(buffer_.begin() + 4,
                               buffer_.begin() + total_len);

            // 从缓冲区移除已处理的帧
            buffer_.erase(buffer_.begin(), buffer_.begin() + total_len);
        }

        return frames;
    }

private:
    static constexpr size_t MAX_FRAME_SIZE = 1024 * 1024;  // 1MB
    std::vector<uint8_t> buffer_;
};

// 帧编码器
class FrameEncoder {
public:
    // 将消息编码为带长度前缀的帧
    static std::vector<uint8_t> encode(const uint8_t* data, size_t len) {
        std::vector<uint8_t> frame;
        uint32_t len_be = htonl(static_cast<uint32_t>(len));
        frame.resize(4 + len);
        memcpy(frame.data(), &len_be, 4);
        memcpy(frame.data() + 4, data, len);
        return frame;
    }
};

int main(void) {
    FrameDecoder decoder;

    // 模拟TCP数据流：两条消息粘在一起
    const char* msg1 = "Hello";
    const char* msg2 = "World";

    auto frame1 = FrameEncoder::encode((const uint8_t*)msg1, strlen(msg1));
    auto frame2 = FrameEncoder::encode((const uint8_t*)msg2, strlen(msg2));

    // 场景1：两条消息一起到达（粘包）
    std::vector<uint8_t> combined;
    combined.insert(combined.end(), frame1.begin(), frame1.end());
    combined.insert(combined.end(), frame2.begin(), frame2.end());

    auto results = decoder.feed(combined.data(), combined.size());
    printf("粘包场景: 收到%zu条完整消息\n", results.size());
    for (size_t i = 0; i < results.size(); i++) {
        printf("  消息%zu: %.*s\n", (unsigned)i,
               (int)results[i].size(), (char*)results[i].data());
    }

    // 场景2：一条消息分两次到达（拆包）
    FrameDecoder decoder2;
    auto partial1 = std::vector<uint8_t>(frame1.begin(), frame1.begin() + 4);
    auto partial2 = std::vector<uint8_t>(frame1.begin() + 4, frame1.end());

    auto r1 = decoder2.feed(partial1.data(), partial1.size());
    printf("拆包场景(第一片): %zu条消息\n", r1.size());

    auto r2 = decoder2.feed(partial2.data(), partial2.size());
    printf("拆包场景(第二片): %zu条消息\n", r2.size());
    if (!r2.empty()) {
        printf("  消息: %.*s\n", (int)r2[0].size(), (char*)r2[0].data());
    }

    return 0;
}
```

#### 3. Protobuf使用示例

```cpp
// person.proto
// syntax = "proto3";
// message Person {
//     int32 id = 1;
//     string name = 2;
//     string email = 3;
//     repeated string phones = 4;
// }

// 以下是概念性示例，展示Protobuf的使用方式

#include <stdio.h>
#include <string.h>
#include <string>
#include <vector>

// 模拟Protobuf的编码/解码（实际使用需安装protobuf库）
class PersonMessage {
public:
    int32_t id = 0;
    std::string name;
    std::string email;
    std::vector<std::string> phones;

    // 序列化（简化版，展示varint编码原理）
    std::vector<uint8_t> Serialize() const {
        std::vector<uint8_t> buf;

        // 字段1: id (varint编码)
        if (id != 0) {
            buf.push_back(0x08);  // (1 << 3) | 0 = varint
            encode_varint(buf, id);
        }

        // 字段2: name (长度前缀编码)
        if (!name.empty()) {
            buf.push_back(0x12);  // (2 << 3) | 2 = length-delimited
            encode_varint(buf, name.size());
            buf.insert(buf.end(), name.begin(), name.end());
        }

        // 字段3: email
        if (!email.empty()) {
            buf.push_back(0x1A);  // (3 << 3) | 2
            encode_varint(buf, email.size());
            buf.insert(buf.end(), email.begin(), email.end());
        }

        // 字段4: phones (repeated)
        for (const auto& phone : phones) {
            buf.push_back(0x22);  // (4 << 3) | 2
            encode_varint(buf, phone.size());
            buf.insert(buf.end(), phone.begin(), phone.end());
        }

        return buf;
    }

private:
    // varint编码：小数字用更少字节
    static void encode_varint(std::vector<uint8_t>& buf, uint64_t val) {
        while (val >= 0x80) {
            buf.push_back(static_cast<uint8_t>(val | 0x80));
            val >>= 7;
        }
        buf.push_back(static_cast<uint8_t>(val));
    }
};

int main(void) {
    PersonMessage person;
    person.id = 42;
    person.name = "张三";
    person.email = "zhangsan@example.com";
    person.phones = {"13800138000", "13900139000"};

    auto data = person.Serialize();
    printf("Protobuf编码: %zu字节\n", data.size());

    // 对比JSON编码
    const char* json = R"({"id":42,"name":"张三","email":"zhangsan@example.com","phones":["13800138000","13900139000"]})";
    printf("JSON编码: %zu字节\n", strlen(json));
    printf("Protobuf比JSON节省: %.0f%%\n",
           (1.0 - (double)data.size() / strlen(json)) * 100);

    return 0;
}
```

### 4. 常见问题

#### Q1：应该自己设计协议还是用Protobuf？

除非有特殊需求（如极致性能、极小体积），否则用Protobuf。它已经解决了编码、解码、版本化、跨语言等问题。

#### Q2：长度字段用几字节？

| 长度字段大小 | 最大消息长度 | 适用场景 |
|-------------|-------------|---------|
| 1字节 | 255B | IoT、嵌入式 |
| 2字节 | 64KB | 游戏消息 |
| 4字节 | 4GB | 通用（推荐） |
| 8字节 | 16EB | 文件传输 |

#### Q3：字节序怎么选？

网络协议统一用大端（网络字节序）。x86是小端，所以需要htonl/ntohl转换。Protobuf内部自己处理字节序，不需要手动转换。

#### Q4：如何处理协议升级？

1. 新增字段用新编号（Protobuf天然支持）
2. 旧字段不能删除，只能标记deprecated
3. 消息头带版本号，服务端根据版本选择解析逻辑
4. 灰度发布：先部署能理解新版本的接收端，再部署发送端

#### Q5：FlatBuffers什么时候用？

当你需要零拷贝访问数据时。典型场景：游戏客户端读取服务器下发的场景数据、实时系统中的消息传递。不需要修改数据、不需要频繁序列化的场景。

### 5. 总结

设计高性能协议的关键决策：

| 决策 | 推荐 | 原因 |
|------|------|------|
| 编码方式 | 二进制 | 体积小、解析快 |
| 定帧方式 | 长度前缀 | 高效、通用 |
| 字段编码 | TLV或Protobuf | 灵活、可扩展 |
| 版本化 | 字段编号 | 前后兼容 |
| 字节序 | 大端（网络序） | 统一标准 |
| 序列化库 | Protobuf（通用）/ FlatBuffers（零拷贝） | 成熟可靠 |

好的协议设计不是一蹴而就的，而是在实践中不断迭代。先用最简单的方案跑通，再根据实际瓶颈优化。
