# 如何优雅关闭服务器
> 📖 相关章节：[网络编程](../../02-CPP/35-网络编程.md)、[IO多路复用](../../08-高性能网络与异步IO/01-IO多路复用深入.md)、[Reactor模式](../../08-高性能网络与异步IO/02-Reactor模式.md)

> "核心速览：优雅关闭=先停止接收新请求，再等现有请求处理完，最后超时强制关闭。不是直接拔电源，而是先存盘再关机。"

***

### 1. 通俗理解

- **优雅关闭** = 服务器在关闭时保证：正在处理的请求完成、数据不丢失、资源正确释放
- 与之相对的是**暴力关闭**：直接kill -9，可能导致数据丢失、连接中断
- 就像关电脑：优雅关闭是"点关机→保存文件→退出程序→断电"，暴力关闭是"直接拔电源"

| 概念 | 类比 | 说明 |
|------|------|------|
| 优雅关闭 | 点关机按钮 | 先保存再关机 |
| 暴力关闭 | 拔电源 | 数据可能丢失 |
| 连接排空 | 等客人吃完再关门 | 等现有请求处理完 |
| 超时强制 | 到点必须关门 | 等太久就强制断开 |
| 热更新 | 换班不关门 | 新老进程无缝切换 |
| 零宕机 | 客人感觉不到换班 | 用户无感知 |

### 2. 技术说明

#### 1. 优雅关闭的步骤

**标准流程**：

```
┌──────────────────────────────────────────────────────────┐
│                    优雅关闭流程                            │
│                                                          │
│  1. 收到关闭信号 (SIGTERM/SIGINT)                         │
│     │                                                    │
│     ▼                                                    │
│  2. 停止接受新连接                                        │
│     - 关闭监听fd                                          │
│     - 从epoll移除listen_fd                                │
│     - 健康检查返回不健康（从LB摘除）                       │
│     │                                                    │
│     ▼                                                    │
│  3. 通知现有连接即将关闭                                   │
│     - 发送"Connection: close"头                           │
│     - 或发送应用层关闭帧                                   │
│     │                                                    │
│     ▼                                                    │
│  4. 等待现有请求处理完成                                   │
│     - 设置超时（如30秒）                                   │
│     - 定期检查活跃连接数                                   │
│     │                                                    │
│     ▼                                                    │
│  5. 超时强制关闭                                          │
│     - 关闭超时的连接                                       │
│     - 释放所有资源                                         │
│     │                                                    │
│     ▼                                                    │
│  6. 保存状态、关闭日志、退出                               │
└──────────────────────────────────────────────────────────┘
```

**各阶段详解**：

| 阶段 | 操作 | 关键点 |
|------|------|--------|
| 1.信号处理 | 注册SIGTERM/SIGINT处理函数 | 不能在信号处理函数中做复杂操作 |
| 2.停止接受 | 关闭listen_fd | 从负载均衡器摘除 |
| 3.通知关闭 | 发送关闭提示 | 让客户端主动断开 |
| 4.等待排空 | 等待活跃连接归零 | 设置超时，不能无限等 |
| 5.强制关闭 | close所有fd | 超时后必须强制 |
| 6.清理退出 | 释放资源、刷日志 | 确保数据持久化 |

#### 2. 连接排空

**排空策略**：

| 策略 | 说明 | 适用场景 |
|------|------|---------|
| 被动等待 | 等客户端自己断开 | 长连接、WebSocket |
| 主动通知 | 发送关闭帧/头 | HTTP/1.1、WebSocket |
| 降低超时 | 缩短keepalive超时 | HTTP长连接 |
| 拒绝新请求 | 返回503/Retry-After | API服务 |

**HTTP连接排空**：

```
1. 停止接受新连接（关闭listen_fd）
2. 对新到达的请求，返回 Connection: close 头
3. 对正在处理的请求，正常完成后返回 Connection: close
4. 等待所有连接关闭或超时
```

**WebSocket连接排空**：

```
1. 发送Close帧（状态码1001=Going Away）
2. 等待对方回复Close帧
3. 关闭TCP连接
```

**数据库连接排空**：

```
1. 不再分配新连接
2. 等待正在使用的连接归还
3. 超时后强制关闭剩余连接
4. 关闭连接池
```

#### 3. 超时强制关闭

**为什么需要超时**：

| 场景 | 问题 |
|------|------|
| 客户端不响应 | 可能永远不断开 |
| 长事务未完成 | 数据库事务可能跑几分钟 |
| 死锁/挂起 | 进程卡住无法退出 |
| 资源泄漏 | 不关闭就释放不了 |

**超时设计**：

```
总超时 = 优雅等待超时 + 强制关闭超时

例如：
  优雅等待超时: 30秒（等请求处理完）
  强制关闭超时: 5秒（等资源释放）
  总超时: 35秒

如果35秒还没退出，外部看门狗kill -9
```

**超时分级**：

| 级别 | 超时 | 动作 |
|------|------|------|
| 第一级 | 10秒 | 停止接受新请求，开始排空 |
| 第二级 | 30秒 | 关闭空闲连接 |
| 第三级 | 60秒 | 强制关闭所有连接 |
| 第四级 | 90秒 | 外部kill -9（看门狗） |

#### 4. 热更新与零宕机

**热更新流程**：

```
┌─────────────────────────────────────────────────────────┐
│                   热更新流程                              │
│                                                         │
│  ┌──────────┐                                           │
│  │ 旧进程    │ ← 正在处理请求                             │
│  │ (PID 100)│                                           │
│  └────┬─────┘                                           │
│       │ 1. 启动新进程                                    │
│       ▼                                                 │
│  ┌──────────┐  ┌──────────┐                            │
│  │ 旧进程    │  │ 新进程    │                            │
│  │ (PID 100)│  │ (PID 200)│ ← 新进程启动，开始监听       │
│  └────┬─────┘  └──────────┘                            │
│       │ 2. 旧进程收到SIGUSR2                              │
│       ▼                                                 │
│  ┌──────────┐  ┌──────────┐                            │
│  │ 旧进程    │  │ 新进程    │                            │
│  │ 排空中... │  │ 接管流量  │ ← 新进程接管新连接          │
│  └────┬─────┘  └──────────┘                            │
│       │ 3. 旧进程排空完成                                 │
│       ▼                                                 │
│  ┌──────────┐  ┌──────────┐                            │
│  │ 旧进程    │  │ 新进程    │                            │
│  │ 退出      │  │ 独立运行  │ ← 旧进程退出               │
│  └──────────┘  └──────────┘                            │
└─────────────────────────────────────────────────────────┘
```

**零宕机的关键**：

| 关键点 | 说明 |
|--------|------|
| 共享监听端口 | SO_REUSEPORT让新旧进程同时监听 |
| 健康检查 | 新进程就绪后才从LB摘除旧进程 |
| 滚动更新 | 一次只更新一个实例 |
| 会话保持 | 长连接需要平滑迁移 |

**Nginx的热更新**：

```bash
# 1. 发送USR2信号，启动新master
kill -USR2 $(cat /var/run/nginx.pid)

# 2. 旧master重命名pid文件，新master创建新pid文件
# 此时新旧master同时运行

# 3. 发送WINCH信号，旧master优雅关闭worker
kill -WINCH $(cat /var/run/nginx.pid.oldbin)

# 4. 确认新worker正常后，退出旧master
kill -QUIT $(cat /var/run/nginx.pid.oldbin)
```

### 3. 代码示例

#### 1. 优雅关闭的信号处理

```cpp
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <signal.h>
#include <sys/socket.h>
#include <netinet/in.h>
#include <sys/epoll.h>
#include <errno.h>
#include <atomic>
#include <thread>
#include <chrono>
#include <set>

#define PORT          8080
#define MAX_EVENTS    1024
#define SHUTDOWN_TIMEOUT_SEC  30

// 全局状态
static std::atomic<bool> g_running{true};
static std::atomic<int> g_active_connections{0};
static int g_listen_fd = -1;
static int g_epfd = -1;

// 信号处理函数
void signal_handler(int sig) {
    printf("\n收到信号 %d，开始优雅关闭...\n", sig);
    g_running = false;

    // 第一步：关闭监听fd，不再接受新连接
    if (g_listen_fd >= 0) {
        close(g_listen_fd);
        g_listen_fd = -1;
        printf("[关闭] 已停止接受新连接\n");
    }
}

// 注册信号处理
void setup_signal_handlers() {
    struct sigaction sa;
    memset(&sa, 0, sizeof(sa));
    sa.sa_handler = signal_handler;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = 0;

    sigaction(SIGTERM, &sa, nullptr);  // kill命令默认信号
    sigaction(SIGINT, &sa, nullptr);   // Ctrl+C

    // 忽略SIGPIPE（防止写已关闭的连接导致进程退出）
    signal(SIGPIPE, SIG_IGN);
}

int main(void) {
    setup_signal_handlers();

    g_listen_fd = socket(AF_INET, SOCK_STREAM | SOCK_NONBLOCK, 0);
    int opt = 1;
    setsockopt(g_listen_fd, SOL_SOCKET, SO_REUSEADDR, &opt, sizeof(opt));
    setsockopt(g_listen_fd, SOL_SOCKET, SO_REUSEPORT, &opt, sizeof(opt));

    struct sockaddr_in addr = {
        .sin_family = AF_INET,
        .sin_addr.s_addr = INADDR_ANY,
        .sin_port = htons(PORT)
    };
    bind(g_listen_fd, (struct sockaddr*)&addr, sizeof(addr));
    listen(g_listen_fd, 512);

    g_epfd = epoll_create1(0);

    struct epoll_event ev;
    ev.events = EPOLLIN | EPOLLET;
    ev.data.fd = g_listen_fd;
    epoll_ctl(g_epfd, EPOLL_CTL_ADD, g_listen_fd, &ev);

    struct epoll_event* events = new epoll_event[MAX_EVENTS];
    std::set<int> client_fds;

    printf("服务器启动，端口: %d\n", PORT);
    printf("按Ctrl+C或kill %d触发优雅关闭\n", getpid());

    while (g_running) {
        int nfds = epoll_wait(g_epfd, events, MAX_EVENTS, 1000);

        for (int i = 0; i < nfds; i++) {
            if (events[i].data.fd == g_listen_fd && g_listen_fd >= 0) {
                // 接受新连接
                while (1) {
                    int client_fd = accept(g_listen_fd, NULL, NULL);
                    if (client_fd < 0) {
                        if (errno == EAGAIN || errno == EWOULDBLOCK) break;
                        break;
                    }
                    int flags = fcntl(client_fd, F_GETFL, 0);
                    fcntl(client_fd, F_SETFL, flags | O_NONBLOCK);

                    struct epoll_event cev;
                    cev.events = EPOLLIN | EPOLLET;
                    cev.data.fd = client_fd;
                    epoll_ctl(g_epfd, EPOLL_CTL_ADD, client_fd, &cev);
                    client_fds.insert(client_fd);
                    g_active_connections++;
                    printf("[连接] 新连接 fd=%d, 活跃连接=%d\n",
                           client_fd, g_active_connections.load());
                }
            } else {
                int fd = events[i].data.fd;
                char buf[256];

                while (1) {
                    int n = read(fd, buf, sizeof(buf));
                    if (n > 0) {
                        write(fd, buf, n);  // 回显
                    } else if (n == 0) {
                        // 连接关闭
                        close(fd);
                        epoll_ctl(g_epfd, EPOLL_CTL_DEL, fd, NULL);
                        client_fds.erase(fd);
                        g_active_connections--;
                        printf("[断开] fd=%d, 活跃连接=%d\n",
                               fd, g_active_connections.load());
                        break;
                    } else {
                        if (errno == EAGAIN || errno == EWOULDBLOCK) break;
                        close(fd);
                        epoll_ctl(g_epfd, EPOLL_CTL_DEL, fd, NULL);
                        client_fds.erase(fd);
                        g_active_connections--;
                        break;
                    }
                }
            }
        }
    }

    // ===== 优雅关闭阶段 =====
    printf("\n[关闭] 开始优雅关闭，等待活跃连接排空...\n");
    printf("[关闭] 当前活跃连接: %d\n", g_active_connections.load());

    // 第二步：等待现有连接处理完成
    auto shutdown_start = std::chrono::steady_clock::now();

    while (g_active_connections > 0) {
        auto elapsed = std::chrono::duration_cast<std::chrono::seconds>(
            std::chrono::steady_clock::now() - shutdown_start).count();

        if (elapsed >= SHUTDOWN_TIMEOUT_SEC) {
            printf("[关闭] 等待超时(%d秒)，强制关闭剩余连接\n",
                   SHUTDOWN_TIMEOUT_SEC);
            break;
        }

        printf("[关闭] 等待中... 活跃连接=%d, 已等待%lld秒\n",
               g_active_connections.load(), (long long)elapsed);

        // 继续处理现有连接的IO
        int nfds = epoll_wait(g_epfd, events, MAX_EVENTS, 1000);
        for (int i = 0; i < nfds; i++) {
            int fd = events[i].data.fd;
            char buf[256];
            while (1) {
                int n = read(fd, buf, sizeof(buf));
                if (n > 0) {
                    // 对即将关闭的连接，发送Connection: close提示
                    const char* close_hint = "Connection: close\r\n";
                    write(fd, buf, n);
                } else if (n == 0) {
                    close(fd);
                    epoll_ctl(g_epfd, EPOLL_CTL_DEL, fd, NULL);
                    client_fds.erase(fd);
                    g_active_connections--;
                    break;
                } else {
                    if (errno == EAGAIN || errno == EWOULDBLOCK) break;
                    close(fd);
                    epoll_ctl(g_epfd, EPOLL_CTL_DEL, fd, NULL);
                    client_fds.erase(fd);
                    g_active_connections--;
                    break;
                }
            }
        }
    }

    // 第三步：强制关闭所有剩余连接
    for (int fd : client_fds) {
        printf("[关闭] 强制关闭 fd=%d\n", fd);
        close(fd);
    }
    client_fds.clear();

    // 第四步：清理资源
    delete[] events;
    close(g_epfd);

    printf("[关闭] 服务器已优雅关闭\n");
    return 0;
}
```

#### 2. 带超时分级的优雅关闭

```cpp
#include <stdio.h>
#include <stdlib.h>
#include <signal.h>
#include <unistd.h>
#include <sys/socket.h>
#include <netinet/in.h>
#include <sys/epoll.h>
#include <errno.h>
#include <atomic>
#include <chrono>
#include <vector>
#include <functional>

// 关闭阶段
enum class ShutdownPhase {
    RUNNING,           // 正常运行
    DRAINING,          // 排空中（不接受新连接）
    FORCE_CLOSING,     // 强制关闭中
    TERMINATED         // 已终止
};

class GracefulServer {
public:
    GracefulServer(int port) : port_(port), phase_(ShutdownPhase::RUNNING) {}

    void run() {
        setupSignals();
        initServer();

        while (phase_ != ShutdownPhase::TERMINATED) {
            switch (phase_) {
                case ShutdownPhase::RUNNING:
                    handleRunning();
                    break;
                case ShutdownPhase::DRAINING:
                    handleDraining();
                    break;
                case ShutdownPhase::FORCE_CLOSING:
                    handleForceClose();
                    break;
                default:
                    break;
            }
        }

        cleanup();
    }

private:
    void setupSignals() {
        struct sigaction sa;
        sa.sa_handler = [](int) {
            // 只设置标志，不做复杂操作
            // 实际项目中用self-pipe技巧
        };
        sigemptyset(&sa.sa_mask);
        sa.sa_flags = 0;
        sigaction(SIGTERM, &sa, nullptr);
        sigaction(SIGINT, &sa, nullptr);
        signal(SIGPIPE, SIG_IGN);
    }

    void initServer() {
        listen_fd_ = socket(AF_INET, SOCK_STREAM | SOCK_NONBLOCK, 0);
        int opt = 1;
        setsockopt(listen_fd_, SOL_SOCKET, SO_REUSEADDR, &opt, sizeof(opt));

        struct sockaddr_in addr = {
            .sin_family = AF_INET,
            .sin_addr.s_addr = INADDR_ANY,
            .sin_port = htons(port_)
        };
        bind(listen_fd_, (struct sockaddr*)&addr, sizeof(addr));
        listen(listen_fd_, 512);

        epfd_ = epoll_create1(0);
        struct epoll_event ev;
        ev.events = EPOLLIN;
        ev.data.fd = listen_fd_;
        epoll_ctl(epfd_, EPOLL_CTL_ADD, listen_fd_, &ev);

        printf("服务器启动，端口: %d\n", port_);
    }

    void handleRunning() {
        struct epoll_event events[1024];
        int nfds = epoll_wait(epfd_, events, 1024, 100);

        for (int i = 0; i < nfds; i++) {
            if (events[i].data.fd == listen_fd_) {
                acceptNewConnection();
            } else {
                handleClientData(events[i].data.fd);
            }
        }

        // 检查是否收到关闭信号（简化示例）
        // 实际项目中通过self-pipe或signalfd
    }

    void handleDraining() {
        printf("[排空] 活跃连接: %d\n", active_count_.load());

        if (active_count_ == 0) {
            printf("[排空] 所有连接已关闭\n");
            phase_ = ShutdownPhase::TERMINATED;
            return;
        }

        auto elapsed = std::chrono::duration_cast<std::chrono::seconds>(
            std::chrono::steady_clock::now() - drain_start_).count();

        if (elapsed > DRAIN_TIMEOUT_SEC) {
            printf("[排空] 超时(%d秒)，进入强制关闭\n", DRAIN_TIMEOUT_SEC);
            phase_ = ShutdownPhase::FORCE_CLOSING;
            force_start_ = std::chrono::steady_clock::now();
            return;
        }

        // 继续处理现有连接
        struct epoll_event events[1024];
        int nfds = epoll_wait(epfd_, events, 1024, 100);
        for (int i = 0; i < nfds; i++) {
            handleClientData(events[i].data.fd);
        }
    }

    void handleForceClose() {
        printf("[强制关闭] 关闭所有剩余连接\n");

        // 关闭所有客户端连接
        for (int fd : client_fds_) {
            close(fd);
        }
        client_fds_.clear();
        active_count_ = 0;

        phase_ = ShutdownPhase::TERMINATED;
    }

    void cleanup() {
        close(epfd_);
        printf("[清理] 服务器已完全关闭\n");
    }

    void acceptNewConnection() {
        while (1) {
            int fd = accept(listen_fd_, NULL, NULL);
            if (fd < 0) {
                if (errno == EAGAIN || errno == EWOULDBLOCK) break;
                break;
            }
            int flags = fcntl(fd, F_GETFL, 0);
            fcntl(fd, F_SETFL, flags | O_NONBLOCK);

            struct epoll_event ev;
            ev.events = EPOLLIN;
            ev.data.fd = fd;
            epoll_ctl(epfd_, EPOLL_CTL_ADD, fd, &ev);
            client_fds_.push_back(fd);
            active_count_++;
        }
    }

    void handleClientData(int fd) {
        char buf[256];
        int n = read(fd, buf, sizeof(buf));
        if (n > 0) {
            write(fd, buf, n);
        } else {
            close(fd);
            epoll_ctl(epfd_, EPOLL_CTL_DEL, fd, NULL);
            client_fds_.erase(
                std::remove(client_fds_.begin(), client_fds_.end(), fd),
                client_fds_.end());
            active_count_--;
        }
    }

    // 触发优雅关闭
    void initiateShutdown() {
        printf("[关闭] 开始优雅关闭\n");
        phase_ = ShutdownPhase::DRAINING;
        drain_start_ = std::chrono::steady_clock::now();

        // 关闭监听fd
        epoll_ctl(epfd_, EPOLL_CTL_DEL, listen_fd_, NULL);
        close(listen_fd_);
        listen_fd_ = -1;
        printf("[关闭] 已停止接受新连接\n");
    }

    static constexpr int DRAIN_TIMEOUT_SEC = 30;

    int port_;
    int listen_fd_ = -1;
    int epfd_ = -1;
    std::atomic<ShutdownPhase> phase_;
    std::atomic<int> active_count_{0};
    std::vector<int> client_fds_;
    std::chrono::steady_clock::time_point drain_start_;
    std::chrono::steady_clock::time_point force_start_;
};

int main(void) {
    GracefulServer server(8080);
    server.run();
    return 0;
}
```

#### 3. 热更新示例

```bash
#!/bin/bash
# 热更新脚本：零宕机重启服务

OLD_PID=$(cat /var/run/myserver.pid)
echo "旧进程PID: $OLD_PID"

# 1. 启动新进程（共享监听端口）
echo "启动新进程..."
./myserver &
NEW_PID=$!
echo $NEW_PID > /var/run/myserver.pid.new
echo "新进程PID: $NEW_PID"

# 2. 等待新进程就绪
echo "等待新进程就绪..."
for i in $(seq 1 30); do
    if curl -s http://localhost:8080/health > /dev/null 2>&1; then
        echo "新进程就绪"
        break
    fi
    sleep 1
done

# 3. 通知旧进程优雅关闭
echo "通知旧进程优雅关闭..."
kill -SIGTERM $OLD_PID

# 4. 等待旧进程退出
echo "等待旧进程退出..."
for i in $(seq 1 60); do
    if ! kill -0 $OLD_PID 2>/dev/null; then
        echo "旧进程已退出"
        break
    fi
    if [ $i -eq 60 ]; then
        echo "旧进程超时，强制终止"
        kill -9 $OLD_PID
    fi
    sleep 1
done

# 5. 更新PID文件
mv /var/run/myserver.pid.new /var/run/myserver.pid
echo "热更新完成"
```

### 4. 常见问题

#### Q1：SIGKILL（kill -9）能被捕获吗？

不能。SIGKILL和SIGSTOP不能被捕获、阻塞或忽略。所以优雅关闭只能处理SIGTERM，对于SIGKILL只能靠外部机制（如事务日志）保证数据一致性。

#### Q2：优雅关闭要等多久？

取决于业务。HTTP服务通常10-30秒，数据库可能需要几分钟（等长事务完成），游戏服务器可能需要更久（等玩家主动下线）。关键是设置合理的超时。

#### Q3：如何确保数据不丢失？

1. 请求处理完成后再确认（ACK）
2. 使用WAL（预写日志），崩溃后可恢复
3. 关闭前刷盘（fsync）
4. 使用幂等操作，重试安全

#### Q4：Docker容器如何优雅关闭？

Docker发送SIGTERM后等待`--stop-timeout`（默认10秒），超时后发送SIGKILL。确保应用正确处理SIGTERM，并设置合理的stop-timeout。

#### Q5：K8s中如何实现零宕机？

1. 配置`terminationGracePeriodSeconds`（默认30秒）
2. 设置`preStop`钩子（等待LB摘除）
3. 配置readinessProbe（新Pod就绪后才接流量）
4. 使用滚动更新策略（`maxUnavailable: 0`）

### 5. 总结

优雅关闭不是锦上添花，而是生产级服务的**必备能力**。核心步骤：停接受→等排空→超时强制→清理退出。热更新则在此基础上实现零宕机：新旧进程共存→流量切换→旧进程优雅退出。记住：**永远不要依赖kill -9之外的方式来停止服务**，因为总有人会用kill -9——所以数据持久化和幂等设计才是最终保障。
