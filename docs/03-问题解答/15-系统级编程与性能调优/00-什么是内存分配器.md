# 什么是内存分配器
> 📖 相关章节：[内存管理](../../01-C语言/09-内存管理.md)、[高级内存管理](../../09-系统级编程与性能调优/01-高级内存管理.md)、[CPU缓存优化](../../09-系统级编程与性能调优/02-CPU缓存优化.md)

> 本质速解：内存分配器是程序与操作系统之间的"批发零售商"——它向操作系统大批量申请内存（批发），再按程序需求小块小块地分配出去（零售），避免每次分配都惊动操作系统这个"大仓库"。

***

### 1. 为什么需要内存分配器

#### 1.1 直接用系统调用的问题

程序每次需要内存都调用 `brk`/`mmap`（Linux）或 `VirtualAlloc`（Windows），会有严重问题：

| 问题 | 说明 |
|------|------|
| 系统调用开销大 | 每次调用都要从用户态切换到内核态，代价约几百到上千个时钟周期 |
| 粒度不匹配 | 操作系统按页（4KB）分配，程序可能只要 32 字节 |
| 碎片化 | 频繁申请释放导致内存碎片，无法利用零散空间 |

**类比**：你每次需要一支笔都跑去批发市场买一箱，太浪费了。不如一次买一箱放家里，需要时从家里拿。

#### 1.2 分配器的角色

```
应用程序  →  malloc/new  →  内存分配器  →  brk/mmap  →  操作系统
            (零售接口)     (批发零售商)    (批发接口)    (大仓库)
```

分配器做三件事：
1. **批量申请**：向操作系统申请大块内存
2. **高效分配**：按需切分成小块给程序使用
3. **回收复用**：程序释放后回收，下次分配时复用

### 2. ptmalloc：glibc 的默认分配器

#### 2.1 核心设计

ptmalloc 是 glibc 的默认内存分配器，源自 Doug Lea 的 dlmalloc，增加了多线程支持。

**核心概念**：

| 概念 | 说明 |
|------|------|
| Arena | 分配区，每个 arena 有自己的锁，减少线程争用 |
| Chunk | 分配的最小单位，包含头部信息和用户数据 |
| Bin | 空闲 chunk 的分类链表，按大小分组 |
| Top chunk | arena 中最大的空闲 chunk，分配时从此切割 |

#### 2.2 Arena 机制

```
主线程 → Main Arena（1个）
线程1  → Thread Arena 1
线程2  → Thread Arena 2
线程3  → 复用 Thread Arena 1（arena 数量有限）
```

- 32位系统：arena 数量上限 = 2 × CPU核心数
- 64位系统：arena 数量上限 = 8 × CPU核心数
- 多个线程可能共享同一个 arena，需要加锁

#### 2.3 Bin 分类

```
Fast Bin（< 80B）    → 单链表，LIFO，不加锁（性能优先）
Small Bin（< 512B）  → 双链表，FIFO，精确大小匹配
Large Bin（≥ 512B）  → 双链表，大小范围匹配
Unsorted Bin         → 释放后先放这里，下次分配时整理归类
```

#### 2.4 ptmalloc 的问题

| 问题 | 说明 |
|------|------|
| 锁争用 | arena 数量有限，多线程仍需争锁 |
| 内存膨胀 | 线程释放的内存可能留在该线程的 arena 中，其他线程无法使用 |
| 碎片化 | 长期运行后碎片严重，RSS 持续增长 |
| 不归还内存 | 释放的内存不一定归还给操作系统 |

```cpp
// ptmalloc 内存膨胀示例
#include <cstdlib>
#include <thread>
#include <vector>

void thread_func() {
    // 线程分配大量内存
    std::vector<void*> ptrs;
    for (int i = 0; i < 10000; ++i) {
        ptrs.push_back(malloc(1024));  // 分配 10MB
    }
    // 全部释放
    for (auto p : ptrs) {
        free(p);
    }
    // 内存释放了，但 ptmalloc 不一定归还给操作系统
    // RSS 可能仍然很高
}

int main() {
    std::thread t1(thread_func);
    std::thread t2(thread_func);
    t1.join();
    t2.join();
    // 此时进程 RSS 可能远高于实际使用量
    return 0;
}
```

### 3. tcmalloc：Google 的高性能分配器

#### 3.1 核心设计

tcmalloc（Thread-Caching Malloc）是 Google 开发的高性能内存分配器，核心思想是**线程本地缓存**。

**架构**：

```
线程1 → ThreadCache → CentralCache → PageHeap → 操作系统
线程2 → ThreadCache → CentralCache → PageHeap → 操作系统
线程3 → ThreadCache → CentralCache → PageHeap → 操作系统
```

#### 3.2 三级缓存

| 层级 | 说明 | 锁粒度 |
|------|------|--------|
| ThreadCache | 每线程私有，无锁分配 | 无锁 |
| CentralCache | 全局中心缓存，按大小类分锁 | 细粒度锁 |
| PageHeap | 管理大块内存（页级别） | 全局锁 |

**分配流程**：

```
1. 查 ThreadCache → 命中则直接返回（无锁）
2. 未命中 → 从 CentralCache 批量获取一批对象（加锁）
3. CentralCache 未命中 → 从 PageHeap 获取 span（加锁）
4. PageHeap 未命中 → 从操作系统申请（系统调用）
```

#### 3.3 大小分类

tcmalloc 将分配大小分为约 88 个类（Size Class）：

```
小对象（≤ 256KB）：从 ThreadCache 分配，极快
中对象（256KB ~ 1MB）：从 CentralCache 分配
大对象（> 1MB）：直接从 PageHeap 分配
```

#### 3.4 tcmalloc 的优势

| 优势 | 说明 |
|------|------|
| 线程缓存无锁 | 小对象分配几乎无锁争用 |
| 内存碎片少 | 精细的大小分类减少内部碎片 |
| 更好的多核扩展 | 线程缓存减少全局锁争用 |
| 主动归还内存 | 空闲内存可以归还给操作系统 |

```cpp
// 使用 tcmalloc
// 编译：g++ -ltcmalloc main.cpp -o main
#include <cstdlib>
#include <thread>
#include <vector>

void thread_func() {
    std::vector<void*> ptrs;
    for (int i = 0; i < 10000; ++i) {
        ptrs.push_back(malloc(1024));
    }
    for (auto p : ptrs) {
        free(p);
    }
    // tcmalloc 会更积极地归还内存给操作系统
}

int main() {
    std::thread t1(thread_func);
    std::thread t2(thread_func);
    t1.join();
    t2.join();
    return 0;
}
```

### 4. jemalloc：高性能低碎片分配器

#### 4.1 核心设计

jemalloc 由 Jason Evans 开发，最初为 FreeBSD 设计，后被 Facebook（Meta）采用和优化。

**架构**：

```
线程1 → tcache → arena 0 → chunks → 操作系统
线程2 → tcache → arena 1 → chunks → 操作系统
线程3 → tcache → arena 2 → chunks → 操作系统
```

#### 4.2 Arena 分配

- arena 数量在启动时确定，通常为 CPU 核心数的 4 倍
- 每个线程绑定到一个 arena（按 round-robin 分配）
- 不同 arena 完全独立，无需同步

#### 4.3 大小分类与 Slab

```
Small（< 8KB）：通过 Slab 分配
                      ┌──────────────────┐
Slab 结构：           │ 区域头 | 对象 | 对象 | ... │
                      └──────────────────┘
                      每个 Slab 管理固定大小的对象

Large（8KB ~ 4MB）：直接分配连续页
Huge（> 4MB）：直接 mmap 分配
```

#### 4.4 jemalloc 的优势

| 优势 | 说明 |
|------|------|
| 低碎片 | 精细的大小分类 + Slab 机制，碎片率极低 |
| 多 arena | 线程间几乎无锁争用 |
| 主动内存整理 | 后台线程定期整理碎片，归还内存 |
| 丰富的统计 | 内建 profiling，可分析内存使用 |
| 可扩展性强 | 大规模多核场景表现优秀 |

```cpp
// 使用 jemalloc
// 编译：g++ -ljemalloc main.cpp -o main
#include <jemalloc/jemalloc.h>
#include <cstdio>

int main() {
    // jemalloc 提供统计接口
    size_t allocated = 0;
    size_t sz = sizeof(allocated);
    je_mallctl("stats.allocated", &allocated, &sz, nullptr, 0);
    printf("当前分配量: %zu bytes\n", allocated);

    void* p = je_malloc(1024);

    je_mallctl("stats.allocated", &allocated, &sz, nullptr, 0);
    printf("分配后: %zu bytes\n", allocated);

    je_free(p);
    return 0;
}
```

### 5. 三大分配器对比

| 维度 | ptmalloc | tcmalloc | jemalloc |
|------|----------|----------|----------|
| 开发者 | glibc 社区 | Google | Jason Evans / Meta |
| 线程缓存 | 无（arena 级别） | ThreadCache | tcache |
| 锁粒度 | arena 锁 | CentralCache 分段锁 | arena 独立 |
| 小对象性能 | 一般 | 优秀 | 优秀 |
| 大对象性能 | 一般 | 良好 | 优秀 |
| 内存碎片 | 高 | 中 | 低 |
| 内存膨胀 | 严重 | 轻微 | 轻微 |
| 多核扩展性 | 差 | 良好 | 优秀 |
| 统计分析 | 基础 | 良好 | 优秀 |
| 适用场景 | 通用 | 多线程小对象 | 多线程 + 低碎片 |

**性能对比（典型场景）**：

### 6. 如何选择分配器

#### 6.1 决策流程

```
你的程序是单线程？
  ├─ 是 → ptmalloc 足够
  └─ 否 → 多线程 + 小对象多？
           ├─ 是 → tcmalloc 或 jemalloc
           └─ 否 → 长期运行 + 碎片敏感？
                    ├─ 是 → jemalloc
                    └─ 否 → tcmalloc
```

#### 6.2 场景推荐

| 场景 | 推荐 | 原因 |
|------|------|------|
| 桌面应用/工具 | ptmalloc | 默认即可，无需额外依赖 |
| Web 服务器 | tcmalloc | 大量小对象，多线程 |
| 数据库 | jemalloc | 低碎片，长期运行 |
| 游戏服务器 | jemalloc | 稳定，碎片可控 |
| 实时系统 | jemalloc | 可预测的延迟 |
| 内存数据库 | jemalloc | 低碎片 + 统计分析 |

#### 6.3 使用方式

```bash
# 方式1：链接时替换（推荐）
g++ -ltcmalloc main.cpp -o main       # 使用 tcmalloc
g++ -ljemalloc main.cpp -o main       # 使用 jemalloc

# 方式2：运行时替换（不修改编译）
LD_PRELOAD=/usr/lib/libtcmalloc.so ./main
LD_PRELOAD=/usr/lib/libjemalloc.so ./main

# 方式3：CMake 中配置
# CMakeLists.txt
find_package(tcmalloc REQUIRED)
target_link_libraries(myapp tcmalloc)
```

### 7. Arena 分配深入

#### 7.1 什么是 Arena

Arena 是一块独立的内存管理区域，拥有自己的空闲链表和锁。不同 arena 之间完全独立，操作互不影响。

```
┌─────────────────────────────────────────────┐
│                  进程内存空间                  │
│                                              │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐    │
│  │ Arena 0  │ │ Arena 1  │ │ Arena 2  │    │
│  │ ┌──────┐ │ │ ┌──────┐ │ │ ┌──────┐ │    │
│  │ │ bins │ │ │ │ bins │ │ │ │ bins │ │    │
│  │ ├──────┤ │ │ ├──────┤ │ │ ├──────┤ │    │
│  │ │chunks│ │ │ │chunks│ │ │ │chunks│ │    │
│  │ ├──────┤ │ │ ├──────┤ │ │ ├──────┤ │    │
│  │ │ lock │ │ │ │ lock │ │ │ │ lock │ │    │
│  │ └──────┘ │ │ └──────┘ │ │ └──────┘ │    │
│  └──────────┘ └──────────┘ └──────────┘    │
└─────────────────────────────────────────────┘
```

#### 7.2 自定义 Arena（jemalloc 示例）

```cpp
// 自定义 arena，隔离不同模块的内存
#include <jemalloc/jemalloc.h>
#include <cstdio>

int main() {
    // 创建独立的 arena
    unsigned arena_id;
    size_t sz = sizeof(arena_id);
    je_mallctl("arenas.create", &arena_id, &sz, nullptr, 0);
    printf("创建 arena: %u\n", arena_id);

    // 在指定 arena 中分配内存
    je_mallocx(1024, MALLOCX_ARENA(arena_id));

    // 销毁 arena（释放该 arena 的所有内存）
    je_mallctl("arena.{}.destroy", nullptr, 0, &arena_id, sizeof(arena_id));

    return 0;
}
```

#### 7.3 Arena 隔离的好处

| 好处 | 说明 |
|------|------|
| 减少锁争用 | 不同线程使用不同 arena，无需加锁 |
| 隔离碎片 | 一个模块的碎片不影响其他模块 |
| 批量释放 | 整个 arena 可以一次性销毁，所有内存立即归还 |
| 统计隔离 | 可以单独统计每个 arena 的内存使用 |

### 8. 实战：内存分配器性能测试

```cpp
// benchmark_alloc.cpp - 对比不同分配器的性能
#include <cstdlib>
#include <chrono>
#include <thread>
#include <vector>
#include <cstdio>

// 小对象分配测试
void bench_small_alloc(int iterations) {
    auto start = std::chrono::high_resolution_clock::now();

    std::vector<void*> ptrs;
    ptrs.reserve(iterations);

    for (int i = 0; i < iterations; ++i) {
        // 模拟真实场景：随机大小的小对象
        size_t size = 16 + (i % 240);  // 16 ~ 256 字节
        ptrs.push_back(malloc(size));
    }

    for (auto p : ptrs) {
        free(p);
    }

    auto end = std::chrono::high_resolution_clock::now();
    auto us = std::chrono::duration_cast<std::chrono::microseconds>(end - start);
    printf("小对象分配 %d 次: %lld us\n", iterations, us.count());
}

// 多线程分配测试
void bench_multi_thread(int thread_count, int iterations) {
    auto start = std::chrono::high_resolution_clock::now();

    std::vector<std::thread> threads;
    for (int t = 0; t < thread_count; ++t) {
        threads.emplace_back([iterations]() {
            std::vector<void*> ptrs;
            ptrs.reserve(iterations);
            for (int i = 0; i < iterations; ++i) {
                ptrs.push_back(malloc(64));
            }
            for (auto p : ptrs) {
                free(p);
            }
        });
    }

    for (auto& t : threads) {
        t.join();
    }

    auto end = std::chrono::high_resolution_clock::now();
    auto us = std::chrono::duration_cast<std::chrono::microseconds>(end - start);
    printf("%d 线程 x %d 次分配: %lld us\n", thread_count, iterations, us.count());
}

int main() {
    bench_small_alloc(1000000);
    bench_multi_thread(8, 100000);
    return 0;
}
```

```bash
# 对比运行
g++ -O2 benchmark_alloc.cpp -o bench_ptmalloc && ./bench_ptmalloc
g++ -O2 -ltcmalloc benchmark_alloc.cpp -o bench_tcmalloc && ./bench_tcmalloc
g++ -O2 -ljemalloc benchmark_alloc.cpp -o bench_jemalloc && ./bench_jemalloc
```

### 9. 常见误区

| 误区 | 事实 |
|------|------|
| "换了分配器一定更快" | 单线程场景差异不大，甚至可能更慢 |
| "jemalloc 总是比 tcmalloc 好" | 各有优势，tcmalloc 在小对象场景可能更快 |
| "分配器能解决内存泄漏" | 分配器只能减少碎片，不能修复泄漏 |
| "arena 越多越好" | arena 过多浪费内存，需要根据线程数调整 |
| "大页 + 高性能分配器 = 最优" | 需要配合使用，单独使用效果有限 |

### 10. 总结

| 要点 | 说明 |
|------|------|
| 分配器的本质 | 批发零售商，减少系统调用，管理碎片 |
| ptmalloc | 默认选择，通用但多线程性能差 |
| tcmalloc | 线程缓存无锁，小对象多线程场景优秀 |
| jemalloc | 低碎片 + 多 arena，长期运行场景优秀 |
| 选择依据 | 线程数、对象大小、运行时长、碎片敏感度 |
| Arena | 独立内存管理区域，减少锁争用，隔离碎片 |
