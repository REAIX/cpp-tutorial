# 什么是分支预测
> 📖 相关章节：[内存管理](../../01-C语言/09-内存管理.md)、[高级内存管理](../../09-系统级编程与性能调优/01-高级内存管理.md)、[CPU缓存优化](../../09-系统级编程与性能调优/02-CPU缓存优化.md)

> 本质洞察：CPU在遇到if/else时不会傻等条件计算完，而是"猜"一条路先走下去——猜对了零开销，猜错了要清空流水线重来，代价约15-20个时钟周期，这就是分支预测失败的性能惩罚。

***

### 1. CPU 分支预测原理

#### 1.1 为什么需要分支预测

现代 CPU 有很深的流水线（14-19级），一条指令从取指到执行完需要多个周期：

```
指令流水线：
取指 → 译码 → 执行 → 访存 → 写回
  ↓     ↓     ↓     ↓     ↓
  1     2     3     4     5   （简化为5级）

遇到条件分支时：
if (condition) {
    // 路径A
} else {
    // 路径B
}

CPU 不知道 condition 的结果，必须等执行阶段才知道
但流水线不能空着，必须选择一条路继续取指
→ 分支预测器"猜"走哪条路
```

#### 1.2 预测正确 vs 预测失败

```
预测正确：
  取指A → 译码A → 执行A → 访存A → 写回A   ← 无额外开销
  结果：流水线满载，零惩罚

预测失败：
  取指A → 译码A → 执行A(发现错了！) → 清空流水线 → 重新取指B
  结果：15-20个时钟周期的惩罚（流水线冲刷）
```

#### 1.3 分支预测器类型

| 预测器 | 原理 | 准确率 |
|--------|------|--------|
| 静态预测 | 永远预测跳转/不跳转 | ~60% |
| 1-bit 预测器 | 记住上次的结果 | ~85% |
| 2-bit 饱和计数器 | 连续两次相同才改变预测 | ~90% |
| 局部分支预测 | 每个分支独立的2-bit计数器 | ~93% |
| 全局分支预测 | 利用全局分支历史 | ~95% |
| 混合预测器 | 结合局部和全局 | ~97% |

#### 1.4 2-bit 饱和计数器

```
状态转换图：

  强不跳转(00) ←→ 弱不跳转(01) ←→ 弱跳转(10) ←→ 强跳转(11)
     ↑                                              ↓
     └──────────── 预测跳转但实际不跳转 ←─────────────┘

规则：
- 预测不跳转：状态 00 或 01
- 预测跳转：状态 10 或 11
- 需要连续两次预测错误才改变预测方向
- 偶尔一次异常不会改变预测（容忍噪声）
```

### 2. 分支预测对性能的影响

#### 2.1 经典示例：有序 vs 无序数据

```cpp
#include <algorithm>
#include <chrono>
#include <cstdio>
#include <vector>
#include <random>

int main() {
    const int N = 10000000;
    std::vector<int> data(N);

    // 填充随机数据
    std::mt19937 rng(42);
    std::uniform_int_distribution<int> dist(0, 255);
    for (auto& d : data) {
        d = dist(rng);
    }

    // ===== 测试1：无序数据 =====
    auto t1 = std::chrono::high_resolution_clock::now();
    long long sum1 = 0;
    for (int i = 0; i < N; ++i) {
        if (data[i] > 128) {  // 分支：约50%概率
            sum1 += data[i];
        }
    }
    auto t2 = std::chrono::high_resolution_clock::now();
    printf("无序数据: %lld ms, sum=%lld\n",
           std::chrono::duration_cast<std::chrono::milliseconds>(t2 - t1).count(),
           sum1);

    // ===== 测试2：有序数据 =====
    std::sort(data.begin(), data.end());  // 排序！
    auto t3 = std::chrono::high_resolution_clock::now();
    long long sum2 = 0;
    for (int i = 0; i < N; ++i) {
        if (data[i] > 128) {  // 分支：先全不跳转，后全跳转
            sum2 += data[i];
        }
    }
    auto t4 = std::chrono::high_resolution_clock::now();
    printf("有序数据: %lld ms, sum=%lld\n",
           std::chrono::duration_cast<std::chrono::milliseconds>(t4 - t3).count(),
           sum2);

    return 0;
}

// 典型结果：
// 无序数据: ~80 ms  （分支预测频繁失败）
// 有序数据: ~20 ms  （分支预测几乎全对）
// 差距：4x！
```

**原因**：
- 无序数据：`data[i] > 128` 约50%概率，分支预测器无法有效预测
- 有序数据：前半段全 ≤ 128（不跳转），后半段全 > 128（跳转），预测器轻松预测

#### 2.2 分支预测失败的代价

```
每次预测失败的代价：
- 流水线冲刷：15-20 个时钟周期
- 等价于 ~5ns（3GHz CPU）
- 如果每秒失败 1 亿次 → 浪费 0.5 秒

对比：
- L1 缓存命中：4 个时钟周期
- L2 缓存命中：12 个时钟周期
- 分支预测失败：15-20 个时钟周期

分支预测失败 ≈ L2 缓存缺失的代价！
```

### 3. likely/unlikely 的使用

#### 3.1 什么是 likely/unlikely

`likely` 和 `unlikely` 是给编译器的提示，告诉它哪个分支更可能被执行。

```cpp
// Linux 内核定义
#define likely(x)   __builtin_expect(!!(x), 1)   // x 大概率为真
#define unlikely(x) __builtin_expect(!!(x), 0)   // x 大概率为假
```

#### 3.2 使用场景

```cpp
#include <cstdio>

// likely：错误检查中，正常路径是常见情况
int process_data(int* data, int size) {
    if (unlikely(data == nullptr)) {  // 错误情况，不太可能发生
        return -1;
    }
    if (unlikely(size <= 0)) {  // 错误情况
        return -1;
    }

    // 正常处理逻辑...
    return 0;
}

// unlikely：罕见事件
void handle_event(int event_type) {
    if (unlikely(event_type == EVENT_ERROR)) {
        // 错误处理，很少执行
        handle_error();
        return;
    }

    // 正常事件处理...
}

// likely：热路径优化
int find_element(const int* arr, int n, int target) {
    for (int i = 0; i < n; ++i) {
        if (likely(arr[i] != target)) {  // 大概率不匹配
            continue;
        }
        return i;  // 找到了
    }
    return -1;
}
```

#### 3.3 C++20 的 [[likely]] 和 [[unlikely]]

```cpp
// C++20 属性语法（更标准）
int process(int* data, int size) {
    if (data == nullptr) [[unlikely]] {
        return -1;
    }

    if (size > 0) [[likely]] {
        // 正常路径
        return do_process(data, size);
    }

    return -1;
}

// switch 语句中使用
void handle_status(int status) {
    switch (status) {
        [[likely]] case STATUS_OK:
            // 正常情况
            break;
        [[unlikely]] case STATUS_ERROR:
            // 错误情况
            break;
    }
}
```

#### 3.4 likely/unlikely 的效果

```cpp
// 不使用 likely/unlikely
if (error_condition) {  // 编译器不知道哪个分支更可能
    // 编译器可能把错误处理代码放在前面（缓存友好）
    // 但正常路径可能跳转
}

// 使用 unlikely
if (unlikely(error_condition)) {  // 告诉编译器：错误很少发生
    // 编译器把错误处理代码放到远处
    // 正常路径顺序执行，不跳转，更快
}
```

编译器做的优化：
1. 将 `likely` 分支的代码放在紧跟 if 的位置（减少跳转）
2. 将 `unlikely` 分支的代码放到函数末尾（不污染缓存）
3. 静态预测提示：首次遇到时预测 likely 分支

### 4. 无分支编程技巧

#### 4.1 条件传送（cmov）

```cpp
// ❌ 有分支的版本
int max_branch(int a, int b) {
    if (a > b) return a;
    else return b;
}
// 汇编：cmp → jle → mov → ret（可能预测失败）

// ✅ 无分支版本（编译器可能自动优化为 cmov）
int max_branchless(int a, int b) {
    return a > b ? a : b;
}
// 汇编：cmp → cmovle → ret（无条件跳转，不会预测失败）
```

#### 4.2 位运算替代分支

```cpp
#include <cstdio>

// ❌ 有分支：取绝对值
int abs_branch(int x) {
    if (x < 0) return -x;
    return x;
}

// ✅ 无分支：位运算取绝对值
int abs_branchless(int x) {
    int mask = x >> 31;        // x为负时mask=0xFFFFFFFF，否则0x00000000
    return (x + mask) ^ mask;  // 等价于 x < 0 ? -x : x
}

// ❌ 有分支：条件赋值
int select_branch(bool cond, int a, int b) {
    if (cond) return a;
    return b;
}

// ✅ 无分支：条件赋值
int select_branchless(bool cond, int a, int b) {
    // cond为true时返回a，否则返回b
    return b + (a - b) * cond;  // 利用bool到int的隐式转换
}

// ❌ 有分支：clamp
int clamp_branch(int x, int lo, int hi) {
    if (x < lo) return lo;
    if (x > hi) return hi;
    return x;
}

// ✅ 无分支：clamp
int clamp_branchless(int x, int lo, int hi) {
    // 先取max(x, lo)，再取min(result, hi)
    x = x ^ ((x ^ lo) & -(x < lo));   // max(x, lo) 无分支
    x = hi ^ ((hi ^ x) & -(hi < x));  // min(x, hi) 无分支
    return x;
}
```

#### 4.3 查表法替代分支

```cpp
// ❌ 有分支：根据类型执行不同操作
int compute_branch(int type, int value) {
    switch (type) {
        case 0: return value + 1;
        case 1: return value * 2;
        case 2: return value * value;
        case 3: return value - 1;
        default: return value;
    }
}

// ✅ 无分支：查表法
int compute_table(int type, int value) {
    // 使用函数指针数组（间接调用，但无分支预测失败）
    using ComputeFunc = int(*)(int);
    static const ComputeFunc funcs[] = {
        [](int v) { return v + 1; },
        [](int v) { return v * 2; },
        [](int v) { return v * v; },
        [](int v) { return v - 1; },
    };

    if (type >= 0 && type < 4) {
        return funcs[type](value);
    }
    return value;
}
```

#### 4.4 SIMD 中的无分支技巧

```cpp
#include <immintrin.h>

// ❌ 有分支：条件过滤（SIMD中分支代价更大）
// SIMD 所有通道必须执行相同操作，分支会导致部分通道空闲

// ✅ 无分支：使用掩码
__m256 conditional_add(__m256 a, __m256 b, __m256 threshold) {
    // 比较 a > threshold
    __m256 mask = _mm256_cmp_ps(a, threshold, _CMP_GT_OS);

    // mask 中：满足条件的通道为 0xFFFFFFFF，否则为 0x00000000
    // 用掩码选择性加 b
    __m256 masked_b = _mm256_and_ps(b, mask);
    return _mm256_add_ps(a, masked_b);
    // 满足条件的通道：a + b
    // 不满足条件的通道：a + 0 = a
}
```

#### 4.5 无分支的性能权衡

| 因素 | 有分支 | 无分支 |
|------|--------|--------|
| 预测成功时 | 更快（跳过不需要的计算） | 稍慢（总是执行所有计算） |
| 预测失败时 | 很慢（15-20周期惩罚） | 稳定（无惩罚） |
| 代码可读性 | 高 | 低 |
| 适用场景 | 分支可预测 | 分支不可预测 |

**决策原则**：
- 分支预测准确率 > 90% → 用分支
- 分支预测准确率 < 90% → 考虑无分支
- 不确定 → 测量！

### 5. 检测分支预测失败

#### 5.1 perf（Linux）

```bash
# 查看分支预测失败率
perf stat -e branches,branch-misses ./my_program

# 输出示例：
#   branches:        1,000,000,000
#   branch-misses:      50,000,000  (5.0% 失败率)
#                      ↑ 超过 3-5% 就需要关注
```

#### 5.2 硬件性能计数器

```cpp
// Linux 下读取分支预测计数器
#include <linux/perf_event.h>
#include <sys/syscall.h>
#include <unistd.h>
#include <cstdio>

long perf_event_open(struct perf_event_attr* attr, pid_t pid,
                     int cpu, int group_fd, unsigned long flags) {
    return syscall(__NR_perf_event_open, attr, pid, cpu, group_fd, flags);
}

int main() {
    struct perf_event_attr attr{};
    attr.type = PERF_TYPE_HARDWARE;
    attr.size = sizeof(attr);
    attr.config = PERF_COUNT_HW_BRANCH_MISSES;
    attr.disabled = 0;
    attr.exclude_kernel = 1;
    attr.exclude_hv = 1;

    int fd = perf_event_open(&attr, 0, -1, -1, 0);
    if (fd == -1) {
        perror("perf_event_open");
        return 1;
    }

    long long misses;
    read(fd, &misses, sizeof(misses));
    printf("分支预测失败次数: %lld\n", misses);

    close(fd);
    return 0;
}
```

### 6. 实战优化案例

#### 6.1 二分查找中的分支优化

```cpp
#include <cstdio>

// 标准二分查找（有分支）
int binary_search_branch(const int* arr, int n, int target) {
    int lo = 0, hi = n - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        if (arr[mid] == target) return mid;
        if (arr[mid] < target) lo = mid + 1;
        else hi = mid - 1;
    }
    return -1;
}

// 无分支二分查找（利用 cmov）
int binary_search_branchless(const int* arr, int n, int target) {
    int base = 0;
    int len = n;

    while (len > 1) {
        int half = len / 2;
        int mid = base + half;

        // 无分支：利用条件传送
        bool go_right = (arr[mid] <= target);
        base = go_right ? mid : base;
        len = go_right ? (len - half) : half;
    }

    // 最终检查
    if (len == 1 && arr[base] == target) {
        return base;
    }
    return -1;
}
```

#### 6.2 排序消除分支预测失败

```cpp
#include <algorithm>
#include <vector>
#include <chrono>
#include <cstdio>

// 处理数据：只处理满足条件的元素
long long process_data(std::vector<int>& data, bool sorted) {
    if (sorted) {
        std::sort(data.begin(), data.end());
    }

    auto start = std::chrono::high_resolution_clock::now();

    long long sum = 0;
    for (auto& d : data) {
        if (d > 128) {  // 排序后，这个分支变得高度可预测
            d = d * 3 + 7;
            sum += d;
        }
    }

    auto end = std::chrono::high_resolution_clock::now();
    printf("%s数据: %lld ms\n",
           sorted ? "有序" : "无序",
           std::chrono::duration_cast<std::chrono::milliseconds>(end - start).count());
    return sum;
}
```

### 7. 常见误区

| 误区 | 事实 |
|------|------|
| "所有分支都需要优化" | 可预测的分支（>95%准确率）几乎零开销 |
| "likely/unlikely 能大幅提升性能" | 只影响首次预测和代码布局，效果有限 |
| "无分支总是更好" | 预测成功时分支更快，无分支多了额外计算 |
| "排序只是为了算法复杂度" | 排序也能改善分支预测，有时排序+线性扫描比二分查找更快 |
| "编译器会自动消除分支" | 编译器只在确定安全时才用 cmov 替代分支 |

***

### 8. 总结

| 要点 | 说明 |
|------|------|
| 分支预测 | CPU 猜测分支走向，猜对零开销，猜错15-20周期惩罚 |
| 预测器 | 2-bit饱和计数器、全局历史、混合预测，准确率~97% |
| likely/unlikely | 给编译器提示，优化代码布局和静态预测 |
| 无分支编程 | cmov、位运算、查表法，消除不可预测分支的惩罚 |
| 优化策略 | 可预测分支不用管，不可预测分支用无分支技巧 |
| 检测方法 | perf stat 查看 branch-misses 比率 |
