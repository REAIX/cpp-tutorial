# 什么是无锁编程
> 📖 相关章节：[内存管理](../../01-C语言/09-内存管理.md)、[高级内存管理](../../09-系统级编程与性能调优/01-高级内存管理.md)、[CPU缓存优化](../../09-系统级编程与性能调优/02-CPU缓存优化.md)

> 先抓核心：无锁编程（Lock-Free）不是"不用锁"，而是用原子操作（CAS）保证多线程安全，即使某个线程挂掉，其他线程仍能继续推进——比互斥锁更难写，但在高争用场景下吞吐量更高、延迟更低。

***

### 1. 无锁编程的原理与适用场景

#### 1.1 什么是有锁 vs 无锁

```
有锁（Lock-Based）：
  线程A → 获取锁 → 临界区 → 释放锁
  线程B → 等待锁... → 获取锁 → 临界区 → 释放锁
  问题：线程A持有锁时挂掉 → 线程B永远等下去

无锁（Lock-Free）：
  线程A → CAS操作 → 成功则完成，失败则重试
  线程B → CAS操作 → 成功则完成，失败则重试
  优势：任何线程挂掉，其他线程仍能推进
```

#### 1.2 无锁的严格定义

| 级别 | 定义 | 保证 |
|------|------|------|
| 阻塞（Blocking） | 使用锁，一个线程阻塞可能导致其他线程无法推进 | 无保证 |
| 无障碍（Obstruction-Free） | 单独执行的线程总能完成 | 最弱保证 |
| 无锁（Lock-Free） | 系统整体总能推进，至少一个线程在前进 | 系统级前进保证 |
| 无等待（Wait-Free） | 每个线程都在有限步骤内完成 | 最强保证 |

**关键区别**：
- Lock-Free：**至少一个**线程在前进（其他线程可能饥饿）
- Wait-Free：**每个**线程都在前进（没有饥饿）

#### 1.3 适用场景

| 场景 | 是否适合无锁 | 原因 |
|------|-------------|------|
| 高争用计数器 | ✅ 适合 | 简单操作，CAS 代价低 |
| 单生产者单消费者队列 | ✅ 适合 | 无争用，天然无锁 |
| 多生产者多消费者队列 | ⚠️ 谨慎 | CAS 争用可能严重 |
| 复杂数据结构 | ❌ 不推荐 | 代码极难正确，用锁更安全 |
| 实时系统 | ✅ 适合 | 无锁保证前进，无优先级反转 |
| 低争用场景 | ❌ 不必要 | 锁的开销已经很低 |

### 2. CAS 操作

#### 2.1 什么是 CAS

**CAS（Compare-And-Swap）** = 原子地比较并交换，是无锁编程的基石。

```
CAS(addr, expected, desired):
  原子地执行：
  if (*addr == expected) {
      *addr = desired;
      return true;   // 成功
  } else {
      return false;  // 失败（值已被其他线程修改）
  }
```

#### 2.2 C++ 中的 CAS

```cpp
#include <atomic>
#include <cstdio>

int main() {
    std::atomic<int> value{0};

    // compare_exchange_weak：可能虚假失败（即使值相等也返回false）
    // 适合用在循环中
    int expected = 0;
    bool success = value.compare_exchange_weak(expected, 1);
    printf("CAS weak: success=%d, value=%d, expected=%d\n",
           success, value.load(), expected);

    // compare_exchange_strong：不会虚假失败
    // 适合不在循环中的单次 CAS
    expected = 1;
    success = value.compare_exchange_strong(expected, 2);
    printf("CAS strong: success=%d, value=%d, expected=%d\n",
           success, value.load(), expected);

    return 0;
}
```

#### 2.3 CAS 实现无锁计数器

```cpp
#include <atomic>
#include <cstdio>
#include <thread>
#include <vector>

// 有锁计数器
class LockedCounter {
    int count = 0;
    std::mutex mtx;
public:
    void increment() {
        std::lock_guard<std::mutex> lock(mtx);
        count++;
    }
    int get() { return count; }
};

// 无锁计数器（CAS 循环）
class LockFreeCounter {
    std::atomic<int> count{0};
public:
    void increment() {
        int old_val = count.load(std::memory_order_relaxed);
        // CAS 循环：失败则重试
        while (!count.compare_exchange_weak(
                   old_val, old_val + 1,
                   std::memory_order_relaxed)) {
            // old_val 已被自动更新为当前值，直接重试
        }
    }
    int get() { return count.load(std::memory_order_relaxed); }
};

// 更简洁：使用 fetch_add
class AtomicCounter {
    std::atomic<int> count{0};
public:
    void increment() {
        count.fetch_add(1, std::memory_order_relaxed);
    }
    int get() { return count.load(std::memory_order_relaxed); }
};

int main() {
    LockFreeCounter counter;
    std::vector<std::thread> threads;

    for (int i = 0; i < 8; ++i) {
        threads.emplace_back([&]() {
            for (int j = 0; j < 1000000; ++j) {
                counter.increment();
            }
        });
    }

    for (auto& t : threads) t.join();
    printf("计数器结果: %d\n", counter.get());  // 应该是 8000000
    return 0;
}
```

#### 2.4 CAS 实现无锁栈

```cpp
#include <atomic>
#include <cstdio>

template<typename T>
class LockFreeStack {
private:
    struct Node {
        T data;
        Node* next;
        Node(T val) : data(std::move(val)), next(nullptr) {}
    };

    std::atomic<Node*> head{nullptr};

public:
    void push(T value) {
        Node* new_node = new Node(std::move(value));
        new_node->next = head.load(std::memory_order_relaxed);

        // CAS：如果 head 没变，就把 head 指向新节点
        while (!head.compare_exchange_weak(
                   new_node->next, new_node,
                   std::memory_order_release,
                   std::memory_order_relaxed)) {
            // head 被其他线程修改了，new_node->next 已更新为新的 head
            // 直接重试
        }
    }

    // 注意：这个 pop 有 ABA 问题（后面会讲）
    bool pop(T& result) {
        Node* old_head = head.load(std::memory_order_relaxed);

        while (old_head) {
            // CAS：如果 head 没变，就把 head 指向下一个节点
            if (head.compare_exchange_weak(
                    old_head, old_head->next,
                    std::memory_order_acquire,
                    std::memory_order_relaxed)) {
                result = std::move(old_head->data);
                // 注意：这里不能立即 delete old_head！
                // 其他线程可能还在访问它（ABA 问题 / 内存安全）
                break;
            }
        }

        return old_head != nullptr;
    }
};

int main() {
    LockFreeStack<int> stack;
    stack.push(1);
    stack.push(2);
    stack.push(3);

    int val;
    while (stack.pop(val)) {
        printf("弹出: %d\n", val);  // 3, 2, 1
    }
    return 0;
}
```

### 3. ABA 问题

#### 3.1 什么是 ABA 问题

```
时间线：
1. 线程A 读取 head = X（X->next = Y）
2. 线程A 被抢占...
3. 线程B pop X，push Z，push X（X 被重新放回）
4. 线程A 恢复执行
5. 线程A CAS(head, X, Y) → 成功！因为 head 确实是 X
6. 但此时 X->next 已经不是 Y 了！
7. 结果：head 被设为错误的值，数据结构被破坏
```

**核心**：CAS 只检查值是否相等，不检查值是否"曾经被修改过又改回来了"。

#### 3.2 ABA 问题的解决方案

**方案1：版本号/标签**

```cpp
#include <atomic>
#include <cstdint>
#include <cstdio>

// 将指针和版本号打包
template<typename T>
class TaggedPointer {
public:
    uintptr_t value;  // 指针 + 版本号

    TaggedPointer(T* ptr, uint64_t tag) {
        // 假设指针低48位有效，高16位用于版本号
        value = reinterpret_cast<uintptr_t>(ptr) | (tag << 48);
    }

    T* get_ptr() const {
        return reinterpret_cast<T*>(value & 0x0000FFFFFFFFFFFF);
    }

    uint64_t get_tag() const {
        return value >> 48;
    }
};

// 使用版本号的 CAS
template<typename T>
bool cas_with_tag(std::atomic<uintptr_t>& addr,
                  T* expected_ptr, uint64_t expected_tag,
                  T* desired_ptr, uint64_t desired_tag) {
    TaggedPointer<T> expected(expected_ptr, expected_tag);
    TaggedPointer<T> desired(desired_ptr, desired_tag);
    return addr.compare_exchange_strong(expected.value, desired.value);
}
```

// 使用 128 位 CAS 同时比较指针和计数器
#include <atomic>

// GCC 支持 __int128 的原子操作
struct PointerAndCount {
    void* ptr;
    uint64_t count;
};

// 在支持 128 位 CAS 的平台上
bool double_cas(std::atomic<__int128>& addr,
                PointerAndCount expected,
                PointerAndCount desired) {
    __int128 exp_val = *reinterpret_cast<__int128*>(&expected);
    __int128 des_val = *reinterpret_cast<__int128*>(&desired);
    return addr.compare_exchange_strong(exp_val, des_val);
}

### 4. 无锁 vs 有锁的性能对比

#### 4.1 低争用场景

```
低争用（8线程，少量操作）：
  互斥锁：  ████████  基准
  无锁CAS： ████████  差异不大
  原子操作： ███████   稍快

原因：锁几乎不争用，获取锁的开销接近一次 CAS
```

#### 4.2 高争用场景

```
高争用（8线程，大量并发操作）：
  互斥锁：  ████████████████████  基准
  无锁CAS： ████████████          约 1.5-2x 快
  原子操作：████████              约 2-3x 快

原因：锁争用导致线程阻塞和上下文切换
      CAS 失败只是重试，没有上下文切换
```

#### 4.3 极端争用场景

```
极端争用（32+线程，疯狂CAS）：
  互斥锁：  ████████████████████  基准
  无锁CAS： ██████████████████████  可能更慢！

原因：大量线程同时 CAS 失败 → 反复重试 → CPU 总线锁争用
      这叫"惊群效应"（Thundering Herd）
```

#### 4.4 延迟对比

```
操作延迟（纳秒）：
  互斥锁（无争用）：    ~25 ns
  互斥锁（有争用）：    ~500-5000 ns（上下文切换）
  CAS（无争用）：       ~10 ns
  CAS（有争用）：       ~50-200 ns（重试）
  fetch_add（无争用）： ~8 ns

关键：互斥锁争用时延迟不可预测，CAS 延迟更稳定
```

#### 4.5 性能测试代码

```cpp
#include <atomic>
#include <mutex>
#include <thread>
#include <vector>
#include <chrono>
#include <cstdio>

// 有锁版本
void bench_mutex(int thread_count, int ops_per_thread) {
    std::mutex mtx;
    int counter = 0;

    auto start = std::chrono::high_resolution_clock::now();

    std::vector<std::thread> threads;
    for (int t = 0; t < thread_count; ++t) {
        threads.emplace_back([&]() {
            for (int i = 0; i < ops_per_thread; ++i) {
                std::lock_guard<std::mutex> lock(mtx);
                counter++;
            }
        });
    }
    for (auto& t : threads) t.join();

    auto end = std::chrono::high_resolution_clock::now();
    auto us = std::chrono::duration_cast<std::chrono::microseconds>(end - start);
    printf("互斥锁: %lld us (result=%d)\n", us.count(), counter);
}

// 无锁版本
void bench_lockfree(int thread_count, int ops_per_thread) {
    std::atomic<int> counter{0};

    auto start = std::chrono::high_resolution_clock::now();

    std::vector<std::thread> threads;
    for (int t = 0; t < thread_count; ++t) {
        threads.emplace_back([&]() {
            for (int i = 0; i < ops_per_thread; ++i) {
                counter.fetch_add(1, std::memory_order_relaxed);
            }
        });
    }
    for (auto& t : threads) t.join();

    auto end = std::chrono::high_resolution_clock::now();
    auto us = std::chrono::duration_cast<std::chrono::microseconds>(end - start);
    printf("无锁: %lld us (result=%d)\n", us.count(), counter.load());
}

int main() {
    bench_mutex(8, 1000000);
    bench_lockfree(8, 1000000);
    return 0;
}
```

### 5. 无锁编程的常见陷阱

#### 5.1 内存回收问题

```cpp
// ❌ 危险：无锁 pop 后立即 delete
bool pop_unsafe(T& result) {
    Node* old_head = head.load();
    if (head.compare_exchange_weak(old_head, old_head->next)) {
        result = old_head->data;
        delete old_head;  // 危险！其他线程可能还在读 old_head
        return true;
    }
    return false;
}

// ✅ 安全：使用延迟回收（Hazard Pointer / Epoch / 引用计数）
```

#### 5.2 内存序问题

```cpp
// ❌ 错误的内存序
void push_wrong(T value) {
    Node* new_node = new Node(value);
    new_node->next = head.load(std::memory_order_relaxed);  // 可能读到旧值
    while (!head.compare_exchange_weak(new_node->next, new_node,
               std::memory_order_relaxed,   // 其他线程可能看不到新节点
               std::memory_order_relaxed)) {}
}

// ✅ 正确的内存序
void push_correct(T value) {
    Node* new_node = new Node(value);
    new_node->next = head.load(std::memory_order_relaxed);
    while (!head.compare_exchange_weak(new_node->next, new_node,
               std::memory_order_release,   // 确保 new_node 的写入对其他线程可见
               std::memory_order_relaxed)) {}
}
```

#### 5.3 活锁问题

```cpp
// 两个线程互相让步，谁也无法推进
// 在高争用 CAS 场景可能出现
void push_with_backoff(T value) {
    Node* new_node = new Node(value);
    int backoff = 1;

    while (true) {
        new_node->next = head.load(std::memory_order_relaxed);
        if (head.compare_exchange_weak(new_node->next, new_node,
                std::memory_order_release, std::memory_order_relaxed)) {
            break;
        }
        // 退避：减少争用
        for (int i = 0; i < backoff; ++i) {
            __builtin_ia32_pause();  // x86 PAUSE 指令
        }
        backoff = std::min(backoff * 2, 1024);  // 指数退避
    }
}
```

### 6. 常见误区

| 误区 | 事实 |
|------|------|
| "无锁 = 更快" | 低争用时差异不大，极端争用时可能更慢 |
| "无锁 = 没有锁" | 无锁是指不使用互斥锁，但仍用原子操作 |
| "CAS 就是万能的" | CAS 只能原子修改一个变量，复杂操作需要多个 CAS |
| "无锁代码不需要内存序" | 无锁代码对内存序要求更高，错误使用会导致数据竞争 |
| "无锁编程应该到处使用" | 无锁编程极难正确，大多数场景用锁更安全 |

***

### 7. 总结

| 要点 | 说明 |
|------|------|
| 无锁编程 | 用原子操作替代锁，保证系统级前进 |
| CAS | 比较并交换，无锁编程的基石 |
| ABA 问题 | 值被改走又改回，CAS 误判，需版本号解决 |
| 适用场景 | 高争用简单操作、实时系统、低延迟要求 |
| 不适用 | 复杂数据结构、低争用场景 |
| 内存回收 | 无锁数据结构的最大难题，需要 Hazard Pointer/RCU/Epoch |
