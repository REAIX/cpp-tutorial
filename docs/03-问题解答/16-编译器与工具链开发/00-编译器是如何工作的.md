# 编译器是如何工作的
> 📖 相关章节：[编译与链接](../../01-C语言/17-编译与链接.md)、[编译器原理](../../10-编译器与工具链开发/00-编译器原理概述.md)

> "本质速解：编译器就是把人类可读的源代码翻译成机器可执行的指令的翻译器，它经历词法分析、语法分析、语义分析、中间代码生成、优化、目标代码生成六个阶段，而现代编译器采用前端-优化器-后端三段式架构，让不同语言和不同平台可以自由组合。"

***

## 1. 编译器六阶段详解

### 1. 总览

```
源代码（hello.cpp）
    │
    ▼
┌──────────────┐
│ 1. 词法分析   │  源代码 → Token流
│   (Lexing)   │  "int x = 42;" → [int][x][=][42][;]
└──────┬───────┘
       │
       ▼
┌──────────────┐
│ 2. 语法分析   │  Token流 → AST（抽象语法树）
│  (Parsing)   │  构建树形结构表达程序的层次关系
└──────┬───────┘
       │
       ▼
┌──────────────┐
│ 3. 语义分析   │  AST + 符号表 → 类型检查、作用域解析
│ (Sema)       │  确保程序含义正确
└──────┬───────┘
       │
       ▼
┌──────────────┐
│ 4. 中间代码   │  AST → IR（中间表示）
│   生成       │  平台无关的中间语言
└──────┬───────┘
       │
       ▼
┌──────────────┐
│ 5. 代码优化   │  IR → 优化后的IR
│ (Optimizer)  │  常量传播、死代码消除、循环优化...
└──────┬───────┘
       │
       ▼
┌──────────────┐
│ 6. 目标代码   │  优化IR → 机器码/汇编
│   生成       │  指令选择、寄存器分配、指令调度
└──────┬───────┘
       │
       ▼
可执行文件（hello）
```

### 2. 阶段一：词法分析（Lexical Analysis）

词法分析器（Lexer/Scanner）将源代码的字符流切分为有意义的Token。

```cpp
// 源代码
int main() {
    int x = 42 + 3;
    return x;
}

// 词法分析后的Token流
// Token类型        词素(Lexeme)    位置
// TOK_INT          "int"          1:1
// TOK_IDENTIFIER   "main"         1:5
// TOK_LPAREN       "("            1:9
// TOK_RPAREN       ")"            1:10
// TOK_LBRACE       "{"            1:11
// TOK_INT          "int"          2:5
// TOK_IDENTIFIER   "x"            2:9
// TOK_ASSIGN       "="            2:11
// TOK_INTEGER      "42"           2:13
// TOK_PLUS         "+"            2:16
// TOK_INTEGER      "3"            2:18
// TOK_SEMICOLON    ";"            2:19
// TOK_RETURN       "return"       3:5
// TOK_IDENTIFIER   "x"            3:12
// TOK_SEMICOLON    ";"            3:13
// TOK_RBRACE       "}"            4:1
```

**手写词法分析器示例**：

```cpp
#include <string>
#include <vector>
#include <cctype>

// Token类型枚举
enum class TokenType {
    INT, IDENTIFIER, INTEGER,
    PLUS, MINUS, STAR, SLASH,
    ASSIGN, SEMICOLON,
    LPAREN, RPAREN, LBRACE, RBRACE,
    RETURN, END_OF_FILE
};

// Token结构体
struct Token {
    TokenType type;       // Token类型
    std::string lexeme;   // 原始文本
    int line;             // 行号
    int column;           // 列号
};

// 简易词法分析器
class Lexer {
private:
    std::string source;   // 源代码文本
    size_t pos = 0;       // 当前位置
    int line = 1;         // 当前行号
    int column = 1;       // 当前列号

    // 跳过空白字符和注释
    void skipWhitespaceAndComments() {
        while (pos < source.size()) {
            if (std::isspace(source[pos])) {
                if (source[pos] == '\n') { line++; column = 1; }
                else { column++; }
                pos++;
            } else if (pos + 1 < source.size() && source[pos] == '/' && source[pos+1] == '/') {
                // 跳过单行注释
                while (pos < source.size() && source[pos] != '\n') pos++;
            } else {
                break;
            }
        }
    }

public:
    Lexer(const std::string& src) : source(src) {}

    // 获取下一个Token
    Token nextToken() {
        skipWhitespaceAndComments();

        if (pos >= source.size()) {
            return {TokenType::END_OF_FILE, "", line, column};
        }

        int startLine = line, startCol = column;
        char ch = source[pos];

        // 识别数字字面量
        if (std::isdigit(ch)) {
            std::string num;
            while (pos < source.size() && std::isdigit(source[pos])) {
                num += source[pos++];
                column++;
            }
            return {TokenType::INTEGER, num, startLine, startCol};
        }

        // 识别标识符和关键字
        if (std::isalpha(ch) || ch == '_') {
            std::string id;
            while (pos < source.size() && (std::isalnum(source[pos]) || source[pos] == '_')) {
                id += source[pos++];
                column++;
            }
            // 关键字判断
            if (id == "int") return {TokenType::INT, id, startLine, startCol};
            if (id == "return") return {TokenType::RETURN, id, startLine, startCol};
            return {TokenType::IDENTIFIER, id, startLine, startCol};
        }

        // 识别单字符Token
        pos++; column++;
        switch (ch) {
            case '+': return {TokenType::PLUS, "+", startLine, startCol};
            case '-': return {TokenType::MINUS, "-", startLine, startCol};
            case '*': return {TokenType::STAR, "*", startLine, startCol};
            case '/': return {TokenType::SLASH, "/", startLine, startCol};
            case '=': return {TokenType::ASSIGN, "=", startLine, startCol};
            case ';': return {TokenType::SEMICOLON, ";", startLine, startCol};
            case '(': return {TokenType::LPAREN, "(", startLine, startCol};
            case ')': return {TokenType::RPAREN, ")", startLine, startCol};
            case '{': return {TokenType::LBRACE, "{", startLine, startCol};
            case '}': return {TokenType::RBRACE, "}", startLine, startCol};
            default:  return {TokenType::END_OF_FILE, std::string(1, ch), startLine, startCol};
        }
    }
};
```

### 3. 阶段二：语法分析（Syntax Analysis / Parsing）

语法分析器（Parser）根据语法规则将Token流组织为AST。

```
int x = 42 + 3; 的AST结构：

        VarDecl (变量声明)
       /        \
   int x      BinaryExpr (二元表达式)
              /          \
         Integer(42)   Integer(3)
              \          /
             Plus (+) 运算
```

**常见的语法分析方法**：

| 方法 | 类型 | 特点 | 代表 |
|------|------|------|------|
| 递归下降 | 自顶向下 | 手写简单，回溯 | Clang、GCC |
| LL(k) | 自顶向下 | 从左到右，左推导 | ANTLR |
| LR/LALR | 自底向上 | 从左到右，右推导 | Yacc/Bison |
| PEG | 自顶向下 | 无歧义，有序选择 | 时尚选择 |

**递归下降解析器示例**：

```cpp
#include <memory>

// AST节点基类
struct Expr {
    virtual ~Expr() = default;
};

// 整数字面量
struct IntegerExpr : Expr {
    int value;
    explicit IntegerExpr(int v) : value(v) {}
};

// 二元表达式
struct BinaryExpr : Expr {
    char op;                       // 运算符
    std::unique_ptr<Expr> left;    // 左操作数
    std::unique_ptr<Expr> right;   // 右操作数

    BinaryExpr(char o, std::unique_ptr<Expr> l, std::unique_ptr<Expr> r)
        : op(o), left(std::move(l)), right(std::move(r)) {}
};

// 简易递归下降解析器（表达式）
class Parser {
private:
    std::vector<Token> tokens;
    size_t pos = 0;

    const Token& current() { return tokens[pos]; }
    const Token& advance() { return tokens[pos++]; }

    // 解析基本表达式：整数
    std::unique_ptr<Expr> parsePrimary() {
        if (current().type == TokenType::INTEGER) {
            int val = std::stoi(advance().lexeme);
            return std::make_unique<IntegerExpr>(val);
        }
        // 还可以扩展：变量引用、括号表达式等
        return nullptr;
    }

    // 解析乘除表达式（较高优先级）
    std::unique_ptr<Expr> parseMultiplicative() {
        auto left = parsePrimary();
        while (current().type == TokenType::STAR || current().type == TokenType::SLASH) {
            char op = advance().lexeme[0];
            auto right = parsePrimary();
            left = std::make_unique<BinaryExpr>(op, std::move(left), std::move(right));
        }
        return left;
    }

    // 解析加减表达式（较低优先级）
    std::unique_ptr<Expr> parseAdditive() {
        auto left = parseMultiplicative();
        while (current().type == TokenType::PLUS || current().type == TokenType::MINUS) {
            char op = advance().lexeme[0];
            auto right = parseMultiplicative();
            left = std::make_unique<BinaryExpr>(op, std::move(left), std::move(right));
        }
        return left;
    }

public:
    Parser(std::vector<Token> toks) : tokens(std::move(toks)) {}

    std::unique_ptr<Expr> parse() {
        return parseAdditive();
    }
};
```

### 4. 阶段三：语义分析（Semantic Analysis）

语义分析确保程序的含义正确，主要工作包括：

```
语义分析的核心任务：
├── 类型检查 — int和string不能相加
├── 作用域解析 — 变量在使用前必须声明
├── 声明检查 — 函数调用参数类型和数量匹配
├── 常量表达式求值 — constexpr编译期计算
├── 控制流检查 — return语句的可达性
└── 访问控制 — private成员的访问权限
```

```cpp
// 语义分析器示例：类型检查
#include <string>
#include <unordered_map>

enum class TypeKind { INT, FLOAT, BOOL, VOID, ERROR };

struct TypeInfo {
    TypeKind kind;
    bool isConst;
    bool isReference;
};

// 符号表——记录变量名到类型的映射
class SymbolTable {
private:
    std::unordered_map<std::string, TypeInfo> symbols;
    SymbolTable* parent = nullptr;  // 外层作用域

public:
    explicit SymbolTable(SymbolTable* p = nullptr) : parent(p) {}

    // 声明变量
    bool declare(const std::string& name, TypeInfo type) {
        if (symbols.count(name)) return false;  // 重复声明
        symbols[name] = type;
        return true;
    }

    // 查找变量类型
    TypeInfo lookup(const std::string& name) const {
        auto it = symbols.find(name);
        if (it != symbols.end()) return it->second;
        if (parent) return parent->lookup(name);
        return {TypeKind::ERROR, false, false};  // 未找到
    }
};

// 类型检查：二元运算
TypeInfo checkBinaryOp(TypeInfo left, TypeInfo right, char op) {
    // 整数 + 整数 = 整数
    if (left.kind == TypeKind::INT && right.kind == TypeKind::INT) {
        if (op == '+' || op == '-' || op == '*' || op == '/') {
            return {TypeKind::INT, false, false};
        }
    }
    // 浮点 + 整数 = 浮点（隐式转换）
    if ((left.kind == TypeKind::FLOAT || right.kind == TypeKind::FLOAT)
        && (op == '+' || op == '-' || op == '*' || op == '/')) {
        return {TypeKind::FLOAT, false, false};
    }
    // 类型不匹配
    return {TypeKind::ERROR, false, false};
}
```

### 5. 阶段四：中间代码生成

将AST转换为中间表示（IR），这是编译器中最重要的抽象之一。

```
源代码：int add(int a, int b) { return a + b; }

AST:
    FunctionDecl "add"
    ├── ParmDecl "a" (int)
    ├── ParmDecl "b" (int)
    └── ReturnStmt
        └── BinaryExpr "+"
            ├── DeclRef "a"
            └── DeclRef "b"

LLVM IR:
    define i32 @add(i32 %a, i32 %b) {
    entry:
        %result = add i32 %a, %b
        ret i32 %result
    }
```

### 6. 阶段五：代码优化

```
常见优化技术：

1. 常量传播（Constant Propagation）
   优化前：x = 42; y = x + 1;
   优化后：x = 42; y = 43;

2. 常量折叠（Constant Folding）
   优化前：y = 3 + 4;
   优化后：y = 7;

3. 死代码消除（Dead Code Elimination）
   优化前：x = 1; x = 2; return x;  // x=1永远不会被使用
   优化后：x = 2; return x;

4. 公共子表达式消除（CSE）
   优化前：a = b + c; d = b + c;
   优化后：a = b + c; d = a;

5. 循环不变量外提（LICM）
   优化前：for(i=0;i<n;i++) { x = y + z; arr[i] = x * i; }
   优化后：x = y + z; for(i=0;i<n;i++) { arr[i] = x * i; }

6. 内联（Inlining）
   优化前：r = add(a, b);  // 函数调用开销
   优化后：r = a + b;      // 直接展开

7. 循环展开（Loop Unrolling）
   优化前：for(i=0;i<4;i++) sum += a[i];
   优化后：sum += a[0]; sum += a[1]; sum += a[2]; sum += a[3];
```

### 7. 阶段六：目标代码生成

```
代码生成的主要任务：
├── 指令选择 — 选择最优的机器指令
├── 寄存器分配 — 将虚拟寄存器映射到物理寄存器
├── 指令调度 — 重排指令以利用流水线
└── 栈帧布局 — 管理局部变量和调用栈

示例：x = a + b 的代码生成

IR:  %x = add i32 %a, %b

x86_64汇编：
    movl (%rbp-4), %eax    ; 加载a到eax
    addl (%rbp-8), %eax    ; 加上b
    movl %eax, (%rbp-12)   ; 存储到x

ARM64汇编：
    ldr w0, [sp, #4]       ; 加载a
    ldr w1, [sp, #8]       ; 加载b
    add w0, w0, w1         ; 相加
    str w0, [sp, #12]      ; 存储到x
```

## 2. 前端/优化器/后端三段式架构

### 1. 为什么要三段式

```
传统单体编译器（如早期GCC）：
  C源码 → [C前端+优化器+x86后端] → x86机器码
  C++源码 → [C++前端+优化器+x86后端] → x86机器码
  └── 每增加一种语言或一种平台，都要写一套完整的编译器
  └── M种语言 × N种平台 = M×N 套编译器

三段式编译器（如LLVM）：
  C前端 ──→ ┐
  C++前端 ─→ ┤→ [通用优化器] → x86后端 ──→ ┐
  Rust前端 ─→ ┘                ARM后端 ──→  ├→ 机器码
                               RISC-V后端 → ┘
  └── M种语言 + N种平台 = M+N 套组件
  └── 新语言只需写前端，自动支持所有后端
  └── 新平台只需写后端，自动支持所有语言
```

### 2. 前端（Frontend）

```
前端的职责：
├── 词法分析 — 字符流 → Token流
├── 语法分析 — Token流 → AST
├── 语义分析 — 类型检查、作用域解析
└── IR生成 — AST → 中间表示

前端是语言相关的：
  Clang → C/C++/ObjC → LLVM IR
  rustc → Rust → LLVM IR
  swiftc → Swift → LLVM IR/SIL
  Flang → Fortran → LLVM IR
```

### 3. 优化器（Optimizer / Middle-end）

```
优化器的职责：
├── 在IR层面进行与语言和平台无关的优化
├── 分析Pass — 收集信息（活跃变量、依赖关系等）
└── 变换Pass — 改写IR（常量传播、内联、向量化等）

优化器的关键特性：
  └── 与语言无关 — 不管源语言是C还是Rust
  └── 与平台无关 — 不管目标是x86还是ARM
  └── 可组合 — Pass可以自由组合和排序
  └── 可扩展 — 可以添加自定义Pass
```

### 4. 后端（Backend / Code Generator）

```
后端的职责：
├── 指令选择 — IR → 目标机器指令
├── 寄存器分配 — 虚拟寄存器 → 物理寄存器
├── 指令调度 — 重排指令以提高流水线效率
├── 栈帧布局 — 管理局部变量和参数
└── 生成目标文件 — 输出.o/.obj文件

后端是平台相关的：
  x86后端 → 生成x86_64机器码
  ARM后端 → 生成AArch64机器码
  RISC-V后端 → 生成RISC-V机器码
  WebAssembly后端 → 生成WASM字节码
```

## 3. 解释器 vs 编译器 vs JIT

### 1. 三种执行方式对比

| 维度 | 解释器 | 编译器（AOT） | JIT编译器 |
|------|--------|--------------|-----------|
| 执行方式 | 逐行解释执行 | 先编译再执行 | 运行时编译+执行 |
| 启动速度 | 快（无需编译） | 慢（需要编译） | 中等 |
| 峰值性能 | 低 | 高 | 可能更高 |
| 内存占用 | 低 | 低 | 高（需保存编译结果） |
| 动态优化 | 无 | 无 | 有（运行时profile） |
| 代表 | Python、Ruby | C/C++、Rust | JVM、V8、PyTorch |

### 2. 解释器的工作方式

```python
# Python解释器逐行执行
x = 42          # 解释器：创建一个整数对象42，绑定到名称x
y = x + 1       # 解释器：查找x的值，执行加法，绑定到y
print(y)        # 解释器：查找y的值，调用print函数

# 解释器内部伪代码
def interpret(ast):
    for node in ast:
        if node.type == 'assignment':
            value = evaluate(node.expr)
            env[node.name] = value
        elif node.type == 'print':
            value = evaluate(node.expr)
            print(value)
```

### 3. JIT编译器的工作方式

```
JIT编译器的核心思想：在运行时将热点代码编译为机器码

执行流程：
  字节码/IR
      │
      ▼
  解释执行（收集profile信息）
      │
      ├── 发现热点代码（频繁执行的代码）
      │
      ▼
  JIT编译热点代码为机器码
      │
      ▼
  后续执行直接运行机器码（更快）
      │
      ├── 运行时收集更多profile
      │
      ▼
  重新优化（去优化+再编译）

JIT的优势：
  └── 可以利用运行时信息进行优化
  └── 例如：虚函数调用可以内联（因为知道实际类型）
  └── 例如：分支预测可以更精确（因为知道实际走向）
```

### 4. 实际性能对比

```cpp
// 计算斐波那契数列——对比不同执行方式的性能

#include <cstdio>
#include <chrono>

// 递归斐波那契
int fib(int n) {
    if (n <= 1) return n;
    return fib(n - 1) + fib(n - 2);
}

int main() {
    auto start = std::chrono::high_resolution_clock::now();
    int result = fib(40);
    auto end = std::chrono::high_resolution_clock::now();

    auto ms = std::chrono::duration_cast<std::chrono::milliseconds>(end - start);
    printf("fib(40) = %d, 耗时: %lld ms\n", result, ms.count());
    return 0;
}

// 典型性能对比（fib(40)）：
// ┌──────────────────┬──────────┐
// │ 执行方式          │ 耗时     │
// ├──────────────────┼──────────┤
// │ C (gcc -O2)      │ ~300ms   │
// │ Python 3         │ ~30s     │
// │ PyPy (JIT)       │ ~500ms   │
// │ Java (JIT热身后) │ ~350ms   │
// │ Node.js (V8 JIT) │ ~400ms   │
// └──────────────────┴──────────┘
```

## 4. 编译器设计哲学

### 1. 正确性优先

```
编译器的第一原则：生成的代码必须正确

优化不能改变程序的可观测行为（as-if规则）：
  └── 优化后的程序必须产生与未优化程序相同的结果
  └── 除非结果属于未定义行为

例外情况：
  └── fast-math选项可以改变浮点语义（牺牲精度换速度）
  └── 严格别名规则允许更激进的优化
```

### 2. 分层抽象

```
编译器的每一层都只关心自己的抽象层次：

字符 → Token → AST → IR → 机器指令

  └── 词法分析器不知道语法规则
  └── 语法分析器不知道语义规则
  └── 优化器不知道目标平台
  └── 代码生成器不知道源语言

好处：
  └── 每层可以独立开发和测试
  └── 修改一层不影响其他层
  └── 新语言/新平台只需替换对应层
```

### 3. 优化是可选的，正确是必须的

```cpp
// 编译器的优化等级
// -O0  不优化，最快编译，最易调试
// -O1  基本优化
// -O2  标准优化（推荐发布版本）
// -O3  激进优化（可能增大代码体积）
// -Os  优化代码大小
// -Oz  更激进地优化代码大小

// 优化可能带来的问题
int main() {
    int x = 42;
    int* p = &x;
    // -O0: x的值在内存中，通过*p可以修改
    // -O2: x可能被优化到寄存器中，*p可能不生效
    // 这就是为什么volatile关键字存在
    return 0;
}
```

### 4. 编译速度 vs 优化质量

```
编译器设计中的经典权衡：

编译速度 ←────────────→ 优化质量
   │                        │
   │ -O0                    │ -O3
   │ 快速编译               │ 慢速编译
   │ 开发时使用             │ 发布时使用
   │ 调试友好               │ 最高性能
   │                        │
   │ 增量编译 ←→ 全量编译   │
   │ 分布式编译 ←→ 本地编译 │

现代编译器的应对策略：
├── 增量编译 — 只重新编译修改过的文件
├── 分布式编译 — distcc/ccache/icecc
├── 模块化 — C++20 Modules减少头文件重复解析
├── PCH — 预编译头文件
└── Unity Build — 合并源文件减少编译单元
```

### 5. 诊断信息的重要性

```
好的错误信息 = 好的开发体验

编译器的诊断能力分级：
├── 错误（Error）— 必须修复，否则无法编译
├── 警告（Warning）— 可能有问题，建议修复
├── 备注（Note）— 附加信息，帮助理解错误
└── 提示（Remark）— 优化建议，如内联失败原因

Clang的设计哲学：
  └── 精确指出错误位置
  └── 提供修复建议
  └── 解释为什么出错
  └── 关联相关代码位置

示例：
  error: no member named 'push_bakc' in 'std::vector<int>'
      v.push_bakc(42);
        ^~~~~~~~~
  note: corrected to 'push_back'
      v.push_back(42);
        ^~~~~~~~~
        push_back
```

## 5. 编译器的实际观察

### 1. 用Clang观察编译各阶段

```bash
# 查看预处理结果
clang -E hello.cpp -o hello.i

# 查看Token
clang -dump-tokens hello.cpp

# 查看AST
clang -Xclang -ast-dump -fsyntax-only hello.cpp

# 查看LLVM IR（未优化）
clang -O0 -S -emit-llvm hello.cpp -o hello_O0.ll

# 查看LLVM IR（优化后）
clang -O2 -S -emit-llvm hello.cpp -o hello_O2.ll

# 查看汇编代码
clang -S hello.cpp -o hello.s

# 查看目标文件
clang -c hello.cpp -o hello.o
objdump -d hello.o
```

### 2. 用GCC观察编译各阶段

```bash
# 预处理
gcc -E hello.cpp -o hello.i

# 编译到汇编
gcc -S hello.cpp -o hello.s

# 编译到目标文件
gcc -c hello.cpp -o hello.o

# 查看所有中间文件
gcc -save-temps hello.cpp -o hello
# 生成：hello.i, hello.s, hello.o, hello
```

## 6. 极简总结

| 阶段 | 输入 | 输出 | 核心任务 |
|------|------|------|---------|
| 词法分析 | 字符流 | Token流 | 切分单词 |
| 语法分析 | Token流 | AST | 构建语法树 |
| 语义分析 | AST | 标注的AST | 类型检查 |
| IR生成 | AST | IR | 生成中间表示 |
| 优化 | IR | 优化IR | 性能提升 |
| 代码生成 | 优化IR | 机器码 | 平台适配 |

**编译器 = 前端（语言相关）+ 优化器（通用）+ 后端（平台相关），三段式架构让M种语言×N种平台只需M+N套组件。**
