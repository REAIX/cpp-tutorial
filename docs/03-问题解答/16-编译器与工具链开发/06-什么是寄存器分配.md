# 什么是寄存器分配
> 📖 相关章节：[编译与链接](../../01-C语言/17-编译与链接.md)、[编译器原理](../../10-编译器与工具链开发/00-编译器原理概述.md)

> "一句话概括：寄存器分配是编译器后端最核心的问题——把程序中无限多的虚拟寄存器映射到有限多的物理寄存器上，分配不好就要频繁访问内存（spill），性能断崖式下降；图着色和线性扫描是两大经典算法，前者质量高但慢，后者快但质量略低。"

***

## 1. 寄存器分配的原理

### 1. 为什么需要寄存器分配

```
问题：
  └── 程序中有无限多的虚拟寄存器（IR中的%1, %2, %3...）
  └── 但CPU只有有限多的物理寄存器（x86-64只有16个通用寄存器）
  └── 必须把虚拟寄存器映射到物理寄存器

类比：
  虚拟寄存器 = 酒店客人（无限多）
  物理寄存器 = 酒店房间（有限多）
  寄存器分配 = 前台安排房间
  Spill      = 客房满了，客人只能住外面的旅馆（内存）

x86-64通用寄存器：
  ├── rax, rbx, rcx, rdx  — 通用
  ├── rsi, rdi             — 源/目标索引
  ├── rbp, rsp             — 基址/栈指针
  ├── r8-r15               — 扩展寄存器
  └── 总共16个，还要扣除被调用约定保留的

ARM64通用寄存器：
  ├── x0-x7    — 参数/返回值
  ├── x8       — 间接结果
  ├── x9-x15   — 临时寄存器
  ├── x16-x17  — 平台保留
  ├── x18      — 平台寄存器
  ├── x19-x28  — 被调用者保存
  ├── x29      — 帧指针
  ├── x30      — 链接寄存器
  └── sp       — 栈指针
  └── 可用的约26个，比x86宽裕
```

### 2. 寄存器分配在编译器中的位置

```
编译器后端的流程：

  LLVM IR
      │
      ▼
  指令选择（Instruction Selection）
      │  IR → 机器指令（使用虚拟寄存器）
      ▼
  ┌──────────────┐
  │ 寄存器分配    │ ← 我们在这里
  │ Register     │    虚拟寄存器 → 物理寄存器
  │ Allocation   │    分配不了的 → Spill到栈
  └──────┬───────┘
         │
         ▼
  指令调度（Instruction Scheduling）
      │  重排指令以利用流水线
      ▼
  机器码输出
```

### 3. 干扰图（Interference Graph）

```
寄存器分配的核心数据结构是干扰图：

规则：如果两个虚拟寄存器在同一时刻都是"活跃的"（live），
      它们就不能共享同一个物理寄存器，在图中连一条边。

示例：
  %1 = load a       ; %1活跃开始
  %2 = load b       ; %2活跃开始，%1也活跃 → %1和%2干扰
  %3 = add %1, %2   ; %3活跃开始，%1和%2可能不再活跃
  %4 = load c       ; %4活跃开始，%3也活跃 → %3和%4干扰
  store %3, x       ; %3活跃结束
  store %4, y       ; %4活跃结束

干扰图：
  %1 ─── %2     （%1和%2同时活跃）
  %3 ─── %4     （%3和%4同时活跃）

如果只有2个物理寄存器(R1, R2)：
  %1 → R1, %2 → R2  （不同颜色）
  %3 → R1, %4 → R2  （可以复用，因为%1和%2已经不活跃了）
```

## 2. 图着色算法

### 1. 图着色与寄存器分配的对应

```
图着色问题：
  └── 给图的每个节点着色
  └── 相邻节点不能同色
  └── 最少使用几种颜色 = 图的色数

寄存器分配 = 图着色：
  └── 节点 = 虚拟寄存器
  └── 边   = 干扰关系（同时活跃）
  └── 颜色 = 物理寄存器
  └── 色数 ≤ 物理寄存器数量

如果色数 > 物理寄存器数量：
  └── 必须spill——把某些虚拟寄存器的值存到内存
  └── 选择spill哪个是关键决策
```

### 2. Chaitin-Briggs图着色算法

```
算法步骤：

1. 构建干扰图
   └── 计算每个虚拟寄存器的活跃区间
   └── 同时活跃的寄存器之间连边

2. 简化（Simplify）
   └── 找到度数 < K 的节点（K = 物理寄存器数量）
   └── 从图中移除该节点，压入栈
   └── 重复直到图为空或所有节点度数 ≥ K

3. 选择溢出（Spill）
   └── 如果所有节点度数 ≥ K，选择一个节点spill
   └── 启发式：选择度数最大 / 使用频率最低的节点
   └── 从图中移除该节点，压入栈
   └── 回到步骤2

4. 选择（Select）
   └── 从栈中依次弹出节点
   └── 为每个节点分配一个与邻居不同的颜色（寄存器）
   └── 如果没有可用颜色，该节点必须spill

5. 重写（Rewrite）
   └── 为spill的节点插入load/store指令
   └── 重新构建干扰图，重新分配
```

### 3. 图着色算法示例

```
假设有3个物理寄存器(R1, R2, R3)，干扰图如下：

    v1 ─── v2
    │       │
    v3 ─── v4
     \     /
      v5

干扰关系：
  v1-v2, v1-v3, v2-v4, v3-v4, v3-v5, v4-v5

步骤1：简化
  v1的度数=2 < 3，移除v1，压栈
  v2的度数=1 < 3，移除v2，压栈
  剩余：v3-v4, v3-v5, v4-v5
  v5的度数=2 < 3，移除v5，压栈
  v3的度数=1 < 3，移除v3，压栈
  v4的度数=0 < 3，移除v4，压栈

步骤2：选择（从栈中弹出并着色）
  v4 → R1（无邻居，任意颜色）
  v3 → R2（与v4不同）
  v5 → R1（与v3不同，v4已不在图中）
  v2 → R1（与v1不在图中，v4已着色R1但v2和v4无干扰...）

  实际分配：
  v4 → R1
  v3 → R2
  v5 → R3（与v3(R2)和v4(R1)都不同）
  v2 → R2（与v4(R1)不同即可，v1不在图中）
  v1 → R1（与v2(R2)和v3(R2)不同即可）

  最终分配：
  v1 → R1, v2 → R2, v3 → R2, v4 → R1, v5 → R3
  只用了3个寄存器，无需spill
```

### 4. 图着色算法的代码框架

```cpp
#include <vector>
#include <unordered_map>
#include <unordered_set>
#include <stack>
#include <queue>

class GraphColoringAllocator {
private:
    int numRegisters;  // 物理寄存器数量

    // 干扰图
    std::unordered_map<int, std::unordered_set<int>> interferenceGraph;

    // 活跃区间
    struct LiveRange {
        int start;
        int end;
        int spillCost;  // 溢出代价
    };
    std::unordered_map<int, LiveRange> liveRanges;

public:
    GraphColoringAllocator(int k) : numRegisters(k) {}

    // 添加干扰边
    void addInterference(int v1, int v2) {
        interferenceGraph[v1].insert(v2);
        interferenceGraph[v2].insert(v1);
    }

    // 执行图着色分配
    std::unordered_map<int, int> allocate() {
        std::unordered_map<int, int> assignment;
        std::stack<int> stack;
        auto graph = interferenceGraph;  // 工作副本

        // 阶段1：简化
        bool changed = true;
        while (changed) {
            changed = false;
            for (auto& [node, neighbors] : graph) {
                if (assignment.count(node)) continue;
                if (neighbors.size() < static_cast<size_t>(numRegisters)) {
                    // 度数 < K，可以安全移除
                    stack.push(node);
                    assignment[node] = -1;  // 标记为已处理
                    // 从邻居的邻接表中移除
                    for (int neighbor : neighbors) {
                        graph[neighbor].erase(node);
                    }
                    changed = true;
                    break;
                }
            }
        }

        // 阶段2：处理度数 >= K的节点（spill）
        for (auto& [node, neighbors] : graph) {
            if (assignment.count(node) && assignment[node] == -1) continue;
            // 选择spill代价最低的节点
            stack.push(node);
            assignment[node] = -1;
            for (int neighbor : neighbors) {
                graph[neighbor].erase(node);
            }
        }

        // 阶段3：选择（着色）
        assignment.clear();
        while (!stack.empty()) {
            int node = stack.top();
            stack.pop();

            // 找出邻居已使用的颜色
            std::unordered_set<int> usedColors;
            for (int neighbor : interferenceGraph[node]) {
                if (assignment.count(neighbor)) {
                    usedColors.insert(assignment[neighbor]);
                }
            }

            // 分配第一个可用颜色
            int color = -1;
            for (int c = 0; c < numRegisters; c++) {
                if (usedColors.find(c) == usedColors.end()) {
                    color = c;
                    break;
                }
            }

            if (color == -1) {
                // 需要spill
                // 在实际编译器中，这里需要插入load/store
                assignment[node] = -2;  // 标记为spilled
            } else {
                assignment[node] = color;
            }
        }

        return assignment;
    }
};
```

## 3. 线性扫描

### 1. 线性扫描算法

```
线性扫描的核心思想：
  └── 不构建干扰图（图着色的瓶颈）
  └── 直接按活跃区间的起始位置排序
  └── 一次线性扫描完成分配

算法步骤：
  1. 计算所有虚拟寄存器的活跃区间 [start, end]
  2. 按start排序
  3. 从左到右扫描：
     ├── 新区间开始：分配一个空闲寄存器
     ├── 区间结束：释放寄存器
     └── 无空闲寄存器：spill最远结束的区间

优势：
  └── 时间复杂度 O(n log n)（排序）
  └── 比图着色快得多
  └── 适合JIT编译器（编译时间敏感）

劣势：
  └── 分配质量不如图着色
  └── 可能spill更多
```

### 2. 线性扫描示例

```
活跃区间（已按start排序）：
  v1: [1, 10]
  v2: [2, 5]
  v3: [3, 8]
  v4: [6, 12]
  v5: [9, 15]

假设3个物理寄存器(R1, R2, R3)：

扫描过程：
  位置1: v1开始 → R1 = v1
  位置2: v2开始 → R2 = v2
  位置3: v3开始 → R3 = v3
  位置5: v2结束 → R2空闲
  位置6: v4开始 → R2 = v4
  位置8: v3结束 → R3空闲
  位置9: v5开始 → R3 = v5
  位置10: v1结束 → R1空闲
  位置12: v4结束 → R2空闲
  位置15: v5结束 → R3空闲

结果：
  v1 → R1, v2 → R2, v3 → R3, v4 → R2, v5 → R3
  无需spill
```

### 3. 线性扫描的实现

```cpp
#include <vector>
#include <algorithm>
#include <unordered_map>

struct LiveInterval {
    int vreg;       // 虚拟寄存器编号
    int start;      // 活跃区间起始
    int end;        // 活跃区间结束
    int physReg;    // 分配的物理寄存器（-1表示未分配）
};

class LinearScanAllocator {
private:
    int numRegisters;

public:
    explicit LinearScanAllocator(int k) : numRegisters(k) {}

    std::unordered_map<int, int> allocate(std::vector<LiveInterval>& intervals) {
        // 按起始位置排序
        std::sort(intervals.begin(), intervals.end(),
                  [](const LiveInterval& a, const LiveInterval& b) {
                      return a.start < b.start;
                  });

        // 活跃列表（当前正在使用寄存器的区间）
        std::vector<LiveInterval*> active;
        // 空闲寄存器列表
        std::vector<int> freeRegs;
        for (int i = 0; i < numRegisters; i++) {
            freeRegs.push_back(i);
        }

        for (auto& interval : intervals) {
            // 过期：移除已结束的区间
            expireOldIntervals(active, freeRegs, interval.start);

            if (freeRegs.empty()) {
                // 没有空闲寄存器，需要spill
                spillAtInterval(active, interval);
            } else {
                // 分配一个空闲寄存器
                int reg = freeRegs.back();
                freeRegs.pop_back();
                interval.physReg = reg;
                active.push_back(&interval);
            }
        }

        // 收集分配结果
        std::unordered_map<int, int> result;
        for (const auto& interval : intervals) {
            result[interval.vreg] = interval.physReg;
        }
        return result;
    }

private:
    void expireOldIntervals(std::vector<LiveInterval*>& active,
                            std::vector<int>& freeRegs,
                            int currentPos) {
        // 移除已结束的区间
        auto it = std::remove_if(active.begin(), active.end(),
            [&](LiveInterval* interval) {
                if (interval->end < currentPos) {
                    freeRegs.push_back(interval->physReg);
                    return true;
                }
                return false;
            });
        active.erase(it, active.end());
    }

    void spillAtInterval(std::vector<LiveInterval*>& active,
                         LiveInterval& interval) {
        // 找到结束最晚的活跃区间
        auto longestIt = std::max_element(active.begin(), active.end(),
            [](LiveInterval* a, LiveInterval* b) {
                return a->end < b->end;
            });

        if ((*longestIt)->end > interval.end) {
            // Spill最长的区间，把它的寄存器给当前区间
            interval.physReg = (*longestIt)->physReg;
            (*longestIt)->physReg = -1;  // 标记为spilled
            *longestIt = &interval;      // 替换活跃列表
        } else {
            // 当前区间最晚结束，spill当前区间
            interval.physReg = -1;  // 标记为spilled
        }
    }
};
```

## 4. 活跃变量分析

### 1. 什么是活跃变量

```
活跃变量（Live Variable）：
  └── 一个变量在程序的某个点"活跃"，意味着这个点的值将来还会被使用
  └── 活跃变量决定了哪些虚拟寄存器可以共享物理寄存器

定义：
  def(v) — 变量v被定义（赋值）的点
  use(v) — 变量v被使用的点
  live-in(B) — 在基本块B入口处活跃的变量集合
  live-out(B) — 在基本块B出口处活跃的变量集合

计算规则（数据流方程）：
  live-in(B) = use(B) ∪ (live-out(B) - def(B))
  live-out(B) = ∪ live-in(S)  对所有后继基本块S

  其中：
  use(B) — 在B中被使用、之前未被定义的变量
  def(B) — 在B中被定义的变量
```

### 2. 活跃变量分析示例

```
基本块B1：
  t1 = a + b        ; def: t1
  t2 = c * d        ; def: t2
  t3 = t1 + t2      ; use: t1, t2; def: t3
  return t3          ; use: t3

use(B1) = {a, b, c, d}  （被使用但之前未定义的）
def(B1) = {t1, t2, t3}  （被定义的）

如果B1的后继B2的live-in = {t3}：
  live-out(B1) = {t3}
  live-in(B1) = {a, b, c, d} ∪ ({t3} - {t1, t2, t3})
              = {a, b, c, d} ∪ {}
              = {a, b, c, d}

活跃区间：
  a: [B1入口, t1=a+b]
  b: [B1入口, t1=a+b]
  c: [B1入口, t2=c*d]
  d: [B1入口, t2=c*d]
  t1: [t1定义, t3=t1+t2]
  t2: [t2定义, t3=t1+t2]
  t3: [t3定义, return t3]
```

### 3. 活跃变量分析的实现

```cpp
#include <unordered_map>
#include <unordered_set>
#include <vector>

struct BasicBlock {
    std::string name;
    std::unordered_set<std::string> def;    // 被定义的变量
    std::unordered_set<std::string> use;    // 被使用（之前未定义）的变量
    std::vector<BasicBlock*> successors;    // 后继基本块
    std::unordered_set<std::string> liveIn;  // 入口活跃变量
    std::unordered_set<std::string> liveOut; // 出口活跃变量
};

class LivenessAnalysis {
private:
    std::vector<BasicBlock*> blocks;

public:
    explicit LivenessAnalysis(std::vector<BasicBlock*> b) : blocks(std::move(b)) {}

    // 迭代求解活跃变量
    void analyze() {
        bool changed = true;
        while (changed) {
            changed = false;
            // 逆序遍历基本块
            for (auto it = blocks.rbegin(); it != blocks.rend(); ++it) {
                BasicBlock* B = *it;

                // 计算live-out
                std::unordered_set<std::string> newLiveOut;
                for (BasicBlock* succ : B->successors) {
                    newLiveOut.insert(succ->liveIn.begin(), succ->liveIn.end());
                }

                // 计算live-in
                std::unordered_set<std::string> newLiveIn = B->use;
                for (const auto& v : newLiveOut) {
                    if (B->def.find(v) == B->def.end()) {
                        newLiveIn.insert(v);
                    }
                }

                // 检查是否变化
                if (newLiveIn != B->liveIn || newLiveOut != B->liveOut) {
                    changed = true;
                    B->liveIn = std::move(newLiveIn);
                    B->liveOut = std::move(newLiveOut);
                }
            }
        }
    }
};
```

## 5. 寄存器分配对性能的影响

### 1. Spill的代价

```
Spill = 将寄存器中的值存到内存（栈），需要时再加载回来

Spill的代价：
  ┌──────────────────────────────────────────┐
  │  操作          │ 延迟（约）  │ 说明       │
  │  ────────────┼───────────┼────────── │
  │  寄存器访问    │ ~1周期     │ 最快       │
  │  L1缓存访问    │ ~4周期     │ 快         │
  │  L2缓存访问    │ ~12周期    │ 中等       │
  │  L3缓存访问    │ ~40周期    │ 慢         │
  │  主存访问      │ ~200周期   │ 很慢       │
  └──────────────────────────────────────────┘

一次spill = 一次store + 一次load ≈ 数十到数百周期

影响程度：
  └── 少量spill：性能下降5-10%
  └── 大量spill：性能下降50%以上
  └── 关键路径上的spill：性能下降更严重
```

### 2. 实际性能对比

```cpp
// 演示寄存器压力对性能的影响
#include <cstdio>
#include <chrono>

// 低寄存器压力版本——使用少量变量
void low_pressure(double* a, double* b, double* c, int n) {
    for (int i = 0; i < n; i++) {
        c[i] = a[i] + b[i];  // 只需3个寄存器
    }
}

// 高寄存器压力版本——使用大量变量
void high_pressure(double* a, double* b, double* c, int n) {
    // 20个临时变量，超出x86可用寄存器数量
    double t1, t2, t3, t4, t5, t6, t7, t8;
    double t9, t10, t11, t12, t13, t14, t15, t16;
    double t17, t18, t19, t20;

    for (int i = 0; i < n; i++) {
        t1 = a[i] * 1.1;   t2 = b[i] * 1.2;
        t3 = a[i] * 1.3;   t4 = b[i] * 1.4;
        t5 = a[i] * 1.5;   t6 = b[i] * 1.6;
        t7 = a[i] * 1.7;   t8 = b[i] * 1.8;
        t9 = t1 + t2;      t10 = t3 + t4;
        t11 = t5 + t6;     t12 = t7 + t8;
        t13 = t9 + t10;    t14 = t11 + t12;
        t15 = t13 + t14;
        // ... 更多计算 ...
        c[i] = t15;
    }
}

int main() {
    const int N = 10000000;
    auto* a = new double[N];
    auto* b = new double[N];
    auto* c = new double[N];

    // 低寄存器压力
    auto start = std::chrono::high_resolution_clock::now();
    low_pressure(a, b, c, N);
    auto end = std::chrono::high_resolution_clock::now();
    printf("低寄存器压力: %lld ms\n",
           std::chrono::duration_cast<std::chrono::milliseconds>(end - start).count());

    // 高寄存器压力（可能触发spill）
    start = std::chrono::high_resolution_clock::now();
    high_pressure(a, b, c, N);
    end = std::chrono::high_resolution_clock::now();
    printf("高寄存器压力: %lld ms\n",
           std::chrono::duration_cast<std::chrono::milliseconds>(end - start).count());

    delete[] a; delete[] b; delete[] c;
    return 0;
}
```

### 3. 减少寄存器压力的技巧

```
1. 减少同时活跃的变量数量
   └── 缩短变量的生命周期
   └── 尽早结束变量的使用

2. 重用变量
   └── 同一个变量名在不同阶段使用
   └── 减少同时活跃的变量数

3. 分解复杂表达式
   └── 将大表达式拆分为多个小表达式
   └── 让编译器更容易分配寄存器

4. 使用局部变量而非全局变量
   └── 局部变量可以被分配到寄存器
   └── 全局变量可能每次都需要从内存加载

5. 避免取地址操作
   └── 取地址的变量不能分配到寄存器
   └── 因为寄存器没有地址

6. 利用循环展开
   └── 适度的循环展开可以增加指令级并行
   └── 但过度展开会增加寄存器压力
```

## 6. 现代寄存器分配技术

### 1. 基于SSA的寄存器分配

```
SSA形式对寄存器分配的好处：
  └── SSA中的变量只赋值一次，活跃区间更短
  └── 干扰图更稀疏，更容易着色
  └── 可以直接从SSA的def-use链计算活跃信息

SSA的寄存器分配优势：
  ┌──────────────┬──────────────┬──────────────┐
  │ 维度          │ 非SSA        │ SSA          │
  │ ────────────┼─────────────┼───────────── │
  │ 干扰图大小    │ 大           │ 小           │
  │ 着色难度      │ 难           │ 容易         │
  │ 活跃区间      │ 长           │ 短           │
  │ 合并机会      │ 少           │ 多           │
  └──────────────┴──────────────┴──────────────┘
```

### 2. 分割式寄存器分配

```
分割式分配（Split Allocation）：
  └── 将寄存器分配问题分割为多个小问题
  └── 每个基本块/区域独立分配
  └── 在边界处插入移动指令

优势：
  └── 每个小问题更容易解决
  └── 编译时间更短
  └── 适合JIT编译器
```

### 3. LLVM的寄存器分配器

```
LLVM提供的寄存器分配器：

1. Greedy（默认）
   └── 基于优先级的图着色变体
   └── 使用线性扫描作为快速路径
   └── 对困难区域回退到图着色
   └── 质量和速度的平衡

2. Basic
   └── 简单的线性扫描
   └── 编译速度快
   └── 分配质量较低

3. PBQP（Partitioned Boolean Quadratic Programming）
   └── 基于PBQP的精确求解
   └── 质量最高
   └── 编译时间最长

选择寄存器分配器：
  clang -regalloc=greedy  hello.cpp   # 默认
  clang -regalloc=basic   hello.cpp   # 快速编译
  clang -regalloc=pbqp    hello.cpp   # 最高质量
```

## 7. 极简总结

| 概念 | 一句话 |
|------|--------|
| 寄存器分配 | 虚拟寄存器→物理寄存器——编译器后端的核心问题 |
| 干扰图 | 同时活跃的变量连边——分配问题的图论建模 |
| 图着色 | 经典算法——质量高但慢 |
| 线性扫描 | 快速算法——O(n log n)，适合JIT |
| Spill | 寄存器不够→存内存——性能杀手 |
| 活跃变量 | 变量从定义到最后一次使用——决定干扰关系 |
| SSA | 变量只赋值一次——简化寄存器分配 |
| Greedy | LLVM默认分配器——图着色+线性扫描混合 |

**寄存器分配 = 把无限虚拟寄存器映射到有限物理寄存器，图着色质量高但慢，线性扫描快但质量低，spill是性能杀手。**
