## 1. 静态分析的原理

### 1. 什么是静态分析

```
静态分析（Static Analysis）= 不执行代码，通过分析代码结构发现问题的技术

静态分析 vs 动态分析：
  ┌──────────────┬──────────────────┬──────────────────┐
  │ 维度          │ 静态分析          │ 动态分析          │
  │ ────────────┼─────────────────┼───────────────── │
  │ 是否运行代码  │ 否               │ 是               │
  │ 覆盖率       │ 高（可覆盖所有路径）│ 低（依赖测试用例） │
  │ 误报率       │ 较高              │ 低               │
  │ 漏报率       │ 较低              │ 较高             │
  │ 性能开销     │ 编译时            │ 运行时           │
  │ 代表工具     │ Clang-SA/CodeQL  │ ASan/Valgrind   │
  └──────────────┴──────────────────┴──────────────────┘

静态分析的能力：
  ├── 发现空指针解引用
  ├── 发现内存泄漏
  ├── 发现未初始化变量
  ├── 发现死锁
  ├── 发现安全漏洞（缓冲区溢出、SQL注入等）
  └── 发现代码规范违规
```

### 2. 静态分析的技术层次

```
静态分析的技术层次（从简单到复杂）：

1. 模式匹配（Pattern Matching）
   └── 用正则或AST匹配器搜索代码模式
   └── 速度快，但精度低
   └── 例如：搜索strcpy的使用

2. 数据流分析（Data Flow Analysis）
   └── 追踪数据在程序中的流动
   └── 中等精度，中等复杂度
   └── 例如：追踪变量是否可能为NULL

3. 符号执行（Symbolic Execution）
   └── 用符号值代替具体值执行程序
   └── 精度高，但路径爆炸问题
   └── 例如：KLEE、Clang Static Analyzer

4. 抽象解释（Abstract Interpretation）
   └── 在抽象域上近似计算程序行为
   └── 可扩展性好，精度取决于抽象域
   └── 例如：Polyspace、Astrée

5. 定理证明（Theorem Proving）
   └── 将程序正确性编码为逻辑公式
   └── 精度最高，但可扩展性差
   └── 例如：Frama-C、CBMC
```

## 2. 数据流分析

### 1. 数据流分析基础

```
数据流分析的核心概念：

1. 控制流图（CFG）
   └── 程序的执行路径图
   └── 节点 = 基本块，边 = 控制流

2. 数据流值
   └── 在每个程序点维护的信息
   └── 例如：变量是否可能为NULL

3. 转移函数
   └── 描述指令如何改变数据流值
   └── 例如：x = NULL → x可能为NULL

4. 汇合运算
   └── 多条路径汇合时如何合并数据流值
   └── 例如：路径1说x可能为NULL，路径2说x不为NULL → x可能为NULL
```

### 2. 常见的数据流分析

```
1. 到达定义分析（Reaching Definitions）
   └── 哪些变量定义可以到达某个使用点
   └── 用于：常量传播、未定义变量检测

2. 活跃变量分析（Live Variable Analysis）
   └── 变量在某个点之后是否还会被使用
   └── 用于：寄存器分配、死代码消除

3. 可用表达式分析（Available Expressions）
   └── 表达式在某个点是否已经计算过
   └── 用于：公共子表达式消除

4. 非常量传播（Constant Propagation）
   └── 变量在某个点是否为常量
   └── 用于：常量折叠、条件编译

5. 空指针分析（Null Pointer Analysis）
   └── 指针在某个点是否可能为NULL
   └── 用于：空指针解引用检测
```

### 3. 空指针分析示例

```cpp
// 空指针分析——追踪指针是否可能为NULL

#include <unordered_map>
#include <unordered_set>
#include <string>

enum class NullState {
    DEFINITELY_NULL,    // 一定为NULL
    POSSIBLY_NULL,      // 可能为NULL
    NOT_NULL            // 一定不为NULL
};

// 合并两个状态（路径汇合时）
NullState merge(NullState a, NullState b) {
    if (a == b) return a;
    return NullState::POSSIBLY_NULL;  // 不一致 → 可能
}

// 转移函数：根据语句更新状态
class NullPointerAnalysis {
private:
    // 变量 → 空指针状态
    std::unordered_map<std::string, NullState> state;

public:
    // 处理赋值语句
    void processAssignment(const std::string& var, const std::string& value) {
        if (value == "NULL" || value == "nullptr" || value == "0") {
            state[var] = NullState::DEFINITELY_NULL;
        } else if (value.find("malloc") != std::string::npos ||
                   value.find("new") != std::string::npos) {
            state[var] = NullState::POSSIBLY_NULL;  // 分配可能失败
        } else {
            state[var] = NullState::NOT_NULL;
        }
    }

    // 处理条件检查
    void processCheck(const std::string& var, bool isNullCheck) {
        if (isNullCheck) {
            // if (var != NULL) → 在then分支中var不为NULL
            state[var] = NullState::NOT_NULL;
        } else {
            // if (var == NULL) → 在then分支中var为NULL
            state[var] = NullState::DEFINITELY_NULL;
        }
    }

    // 检查解引用是否安全
    bool isDerefSafe(const std::string& var) const {
        auto it = state.find(var);
        if (it == state.end()) return true;  // 未知变量，假设安全
        return it->second != NullState::DEFINITELY_NULL;
    }

    NullState getState(const std::string& var) const {
        auto it = state.find(var);
        return it != state.end() ? it->second : NullState::NOT_NULL;
    }
};
```

### 4. 数据流分析的迭代框架

```cpp
// 通用的数据流分析框架
#include <vector>
#include <unordered_map>
#include <functional>

template<typename DataFlowValue>
class DataFlowFramework {
private:
    // 基本块
    struct BasicBlock {
        std::string name;
        std::vector<BasicBlock*> predecessors;
        std::vector<BasicBlock*> successors;
        DataFlowValue inValue;   // 入口值
        DataFlowValue outValue;  // 出口值
    };

    std::vector<BasicBlock*> blocks;
    std::function<DataFlowValue(const DataFlowValue&, const std::string&)> transfer;
    std::function<DataFlowValue(const DataFlowValue&, const DataFlowValue&)> meet;
    DataFlowValue initValue;
    bool isForward;  // 前向/后向分析

public:
    DataFlowFramework(
        std::function<DataFlowValue(const DataFlowValue&, const std::string&)> t,
        std::function<DataFlowValue(const DataFlowValue&, const DataFlowValue&)> m,
        DataFlowValue init,
        bool forward)
        : transfer(t), meet(m), initValue(init), isForward(forward) {}

    // 迭代求解
    void solve() {
        // 初始化
        for (auto* B : blocks) {
            B->inValue = initValue;
            B->outValue = initValue;
        }

        bool changed = true;
        while (changed) {
            changed = false;
            for (auto* B : (isForward ? blocks : std::vector<BasicBlock*>(blocks.rbegin(), blocks.rend()))) {
                // 计算入口值（前向：汇合前驱的出口值）
                if (isForward) {
                    DataFlowValue newIn = initValue;
                    for (auto* pred : B->predecessors) {
                        newIn = meet(newIn, pred->outValue);
                    }
                    B->inValue = newIn;
                }

                // 应用转移函数
                DataFlowValue newOut = transfer(B->inValue, B->name);
                if (newOut != B->outValue) {
                    B->outValue = newOut;
                    changed = true;
                }

                // 后向分析：计算出口值
                if (!isForward) {
                    DataFlowValue newOut2 = initValue;
                    for (auto* succ : B->successors) {
                        newOut2 = meet(newOut2, succ->inValue);
                    }
                    B->outValue = newOut2;
                }
            }
        }
    }
};
```

## 3. Clang Static Analyzer

### 1. CSA简介

```
Clang Static Analyzer（CSA）= Clang的静态分析引擎

特点：
  ├── 路径敏感 — 区分不同的执行路径
  ├── 过程间分析 — 跨函数追踪
  ├── 符号执行 — 用符号值执行程序
  └── 可扩展 — 可以编写自定义Checker

CSA的工作流程：
  源代码
      │
      ▼
  Clang前端 → AST
      │
      ▼
  CSA引擎 → ExplodedGraph（爆炸图）
      │  每个节点 = (程序点, 状态)
      │  每条边 = 状态转移
      ▼
  Checkers检查每个节点 → 报告Bug
```

### 2. 使用CSA


### 3. 编写自定义CSA Checker

```cpp
// 自定义Checker：检测整数除零
// 文件：DivZeroChecker.cpp

#include "clang/StaticAnalyzer/Core/Checker.h"
#include "clang/StaticAnalyzer/Core/PathSensitive/CheckerContext.h"
#include "clang/StaticAnalyzer/Core/BugReporter/BugType.h"
#include "clang/AST/Decl.h"

using namespace clang;
using namespace ento;

namespace {

class DivZeroChecker : public Checker<check::PreStmt<BinaryOperator>> {
private:
    std::unique_ptr<BugType> bugType;

public:
    DivZeroChecker() : bugType(std::make_unique<BugType>(
        this, "Division by zero", "Logic error")) {}

    // 在二元运算执行前检查
    void checkPreStmt(const BinaryOperator* B, CheckerContext& C) const {
        // 只检查除法运算
        BinaryOperator::Opcode op = B->getOpcode();
        if (op != BO_Div && op != BO_Rem &&
            op != BO_DivAssign && op != BO_RemAssign) {
            return;
        }

        // 获取右操作数（除数）
        const Expr* divisor = B->getRHS();
        ProgramStateRef state = C.getState();

        // 检查除数是否为0（符号执行）
        SVal divisorVal = C.getSVal(divisor);

        // 检查是否确定为0
        if (divisorVal.isZeroConstant()) {
            // 确定除零——报告Bug
            reportBug(B, C, "除数为0，将导致未定义行为");
            return;
        }

        // 检查是否可能为0（约束求解）
        if (auto divisorLoc = divisorVal.getAs<DefinedSVal>()) {
            ConstraintManager& CM = C.getConstraintManager();
            ProgramStateRef notZeroState, zeroState;
            std::tie(notZeroState, zeroState) = CM.assumeDual(state, *divisorLoc);

            if (zeroState && !notZeroState) {
                // 在当前路径上除数一定为0
                reportBug(B, C, "除数在此路径上一定为0");
            }
        }
    }

private:
    void reportBug(const BinaryOperator* B, CheckerContext& C,
                   const char* msg) const {
        // 生成错误报告
        ExplodedNode* errorNode = C.generateErrorNode();
        if (!errorNode) return;

        auto report = std::make_unique<PathSensitiveBugReport>(
            *bugType, msg, errorNode);
        report->addRange(B->getRHS()->getSourceRange());
        C.emitReport(std::move(report));
    }
};

} // anonymous namespace

// 注册Checker
void ento::registerDivZeroChecker(CheckerManager& mgr) {
    mgr.registerChecker<DivZeroChecker>();
}

bool ento::shouldRegisterDivZeroChecker(const CheckerManager& mgr) {
    return true;
}
```

```ql
import semmle.code.python.dataflow.TaintTracking

class SqlInjectionConfig extends TaintTracking::Configuration {
    SqlInjectionConfig() { this = "SqlInjectionConfig" }

    override predicate isSource(DataFlow::Node source) {
        // 用户输入是污点源
        exists(Call call |
            call.getFunc().(Attribute).getName() = "get" and
            source.asExpr() = call
        )
    }

    override predicate isSink(DataFlow::Node sink) {
        // SQL执行函数是污点汇
        exists(Call call |
            call.getFunc().(Attribute).getName() = "execute" and
            sink.asExpr() = call.getAnArgument()
        )
    }
}

from SqlInjectionConfig config, DataFlow::Node source, DataFlow::Node sink
where config.hasFlow(source, sink)
select sink, "SQL注入：用户输入直接传入SQL查询"
```

## 5. 自定义规则开发

### 1. 基于Clang AST的规则

```cpp
// 自定义规则：检测未检查的malloc返回值
#include "clang/AST/RecursiveASTVisitor.h"
#include "clang/ASTMatchers/ASTMatchFinder.h"
#include "clang/Frontend/FrontendAction.h"
#include "clang/Tooling/Tooling.h"

using namespace clang;
using namespace clang::ast_matchers;
using namespace clang::tooling;

class UncheckedMallocCallback : public MatchFinder::MatchCallback {
public:
    void run(const MatchFinder::MatchResult& result) override {
        const auto* call = result.Nodes.getNodeAs<CallExpr>("malloc_call");
        if (!call) return;

        // 检查返回值是否被检查
        const auto* parent = result.Context->getParents(*call)[0].get<Expr>();
        if (!parent) {
            // malloc返回值被丢弃
            DiagnosticsEngine& diag = result.Context->getDiagnostics();
            unsigned id = diag.getCustomDiagID(
                DiagnosticsEngine::Warning,
                "malloc返回值未检查，可能导致空指针解引用");
            diag.Report(call->getExprLoc(), id);
        }
    }
};

// 匹配模式
StatementMatcher MallocMatcher =
    callExpr(callee(functionDecl(hasName("malloc")))).bind("malloc_call");
```

### 2. 基于LLVM IR的规则

```cpp
// 基于LLVM IR的分析：检测未初始化内存读取
#include "llvm/IR/Function.h"
#include "llvm/IR/Instructions.h"
#include "llvm/IR/PassManager.h"
#include "llvm/Passes/PassPlugin.h"
#include "llvm/Support/raw_ostream.h"

using namespace llvm;

struct UninitReadPass : public PassInfoMixin<UninitReadPass> {
    PreservedAnalyses run(Function& F, FunctionAnalysisManager& AM) {
        // 追踪alloca的初始化状态
        std::unordered_map<Value*, bool> initialized;

        for (BasicBlock& BB : F) {
            for (Instruction& I : BB) {
                // alloca分配的内存初始未初始化
                if (auto* alloca = dyn_cast<AllocaInst>(&I)) {
                    initialized[alloca] = false;
                }
                // store初始化内存
                else if (auto* store = dyn_cast<StoreInst>(&I)) {
                    Value* ptr = store->getPointerOperand();
                    if (auto* alloca = dyn_cast<AllocaInst>(ptr)) {
                        initialized[alloca] = true;
                    }
                }
                // load读取内存——检查是否初始化
                else if (auto* load = dyn_cast<LoadInst>(&I)) {
                    Value* ptr = load->getPointerOperand();
                    if (auto* alloca = dyn_cast<AllocaInst>(ptr)) {
                        auto it = initialized.find(alloca);
                        if (it != initialized.end() && !it->second) {
                            errs() << "警告：可能读取未初始化的内存\n";
                            errs() << "  位置：" << *load << "\n";
                        }
                    }
                }
            }
        }

        return PreservedAnalyses::all();
    }

    static bool isRequired() { return true; }
};
```

## 7. 极简总结

| 概念 | 一句话 |
|------|--------|
| 静态分析 | 不运行代码找Bug——覆盖率高但有误报 |
| 数据流分析 | 追踪数据流动——空指针/未初始化检测 |
| 符号执行 | 用符号值执行——路径敏感但路径爆炸 |
| Clang SA | Clang静态分析器——路径敏感+符号执行 |
| CodeQL | 声明式查询语言——GitHub代码分析平台 |
| Checker | CSA的检查器——自定义Bug检测规则 |
| 污点追踪 | 追踪不可信数据——安全漏洞检测 |
| 误报/漏报 | 静态分析的永恒权衡——减少误报是关键 |

**静态分析 = 数据流分析/符号执行/模式匹配，Clang SA做路径敏感分析，CodeQL用声明式查询，自定义规则基于AST或IR。**
