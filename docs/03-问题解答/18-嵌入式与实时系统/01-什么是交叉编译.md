# 什么是交叉编译
> 📖 相关章节：[嵌入式概述](../../12-嵌入式与实时系统/00-嵌入式系统概述.md)

> **交叉编译就是"在A机器上编译，在B机器上运行"——你的开发电脑是x86，目标设备是ARM，编译出来的程序不能在你的电脑上跑，只能在目标设备上跑。**

***

### 1. 核心速览

**交叉编译（Cross Compilation）** 是指在一个平台（宿主机/Host）上编译生成另一个平台（目标机/Target）上运行的可执行文件。宿主机和目标机的CPU架构、操作系统、ABI可能完全不同——交叉编译工具链负责处理这些差异。

***

### 2. 生活类比

| 类比 | 说明 |
|------|------|
| 交叉编译 = 在中国做日本料理 | 厨房在中国（宿主机），菜品要符合日本口味（目标机） |
| 本地编译 = 在中国做中国菜 | 厨房和菜品在同一环境 |
| 工具链 = 厨具套装 | 不同菜系需要不同的厨具 |

**具体场景**：你在Windows/x86电脑上开发，编译出来的程序要运行在树莓派（ARM/Linux）上——这就是交叉编译。编译器必须生成ARM指令而非x86指令。

***

### 3. 交叉编译的原理

#### 3.1 为什么需要交叉编译

```
目标设备资源受限，无法自编译：
┌─────────────────────────────────────────────┐
│ 嵌入式设备（目标机）                          │
│ - CPU：ARM Cortex-M4 @ 48MHz                │
│ - RAM：128KB                                 │
│ - Flash：512KB                               │
│ - 无OS或极简RTOS                             │
│                                               │
│ → 无法运行编译器（GCC本身需要数百MB内存）     │
│ → 必须在开发机上编译                          │
└─────────────────────────────────────────────┘

开发电脑（宿主机）：
┌─────────────────────────────────────────────┐
│ - CPU：x86_64 @ 3GHz+                        │
│ - RAM：16GB+                                  │
│ - SSD：512GB+                                 │
│ - 完整开发环境                                │
│                                               │
│ → 运行交叉编译工具链                          │
│ → 生成目标设备的可执行文件                    │
└─────────────────────────────────────────────┘
```

#### 3.2 工具链命名规则

```
工具链命名格式：<arch>-<vendor>-<os>-<abi>

常见工具链前缀：
arm-none-eabi-        → ARM裸机（无OS），嵌入式最常用
arm-linux-gnueabihf-  → ARM Linux，硬浮点ABI
aarch64-linux-gnu-    → ARM64 Linux
riscv64-unknown-elf-  → RISC-V裸机
x86_64-w64-mingw32-   → Windows交叉编译（从Linux）

各部分含义：
arch    = 目标架构（arm, aarch64, riscv64, x86_64）
vendor  = 供应商（none, unknown, 厂商名）
os      = 操作系统（none, linux, freebsd）
abi     = 应用二进制接口（eabi, gnueabihf, gnu）
```

#### 3.3 交叉编译工具链组成

```
交叉编译工具链：

arm-none-eabi-gcc       → C编译器
arm-none-eabi-g++       → → C++编译器
arm-none-eabi-as        → 汇编器
arm-none-eabi-ld        → 链接器
arm-none-eabi-objdump   → 反汇编工具
arm-none-eabi-objcopy   → 格式转换工具
arm-none-eabi-size      → 段大小查看
arm-none-eabi-nm        → 符号表查看
arm-none-eabi-gdb       → 调试器
arm-none-eabi-newlib    → 嵌入式C库
```

### 4. 工具链配置

#### 4.1 安装交叉编译工具链

```bash
# Ubuntu/Debian：安装ARM裸机工具链
sudo apt-get install gcc-arm-none-eabi

# 安装ARM Linux工具链
sudo apt-get install gcc-arm-linux-gnueabihf

# 安装AArch64 Linux工具链
sudo apt-get install gcc-aarch64-linux-gnu

# Windows：下载ARM官方工具链
# https://developer.arm.com/tools-and-software/open-source-software/developer-tools/gnu-toolchain

# 验证安装
arm-none-eabi-gcc --version
# 输出：arm-none-eabi-gcc (GNU Arm Embedded Toolchain 10.3-2021.10) 10.3.1
```

#### 4.2 编译选项

```bash
# ARM Cortex-M4 裸机编译
arm-none-eabi-gcc \
    -mcpu=cortex-m4 \       # 指定CPU型号
    -mthumb \                # 使用Thumb指令集（16位，代码更小）
    -Wall \                  # 所有警告
    -O2 \                    # 优化等级
    -ffunction-sections \    # 每个函数单独一个段（便于链接时优化）
    -fdata-sections \        # 每个数据单独一个段
    -ffreestanding \         # 不假设有标准库
    -nostdlib \              # 不链接标准库
    -T linker.ld \           # 指定链接脚本
    -Wl,--gc-sections \      # 链接时删除未使用的段
    -o firmware.elf \
    main.c startup.s

# ARM Linux交叉编译
arm-linux-gnueabihf-gcc \
    -march=armv7-a \         # ARMv7架构
    -mfpu=neon \             # 使用NEON SIMD
    -mfloat-abi=hard \       # 硬浮点ABI
    --sysroot=/path/to/sysroot \  # 目标系统根目录
    -o myapp \
    main.c
```

### 5. CMake交叉编译

#### 5.1 工具链文件

```cmake
# 文件：toolchain-arm-none-eabi.cmake
# ARM Cortex-M 裸机交叉编译工具链

set(CMAKE_SYSTEM_NAME Generic)           # 裸机，无OS
set(CMAKE_SYSTEM_PROCESSOR ARM)

# 指定工具链前缀
set(TOOLCHAIN_PREFIX arm-none-eabi)

# 查找编译器
set(CMAKE_C_COMPILER ${TOOLCHAIN_PREFIX}-gcc)
set(CMAKE_CXX_COMPILER ${TOOLCHAIN_PREFIX}-g++)
set(CMAKE_ASM_COMPILER ${TOOLCHAIN_PREFIX}-gcc)
set(CMAKE_AR ${TOOLCHAIN_PREFIX}-ar)
set(CMAKE_OBJCOPY ${TOOLCHAIN_PREFIX}-objcopy)
set(CMAKE_OBJDUMP ${TOOLCHAIN_PREFIX}-objdump)
set(CMAKE_SIZE ${TOOLCHAIN_PREFIX}-size)

# 编译标志
set(CMAKE_C_FLAGS "-mcpu=cortex-m4 -mthumb -Wall -ffunction-sections -fdata-sections -ffreestanding")
set(CMAKE_CXX_FLAGS "${CMAKE_C_FLAGS} -fno-exceptions -fno-rtti")
set(CMAKE_ASM_FLAGS "-mcpu=cortex-m4 -mthumb")

# 链接标志
set(CMAKE_EXE_LINKER_FLAGS "-T${CMAKE_SOURCE_DIR}/linker.ld -Wl,--gc-sections -nostdlib")

# 不在宿主机上尝试运行编译出的程序
set(CMAKE_TRY_COMPILE_TARGET_TYPE STATIC_LIBRARY)
```

```cmake
# 文件：toolchain-arm-linux.cmake
# ARM Linux交叉编译工具链

set(CMAKE_SYSTEM_NAME Linux)
set(CMAKE_SYSTEM_PROCESSOR ARM)

set(TOOLCHAIN_PREFIX arm-linux-gnueabihf)

set(CMAKE_C_COMPILER ${TOOLCHAIN_PREFIX}-gcc)
set(CMAKE_CXX_COMPILER ${TOOLCHAIN_PREFIX}-g++)

# 目标系统的sysroot（包含目标机的库和头文件）
set(CMAKE_SYSROOT /opt/arm-sysroot)
set(CMAKE_FIND_ROOT_PATH /opt/arm-sysroot)

# 只在sysroot中搜索库和头文件
set(CMAKE_FIND_ROOT_PATH_MODE_PROGRAM NEVER)
set(CMAKE_FIND_ROOT_PATH_MODE_LIBRARY ONLY)
set(CMAKE_FIND_ROOT_PATH_MODE_INCLUDE ONLY)

# 编译标志
set(CMAKE_C_FLAGS "-march=armv7-a -mfpu=neon -mfloat-abi=hard")
```

#### 5.2 使用工具链文件

```cmake
# 文件：CMakeLists.txt
cmake_minimum_required(VERSION 3.20)
project(baremetal_firmware C CXX ASM)

# 源文件
add_executable(firmware.elf
    src/main.c
    src/gpio.c
    src/uart.c
    startup.s
)

# 链接脚本
target_link_options(firmware.elf PRIVATE
    -T${CMAKE_SOURCE_DIR}/linker.ld
    -nostdlib
    -Wl,--gc-sections
    -Wl,--print-memory-usage
)

# 生成.bin和.hex文件
add_custom_command(TARGET firmware.elf POST_BUILD
    COMMAND ${CMAKE_OBJCOPY} -O binary $<TARGET_FILE:firmware.elf> firmware.bin
    COMMAND ${CMAKE_OBJCOPY} -O ihex $<TARGET_FILE:firmware.elf> firmware.hex
    COMMAND ${CMAKE_SIZE} $<TARGET_FILE:firmware.elf>
)
```

```bash
# 使用工具链文件构建
mkdir build && cd build
cmake -DCMAKE_TOOLCHAIN_FILE=../toolchain-arm-none-eabi.cmake ..
cmake --build .
```

### 6. 常见嵌入式工具链

| 工具链 | 目标架构 | 适用场景 | 特点 |
|--------|---------|---------|------|
| GNU Arm Embedded | ARM Cortex-M/A | 裸机/RTOS | 官方维护，最常用 |
| arm-linux-gnueabihf | ARM Linux | 嵌入式Linux | 硬浮点ABI |
| aarch64-linux-gnu | ARM64 Linux | 服务器/嵌入式 | 64位ARM |
| RISC-V GNU Toolchain | RISC-V | 新兴架构 | 开源 |
| Zephyr SDK | 多架构 | Zephyr RTOS | 一站式工具链 |
| LLVM/Clang | 多架构 | 通用 | 模块化，跨架构 |
| Mingw-w64 | x86_64 Windows | Windows交叉编译 | 从Linux编译Windows程序 |

#### 6.1 Sysroot的重要性

```
Sysroot = 目标系统的"根目录镜像"

/opt/arm-sysroot/
├── usr/
│   ├── include/        # 目标系统的头文件
│   │   ├── stdio.h
│   │   ├── stdlib.h
│   │   └── ...
│   └── lib/            # 目标系统的库文件
│       ├── libc.so
│       ├── libm.so
│       └── libpthread.so
├── lib/
│   ├── ld-linux-armhf.so.3
│   └── libc.so.6
└── ...

获取Sysroot的方法：
1. 从目标设备拷贝：scp -r root@target:/usr /opt/arm-sysroot/usr
2. 使用目标设备的SDK/根文件系统
3. 使用Buildroot/Yocto构建
```

### 7. 交叉编译常见问题

#### 7.1 头文件路径问题

```bash
# 问题：找不到目标系统的头文件
fatal error: stdio.h: No such file or directory

# 解决：指定sysroot
arm-linux-gnueabihf-gcc --sysroot=/opt/arm-sysroot main.c

# 或在CMake中设置
set(CMAKE_SYSROOT /opt/arm-sysroot)
```

#### 7.2 库文件路径问题

```bash
# 问题：链接时找不到目标系统的库
/usr/lib/x86_64-linux-gnu/libc.so: incompatible target

# 原因：链接了宿主机的库而非目标机的库

# 解决：确保搜索路径指向目标系统的库
arm-linux-gnueabihf-gcc -L/opt/arm-sysroot/usr/lib main.c
```

#### 7.3 运行时库不匹配

```bash
# 问题：在目标设备上运行时报错
./myapp: /lib/libc.so.6: version `GLIBC_2.28' not found

# 原因：编译时链接的glibc版本比目标设备上的新

# 解决：
# 1. 使用目标设备上glibc版本对应的工具链
# 2. 静态链接：-static
# 3. 使用musl libc替代glibc
arm-linux-gnueabihf-gcc -static main.c -o myapp
```

### 8. 常见误区

| 误区 | 事实 |
|------|------|
| 交叉编译就是换个编译器 | 还需要正确的sysroot、库、头文件 |
| 交叉编译只能编译C | C++、Rust、Go都支持交叉编译 |
| 交叉编译一定比本地编译慢 | 编译速度取决于宿主机性能 |
| 所有ARM都一样 | ARMv6/7/8、Cortex-M/A指令集不同 |
| 交叉编译后就能直接运行 | 可能需要目标设备上的运行时库 |

***

### 9. 总结

| 维度 | 核心要点 |
|------|---------|
| 本质 | 在宿主机编译，在目标机运行 |
| 工具链 | arch-vendor-os-abi命名规则 |
| CMake | 通过toolchain文件配置交叉编译 |
| Sysroot | 目标系统的根目录镜像 |
| 常见问题 | 头文件/库路径、ABI不匹配 |

**核心记忆**：交叉编译 = 宿主机编译 + 目标机运行 + 工具链处理架构差异。关键是选对工具链、配好sysroot、确保库和ABI匹配。
