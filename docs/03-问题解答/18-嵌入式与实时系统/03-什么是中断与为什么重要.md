# 什么是中断与为什么重要
> 📖 相关章节：[嵌入式概述](../../12-嵌入式与实时系统/00-嵌入式系统概述.md)

> **中断就是硬件对CPU说"停下手头的事，先处理我！"——没有中断，CPU只能傻傻地轮询，99%的时间都在空转等事件。** 中断让CPU从"主动问"变成"被动通知"，效率提升千百倍。

***

### 1. 本质速解

**中断（Interrupt）** 是硬件或软件发出的信号，要求CPU暂停当前执行流程，转去处理更紧急的事件。中断机制让CPU不需要轮询等待事件，而是事件发生时主动通知CPU——这是嵌入式系统响应外部世界的核心机制。

***

### 2. 生活类比

| 类比 | 说明 |
|------|------|
| 轮询 = 不断看手机 | 每隔5秒看一次有没有消息，99%的时间白看 |
| 中断 = 手机响铃 | 有消息时手机响，你才去看——高效 |
| 中断 = 门铃 | 不需要一直站在门口等，门铃响了再去开门 |
| 中断优先级 = 急救电话 vs 普通电话 | 急救电话可以打断普通通话 |

**具体场景**：UART接收数据——轮询方式CPU要不停检查"数据来了吗？"，中断方式CPU做别的事，数据到了硬件自动通知CPU。

***

### 3. 中断的原理

#### 3.1 中断处理流程

```
正常程序执行：
  指令1 → 指令2 → 指令3 → [中断发生!]
                                    │
                                    ↓
                            保存上下文（寄存器入栈）
                                    │
                                    ↓
                            查找中断向量表
                                    │
                                    ↓
                            执行ISR（中断服务程序）
                                    │
                                    ↓
                            恢复上下文（寄存器出栈）
                                    │
                                    ↓
  指令4 → 指令5 → 指令6 → ...（继续执行）

关键步骤：
1. CPU完成当前指令
2. 保存返回地址和状态寄存器
3. 根据中断号查找向量表
4. 跳转到ISR执行
5. ISR执行完毕，恢复上下文
6. 返回被中断的程序
```

#### 3.2 中断类型

| 类型 | 触发源 | 示例 |
|------|--------|------|
| 外部中断（IRQ） | 外部硬件引脚 | 按键、传感器、UART |
| 内部中断 | 片上外设 | 定时器溢出、ADC完成 |
| 异常（Exception） | CPU内部 | 除零、未定义指令、内存错误 |
| 软件中断（SVC） | 软件指令 | 系统调用、上下文切换 |
| 不可屏蔽中断（NMI） | 关键硬件 | 看门狗、电源故障 |

### 4. 中断向量表

#### 4.1 向量表结构

```cpp
// ARM Cortex-M 中断向量表
// 每个条目是一个函数指针，指向对应的ISR

typedef void (*ISR_Handler)(void);

// 向量表（放在Flash最前面）
__attribute__((section(".isr_vector")))
const ISR_Handler vector_table[] = {
    // 系统异常（前16个）
    (ISR_Handler)_estack,          // 0: 初始栈指针
    Reset_Handler,                 // 1: 复位
    NMI_Handler,                   // 2: 不可屏蔽中断
    HardFault_Handler,             // 3: 硬件错误
    MemManage_Handler,             // 4: 内存管理错误
    BusFault_Handler,              // 5: 总线错误
    UsageFault_Handler,            // 6: 用法错误
    0,                             // 7: 保留
    0,                             // 8: 保留
    0,                             // 9: 保留
    0,                             // 10: 保留
    SVC_Handler,                   // 11: 系统服务调用
    DebugMon_Handler,              // 12: 调试监控
    0,                             // 13: 保留
    PendSV_Handler,                // 14: PendSV（上下文切换用）
    SysTick_Handler,               // 15: 系统滴答定时器

    // 外部中断（从16开始）
    WWDG_IRQHandler,               // 16: 窗口看门狗
    PVD_IRQHandler,                // 17: 电源电压检测
    TAMPER_IRQHandler,             // 18: 篡改检测
    RTC_IRQHandler,                // 19: 实时时钟
    FLASH_IRQHandler,              // 20: Flash
    RCC_IRQHandler,                // 21: 时钟控制
    EXTI0_IRQHandler,              // 22: 外部中断线0
    EXTI1_IRQHandler,              // 23: 外部中断线1
    // ... 更多外部中断
};
```

#### 4.2 运行时重定向向量表

```cpp
// Cortex-M允许运行时重定向向量表到RAM
// 这在Bootloader中很有用

#define SCB_VTOR ((volatile uint32_t*)0xE000ED08)

void relocate_vector_table(uint32_t new_base) {
    // 新向量表地址必须对齐到向量表大小的倍数
    *SCB_VTOR = new_base;
}

// 示例：Bootloader跳转到App
void jump_to_app(uint32_t app_base) {
    // App的向量表在app_base
    uint32_t app_stack = *(uint32_t*)app_base;
    uint32_t app_entry = *(uint32_t*)(app_base + 4);

    // 重定向向量表
    relocate_vector_table(app_base);

    // 设置栈指针
    __set_MSP(app_stack);

    // 跳转到App的Reset_Handler
    ((void(*)(void))app_entry)();
}
```

### 5. 中断优先级

#### 5.1 优先级机制

```cpp
// ARM Cortex-M 中断优先级

// 优先级数值越小 = 优先级越高
// STM32F4: 0（最高）到 15（最低），4位优先级
// STM32F1: 0（最高）到 255（最低），8位优先级（实际只用4位）

// 优先级分组：抢占优先级 + 子优先级
// 抢占优先级：高优先级可以抢占低优先级的ISR
// 子优先级：同抢占优先级的ISR按子优先级排队

// 配置优先级分组（整个系统只设一次）
NVIC_SetPriorityGrouping(NVIC_PRIORITYGROUP_4);
// Group 4: 4位抢占优先级，0位子优先级（最常用）
// Group 3: 3位抢占优先级，1位子优先级
// Group 2: 2位抢占优先级，2位子优先级
// ...

// 设置中断优先级
NVIC_SetPriority(EXTI0_IRQn, 5);   // 设置外部中断0的优先级
NVIC_SetPriority(USART1_IRQn, 10); // UART优先级更低
NVIC_SetPriority(SysTick_IRQn, 15); // SysTick优先级最低

// 使能中断
NVIC_EnableIRQ(EXTI0_IRQn);
NVIC_EnableIRQ(USART1_IRQn);
```

#### 5.2 优先级设计原则

```
优先级设计示例（汽车ECU）：

优先级  中断源           说明
  0    看门狗           系统安全，最高优先级
  1    刹车传感器       安全关键
  2    发动机控制       实时控制
  3    ABS传感器        安全相关
  4    CAN总线接收      通信
  5    定时器           周期性任务
  6    ADC转换完成      数据采集
  7    UART接收         调试/日志
  8    I2C事件          低速外设
  15   SysTick          系统时钟，最低优先级

原则：
1. 安全关键的中断优先级最高
2. 实时性要求高的优先级高
3. 通信中断中等优先级
4. 调试/日志最低优先级
5. SysTick通常最低（避免影响其他中断）
```

### 6. ISR的编写规则

#### 6.1 ISR编写铁律

```cpp
// 规则1：ISR必须尽可能短
// 差：在ISR中做大量处理
void USART1_IRQHandler(void) {
    if (USART1->SR & USART_SR_RXNE) {
        uint8_t data = USART1->DR;
        // 在ISR中解析协议——错误！
        if (data == 0xAA) {  // 帧头
            frame_index = 0;
        }
        frame_buffer[frame_index++] = data;
        if (frame_index >= FRAME_SIZE) {
            process_frame(frame_buffer);  // 在ISR中处理帧——错误！
        }
    }
}

// 好：ISR只做最少的操作，把数据处理推迟到任务中
volatile uint8_t rx_buffer[256];
volatile uint16_t rx_write_idx = 0;

void USART1_IRQHandler(void) {
    if (USART1->SR & USART_SR_RXNE) {
        uint8_t data = USART1->DR;
        rx_buffer[rx_write_idx & 0xFF] = data;  // 只存数据
        rx_write_idx++;
        // 通知任务处理
        BaseType_t xHigherPriorityTaskWoken = pdFALSE;
        xSemaphoreGiveFromISR(xUartRxSemaphore, &xHigherPriorityTaskWoken);
        portYIELD_FROM_ISR(xHigherPriorityTaskWoken);
    }
}

// 规则2：ISR中不能调用阻塞函数
// 错误：在ISR中等待信号量
void ISR_Handler(void) {
    xSemaphoreTake(xMutex, portMAX_DELAY);  // 绝对不行！ISR不能阻塞
}

// 正确：使用FromISR版本的API，不阻塞
void ISR_Handler(void) {
    BaseType_t xWoken = pdFALSE;
    xSemaphoreGiveFromISR(xSemaphore, &xWoken);  // 使用FromISR版本
    portYIELD_FROM_ISR(xWoken);
}

// 规则3：ISR中不能使用malloc/free
// 规则4：ISR中不能使用浮点运算（某些MCU）
// 规则5：共享变量必须用volatile修饰
```

#### 6.2 ISR与主程序的通信

```cpp
// 方法1：全局标志变量（最简单）
volatile bool g_button_pressed = false;

void EXTI0_IRQHandler(void) {
    if (EXTI->PR & EXTI_PR_PR0) {
        EXTI->PR = EXTI_PR_PR0;  // 清除中断标志
        g_button_pressed = true;  // 设置标志
    }
}

void main_loop(void) {
    if (g_button_pressed) {
        g_button_pressed = false;
        handle_button_press();  // 在主循环中处理
    }
}

// 方法2：环形缓冲区（数据传输）
#define RING_SIZE 64
typedef struct {
    uint8_t buffer[RING_SIZE];
    volatile uint8_t head;
    volatile uint8_t tail;
} RingBuffer;

void ring_write(RingBuffer* rb, uint8_t data) {
    rb->buffer[rb->head] = data;
    rb->head = (rb->head + 1) % RING_SIZE;
}

bool ring_read(RingBuffer* rb, uint8_t* data) {
    if (rb->head == rb->tail) return false;
    *data = rb->buffer[rb->tail];
    rb->tail = (rb->tail + 1) % RING_SIZE;
    return true;
}

// 方法3：RTOS队列/信号量（最规范）
// 见RTOS章节的示例
```

### 7. 中断延迟

#### 7.1 延迟组成

```
中断延迟 = 中断发生到ISR第一条指令执行的时间

组成：
1. 指令完成延迟：当前指令执行完成（1-3个周期）
2. 中断响应延迟：CPU保存上下文、查向量表（12个周期，Cortex-M）
3. 优先级判断：NVIC判断优先级（1-2个周期）
4. ISR入口代码：编译器生成的prologue（5-10个周期）

总延迟（Cortex-M4 @ 168MHz）：
- 最佳情况：~20个周期 ≈ 120ns
- 典型情况：~30个周期 ≈ 180ns
- 最坏情况：如果中断被禁用，延迟 = 禁用时间 + 上述延迟

影响中断延迟的因素：
1. 中断是否被禁用（__disable_irq()）
2. 是否在执行同优先级或更高优先级的ISR
3. Flash等待周期
4. 流水线刷新
```

#### 7.2 减少中断延迟

```cpp
// 1. 尽量缩短中断禁用时间
// 差：大段代码禁用中断
void bad_critical_section(void) {
    __disable_irq();
    do_something_big();  // 中断被禁用太久！
    do_another_thing();
    __enable_irq();
}

// 好：只保护必要的部分
void good_critical_section(void) {
    // 不需要保护的部分
    prepare_data();
    __disable_irq();
    shared_var = new_value;  // 只保护共享变量的访问
    __enable_irq();
    // 不需要保护的部分
    process_after();
}

// 2. 使用BASEPRI寄存器代替全局禁用中断
// 只屏蔽低于某优先级的中断，高优先级中断仍可响应
void selective_mask(void) {
    __set_BASEPRI(5 << 4);  // 只屏蔽优先级≥5的中断
    // 优先级0-4的中断仍可响应
    critical_operation();
    __set_BASEPRI(0);       // 恢复所有中断
}
```

### 8. 常见误区

| 误区 | 事实 |
|------|------|
| ISR越短越好 | 短是原则，但必须完成必要的操作 |
| 中断优先级越高越好 | 不必要的高优先级会导致其他中断延迟 |
| 所有中断都需要ISR | 某些中断只需要清除标志位 |
| 中断中可以用printf | 绝对不行，printf太慢且可能阻塞 |
| 中断总是比轮询好 | 低频事件轮询可能更简单可靠 |

***

### 9. 总结

| 维度 | 核心要点 |
|------|---------|
| 本质 | 硬件主动通知CPU处理事件 |
| 向量表 | 中断号→ISR函数指针的映射 |
| 优先级 | 抢占优先级+子优先级，数值越小越高 |
| ISR规则 | 短、不阻塞、不用malloc、volatile共享变量 |
| 延迟 | 指令完成+上下文保存+查表，通常亚微秒级 |

**核心记忆**：中断 = 硬件主动通知 + 向量表查找 + ISR执行 + 优先级管理。ISR必须短小精悍，重逻辑推迟到主循环或RTOS任务中处理。
