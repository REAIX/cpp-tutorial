# 嵌入式C++有哪些限制
> 📖 相关章节：[嵌入式概述](../../12-嵌入式与实时系统/00-嵌入式系统概述.md)

> **嵌入式C++是C++的"减肥版"——异常、RTTI、动态内存这些"奢侈品"都得砍掉，因为你的目标芯片可能只有64KB内存。** 在资源受限的世界里，每一字节、每一周期都要精打细算。

***

### 1. 要义概览

**嵌入式C++** 是标准C++在资源受限环境下的受限子集。由于嵌入式设备内存小、无MMU、实时性要求高，许多C++特性（异常、RTTI、动态内存分配、STL容器）被禁用或限制使用——开发者需要在C++的便利性和嵌入式的约束之间找到平衡。

***

### 2. 生活类比

| 类比 | 说明 |
|------|------|
| 标准C++ = 全功能厨房 | 烤箱、微波炉、洗碗机一应俱全 |
| 嵌入式C++ = 野营厨房 | 只有一个便携炉和一口锅，但也能做出好菜 |
| 异常 = 紧急呼叫系统 | 好用但占资源，野营时不需要 |
| RTTI = 身份证扫描 | 方便但耗电，野营时用不上 |
| 动态内存 = 信用卡 | 灵活但有风险，现金（静态分配）更安全 |

### 3. 无异常（No Exceptions）

#### 3.1 为什么禁用异常

```
异常的运行时开销：
1. 代码膨胀：异常处理表可能增加30-50%的代码大小
2. RAM开销：异常展开表需要额外RAM
3. 不可预测的时序：异常抛出时的时间不确定
4. 与RTOS不兼容：异常展开可能破坏RTOS的栈

在128KB Flash + 20KB RAM的MCU上：
- 启用异常：代码增加~50KB，RAM增加~10KB
- 禁用异常：节省这些资源用于实际功能
```

#### 3.2 替代方案

```cpp
// 标准C++：使用异常
Result parse_config(const std::string& path) {
    auto file = open_file(path);  // 可能抛异常
    if (!file.is_valid()) {
        throw ConfigError("无法打开配置文件");
    }
    return file.parse();  // 可能抛异常
}

// 嵌入式C++：使用错误码
enum class ParseResult {
    OK,
    FileNotFound,
    InvalidFormat,
    OutOfMemory
};

ParseResult parse_config(const char* path, Config& out_config) {
    FileHandle file;
    FileResult fr = open_file(path, &file);
    if (fr != FileResult::OK) {
        return ParseResult::FileNotFound;
    }
    return file.parse(out_config);
}

// 嵌入式C++：使用std::expected（C++23，如果可用）
std::expected<Config, ParseError> parse_config(const char* path) {
    auto file = open_file(path);
    if (!file) {
        return std::unexpected(file.error());
    }
    return file->parse();
}

// 编译选项：禁用异常
// GCC: -fno-exceptions
// Clang: -fno-exceptions
// MSVC: /EHs-c-
```

### 4. 无RTTI（No Runtime Type Information）

#### 4.1 为什么禁用RTTI

```cpp
// RTTI的开销
// 1. 每个多态类增加一个type_info对象（~20-40字节）
// 2. vtable中增加指向type_info的指针
// 3. dynamic_cast需要遍历继承链，时间不确定

// 禁用RTTI后：
// - 不能使用dynamic_cast
// - 不能使用typeid
// - 节省代码空间和RAM

// 编译选项：禁用RTTI
// GCC: -fno-rtti
// Clang: -fno-rtti
// MSVC: /GR-
```

#### 4.2 替代方案

```cpp
// 标准C++：使用dynamic_cast
class Base {
public:
    virtual ~Base() = default;
};

class DerivedA : public Base {
public:
    void method_a() { /* ... */ }
};

class DerivedB : public Base {
public:
    void method_b() { /* ... */ }
};

void process(Base* obj) {
    if (auto* a = dynamic_cast<DerivedA*>(obj)) {
        a->method_a();  // dynamic_cast需要RTTI
    } else if (auto* b = dynamic_cast<DerivedB*>(obj)) {
        b->method_b();
    }
}

// 嵌入式C++：使用枚举类型标识
enum class ObjectType { TypeA, TypeB };

class Base {
public:
    ObjectType type;  // 手动类型标识
    Base(ObjectType t) : type(t) {}
    virtual ~Base() = default;
};

class DerivedA : public Base {
public:
    DerivedA() : Base(ObjectType::TypeA) {}
    void method_a() { /* ... */ }
};

class DerivedB : public Base {
public:
    DerivedB() : Base(ObjectType::TypeB) {}
    void method_b() { /* ... */ }
};

void process(Base* obj) {
    switch (obj->type) {
        case ObjectType::TypeA:
            static_cast<DerivedA*>(obj)->method_a();
            break;
        case ObjectType::TypeB:
            static_cast<DerivedB*>(obj)->method_b();
            break;
    }
}

// 嵌入式C++：使用CRTP（编译时多态）
template<typename Derived>
class Base {
public:
    void process() {
        static_cast<Derived*>(this)->impl();
    }
};

class DerivedA : public Base<DerivedA> {
public:
    void impl() { /* A的实现 */ }
};

class DerivedB : public Base<DerivedB> {
public:
    void impl() { /* B的实现 */ }
};
// 无虚函数开销，无RTTI需求
```

### 5. 受限堆（Restricted Heap）

#### 5.1 为什么限制动态内存

```
嵌入式系统中动态内存的问题：
1. 内存碎片：长时间运行后，堆碎片化导致分配失败
2. 不确定性：malloc/new的执行时间不可预测
3. 分配失败：没有虚拟内存，malloc失败无法恢复
4. 实时性：垃圾回收（如果有）会导致停顿

典型嵌入式内存布局：
┌──────────────┐ 0x20000000
│  .data段     │  已初始化的全局变量
├──────────────┤
│  .bss段      │  未初始化的全局变量
├──────────────┤
│  堆（可选）   │  可能只有几KB或完全没有
├──────────────┤
│  ???         │
├──────────────┤
│  栈          │  从顶部向下增长
└──────────────┘ 0x20020000（128KB RAM）
```

#### 5.2 静态分配模式

```cpp
// 不用new/malloc，所有内存在编译时分配

// 方法1：静态数组
class SensorBuffer {
    static constexpr size_t MAX_SIZE = 64;
    float data_[MAX_SIZE];
    size_t size_ = 0;
public:
    bool push(float value) {
        if (size_ >= MAX_SIZE) return false;
        data_[size_++] = value;
        return true;
    }
    float operator[](size_t i) const { return data_[i]; }
    size_t size() const { return size_; }
};

// 方法2：对象池
template<typename T, size_t N>
class ObjectPool {
    alignas(T) uint8_t storage_[N][sizeof(T)];
    bool used_[N] = {};
public:
    T* allocate() {
        for (size_t i = 0; i < N; i++) {
            if (!used_[i]) {
                used_[i] = true;
                return new (storage_[i]) T();
            }
        }
        return nullptr;  // 池满
    }

    void deallocate(T* ptr) {
        for (size_t i = 0; i < N; i++) {
            if (ptr == reinterpret_cast<T*>(storage_[i])) {
                ptr->~T();
                used_[i] = false;
                return;
            }
        }
    }
};

// 使用对象池
ObjectPool<Message, 16> message_pool;

void send_message(const char* text) {
    Message* msg = message_pool.allocate();
    if (msg) {
        msg->set_text(text);
        msg_queue.push(msg);
    }
}

// 方法3：编译时大小的容器
template<typename T, size_t N>
class StaticVector {
    alignas(T) uint8_t storage_[N * sizeof(T)];
    size_t size_ = 0;
public:
    // 使用placement new在预分配的存储中构造对象
    template<typename... Args>
    T& emplace_back(Args&&... args) {
        T* ptr = new (storage_ + size_ * sizeof(T)) T(static_cast<Args&&>(args)...);
        size_++;
        return *ptr;
    }

    T& operator[](size_t i) { return *reinterpret_cast<T*>(storage_ + i * sizeof(T)); }
    size_t size() const { return size_; }
    bool full() const { return size_ >= N; }
};
```

#### 5.3 重载new/delete

```cpp
// 全局重载new/delete，用于监控或禁止动态分配

// 方案1：完全禁止new/delete
void* operator new(size_t size) = delete;
void operator delete(void* ptr) = delete;
// 编译时任何使用new/delete的代码都会报错

// 方案2：使用固定大小堆
static uint8_t heap_buffer[4096];  // 4KB堆
static size_t heap_offset = 0;

void* operator new(size_t size) {
    size = (size + 3) & ~3;  // 对齐
    if (heap_offset + size > sizeof(heap_buffer)) {
        return nullptr;  // 堆满
    }
    void* ptr = &heap_buffer[heap_offset];
    heap_offset += size;
    return ptr;
}

void operator delete(void* ptr) {
    // 简单分配器不支持释放
    // 实际项目应使用更复杂的分配策略
}
```

### 6. MISRA C++规范

#### 6.1 MISRA C++简介

```
MISRA C++ = Motor Industry Software Reliability Association C++ Guidelines
目标：为安全关键系统提供C++编码规范

核心原则：
1. 避免未定义行为
2. 避免实现定义行为
3. 使代码可预测、可验证
4. 减少出错可能性

主要规则类别：
- 语言使用限制（禁用某些特性）
- 类型安全（强制类型转换规则）
- 内存安全（限制指针操作）
- 控制流（限制goto、递归等）
- 并发安全（限制共享数据访问）
```

#### 6.2 常见MISRA C++规则

```cpp
// 规则0-1-1：不能有不可达代码
void bad(void) {
    return;
    do_something();  // 违规：不可达代码
}

// 规则5-0-6：隐式转换不能丢失信息
int32_t big_val = 100000;
int16_t small_val = big_val;  // 违规：可能截断

// 规则6-3-1：switch必须有default
switch (mode) {
    case Mode::A: do_a(); break;
    case Mode::B: do_b(); break;
    // 违规：没有default
}

// 正确：
switch (mode) {
    case Mode::A: do_a(); break;
    case Mode::B: do_b(); break;
    default: handle_error(); break;
}

// 规则7-5-2：函数指针不能用于调用
typedef void (*Callback)(void);
Callback cb = my_callback;
cb();  // 违规：通过函数指针调用

// 规则15-0-3：不能依赖求值顺序
int arr[10];
int i = 0;
arr[i] = i++;  // 违规：求值顺序未定义

// 规则16-0-8：不能使用placement new
T* obj = new (buffer) T();  // 违规：MISRA禁止placement new
// 但这在嵌入式C++中很常用，很多项目会豁免此规则
```

### 7. 嵌入式C++子集总结

| 特性 | 标准C++ | 嵌入式C++ | 原因 |
|------|--------|-----------|------|
| 异常 | ✅ | ❌ | 代码膨胀、时序不确定 |
| RTTI | ✅ | ❌ | 代码/数据开销 |
| 动态内存 | ✅ | ⚠️受限 | 碎片、不确定性 |
| STL容器 | ✅ | ⚠️受限 | 依赖动态内存 |
| 虚函数 | ✅ | ✅ | 开销可接受 |
| 模板 | ✅ | ✅ | 零开销抽象 |
| constexpr | ✅ | ✅ | 编译时计算 |
| 多重继承 | ✅ | ⚠️谨慎 | 复杂性 |
| 全局变量 | ✅ | ⚠️受限 | 初始化顺序问题 |
| 递归 | ✅ | ⚠️受限 | 栈溢出风险 |

#### 7.1 可以放心使用的C++特性

```cpp
// 1. 类和构造/析构（RAII）
class GpioPin {
    uint32_t port_;
    uint16_t pin_;
public:
    GpioPin(uint32_t port, uint16_t pin) : port_(port), pin_(pin) {
        gpio_init(port_, pin_);
    }
    ~GpioPin() {
        gpio_deinit(port_, pin_);
    }
    void set_high() { gpio_write(port_, pin_, 1); }
    void set_low()  { gpio_write(port_, pin_, 0); }
};

// 2. 模板（零开销抽象）
template<typename T>
inline T clamp(T value, T min_val, T max_val) {
    if (value < min_val) return min_val;
    if (value > max_val) return max_val;
    return value;
}

// 3. constexpr（编译时计算）
constexpr uint32_t baud_to_brr(uint32_t clock, uint32_t baud) {
    return (clock + baud / 2) / baud;
}

// 编译时计算，运行时零开销
constexpr uint32_t uart_brr = baud_to_brr(84000000, 115200);

// 4. 枚举类（类型安全）
enum class PinMode : uint8_t {
    Input,
    Output,
    Alternate,
    Analog
};

// 5. 命名空间
namespace driver {
    namespace uart {
        void init(uint32_t baudrate);
        void send(uint8_t data);
    }
}
```

### 8. 常见误区

| 误区 | 事实 |
|------|------|
| 嵌入式不能用C++ | 可以用，但需要选择合适的子集 |
| C++比C大很多 | 禁用异常和RTTI后，代码大小差异很小 |
| 模板导致代码膨胀 | 合理使用模板不会比手写代码更大 |
| 虚函数太慢 | 虚函数调用只多一次间接寻址，通常可接受 |
| 嵌入式C++就是C | C++的RAII、模板、枚举类在嵌入式中有巨大价值 |

***

### 9. 总结

| 维度 | 核心要点 |
|------|---------|
| 无异常 | 用错误码/expected替代 |
| 无RTTI | 用枚举标识/CRTP替代 |
| 受限堆 | 静态分配、对象池、固定大小容器 |
| MISRA C++ | 安全关键系统的编码规范 |
| 可用特性 | 类/RAII、模板、constexpr、枚举类 |

**核心记忆**：嵌入式C++ = 标准C++ - 异常 - RTTI - 动态内存 + 静态分配 + MISRA规范。不是不能用C++，而是选择合适的子集，用编译时安全替代运行时灵活。
