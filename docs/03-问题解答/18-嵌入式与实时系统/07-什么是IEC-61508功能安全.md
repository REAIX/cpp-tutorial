# 什么是IEC-61508功能安全
> 📖 相关章节：[嵌入式概述](../../12-嵌入式与实时系统/00-嵌入式系统概述.md)

> **IEC 61508就是安全关键系统的"法律"——它告诉你，如果你的软件出错可能伤人，你必须做到什么程度来防止这种事。** SIL等级越高，要求越严，SIL 3意味着你的系统每年因故障导致危险的概率不超过十万分之一。

***

### 1. 本质洞察

**IEC 61508** 是国际电工委员会制定的电气/电子/可编程电子安全相关系统的功能安全基础标准。它定义了**安全完整性等级（SIL）**，规定了不同危险程度下安全系统必须达到的可靠性要求——从SIL 1（最低）到SIL 4（最高），等级越高，对系统可靠性和开发过程的要求越严格。

***

### 2. 生活类比

| 类比 | 说明 |
|------|------|
| IEC 61508 = 建筑安全规范 | 不同建筑有不同安全要求（住宅vs医院vs核电站） |
| SIL等级 = 建筑抗震等级 | 等级越高，要求越严，成本越高 |
| 安全生命周期 = 从设计到拆除 | 安全不是一步到位，而是贯穿始终 |
| 技术措施 = 安全冗余 | 一个刹车不够，装两个；一个传感器不够，装三个 |

**具体场景**：化工厂的温度控制系统——如果软件出错导致阀门无法关闭，可能引发爆炸。IEC 61508要求你分析这个风险，确定需要SIL 3等级，然后按照SIL 3的要求开发和验证软件。

***

### 3. SIL等级

#### 3.1 SIL等级定义

| SIL等级 | 低要求模式（按次计算） | 高要求/连续模式（按小时计算） | 典型应用 |
|---------|---------------------|--------------------------|---------|
| SIL 1 | ≥10⁻² ~ <10⁻¹ | ≥10⁻⁵ ~ <10⁻⁴ | 轻微伤害 |
| SIL 2 | ≥10⁻³ ~ <10⁻² | ≥10⁻⁶ ~ <10⁻⁵ | 严重伤害 |
| SIL 3 | ≥10⁻⁴ ~ <10⁻³ | ≥10⁻⁷ ~ <10⁻⁶ | 多人死亡 |
| SIL 4 | ≥10⁻⁵ ~ <10⁻⁴ | ≥10⁻⁸ ~ <10⁻⁷ | 灾难性后果 |

```
低要求模式：安全功能只在需要时触发
  例：紧急停车系统——正常不动作，危险时才触发
  指标：平均危险故障概率（PFH_avg）

高要求/连续模式：安全功能持续运行
  例：汽车刹车系统——一直在工作
  指标：每小时危险故障概率（PFH）

SIL 3的含义：
- 低要求模式：每次需要时，故障概率 < 0.1%
- 连续模式：每小时故障概率 < 0.00001%（即每千万小时不超过1次）
```

#### 3.2 SIL等级确定

```
确定SIL等级的过程（风险图法）：

1. 评估后果（C）：
   C1: 轻微伤害
   C2: 严重伤害，1人死亡
   C3: 多人死亡
   C4: 灾难性，大量死亡

2. 评估暴露时间（F）：
   F1: 很少暴露于危险
   F2: 频繁暴露于危险

3. 评估避免可能性（P）：
   P1: 可能避免
   P2: 几乎不可能避免

4. 评估意外事件概率（W）：
   W1: 极低概率
   W2: 低概率
   W3: 相对较高概率

根据C+F+P+W的组合查表得到SIL等级

示例：化工厂反应釜控制
- 后果：C3（可能多人死亡）
- 暴露：F2（工人一直在附近）
- 避免：P2（事故发生太快无法避免）
- 概率：W2（低概率但可能发生）
→ 查表得到：SIL 3
```

```
        需求规格 ──────────────────────── 验证需求
            │                                  ↑
            ↓                                  │
        架构设计 ───────────────────── 集成测试

V模型核心原则：
- 左侧是设计和实现
- 右侧是测试和验证
- 每个设计阶段都有对应的验证阶段
- SIL等级越高，每个阶段的要求越严格
```

### 5. 技术措施要求

#### 5.1 不同SIL等级的软件要求

| 要求 | SIL 1 | SIL 2 | SIL 3 | SIL 4 |
|------|-------|-------|-------|-------|
| 编码规范 | 推荐 | 必须 | 必须 | 必须 |
| 代码审查 | 推荐 | 必须 | 必须 | 必须 |
| 单元测试 | 推荐 | 必须 | 必须 | 必须 |
| 代码覆盖率 | 入口点 | 100%分支 | 100%MC/DC | 100%MC/DC |
| 静态分析 | 推荐 | 推荐 | 必须 | 必须 |
| 动态分析 | 推荐 | 推荐 | 必须 | 必须 |
| 形式化方法 | - | - | 推荐 | 必须 |
| 半形式化方法 | 推荐 | 必须 | 必须 | 必须 |
| 独立性等级 | 独立人员 | 独立人员 | 独立部门 | 独立组织 |

#### 5.2 编码规范要求

```cpp
// IEC 61508推荐的编码规范（基于MISRA C/C++）

// 1. 禁止动态内存分配（SIL 2+）
// 错误：
char* buffer = malloc(1024);  // 禁止

// 正确：
char buffer[1024];  // 静态分配

// 2. 禁止递归（SIL 2+）
// 错误：
int factorial(int n) {
    return n <= 1 ? 1 : n * factorial(n-1);  // 禁止递归
}

// 正确：
int factorial(int n) {
    int result = 1;
    for (int i = 2; i <= n; i++) {
        result *= i;
    }
    return result;
}

// 3. 限制指针使用（SIL 2+）
// 4. 所有switch必须有default
// 5. 禁止隐式类型转换
// 6. 限制使用预处理宏
// 7. 函数必须有单一出口点（SIL 3+）

// 6. 安全关键函数模板
typedef enum {
    SAFETY_OK,
    SAFETY_WARNING,
    SAFETY_CRITICAL,
    SAFETY_ERROR
} SafetyStatus;

SafetyStatus check_pressure(float pressure) {
    // 输入验证
    if (pressure < 0.0f || pressure > MAX_PRESSURE) {
        return SAFETY_ERROR;  // 传感器故障
    }

    // 安全检查
    if (pressure > CRITICAL_THRESHOLD) {
        return SAFETY_CRITICAL;
    } else if (pressure > WARNING_THRESHOLD) {
        return SAFETY_WARNING;
    }

    return SAFETY_OK;
}
```

#### 5.3 冗余与多样性

```
硬件冗余策略：

1. 1oo1（一取一）：无冗余
   [传感器A] → [处理器] → [执行器]
   任何单点故障都导致系统失效

2. 1oo2（二取一）：双通道，任一正常即可
   [传感器A] → [处理器A] →┐
                           ├→ [投票] → [执行器]
   [传感器B] → [处理器B] →┘
   任一通道故障，另一通道仍可工作

3. 2oo3（三取二）：三通道，至少两个一致
   [传感器A] → [处理器A] →┐
   [传感器B] → [处理器B] →├→ [投票] → [执行器]
   [传感器C] → [处理器C] →┘
   一个通道故障不影响系统，两个通道同时故障才失效

4. 2oo2（二取二）：双通道，两个都正常才行
   用于需要极高安全性的场景（防止误触发）

软件多样性：
- 通道A用C语言实现
- 通道B用C++实现
- 通道C用不同算法实现
→ 减少共因故障（同一bug不会同时影响所有通道）
```

### 6. 认证流程

```
IEC 61508认证流程：

1. 确定SIL等级
   └→ 风险分析 → SIL 3

2. 制定安全计划
   └→ 文档化所有安全活动

3. 执行安全生命周期
   ├→ 需求分析（SRS）
   ├→ 架构设计
   ├→ 详细设计
   ├→ 编码实现
   ├→ 单元测试
   ├→ 集成测试
   └→ 系统验证

4. 安全验证
   ├→ 功能安全评估（FSA）
   ├→ 确认测试
   └→ 安全手册

5. 认证机构审核
   ├→ TÜV、SGS、UL等
   ├→ 审查文档和证据
   └→ 颁发SIL证书

6. 运行维护
   ├→ 定期功能安全审计
   ├→ 变更管理
   └→ 退役计划

认证成本：
- SIL 1: 数十万人民币
- SIL 2: 数百万人民币
- SIL 3: 数千万人民币
- SIL 4: 极高，罕见
```

### 7. IEC 61508 vs DO-178C

| 维度 | IEC 61508 | DO-178C |
|------|-----------|---------|
| 领域 | 工业、过程控制 | 航空 |
| 等级 | SIL 1-4 | DAL A-E |
| 关注点 | 功能安全 | 软件安全 |
| 方法 | 基于风险 | 基于目标 |
| 覆盖范围 | 硬件+软件 | 仅软件 |
| 代码覆盖率 | MC/DC（SIL 3+） | MC/DC（DAL A/B） |
| 形式化方法 | 推荐（SIL 4） | 可替代（DAL A） |
| 认证机构 | TÜV/SGS | FAA/EASA |
| 修改管理 | MOC（变更管理） | MOC |

```
等级对照（大致对应）：
IEC 61508 SIL 1 ≈ DO-178C DAL D
IEC 61508 SIL 2 ≈ DO-178C DAL C
IEC 61508 SIL 3 ≈ DO-178C DAL B
IEC 61508 SIL 4 ≈ DO-178C DAL A
```

### 8. 常见误区

| 误区 | 事实 |
|------|------|
| SIL等级越高系统越安全 | SIL等级是要求等级，不是系统属性 |
| 通过认证就一定安全 | 认证证明过程合规，不保证零缺陷 |
| SIL只涉及软件 | IEC 61508覆盖硬件+软件+系统 |
| 任何软件都需要SIL认证 | 只有安全相关系统才需要 |
| SIL认证一次终身有效 | 需要定期审计和更新 |

***

### 9. 总结

| 维度 | 核心要点 |
|------|---------|
| SIL等级 | 1-4级，等级越高要求越严 |
| 安全生命周期 | 从概念到退役的全流程管理 |
| 技术措施 | 编码规范、测试、冗余、多样性 |
| 认证 | 第三方机构审核，颁发SIL证书 |
| 与DO-178C | 领域不同，理念相似，等级大致对应 |

**核心记忆**：IEC 61508 = 功能安全的基础标准。SIL等级决定要求严格程度，安全生命周期确保从设计到退役的全程安全，技术措施（冗余、多样性、编码规范）降低故障概率。SIL 3意味着危险故障概率低于十万分之一。
