# 什么是栈溢出攻击
> 📖 相关章节：[安全编程概述](../../13-安全编程与逆向工程/00-安全编程概述.md)、[内存安全](../../13-安全编程与逆向工程/01-内存安全与漏洞防御.md)

> **栈溢出就是往杯子里倒水倒满了还继续倒——多出来的水覆盖了桌上的东西，而攻击者可以精确控制"水"流到哪里。** 覆盖返回地址，就能劫持程序执行流。

***

### 1. 一句话概括

**栈溢出攻击（Stack Buffer Overflow Attack）** 是通过向栈上的缓冲区写入超出其容量的数据，覆盖相邻的栈帧数据（尤其是返回地址），从而劫持程序执行流的攻击技术。它是历史上最经典、危害最大的安全漏洞类型之一。

***

### 2. 生活类比

| 类比 | 说明 |
|------|------|
| 栈 = 一摞盘子 | 每个函数一层盘子，返回地址是盘子上贴的标签 |
| 缓冲区 = 盘子上的格子 | 只能装固定量的东西 |
| 溢出 = 格子装满了还继续装 | 多出来的东西覆盖了标签 |
| 覆盖返回地址 = 换掉标签 | 程序返回时去了错误的地方 |
| Shellcode = 伪造的指令 | 放在溢出数据中的恶意代码 |

***

### 3. 栈溢出原理

#### 3.1 栈帧结构

```
函数调用时的栈布局（x86，从高地址到低地址）：

高地址
┌──────────────────┐
│   参数N           │
│   ...            │
│   参数1           │  ← 调用者压入
│   返回地址(EIP)   │  ← CALL指令自动压入
├──────────────────┤
│   保存的EBP       │  ← 被调用者压入（push ebp）
├──────────────────┤
│   局部变量        │
│   char buf[16]   │  ← 缓冲区（溢出点）
│   int var1       │
│   ...            │
├──────────────────┤
│   临时空间        │
低地址              ← ESP指向这里

溢出方向：从buf向高地址覆盖
buf[16] → 覆盖var1 → 覆盖saved EBP → 覆盖返回地址！
```

#### 3.2 基本溢出示例

```c
// 漏洞代码：经典的栈溢出
#include <stdio.h>
#include <string.h>

void vulnerable_function(char* input) {
    char buffer[16];              // 只有16字节的缓冲区
    strcpy(buffer, input);        // 不检查长度，可以写入任意多数据！
    printf("你输入了: %s\n", buffer);
}

int main(int argc, char* argv[]) {
    if (argc > 1) {
        vulnerable_function(argv[1]);
    }
    return 0;
}

// 正常输入：./program hello
// 栈布局：buffer = "hello\0..."  返回地址不变 → 正常返回

// 恶意输入：./program AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA\xef\xbe\xad\xde
// 栈布局：buffer = "AAAA..."  返回地址被覆盖为0xDEADBEEF → 跳转到0xDEADBEEF
```

#### 3.3 攻击步骤

```
栈溢出攻击步骤：

1. 找到漏洞点
   - 使用不安全的函数：strcpy, gets, sprintf, scanf("%s",...)
   - 缓冲区大小固定，输入无长度检查

2. 确定偏移量
   - 缓冲区到返回地址的距离
   - 方法：发送不同长度的模式字符串，观察哪个位置覆盖了返回地址

3. 构造payload
   ┌─────────────────────────────────────────┐
   │ 填充数据（覆盖到返回地址） │ 返回地址 │ Shellcode │
   └─────────────────────────────────────────┘
   │←── offset字节 ──→│←─ 4字节 ─→│←─ 变长 ─→│

4. 执行Shellcode
   - 返回地址指向Shellcode的起始位置
   - 程序返回时跳转到Shellcode执行

攻击成功后：
- 攻击者获得与被攻击程序相同的权限
- 如果程序是root/setuid，攻击者获得root权限
```

### 4. Shellcode注入

#### 4.1 简单Shellcode

```asm
; Linux x86 Shellcode：执行 /bin/sh
; 31字节

; 策略：通过int 0x80系统调用执行execve("/bin/sh", NULL, NULL)

xor    eax, eax       ; eax = 0
push   eax            ; 字符串结尾的\0
push   0x68732f2f     ; "//sh"（反序，因为小端）
push   0x6e69622f     ; "/bin"
mov    ebx, esp       ; ebx = 指向"/bin//sh"的指针
xor    ecx, ecx       ; ecx = NULL (argv)
xor    edx, edx       ; edx = NULL (envp)
mov    al, 0x0b       ; 系统调用号 11 = execve
int    0x80           ; 触发系统调用

; 对应的机器码（十六进制）：
; \x31\xc0\x50\x68\x2f\x2f\x73\x68\x68\x2f\x62\x69\x6e
; \x89\xe3\x31\xc9\x31\xd2\xb0\x0b\xcd\x80
```

#### 4.2 Shellcode的挑战

```
Shellcode编写的限制：

1. 不能包含\0字节
   - strcpy等函数遇到\0会停止复制
   - 解决：用xor eax,eax代替mov eax,0

2. 不能包含换行符\n (0x0a)
   - gets()等函数遇到换行停止

3. 地址硬编码问题
   - Shellcode在栈上的位置不确定
   - 解决：使用NOP滑梯或跳转指令

4. 代码必须位置无关
   - 不能使用绝对地址
   - 解决：用call/pop获取当前地址

NOP滑梯：
┌──────────────────────────────────────────────────┐
│ NOP NOP NOP NOP NOP NOP ... │ Shellcode          │
│ \x90\x90\x90\x90\x90\x90...│ \x31\xc0\x50...    │
└──────────────────────────────────────────────────┘
│←── 大量NOP指令 ──→│←── 实际代码 ──→│

只要返回地址落在NOP区域中的任何位置，
CPU会滑过NOP执行到Shellcode
```

### 5. ROP攻击（Return-Oriented Programming）

#### 5.1 为什么需要ROP

```
DEP/NX位的出现：
- 数据区域（栈/堆）不可执行
- Shellcode在栈上无法执行
- 需要利用已有代码片段

ROP的核心思想：
- 不注入新代码
- 利用程序中已有的代码片段（gadgets）
- 每个gadget以ret结尾
- 通过栈上的返回地址链串联gadgets

Gadget = 以ret结尾的短指令序列
例如：
  pop eax; ret       → 从栈上弹出一个值到eax
  pop ebx; ret       → 从栈上弹出一个值到ebx
  add eax, ebx; ret  → eax = eax + ebx
```

#### 5.2 ROP链构造

```
ROP链示例：调用execve("/bin/sh", NULL, NULL)

栈布局（ROP链）：

┌──────────────────────┐
│ 填充数据（到返回地址） │
├──────────────────────┤
│ gadget1地址           │  ← pop eax; ret
├──────────────────────┤
│ 0x0b                 │  ← eax = 11 (execve系统调用号)
├──────────────────────┤
│ gadget2地址           │  ← pop ebx; ret
├──────────────────────┤
│ "/bin/sh"字符串地址   │  ← ebx = "/bin/sh"
├──────────────────────┤
│ gadget3地址           │  ← pop ecx; ret
├──────────────────────┤
│ 0x00000000           │  ← ecx = NULL
├──────────────────────┤
│ gadget4地址           │  ← pop edx; ret
├──────────────────────┤
│ 0x00000000           │  ← edx = NULL
├──────────────────────┤
│ gadget5地址           │  ← int 0x80; ret
└──────────────────────┘

执行流程：
1. 函数返回 → 跳到gadget1 → pop eax=0x0b → ret
2. ret → 跳到gadget2 → pop ebx="/bin/sh" → ret
3. ret → 跳到gadget3 → pop ecx=0 → ret
4. ret → 跳到gadget4 → pop edx=0 → ret
5. ret → 跳到gadget5 → int 0x80 → 执行execve！
```

#### 5.3 ROP工具

```bash
# ROPgadget：自动搜索gadgets
python3 ROPgadget.py --binary ./vulnerable --only "pop|ret"

# ropper：另一个ROP工具
ropper --file ./vulnerable --search "pop eax; ret"

# pwntools：Python漏洞利用框架
from pwn import *

elf = ELF('./vulnerable')
rop = ROP(elf)

# 自动构造ROP链
rop.execve(next(elf.search(b'/bin/sh')), 0, 0)
print(rop.dump())
```

### 6. 现代防御机制

#### 6.1 防御概览

| 防御机制 | 防御目标 | 原理 |
|---------|---------|------|
| Stack Canary | 栈溢出检测 | 函数入口放随机值，返回前检查 |
| ASLR | 地址随机化 | 每次运行栈/库地址不同 |
| DEP/NX | 阻止代码执行 | 栈/堆不可执行 |
| PIE | 代码地址随机化 | 可执行文件加载地址随机 |
| RELRO | 防止GOT覆写 | GOT表只读 |
| CFI | 控制流完整性 | 验证间接跳转目标 |

#### 6.2 Stack Canary（栈金丝雀）

```c
// Stack Canary原理
void vulnerable_function(char* input) {
    // 编译器插入的代码：
    // canary = __stack_chk_guard;  // 随机值
    // 保存到栈上（在缓冲区和返回地址之间）

    char buffer[16];
    strcpy(buffer, input);

    // 编译器插入的代码：
    // if (canary != __stack_chk_guard) {
    //     __stack_chk_fail();  // 检测到溢出，终止程序
    // }
}

// 栈布局（有Canary）：
// ┌──────────────────┐
// │   返回地址        │
// ├──────────────────┤
// │   保存的EBP       │
// ├──────────────────┤
// │   Canary值        │  ← 溢出必须经过这里
// ├──────────────────┤
// │   char buf[16]   │  ← 溢出起点
// └──────────────────┘

// 溢出时必须覆盖Canary，但不知道其值
// 覆盖后Canary检查失败，程序终止

// GCC编译选项：
// -fstack-protector-all    所有函数加Canary
// -fstack-protector-strong 较高风险的函数加Canary
// -fno-stack-protector     禁用Canary
```

#### 6.3 ASLR（地址空间布局随机化）

```bash
# Linux ASLR控制
cat /proc/sys/kernel/randomize_va_space
# 0 = 关闭
# 1 = 部分随机化（共享库、mmap）
# 2 = 完全随机化（包括栈和堆）

# 临时关闭（调试用）
echo 0 | sudo tee /proc/sys/kernel/randomize_va_space

# 编译时启用PIE（位置无关可执行文件）
gcc -pie -fPIE -o program program.c
```

#### 6.4 DEP/NX（数据执行保护）

```bash
# Linux：NX位
# 默认启用，栈和堆不可执行
# 编译时控制：
gcc -z noexecstack    # 启用NX（默认）
gcc -z execstack      # 禁用NX（调试用）

# 查看ELF文件的NX状态
readelf -l program | grep GNU_STACK
# RWE = 可读写执行（NX关闭）
# RW  = 可读写（NX启用）
```

### 7. 安全编码实践

```c
// 替换不安全的函数

// 不安全 → 安全替代
gets(buf)              → fgets(buf, sizeof(buf), stdin)
strcpy(dst, src)       → strncpy(dst, src, sizeof(dst)-1)
sprintf(dst, fmt, ...) → snprintf(dst, sizeof(dst), fmt, ...)
strcat(dst, src)       → strncat(dst, src, sizeof(dst)-strlen(dst)-1)
scanf("%s", buf)       → scanf("%99s", buf)  // 限制长度

// 安全版本示例
void safe_input(void) {
    char buffer[64];

    // 安全读取：限制长度
    if (fgets(buffer, sizeof(buffer), stdin) != NULL) {
        // 去除换行符
        size_t len = strlen(buffer);
        if (len > 0 && buffer[len-1] == '\n') {
            buffer[len-1] = '\0';
        }
        // 安全使用buffer
    }
}

// 安全字符串拷贝
void safe_copy(char* dst, size_t dst_size, const char* src) {
    strncpy(dst, src, dst_size - 1);
    dst[dst_size - 1] = '\0';  // 确保以\0结尾
}

// C++中使用更安全的容器
#include <string>
#include <vector>

void safe_cpp(void) {
    std::string input;  // 自动管理内存，不会溢出
    std::getline(std::cin, input);

    std::vector<char> buffer(1024);  // 边界检查
    // ...
}
```

### 8. 常见误区

| 误区 | 事实 |
|------|------|
| 栈溢出已经过时 | 仍是常见漏洞，只是现代防御增加了利用难度 |
| 有了ASLR就安全了 | ASLR可以被信息泄露绕过 |
| 有了Canary就安全了 | Canary可以被逐字节爆破或格式化字符串泄露 |
| 64位系统不会有栈溢出 | 64位同样存在，只是利用方式不同 |
| 只有C/C++有栈溢出 | 任何不检查边界的语言都可能 |

***

### 9. 总结

| 维度 | 核心要点 |
|------|---------|
| 原理 | 缓冲区溢出覆盖返回地址，劫持执行流 |
| Shellcode | 注入的恶意代码，需避开\0等特殊字符 |
| ROP | 利用已有代码片段绕过DEP/NX |
| 防御 | Canary + ASLR + DEP + PIE + RELRO |
| 编码 | 用安全函数替代不安全函数，检查边界 |

**核心记忆**：栈溢出 = 缓冲区越界 + 覆盖返回地址 + 劫持执行流。现代防御（Canary/ASLR/DEP）增加了利用难度，但根本解决方案是安全编码——使用安全函数、检查边界、限制输入长度。
