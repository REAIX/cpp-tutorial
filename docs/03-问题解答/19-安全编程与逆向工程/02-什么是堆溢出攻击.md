# 什么是堆溢出攻击
> 📖 相关章节：[安全编程概述](../../13-安全编程与逆向工程/00-安全编程概述.md)、[内存安全](../../13-安全编程与逆向工程/01-内存安全与漏洞防御.md)

> **堆溢出就是往堆上的杯子里倒水倒满了还继续倒——但和栈不同，溢出的"水"不是覆盖返回地址，而是覆盖堆管理器的元数据，让你能控制后续的内存分配。** 堆攻击比栈攻击更复杂，但也更灵活。

***

### 1. 精髓速览

**堆溢出攻击（Heap Buffer Overflow Attack）** 是通过向堆上的缓冲区写入超出其容量的数据，覆盖相邻的堆块元数据或其他堆上数据，从而实现任意地址读写、代码执行等攻击目标。与栈溢出不同，堆溢出利用的是堆管理器（malloc/free）的内部数据结构。

***

### 2. 生活类比

| 类比 | 说明 |
|------|------|
| 堆 = 仓库 | 动态分配的储物空间 |
| 堆块 = 储物柜 | 每个柜子有标签（元数据）和内容（数据） |
| 堆溢出 = 柜子装满了溢到隔壁 | 覆盖隔壁柜子的标签 |
| 堆管理器 = 仓库管理员 | 根据标签管理柜子的分配和回收 |
| 攻击 = 伪造标签 | 让管理员把柜子分配到你想要的地方 |

### 3. 堆管理器原理

#### 3.1 glibc malloc结构

```
堆块结构（glibc ptmalloc）：

已分配的堆块：
┌──────────────────────────────────┐
│ prev_size (8字节) │ 上一个块大小（仅当上一块空闲时有效）
├───────────────────┤
│ size (8字节)      │ 当前块大小 + 标志位(A|M|P)
│                   │   P = 上一块是否在使用中
│                   │   M = 是否通过mmap分配
│                   │   A = 是否属于非主arena
├───────────────────┤
│ 用户数据          │ ← malloc返回的指针指向这里
│ ...               │
└───────────────────┘

空闲的堆块（Free Chunk）：
┌──────────────────────────────────┐
│ prev_size        │
├──────────────────┤
│ size             │
├──────────────────┤
│ fd (前向指针)    │ 指向同一bin中下一个空闲块
├──────────────────┤
│ bk (后向指针)    │ 指向同一bin中上一个空闲块
├──────────────────┤
│ fd_nextsize      │ (仅large bin)
├──────────────────┤
│ bk_nextsize      │ (仅large bin)
└──────────────────┘

关键：空闲块的fd/bk指针维护空闲链表
如果攻击者能覆盖fd/bk，就能控制堆管理器的行为
```

#### 3.2 空闲链表（Bins）

```
glibc的空闲块管理：

Fastbins：单链表，LIFO
  - 小块内存（<160字节，64位系统）
  - 不合并相邻空闲块
  - 最容易利用

Small Bins：双链表，FIFO
  - 中等大小块
  - 合并相邻空闲块

Large Bins：双链表，按大小排序
  - 大块内存

Unsorted Bin：双链表
  - 刚释放的块，等待分类
  - 分配时先检查这里

Bins的利用：
- Fastbin attack：伪造fd指针，让malloc返回任意地址
- Unsorted bin attack：泄露libc地址
- Tcache attack：类似fastbin但更简单
```

### 4. 堆漏洞利用方式

#### 4.1 基本堆溢出

```c
// 堆溢出示例
#include <stdlib.h>
#include <string.h>
#include <stdio.h>

int main(void) {
    // 分配两个相邻的堆块
    char* buf1 = (char*)malloc(32);  // 堆块1
    char* buf2 = (char*)malloc(32);  // 堆块2

    // 堆布局：
    // [buf1头部|buf1数据(32B)] [buf2头部|buf2数据(32B)]
    //   ↑ buf1指向这里          ↑ buf2指向这里

    // 溢出buf1，覆盖buf2的头部
    strcpy(buf1, "AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA");
    // 32字节数据 + 16字节头部 = 48字节才到buf2的数据区
    // 但溢出的数据会先覆盖buf2的size字段

    // 如果buf2是空闲的，溢出可以覆盖fd/bk指针
    free(buf2);
    // 此时buf2的布局：
    // [prev_size|size|fd|bk|...]
    // 溢出buf1可以覆盖buf2的fd和bk

    // 下一次malloc可能返回攻击者控制的地址
    char* fake = (char*)malloc(32);

    free(buf1);
    return 0;
}
```

#### 4.2 Use-After-Free（释放后使用）

```c
// UAF漏洞：使用了已经释放的内存
#include <stdlib.h>
#include <string.h>
#include <stdio.h>

typedef struct {
    void (*print_func)(const char*);
    char name[32];
} Object;

void safe_print(const char* msg) {
    printf("安全: %s\n", msg);
}

void evil_print(const char* msg) {
    printf("被劫持! %s\n", msg);
    // 攻击者可以在这里执行任意代码
}

int main(void) {
    // 1. 分配对象
    Object* obj = (Object*)malloc(sizeof(Object));
    obj->print_func = safe_print;
    strcpy(obj->name, "Hello");

    // 2. 释放对象
    free(obj);
    // obj变成悬空指针（dangling pointer）
    // 但obj变量仍然保存着旧地址

    // 3. 分配新对象，可能复用刚释放的内存
    char* attacker = (char*)malloc(sizeof(Object));
    // 如果attacker和obj指向同一块内存
    strcpy(attacker, (char*)&evil_print);  // 覆盖函数指针
    // 假设evil_print的地址被写入attacker的前8字节

    // 4. 通过悬空指针调用已释放对象的方法
    obj->print_func("test");
    // 实际调用的是evil_print！控制流被劫持

    return 0;
}

// UAF利用的关键：
// 1. 释放对象后，指针没有置NULL
// 2. 新分配的对象复用了同一块内存
// 3. 攻击者通过新对象控制旧对象的数据
// 4. 通过旧指针调用被覆盖的函数指针
```

#### 4.3 Double-Free（双重释放）

```c
// Double-Free漏洞：同一块内存被释放两次
#include <stdlib.h>

int main(void) {
    char* ptr = (char*)malloc(32);

    free(ptr);   // 第一次释放：正常
    // ptr没有置NULL

    free(ptr);   // 第二次释放：同一个指针被再次释放！
    // 这会导致空闲链表中出现循环

    // 后续的malloc可能返回已被分配的内存
    char* p1 = (char*)malloc(32);
    char* p2 = (char*)malloc(32);
    // p1和p2可能指向同一块内存！
    // 写入p1会影响p2

    return 0;
}

// Double-Free利用（Fastbin Attack）：
// 1. free(ptr) → fastbin链表：ptr → NULL
// 2. free(ptr) → fastbin链表：ptr → ptr → ...（循环！）
// 3. malloc(32) → 返回ptr，fastbin：ptr → ...
// 4. 修改ptr的fd指针指向目标地址
// 5. malloc(32) → 返回ptr
// 6. malloc(32) → 返回目标地址！任意地址写入
```

#### 4.4 堆风水（Heap Feng Shui）

```
堆风水 = 通过精心安排堆分配/释放，创造特定的堆布局

目标：让目标缓冲区和可覆盖的对象相邻

步骤：
1. 分配大量相同大小的块（填充碎片）
2. 释放部分块，创造可预测的空洞
3. 让目标对象和溢出缓冲区分配在相邻位置
4. 溢出缓冲区，精确覆盖目标对象

示例布局：
┌────────┐
│ 填充块1 │  ← 防止与顶部块合并
├────────┤
│ 目标块  │  ← 要覆盖的对象（如函数指针结构体）
├────────┤
│ 溢出块  │  ← 可以溢出的缓冲区
├────────┤
│ 填充块2 │  ← 防止与顶部块合并
├────────┤
│ 顶部块  │  ← 剩余堆空间
└────────┘

溢出溢出块 → 覆盖目标块的函数指针 → 劫持控制流
```

### 5. 堆漏洞防御

| 防御机制 | 防御目标 | 原理 |
|---------|---------|------|
| Safe-Linking | Fastbin攻击 | 加密fd指针，检测篡改 |
| Tcache Key | Double-Free | 在tcache块中写入随机key |
| Heap Consistency Check | 堆元数据篡改 | free时检查块的有效性 |
| Guard Pages | 堆块间隔离 | 在敏感分配之间插入不可访问页 |
| ASLR | 地址预测 | 堆地址随机化 |
| Free List Encryption | 链表篡改 | 加密空闲链表指针 |

```c
// 安全堆使用模式

// 1. 释放后立即置NULL
char* ptr = (char*)malloc(32);
// ... 使用ptr
free(ptr);
ptr = NULL;  // 防止UAF和Double-Free

// 2. 使用智能指针（C++）
#include <memory>
void safe_cpp(void) {
    auto ptr = std::make_unique<char[]>(32);
    // 自动释放，不可能UAF
}

// 3. 使用安全分配器
// - jemalloc：更安全的堆管理器
// - Electric Fence：检测溢出的调试分配器
// - ASan：Address Sanitizer，检测堆溢出和UAF

// 4. 编译时启用Address Sanitizer
// gcc -fsanitize=address -g program.c
// 运行时检测：堆溢出、UAF、Double-Free、栈溢出
```

### 6. 常见误区

| 误区 | 事实 |
|------|------|
| 堆溢出比栈溢出少见 | 堆溢出在复杂程序中更常见 |
| 堆溢出不能执行代码 | 通过覆盖函数指针或vtable可以执行代码 |
| ASLR可以防止堆溢出 | ASLR增加预测难度，但不防止溢出本身 |
| Java/Python没有堆溢出 | 有，但通常是逻辑漏洞而非内存错误 |
| 释放后立即崩溃就是UAF | 有些UAF不会立即崩溃，更危险 |

***

### 7. 总结

| 维度 | 核心要点 |
|------|---------|
| 原理 | 溢出覆盖堆元数据（size/fd/bk） |
| UAF | 使用已释放内存，通过悬空指针控制数据 |
| Double-Free | 同一块内存释放两次，导致空闲链表循环 |
| 堆风水 | 精心安排堆布局，创造可利用的条件 |
| 防御 | Safe-Linking、ASan、释放后置NULL |

**核心记忆**：堆溢出 = 覆盖堆元数据 + 控制堆管理器行为。UAF和Double-Free是最常见的堆漏洞类型。防御关键是释放后置NULL、使用智能指针、启用ASan检测。
