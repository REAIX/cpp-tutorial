# 什么是ASLR与DEP
> 📖 相关章节：[安全编程概述](../../13-安全编程与逆向工程/00-安全编程概述.md)、[内存安全](../../13-安全编程与逆向工程/01-内存安全与漏洞防御.md)

> **ASLR让攻击者找不到目标在哪，DEP让攻击者即使找到了也执行不了——两者组合，就是现代系统防御栈/堆溢出的基石。**

***

### 1. 核心速览

**ASLR（Address Space Layout Randomization，地址空间布局随机化）** 每次运行程序时随机化内存布局，让攻击者无法预测目标地址。**DEP（Data Execution Prevention，数据执行保护）** 也称NX位，标记数据页（栈/堆）为不可执行，阻止攻击者执行注入的Shellcode。两者配合，大幅提高了漏洞利用的难度。

***

### 2. 生活类比

| 类比 | 说明 |
|------|------|
| 没有ASLR = 固定门牌号 | 攻击者知道你家在哪，直接上门 |
| 有ASLR = 随机门牌号 | 每天换门牌号，攻击者找不到你家 |
| 没有DEP = 任何房间都能开派对 | 攻击者在储物间（数据区）也能搞事 |
| 有DEP = 只有客厅（代码区）能开派对 | 储物间不能执行代码 |

***

### 3. ASLR详解

#### 3.1 ASLR随机化的内容

```
无ASLR的内存布局（每次运行相同）：
┌──────────────┐ 0x08048000
│  代码段(.text)│  固定地址
├──────────────┤
│  数据段(.data)│  固定地址
├──────────────┤
│  堆           │  固定起始地址
├──────────────┤
│  ...          │
├──────────────┤
│  共享库       │  固定地址（如libc在0xb7e00000）
├──────────────┤
│  栈           │  固定地址
└──────────────┘

有ASLR的内存布局（每次运行不同）：
┌──────────────┐ 0x55XXXXXXXX  ← 随机偏移
│  代码段       │
├──────────────┤
│  数据段       │
├──────────────┤
│  堆           │  0x55XXXXXXXX ← 随机偏移
├──────────────┤
│  ...          │
├──────────────┤
│  共享库       │  0x7fXXXXXXXX ← 随机偏移
├──────────────┤
│  栈           │  0x7fXXXXXXXX ← 随机偏移
└──────────────┘
```

#### 3.2 ASLR的随机化范围

| 区域 | 32位随机化位数 | 64位随机化位数 | 说明 |
|------|--------------|--------------|------|
| 栈 | ~16位（64K种） | ~22位（4M种） | 栈基址随机 |
| 堆 | ~13位（8K种） | ~22位（4M种） | 堆起始地址随机 |
| 共享库 | ~8位（256种） | ~22位（4M种） | 库加载地址随机 |
| 可执行文件 | 不随机 | ~22位（PIE） | 需要PIE编译 |
| brk | 不随机 | 不随机 | 紧跟数据段 |

```
32位ASLR的弱点：
- 随机化位数少，可以暴力爆破
- 栈：16位 = 65536种可能，几秒就能爆破
- 库：8位 = 256种可能，瞬间爆破

64位ASLR的优势：
- 随机化位数多（22位以上）
- 暴力爆破不可行（4百万种以上）
- 但仍可被信息泄露绕过
```

#### 3.3 ASLR的状态控制

```bash
# Linux ASLR控制
# 查看当前ASLR状态
cat /proc/sys/kernel/randomize_va_space

# 0 = 关闭
# 1 = 部分随机化（共享库+栈）
# 2 = 完全随机化（共享库+栈+堆）

# 临时关闭（调试用）
echo 0 | sudo tee /proc/sys/kernel/randomize_va_space

# 永久设置
echo "kernel.randomize_va_space = 2" | sudo tee -a /etc/sysctl.conf

# 编译时启用PIE（让可执行文件也随机化）
gcc -pie -fPIE -o program program.c

# 查看二进制是否启用PIE
readelf -h program | grep Type
# DYN = PIE启用
# EXEC = PIE未启用
```

### 4. DEP/NX详解

#### 4.1 NX位原理

```
页表项中的NX位（No eXecute）：

┌──────────────────────────────────────────────┐
│ 页表项格式（x86-64）                          │
├──┬──┬──┬──┬──┬──┬──┬──┬──┬──┬──┬──┬──┬──┬──┐ │
│NX│..│..│..│..│..│..│..│..│..│..│..│..│..│..│ │
└──┴──┴──┴──┴──┴──┴──┴──┴──┴──┴──┴──┴──┴──┴──┘ │
│                                               │
NX=0: 该页可执行（代码段）                       │
NX=1: 该页不可执行（数据段、栈、堆）              │

典型内存权限：
代码段(.text):  R-X  （可读可执行，不可写）
数据段(.data):  RW-  （可读可写，不可执行）
栈:             RW-  （可读可写，不可执行）
堆:             RW-  （可读可写，不可执行）
```

#### 4.2 DEP的效果

```c
// 没有DEP：Shellcode在栈上可以执行
void vulnerable(char* input) {
    char buffer[64];
    strcpy(buffer, input);  // 溢出，Shellcode在buffer中
    // 函数返回时跳到buffer中的Shellcode
    // 没有DEP → Shellcode可以执行！
}

// 有DEP：Shellcode在栈上不能执行
// 函数返回时跳到buffer中的Shellcode
// CPU检测到NX位=1 → 触发段错误 → 程序崩溃
// 攻击者不能直接执行注入的代码

// 绕过DEP的方法：ROP（Return-Oriented Programming）
// 不注入新代码，而是利用已有代码片段
```

#### 4.3 DEP控制

```bash
# Linux NX位
# 编译时控制栈是否可执行
gcc -z noexecstack program.c   # 启用NX（默认）
gcc -z execstack program.c     # 禁用NX（调试用）

# 查看ELF的栈是否可执行
readelf -l program | grep GNU_STACK
# RWE = 可读写执行（NX关闭，危险）
# RW  = 可读写（NX启用，安全）

# Windows DEP
# 系统设置 → 高级 → 性能 → 数据执行保护
# OptIn: 仅保护核心Windows服务（默认）
# OptOut: 保护所有程序（可添加例外）
# AlwaysOn: 强制所有程序（不可关闭）
```

### 5. 绕过技术

#### 5.1 信息泄露（Info Leak）

```
ASLR的弱点：随机化只在程序启动时进行
一旦程序运行，地址就确定了
如果能泄露一个地址，就能推算其他地址

常见信息泄露方法：

1. 格式化字符串漏洞
   printf(user_input);  // 攻击者可以读栈上的数据
   // 泄露栈上的libc地址 → 计算system()的地址

2. 堆元数据泄露
   // 空闲堆块的fd/bk指向libc内部地址
   // 如果能读取这些指针，就能推算libc基址

3. 数组越界读取
   // 读取越界数据，可能包含指针

4. 侧信道攻击
   // 通过时间差异推断地址

信息泄露后：
libc_base = leaked_address - known_offset
system_addr = libc_base + system_offset
// 现在知道了system()的地址，可以构造ROP链
```

#### 5.2 ROP绕过DEP

```c
// ROP：利用已有代码绕过DEP
// 不注入新代码，而是串联已有代码片段

// 常见ROP策略：

// 策略1：直接调用system()
// ROP链：pop rdi; ret → "/bin/sh"地址 → system()地址

// 策略2：调用mprotect()使栈可执行
// mprotect(stack_addr, 0x1000, PROT_READ|PROT_WRITE|PROT_EXEC)
// 然后跳转到栈上的Shellcode

// 策略3：调用mmap()分配可执行内存
// 将Shellcode拷贝到可执行区域，然后跳转

// pwntools自动构造ROP链
from pwn import *

elf = ELF('./vulnerable')
libc = ELF('/lib/x86_64-linux-gnu/libc.so.6')

# 已泄露的libc地址
leaked_addr = 0x7f1234567890
libc.address = leaked_addr - libc.symbols['puts']

# 构造ROP链
rop = ROP(libc)
rop.call('system', [next(libc.search(b'/bin/sh'))])

print(rop.dump())
```

#### 5.3 Ret2libc

```
Ret2libc：返回到libc函数，不需要Shellcode

栈布局：
┌──────────────────────┐
│ 填充数据              │
├──────────────────────┤
│ system()地址          │  ← 返回地址被覆盖为system()
├──────────────────────┤
│ exit()地址            │  ← system()返回后跳到这里
├──────────────────────┤
│ "/bin/sh"字符串地址   │  ← system()的参数
└──────────────────────┘

执行流程：
1. 函数返回 → 跳到system()
2. system()从栈上取参数 → "/bin/sh"
3. 执行 /bin/sh → 获得shell
4. shell退出 → 跳到exit()

优势：
- 不需要注入代码，绕过DEP
- 只需要知道system()和"/bin/sh"的地址
- 地址可通过信息泄露获得
```

### 6. ASLR的强化

#### 6.1 强化措施

| 措施 | 说明 | 效果 |
|------|------|------|
| PIE | 可执行文件地址随机化 | 消除固定地址基址 |
| Full RELRO | GOT表只读 | 防止GOT覆写 |
| 64位系统 | 更大的随机化空间 | 暴力爆破不可行 |
| Fork服务器 | 每次fork继承地址 | 子进程地址相同（弱点） |
| ASLR + CFI | 控制流完整性 | 限制ROP gadget |

#### 6.2 ASLR的局限

```
ASLR不能防止的攻击：

1. 信息泄露攻击
   - 一旦泄露一个地址，ASLR就失效
   - 格式化字符串、越界读取等

2. fork()后的子进程
   - fork()继承父进程的内存布局
   - 子进程的地址与父进程相同
   - 可以在子进程中反复探测

3. 堆喷射（Heap Spraying）
   - 在大范围内分配相同内容的内存块
   - 提高跳转到Shellcode的概率

4. 部分覆盖
   - 只覆盖返回地址的最低1-2字节
   - 在256种可能中命中正确地址

5. 32位系统暴力爆破
   - 随机化位数太少
   - 可以快速尝试所有可能
```

***

### 7. 常见误区

| 误区 | 事实 |
|------|------|
| ASLR可以防止溢出 | ASLR只增加利用难度，不防止溢出本身 |
| DEP可以防止所有代码执行 | ROP可以绕过DEP |
| 64位ASLR不可绕过 | 信息泄露仍然可以绕过 |
| 关闭ASLR更安全 | 关闭ASLR让攻击更容易 |
| ASLR和DEP是同一回事 | 两者独立，ASLR管地址，DEP管执行权限 |

***

### 8. 总结

| 维度 | ASLR | DEP/NX |
|------|------|--------|
| 目标 | 隐藏目标地址 | 阻止代码执行 |
| 原理 | 随机化内存布局 | 数据页不可执行 |
| 绕过方法 | 信息泄露 | ROP |
| 效果 | 增加预测难度 | 阻止Shellcode |
| 配合使用 | 两者组合大幅提高利用难度 | |

**核心记忆**：ASLR = 地址随机化，让攻击者找不到目标；DEP = 数据不可执行，让攻击者跑不了代码。两者组合是现代系统安全的基础，但都能被绕过——信息泄露绕过ASLR，ROP绕过DEP。安全是多层防御，不是单一银弹。
