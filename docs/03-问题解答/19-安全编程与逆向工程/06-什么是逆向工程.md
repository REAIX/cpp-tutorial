# 什么是逆向工程
> 📖 相关章节：[安全编程概述](../../13-安全编程与逆向工程/00-安全编程概述.md)、[内存安全](../../13-安全编程与逆向工程/01-内存安全与漏洞防御.md)

> **逆向工程就是"拆开别人的玩具看怎么做的"——把编译后的二进制程序反汇编成汇编代码，分析它的逻辑和算法。** 正向是写代码→编译→二进制，逆向是二进制→反汇编→理解逻辑。

***

### 1. 核心提炼

**逆向工程（Reverse Engineering）** 是通过分析已编译的二进制程序，推导出其设计、算法和功能的过程。主要方法包括**静态分析**（不运行程序，直接分析二进制）和**动态分析**（运行程序并观察行为）。它是安全研究、恶意软件分析、漏洞挖掘的核心技能。

***

### 2. 生活类比

| 类比 | 说明 |
|------|------|
| 正向工程 = 按图纸盖楼 | 有设计图，按步骤施工 |
| 逆向工程 = 拆楼研究结构 | 没有图纸，拆开看怎么建的 |
| 反汇编 = 翻译外文 | 把机器码翻译成人能读的汇编 |
| 反编译 = 写摘要 | 从汇编推导出接近源代码的逻辑 |
| 调试 = 盯着施工 | 运行时观察每一步做什么 |

***

### 3. 静态分析与动态分析

| 维度 | 静态分析 | 动态分析 |
|------|---------|---------|
| 是否运行 | 不运行 | 运行 |
| 工具 | IDA Pro, Ghidra, Binary Ninja | GDB, x64dbg, WinDbg |
| 优势 | 全局视角，可看所有代码路径 | 可观察运行时行为和数据 |
| 劣势 | 无法确定实际执行路径 | 只能看到执行的路径 |
| 适用 | 理解程序结构、算法 | 验证假设、观察加密解密 |
| 挑战 | 代码混淆、加壳 | 反调试技术 |

关键窗口：

- 十六进制视图：原始二进制数据
- 函数窗口：所有识别的函数列表
- 交叉引用：谁调用了这个函数/使用了这个数据

### 5. Ghidra入门

#### 5.1 Ghidra特点

```
Ghidra vs IDA Pro：

| 维度       | IDA Pro          | Ghidra           |
|-----------|------------------|------------------|
| 价格      | 商业（数千美元）   | 免费开源          |
| 反编译器  | Hex-Rays（额外付费）| 内置免费          |
| 插件      | 丰富（部分付费）   | Java/Python脚本   |
| 平台      | Windows为主       | 跨平台（Java）    |
| 社区      | 专业逆向工程师     | 快速增长的开源社区 |
| 适合      | 专业安全研究员     | 学习和日常逆向     |
```

#### 5.2 Ghidra使用

```
Ghidra基本工作流：

1. 创建项目
   File → New Project → 非共享项目

2. 导入二进制文件
   File → Import File → 选择文件 → 自动分析

3. 分析
   Ghidra自动运行分析器：
   - 函数识别
   - 引用分析
   - 数据类型推断
   - 反编译

4. 查看反编译结果
   窗口 → 反编译（Decompile）
   显示C伪代码

5. 编写脚本
   Window → Script Manager → 新建Python脚本
```

```python
# Ghidra Python脚本示例：提取所有字符串
from ghidra.program.model.symbol import SymbolType

# 获取当前程序的所有字符串
listing = currentProgram.getListing()
dataIterator = listing.getDefinedData(True)

strings = []
for data in dataIterator:
    if data.hasStringValue():
        addr = data.getAddress()
        value = data.getValue()
        strings.append((str(addr), value))

# 输出结果
for addr, s in strings:
    print(f"{addr}: {s}")
```

### 6. 反汇编基础

#### 6.1 x86-64常用指令

```asm
; 数据传送
mov  rax, rbx       ; rax = rbx
mov  rax, [rbp-8]   ; rax = 内存[rbp-8]
mov  [rbp-8], rax   ; 内存[rbp-8] = rax
lea  rax, [rbp-8]   ; rax = rbp-8的地址（不是值）

; 算术运算
add  rax, rbx       ; rax += rbx
sub  rax, rbx       ; rax -= rbx
imul rax, rbx       ; rax *= rbx
xor  rax, rax       ; rax = 0（常用清零技巧）
inc  rax            ; rax++
dec  rax            ; rax--

; 比较和跳转
cmp  rax, rbx       ; 比较rax和rbx（设置标志位）
test rax, rax       ; 测试rax是否为0
je   label          ; 如果相等则跳转 (ZF=1)
jne  label          ; 如果不等则跳转 (ZF=0)
jl   label          ; 如果小于则跳转 (SF≠OF)
jg   label          ; 如果大于则跳转 (ZF=0且SF=OF)

; 函数调用
call function       ; 压入返回地址，跳转到function
ret                 ; 弹出返回地址，跳转回去
push rax            ; 压栈
pop  rax            ; 出栈

; 栈帧操作
push rbp            ; 保存旧栈帧
mov  rbp, rsp       ; 建立新栈帧
sub  rsp, 0x20      ; 分配局部变量空间
; ... 函数体 ...
leave               ; 恢复栈帧 (mov rsp,rbp; pop rbp)
ret                 ; 返回
```

#### 6.2 识别常见模式

```asm
; 模式1：if-else
    cmp  [rbp-4], 0
    je   else_branch
    ; if分支代码
    jmp  end_if
else_branch:
    ; else分支代码
end_if:
    ; 继续执行

; 模式2：for循环
    mov  [rbp-4], 0       ; i = 0
for_start:
    cmp  [rbp-4], 10      ; i < 10?
    jge  for_end
    ; 循环体
    inc  [rbp-4]          ; i++
    jmp  for_start
for_end:

; 模式3：switch-case
    cmp  [rbp-4], 0
    je   case_0
    cmp  [rbp-4], 1
    je   case_1
    cmp  [rbp-4], 2
    je   case_2
    jmp  default_case
    ; 或者使用跳转表（jump table）

; 模式4：函数调用
    mov  edi, 1           ; 第一个参数
    mov  esi, 2           ; 第二个参数
    mov  edx, 3           ; 第三个参数
    call some_function    ; 调用函数
    ; 返回值在eax/rax中
```

### 7. 合法性与伦理

#### 7.1 逆向工程的法律框架

```
逆向工程的法律状况（因地区和目的而异）：

合法的逆向：
✅ 安全研究（发现漏洞并负责任披露）
✅ 恶意软件分析
✅ 互操作性（理解文件格式以开发兼容软件）
✅ 学术研究
✅ CTF竞赛和安全挑战

灰色地带：
⚠️ 绕过DRM/反拷贝保护（DMCA 1201可能禁止）
⚠️ 逆向专有协议
⚠️ 逆向游戏反作弊系统

非法的逆向：
❌ 窃取商业机密
❌ 破解软件授权
❌ 开发作弊工具
❌ 逆向用于制造仿冒产品

中国法律：
- 《著作权法》：合理使用范围内的逆向可能被允许
- 《反不正当竞争法》：商业秘密保护
- 《网络安全法》：安全研究有法律空间
```

#### 7.2 伦理准则

```
逆向工程伦理准则：

1. 目的正当
   - 安全研究、学习、互操作性 → 正当
   - 盗版、作弊、窃取 → 不正当

2. 负责任披露
   - 发现漏洞先通知厂商
   - 给厂商合理时间修复
   - 不公开利用细节直到修复完成

3. 尊重知识产权
   - 不复制代码逻辑
   - 不分发逆向得到的源代码
   - 遵守EULA和许可协议

4. 不造成伤害
   - 不开发恶意利用
   - 不破坏他人系统
   - 不侵犯用户隐私
```

### 8. 常见误区

| 误区 | 事实 |
|------|------|
| 逆向工程就是黑客行为 | 逆向是中性技术，用途决定性质 |
| 逆向可以完全还原源代码 | 只能得到近似逻辑，变量名和注释丢失 |
| 逆向需要极高的技术 | 入门不难，精通需要经验 |
| 逆向是非法的 | 大部分情况下合法，取决于目的和地区 |
| 只有汇编才能逆向 | 高级工具可以反编译为C伪代码 |

### 9. 总结

| 维度 | 核心要点 |
|------|---------|
| 本质 | 从二进制推导程序逻辑和设计 |
| 静态分析 | 不运行程序，用IDA/Ghidra分析 |
| 动态分析 | 运行程序，用GDB/x64dbg观察 |
| 反汇编 | 机器码→汇编代码→理解逻辑 |
| 合法性 | 安全研究通常合法，窃取商业机密非法 |

**核心记忆**：逆向工程 = 静态分析（IDA/Ghidra）+ 动态分析（GDB/x64dbg）。从二进制推导逻辑，是安全研究和恶意软件分析的核心技能。合法性取决于目的和地区，安全研究通常合法。
