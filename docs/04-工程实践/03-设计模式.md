## 1. 设计模式概述

### 1. 概念与定义

**设计模式（design pattern）**：C++中用于解决软件设计问题的通用解决方案。设计模式可以提高代码的可维护性、可扩展性、可测试性、可读性和低耦合性。例如单例模式、工厂模式、建造者模式、原型模式等。

**创建型模式（creational pattern）**：C++中用于解决对象创建问题的设计模式。创建型模式可以分为单例模式、工厂模式、建造者模式、原型模式等。例如单例模式用于保证一个类只有一个实例，工厂模式用于创建对象的实例。

**结构型模式（structural pattern）**：C++中用于解决类与对象组合问题的设计模式。结构型模式可以分为适配器模式、装饰器模式、代理模式、外观模式等。例如适配器模式用于将一个接口转换为另一个接口，装饰器模式用于动态地给一个对象添加额外的功能。

**行为型模式（behavioral pattern）**：C++中用于解决对象间通信问题的设计模式。行为型模式可以分为观察者模式、策略模式、命令模式、状态模式等。例如观察者模式用于实现对象间的一对多依赖关系，策略模式用于实现算法的动态切换。

**单例模式（Singleton pattern）**：C++中用于保证一个类只有一个实例的设计模式。单例模式可以分为饿汉式单例和懒汉式单例。例如`class Singleton { /* ... */ };`用于实现单例模式。

**工厂模式（Factory pattern）**：C++中用于创建对象的实例的设计模式。工厂模式可以分为简单工厂模式、工厂方法模式、抽象工厂模式。例如`class Factory { /* ... */ };`用于实现工厂模式。

**建造者模式（Builder pattern）**：C++中用于创建复杂对象的实例的设计模式。建造者模式可以分为建造者模式和导演模式。例如`class Builder { /* ... */ };`用于实现建造者模式。

**原型模式（Prototype pattern）**：C++中用于创建对象的实例的设计模式。原型模式可以分为浅拷贝和深拷贝。例如`class Prototype { /* ... */ };`用于实现原型模式。

**适配器模式（Adapter pattern）**：C++中用于将一个接口转换为另一个接口的设计模式。适配器模式可以分为类适配器模式和对象适配器模式。例如`class Adapter { /* ... */ };`用于实现适配器模式。

**装饰器模式（Decorator pattern）**：C++中用于动态地给一个对象添加额外的功能的设计模式。装饰器模式可以分为装饰器模式和组件模式。例如`class Decorator { /* ... */ };`用于实现装饰器模式。

**代理模式（Proxy pattern）**：C++中用于为其他对象提供一种代理以控制对这个对象的访问的设计模式。代理模式可以分为静态代理模式和动态代理模式。例如`class Proxy { /* ... */ };`用于实现代理模式。

**外观模式（Facade pattern）**：C++中用于为子系统中的一组接口提供一个一致的界面的设计模式。外观模式可以分为外观模式和子系统模式。例如`class Facade { /* ... */ };`用于实现外观模式。

**观察者模式（Observer pattern）**：C++中用于实现对象间的一对多依赖关系的设计模式。观察者模式可以分为观察者模式和主题模式。例如`class Observer { /* ... */ };`用于实现观察者模式。

**策略模式（Strategy pattern）**：C++中用于实现算法的动态切换的设计模式。策略模式可以分为策略模式和上下文模式。例如`class Strategy { /* ... */ };`用于实现策略模式。

**命令模式（Command pattern）**：C++中用于将请求封装成对象的设计模式。命令模式可以分为命令模式和接收者模式。例如`class Command { /* ... */ };`用于实现命令模式。

**状态模式（State pattern）**：C++中用于允许一个对象在其内部状态改变时改变它的行为的设计模式。状态模式可以分为状态模式和上下文模式。例如`class State { /* ... */ };`用于实现状态模式。

### 2. 三大分类

| 类型 | 说明 | 常见模式 |
|-----|------|---------|
| **创建型** | 对象创建机制 | 单例、工厂、建造者、原型 |
| **结构型** | 类与对象组合 | 适配器、装饰器、代理、外观 |
| **行为型** | 对象间通信 | 观察者、策略、命令、状态 |

### 3. 设计原则（SOLID）

| 原则 | 说明 |
|-----|------|
| **S** - 单一职责 | 一个类只做一件事 |
| **O** - 开闭原则 | 对扩展开放，对修改关闭 |
| **L** - 里氏替换 | 子类可以替换父类 |
| **I** - 接口隔离 | 接口要小而专一 |
| **D** - 依赖倒置 | 依赖抽象而非具体 |

## 2. 创建型模式

### 1. 单例模式（Singleton）

```cpp
#include <iostream>
#include <mutex>
#include <atomic>

class Singleton {
private:
    static std::atomic<Singleton*> instance;
    static std::mutex mtx;
    
    Singleton() {}
    Singleton(const Singleton&) = delete;
    Singleton& operator=(const Singleton&) = delete;
    
public:
    static Singleton* getInstance() {
        Singleton* tmp = instance.load(std::memory_order_acquire);
        if (tmp == nullptr) {
            std::lock_guard<std::mutex> lock(mtx);
            tmp = instance.load(std::memory_order_relaxed);
            if (tmp == nullptr) {
                tmp = new Singleton();
                instance.store(tmp, std::memory_order_release);
            }
        }
        return tmp;
    }
    
    void doSomething() {
        std::cout << "Singleton working\n";
    }
};

std::atomic<Singleton*> Singleton::instance{nullptr};
std::mutex Singleton::mtx;

// C++11 更简洁的实现（推荐：Meyers' Singleton）
// C++11保证局部静态变量的初始化是线程安全的
class SingletonModern {
public:
    static SingletonModern& getInstance() {
        static SingletonModern instance;
        return instance;
    }
    
    SingletonModern(const SingletonModern&) = delete;
    SingletonModern& operator=(const SingletonModern&) = delete;
    
private:
    SingletonModern() = default;
};

// 注意：上面的DCL（Double-Checked Locking）实现使用了 std::atomic +
// memory_order_acquire/release，在C++11内存模型下是正确的。
// 旧版DCL使用普通指针，首次检查无同步读取，构成数据竞争（UB）。
// 仍推荐使用Meyers' Singleton（即SingletonModern），更简洁且线程安全。

// 使用
int main() {
    Singleton::getInstance()->doSomething();
    SingletonModern::getInstance();
    return 0;
}
```

### 2. 工厂模式（Factory）

#### 1. UML类图

```
工厂方法模式：

┌──────────────┐          ┌──────────────┐
│   Factory    │          │   Product    │
├──────────────┤          ├──────────────┤
│              │          │ + use()      │
├──────────────┤          └──────┬───────┘
│ + create()   │                 │
└──────┬───────┘                 │
       │                         │
  ┌────┴────┐              ┌────┴────┐
  │         │              │         │
┌─▼──────┐ ┌▼──────┐    ┌─▼──────┐ ┌▼──────┐
│FactoryA│ │FactoryB│    │ProductA│ │ProductB│
├────────┤ ├────────┤    ├────────┤ ├────────┤
│        │ │        │    │        │ │        │
├────────┤ ├────────┤    ├────────┤ ├────────┤
│create()│ │create()│    │ use()  │ │ use()  │
└───┬────┘ └───┬────┘    └────────┘ └────────┘
    │          │
    │          │
    └──┐    ┌──┘
       │    │
    creates  creates
       │    │
       ▼    ▼
  ProductA  ProductB
```

**模式结构：**
- `Product`：抽象产品接口
- `ProductA/B`：具体产品
- `Factory`：抽象工厂接口
- `FactoryA/B`：具体工厂，创建对应产品

```cpp
#include <iostream>
#include <memory>
#include <string>

// 产品接口
class Product {
public:
    virtual ~Product() = default;
    virtual void use() = 0;
};

// 具体产品
class ProductA : public Product {
public:
    void use() override {
        std::cout << "Using Product A\n";
    }
};

class ProductB : public Product {
public:
    void use() override {
        std::cout << "Using Product B\n";
    }
};

// 简单工厂
class SimpleFactory {
public:
    static std::unique_ptr<Product> create(const std::string& type) {
        if (type == "A") return std::make_unique<ProductA>();
        if (type == "B") return std::make_unique<ProductB>();
        return nullptr;
    }
};

// 工厂方法
class Factory {
public:
    virtual ~Factory() = default;
    virtual std::unique_ptr<Product> create() = 0;
};

class FactoryA : public Factory {
public:
    std::unique_ptr<Product> create() override {
        return std::make_unique<ProductA>();
    }
};

class FactoryB : public Factory {
public:
    std::unique_ptr<Product> create() override {
        return std::make_unique<ProductB>();
    }
};

// 使用
int main() {
    auto productA = SimpleFactory::create("A");
    productA->use();
    
    std::unique_ptr<Factory> factory = std::make_unique<FactoryB>();
    auto product = factory->create();
    product->use();
    
    return 0;
}
```

### 2. 装饰器模式（Decorator）

#include <iostream>

#include <string>

class Component {

    virtual ~Component() = default;

## 4. 行为型模式

### 1. 观察者模式（Observer）

#### 1. UML类图

```
┌──────────────────┐          ┌──────────────────┐
│     Subject      │          │     Observer     │
├──────────────────┤          ├──────────────────┤
│ - observers      │─────────▶│ + update()       │
├──────────────────┤          └────────┬─────────┘
│ + attach()       │                   │
│ + notify()       │                   │
└──────────────────┘                   │
                                       │
                              ┌────────┴────────┐
                              │                 │
                       ┌──────▼──────┐   ┌──────▼──────┐
                       │ Observer1   │   │ Observer2   │
                       ├─────────────┤   ├─────────────┤
                       │ - name      │   │ - name      │
                       ├─────────────┤   ├─────────────┤
                       │ + update()  │   │ + update()  │
                       └─────────────┘   └─────────────┘

工作流程：
1. Observer1 和 Observer2 注册到 Subject
2. Subject 状态改变时调用 notify()
3. notify() 遍历所有观察者，调用 update()
4. 各观察者收到通知并做出响应
```

```cpp
#include <iostream>
#include <vector>
#include <memory>
#include <string>

// 观察者接口
class Observer {
public:
    virtual ~Observer() = default;
    virtual void update(const std::string& message) = 0;
};

// 主题
class Subject {
private:
    std::vector<std::weak_ptr<Observer>> observers;
    
public:
    void attach(std::shared_ptr<Observer> observer) {
        observers.push_back(observer);
    }
    
    void notify(const std::string& message) {
        for (auto it = observers.begin(); it != observers.end();) {
            if (auto observer = it->lock()) {
                observer->update(message);
                ++it;
            } else {
                it = observers.erase(it);
            }
        }
    }
};

// 具体观察者
class ConcreteObserver : public Observer {
private:
    std::string name;
    
public:
    ConcreteObserver(const std::string& n) : name(n) {}
    
    void update(const std::string& message) override {
        std::cout << name << " received: " << message << "\n";
    }
};

// 使用
int main() {
    Subject subject;
    
    auto observer1 = std::make_shared<ConcreteObserver>("Observer1");
    auto observer2 = std::make_shared<ConcreteObserver>("Observer2");
    
    subject.attach(observer1);
    subject.attach(observer2);
    
    subject.notify("Hello!");
    return 0;
}
```

### 2. 策略模式（Strategy）

```cpp
#include <iostream>
#include <memory>
#include <vector>
#include <algorithm>

// 策略接口
class SortStrategy {
public:
    virtual ~SortStrategy() = default;
    virtual void sort(std::vector<int>& data) = 0;
};

// 具体策略
class AscendingSort : public SortStrategy {
public:
    void sort(std::vector<int>& data) override {
        std::sort(data.begin(), data.end());
    }
};

class DescendingSort : public SortStrategy {
public:
    void sort(std::vector<int>& data) override {
        std::sort(data.begin(), data.end(), std::greater<int>());
    }
};

// 上下文
class Sorter {
private:
    std::unique_ptr<SortStrategy> strategy;
    
public:
    void setStrategy(std::unique_ptr<SortStrategy> s) {
        strategy = std::move(s);
    }
    
    void sort(std::vector<int>& data) {
        if (strategy) {
            strategy->sort(data);
        }
    }
};

// 使用
int main() {
    std::vector<int> data = {3, 1, 4, 1, 5, 9, 2, 6};
    
    Sorter sorter;
    sorter.setStrategy(std::make_unique<AscendingSort>());
    sorter.sort(data);
    
    for (int n : data) std::cout << n << " ";
    std::cout << "\n";
    
    return 0;
}
```

### 3. 命令模式（Command）

```cpp
#include <iostream>
#include <memory>
#include <vector>
#include <string>

// 命令接口
class Command {
public:
    virtual ~Command() = default;
    virtual void execute() = 0;
    virtual void undo() = 0;
};

// 接收者
class Light {
public:
    void on() { std::cout << "Light is ON\n"; }
    void off() { std::cout << "Light is OFF\n"; }
};

// 具体命令
class LightOnCommand : public Command {
private:
    Light& light;
    
public:
    LightOnCommand(Light& l) : light(l) {}
    
    void execute() override { light.on(); }
    void undo() override { light.off(); }
};

class LightOffCommand : public Command {
private:
    Light& light;
    
public:
    LightOffCommand(Light& l) : light(l) {}
    
    void execute() override { light.off(); }
    void undo() override { light.on(); }
};

// 调用者
class RemoteControl {
private:
    std::vector<std::unique_ptr<Command>> commands;
    
public:
    void executeCommand(std::unique_ptr<Command> cmd) {
        cmd->execute();
        commands.push_back(std::move(cmd));
    }
    
    void undoLast() {
        if (!commands.empty()) {
            commands.back()->undo();
            commands.pop_back();
        }
    }
};

// 使用
int main() {
    Light light;
    RemoteControl remote;
    
    remote.executeCommand(std::make_unique<LightOnCommand>(light));
    remote.undoLast();
    
    return 0;
}
```

### 4. 状态模式（State）

```cpp
#include <iostream>
#include <memory>

class TrafficLight;

// 状态接口
class State {
public:
    virtual ~State() = default;
    virtual void handle(TrafficLight& light) = 0;
    virtual std::string getName() = 0;
};

// 上下文
class TrafficLight {
private:
    std::unique_ptr<State> state;
    
public:
    TrafficLight(std::unique_ptr<State> s) : state(std::move(s)) {}
    
    void setState(std::unique_ptr<State> s) {
        state = std::move(s);
    }
    
    void change() {
        std::cout << "Current: " << state->getName() << "\n";
        state->handle(*this);
    }
};

// 具体状态
class RedState : public State {
public:
    void handle(TrafficLight& light) override;
    std::string getName() override { return "Red"; }
};

class GreenState : public State {
public:
    void handle(TrafficLight& light) override;
    std::string getName() override { return "Green"; }
};

class YellowState : public State {
public:
    void handle(TrafficLight& light) override;
    std::string getName() override { return "Yellow"; }
};

void RedState::handle(TrafficLight& light) {
    light.setState(std::make_unique<GreenState>());
}

void GreenState::handle(TrafficLight& light) {
    light.setState(std::make_unique<YellowState>());
}

void YellowState::handle(TrafficLight& light) {
    light.setState(std::make_unique<RedState>());
}

// 使用
int main() {
    TrafficLight light(std::make_unique<RedState>());
    
    for (int i = 0; i < 6; ++i) {
        light.change();
    }
    
    return 0;
}
```

## 5. 注意事项与最佳实践

### 1. 模式选择指南

| 场景 | 推荐模式 |
|-----|---------|
| 需要唯一实例 | 单例 |
| 创建对象复杂 | 工厂、建造者 |
| 接口不兼容 | 适配器 |
| 动态添加功能 | 装饰器 |
| 对象间一对多依赖 | 观察者 |
| 算法可互换 | 策略 |
| 状态改变行为 | 状态 |

### 2. 常见陷阱

```cpp
// 1. 单例内存泄漏
class BadSingleton {
    static BadSingleton* instance;
public:
    static BadSingleton* get() {
        if (!instance) instance = new BadSingleton();
        return instance;
    }
};
// 解决：使用静态局部变量

// 2. 过度使用模式
// 简单问题不需要复杂模式
class Simple {
    int value;
public:
    int getValue() { return value; }
};

// 3. 忽略性能
// 每次创建新对象可能影响性能
// 考虑对象池或缓存
```

### 3. 最佳实践

```cpp
// 1. 组合优于继承
class Good {
    std::unique_ptr<Behavior> behavior;  // 组合
};

// 2. 面向接口编程
void process(std::unique_ptr<Strategy> strategy) {
    strategy->execute();
}

// 3. 单一职责
class Logger {
    void log(const std::string& msg);
};

class Validator {
    bool validate(const std::string& data);
};

// 4. 依赖注入
class Service {
    std::shared_ptr<Repository> repo;
public:
    Service(std::shared_ptr<Repository> r) : repo(r) {}
};
```

## 6. 本章小结

### 1. 核心概念回顾

| 类型 | 模式 | 用途 |
|-----|------|------|
| **创建型** | 单例 | 唯一实例 |
| | 工厂 | 对象创建 |
| | 建造者 | 复杂对象 |
| | 原型 | 对象克隆 |
| **结构型** | 适配器 | 接口转换 |
| | 装饰器 | 动态扩展 |
| | 代理 | 访问控制 |
| | 外观 | 简化接口 |
| **行为型** | 观察者 | 事件通知 |
| | 策略 | 算法切换 |
| | 命令 | 操作封装 |
| | 状态 | 状态行为 |

### 2. 关键语法要点

1. **单例**：静态局部变量、删除拷贝构造
2. **工厂**：虚函数、智能指针
3. **装饰器**：继承+组合
4. **观察者**：weak_ptr 避免循环引用
5. **策略**：多态、函数对象

### 3. 最佳实践

1. 选择合适的模式，不过度设计
2. 组合优于继承
3. 面向接口编程
4. 使用智能指针管理资源
5. 遵循 SOLID 原则
