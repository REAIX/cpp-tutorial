### 1. 桥接模式（Bridge）

#### 1. 问题

假设你要开发一个图形绘制库，支持不同形状（圆形、矩形）和不同渲染方式（OpenGL、DirectX）：

```cpp
/* 不用桥接：类爆炸 */
class CircleOpenGL {};
class CircleDirectX {};
class RectangleOpenGL {};
class RectangleDirectX {};
/* 每增加一个形状或渲染方式，类数量乘以另一个维度的数量 */
```

形状和渲染是两个独立变化的维度，用继承会导致类爆炸。

#### 2. 模式

桥接模式将**抽象部分**（形状）与**实现部分**（渲染）分离，使它们可以独立变化。核心思想：用组合代替继承。

```
┌─────────────┐         ┌─────────────┐
│   Shape     │         │  Renderer   │
│ (抽象部分)   │────────▶│ (实现部分)   │
├─────────────┤         ├─────────────┤
│ #renderer   │         │ +render()   │
├─────────────┤         └──────┬──────┘
│ +draw()     │                │
└──────┬──────┘          ┌─────┴─────┐
       │                 │           │
 ┌─────┴─────┐    ┌──────▼──┐ ┌──────▼──┐
 │  Circle   │    │ OpenGL  │ │ DirectX │
 │ Rectangle │    │Renderer │ │Renderer │
 └───────────┘    └─────────┘ └─────────┘
```

#### 3. C++实现

```cpp
#include <iostream>
#include <memory>
#include <string>

/* 实现接口：渲染器 */
class Renderer {
public:
    virtual ~Renderer() = default;
    virtual void renderCircle(const std::string& name) = 0;
    virtual void renderRectangle(const std::string& name) = 0;
};

/* 具体实现：OpenGL渲染器 */
class OpenGLRenderer : public Renderer {
public:
    void renderCircle(const std::string& name) override {
        std::cout << "OpenGL 渲染圆形: " << name << std::endl;
    }

    void renderRectangle(const std::string& name) override {
        std::cout << "OpenGL 渲染矩形: " << name << std::endl;
    }
};

/* 具体实现：DirectX渲染器 */
class DirectXRenderer : public Renderer {
public:
    void renderCircle(const std::string& name) override {
        std::cout << "DirectX 渲染圆形: " << name << std::endl;
    }

    void renderRectangle(const std::string& name) override {
        std::cout << "DirectX 渲染矩形: " << name << std::endl;
    }
};

/* 抽象接口：形状 */
class Shape {
protected:
    std::shared_ptr<Renderer> renderer;

public:
    Shape(std::shared_ptr<Renderer> r) : renderer(r) {}
    virtual ~Shape() = default;
    virtual void draw() = 0;
};

/* 扩展抽象：圆形 */
class Circle : public Shape {
private:
    std::string name;

public:
    Circle(std::shared_ptr<Renderer> r, const std::string& n)
        : Shape(r), name(n) {}

    void draw() override {
        renderer->renderCircle(name);
    }
};

/* 扩展抽象：矩形 */
class Rectangle : public Shape {
private:
    std::string name;

public:
    Rectangle(std::shared_ptr<Renderer> r, const std::string& n)
        : Shape(r), name(n) {}

    void draw() override {
        renderer->renderRectangle(name);
    }
};

int main() {
    auto opengl = std::make_shared<OpenGLRenderer>();
    auto directx = std::make_shared<DirectXRenderer>();

    /* 同一个形状，不同渲染器 */
    Circle circle1(opengl, "太阳");
    Circle circle2(directx, "月亮");

    /* 同一个渲染器，不同形状 */
    Rectangle rect1(opengl, "门");
    Rectangle rect2(directx, "窗");

    circle1.draw();
    circle2.draw();
    rect1.draw();
    rect2.draw();

    return 0;
}
```

#### 4. 适用场景

- 一个类有**两个独立变化的维度**，用继承会导致类爆炸
- 需要在运行时切换实现（如切换渲染引擎、切换数据库驱动）
- 想让抽象和实现可以独立扩展，互不影响

### 2. 组合模式（Composite）

#### 1. 问题

文件系统中有文件和文件夹，文件夹可以包含文件和其他文件夹。如果分别处理文件和文件夹，代码会充满`if-else`类型判断：

```cpp
/* 不用组合：每增加一种节点类型就要改遍历逻辑 */
void printSize(FileSystemNode* node) {
    if (node->isFile()) {
        /* 处理文件 */
    } else if (node->isFolder()) {
        /* 处理文件夹，还要递归处理子节点 */
    }
}
```

#### 2. 模式

组合模式将对象组合成**树形结构**，使得用户对单个对象和组合对象的使用具有一致性。核心思想：统一接口，递归组合。

```
┌──────────────┐
│  Component   │  ← 统一接口
├──────────────┤
│ +operation() │
└──────┬───────┘
       │
  ┌────┴────┐
  │         │
┌─▼──────┐ ┌▼────────┐
│  Leaf  │ │Composite│  ← 叶子和组合实现同一接口
├────────┤ ├─────────┤
│        │ │children │  ← 组合持有子组件列表
│        │ │add()    │
│        │ │remove() │
└────────┘ └─────────┘
```

#### 3. C++实现

```cpp
#include <iostream>
#include <memory>
#include <vector>
#include <string>

/* 组件接口：文件系统节点 */
class FileSystemNode {
public:
    virtual ~FileSystemNode() = default;
    virtual void display(int indent = 0) = 0;
    virtual int getSize() = 0;
};

/* 叶子节点：文件 */
class File : public FileSystemNode {
private:
    std::string name;
    int size;

public:
    File(const std::string& n, int s) : name(n), size(s) {}

    void display(int indent = 0) override {
        std::string padding(indent, ' ');
        std::cout << padding << "- 文件: " << name
                  << " (" << size << "KB)" << std::endl;
    }

    int getSize() override {
        return size;
    }
};

/* 组合节点：文件夹 */
class Folder : public FileSystemNode {
private:
    std::string name;
    std::vector<std::shared_ptr<FileSystemNode>> children;

public:
    Folder(const std::string& n) : name(n) {}

    void add(std::shared_ptr<FileSystemNode> node) {
        children.push_back(node);
    }

    void remove(std::shared_ptr<FileSystemNode> node) {
        for (auto it = children.begin(); it != children.end(); ++it) {
            if (*it == node) {
                children.erase(it);
                break;
            }
        }
    }

    void display(int indent = 0) override {
        std::string padding(indent, ' ');
        std::cout << padding << "+ 文件夹: " << name
                  << " (总大小: " << getSize() << "KB)" << std::endl;
        for (auto& child : children) {
            child->display(indent + 2);
        }
    }

    int getSize() override {
        int total = 0;
        for (auto& child : children) {
            total += child->getSize();
        }
        return total;
    }
};

int main() {
    auto root = std::make_shared<Folder>("项目根目录");
    auto src = std::make_shared<Folder>("src");
    auto docs = std::make_shared<Folder>("docs");

    src->add(std::make_shared<File>("main.cpp", 15));
    src->add(std::make_shared<File>("utils.cpp", 8));

    docs->add(std::make_shared<File>("README.md", 3));

    root->add(src);
    root->add(docs);
    root->add(std::make_shared<File>("CMakeLists.txt", 2));

    root->display();

    return 0;
}
```

#### 4. 适用场景

- 需要表示**树形结构**（文件系统、菜单系统、组织架构）
- 希望统一处理**单个对象和组合对象**，避免类型判断
- 需要递归遍历的结构（XML/HTML DOM、GUI组件树）

### 3. 享元模式（Flyweight）

#### 1. 问题

游戏中有10000棵树，每棵树有自己的位置和大小，但树的纹理、3D模型是共享的。如果每棵树都存储一份纹理，内存会爆炸：

```cpp
/* 不用享元：10000棵树 = 10000份纹理，内存爆炸 */
class Tree {
    Texture texture;  /* 每棵树都存一份纹理！ */
    int x, y;
    double scale;
};
```

#### 2. 模式

享元模式通过**共享细粒度对象**来减少内存使用。将对象的状态分为：
- **内部状态**（Intrinsic）：可共享的、不随环境变化的部分（纹理、模型）
- **外部状态**（Extrinsic）：不可共享的、随环境变化的部分（位置、大小）

#### 3. C++实现

```cpp
#include <iostream>
#include <memory>
#include <unordered_map>
#include <string>

/* 享元对象：树的共享数据（内部状态） */
class TreeType {
private:
    std::string name;
    std::string color;
    std::string texture;

public:
    TreeType(const std::string& n, const std::string& c, const std::string& t)
        : name(n), color(c), texture(t) {}

    void draw(int x, int y, double scale) const {
        std::cout << "绘制 " << name
                  << " 颜色=" << color
                  << " 纹理=" << texture
                  << " 位置=(" << x << "," << y << ")"
                  << " 缩放=" << scale
                  << std::endl;
    }
};

/* 享元工厂：管理共享对象 */
class TreeFactory {
private:
    static std::unordered_map<std::string, std::shared_ptr<TreeType>> types;

public:
    static std::shared_ptr<TreeType> getTreeType(
        const std::string& name,
        const std::string& color,
        const std::string& texture)
    {
        std::string key = name + "_" + color + "_" + texture;
        if (types.find(key) == types.end()) {
            types[key] = std::make_shared<TreeType>(name, color, texture);
            std::cout << "创建新的树类型: " << key << std::endl;
        }
        return types[key];
    }
};

std::unordered_map<std::string, std::shared_ptr<TreeType>> TreeFactory::types;

/* 上下文对象：树的外部状态 + 享元引用 */
class Tree {
private:
    int x, y;
    double scale;
    std::shared_ptr<TreeType> type;

public:
    Tree(int x, int y, double scale, std::shared_ptr<TreeType> t)
        : x(x), y(y), scale(scale), type(t) {}

    void draw() const {
        type->draw(x, y, scale);
    }
};

int main() {
    /* 只有3种树类型，但可以创建10000棵树 */
    auto oak = TreeFactory::getTreeType("橡树", "绿色", "粗糙");
    auto pine = TreeFactory::getTreeType("松树", "深绿", "针状");
    auto maple = TreeFactory::getTreeType("枫树", "红色", "光滑");

    std::vector<Tree> forest;
    forest.push_back(Tree(10, 20, 1.0, oak));
    forest.push_back(Tree(30, 40, 1.5, oak));
    forest.push_back(Tree(50, 60, 0.8, pine));
    forest.push_back(Tree(70, 80, 1.2, maple));
    forest.push_back(Tree(90, 100, 1.0, pine));

    for (const auto& tree : forest) {
        tree.draw();
    }

    return 0;
}
```

#### 4. 适用场景

- 需要创建**大量相似对象**，内存是瓶颈
- 对象的大部分状态可以**外部化**（提取为外部状态）
- 游戏开发中的粒子系统、树木、NPC等大量对象管理
- 文本编辑器中的字符格式化（相同字体/大小共享）

### 4. 迭代器模式（Iterator）

#### 1. 问题

你有一个自定义容器类，想用统一的方式遍历它，而不是暴露内部数据结构：

```cpp
/* 不用迭代器：暴露了内部是vector的事实 */
class MyContainer {
    std::vector<int> data;
public:
    std::vector<int>& getData() { return data; }  /* 糟糕！暴露了实现细节 */
};
```

#### 2. 模式

迭代器模式提供一种方法**顺序访问聚合对象中的元素**，而不暴露其内部表示。C++ STL的迭代器就是这个模式的经典实现。

#### 3. C++实现

```cpp
#include <iostream>
#include <vector>
#include <memory>

/* 迭代器接口 */
template<typename T>
class Iterator {
public:
    virtual ~Iterator() = default;
    virtual bool hasNext() = 0;
    virtual T next() = 0;
};

/* 聚合接口 */
template<typename T>
class Aggregate {
public:
    virtual ~Aggregate() = default;
    virtual std::unique_ptr<Iterator<T>> createIterator() = 0;
};

/* 具体迭代器：数组迭代器 */
template<typename T>
class ArrayIterator : public Iterator<T> {
private:
    const std::vector<T>& data;
    size_t index;

public:
    ArrayIterator(const std::vector<T>& d) : data(d), index(0) {}

    bool hasNext() override {
        return index < data.size();
    }

    T next() override {
        return data[index++];
    }
};

/* 具体聚合：自定义列表 */
template<typename T>
class MyList : public Aggregate<T> {
private:
    std::vector<T> data;

public:
    void add(const T& item) {
        data.push_back(item);
    }

    size_t size() const {
        return data.size();
    }

    std::unique_ptr<Iterator<T>> createIterator() override {
        return std::make_unique<ArrayIterator<T>>(data);
    }
};

/* 演示STL迭代器的设计思想 */
template<typename T>
void printWithIterator(Iterator<T>& it) {
    while (it.hasNext()) {
        std::cout << it.next() << " ";
    }
    std::cout << std::endl;
}

int main() {
    MyList<int> list;
    list.add(10);
    list.add(20);
    list.add(30);
    list.add(40);
    list.add(50);

    auto iter = list.createIterator();
    printWithIterator(*iter);

    return 0;
}
```

#### 4. 适用场景

- 需要统一遍历不同类型的聚合对象
- 不想暴露聚合对象的内部表示
- 需要多种遍历方式（前序、中序、后序遍历树）
- STL容器的设计基础——每个容器都提供`begin()`/`end()`

### 5. 中介者模式（Mediator）

#### 1. 问题

聊天室中，每个用户都需要和其他所有用户直接通信，导致网状依赖：

```cpp
/* 不用中介者：每个用户都要知道其他所有用户 */
class User {
    std::vector<User*> contacts;  /* 联系人列表越来越长 */
    void sendMessage(const std::string& msg) {
        for (auto* c : contacts) c->receive(msg);  /* 紧耦合！ */
    }
};
```

#### 2. 模式

中介者模式用一个**中介对象**来封装一系列对象之间的交互，使各对象不需要显式引用彼此，从而使其耦合松散。

```
┌────────┐  ┌────────┐  ┌────────┐
│ User A │  │ User B │  │ User C │
└───┬────┘  └───┬────┘  └───┬────┘
    │           │           │
    └───────────┼───────────┘
                │
          ┌─────▼─────┐
          │  Mediator  │  ← 所有通信通过中介者
          │ (聊天室)    │
          └───────────┘
```

#### 3. C++实现

```cpp
#include <iostream>
#include <string>
#include <vector>

/* 前向声明 */
class ChatRoom;

/* 同事类：用户 */
class User {
private:
    std::string name;
    ChatRoom* room;

public:
    User(const std::string& n) : name(n), room(nullptr) {}

    std::string getName() const { return name; }

    void setRoom(ChatRoom* r) { room = r; }

    void send(const std::string& message);

    void receive(const std::string& from, const std::string& message) {
        std::cout << "[" << name << " 收到来自 " << from
                  << " 的消息]: " << message << std::endl;
    }
};

/* 中介者：聊天室 */
class ChatRoom {
private:
    std::vector<User*> users;

public:
    void join(User* user) {
        users.push_back(user);
        user->setRoom(this);
        std::cout << user->getName() << " 加入了聊天室" << std::endl;
    }

    void leave(User* user) {
        for (auto it = users.begin(); it != users.end(); ++it) {
            if (*it == user) {
                users.erase(it);
                break;
            }
        }
        user->setRoom(nullptr);
        std::cout << user->getName() << " 离开了聊天室" << std::endl;
    }

    void broadcast(User* sender, const std::string& message) {
        for (auto* user : users) {
            if (user != sender) {
                user->receive(sender->getName(), message);
            }
        }
    }

    void sendTo(User* sender, User* receiver, const std::string& message) {
        receiver->receive(sender->getName(), message);
    }
};

void User::send(const std::string& message) {
    if (room) {
        room->broadcast(this, message);
    }
}

int main() {
    ChatRoom room;

    User alice("Alice");
    User bob("Bob");
    User charlie("Charlie");

    room.join(&alice);
    room.join(&bob);
    room.join(&charlie);

    std::cout << std::endl;
    alice.send("大家好！");

    std::cout << std::endl;
    bob.send("你好 Alice！");

    return 0;
}
```

#### 4. 适用场景

- 一组对象以**复杂且混乱的方式通信**，依赖关系网状化
- 想要复用一个对象，但它引用了太多其他对象（空中交通管制系统）
- GUI组件之间的交互（按钮、文本框、列表框之间的联动）

### 6. 备忘录模式（Memento）

#### 1. 问题

编辑器需要实现"撤销"功能，但直接暴露对象的内部状态会破坏封装：

```cpp
/* 不用备忘录：直接暴露内部状态，破坏封装 */
class Editor {
public:
    std::string text;  /* 公开内部状态！ */
    int cursor;
};
```

#### 2. 模式

备忘录模式在不破坏封装的前提下，**捕获对象的内部状态**，以便之后恢复。核心思想：将状态保存为不可变的"快照"。

#### 3. C++实现

```cpp
#include <iostream>
#include <string>
#include <vector>
#include <memory>

/* 备忘录：保存编辑器的状态快照 */
class EditorMemento {
private:
    std::string text;
    int cursorPos;

    /* 只有编辑器可以访问备忘录的内容 */
    friend class Editor;

    EditorMemento(const std::string& t, int c) : text(t), cursorPos(c) {}

public:
    /* 外部只能看到快照的元信息 */
    int getCursorPos() const { return cursorPos; }
};

/* 原发器：编辑器 */
class Editor {
private:
    std::string text;
    int cursorPos;

public:
    Editor() : cursorPos(0) {}

    void type(const std::string& words) {
        text.insert(cursorPos, words);
        cursorPos += words.length();
    }

    void moveCursor(int pos) {
        cursorPos = pos;
    }

    void show() const {
        std::cout << "文本: \"" << text
                  << "\" 光标位置: " << cursorPos << std::endl;
    }

    /* 创建备忘录 */
    std::shared_ptr<EditorMemento> save() {
        return std::shared_ptr<EditorMemento>(
            new EditorMemento(text, cursorPos)
        );
    }

    /* 从备忘录恢复 */
    void restore(std::shared_ptr<EditorMemento> memento) {
        text = memento->text;
        cursorPos = memento->cursorPos;
    }
};

/* 负责人：历史记录管理器 */
class History {
private:
    std::vector<std::shared_ptr<EditorMemento>> snapshots;

public:
    void push(std::shared_ptr<EditorMemento> memento) {
        snapshots.push_back(memento);
    }

    std::shared_ptr<EditorMemento> pop() {
        if (snapshots.empty()) return nullptr;
        auto m = snapshots.back();
        snapshots.pop_back();
        return m;
    }

    bool isEmpty() const {
        return snapshots.empty();
    }
};

int main() {
    Editor editor;
    History history;

    /* 输入第一行 */
    history.push(editor.save());
    editor.type("你好");
    editor.show();

    /* 输入第二行 */
    history.push(editor.save());
    editor.type(" 世界");
    editor.show();

    /* 输入第三行 */
    editor.type("！");
    editor.show();

    /* 撤销一次 */
    std::cout << std::endl << "--- 撤销 ---" << std::endl;
    editor.restore(history.pop());
    editor.show();

    /* 再撤销一次 */
    std::cout << std::endl << "--- 再撤销 ---" << std::endl;
    editor.restore(history.pop());
    editor.show();

    return 0;
}
```

#### 4. 适用场景

- 需要**撤销/重做**功能（编辑器、绘图软件）
- 需要保存对象在某个时刻的状态快照，以便之后回滚
- 事务处理中的检查点（checkpoint）机制
- 游戏中的存档/读档功能

### 7. 模板方法模式（Template Method）

#### 1. 问题

多个类有相似的算法流程，但某些步骤的实现不同。如果每个类都从头写，会有大量重复代码：

```cpp
/* 不用模板方法：每个类都重复相同的流程框架 */
class PDFReport {
    void generate() {
        openFile();     /* 重复 */
        writeHeader();  /* 不同 */
        writeBody();    /* 不同 */
        writeFooter();  /* 不同 */
        closeFile();    /* 重复 */
    }
};
```

#### 2. 模式

模板方法模式在基类中定义**算法的骨架**，将某些步骤延迟到子类中实现。核心思想：不变的部分在基类实现，变化的部分由子类实现。

#### 3. C++实现

```cpp
#include <iostream>
#include <string>

/* 抽象类：定义算法骨架 */
class ReportGenerator {
public:
    /* 模板方法：定义算法骨架，子类不应重写 */
    void generate() {
        openFile();
        writeHeader();
        writeBody();
        writeFooter();
        closeFile();
    }

    virtual ~ReportGenerator() = default;

protected:
    /* 公共步骤：基类实现 */
    void openFile() {
        std::cout << "打开文件..." << std::endl;
    }

    void closeFile() {
        std::cout << "关闭文件..." << std::endl;
    }

    /* 变化步骤：子类实现 */
    virtual void writeHeader() = 0;
    virtual void writeBody() = 0;
    virtual void writeFooter() = 0;
};

/* 具体类：HTML报告 */
class HTMLReport : public ReportGenerator {
protected:
    void writeHeader() override {
        std::cout << "写入 <html><head>...</head>" << std::endl;
    }

    void writeBody() override {
        std::cout << "写入 <body>HTML内容</body>" << std::endl;
    }

    void writeFooter() override {
        std::cout << "写入 </html>" << std::endl;
    }
};

/* 具体类：Markdown报告 */
class MarkdownReport : public ReportGenerator {
protected:
    void writeHeader() override {
        std::cout << "写入 # 标题" << std::endl;
    }

    void writeBody() override {
        std::cout << "写入 Markdown正文内容" << std::endl;
    }

    void writeFooter() override {
        std::cout << "写入 --- 完 ---" << std::endl;
    }
};

/* 具体类：纯文本报告 */
class TextReport : public ReportGenerator {
protected:
    void writeHeader() override {
        std::cout << "写入 ===== 报告 =====" << std::endl;
    }

    void writeBody() override {
        std::cout << "写入 纯文本正文内容" << std::endl;
    }

    void writeFooter() override {
        std::cout << "写入 ================" << std::endl;
    }
};

int main() {
    std::cout << "--- 生成HTML报告 ---" << std::endl;
    HTMLReport html;
    html.generate();

    std::cout << std::endl << "--- 生成Markdown报告 ---" << std::endl;
    MarkdownReport md;
    md.generate();

    std::cout << std::endl << "--- 生成纯文本报告 ---" << std::endl;
    TextReport txt;
    txt.generate();

    return 0;
}
```

#### 4. 适用场景

- 多个类有**相同的算法流程**，但某些步骤不同
- **框架设计**的核心模式（框架定义流程，用户实现具体步骤）
- 想控制子类的扩展点（NVI手法：Non-Virtual Interface）

### 8. 访问者模式（Visitor）

#### 1. 问题

编译器需要遍历AST（抽象语法树），对不同类型的节点执行不同操作（类型检查、代码生成、优化）。如果把这些操作都写在节点类里，每增加一种操作就要修改所有节点类：

```cpp
/* 不用访问者：每增加一种操作就要改所有节点类 */
class NumberNode {
    void typeCheck() { /* ... */ }
    void codeGen() { /* ... */ }
    void optimize() { /* ... */ }  /* 又要改！ */
};
```

#### 2. 模式

访问者模式允许在不修改类的前提下**增加操作**。核心思想：将操作从数据结构中分离出来，放入访问者中。利用C++的**双分派**机制实现。

#### 3. C++实现

```cpp
#include <iostream>
#include <memory>
#include <vector>
#include <string>

/* 前向声明 */
class NumberNode;
class StringNode;
class BinaryOpNode;

/* 访问者接口 */
class ASTVisitor {
public:
    virtual ~ASTVisitor() = default;
    virtual void visit(NumberNode& node) = 0;
    virtual void visit(StringNode& node) = 0;
    virtual void visit(BinaryOpNode& node) = 0;
};

/* 节点基类 */
class ASTNode {
public:
    virtual ~ASTNode() = default;
    virtual void accept(ASTVisitor& visitor) = 0;
};

/* 具体节点：数字 */
class NumberNode : public ASTNode {
private:
    double value;

public:
    NumberNode(double v) : value(v) {}

    double getValue() const { return value; }

    void accept(ASTVisitor& visitor) override {
        visitor.visit(*this);
    }
};

/* 具体节点：字符串 */
class StringNode : public ASTNode {
private:
    std::string value;

public:
    StringNode(const std::string& v) : value(v) {}

    std::string getValue() const { return value; }

    void accept(ASTVisitor& visitor) override {
        visitor.visit(*this);
    }
};

/* 具体节点：二元运算 */
class BinaryOpNode : public ASTNode {
private:
    std::string op;
    std::unique_ptr<ASTNode> left;
    std::unique_ptr<ASTNode> right;

public:
    BinaryOpNode(const std::string& o,
                 std::unique_ptr<ASTNode> l,
                 std::unique_ptr<ASTNode> r)
        : op(o), left(std::move(l)), right(std::move(r)) {}

    std::string getOp() const { return op; }
    ASTNode& getLeft() { return *left; }
    ASTNode& getRight() { return *right; }

    void accept(ASTVisitor& visitor) override {
        visitor.visit(*this);
    }
};

/* 具体访问者：打印AST */
class PrintVisitor : public ASTVisitor {
private:
    int indent = 0;

    void printIndent() {
        for (int i = 0; i < indent; ++i) {
            std::cout << "  ";
        }
    }

public:
    void visit(NumberNode& node) override {
        printIndent();
        std::cout << "数字: " << node.getValue() << std::endl;
    }

    void visit(StringNode& node) override {
        printIndent();
        std::cout << "字符串: \"" << node.getValue() << "\"" << std::endl;
    }

    void visit(BinaryOpNode& node) override {
        printIndent();
        std::cout << "二元运算: " << node.getOp() << std::endl;
        indent++;
        node.getLeft().accept(*this);
        node.getRight().accept(*this);
        indent--;
    }
};

/* 具体访问者：计算表达式值（简化版） */
class EvaluateVisitor : public ASTVisitor {
private:
    double result;

public:
    double getResult() const { return result; }

    void visit(NumberNode& node) override {
        result = node.getValue();
    }

    void visit(StringNode& node) override {
        result = 0.0;
    }

    void visit(BinaryOpNode& node) override {
        node.getLeft().accept(*this);
        double leftVal = result;
        node.getRight().accept(*this);
        double rightVal = result;

        if (node.getOp() == "+") result = leftVal + rightVal;
        else if (node.getOp() == "-") result = leftVal - rightVal;
        else if (node.getOp() == "*") result = leftVal * rightVal;
        else if (node.getOp() == "/") result = leftVal / rightVal;
    }
};

int main() {
    /* 构建表达式: (3 + 4) * 2 */
    auto expr = std::make_unique<BinaryOpNode>(
        "*",
        std::make_unique<BinaryOpNode>(
            "+",
            std::make_unique<NumberNode>(3),
            std::make_unique<NumberNode>(4)
        ),
        std::make_unique<NumberNode>(2)
    );

    std::cout << "--- 打印AST ---" << std::endl;
    PrintVisitor printer;
    expr->accept(printer);

    std::cout << std::endl << "--- 计算表达式 ---" << std::endl;
    EvaluateVisitor evaluator;
    expr->accept(evaluator);
    std::cout << "结果: " << evaluator.getResult() << std::endl;

    return 0;
}
```

#### 4. 适用场景

- 需要对一个**固定结构的对象树**执行多种不同操作
- **编译器**：AST遍历、类型检查、代码生成
- 数据结构稳定，但操作经常变化
- 注意：如果经常增加新的节点类型，访问者模式反而不合适（需要修改所有访问者）

## 2. C++特有的高级模式

GoF的23个模式是面向对象语言的通用模式。但C++有模板元编程的能力，催生了独有的高级模式——它们在**编译期**完成多态，实现**零开销抽象**。

| 模式 | 核心思想 | 与传统模式的区别 |
|-----|---------|----------------|
| **CRTP** | 编译期多态 | 替代虚函数，零开销 |
| **Type Erasure** | 运行时多态+值语义 | 替代虚函数+指针，值语义更安全 |
| **Policy-Based Design** | 编译期策略组合 | 替代策略模式的运行时分派 |
| **RAII守卫** | 析构函数即资源回收 | C++独有的确定性析构 |

---

### 1. CRTP（奇异递归模板模式）

#### 1. 问题

虚函数是C++实现运行时多态的标准方式，但它有开销：
- 虚函数表（vtable）增加内存
- 虚函数调用是间接跳转，无法内联
- 性能敏感场景下，这些开销不可接受

```cpp
/* 虚函数的开销 */
class Base {
public:
    virtual void doWork() = 0;  /* 间接调用，无法内联 */
    virtual ~Base() = default;
};
```

有没有办法在**编译期**实现多态，避免虚函数开销？

#### 2. 模式

CRTP（Curiously Recurring Template Pattern）让派生类将自己作为模板参数传给基类：

```cpp
template<typename Derived>
class Base {
    void interface() {
        static_cast<Derived*>(this)->implementation();
    }
};

class MyDerived : public Base<MyDerived> {
    void implementation() { /* ... */ }
};
```

基类通过`static_cast`在编译期将`this`转为`Derived*`，调用派生类的方法——**没有虚函数，没有间接调用，编译器可以完全内联**。

#### 3. C++实现（一）：统计对象数量

```cpp
#include <iostream>
#include <string>

/* CRTP基类：统计任意类型的对象数量 */
template<typename Derived>
class ObjectCounter {
private:
    static int count;

protected:
    ObjectCounter() { ++count; }
    ObjectCounter(const ObjectCounter&) { ++count; }
    ~ObjectCounter() { --count; }

public:
    static int getCount() { return count; }
};

template<typename Derived>
int ObjectCounter<Derived>::count = 0;

/* 每个派生类有自己独立的计数器 */
class Widget : public ObjectCounter<Widget> {
public:
    std::string name;
    Widget(const std::string& n) : name(n) {}
};

class Gadget : public ObjectCounter<Gadget> {
public:
    int id;
    Gadget(int i) : id(i) {}
};

int main() {
    std::cout << "Widget数量: " << Widget::getCount() << std::endl;
    std::cout << "Gadget数量: " << Gadget::getCount() << std::endl;

    Widget w1("按钮");
    Widget w2("滑块");
    Gadget g1(100);

    std::cout << "创建后:" << std::endl;
    std::cout << "Widget数量: " << Widget::getCount() << std::endl;
    std::cout << "Gadget数量: " << Gadget::getCount() << std::endl;

    {
        Widget w3("临时");
        std::cout << "作用域内Widget数量: " << Widget::getCount() << std::endl;
    }

    std::cout << "作用域外Widget数量: " << Widget::getCount() << std::endl;

    return 0;
}
```

**关键点**：`ObjectCounter<Widget>`和`ObjectCounter<Gadget>`是两个完全不同的类，各自有独立的`static count`。这是CRTP的精髓——**编译期为每个派生类生成独立的基类代码**。

#### 4. C++实现（二）：混合式编程（Mixin）

```cpp
#include <iostream>
#include <string>

/* CRTP混入：添加打印能力 */
template<typename Derived>
class Printable {
public:
    void print() const {
        static_cast<const Derived*>(this)->doPrint();
    }
};

/* CRTP混入：添加比较能力 */
template<typename Derived>
class Comparable {
public:
    bool operator<(const Derived& other) const {
        return static_cast<const Derived*>(this)->compareTo(other) < 0;
    }

    bool operator>(const Derived& other) const {
        return static_cast<const Derived*>(this)->compareTo(other) > 0;
    }

    bool operator==(const Derived& other) const {
        return static_cast<const Derived*>(this)->compareTo(other) == 0;
    }
};

/* 组合多个混入 */
class Student : public Printable<Student>, public Comparable<Student> {
private:
    std::string name;
    int score;

public:
    Student(const std::string& n, int s) : name(n), score(s) {}

    void doPrint() const {
        std::cout << "学生: " << name << ", 成绩: " << score << std::endl;
    }

    int compareTo(const Student& other) const {
        return score - other.score;
    }
};

int main() {
    Student alice("Alice", 90);
    Student bob("Bob", 85);

    alice.print();
    bob.print();

    std::cout << std::endl;
    std::cout << "alice > bob: " << (alice > bob ? "是" : "否") << std::endl;
    std::cout << "alice < bob: " << (alice < bob ? "是" : "否") << std::endl;
    std::cout << "alice == bob: " << (alice == bob ? "是" : "否") << std::endl;

    return 0;
}
```

#### 5. C++实现（三）：编译期多态 vs 虚函数对比

```cpp
#include <iostream>
#include <chrono>

/* 虚函数方式 */
class VirtualBase {
public:
    virtual int compute(int x) = 0;
    virtual ~VirtualBase() = default;
};

class VirtualImplA : public VirtualBase {
public:
    int compute(int x) override { return x * x; }
};

class VirtualImplB : public VirtualBase {
public:
    int compute(int x) override { return x + x; }
};

/* CRTP方式 */
template<typename Derived>
class CRTPBase {
public:
    int compute(int x) {
        return static_cast<Derived*>(this)->computeImpl(x);
    }
};

class CRTPImplA : public CRTPBase<CRTPImplA> {
public:
    int computeImpl(int x) { return x * x; }
};

class CRTPImplB : public CRTPBase<CRTPImplB> {
public:
    int computeImpl(int x) { return x + x; }
};

int main() {
    const int N = 100000000;

    /* 虚函数测试 */
    VirtualImplA virtualA;
    VirtualBase* vptr = &virtualA;
    int sum1 = 0;
    auto start1 = std::chrono::high_resolution_clock::now();
    for (int i = 0; i < N; ++i) {
        sum1 += vptr->compute(i);
    }
    auto end1 = std::chrono::high_resolution_clock::now();
    std::chrono::duration<double> virtualTime = end1 - start1;

    /* CRTP测试 */
    CRTPImplA crtpA;
    int sum2 = 0;
    auto start2 = std::chrono::high_resolution_clock::now();
    for (int i = 0; i < N; ++i) {
        sum2 += crtpA.compute(i);
    }
    auto end2 = std::chrono::high_resolution_clock::now();
    std::chrono::duration<double> crtpTime = end2 - start2;

    std::cout << "虚函数耗时: " << virtualTime.count() << "秒" << std::endl;
    std::cout << "CRTP耗时: " << crtpTime.count() << "秒" << std::endl;
    std::cout << "结果验证: " << sum1 << " == " << sum2 << std::endl;

    return 0;
}
```

#### 6. CRTP适用场景

- **性能敏感**的代码，需要多态但不能承受虚函数开销
- **混入式编程**（Mixin）：给类添加可组合的功能片段
- **静态接口**：编译期检查派生类是否实现了所需方法
- **零开销抽象**：C++的核心设计哲学——你不为你不用的东西付费

#### 7. CRTP注意事项

- CRTP是**编译期多态**，不能在运行时切换类型（不像虚函数可以通过指针切换）
- 编译错误信息可能很难读（模板报错）
- 不要在基类构造/析构函数中调用`static_cast<Derived*>(this)`（此时Derived尚未构造或已析构）

### 2. Type Erasure（类型擦除）

#### 1. 问题

虚函数多态必须通过**指针或引用**使用，这带来了问题：

```cpp
/* 虚函数多态必须用指针，值语义会切片 */
std::vector<std::unique_ptr<Shape>> shapes;  /* 必须用指针 */
/* 无法直接存储值：std::vector<Shape> shapes; ← 对象切片！ */
```

指针带来内存管理、生命周期、异常安全等问题。能不能**像值一样使用多态对象**？

#### 2. 模式

Type Erasure（类型擦除）结合了**运行时多态**和**值语义**：
- 外部接口统一（像虚函数）
- 内部存储具体类型（像模板）
- 使用时像普通值一样（拷贝、赋值、存储在容器中）

`std::function`、`std::any`、`std::shared_ptr`的删除器都是Type Erasure的经典应用。

#### 3. C++实现：手写简化版`std::function`

```cpp
#include <iostream>
#include <memory>
#include <string>

/* 类型擦除的函数包装器（简化版std::function） */
template<typename Signature>
class Function;

template<typename ReturnType, typename... Args>
class Function<ReturnType(Args...)> {
private:
    /* 内部接口：定义统一调用协议 */
    struct ICallable {
        virtual ~ICallable() = default;
        virtual ReturnType invoke(Args... args) = 0;
        virtual std::unique_ptr<ICallable> clone() const = 0;
    };

    /* 具体实现：模板化，可以存储任意可调用对象 */
    template<typename CallableType>
    class CallableImpl : public ICallable {
    private:
        CallableType callable;

    public:
        CallableImpl(CallableType c) : callable(std::move(c)) {}

        ReturnType invoke(Args... args) override {
            return callable(std::forward<Args>(args)...);
        }

        std::unique_ptr<ICallable> clone() const override {
            return std::make_unique<CallableImpl>(callable);
        }
    };

    std::unique_ptr<ICallable> callable;

public:
    Function() = default;

    /* 从任意可调用对象构造 */
    template<typename CallableType>
    Function(CallableType c)
        : callable(std::make_unique<CallableImpl<std::decay_t<CallableType>>>(
              std::move(c)))
    {}

    /* 拷贝构造 */
    Function(const Function& other)
        : callable(other.callable ? other.callable->clone() : nullptr)
    {}

    /* 拷贝赋值 */
    Function& operator=(const Function& other) {
        if (this != &other) {
            callable = other.callable ? other.callable->clone() : nullptr;
        }
        return *this;
    }

    /* 移动构造 */
    Function(Function&& other) noexcept = default;

    /* 移动赋值 */
    Function& operator=(Function&& other) noexcept = default;

    /* 调用 */
    ReturnType operator()(Args... args) {
        if (!callable) {
            throw std::runtime_error("Function未绑定可调用对象");
        }
        return callable->invoke(std::forward<Args>(args)...);
    }

    /* 检查是否绑定了可调用对象 */
    explicit operator bool() const {
        return callable != nullptr;
    }
};

/* 演示：不同类型的可调用对象统一存储 */
int add(int a, int b) {
    return a + b;
}

int main() {
    /* 存储普通函数 */
    Function<int(int, int)> f1 = add;
    std::cout << "普通函数: " << f1(3, 4) << std::endl;

    /* 存储lambda表达式 */
    Function<int(int, int)> f2 = [](int a, int b) {
        return a * b;
    };
    std::cout << "Lambda: " << f2(3, 4) << std::endl;

    /* 存储仿函数（函数对象） */
    struct Subtract {
        int offset;
        Subtract(int o) : offset(o) {}
        int operator()(int a, int b) { return a - b + offset; }
    };

    Function<int(int, int)> f3 = Subtract(10);
    std::cout << "仿函数: " << f3(10, 3) << std::endl;

    /* 值语义：可以拷贝、赋值、存入容器 */
    Function<int(int, int)> f4 = f2;
    std::cout << "拷贝后调用: " << f4(5, 6) << std::endl;

    f4 = f1;
    std::cout << "赋值后调用: " << f4(7, 8) << std::endl;

    return 0;
}
```

#### 4. C++实现：通用的类型擦除容器

```cpp
#include <iostream>
#include <memory>
#include <string>
#include <vector>

/* 通用的类型擦除容器（简化版std::any） */
class Any {
private:
    struct IHolder {
        virtual ~IHolder() = default;
        virtual std::unique_ptr<IHolder> clone() const = 0;
        virtual std::string typeName() const = 0;
    };

    template<typename T>
    class Holder : public IHolder {
    private:
        T value;

    public:
        Holder(const T& v) : value(v) {}
        Holder(T&& v) : value(std::move(v)) {}

        const T& get() const { return value; }
        T& get() { return value; }

        std::unique_ptr<IHolder> clone() const override {
            return std::make_unique<Holder>(value);
        }

        std::string typeName() const override {
            return typeid(T).name();
        }
    };

    std::unique_ptr<IHolder> holder;

public:
    Any() = default;

    template<typename T>
    Any(T&& v)
        : holder(std::make_unique<Holder<std::decay_t<T>>>(
              std::forward<T>(v)))
    {}

    Any(const Any& other)
        : holder(other.holder ? other.holder->clone() : nullptr)
    {}

    Any& operator=(const Any& other) {
        if (this != &other) {
            holder = other.holder ? other.holder->clone() : nullptr;
        }
        return *this;
    }

    Any(Any&& other) noexcept = default;
    Any& operator=(Any&& other) noexcept = default;

    template<typename T>
    const T& cast() const {
        auto* h = dynamic_cast<Holder<std::decay_t<T>>*>(holder.get());
        if (!h) {
            throw std::bad_cast();
        }
        return h->get();
    }

    explicit operator bool() const {
        return holder != nullptr;
    }
};

int main() {
    Any a1 = 42;
    Any a2 = std::string("你好");
    Any a3 = 3.14;

    std::cout << "整数: " << a1.cast<int>() << std::endl;
    std::cout << "字符串: " << a2.cast<std::string>() << std::endl;
    std::cout << "浮点数: " << a3.cast<double>() << std::endl;

    /* 值语义：可以存入容器 */
    std::vector<Any> items;
    items.push_back(Any(100));
    items.push_back(Any(std::string("世界")));
    items.push_back(Any(2.718));

    std::cout << std::endl << "容器中的元素:" << std::endl;
    std::cout << items[0].cast<int>() << std::endl;
    std::cout << items[1].cast<std::string>() << std::endl;
    std::cout << items[2].cast<double>() << std::endl;

    return 0;
}
```

#### 5. Type Erasure适用场景

- 需要**值语义的多态**（存储在容器中、拷贝传递）
- `std::function`：存储任意可调用对象
- `std::any`：存储任意类型的值
- `std::shared_ptr`的删除器：不同删除类型统一管理
- 插件系统：加载不同类型的插件，用统一接口调用

#### 6. Type Erasure vs 虚函数 vs CRTP

| 特性 | 虚函数 | CRTP | Type Erasure |
|-----|--------|------|-------------|
| 多态时机 | 运行时 | 编译期 | 运行时 |
| 性能开销 | 有（间接调用） | 无 | 有（间接调用+堆分配） |
| 值语义 | 否（必须用指针） | 是 | 是 |
| 运行时类型切换 | 是 | 否 | 是 |
| 使用复杂度 | 低 | 中 | 高 |

### 3. Policy-Based Design（策略设计）

#### 1. 问题

策略模式（第2章）在运行时切换算法，但有开销。如果策略在编译期就能确定，能否消除运行时开销？

```cpp
/* 运行时策略模式：有虚函数开销 */
class Strategy {
public:
    virtual void execute() = 0;  /* 间接调用 */
};
```

#### 2. 模式

Policy-Based Design将策略作为**模板参数**，在编译期组合不同的策略。这是现代C++模板元编程的核心设计方法，Andrei Alexandrescu在《Modern C++ Design》中系统阐述。

#### 3. C++实现：可配置的线程安全策略

```cpp
#include <iostream>
#include <mutex>
#include <string>

/* 策略1：单线程策略（无锁，零开销） */
class SingleThreaded {
public:
    class Lock {
    public:
        Lock(const SingleThreaded&) {}
    };
};

/* 策略2：多线程策略（加锁保护） */
class MultiThreaded {
private:
    static std::mutex mtx;

public:
    class Lock {
    public:
        Lock(const MultiThreaded&) {
            mtx.lock();
        }
        ~Lock() {
            mtx.unlock();
        }
    };
};

std::mutex MultiThreaded::mtx;

/* 策略3：日志策略 */
class NoLogging {
public:
    void log(const std::string&) {}
};

class ConsoleLogging {
public:
    void log(const std::string& msg) {
        std::cout << "[日志] " << msg << std::endl;
    }
};

/* 使用策略的类：线程安全的计数器 */
template<typename ThreadingPolicy = SingleThreaded,
         typename LoggingPolicy = NoLogging>
class Counter : private ThreadingPolicy, private LoggingPolicy {
private:
    int count;

public:
    Counter() : count(0) {}

    void increment() {
        typename ThreadingPolicy::Lock lock(*this);
        (void)lock;
        ++count;
        LoggingPolicy::log("计数器递增到 " + std::to_string(count));
    }

    void decrement() {
        typename ThreadingPolicy::Lock lock(*this);
        (void)lock;
        --count;
        LoggingPolicy::log("计数器递减到 " + std::to_string(count));
    }

    int get() const {
        return count;
    }
};

int main() {
    /* 单线程 + 无日志：零开销 */
    Counter<> simple;
    simple.increment();
    simple.increment();
    std::cout << "简单计数器: " << simple.get() << std::endl;

    std::cout << std::endl;

    /* 单线程 + 控制台日志 */
    Counter<SingleThreaded, ConsoleLogging> logged;
    logged.increment();
    logged.increment();
    logged.decrement();
    std::cout << "带日志计数器: " << logged.get() << std::endl;

    std::cout << std::endl;

    /* 多线程 + 控制台日志 */
    Counter<MultiThreaded, ConsoleLogging> threadSafe;
    threadSafe.increment();
    threadSafe.increment();
    std::cout << "线程安全计数器: " << threadSafe.get() << std::endl;

    return 0;
}
```

#### 4. 适用场景

- 策略在**编译期确定**，运行时不需要切换
- 需要**零开销**的策略组合（如线程安全策略、内存分配策略）
- 库的设计：让用户通过模板参数选择行为（如`std::vector`的分配器）
- 性能关键的代码：编译期策略消除虚函数开销

### 4. RAII守卫模式

#### 1. 问题

C++中经常需要在函数退出时执行清理操作（释放锁、关闭文件、回滚事务）。如果每个退出点都手动写清理代码，容易遗漏：

```cpp
/* 不用守卫：每个退出点都要手动清理 */
void process() {
    lock(mutex);
    if (error1) {
        unlock(mutex);  /* 容易遗漏！ */
        return;
    }
    if (error2) {
        unlock(mutex);  /* 又要写一遍！ */
        return;
    }
    unlock(mutex);  /* 正常退出也要写！ */
}
```

#### 2. 模式

RAII守卫模式利用C++的**确定性析构**，在作用域退出时自动执行清理操作。`std::lock_guard`就是最经典的RAII守卫。我们可以实现更通用的`scope_exit`和`scope_fail`。

#### 3. C++实现

```cpp
#include <iostream>
#include <functional>
#include <stdexcept>
#include <vector>

/* scope_exit：作用域退出时执行（无论正常还是异常） */
class ScopeExit {
private:
    std::function<void()> cleanup;
    bool engaged;

public:
    explicit ScopeExit(std::function<void()> fn)
        : cleanup(std::move(fn)), engaged(true)
    {}

    ~ScopeExit() {
        if (engaged) {
            try {
                cleanup();
            } catch (...) {
                /* 析构函数中不应抛出异常 */
            }
        }
    }

    /* 取消执行 */
    void dismiss() { engaged = false; }

    ScopeExit(const ScopeExit&) = delete;
    ScopeExit& operator=(const ScopeExit&) = delete;
};

/* scope_fail：仅异常退出时执行 */
class ScopeFail {
private:
    std::function<void()> cleanup;
    int exceptionCount;

public:
    explicit ScopeFail(std::function<void()> fn)
        : cleanup(std::move(fn)), exceptionCount(std::uncaught_exceptions())
    {}

    ~ScopeFail() {
        if (std::uncaught_exceptions() > exceptionCount) {
            try {
                cleanup();
            } catch (...) {
                /* 析构函数中不应抛出异常 */
            }
        }
    }

    ScopeFail(const ScopeFail&) = delete;
    ScopeFail& operator=(const ScopeFail&) = delete;
};

/* scope_success：仅正常退出时执行 */
class ScopeSuccess {
private:
    std::function<void()> action;
    int exceptionCount;

public:
    explicit ScopeSuccess(std::function<void()> fn)
        : action(std::move(fn)), exceptionCount(std::uncaught_exceptions())
    {}

    ~ScopeSuccess() {
        if (std::uncaught_exceptions() == exceptionCount) {
            try {
                action();
            } catch (...) {
                /* 析构函数中不应抛出异常 */
            }
        }
    }

    ScopeSuccess(const ScopeSuccess&) = delete;
    ScopeSuccess& operator=(const ScopeSuccess&) = delete;
};

/* 辅助宏：简化创建 */
#define SCOPE_EXIT(fn) ScopeExit _scopeExit_##__LINE__(fn)
#define SCOPE_FAIL(fn) ScopeFail _scopeFail_##__LINE__(fn)
#define SCOPE_SUCCESS(fn) ScopeSuccess _scopeSuccess_##__LINE__(fn)

/* 模拟数据库事务 */
class Database {
private:
    std::vector<std::string> data;
    bool transactionActive;

public:
    Database() : transactionActive(false) {}

    void beginTransaction() {
        transactionActive = true;
        std::cout << "事务开始" << std::endl;
    }

    void commit() {
        transactionActive = false;
        std::cout << "事务提交" << std::endl;
    }

    void rollback() {
        transactionActive = false;
        std::cout << "事务回滚" << std::endl;
    }

    void insert(const std::string& item) {
        data.push_back(item);
        std::cout << "插入数据: " << item << std::endl;
    }

    bool isTransactionActive() const { return transactionActive; }
};

void processTransaction(Database& db, bool shouldFail) {
    db.beginTransaction();

    /* 无论成功还是失败，都确保事务结束 */
    ScopeExit guard([&db]() {
        if (db.isTransactionActive()) {
            db.rollback();
        }
    });

    db.insert("记录A");
    db.insert("记录B");

    if (shouldFail) {
        std::cout << "发生错误！" << std::endl;
        throw std::runtime_error("处理失败");
    }

    db.commit();
    guard.dismiss();  /* 提交成功，取消自动回滚 */
}

int main() {
    Database db;

    /* 正常流程 */
    std::cout << "--- 正常流程 ---" << std::endl;
    try {
        processTransaction(db, false);
    } catch (const std::exception& e) {
        std::cout << "捕获异常: " << e.what() << std::endl;
    }

    std::cout << std::endl;

    /* 异常流程 */
    std::cout << "--- 异常流程 ---" << std::endl;
    try {
        processTransaction(db, true);
    } catch (const std::exception& e) {
        std::cout << "捕获异常: " << e.what() << std::endl;
    }

    std::cout << std::endl;

    /* 演示scope_exit/scope_fail/scope_success组合使用 */
    std::cout << "--- 守卫组合 ---" << std::endl;
    {
        ScopeExit exitGuard([]() {
            std::cout << "scope_exit: 作用域退出" << std::endl;
        });
        ScopeFail failGuard([]() {
            std::cout << "scope_fail: 异常退出" << std::endl;
        });
        ScopeSuccess successGuard([]() {
            std::cout << "scope_success: 正常退出" << std::endl;
        });

        std::cout << "执行正常逻辑..." << std::endl;
    }

    return 0;
}
```

#### 4. 适用场景

- **资源管理**：锁的获取/释放、文件打开/关闭、内存分配/释放
- **事务处理**：beginTransaction/commit/rollback
- **日志记录**：函数进入/退出时自动记录
- **状态恢复**：临时修改状态后自动恢复

### 1. 观察者+策略：可配置的事件通知

```cpp
#include <iostream>
#include <memory>
#include <vector>
#include <string>
#include <functional>

/* 策略接口：通知策略 */
class NotificationStrategy {
public:
    virtual ~NotificationStrategy() = default;
    virtual void notify(const std::string& event, const std::string& data) = 0;
};

/* 具体策略：控制台通知 */
class ConsoleNotification : public NotificationStrategy {
public:
    void notify(const std::string& event, const std::string& data) override {
        std::cout << "[控制台] 事件=" << event << " 数据=" << data << std::endl;
    }
};

/* 具体策略：日志文件通知 */
class LogFileNotification : public NotificationStrategy {
public:
    void notify(const std::string& event, const std::string& data) override {
        std::cout << "[日志文件] 写入: " << event << " - " << data << std::endl;
    }
};

/* 观察者：使用策略决定通知方式 */
class EventObserver {
private:
    std::string name;
    std::shared_ptr<NotificationStrategy> strategy;

public:
    EventObserver(const std::string& n, std::shared_ptr<NotificationStrategy> s)
        : name(n), strategy(s) {}

    void onEvent(const std::string& event, const std::string& data) {
        std::cout << name << " 收到事件: ";
        strategy->notify(event, data);
    }
};

/* 被观察者：事件管理器 */
class EventManager {
private:
    std::vector<std::shared_ptr<EventObserver>> observers;

public:
    void subscribe(std::shared_ptr<EventObserver> observer) {
        observers.push_back(observer);
    }

    void emit(const std::string& event, const std::string& data) {
        for (auto& observer : observers) {
            observer->onEvent(event, data);
        }
    }
};

int main() {
    EventManager manager;

    auto console = std::make_shared<ConsoleNotification>();
    auto logfile = std::make_shared<LogFileNotification>();

    auto obs1 = std::make_shared<EventObserver>("观察者A", console);
    auto obs2 = std::make_shared<EventObserver>("观察者B", logfile);

    manager.subscribe(obs1);
    manager.subscribe(obs2);

    manager.emit("用户登录", "Alice");
    manager.emit("订单创建", "订单#123");

    return 0;
}
```

### 2. 工厂+原型：动态对象创建

#include <memory>

class EnemyFactory {
private:
    std::unordered_map<std::string, std::unique_ptr<Enemy>> prototypes;

public:
    void registerPrototype(const std::string& type, std::unique_ptr<Enemy> proto) {
        prototypes[type] = std::move(proto);
    }

    std::unique_ptr<Enemy> create(const std::string& type) {
        auto it = prototypes.find(type);
        if (it != prototypes.end()) {
            return it->second->clone();
        }
        return nullptr;
    }
};

    auto e1 = factory.create("哥布林");
    auto e2 = factory.create("哥布林");
    auto e3 = factory.create("巨龙");

    e1->show();
    e2->show();
    e3->show();

    e1->attack();

### 3. 状态+策略：状态相关的行为切换

```cpp
#include <iostream>
#include <memory>
#include <string>

/* 策略接口：攻击策略 */
class AttackStrategy {
public:
    virtual ~AttackStrategy() = default;
    virtual void attack() = 0;
    virtual std::string name() = 0;
};

/* 具体策略 */
class MeleeAttack : public AttackStrategy {
public:
    void attack() override {
        std::cout << "近战攻击：挥剑！" << std::endl;
    }
    std::string name() override { return "近战"; }
};

class RangedAttack : public AttackStrategy {
public:
    void attack() override {
        std::cout << "远程攻击：射箭！" << std::endl;
    }
    std::string name() override { return "远程"; }
};

class MagicAttack : public AttackStrategy {
public:
    void attack() override {
        std::cout << "魔法攻击：火球术！" << std::endl;
    }
    std::string name() override { return "魔法"; }
};

/* 状态接口 */
class CharacterState {
public:
    virtual ~CharacterState() = default;
    virtual void handleAttack() = 0;
    virtual std::string name() = 0;
};

/* 前向声明 */
class Character;

/* 具体状态：正常 */
class NormalState : public CharacterState {
private:
    Character* character;

public:
    NormalState(Character* c) : character(c) {}

    void handleAttack() override;
    std::string name() override { return "正常"; }
};

/* 具体状态：狂暴 */
class BerserkState : public CharacterState {
private:
    Character* character;

public:
    BerserkState(Character* c) : character(c) {}

    void handleAttack() override;
    std::string name() override { return "狂暴"; }
};

/* 具体状态：虚弱 */
class WeakState : public CharacterState {
private:
    Character* character;

public:
    WeakState(Character* c) : character(c) {}

    void handleAttack() override;
    std::string name() override { return "虚弱"; }
};

/* 上下文：角色 */
class Character {
private:
    std::unique_ptr<CharacterState> state;
    std::unique_ptr<AttackStrategy> strategy;

public:
    Character() {
        state = std::make_unique<NormalState>(this);
        strategy = std::make_unique<MeleeAttack>();
    }

    void setState(std::unique_ptr<CharacterState> s) {
        state = std::move(s);
    }

    void setStrategy(std::unique_ptr<AttackStrategy> s) {
        strategy = std::move(s);
    }

    AttackStrategy* getStrategy() { return strategy.get(); }

    void attack() {
        std::cout << "【状态: " << state->name()
                  << " 策略: " << strategy->name() << "】";
        state->handleAttack();
    }

    void goBerserk() {
        std::cout << "进入狂暴状态！" << std::endl;
        state = std::make_unique<BerserkState>(this);
    }

    void goWeak() {
        std::cout << "进入虚弱状态！" << std::endl;
        state = std::make_unique<WeakState>(this);
    }

    void goNormal() {
        std::cout << "恢复正常状态！" << std::endl;
        state = std::make_unique<NormalState>(this);
    }
};

void NormalState::handleAttack() {
    character->getStrategy()->attack();
}

void BerserkState::handleAttack() {
    std::cout << "狂暴加成！伤害翻倍！";
    character->getStrategy()->attack();
}

void WeakState::handleAttack() {
    std::cout << "虚弱减益！攻击无力...";
    character->getStrategy()->attack();
}

int main() {
    Character hero;

    /* 正常状态 + 近战 */
    hero.attack();

    /* 切换策略为魔法 */
    hero.setStrategy(std::make_unique<MagicAttack>());
    hero.attack();

    /* 进入狂暴状态 */
    hero.goBerserk();
    hero.attack();

    /* 进入虚弱状态 */
    hero.goWeak();
    hero.attack();

    /* 恢复正常 + 远程 */
    hero.goNormal();
    hero.setStrategy(std::make_unique<RangedAttack>());
    hero.attack();

    return 0;
}
```

### 4. 实战案例：简单的事件驱动系统

综合使用**观察者、策略、命令、中介者**模式，构建一个事件驱动系统：

```cpp
#include <iostream>
#include <memory>
#include <vector>
#include <string>
#include <unordered_map>
#include <functional>

/* 命令接口 */
class Command {
public:
    virtual ~Command() = default;
    virtual void execute() = 0;
    virtual std::string name() const = 0;
};

/* 具体命令：日志命令 */
class LogCommand : public Command {
private:
    std::string message;

public:
    LogCommand(const std::string& msg) : message(msg) {}

    void execute() override {
        std::cout << "[日志] " << message << std::endl;
    }

    std::string name() const override { return "LogCommand"; }
};

/* 具体命令：告警命令 */
class AlertCommand : public Command {
private:
    std::string level;
    std::string message;

public:
    AlertCommand(const std::string& lvl, const std::string& msg)
        : level(lvl), message(msg) {}

    void execute() override {
        std::cout << "[告警 " << level << "] " << message << std::endl;
    }

    std::string name() const override { return "AlertCommand"; }
};

/* 策略接口：事件过滤策略 */
class FilterStrategy {
public:
    virtual ~FilterStrategy() = default;
    virtual bool shouldProcess(const std::string& eventType) = 0;
};

/* 具体策略：处理所有事件 */
class AcceptAllFilter : public FilterStrategy {
public:
    bool shouldProcess(const std::string&) override { return true; }
};

/* 具体策略：只处理特定类型 */
class TypeFilter : public FilterStrategy {
private:
    std::string allowedType;

public:
    TypeFilter(const std::string& t) : allowedType(t) {}

    bool shouldProcess(const std::string& eventType) override {
        return eventType == allowedType;
    }
};

/* 观察者：事件处理器 */
class EventHandler {
private:
    std::string handlerName;
    std::shared_ptr<FilterStrategy> filter;

public:
    EventHandler(const std::string& name, std::shared_ptr<FilterStrategy> f)
        : handlerName(name), filter(f) {}

    void handleEvent(const std::string& eventType, Command& cmd) {
        if (filter->shouldProcess(eventType)) {
            std::cout << handlerName << " 处理事件[" << eventType << "]: ";
            cmd.execute();
        }
    }
};

/* 中介者+被观察者：事件总线 */
class EventBus {
private:
    std::unordered_map<std::string, std::vector<std::shared_ptr<EventHandler>>> subscribers;

public:
    void subscribe(const std::string& eventType, std::shared_ptr<EventHandler> handler) {
        subscribers[eventType].push_back(handler);
    }

    void publish(const std::string& eventType, std::unique_ptr<Command> cmd) {
        auto it = subscribers.find(eventType);
        if (it != subscribers.end()) {
            for (auto& handler : it->second) {
                handler->handleEvent(eventType, *cmd);
            }
        }
    }
};

int main() {
    EventBus bus;

    auto allFilter = std::make_shared<AcceptAllFilter>();
    auto errorFilter = std::make_shared<TypeFilter>("error");
    auto warningFilter = std::make_shared<TypeFilter>("warning");

    auto logger = std::make_shared<EventHandler>("日志处理器", allFilter);
    auto alerter = std::make_shared<EventHandler>("告警处理器", errorFilter);
    auto warner = std::make_shared<EventHandler>("警告处理器", warningFilter);

    bus.subscribe("info", logger);
    bus.subscribe("warning", logger);
    bus.subscribe("warning", warner);
    bus.subscribe("error", logger);
    bus.subscribe("error", alerter);

    std::cout << "=== 发布info事件 ===" << std::endl;
    bus.publish("info", std::make_unique<LogCommand>("系统启动完成"));

    std::cout << std::endl << "=== 发布warning事件 ===" << std::endl;
    bus.publish("warning", std::make_unique<AlertCommand>("WARN", "内存使用率80%"));

    std::cout << std::endl << "=== 发布error事件 ===" << std::endl;
    bus.publish("error", std::make_unique<AlertCommand>("CRITICAL", "数据库连接失败"));

    return 0;
}
```

## 4. 设计模式的取舍

> **知止而后有定，定而后能静，静而后能安。**
> （Knowing when to stop, one can be determined; determined, one can be calm; calm, one can be at peace.）

---

### 1. 何时使用设计模式

| 信号 | 说明 |
|-----|------|
| 代码重复 | 相同逻辑出现在多处，考虑模板方法或策略 |
| 难以扩展 | 每次加功能都要改大量代码，考虑观察者或访问者 |
| 类爆炸 | 继承层次过深，考虑桥接或装饰器 |
| 紧耦合 | 类之间直接依赖太多，考虑中介者或依赖注入 |
| 状态混乱 | 大量if-else判断状态，考虑状态模式 |

### 2. 何时不用设计模式

| 信号 | 说明 |
|-----|------|
| 简单逻辑 | 3行代码能解决的，不需要模式 |
| 需求不确定 | YAGNI——你不会需要它，等需求明确了再重构 |
| 团队不熟悉 | 引入团队不理解的模式，反而增加沟通成本 |
| 性能关键 | 虚函数和间接调用有开销，热路径上慎用 |
| 过早抽象 | 只有一个实现时，不要急着写接口 |

### 3. 过度设计的危害

```cpp
/* 过度设计：简单的配置读取变成了模式大杂烩 */
class ConfigReader
    : public Singleton<ConfigReader>
    , public Subject
    , public Prototype
{
    std::unique_ptr<Strategy> parseStrategy;
    std::unique_ptr<Iterator<std::string>> iter;
    /* ... 5个模式混在一起，谁看得懂？ */
};

/* 简单设计：够用就好 */
class Config {
    std::unordered_map<std::string, std::string> data;
public:
    std::string get(const std::string& key, const std::string& defaultVal = "") {
        auto it = data.find(key);
        return it != data.end() ? it->second : defaultVal;
    }
};
```

### 4. KISS / YAGNI原则

**KISS（Keep It Simple, Stupid）**：保持简单
- 简单的方案优于"聪明"的方案
- 代码是写给人看的，不是写给编译器看的
- 三个月后你自己也看不懂"聪明"的代码

**YAGNI（You Aren't Gonna Need It）**：你不会需要它
- 不要为了"将来可能用到"而提前设计
- 等需求真的来了再重构，重构的成本通常低于过度设计的成本
- 最好的代码是不存在的代码

### 5. 设计模式与代码复杂度的权衡

```
复杂度
  ^
  |                          *
  |                       *     *
  |                    *           *
  |                 *    最佳区间    *
  |              *                    *
  |           *                          *
  |        *                                *
  |     *   模式不足                     过度设计   *
  |  *                                              *
  +---------------------------------------------------> 模式使用量
```

- **模式不足**：代码重复、紧耦合、难以扩展
- **最佳区间**：恰到好处地使用模式，代码清晰且灵活
- **过度设计**：模式堆砌、代码晦涩、维护成本高

### 6. 实用建议

1. **先写简单的代码**，遇到问题再引入模式
2. **一次只引入一个模式**，不要一次性重构
3. **用测试保护重构**，确保引入模式后行为不变
4. **命名要清晰**，让模式意图一目了然（如`Subject`、`Observer`、`Strategy`）
5. **定期审视**，删掉不再需要的模式

## 5. 本章小结

### 1. GoF剩余模式速查

| 模式 | 核心思想 | 一句话总结 |
|-----|---------|-----------|
| **桥接** | 分离抽象与实现 | 用组合代替继承，避免类爆炸 |
| **组合** | 树形结构统一处理 | 叶子和组合实现同一接口 |
| **享元** | 共享细粒度对象 | 分离内部状态和外部状态 |
| **迭代器** | 统一遍历接口 | 不暴露内部结构即可遍历 |
| **中介者** | 集中管理对象通信 | 网状依赖变星形依赖 |
| **备忘录** | 保存和恢复状态 | 不破坏封装的快照机制 |
| **模板方法** | 定义算法骨架 | 不变的在基类，变化的在子类 |
| **访问者** | 不修改类增加操作 | 双分派实现操作与数据分离 |

### 2. C++特有模式速查

| 模式 | 核心思想 | 适用场景 |
|-----|---------|---------|
| **CRTP** | 编译期多态 | 零开销抽象、混入式编程 |
| **Type Erasure** | 运行时多态+值语义 | 值语义的多态容器 |
| **Policy-Based Design** | 编译期策略组合 | 可配置的零开销策略 |
| **RAII守卫** | 析构即清理 | scope_exit/scope_fail |

### 3. 模式组合速查

| 组合 | 效果 |
|-----|------|
| 观察者+策略 | 可配置的事件通知 |
| 工厂+原型 | 动态对象创建 |
| 状态+策略 | 状态相关的行为切换 |
| 观察者+策略+命令+中介者 | 事件驱动系统 |
