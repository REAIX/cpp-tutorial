## 本章导读

C++关键字是C++语言的核心组成部分，它们具有特殊的含义和用途。正确使用关键字可以帮助我们编写清晰、高效、可维护的C++代码。本章将详细介绍C++关键字的分类、`explicit`含义和使用方法，帮助你掌握C++关键字的正确使用。

### 1. 概念与定义

**关键字（keyword）**：C++中具有特殊含义的单词。关键字不能用作标识符（变量名、函数名、类名等）。例如`int`、`float`、`double`、`char`、`bool`等都是关键字。

**标识符（identifier）**：C++中用于标识变量、函数、类、对象等的名称。标识符由字母、数字和下划线组成，不能以数字开头，不能与关键字重名。例如`x`、`y`、`z`、`add`、`sub`、`mul`、`div`等都是标识符。

**保留字（reserved word）**：C++中已经被保留但尚未使用的单词。保留字不能用作标识符。例如`export`、`import`、`module`等都是保留字。

**标准库标识符（standard library identifier）**：C++标准库中使用的标识符。标准库标识符不能用作用户自定义的标识符。例如`std`、`cout`、`cin`、`endl`等都是标准库标识符。

## 1. 关键字的分类

C++关键字可以分为以下几类：

### 1. 数据类型关键字

- `bool`：布尔类型，用于表示真或假
- `char`：字符类型，用于表示单个字符
- `int`：整数类型，用于表示整数
- `float`：单精度浮点数类型，用于表示小数
- `double`：双精度浮点数类型，用于表示高精度小数
- `void`：空类型，用于表示没有返回值或没有参数
- `wchar_t`：宽字符类型，用于表示Unicode字符

### 2. 存储类关键字

- `auto`：自动变量，用于自动推导变量类型
- `register`：寄存器变量，用于将变量存储在寄存器中
- `static`：静态变量，用于保持变量的值在函数调用之间
- `extern`：外部变量，用于声明外部变量
- `mutable`：可变成员，用于允许在const成员函数中修改成员变量
- `thread_local`：线程局部变量，用于将变量存储在线程局部存储中

### 3. 控制流关键字

- `if`：条件语句，用于根据条件执行不同的代码
- `else`：条件语句的分支，用于在条件不满足时执行代码
- `switch`：开关语句，用于根据不同的情况执行不同的代码
- `case`：开关语句的分支，用于表示不同的情况
- `default`：开关语句的默认分支，用于表示默认情况
- `for`：循环语句，用于重复执行代码
- `while`：循环语句，用于在条件满足时重复执行代码
- `do`：循环语句，用于先执行代码再检查条件
- `break`：跳出循环，用于终止循环
- `continue`：继续循环，用于跳过当前循环的剩余部分
- `return`：返回语句，用于从函数返回值
- `goto`：跳转语句，用于跳转到指定的标签

### 4. 面向对象关键字

- `class`：类，用于定义类
- `struct`：结构体，用于定义结构体
- `union`：联合体，用于定义联合体
- `enum`：枚举，用于定义枚举类型
- `public`：公共访问权限，用于表示公共成员
- `protected`：保护访问权限，用于表示保护成员
- `private`：私有访问权限，用于表示私有成员
- `virtual`：虚函数，用于实现多态
- `override`：覆盖虚函数，用于覆盖基类的虚函数
- `final`：最终类或函数，用于防止类被继承或函数被覆盖
- `friend`：友元，用于允许其他函数或类访问私有成员
- `this`：当前对象指针，用于指向当前对象
- `operator`：运算符重载，用于重载运算符
- `new`：动态内存分配，用于分配动态内存
- `delete`：动态内存释放，用于释放动态内存
- `typeid`：类型识别，用于获取对象的类型信息
- `dynamic_cast`：动态类型转换，用于在运行时转换类型
- `static_cast`：静态类型转换，用于在编译时转换类型
- `reinterpret_cast`：重新解释类型转换，用于重新解释内存中的数据
- `const_cast`：常量类型转换，用于去除常量属性

### 5. 模板关键字

- `template`：模板，用于定义模板
- `typename`：类型名，用于表示类型参数
- `constexpr`：常量表达式，用于表示编译时常量
- `decltype`：类型推导，用于推导表达式的类型
- `auto`：自动类型推导，用于自动推导变量类型

### 6. 异常处理关键字

- `try`：异常处理的开始，用于包裹可能抛出异常的代码
- `catch`：异常处理的分支，用于捕获并处理异常
- `throw`：抛出异常，用于抛出异常
- `noexcept`：不抛出异常，用于表示函数不会抛出异常

### 7. 其他关键字

- `const`：常量，用于表示只读变量
- `volatile`：易变变量，用于表示可能被外部修改的变量
- `inline`：内联函数，用于将函数体插入到调用处
- `namespace`：命名空间，用于组织代码
- `using`：使用命名空间或类型别名，用于简化代码
- `asm`：汇编代码，用于插入汇编代码
- `sizeof`：求大小，用于获取类型或变量的大小
- `alignas`：对齐，用于指定对齐方式
- `alignof`：求对齐，用于获取类型的对齐方式
- `nullptr`：空指针，用于表示空指针
- `true`：布尔值真，用于表示真
- `false`：布尔值假，用于表示假

### 8. C++20新增关键字

- `concept`：概念，用于定义命名约束
- `requires`：约束，用于约束模板参数或检查表达式有效性
- `co_await`：协程等待，用于挂起协程等待异步操作
- `co_yield`：协程产出，用于产生一个值并挂起协程
- `co_return`：协程返回，用于从协程返回
- `consteval`：立即函数，用于声明必须在编译期执行的函数
- `constinit`：编译期初始化，用于确保变量在编译期初始化
- `char8_t`：UTF-8字符类型，用于表示UTF-8字符

### 9. C++23新增关键字

- `import`：导入模块，用于导入模块中的声明
- `module`：声明模块，用于声明一个模块

## 3. 预处理指令与宏

C++的预处理指令和宏是强大的工具，正确使用可以提高代码的灵活性和可维护性。

### 1. 宏定义 `#define`

```cpp
// 常量宏
#define PI 3.14159
#define MAX(a, b) ((a) > (b) ? (a) : (b))
#define SQUARE(x) ((x) * (x))

// 注意事项：使用括号避免运算优先级问题
#define MULTIPLY(a, b) (a * b)  // 错误！
#define MULTIPLY(a, b) ((a) * (b))  // 正确

// 字符串化 # 操作符
#define STRINGIZE(x) #x
std::cout << STRINGIZE(hello world) << std::endl;  // 输出: "hello world"

// 连接 ## 操作符
#define CONCAT(a, b) a##b
int CONCAT(x, 1) = 10;  // int x1 = 10;

// 可变参数宏
#define LOG(fmt, ...) printf(fmt, ##__VA_ARGS__)
LOG("Error: %s\n");  // 不传参数也能工作
LOG("Value: %d\n", 42);  // 输出: Value: 42
```

### 2. 条件编译

```cpp
// 调试模式开关
#ifdef DEBUG
    #define LOG(x) std::cout << "[DEBUG] " << x << std::endl;
#else
    #define LOG(x)
#endif

// 跨平台代码
#ifdef _WIN32
    #include <windows.h>
#elif defined(__linux__)
    #include <unistd.h>
#elif defined(__APPLE__)
    #include <mach/mach.h>
#endif

// 版本检查
#if __cplusplus >= 202002L
    #define CXX_STANDARD "C++20"
#elif __cplusplus >= 201703L
    #define CXX_STANDARD "C++17"
#elif __cplusplus >= 201402L
    #define CXX_STANDARD "C++14"
#else
    #define CXX_STANDARD "C++11"
#endif

// 特性检测宏
#if defined(__has_feature)
    #if __has_feature(cxx_threadsafe_static_init)
        #define THREAD_SAFE_STATIC 1
    #endif
#endif

// 防止头文件重复包含
#ifndef MY_HEADER_H
#define MY_HEADER_H
// 头文件内容
#endif

// 或者使用 #pragma once（现代编译器支持）
#pragma once
```

### 3. 预定义宏

```cpp
// 标准预定义宏
__FILE__    // 当前文件名
```

### 4. 宏的使用技巧

```cpp
// 1. 避免多次求值（参数可能被求值多次）
#define MAX(a, b) ((a) > (b) ? (a) : (b))

// 错误用法：MAX(i++, j++) 可能导致i被递增两次
// 正确用法：
int x = 5, y = 10;
int z = MAX(x, y);  // 安全

// 2. 使用 do-while(0) 包裹多条语句
#define SWAP(a, b) \
    do { \
        auto _tmp = (a); \
        (a) = (b); \
        (b) = _tmp; \
    } while(0)

// 3. 类型安全的宏（使用 inline 函数代替）
template<typename T>
inline T max(const T& a, const T& b) {
    return a > b ? a : b;
}

// 4. 条件编译实现特性检测
#if __cplusplus >= 201703L
    #define HAS_CXX17 1
#endif

#if __cplusplus >= 202002L
    #define HAS_CXX20 1
#endif

// 5. 废弃API警告
#if defined(__GNUC__) || defined(__clang__)
    #define DEPRECATED __attribute__((deprecated))
#elif defined(_MSC_VER)
    #define DEPRECATED __declspec(deprecated)
#endif
```

### 5. 宏的注意事项

```cpp
// 注意事项1：宏不是类型安全的
#define FOO(x) (x + 1)
int* p = FOO(1);  // 错误！变成 int* p = (1 + 1);

// 注意事项2：宏参数需要加括号
#define SQR(x) x * x  // 错误
#define SQR(x) ((x) * (x))  // 正确

// 注意事项3：分号问题
#define CALL(x) x()
// 不能写成 CALL(func()); 因为宏展开后没有分号
// 使用 do-while(0) 解决

// 注意事项4：宏与作用域
int x = 10;
#define X 20
// 宏没有作用域概念，会影响后续代码

// 最佳实践：尽量使用 const/enum/inline 代替宏
const int MAX_SIZE = 100;  // 代替 #define MAX_SIZE 100
inline int max(int a, int b) { return a > b ? a : b; }  // 代替 #define max(a,b)
```

### 6. 常用宏模式

```cpp
// 1. 单例模式
#define DISALLOW_COPY(ClassName) \
    ClassName(const ClassName&) = delete; \
    ClassName& operator=(const ClassName&) = delete;

// 2. 禁用移动
#define DISALLOW_MOVE(ClassName) \
    ClassName(ClassName&&) = delete; \
    ClassName& operator=(ClassName&&) = delete;

// 3. 禁止拷贝和移动
#define DISALLOW_COPY_AND_MOVE(ClassName) \
    DISALLOW_COPY(ClassName) \
    DISALLOW_MOVE(ClassName)

// 使用示例
class Singleton {
public:
    static Singleton& getInstance() {
        static Singleton instance;
        return instance;
    }
    
private:
    Singleton() = default;
    DISALLOW_COPY_AND_MOVE(Singleton)
};

// 4. 编译器特性检测
#if defined(__GNUC__)
    #if (__GNUC__ > 4) || (__GNUC__ == 4 && __GNUC_MINOR__ >= 8)
        #define COMPILER_SUPPORTS_CXX11 1
    #endif
#endif

#if defined(_MSC_VER)
    #if _MSC_VER >= 1900
        #define COMPILER_SUPPORTS_CXX11 1
    #endif
#endif

// 5. 平台检测
#if defined(_WIN32) || defined(_WIN64)
    #define PLATFORM_WINDOWS 1
#elif defined(__linux__)
    #define PLATFORM_LINUX 1
#elif defined(__APPLE__)
    #define PLATFORM_MAC 1
#endif
```

## 4. 关键字的使用注意事项

### 1. 不能与关键字重名

```cpp
// 错误：不能与关键字重名
int int = 10;

// 错误：不能与关键字重名
int char = 20;

// 错误：不能与关键字重名
int float = 30;
```

### 2. 注意关键字的大小写

C++关键字是区分大小写的，关键字必须全部小写。

```cpp
// 错误：关键字必须全部小写
Int x = 10;

// 错误：关键字必须全部小写
Float y = 20;

// 错误：关键字必须全部小写
Double z = 30;
```

### 3. 注意关键字的使用范围

有些关键字只能在特定的上下文中使用。

```cpp
// 错误：mutable只能用于类的非静态成员
mutable int x = 10;

// 正确：mutable用于类的非静态成员
class MyClass {
public:
    mutable int x = 10;
};

// 错误：override只能用于类的成员函数
void func() override {
    // 函数体
}

// 正确：override用于类的成员函数
class MyDerivedClass : public MyBaseClass {
public:
    void func() override {
        // 函数体
    }
};
```

## 5. C++20与C++23新增关键字详解

C++20和C++23为语言引入了多项重要特性，包括概念约束、协程、立即函数、编译期初始化和模块系统等。这些新关键字极大地增强了C++的表达能力和类型安全性。

### 1. concept — 定义命名约束

`concept`用于定义一个命名的约束（概念），它可以对模板参数提出要求，使模板编程更加清晰和易于调试。

**语法：**

```cpp
template<typename T>
concept 概念名 = 约束表达式;
```

**与requires子句的区别：**

- `concept`定义的是一个**可复用的命名约束**，可以在多处引用
- `requires`子句是**内联的约束条件**，直接写在模板声明处，不可复用

**代码示例：**

```cpp
#include <concepts>
#include <iostream>

// 定义概念：要求类型T支持加法运算
template<typename T>
concept Addable = requires(T a, T b) {
    a + b;
};

// 定义概念：要求类型T是整数类型
template<typename T>
concept Integral = std::is_integral_v<T>;

// 使用概念约束模板参数（方式一：concept名称直接替换typename）
template<Addable T>
T add(T a, T b) {
    return a + b;
}

// 使用概念约束模板参数（方式二：requires子句引用concept）
template<typename T>
requires Addable<T>
T multiply(T a, T b) {
    return a * b;
}

// 使用概念约束模板参数（方式三：尾置requires）
template<typename T>
T subtract(T a, T b) requires Addable<T> {
    return a - b;
}

int main() {
    std::cout << add(3, 4) << std::endl;       // 正确：int满足Addable
    std::cout << multiply(2.5, 3.0) << std::endl; // 正确：double满足Addable
    // add("hello", "world");  // 错误：const char*不满足Addable
    return 0;
}
```

### 2. requires — 约束表达式

`requires`有两种用法：**requires子句**和**requires表达式**，它们在模板约束中扮演不同角色。

**requires子句（模板约束）：**

用于在模板声明中指定约束条件，决定模板是否参与重载决议。

```cpp
// requires子句：约束模板参数T必须是整数类型
template<typename T>
requires std::is_integral_v<T>
T factorial(T n) {
    if (n <= 1) return 1;
    return n * factorial(n - 1);
}
```

**requires表达式（检查表达式有效性）：**

用于检查一组表达式是否有效，通常与`concept`配合使用。

```cpp
#include <concepts>

// requires表达式：检查多个表达式是否有效
template<typename T>
concept Printable = requires(T t, std::ostream& os) {
    { os << t } -> std::same_as<std::ostream&>;  // 检查t是否可以输出到流
};

template<typename T>
concept Container = requires(T c) {
    typename T::value_type;       // 检查是否有value_type类型成员
    { c.begin() } -> std::input_or_output_iterator;  // 检查是否有begin方法
    { c.end() } -> std::input_or_output_iterator;    // 检查是否有end方法
    { c.size() } -> std::convertible_to<std::size_t>; // 检查是否有size方法
};
```

**requires子句与requires表达式的区别：**

| 特性 | requires子句 | requires表达式 |
|------|-------------|---------------|
| 用途 | 约束模板参数 | 检查表达式有效性 |
| 出现位置 | 模板声明处 | concept定义或requires子句中 |
| 返回值 | 布尔常量 | 布尔常量 |
| 可否独立使用 | 可以 | 可以 |

### 3. co_await / co_yield / co_return — 协程关键字

C++20引入了协程（Coroutine）支持，通过三个关键字实现协程的挂起、产出和返回。

- **co_await**：挂起协程，等待异步操作完成
- **co_yield**：产生一个值并挂起协程
- **co_return**：从协程中返回，结束协程

**代码示例：**

```cpp
#include <coroutine>
#include <iostream>

// 简单的生成器协程
struct Generator {
    struct promise_type {
        int current_value;

        Generator get_return_object() {
            return Generator{std::coroutine_handle<promise_type>::from_promise(*this)};
        }
        std::suspend_always initial_suspend() { return {}; }
        std::suspend_always final_suspend() noexcept { return {}; }
        std::suspend_always yield_value(int value) {
            current_value = value;
            return {};
        }
        void return_void() {}
        void unhandled_exception() { std::terminate(); }
    };

    std::coroutine_handle<promise_type> handle;

    ~Generator() {
        if (handle) handle.destroy();
    }

    // 获取当前值
    int current() const {
        return handle.promise().current_value;
    }

    // 推进到下一个值
    bool next() {
        handle.resume();
        return !handle.done();
    }
};

// 使用co_yield产生斐波那契数列
Generator fibonacci() {
    int a = 0, b = 1;
    while (true) {
        co_yield a;       // 产出当前值并挂起
        int temp = a + b;
        a = b;
        b = temp;
    }
}

// 使用co_return从协程返回
Generator countdown(int from) {
    while (from > 0) {
        co_yield from;    // 产出当前值并挂起
        --from;
    }
    co_return;            // 协程结束返回
}

int main() {
    // 斐波那契数列生成器
    auto gen = fibonacci();
    for (int i = 0; i < 10; ++i) {
        std::cout << gen.current() << " ";
        gen.next();
    }
    std::cout << std::endl;

    // 倒计时生成器
    auto counter = countdown(5);
    while (counter.next()) {
        std::cout << counter.current() << " ";
    }
    std::cout << std::endl;

    return 0;
}
```

> **注意：** 协程函数中只要使用了`co_await`、`co_yield`或`co_return`中的任何一个，该函数就自动成为协程。协程不能使用普通的`return`语句。

### 4. consteval — 立即函数

`consteval`声明的函数称为**立即函数**（immediate function），它**必须**在编译期执行，无法在运行时调用。

**与constexpr的区别：**

| 特性 | constexpr | consteval |
|------|-----------|-----------|
| 编译期执行 | **可能**在编译期执行 | **必须**在编译期执行 |
| 运行时调用 | 允许 | 不允许 |
| 参数要求 | 编译期常量时在编译期执行 | 所有调用必须在编译期完成 |
| 灵活性 | 更灵活 | 更严格，但保证编译期执行 |

**代码示例：**

```cpp
#include <array>
#include <iostream>

// consteval函数：必须在编译期执行
consteval int square(int x) {
    return x * x;
}

// consteval函数：编译期计算字符串长度
consteval std::size_t str_length(const char* str) {
    std::size_t len = 0;
    while (str[len] != '\0') ++len;
    return len;
}

// constexpr函数：可能在编译期执行
constexpr int cube(int x) {
    return x * x * x;
}

int main() {
    // consteval：所有调用都在编译期完成
    constexpr int s1 = square(5);        // 正确：编译期计算，结果为25
    std::cout << s1 << std::endl;

    // 使用consteval进行编译期计算
    constexpr auto len = str_length("hello");  // 正确：编译期计算，结果为5
    std::cout << len << std::endl;

    // consteval不能使用运行时变量
    int runtime_val = 10;
    // int error = square(runtime_val);  // 错误！runtime_val不是编译期常量

    // constexpr可以在运行时调用
    int runtime_result = cube(runtime_val);  // 正确：运行时执行
    std::cout << runtime_result << std::endl;

    // constexpr在编译期常量上下文中编译期执行
    constexpr int compile_result = cube(3);  // 正确：编译期执行，结果为27
    std::cout << compile_result << std::endl;

    return 0;
}
```

### 5. constinit — 编译期初始化

`constinit`确保变量在编译期完成初始化，从而避免**静态初始化顺序问题**（Static Initialization Order Fiasco）。

**与constexpr变量的区别：**

| 特性 | constexpr变量 | constinit变量 |
|------|--------------|--------------|
| 编译期初始化 | 是 | 是 |
| 是否为const | 是（隐式const） | 否（不添加const属性） |
| 运行时修改 | 不允许 | 允许 |
| 适用场景 | 编译期常量 | 需要编译期初始化但运行时可修改的变量 |

**代码示例：**

```cpp
#include <iostream>

// constinit：编译期初始化，但运行时可修改
constinit int global_counter = 0;

// constexpr：编译期初始化，不可修改
constexpr int max_size = 100;

// 演示静态初始化顺序问题
struct Logger {
    Logger() {
        std::cout << "Logger初始化" << std::endl;
    }
    void log(const char* msg) {
        std::cout << msg << std::endl;
    }
};

// 不使用constinit：可能存在初始化顺序问题
// Logger logger;  // 如果另一个翻译单元的静态对象在构造时调用logger，可能未初始化

// 使用constinit确保编译期初始化
constinit int safe_value = 42;  // 编译期初始化，不会有顺序问题

// constinit与动态初始化
constinit const char* config_path = "/etc/app/config";  // 正确：编译期常量初始化

int main() {
    std::cout << "global_counter = " << global_counter << std::endl;
    std::cout << "max_size = " << max_size << std::endl;
    std::cout << "safe_value = " << safe_value << std::endl;

    // constinit变量可以在运行时修改
    global_counter = 10;
    std::cout << "修改后 global_counter = " << global_counter << std::endl;

    // constexpr变量不可修改
    // max_size = 200;  // 错误！constexpr变量是const的

    return 0;
}
```

### 6. char8_t — UTF-8字符类型

C++20引入`char8_t`作为UTF-8字符的专用类型，解决了`char`类型在处理UTF-8时的歧义问题。

**与char的区别：**

| 特性 | char | char8_t |
|------|------|---------|
| 编码 | 执行字符集（可能是ASCII、UTF-8等） | 明确为UTF-8编码 |
| 大小 | 通常1字节 | 1字节 |
| u8字面量类型（C++20前） | u8'x'的类型为char | — |
| u8字面量类型（C++20起） | — | u8'x'的类型为char8_t |
| 与char的隐式转换 | — | 不允许隐式转换为char |

**代码示例：**

```cpp
#include <iostream>

int main() {
    // C++20之前：u8字符字面量的类型是char
    // C++20起：u8字符字面量的类型是char8_t
    char8_t c1 = u8'A';
    char8_t c2 = u8'中';

    // u8字符串字面量的类型从const char[]变为const char8_t[]
    const char8_t* str = u8"你好世界";

    // char8_t不能隐式转换为char
    // char ch = c1;  // 错误！C++20不允许隐式转换

    // 需要显式转换
    char ch = static_cast<char>(c1);  // 正确：显式转换

    // 注意：u8字符串字面量类型变化可能导致旧代码不兼容
    // C++17：auto s = u8"hello";  // s的类型是const char*
    // C++20：auto s = u8"hello";  // s的类型是const char8_t*

    return 0;
}
```

### 7. import与module — 模块系统

C++20引入模块系统，C++23中`import`和`module`从上下文敏感关键字升级为更正式的关键字。模块系统旨在替代传统的头文件包含机制。

**import — 导入模块：**

```cpp
// 导入标准库模块（C++23起支持）
import std;

// 导入自定义模块
import my_module;

// 导入模块的特定分区
import my_module:partitions;
```

**module — 声明模块：**

```cpp
// 声明模块接口单元
export module my_module;

// 声明模块实现单元（不导出）
module my_module;

// 声明模块分区
export module my_module:partitions;
```

**完整模块示例：**

```cpp
// ========== math_utils.cppm（模块接口文件）==========
export module math_utils;

import <iostream>;

// 导出的函数
export int add(int a, int b) {
    return a + b;
}

export int multiply(int a, int b) {
    return a * b;
}

// 未导出的内部函数（模块外部不可见）
void internal_helper() {
    std::cout << "内部辅助函数" << std::endl;
}

// ========== main.cpp（使用模块）==========
import math_utils;
import <iostream>;

int main() {
    std::cout << add(3, 4) << std::endl;       // 正确：add被导出
    std::cout << multiply(2, 5) << std::endl;  // 正确：multiply被导出
    // internal_helper();  // 错误：未导出，模块外部不可见
    return 0;
}
```

> **注意：** 模块系统是C++20引入的重大特性，但`import`和`module`在C++20中是上下文敏感关键字（只在特定位置被视为关键字），在C++23中地位更加明确。

### 8. 上下文敏感关键字

C++中有一类特殊的关键字称为**上下文敏感关键字**（contextual keyword），它们只在特定的语法位置才被视为关键字，在其他位置可以作为普通标识符使用。

**常见的上下文敏感关键字：**

| 关键字 | 生效位置 | 用途 |
|--------|---------|------|
| `override` | 成员函数声明末尾 | 标记虚函数覆盖 |
| `final` | 类声明或成员函数声明末尾 | 防止继承或覆盖 |
| `import` | 模块导入声明处 | 导入模块 |
| `module` | 模块声明处 | 声明模块 |
| `audit` | 合约属性中 | 审计合约（C++20合约，暂移除） |
| `axiom` | 合约属性中 | 公理合约（C++20合约，暂移除） |

**与普通关键字的区别：**

```cpp
// 普通关键字：不能在任何位置作为标识符
// int class = 10;  // 错误！class是普通关键字，不能作为变量名

// 上下文敏感关键字：在非关键字位置可以作为标识符
int override = 10;     // 正确！override在此处不是关键字
int final = 20;        // 正确！final在此处不是关键字
int import = 30;       // 正确！import在此处不是关键字

// 但在特定位置它们是关键字
class Base {
public:
    virtual void func() {}
};

class Derived : public Base {
public:
    void func() override {  // override在此处是关键字
        // 覆盖基类的虚函数
    }
};

class Last final {  // final在此处是关键字
    // 此类不可被继承
};
```

> **最佳实践：** 尽管上下文敏感关键字可以作为标识符，但为了避免混淆，不建议将它们用作变量名或函数名。

## 7. 关键字的最佳实践

### 1. 合理使用关键字

根据代码的需求合理使用关键字，避免滥用关键字。

```cpp
// 合理使用关键字
const int x = 10;

// 合理使用关键字
inline int add(int x, int y) {
    return x + y;
}

// 合理使用关键字
template <typename T>
T add(T x, T y) {
    return x + y;
}
```

### 2. 遵循编码规范

遵循团队的编码规范，统一关键字的使用方式。

```cpp
// 遵循编码规范：关键字后面留一个空格
int x = 10;

// 遵循编码规范：关键字后面留一个空格
if (x > 0) {
    // 分支1
} else {
    // 分支2
}

// 遵循编码规范：关键字后面留一个空格
for (int i = 0; i < 10; i++) {
    // 循环体
}
```

注意关键字的版本兼容性，避免使用不兼容的关键字。

```cpp
// 注意版本兼容性：constexpr是C++11新增的关键字
#if __cplusplus >= 201103L
constexpr int x = 10;
```
