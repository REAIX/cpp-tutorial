> 💡 **通俗理解 - 什么是调试？**

想象你组装模型：
- **没有调试**：发现错了，不知道哪一步出问题
- **有调试**：一步步检查，找出问题所在

**调试就是"找问题"！**
- 程序出错了
- 用工具定位问题
- 修复它

> 🔬 **抽象理解 - 调试的本质**：
> - **断点**：是"暂停点"，让程序在指定位置停止，检查状态
> - **单步执行**：是"逐步推进"，观察每一步的状态变化
> - **变量监视**：是"观察状态"，实时查看变量值
> - **日志**：是"轨迹记录"，通过输出信息追踪程序执行
> - **调试的本质**：是"状态观察"和"假设验证"的循环，找出错误的根本原因

## 1. 调试基础

### 1. 概念与定义

**调试（debugging）**：C++中用于查找和修复程序错误的过程。调试可以分为发现问题、重现问题、定位问题、分析原因、修复问题、验证修复等步骤。例如使用GDB调试器查找程序的错误，使用日志调试查找程序的错误，使用断言调试查找程序的错误。

**调试器（debugger）**：C++中用于调试程序的工具。调试器可以分为GDB、LLDB、Visual Studio Debugger等。例如GDB是GNU调试器，LLDB是LLVM调试器，Visual Studio Debugger是Visual Studio调试器。

**调试信息（debug information）**：C++中用于调试程序的信息。调试信息可以分为`-g0`、`-g1`、`-g2`、`-g3`、`-ggdb`等。例如`-g2`表示默认调试信息，`-g3`表示最大调试信息，`-ggdb`表示GDB专用调试信息。

**断点（breakpoint）**：C++中用于调试程序的机制。断点可以分为普通断点、条件断点、临时断点等。例如`break main`表示在`main`函数设置断点，`break file.cpp:10`表示在文件第10行设置断点，`break func if x>5`表示条件断点，`tbreak func`表示临时断点。

**日志调试（log debugging）**：C++中用于调试程序的机制。日志调试可以分为使用`std::cout`输出日志、使用`std::cerr`输出错误信息、使用`spdlog`库输出日志等。例如`std::cout << "x = " << x << std::endl;`用于输出变量`x`的值，`std::cerr << "Error: x is negative" << std::endl;`用于输出错误信息，`spdlog::info("x = {}", x);`用于输出日志。

**内存调试（memory debugging）**：C++中用于调试程序的机制。内存调试可以分为使用`valgrind`查找内存泄漏、使用`AddressSanitizer`查找内存错误、使用`UndefinedBehaviorSanitizer`查找未定义行为等。例如`valgrind --leak-check=full ./program`用于查找内存泄漏，`g++ -fsanitize=address main.cpp -o program`用于编译带地址 sanitizer 的程序，`g++ -fsanitize=undefined main.cpp -o program`用于编译带未定义行为 sanitizer 的程序。

**常见错误类型（common error type）**：C++中用于表示程序错误的类型。常见错误类型可以分为语法错误、逻辑错误、运行时错误、内存错误、并发错误等。例如语法错误表示程序的语法不符合C++标准，逻辑错误表示程序的逻辑不正确，运行时错误表示程序在运行时发生错误，内存错误表示程序的内存使用不正确，并发错误表示程序的并发使用不正确。

**断言（assertion）**：C++中用于调试程序的机制。断言可以分为使用`assert`宏、使用`static_assert`等。例如`assert(x > 0);`用于断言`x`大于0，`static_assert(sizeof(int) == 4);`用于静态断言`int`的大小为4字节。

**内存泄漏（memory leak）**：C++中用于表示程序未能释放已分配内存的错误。内存泄漏可以分为堆内存泄漏、栈内存泄漏、全局内存泄漏等。例如堆内存泄漏表示程序未能释放堆内存，栈内存泄漏表示程序未能释放栈内存，全局内存泄漏表示程序未能释放全局内存。

**未定义行为（undefined behavior）**：C++中用于表示程序行为不确定的错误。未定义行为可以分为空指针解引用、数组越界访问、整数溢出等。例如空指针解引用表示程序解引用了空指针，数组越界访问表示程序访问了数组越界的元素，整数溢出表示程序发生了整数溢出。

**并发错误（concurrency error）**：C++中用于表示程序并发使用不正确的错误。并发错误可以分为竞态条件、死锁、活锁等。例如竞态条件表示程序的执行结果依赖于线程的执行顺序，死锁表示程序的线程相互等待，活锁表示程序的线程不断改变状态但无法继续执行。

**语法错误（syntax error）**：C++中用于表示程序的语法不符合C++标准的错误。语法错误可以分为关键字错误、括号不匹配、分号缺失等。例如关键字错误表示程序使用了不正确的关键字，括号不匹配表示程序的括号不匹配，分号缺失表示程序的分号缺失。

**逻辑错误（logic error）**：C++中用于表示程序的逻辑不正确的错误。逻辑错误可以分为条件判断错误、循环条件错误、变量初始化错误等。例如条件判断错误表示程序的条件判断不正确，循环条件错误表示程序的循环条件不正确，变量初始化错误表示程序的变量初始化不正确。

**运行时错误（runtime error）**：C++中用于表示程序在运行时发生错误的错误。运行时错误可以分为除零错误、空指针解引用、数组越界访问等。例如除零错误表示程序进行了除零操作，空指针解引用表示程序解引用了空指针，数组越界访问表示程序访问了数组越界的元素。

## 2. GDB调试器

### 1. 基本命令

```bash
# 启动GDB
gdb ./program

# 常用命令
(gdb) run [args]          # 运行程序
(gdb) start               # 开始执行（停在main）
(gdb) quit                # 退出GDB
(gdb) help [command]      # 查看帮助
```

### 2. 断点操作

```bash
# 设置断点
(gdb) break main          # 在main函数设置断点
(gdb) break file.cpp:10   # 在文件第10行设置断点
(gdb) break func if x>5   # 条件断点
(gdb) tbreak func         # 临时断点（只触发一次）

# 查看断点
(gdb) info breakpoints    # 显示所有断点
(gdb) info break 1        # 显示1号断点详情

# 管理断点
(gdb) delete 1            # 删除断点1
(gdb) disable 1           # 禁用断点1
(gdb) enable 1            # 启用断点1
(gdb) clear func          # 清除func的所有断点
```

### 3. 执行控制

```bash
# 单步执行
(gdb) next        # 执行下一行（不进入函数）
(gdb) step        # 执行下一行（进入函数）
(gdb) continue    # 继续执行到下一个断点
(gdb) finish      # 执行到当前函数返回
(gdb) until       # 执行到当前循环结束

# 跳转执行
(gdb) jump 20     # 跳转到第20行
```

### 4. 查看变量

```bash
# 打印变量
(gdb) print var           # 打印变量值
(gdb) print *ptr          # 打印指针指向的值
(gdb) print arr[0]@10     # 打印数组前10个元素
(gdb) print/x var         # 以十六进制打印

# 查看类型
(gdb) whatis var          # 查看变量类型
(gdb) ptype var           # 查看详细类型信息

# 查看内存
(gdb) x/10x address       # 以十六进制查看10个内存单元
(gdb) x/s str             # 查看字符串

# 查看调用栈
(gdb) backtrace           # 显示调用栈
(gdb) frame 2             # 切换到第2帧
(gdb) up                  # 上移一帧
(gdb) down                # 下移一帧
```

### 5. 监视点


### 6. GDB调试示例

```cpp
#include <iostream>
#include <vector>

// 示例程序：调试vector操作
int findMax(const std::vector<int>& nums) {
    if (nums.empty()) {
        return -1;
    }
    
    int maxVal = nums[0];
    for (size_t i = 1; i < nums.size(); ++i) {
        if (nums[i] > maxVal) {
            maxVal = nums[i];
        }
    }
    return maxVal;
}

int main() {

    int result = findMax(data);
    std::cout << "最大值: " << result << std::endl;
    
    return 0;
}
```

```cpp
    smartPointer();
```

## 4. 日志调试

### 1. 简单日志系统

```cpp
#include <iostream>
#include <fstream>
#include <chrono>
#include <iomanip>
#include <sstream>

enum class LogLevel {
    DEBUG,
    INFO,
    WARNING,
    ERROR
};

class Logger {
private:
    std::ofstream logFile;
    LogLevel minLevel = LogLevel::DEBUG;
    
    std::string getTimestamp() {
        auto now = std::chrono::system_clock::now();
        auto time = std::chrono::system_clock::to_time_t(now);
        std::stringstream ss;
        ss << std::put_time(std::localtime(&time), "%Y-%m-%d %H:%M:%S");
        return ss.str();
    }
    
    std::string levelToString(LogLevel level) {
        switch (level) {
            case LogLevel::DEBUG:   return "DEBUG";
            case LogLevel::INFO:    return "INFO";
            case LogLevel::WARNING: return "WARNING";
            case LogLevel::ERROR:   return "ERROR";
        }
        return "UNKNOWN";
    }
    
public:
    Logger(const std::string& filename) {
        logFile.open(filename, std::ios::app);
    }
    
    ~Logger() {
        if (logFile.is_open()) {
            logFile.close();
        }
    }
    
    void log(LogLevel level, const std::string& message, 
             const std::string& file = "", int line = 0) {
        if (level < minLevel) return;
        
        std::string location;
        if (!file.empty()) {
            location = " [" + file + ":" + std::to_string(line) + "]";
        }
        
        std::string logLine = getTimestamp() + " [" + 
                              levelToString(level) + "]" + location + 
                              " " + message + "\n";
        
        // 输出到文件
        if (logFile.is_open()) {
            logFile << logLine;
        }
        
        // 同时输出到控制台
        std::cout << logLine;
    }
    
    void setLevel(LogLevel level) {
        minLevel = level;
    }
};

// 宏定义
#define LOG_DEBUG(logger, msg)  logger.log(LogLevel::DEBUG, msg, __FILE__, __LINE__)
#define LOG_INFO(logger, msg)   logger.log(LogLevel::INFO, msg, __FILE__, __LINE__)
#define LOG_WARN(logger, msg)   logger.log(LogLevel::WARNING, msg, __FILE__, __LINE__)
#define LOG_ERROR(logger, msg)  logger.log(LogLevel::ERROR, msg, __FILE__, __LINE__)

int main() {
    Logger logger("app.log");
    logger.setLevel(LogLevel::DEBUG);
    
    LOG_DEBUG(logger, "程序启动");
    LOG_INFO(logger, "处理数据中...");
    LOG_WARN(logger, "内存使用率较高");
    LOG_ERROR(logger, "文件打开失败");
    
    return 0;
}
```

```cpp
int main() {
    // 使用 GDB 调试段错误
```

### 2. 内存错误

```cpp
#include <iostream>
```

### 3. 逻辑错误

```cpp
#include <iostream>
#include <vector>

// 1. 整数溢出
void integerOverflow() {
    int x = INT_MAX;
    x = x + 1;  // 溢出！
    std::cout << x << std::endl;  // 负数
}

// 2. 无符号整数陷阱
void unsignedTrap() {
    std::vector<int> v = {1, 2, 3};
    
    // 错误：当 v.size() 为 0 时，v.size() - 1 是很大的正数
    for (int i = v.size() - 1; i >= 0; --i) {
        std::cout << v[i] << " ";
    }
    
    // 正确做法
    for (int i = static_cast<int>(v.size()) - 1; i >= 0; --i) {
        std::cout << v[i] << " ";
    }
}

// 3. 浮点数比较
void floatComparison() {
    double a = 0.1 + 0.2;
    double b = 0.3;
    
    // 错误：直接比较
    if (a == b) {  // 可能为 false
        std::cout << "equal\n";
    }
    
    // 正确：使用容差
    if (std::abs(a - b) < 1e-9) {
        std::cout << "approximately equal\n";
    }
}

// 4. 迭代器失效
void iteratorInvalidation() {
    std::vector<int> v = {1, 2, 3, 4, 5};
    
    // 错误：在遍历时修改容器
    for (auto it = v.begin(); it != v.end(); ++it) {
        if (*it == 3) {
            v.erase(it);  // 迭代器失效！
        }
    }
    
    // 正确做法
    for (auto it = v.begin(); it != v.end(); ) {
        if (*it == 3) {
            it = v.erase(it);  // 使用返回的新迭代器
        } else {
            ++it;
        }
    }
}
```

## 7. Core Dump分析

### 1. Core Dump的概念

**Core Dump（核心转储）**：当程序崩溃时，操作系统将程序当时的内存状态、寄存器状态、调用栈等信息写入磁盘文件的过程。这个文件就是Core Dump文件，它相当于程序崩溃瞬间的"内存快照"。

```
┌─────────────────────────────────────────────────────────┐
│                Core Dump 工作原理                        │
├─────────────────────────────────────────────────────────┤
│                                                         │
│   程序运行 ──→ 发生崩溃（如段错误）                       │
│       │                    │                            │
│       │                    ↓                            │
│       │            操作系统捕获信号                       │
│       │                    │                            │
│       │                    ↓                            │
│       │            将内存映像写入磁盘                     │
│       │                    │                            │
│       │                    ↓                            │
│       │            生成 core 文件                        │
│       │                    │                            │
│       └────────────────────↓                            │
│                   用GDB分析core文件                      │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

### 2. 启用Core Dump

```bash
# 查看当前core文件大小限制
ulimit -c

# 如果输出0，表示禁止生成core文件
# 启用core文件生成（不限制大小）
ulimit -c unlimited

# 设置core文件最大大小（单位：KB）
ulimit -c 102400

# 永久生效：在 ~/.bashrc 或 /etc/profile 中添加
echo "ulimit -c unlimited" >> ~/.bashrc
```

### 3. 配置core文件路径

```bash
# 查看当前core文件命名规则
cat /proc/sys/kernel/core_pattern

# 默认可能只输出 "core"
# 修改core文件命名规则（需要root权限）
# %e - 可执行文件名
# %p - 进程PID
# %t - 时间戳
# %s - 导致崩溃的信号
# %h - 主机名

# 示例：设置core文件路径格式
sudo sh -c 'echo "/tmp/coredump/core_%e_%p_%t" > /proc/sys/kernel/core_pattern'

# 永久生效：编辑 /etc/sysctl.conf
# kernel.core_pattern = /tmp/coredump/core_%e_%p_%t
sudo sysctl -p

# 创建coredump目录
sudo mkdir -p /tmp/coredump
sudo chmod 777 /tmp/coredump

# 使用systemd-coredump（现代Linux发行版推荐）
# 查看已收集的core dump
coredumpctl list

# 查看某个core dump的详细信息
coredumpctl info <PID>

# 直接用GDB调试最近的core dump
coredumpctl debug
```

### 4. 用GDB分析Core Dump

```bash

# 指定core文件路径
gdb ./program /tmp/coredump/core_program_12345_1690000000

# 使用coredumpctl
coredumpctl debug

# GDB加载core文件后的常用命令
(gdb) bt                    # 查看崩溃时的调用栈
(gdb) bt full               # 查看调用栈及所有局部变量
(gdb) frame 0               # 切换到栈顶帧
(gdb) frame 3               # 切换到第3帧

(gdb) info threads          # 查看所有线程

(gdb) list                  # 查看崩溃位置附近的源代码
```

### 6. Core Dump的大小控制

```bash
# Core Dump文件可能非常大（等于程序的虚拟内存大小）
# 控制方法：

# 1. 限制core文件大小
ulimit -c 1048576  # 限制为1GB

# 2. 使用压缩的core文件（通过core_pattern管道）
sudo sh -c 'echo "|/usr/bin/gzip > /tmp/coredump/core_%e_%p_%t.gz" > /proc/sys/kernel/core_pattern'

# 3. 只生成部分core（排除共享库等）
# 在 /proc/PID/coredump_filter 中设置
# 默认值通常为 0x33，表示包含私有和共享的匿名内存等
cat /proc/self/coredump_filter

# 位掩码含义：
# 0x01 - 匿名私有内存
# 0x02 - 匿名共享内存
# 0x04 - 文件映射私有内存
# 0x08 - 文件映射共享内存
# 0x10 - ELF头
# 0x20 - 大页私有内存
# 0x40 - 大页共享内存
# 0x80 - 私有大页内存（DAX）

# 最小化core dump：只包含匿名私有内存
echo 0x01 > /proc/self/coredump_filter
```

```bash
ASAN_OPTIONS=log_path=asan.log ./program         # 输出到日志文件
```

### 2. TSan（Thread Sanitizer）：数据竞争检测

TSan用于检测多线程程序中的数据竞争和锁顺序问题，性能开销约5-15倍。

```bash
# 编译选项
g++ -fsanitize=thread -g program.cpp -o program -lpthread

# 注意：TSan与ASan不能同时使用
```

```cpp
#include <iostream>
#include <thread>
#include <vector>

// 数据竞争示例
int sharedCounter = 0;

void incrementCounter(int times) {
    for (int i = 0; i < times; ++i) {
        sharedCounter++;  // 数据竞争！多个线程同时修改
    }
}

int main() {
    const int numThreads = 4;
    const int increments = 100000;
    std::vector<std::thread> threads;

    for (int i = 0; i < numThreads; ++i) {
        threads.emplace_back(incrementCounter, increments);
    }

    for (auto& t : threads) {
        t.join();
    }

    // 期望结果：400000
    // 实际结果：通常小于400000（数据竞争导致丢失更新）
    std::cout << "期望: " << numThreads * increments << std::endl;
    std::cout << "实际: " << sharedCounter << std::endl;

    return 0;
}
```

```cpp
#include <iostream>
#include <thread>
#include <vector>
#include <mutex>

// 修复数据竞争：使用互斥锁
int sharedCounter = 0;
std::mutex counterMutex;

void incrementCounter(int times) {
    for (int i = 0; i < times; ++i) {
        std::lock_guard<std::mutex> lock(counterMutex);
        sharedCounter++;
    }
}

int main() {

    const int increments = 100000;
    std::vector<std::thread> threads;

    for (int i = 0; i < numThreads; ++i) {
        threads.emplace_back(incrementCounter, increments);

    for (auto& t : threads) {
        t.join();
    }

    std::cout << "期望: " << numThreads * increments << std::endl;
    std::cout << "实际: " << sharedCounter << std::endl;

    return 0;
}
```

### 5. 多个Sanitizer能否同时使用

**不能同时使用。** 不同Sanitizer之间会相互冲突，只能单独使用。

```bash

# 报错：error: '-fsanitize=address' and '-fsanitize=memory' are incompatible

# 正确做法：分别编译和测试
g++ -fsanitize=address -g program.cpp -o program_asan
g++ -fsanitize=thread -g program.cpp -o program_tsan
g++ -fsanitize=undefined -g program.cpp -o program_ubsan
```

### 6. Sanitizer性能开销对比表

| Sanitizer | 编译选项 | 检测能力 | 性能开销 | 内存开销 | 编译器支持 |
|-----------|---------|---------|---------|---------|-----------|
| **ASan** | `-fsanitize=address` | 内存错误（溢出、use-after-free、泄漏） | ~2x | ~3x | GCC, Clang, MSVC |
| **TSan** | `-fsanitize=thread` | 数据竞争、锁顺序问题 | ~5-15x | ~5-10x | GCC, Clang |
| **UBSan** | `-fsanitize=undefined` | 未定义行为（溢出、空指针、类型不匹配） | ~1.5x | ~1.5x | GCC, Clang |
| **MSan** | `-fsanitize=memory` | 未初始化内存读取 | ~3x | ~3x | 仅Clang |

> **选择建议：**
> - 日常开发测试：优先使用 **ASan**，开销最小、检测能力最强
> - 多线程程序：使用 **TSan**，但注意开销较大
> - 追求正确性：使用 **UBSan**，开销最小
> - 怀疑未初始化问题：使用 **MSan**（需要Clang）
> - CI/CD流水线：可以分别运行ASan + UBSan、TSan两轮测试

### 1. rr的概念

**rr（Record and Replay）**：由Mozilla开发的调试工具，能够录制程序的执行过程，然后精确回放。rr最大的特点是支持**逆向调试**——你可以从崩溃点往回执行，找到bug的根本原因。

```
│  传统调试：                                              │
│  ──────●─────────────────✕                              │
│        ↑                 ↑                              │
│      设置断点          程序崩溃                           │
│      只能从头重新运行                                    │
│                                                         │
│  rr调试：                                                │
│  ──────●─────────────────✕                              │
│        ↑                 ↑                              │
│      录制开始          崩溃点                            │
│      可以从崩溃点往回执行！                               │
│      reverse-continue / reverse-step / reverse-next      │
│                                                         │
```


### 7. 实战案例：用rr调试一个间歇性Bug

```cpp
#include <iostream>
#include <thread>
#include <vector>
#include <random>
#include <atomic>

// 间歇性Bug：多线程下的竞态条件
// 某个线程偶尔会读到不一致的数据

class ThreadSafeCounter {
    int value_;
public:
    ThreadSafeCounter() : value_(0) {}

    void increment() {
        value_++;  // 故意不加锁，模拟竞态条件
    }

    int get() const {
        return value_;
    }
};

ThreadSafeCounter counter;
std::atomic<bool> done{false};

void worker() {
    for (int i = 0; i < 100000; ++i) {
        counter.increment();
    }
}

void monitor() {
    int lastValue = 0;
    while (!done.load()) {
        int current = counter.get();
        if (current < lastValue) {
            // 不应该发生：值不应该减小
            std::cout << "检测到异常：值从 " << lastValue
                      << " 减小到 " << current << std::endl;
        }
        lastValue = current;
    }
}

int main() {
    std::vector<std::thread> workers;
    for (int i = 0; i < 4; ++i) {
        workers.emplace_back(worker);
    }

    std::thread mon(monitor);

    for (auto& w : workers) {
        w.join();
    }
    done = true;
    mon.join();

    std::cout << "最终值: " << counter.get() << std::endl;
    std::cout << "期望值: " << 4 * 100000 << std::endl;

    return 0;
}
```

```bash
# 或者在具体行号设置断点

# 步骤4：继续执行到断点
```

```
## 12. 问题解答

### 47. Q: 为什么要使用调试版本编译？
A: 调试版本（`-g -O0`）包含调试信息，并且不进行优化，可以方便地使用调试器进行调试。发布版本（`-O2`）进行了优化，执行速度更快，但调试信息较少。

### 48. Q: 如何调试段错误？
A: 使用GDB调试段错误的步骤：
1. 使用`-g`编译程序
2. 启动GDB：`gdb ./program`
3. 运行程序：`run`
4. 当程序崩溃时，使用`backtrace`查看调用栈
5. 使用`print`查看变量值
6. 使用`list`查看源代码

### 49. Q: 如何检测内存泄漏？
A: 可以使用Valgrind或AddressSanitizer检测内存泄漏：
- Valgrind：`valgrind --leak-check=full ./program`
- AddressSanitizer：编译时添加`-fsanitize=address`参数

### 50. Q: 如何调试多线程程序？
A: 使用GDB调试多线程程序的步骤：
1. 使用`-g`编译程序
2. 启动GDB：`gdb ./program`
3. 运行程序：`run`
4. 使用`info threads`查看所有线程
5. 使用`thread <id>`切换线程
6. 使用`break <func> thread <id>`设置线程断点

### 51. Q: 如何调试核心转储文件？
A: 调试核心转储文件的步骤：
1. 启用核心转储：`ulimit -c unlimited`
2. 运行程序，当程序崩溃时生成核心转储文件
3. 使用GDB调试核心转储文件：`gdb ./program core`
4. 使用`backtrace`查看调用栈

### 52. Q: 如何使用日志调试？
A: 使用日志调试的步骤：
1. 在代码中添加日志输出
2. 运行程序，生成日志文件
3. 分析日志文件，定位问题
4. 调试完成后，移除或注释日志输出

### 53. Q: 如何使用静态分析工具？
A: 常用的静态分析工具有Clang Static Analyzer、Cppcheck和Clang-Tidy：
- Clang Static Analyzer：`scan-build g++ main.cpp -o program`
- Cppcheck：`cppcheck --enable=all main.cpp`
- Clang-Tidy：`clang-tidy main.cpp -- -std=c++17`
```
