## 1. 能力维度总览

### 1. 概念与定义

**[能力图谱](14-能力图谱.md)（competency map）**：描述程序员在各个技术维度上的能力等级和成长路径的框架。[能力图谱](14-能力图谱.md)帮助程序员客观评估自己的水平，找到提升方向。

**能力维度（competency dimension）**：程序员能力的不同方面，包括语言基础、工程实践、系统设计、调试排错、学习成长等。

**能力等级（competency level）**：每个维度上的熟练程度，通常分为入门、熟练、精通、专家四个等级。

### 2. 五大能力维度

```
                    ┌─────────────────┐
                    │   系统设计能力   │
                    │  (架构与设计)    │
                    └────────┬────────┘
                             │
            ┌────────────────┼────────────────┐
            │                │                │
   ┌────────┴────────┐      │      ┌────────┴────────┐
   │  调试排错能力    │      │      │  工程实践能力    │
   │  (定位与修复)    │      │      │  (规范与协作)    │
   └─────────────────┘      │      └─────────────────┘
                             │
                    ┌────────┴────────┐
                    │  语言基础能力    │
                    │  (语法与特性)    │
                    └─────────────────┘
                             │
                    ┌────────┴────────┐
                    │  学习成长能力    │
                    │  (方法与习惯)    │
                    └─────────────────┘
```

### 3. 能力等级定义

| 等级 | 名称 | 特征 | 典型表现 |
|------|------|------|---------|
| L1 | 入门 | 知道概念，需要指导 | 能看懂代码，需要查文档 |
| L2 | 熟练 | 能独立完成常规任务 | 能独立编写功能代码 |
| L3 | 精通 | 深入理解，能解决复杂问题 | 能优化性能，设计架构 |
| L4 | 专家 | 领域权威，能创新突破 | 能设计系统，引领方向 |

### 2.2 提升建议

**L1 → L2**：
- 完成至少3个完整项目
- 系统学习C++ Primer或The C Programming Language
- 每天编写代码，养成编码习惯

**L2 → L3**：
- 深入学习Effective C++系列
- 阅读STL源码
- 尝试实现自己的容器和算法

**L3 → L4**：
- 研究编译器实现原理
- 参与语言标准讨论
- 设计并实现通用库

## 6. 学习成长能力

### 6.1 能力清单

| 能力项 | L1 入门 | L2 熟练 | L3 精通 | L4 专家 |
|--------|---------|---------|---------|---------|
| 文档阅读 | 能读中文文档 | 能读英文文档 | 能读语言规范 | 能读学术论文 |
| 源码阅读 | 能读简单代码 | 能读项目源码 | 能理解设计意图 | 能发现设计缺陷 |
| 知识管理 | 知道要记笔记 | 能系统整理笔记 | 能建立知识体系 | 能输出知识框架 |
| 技术选型 | 知道常用工具 | 能比较方案优劣 | 能做出合理选择 | 能设计技术路线 |
| 技术分享 | 能做简单分享 | 能做主题演讲 | 能做系统培训 | 能引领技术方向 |
| 持续学习 | 知道要学习 | 有学习计划 | 有学习方法论 | 能构建学习生态 |

### 6.2 学习方法

#### 费曼学习法

```
1. 选择一个概念
2. 用简单语言教给别人
3. 发现自己讲不清楚的地方
4. 回去重新学习
5. 简化表达，直到任何人都能理解
```

#### 刻意练习

```
1. 明确目标：我要掌握什么？
2. 专注练习：全神贯注地练习
3. 即时反馈：立刻知道对错
4. 走出舒适区：挑战稍难的题目
5. 重复迭代：直到形成肌肉记忆
```

#### 主题阅读法

```
1. 选择一个主题（如"内存管理"）
2. 找3-5本相关书籍/文章
3. 对比不同作者的讲解
4. 整合形成自己的理解
5. 通过实践验证理解
```

## 8. 能力提升路径

### 8.1 初级 → 中级（1-3年）

#### 目标

掌握语言特性，能独立完成模块开发，具备基本调试能力。

#### 关键能力

| 能力 | 具体要求 | 学习方式 |
|------|---------|---------|
| C++核心特性 | 类、继承、多态、模板基础 | 系统学习+项目实践 |
| STL使用 | 容器、算法、迭代器 | 每日练习 |
| 内存管理 | new/delete、智能指针 | 项目实践+工具检测 |
| 调试基础 | GDB基本操作、日志 | 实际调试 |
| 编码规范 | 团队规范、命名规则 | Code Review |
| 版本控制 | Git基本操作 | 日常使用 |

#### 推荐学习计划

```
第1-3月：C++基础语法
  → C++ Primer前12章
  → 每天编码1小时
  → 完成3个小项目

第4-6月：STL与模板
  → 学习STL容器和算法
  → 编写模板函数和类
  → 完成1个中型项目

第7-9月：工程实践
  → 学习CMake和Git
  → 编写单元测试
  → 参与代码审查

第10-12月：调试与优化
  → 学习GDB和Valgrind
  → 分析和修复Bug
  → 性能优化实践
```

---

### 8.2 中级 → 高级（3-5年）

#### 目标

掌握系统设计，能优化性能，具备架构设计能力。

#### 关键能力

| 能力 | 具体要求 | 学习方式 |
|------|---------|---------|
| 系统设计 | 模块划分、接口设计、设计模式 | 设计实践+案例分析 |
| 性能优化 | CPU、内存、I/O优化 | 性能分析+优化实践 |
| 并发编程 | 多线程、锁、无锁编程 | 项目实践+理论学习 |
| 网络编程 | Socket、协议设计 | 网络项目实践 |
| 高级调试 | 多线程调试、性能分析 | 复杂问题排查 |
| 代码质量 | 重构、设计原则 | Code Review+重构实践 |

#### 推荐学习计划

```
第1-6月：系统设计能力
  → 学习设计模式
  → 研究开源项目架构
  → 设计并实现一个完整系统

第7-12月：性能与并发
  → 学习CPU缓存、内存模型
  → 实现多线程服务器
  → 性能优化实战

第13-18月：深入领域
  → 选择一个方向深入（网络/数据库/编译器/图形）
  → 阅读领域经典书籍
  → 完成领域项目

第19-24月：架构能力
  → 学习分布式系统
  → 参与架构设计
  → 技术分享和指导
```

---

### 8.3 高级 → 专家（5-10年）

#### 目标

具备架构设计能力、技术领导力，能引领技术方向。

#### 关键能力

| 能力 | 具体要求 | 学习方式 |
|------|---------|---------|
| 架构设计 | 系统架构、技术选型 | 大型项目实践 |
| 技术领导力 | 团队指导、技术决策 | 带团队+技术管理 |
| 领域专精 | 某领域深度专家 | 持续深耕 |
| 创新能力 | 解决前所未有的问题 | 研究+实践 |
| 影响力 | 技术分享、开源贡献 | 写作+演讲+开源 |
| 跨领域 | 多领域知识融合 | 广泛学习 |

#### 成长方向

```
技术专家路线：
  高级工程师 → 资深工程师 → 技术专家 → 首席工程师

技术管理路线：
  高级工程师 → 技术负责人 → 架构师 → CTO

创业路线：
  高级工程师 → 技术合伙人 → CTO/创始人

开源/独立路线：

```

## 10. 面试能力准备

### 10.1 面试考察维度

```
基础知识（40%）
  → C/C++语法、指针、内存管理、面向对象

算法能力（30%）
  → 数据结构、算法设计、复杂度分析

系统设计（20%）
  → 架构设计、性能优化、方案比较

工程实践（10%）
  → 项目经验、问题解决、团队协作
```

### 10.2 高频面试题分类

#### C语言高频题

| 题目 | 考察点 |
|------|--------|

| struct内存对齐 | 内存布局理解 |
| volatile关键字 | 编译器优化理解 |
| 宏与函数的区别 | 预处理器理解 |
| 手写strcpy/memcpy | 字符串/内存操作 |

#### C++高频题

| 题目 | 考察点 |
|------|--------|
| 虚函数机制 | 多态底层实现 |

| 右值引用与移动语义 | 资源管理优化 |
| STL容器底层实现 | 数据结构理解 |
| 模板特化与偏特化 | 泛型编程 |
| lambda表达式 | 函数对象 |

#### 系统设计高频题

| 题目 | 考察点 |
|------|--------|
| 设计一个线程池 | 并发编程 |
| 设计一个LRU缓存 | 数据结构+算法 |
| 设计一个内存池 | 内存管理 |
| 设计一个日志系统 | I/O+并发 |
| 设计一个消息队列 | 系统设计 |

### 10.3 面试准备策略

#### 基础知识准备

```
1. 整理核心知识点清单
2. 每个知识点准备"是什么→为什么→怎么用"三层回答
3. 对每个知识点准备代码示例
4. 准备"常见陷阱"和"最佳实践"
```

#### 算法准备

```
1. 刷LeetCode Hot 100
2. 按专题练习（数组、链表、树、动态规划等）
3. 每题写多种解法，分析复杂度
4. 模拟面试，限时完成
```

#### 项目经验准备

```
1. 用STAR法则整理项目（情境→任务→行动→结果）
2. 准备每个项目的难点和解决方案
3. 准备项目中的技术决策和权衡
4. 准备量化结果（性能提升X%，延迟降低Yms）
```

### 10.4 面试技巧

| 技巧 | 说明 |
|------|------|
| 先思考再回答 | 不要急于开口，理清思路 |
| 大声思考 | 让面试官看到你的思考过程 |
| 从简单到复杂 | 先给暴力解，再优化 |
| 主动沟通 | 不确定时主动询问 |
| 展示深度 | 回答后主动延伸相关知识点 |
| 诚实作答 | 不会就说不会，不要编造 |

## 总结

### [能力图谱](14-能力图谱.md)核心要点

1. **五大维度**：语言基础、工程实践、系统设计、调试排错、学习成长
2. **四个等级**：入门→熟练→精通→专家
3. **客观自评**：定期评估，找到短板
4. **持续提升**：每个阶段有明确的学习目标和路径
5. **全面发展**：不要只关注语言，工程和设计同样重要

### 成长心法

```
语言基础是根基 → 没有基础，一切都是空中楼阁
工程实践是骨架 → 没有规范，代码无法维护
系统设计是灵魂 → 没有设计，系统无法扩展
调试排错是利器 → 没有调试，问题无法解决
学习成长是引擎 → 没有学习，能力无法提升
```

> 💡 **记住：能力提升是马拉松，不是短跑。每天进步一点点，一年后你会惊讶自己的成长。**
