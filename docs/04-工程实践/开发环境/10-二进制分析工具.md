# 编译器隐藏工具与鲜为人知的能力

> **前置阅读**：如果你还不了解编译器的基本使用，请先阅读 [FAQ-138：开发环境配置详解](../../03-问题解答/01-基础概念/33-开发环境配置.md) 和 [GCC/G++编译器深度使用指南](07-GCC编译器基础.md)。本文档将带你发现编译器工具链中那些鲜为人知但极为实用的工具和能力。

## 1. GCC工具链中你可能不知道的工具

GCC工具链不仅包含编译器本身，还附带了大量辅助工具，这些工具在排查问题、分析二进制、优化性能时极为有用。

### 1. addr2line —— 地址转源码行号

**用途说明**：将程序中的内存地址转换为源代码文件名和行号。在分析 crash 时的 backtrace 地址、core dump 中的指令地址时非常关键。

**常用命令示例**：

```bash
# 基本用法：将地址转换为源码位置
addr2line -e myapp 0x401234

# 批量转换多个地址
addr2line -e myapp 0x401234 0x401250 0x4012a0

# 同时显示函数名
addr2line -f -e myapp 0x401234

# 处理内联函数（需要调试信息）
addr2line -f -i -e myapp 0x401234
```

**实际使用场景**：程序崩溃后从 core dump 中获取到指令地址 `0x401234`，使用 `addr2line -f -e myapp 0x401234` 即可定位到具体的源文件和行号，快速定位崩溃位置。

### 2. ar —— 静态库管理

**用途说明**：创建、修改和提取静态库（`.a` 文件）。静态库本质上是 `.o` 文件的归档包。

**常用命令示例**：

```bash
# 创建静态库
ar rcs libmylib.a foo.o bar.o baz.o

# 查看静态库中的目标文件列表
ar t libmylib.a

# 查看详细列表（包含时间戳和权限）
ar tv libmylib.a

# 从静态库中提取目标文件
ar x libmylib.a foo.o

# 向已有静态库追加目标文件
ar r libmylib.a new_module.o

# 删除静态库中的某个目标文件
ar d libmylib.a old_module.o
```

**实际使用场景**：项目需要将多个 `.o` 文件打包为 `libutils.a` 供其他模块链接，使用 `ar rcs libutils.a *.o` 即可完成打包。

### 3. as —— 汇编器

**用途说明**：GNU 汇编器，将汇编语言源文件编译为目标文件（`.o`）。GCC 在编译 C/C++ 代码时，内部会先生成汇编再调用 `as` 进行汇编。

**常用命令示例**：

```bash
# 汇编一个.s文件
as -o hello.o hello.s

# 生成调试信息
as -g -o hello.o hello.s

# 指定目标架构
as --64 -o hello.o hello.s
```

**实际使用场景**：手写汇编优化关键路径代码时，直接使用 `as` 将 `.s` 文件汇编为 `.o` 文件，再与其他 C++ 目标文件链接。

### 4. c++filt —— C++名称反改编（demangle）

**用途说明**：C++ 编译器会对函数名进行名称改编（name mangling），将重载函数、命名空间等信息编码到符号名中。`c++filt` 将这些改编后的名称还原为人类可读的形式。

**常用命令示例**：

```bash
# 反改编单个符号
c++filt _ZN3foo3barEi
# 输出: foo::bar(int)

# 从nm输出中反改编所有符号
nm myapp | c++filt

# 从objdump输出中反改编
objdump -t myapp | c++filt

# 处理整个文件中的改编名称
cat symbols.txt | c++filt
```

**实际使用场景**：链接器报错 `undefined reference to _ZNSt8ios_base4InitC1Ev`，使用 `c++filt _ZNSt8ios_base4InitC1Ev` 得到 `std::ios_base::Init::Init()`，即可理解缺少的是 C++ I/O 初始化。

### 5. cpp —— C预处理器

**用途说明**：GCC 内置的 C 预处理器，执行宏展开、头文件包含、条件编译等预处理操作。

**常用命令示例**：

```bash
# 仅执行预处理
cpp -E main.cpp -o main.ii

# 保留注释进行预处理
cpp -E -C main.cpp -o main.ii

# 查看宏展开结果（调试宏问题时有用）
cpp -E -dM main.cpp > macros.txt

# 添加自定义宏定义
cpp -E -DDEBUG=1 -DVERSION=\"2.0\" main.cpp
```

**实际使用场景**：宏展开结果不符合预期时，使用 `cpp -E main.cpp` 查看预处理后的输出，定位宏展开问题。

### 6. dwp —— DWARF打包工具

**用途说明**：将分散在多个 `.o` 文件中的 DWARF 调试信息合并为一个 `.dwp`（DWARF Package）文件，减小发布二进制的体积。

**常用命令示例**：

```bash
# 从可执行文件和其调试链接创建.dwp文件
dwp -e myapp -o myapp.dwp

# 验证.dwp文件
dwp -v myapp.dwp
```

**实际使用场景**：发布版本需要分离调试信息时，先用 `objcopy --strip-debug` 去除调试信息，再用 `dwp` 将所有调试信息打包为单个 `.dwp` 文件，便于集中管理。

### 7. elfedit —— ELF文件编辑器

**用途说明**：直接编辑 ELF 文件的头部字段，如修改 ELF 标识、类型等。

**常用命令示例**：

```bash
# 查看ELF头部
elfedit --output-magic myapp

# 修改ELF类型
elfedit --input-magic --output-magic myapp

# 查看所有段头
elfedit -h myapp
```

**实际使用场景**：需要修改 ELF 文件的某些头部属性（如将共享库标记为可执行）时，使用 `elfedit` 直接修改而无需重新编译。

### 8. gcov —— 代码覆盖率分析

**用途说明**：分析程序运行时的代码覆盖率，统计每行代码、每个分支被执行的次数。配合 `-fprofile-arcs -ftest-coverage` 编译选项使用。

**常用命令示例**：

```bash
# 编译时启用覆盖率
g++ -fprofile-arcs -ftest-coverage -o myapp main.cpp

# 运行程序（生成.gcda文件）
./myapp

# 生成覆盖率报告
gcov main.cpp

# 查看分支覆盖详情
gcov -b main.cpp

# 查看所有源文件的覆盖率
gcov -a main.cpp
```

**实际使用场景**：单元测试需要评估测试覆盖率时，编译时加覆盖率选项，运行测试后用 `gcov` 生成报告，找出未被测试覆盖的代码路径。

### 9. gprof —— 性能分析

**用途说明**：分析程序的函数调用关系和执行时间，生成 flat profile 和 call graph。编译时需加 `-pg` 选项。

**常用命令示例**：

```bash
# 编译时启用性能分析
g++ -pg -o myapp main.cpp

# 运行程序（生成gmon.out）
./myapp

# 生成分析报告
gprof myapp gmon.out > analysis.txt

# 只看flat profile（不包含调用图）
gprof -p myapp gmon.out

# 只看调用图
gprof -q myapp gmon.out
```

**实际使用场景**：程序运行缓慢需要定位热点函数时，使用 `gprof` 找出占用 CPU 时间最多的函数，集中优化。

### 10. ld —— 链接器

**用途说明**：GNU 链接器，将多个目标文件和库链接为可执行文件或共享库。通常不直接调用，而是通过 GCC 间接使用。

**常用命令示例**：

```bash
# 直接链接目标文件
ld -o myapp main.o utils.o -lc++

# 链接时指定库搜索路径
ld -o myapp main.o -L/usr/local/lib -lmylib

# 生成共享库
ld -shared -o libmylib.so foo.o bar.o

# 查看链接器脚本
ld --verbose

# 链接时生成map文件（查看符号分配地址）
ld -Map=myapp.map -o myapp main.o
```

**实际使用场景**：链接时出现符号冲突或内存布局异常，使用 `ld -Map` 生成 map 文件查看符号的具体分配地址和段布局。

### 11. nm —— 符号表查看

**用途说明**：列出目标文件、静态库、共享库和可执行文件中的符号表，查看定义和引用的符号。

**常用命令示例**：

```bash
# 列出所有符号
nm myapp

# 只显示动态符号
nm -D libmylib.so

# 按地址排序显示
nm -n myapp

# 显示符号大小
nm -S myapp

# 查看未定义的符号（常用于排查链接错误）
nm -u myapp

# 反改编C++符号名
nm -C myapp
```

**实际使用场景**：链接报 `undefined reference` 错误时，用 `nm -u myapp` 查看所有未定义符号，再用 `nm -D libxxx.so` 检查库中是否提供了该符号。

### 12. objcopy —— 二进制文件转换

**用途说明**：复制和转换目标文件，常用于分离调试信息、转换文件格式、去除特定段等。

**常用命令示例**：

```bash
# 分离调试信息到单独文件
objcopy --only-keep-debug myapp myapp.debug

# 去除调试信息
objcopy --strip-debug myapp myapp.stripped

# 去除所有符号信息
objcopy --strip-all myapp myapp.stripped

# 添加调试链接指向分离的调试文件
objcopy --add-gnu-debuglink=myapp.debug myapp

# 将ELF转换为Intel HEX格式
objcopy -O ihex firmware.elf firmware.hex

# 将ELF转换为二进制（裸机固件常用）
objcopy -O binary firmware.elf firmware.bin

# 只保留特定段
objcopy -j .text -j .data -O binary firmware.elf firmware.bin
```

**实际使用场景**：嵌入式开发中将 ELF 转换为二进制固件 `objcopy -O binary app.elf app.bin`；发布版本分离调试信息 `objcopy --only-keep-debug` 保留调试文件供事后分析。

### 13. objdump —— 反汇编和查看ELF

**用途说明**：反汇编目标文件、查看 ELF 文件的各个段和头部信息，是二进制分析的瑞士军刀。

**常用命令示例**：

```bash
# 反汇编所有段
objdump -d myapp

# 反汇编并交织源代码（需要调试信息）
objdump -S myapp

# 反汇编特定函数
objdump -d myapp | grep -A 20 '<main>'

# 查看所有段头部
objdump -h myapp

# 查看ELF完整头部
objdump -x myapp

# 查看重定位条目
objdump -r myapp.o

# 反改编C++符号
objdump -d -C myapp

# 查看动态段
objdump -p myapp | grep NEEDED
```

**实际使用场景**：需要确认编译器是否将关键循环正确向量化时，用 `objdump -S myapp | grep -A 30 'my_loop'` 查看反汇编中是否出现 SIMD 指令。

### 14. ranlib —— 静态库索引

**用途说明**：为静态库（`.a` 文件）生成符号索引，加速链接器在静态库中查找符号的速度。

**常用命令示例**：

```bash
# 为静态库生成索引
ranlib libmylib.a

# 检查静态库是否已有索引
ranlib -t libmylib.a
```

**实际使用场景**：链接时出现静态库符号找不到的问题，可能是库缺少索引，运行 `ranlib libmylib.a` 重新生成索引即可解决。`ar rcs` 中的 `s` 选项等价于自动调用 `ranlib`。

### 15. readelf —— ELF文件查看

**用途说明**：专门用于查看 ELF 文件的各种信息，比 `objdump` 更专注于 ELF 格式解析，不依赖 BFD 库。

**常用命令示例**：

```bash
# 查看ELF头部
readelf -h myapp

# 查看所有段头部
readelf -S myapp

# 查看符号表
readelf -s myapp

# 查看动态段（依赖的共享库）
readelf -d myapp

# 查看程序头部（段映射）
readelf -l myapp

# 查看重定位条目
readelf -r myapp.o

# 查看DWARF调试信息
readelf -w myapp

# 查看所有信息
readelf -a myapp
```

**实际使用场景**：排查动态库加载问题时，用 `readelf -d myapp` 查看 `NEEDED` 条目确认程序依赖的共享库列表；用 `readelf -r myapp.o` 查看重定位确认符号引用是否正确。

### 16. size —— 段大小查看

**用途说明**：列出目标文件或可执行文件中各段（text、data、bss）的大小，快速了解程序的内存占用。

**常用命令示例**：

```bash
# 查看各段大小（系统V格式）
size myapp

# 查看各段大小（Berkeley格式，更详细）
size -A myapp

# 查看所有目标文件的段大小
size *.o
```

**实际使用场景**：嵌入式开发中内存紧张，用 `size firmware.elf` 快速查看 text（代码）、data（已初始化数据）、bss（未初始化数据）各占多少字节，评估是否超出 Flash 和 RAM 容量。

### 17. strings —— 提取可打印字符串

**用途说明**：从二进制文件中提取可打印的字符串序列，无需反汇编即可查看文件中嵌入的文本信息。

**常用命令示例**：

```bash
# 提取所有可打印字符串（默认最少4字符）
strings myapp

# 指定最小字符串长度
strings -n 3 myapp

# 只查看特定段中的字符串
strings -t x myapp  # 同时显示偏移地址（十六进制）

# 查看动态库中的版本信息
strings libmylib.so | grep -i version
```

**实际使用场景**：拿到一个无源码的二进制文件，用 `strings myapp | grep -i "error\|warning\|copyright"` 快速了解程序的错误提示、版权信息等；排查硬编码路径时 `strings myapp | grep "/"`。

### 18. strip —— 去除符号和调试信息

**用途说明**：去除目标文件中的符号表和调试信息，显著减小文件体积。发布版本通常都会 strip。

**常用命令示例**：

```bash
# 去除所有符号和调试信息
strip myapp

# 只去除调试信息，保留符号表
strip --strip-debug myapp

# 只去除不需要的符号（保留动态符号）
strip --strip-unneeded myapp

# 去除特定符号
strip --strip-symbol=unused_func myapp

# 先保存调试信息再strip
objcopy --only-keep-debug myapp myapp.debug
strip --strip-all myapp
objcopy --add-gnu-debuglink=myapp.debug myapp
```

**实际使用场景**：发布前减小二进制体积，`strip myapp` 通常可将文件缩小 30%-70%。配合 `objcopy --add-gnu-debuglink` 可在 strip 后仍能通过调试文件进行调试。

### 19. vsdb —— 调试信息验证

**用途说明**：验证 DWARF 调试信息的完整性和正确性，确保调试信息与实际代码一致。

**常用命令示例**：

```bash
# 验证调试信息
vsdb myapp

# 验证并输出详细信息
vsdb -v myapp
```

**实际使用场景**：调试器显示的行号与源码不匹配时，使用 `vsdb` 验证调试信息是否正确生成，排查编译器优化导致的调试信息失真问题。

## 2. Clang/LLVM工具链中你可能不知道的工具

LLVM 工具链提供了许多现代化的开发工具，在代码质量、性能分析和调试方面比 GCC 工具链更先进。

### 1. clang-format —— 代码格式化

**用途说明**：根据配置规则自动格式化 C/C++/ObjC 代码，支持多种内置风格（LLVM、Google、Chromium、Mozilla、WebKit）和自定义 `.clang-format` 配置文件。

**常用命令示例**：

```bash
# 使用LLVM默认风格格式化（输出到stdout）
clang-format main.cpp

# 就地格式化文件
clang-format -i main.cpp

# 格式化整个项目
find src -name "*.cpp" -o -name "*.h" | xargs clang-format -i

# 检查哪些文件格式不符合规范
clang-format --dry-run --Werror src/*.cpp

# 生成.clang-format配置文件
clang-format -style=llvm -dump-config > .clang-format

# 只格式化git diff中修改的行
git diff | clang-format -style=file
```

**实际使用场景**：团队开发中统一代码风格，在 CI 中加入 `clang-format --dry-run --Werror` 检查，确保所有提交的代码都符合格式规范。

### 2. clang-tidy —— 静态分析

**用途说明**：基于 Clang 的 C++ 静态分析工具（linter），内置数百条检查规则，涵盖代码质量、现代 C++ 最佳实践、性能优化、Bug 检测等，还支持自动修复。

**常用命令示例**：

```bash
# 运行所有检查
clang-tidy main.cpp

# 运行特定检查
clang-tidy -checks='modernize-*' main.cpp

# 运行检查并自动修复
clang-tidy -checks='modernize-*' -fix main.cpp

# 使用compile_commands.json
clang-tidy -p build main.cpp

# 列出所有可用的检查
clang-tidy -list-checks -checks='*'

# 只运行性能相关检查
clang-tidy -checks='performance-*' -p build src/*.cpp
```

**实际使用场景**：将 C++ 代码从 C++11 升级到 C++17 时，使用 `clang-tidy -checks='modernize-*' -fix` 自动将旧式循环改为范围 for、将 `NULL` 改为 `nullptr`、将 `typedef` 改为 `using` 等。

### 3. clang-query —— AST查询

**用途说明**：交互式查询 Clang AST（抽象语法树），使用类正则表达式语法匹配 AST 节点，是编写 clang-tidy 自定义检查的基础工具。

**常用命令示例**：

```bash
# 交互式查询
clang-query main.cpp

# 查询所有函数声明
clang-query -c "match functionDecl()" main.cpp

# 查询所有调用expr
clang-query -c "match callExpr()" main.cpp

# 查询特定名称的函数
clang-query -c "match functionDecl(hasName('main'))" main.cpp

# 查询所有if语句
clang-query -c "match ifStmt()" main.cpp
```

**实际使用场景**：需要编写自定义 clang-tidy 检查规则时，先用 `clang-query` 探索 AST 结构，确认匹配表达式的正确性。

### 4. clang-check —— 语法检查

**用途说明**：快速对源文件进行语法和语义检查，不需要完整的构建系统配置，比完整编译更快。

**常用命令示例**：

```bash
# 基本语法检查
clang-check main.cpp

# 指定C++标准
clang-check -extra-arg=-std=c++17 main.cpp

# 分析模式（显示AST）
clang-check -ast-dump main.cpp

# 语法检查并显示诊断
clang-check -analyze main.cpp
```

**实际使用场景**：编辑器中集成实时语法检查，在保存文件时自动运行 `clang-check`，快速发现语法错误而无需等待完整编译。

### 5. scan-build —— 静态分析扫描

**用途说明**：在构建过程中拦截编译命令并运行 Clang 静态分析器，无需修改构建系统即可对整个项目进行静态分析。

**常用命令示例**：

```bash
# 使用scan-build进行make构建
scan-build make

# 使用scan-build进行cmake构建
scan-build cmake ..
scan-build make

# 指定分析器路径
scan-build --use-analyzer /usr/bin/clang make

# 指定输出目录
scan-build -o /tmp/scan-results make

# 只启用特定检查器
scan-build -enable-checker core.DivideZero make
```

**实际使用场景**：遗留项目没有 `compile_commands.json`，无法直接使用 `clang-tidy`，使用 `scan-build make` 在构建过程中自动分析所有源文件。

### 6. scan-view —— 分析结果查看

**用途说明**：查看 `scan-build` 生成的静态分析报告，启动本地 Web 服务器以浏览器方式浏览结果。

**常用命令示例**：

```bash
# 查看scan-build生成的报告
scan-view /tmp/scan-results/2024-01-01-*

# 指定端口号
scan-view --port 8888 /tmp/scan-results/2024-01-01-*
```

**实际使用场景**：`scan-build` 分析完成后，使用 `scan-view` 打开浏览器查看详细的 Bug 报告，包括代码路径、变量状态等可视化信息。

### 7. llvm-symbolizer —— 地址符号化

**用途说明**：将内存地址转换为源代码位置（文件名、行号、函数名），类似于 `addr2line` 但基于 LLVM，支持更多调试信息格式。

**常用命令示例**：

```bash
# 基本用法
llvm-symbolizer -obj=myapp 0x401234

# 批量符号化
echo "0x401234\n0x401250" | llvm-symbolizer -obj=myapp

# 打印函数名
llvm-symbolizer -obj=myapp -f 0x401234

# 处理内联函数
llvm-symbolizer -obj=myapp -f -i 0x401234
```

**实际使用场景**：配合 AddressSanitizer 使用，ASan 输出的错误报告中的地址通过 `llvm-symbolizer` 转换为源码位置，快速定位内存错误。

### 8. llvm-dwarfdump —— DWARF查看

**用途说明**：查看和验证 ELF 文件中的 DWARF 调试信息，提供比 `readelf -w` 更详细和可读的输出。

**常用命令示例**：

```bash
# 查看所有DWARF信息
llvm-dwarfdump myapp

# 只查看调试信息入口（DIE）
llvm-dwarfdump -debug-info myapp

# 只查看行号信息
llvm-dwarfdump -debug-line myapp

# 只查看帧信息
llvm-dwarfdump -debug-frame myapp

# 验证DWARF信息完整性
llvm-dwarfdump -verify myapp
```

**实际使用场景**：调试器行为异常时，用 `llvm-dwarfdump -verify myapp` 验证 DWARF 信息的完整性，确认编译器生成的调试信息是否有误。

### 9. llvm-objdump —— 反汇编

**用途说明**：LLVM 版本的 `objdump`，支持更多体系结构和输出格式，与 LLVM 工具链配合更好。

**常用命令示例**：

```bash
# 反汇编
llvm-objdump -d myapp

# 反汇编并交织源代码
llvm-objdump -S myapp

# 反汇编特定段
llvm-objdump -d -j .text myapp

# 查看所有段
llvm-objdump -h myapp

# 显示符号表
llvm-objdump -t myapp

# 反汇编并显示指令编码
llvm-objdump -d --show-all-sources myapp
```

**实际使用场景**：交叉编译的 ARM/RISC-V 二进制文件，使用 `llvm-objdump` 反汇编比 GNU `objdump` 支持更多目标架构。

### 10. llvm-cov —— 代码覆盖率

**用途说明**：LLVM 的代码覆盖率工具，配合 `-fprofile-instr-generate -fcoverage-mapping` 编译选项使用，生成比 `gcov` 更精确的覆盖率报告。

**常用命令示例**：

```bash
# 编译时启用覆盖率
clang++ -fprofile-instr-generate -fcoverage-mapping -o myapp main.cpp

# 运行程序生成原始数据
LLVM_PROFILE_FILE="myapp.profraw" ./myapp

# 合并原始数据
llvm-profdata merge -sparse myapp.profraw -o myapp.profdata

# 生成文本覆盖率报告
llvm-cov report ./myapp -instr-profile=myapp.profdata

# 生成HTML覆盖率报告
llvm-cov show ./myapp -instr-profile=myapp.profdata -format=html > coverage.html

# 查看特定文件的行级覆盖率
llvm-cov show ./myapp -instr-profile=myapp.profdata main.cpp
```

**实际使用场景**：CI/CD 流水线中生成覆盖率报告，使用 `llvm-cov show -format=html` 生成美观的 HTML 报告，直观展示每行代码的覆盖情况。

### 11. llvm-profdata —— 性能数据

**用途说明**：管理和处理 LLVM 的性能分析数据（profile data），包括合并、显示和转换 profile 文件格式。

**常用命令示例**：

```bash
# 合并多个profile文件
llvm-profdata merge profile1.profraw profile2.profraw -o merged.profdata

# 显示profile信息
llvm-profdata show merged.profdata

# 转换profile格式
llvm-profdata merge -text profile.profraw -o profile.profdata

# 覆盖率数据合并
llvm-profdata merge -sparse *.profraw -o coverage.profdata
```

**实际使用场景**：多次运行测试产生的多个 `.profraw` 文件，使用 `llvm-profdata merge` 合并为一个 `.profdata` 文件，用于 PGO（Profile-Guided Optimization）或覆盖率报告。

### 12. llvm-mca —— 微架构分析

**用途说明**：分析汇编代码在特定 CPU 微架构上的执行性能，包括指令调度、流水线利用率和吞吐量估算。

**常用命令示例**：

```bash
# 分析一段汇编代码的微架构性能
echo "add %rax, %rbx
mul %rcx
add %rdx, %rax" | llvm-mca -mcpu=skylake

# 分析文件中的汇编
llvm-mca -mcpu=haswell assembly.s

# 指定迭代次数
llvm-mca -mcpu=znver3 -iterations=100 assembly.s

# 输出详细的时间线信息
llvm-mca -mcpu=skylake -timeline assembly.s

# 输出资源压力信息
llvm-mca -mcpu=skylake -all-stats assembly.s
```

**实际使用场景**：优化热点循环时，先用 `clang -S -O2 -masm=intel` 生成汇编，再用 `llvm-mca -mcpu=skylake` 分析指令级并行度和流水线停顿，指导手动优化。

### 13. llc —— LLVM IR到汇编

**用途说明**：将 LLVM IR（`.ll` 文件）或 LLVM bitcode（`.bc` 文件）编译为目标平台的汇编代码或目标文件。

**常用命令示例**：

```bash
# LLVM IR编译为汇编
llc input.ll -o output.s

# LLVM IR编译为目标文件
llc input.ll -filetype=obj -o output.o

# 指定目标架构
llc -march=x86-64 input.ll -o output.s

# 指定CPU型号（影响指令选择）
llc -march=x86-64 -mcpu=skylake input.ll -o output.s

# 查看所有可用pass
llc -debug-pass=Structure input.ll
```

**实际使用场景**：学习编译器后端时，用 `llc` 将 LLVM IR 编译为不同架构的汇编代码，对比理解指令选择和寄存器分配策略。

### 14. opt —— LLVM优化器

**用途说明**：LLVM 的模块级优化器，可以对 LLVM IR 运行各种优化 pass，是理解和调试编译器优化的核心工具。

**常用命令示例**：

```bash
# 运行所有优化pass
opt -O2 input.ll -S -o output.ll

# 运行特定优化pass
opt -mem2reg input.ll -S -o output.ll

# 查看优化前后的IR差异
opt -instcombine input.ll -S

# 运行多个指定pass
opt -mem2reg -instcombine -gvn input.ll -S -o output.ll

# 查看所有可用pass
opt -passes=list

# 生成优化统计信息
opt -O2 -stats input.ll -S -o output.ll
```

**实际使用场景**：调试优化问题时，逐步添加优化 pass 观察每一步 IR 的变化，定位是哪个 pass 引入了问题。

### 15. FileCheck —— 测试输出验证

**用途说明**：验证编译器或工具的输出是否符合预期，使用声明式模式匹配语法，是 LLVM 测试基础设施的核心组件。

**常用命令示例**：

```bash
# 验证编译器输出
clang -S -O2 test.cpp | FileCheck test.cpp

# test.cpp中的检查指令示例
# // CHECK: movl $42, %eax
# // CHECK-NEXT: retq

# 检查特定字符串
echo "hello world 42" | FileCheck -check-prefix=TEST
# TEST: hello world [[NUM:[0-9]+]]
# TEST-SAME: {{[0-9]+}}

# 严格匹配（不允许额外输出）
FileCheck -strict-whitespace test.cpp

# 显示匹配详情
FileCheck -v test.cpp
```

**实际使用场景**：编写编译器测试用例时，在源文件中用 `// CHECK:` 注释标注期望的输出模式，`FileCheck` 自动验证编译器输出是否匹配，实现回归测试。
