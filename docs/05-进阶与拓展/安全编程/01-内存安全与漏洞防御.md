> 💡 **通俗理解 - 什么是内存安全漏洞？**

想象一下：

- **栈溢出** 就像"书包里塞了太多东西"，多出来的东西溢出到旁边的桌子上
- **堆溢出** 就像"仓库里放货超出了自己的区域"，侵占了隔壁的仓库
- **格式化字符串** 就像"填表时在名字栏写了指令"，系统把指令也执行了
- **ASLR** 就像"每次搬家换地址"，让攻击者找不到目标在哪里

C/C++的内存安全漏洞是网络安全中最危险也最常见的漏洞类型。

> 🔬 **抽象理解 - 内存安全漏洞本质**：
>
> - **越界访问**：读写超出分配范围的内存
> - **类型混淆**：将内存数据错误地解释为另一种类型
> - **生命周期错误**：访问已释放或未初始化的内存
> - **控制流劫持**：通过修改返回地址或函数指针劫持程序执行流

## 🟢 1. 栈溢出

### 1.1 栈溢出原理

```
正常栈布局：
高地址
┌──────────────────┐
│  函数参数         │
├──────────────────┤
│  返回地址 (EIP)   │  ← 攻击目标！
├──────────────────┤
│  保存的EBP        │
├──────────────────┤
│  局部变量 buf[64] │  ← 溢出起点
│  ...             │
├──────────────────┤
│  其他局部变量     │
└──────────────────┘
低地址

溢出后：
┌──────────────────┐
│  函数参数         │
├──────────────────┤
│  恶意代码地址!!!  │  ← 返回地址被覆盖
├──────────────────┤
│  AAAA (覆盖EBP)  │
├──────────────────┤
│  AAAA...AAAA     │  ← buf被溢出
│  AAAA...AAAA     │
├──────────────────┤
│  其他局部变量     │
└──────────────────┘
```

### 1.2 栈溢出示例

```cpp
// 栈溢出漏洞示例

// ❌ 经典的栈溢出漏洞
#include <cstdio>
#include <cstring>

void vulnerableFunction() {
    char buffer[64];

    // ❌ 危险：gets不检查输入长度
    gets(buffer);  // 如果输入超过64字节，将溢出到返回地址

    // ❌ 危险：strcpy不检查源字符串长度
    char input[256];
    scanf("%s", input);
    strcpy(buffer, input);  // 如果input超过64字节，溢出

    // ❌ 危险：sprintf不检查输出缓冲区大小
    char name[64];
    scanf("%s", name);
    sprintf(buffer, "Hello, %s! Welcome to our system.", name);
    // 如果name很长，buffer会溢出
}

// ✅ 安全的替代方案
void secureFunction() {
    char buffer[64];

    // ✅ 使用fgets限制输入长度
    fgets(buffer, sizeof(buffer), stdin);

    // ✅ 使用strncpy限制复制长度
    char input[256];
    scanf("%255s", input);
    strncpy(buffer, input, sizeof(buffer) - 1);
    buffer[sizeof(buffer) - 1] = '\0';

    // ✅ 使用snprintf限制输出长度
    char name[64];
    scanf("%63s", name);
    snprintf(buffer, sizeof(buffer), "Hello, %s!", name);
}

// 栈溢出攻击：覆盖返回地址
// 攻击者构造的输入：
// [64字节的填充数据] + [4字节的EBP覆盖] + [4字节的新返回地址]
// 新返回地址指向攻击者注入的shellcode

// 更复杂的攻击：ROP（Return-Oriented Programming）
// 当栈不可执行时，攻击者利用已有的代码片段（gadgets）
// 每个gadget以ret指令结尾，通过链式返回实现任意代码执行
```

### 1.3 栈溢出漏洞利用原理详解

```
栈溢出利用的完整流程：

1. 确定溢出偏移量
   ┌──────────────────────────────────────┐
   │  输入缓冲区 (用户可控)                │  ← 溢出起点
   │  ...                                 │
   │  保存的EBP (4/8字节)                 │  ← 需要覆盖
   │  返回地址 (4/8字节)                  │  ← 攻击目标
   │  函数参数                            │
   └──────────────────────────────────────┘

   偏移量 = 缓冲区大小 + 保存的EBP大小
   32位: offset = buf_size + 4
   64位: offset = buf_size + 8

2. 确定目标地址
   - shellcode在栈上的地址（需要知道栈地址）
   - libc函数地址（ret2libc）
   - ROP gadget地址

3. 构造payload
   [padding * offset] + [target_address]

   带NOP滑梯的payload：
   [NOP * 200] + [shellcode] + [padding] + [栈地址范围内的地址]

4. 利用方式分类

   ┌──────────────┬──────────────────────────────────────┐
   │ 利用方式      │ 条件与特点                            │
   ├──────────────┼──────────────────────────────────────┤
   │ ret2shellcode│ 栈可执行，需要知道栈地址               │
   │ ret2libc     │ 栈不可执行，需要知道libc基址           │
   │ ret2plt      │ 通过PLT表调用libc函数                 │
   │ ROP          │ 栈不可执行，通过gadget链实现           │
   │ ret2csu      │ 利用__libc_csu_init中的gadget         │
   │ SROP         │ 利用sigreturn系统调用                 │
   │ ret2vuln     │ 返回到另一个有漏洞的函数               │
   └──────────────┴──────────────────────────────────────┘
```

### 1.4 ROP攻击详解

```cpp
// ROP（Return-Oriented Programming）攻击详解

// ROP的核心思想：
// 1. 即使栈不可执行（NX启用），程序代码段仍是可执行的
// 2. 在已有的代码中寻找以ret结尾的短指令序列（gadget）
// 3. 将多个gadget的地址串联在栈上
// 4. 每个gadget执行完后ret到下一个gadget

// 常用gadget示例（x86-64）：
// gadget 1: pop rdi; ret        → 设置函数第一个参数
// gadget 2: pop rsi; ret        → 设置函数第二个参数
// gadget 3: pop rdx; ret        → 设置函数第三个参数
// gadget 4: pop rax; ret        → 设置系统调用号
// gadget 5: syscall; ret        → 执行系统调用

// 构造execve("/bin/sh", 0, 0)的ROP链（Linux x86-64）：
// 栈布局：
// ┌──────────────────────┐
// │ padding (64+8字节)    │
// ├──────────────────────┤
// │ pop_rax_ret 地址      │  → rax = 59 (execve系统调用号)
// │ 59                    │
// ├──────────────────────┤
// │ pop_rdi_ret 地址      │  → rdi = "/bin/sh"地址
// │ "/bin/sh" 地址        │
// ├──────────────────────┤
// │ pop_rsi_ret 地址      │  → rsi = 0 (argv)
// │ 0                     │
// ├──────────────────────┤
// │ pop_rdx_ret 地址      │  → rdx = 0 (envp)
// │ 0                     │
// ├──────────────────────┤
// │ syscall_ret 地址      │  → 执行系统调用
// └──────────────────────┘

// 自动化ROP工具
// 1. ROPgadget（Python工具）
//    pip install ROPgadget
//    ROPgadget --binary ./program --ropchain

// 2. ropper
//    pip install ropper
//    ropper --file ./program --chain "execve"

// 3. pwntools（Python漏洞利用框架）
//    from pwn import *
//    elf = ELF('./program')
//    rop = ROP(elf)
//    rop.call('system', ['/bin/sh'])
//    print(rop.dump())
```

```cpp
// CVE-2010-3333 - Microsoft Office RTF栈溢出
// 漏洞位置：RTF解析器中的pfragments属性处理
// 漏洞原理：复制pfragments数据时未验证长度

// 漏洞伪代码（简化）：
void parseRTFProperty(RTFStream* stream) {
    // 读取属性数据
    uint16_t cb = stream->readWord();  // 数据长度（攻击者可控）

    char buffer[256];  // 固定大小缓冲区

    // ❌ 漏洞：未检查cb是否超过buffer大小
    stream->readBytes(buffer, cb);  // 如果cb > 256，栈溢出！

    processProperty(buffer, cb);
}

// 修复：添加长度检查
void parseRTFPropertyFixed(RTFStream* stream) {
    uint16_t cb = stream->readWord();

    // ✅ 验证长度不超过缓冲区大小
    if (cb > 256) {
        logError("RTF属性数据过长");
        return;
    }

    char buffer[256];
    stream->readBytes(buffer, cb);
    processProperty(buffer, cb);
}

// 利用方式：
// 1. 构造恶意RTF文件，设置pfragments长度超过256
// 2. 在溢出数据中放置shellcode或ROP链
// 3. 覆盖返回地址，劫持控制流
// 4. 实现远程代码执行（打开文档即中招）

// 教训：
// - 解析文件格式时必须验证所有长度字段
// - 使用安全函数（如memcpy_s）替代不安全函数
// - 启用编译器安全选项（/GS在MSVC中）
```

## 🟡 2. 堆溢出

### 2.1 堆溢出原理

```
堆内存布局：

┌──────────────────┐
│  Chunk A 头部     │  ← malloc元数据
│  Chunk A 数据     │  ← 用户数据区域
├──────────────────┤
│  Chunk B 头部     │  ← malloc元数据（攻击目标！）
│  Chunk B 数据     │
├──────────────────┤
│  空闲链表         │
└──────────────────┘

堆溢出：向Chunk A写入超过其大小的数据，
覆盖Chunk B的头部（malloc元数据），
导致后续malloc/free操作时执行任意代码。
```

### 2.2 堆溢出示例

```cpp
// 堆溢出漏洞示例

// ❌ 堆溢出漏洞
void heapOverflowVuln() {
    char* bufferA = (char*)malloc(32);
    char* bufferB = (char*)malloc(32);

    // ❌ 向bufferA写入超过32字节的数据
    // 溢出的数据覆盖bufferB的堆元数据
    strcpy(bufferA, longUserInput);  // 如果输入>32字节，溢出到bufferB的头部

    // 被篡改的元数据可能导致任意代码执行
    free(bufferB);

void secureHeapOps() {
    // 使用C++智能指针
    auto bufferA = std::make_unique<char[]>(32);
    auto bufferB = std::make_unique<char[]>(32);

    // 使用安全函数限制写入长度
    strncpy(bufferA.get(), userInput, 31);
    bufferA[31] = '\0';

    // 智能指针自动释放，无需手动free
}

// Use-After-Free漏洞
void useAfterFreeVuln() {
    int* ptr = new int(42);
    delete ptr;

    // ❌ 使用已释放的内存
    printf("值: %d\n", *ptr);  // 未定义行为

    // 攻击者可能在ptr被释放后重新分配该内存
    // 然后通过ptr修改新分配的数据
}

// ✅ 安全的替代
void noUseAfterFree() {
    auto ptr = std::make_unique<int>(42);
    printf("值: %d\n", *ptr);
    // 自动释放，ptr变为nullptr

    // 如果需要手动管理
    int* raw = new int(42);
    delete raw;
    raw = nullptr;  // 立即置空，防止UAF

    // 使用raw前检查
    if (raw != nullptr) {
        printf("值: %d\n", *raw);
    }
}

// Double Free漏洞
void doubleFreeVuln() {
    char* ptr = (char*)malloc(100);
    free(ptr);
    // ❌ 重复释放
    free(ptr);  // 未定义行为！可能导致任意代码执行

    // 攻击者利用double free可以：
    // 1. 将同一块内存放入空闲链表两次
    // 2. 后续两次malloc返回同一地址
    // 3. 两个指针指向同一内存，造成数据混淆
}

// ✅ 安全的替代
void noDoubleFree() {
    auto ptr = std::make_unique<char[]>(100);
    // 自动释放，不会double free
}
```

### 2.3 堆漏洞利用技术

```cpp
// 常见堆漏洞利用技术（了解攻击原理有助于防御）

// 1. Unlink攻击（glibc < 2.26）
// 利用free()时的unlink操作，将恶意指针写入任意位置
// 已被glibc 2.26+的tcache机制缓解

// 2. Fastbin Dup（快速桶重复分配）
// 通过double free将同一chunk放入fastbin两次
// 后续两次malloc返回同一地址

// 3. Tcache Poisoning（glibc 2.26+）
// 篡改tcache链表的next指针，使malloc返回任意地址

// 4. House of Force
// 通过溢出修改top chunk的大小字段
// 使后续malloc返回任意地址

// 5. House of Orange
// 不需要free操作的堆利用技术
// 通过修改top chunk触发sysmalloc获取任意写

// 防御策略：
// - 使用安全的内存分配器（如jemalloc, tcmalloc）
// - 启用堆保护机制（heap canary）
// - 使用C++智能指针避免手动内存管理
// - 使用AddressSanitizer检测堆漏洞
```

### 2.4 glibc堆管理器深入分析

```
glibc ptmalloc2堆管理器核心数据结构：

1. malloc_chunk结构（已分配）
┌──────────────────────────────────────┐
│ prev_size (8字节)                     │  ← 仅当上一chunk空闲时有效
│ size (8字节)                          │  ← 包含3个标志位: A|M|P
│   P (PREV_INUSE): 上一chunk是否在使用  │
│   M (IS_MMAPPED): 是否通过mmap分配     │
│   A (NON_MAIN_ARENA): 是否属于非主线程 │
│ user data                             │  ← 返回给用户的指针
│ ...                                   │
└──────────────────────────────────────┘

2. malloc_chunk结构（空闲）
┌──────────────────────────────────────┐
│ prev_size                            │
│ size                                 │
│ fd (forward pointer)                 │  ← 指向同bin中下一个空闲chunk
│ bk (backward pointer)                │  ← 指向同bin中上一个空闲chunk
│ fd_nextsize (仅large bin)            │
│ bk_nextsize (仅large bin)            │
└──────────────────────────────────────┘

3. Bin分类
┌──────────────┬──────────────────────────────────────┐
│ Bin类型       │ 说明                                  │
├──────────────┼──────────────────────────────────────┤
│ Fastbins     │ 单链表，LIFO，大小16-128字节(x64)      │
│              │ 不合并，快速分配/释放                   │
├──────────────┼──────────────────────────────────────┤
│ Unsorted bin │ 双链表，刚释放的chunk先放入此处         │
│              │ 下次malloc时整理到对应bin               │
├──────────────┼──────────────────────────────────────┤
│ Small bins   │ 62个双链表，大小16-1024字节(x64)       │
│              │ FIFO，相邻空闲chunk会合并               │
├──────────────┼──────────────────────────────────────┤
│ Large bins   │ 63个双链表，大小>=1024字节(x64)        │
│              │ 按大小排序，包含fd_nextsize/bk_nextsize│
├──────────────┼──────────────────────────────────────┤
│ Tcache       │ (glibc 2.26+) 每线程缓存，64个bin     │
│              │ 单链表，LIFO，默认每bin最多7个chunk     │
│              │ 安全检查最少，是最容易被利用的bin        │
└──────────────┴──────────────────────────────────────┘

4. malloc分配流程
   1) 检查tcache（如果有）
   2) 检查fastbin
   3) 检查smallbin
   4) 整理unsorted bin → 放入smallbin/largebin
   5) 检查largebin
   6) 使用top chunk
   7) 调用sysmalloc向OS申请新内存

5. free释放流程
   1) 检查tcache，如果对应bin未满则放入tcache
   2) 检查是否与相邻chunk合并
   3) 放入unsorted bin（或fastbin/tcache）
```

```cpp
// 原理：篡改tcache链表的fd指针，使malloc返回任意地址

// tcache_entry {

// 步骤2：攻击流程
// 1. 分配chunk A, chunk B（大小相同，属于同一tcache bin）
// 2. 释放chunk B → tcache: B → NULL
// 3. 释放chunk A → tcache: A → B → NULL
// 4. 溢出chunk A，修改A的fd指针为目标地址target
//    tcache: A → target → ???
// 5. malloc() 返回 A
// 6. malloc() 返回 target（任意地址分配！）

// 代码演示（概念性，需要配合溢出漏洞）
void tcachePoisoningDemo() {
    // 假设我们有堆溢出漏洞可以修改tcache的fd指针

    void* a = malloc(0x20);
    void* b = malloc(0x20);
    void* target = (void*)0xdeadbeef;  // 我们想控制的地址

    free(a);  // tcache: a -> b -> NULL

    // ❌ 假设通过堆溢出修改a的fd指针
    // *(void**)a = target;

}

// tcache引入了safe-linking机制：
```

```python
    p.sendline(payload)

def write_value(addr, value, offset):
    """向指定地址写入值"""
    # %n写入已输出的字符数
    # 需要精确控制输出字符数

    # 分解value为多个字节写入
    # 例如写入0x0804abcd到addr
    # 分为两次写入：0xabcd到addr+0, 0x0804到addr+2

    writes = []
    for i in range(4):
        byte_val = (value >> (i * 8)) & 0xFF
        if byte_val > 0:
            writes.append((addr + i, byte_val))

    # 按值从小到大排序（%n只能增加计数器）
    writes.sort(key=lambda x: x[1])

    # 构造payload
    payload = b""
    written = 0
    format_parts = []

    for target_addr, byte_val in writes:
        # 放置目标地址
        payload += p32(target_addr)
        # 计算需要输出的字符数
        pad = byte_val - written
        if pad > 0:
            format_parts.append(f"%{pad}c")
            written = byte_val
        # %n写入
        format_parts.append(f"%{offset}$n")

    # 将格式化部分放在地址后面
    # 需要确保对齐
    format_str = "".join(format_parts).encode()
    padding = (4 - len(format_str) % 4) % 4
    format_str += b" " * padding

    full_payload = format_str + payload
    p.sendline(full_payload)

    system_addr = libc.symbols['system']

    # 3. 写入新地址
```

## 🟢 4. 现代防御机制

### 4.1 ASLR（地址空间布局随机化）

```
ASLR：每次运行时随机化内存布局

无ASLR：
0x08048000  代码段（固定地址）
0x08049000  数据段（固定地址）
0xbffff000  栈（固定地址）

有ASLR：
0x5623a000  代码段（随机地址）
0x5623b000  数据段（随机地址）
0x7ffd8a00  栈（随机地址）

ASLR随机化的区域：
- 栈位置
- 堆位置
- 共享库加载位置
- mmap区域

ASLR的限制：
- 代码段位置通常不随机化（需要PIE）
- 32位地址空间有限，暴力破解可行
- 信息泄露可以绕过ASLR
```


### 4.2 DEP/NX（数据执行保护）

```
DEP/NX：将数据区域标记为不可执行

无NX：
┌──────────┐
│  代码段   │ 可读可执行
│  栈       │ 可读可写可执行  ← 可以执行栈上的shellcode
│  堆       │ 可读可写可执行  ← 可以执行堆上的shellcode
└──────────┘

有NX：
┌──────────┐
│  代码段   │ 可读可执行
│  栈       │ 可读可写（不可执行）  ← shellcode无法执行
│  堆       │ 可读可写（不可执行）  ← shellcode无法执行
└──────────┘

绕过NX的方法：
- ROP（Return-Oriented Programming）
- Ret2libc（返回到libc函数）
- JIT喷射（利用JIT编译器生成可执行代码）
```

```cpp
void safeSpanAccess(std::span<int> arr, size_t index) {
    if (index >= arr.size()) {

class SafeString {

        return str.substr(pos, len);

    static bool safeCopy(char* dst, size_t dstSize, const std::string& src) {
```

### 5.2 智能指针避免内存漏洞

```cpp
// 使用智能指针避免内存安全漏洞

// ❌ 裸指针的问题
class RawPointerExample {
public:
    void dangerous() {
        // 内存泄漏
        int* p1 = new int(42);
        if (errorCondition()) return;  // 忘记delete

        // Double free
        int* p2 = new int(42);
        delete p2;
        delete p2;  // 重复释放

        // Use-after-free
        int* p3 = new int(42);
        delete p3;
        int val = *p3;  // 使用已释放内存

        // 悬空指针
        int* p4 = createObject();
        destroyObject(p4);
        p4->doSomething();  // 悬空指针
    }

private:
    bool errorCondition();
    int* createObject();
    void destroyObject(int*);
};

// ✅ 智能指针解决方案
class SmartPointerExample {
public:
    void safe() {
        // unique_ptr：独占所有权，自动释放
        auto p1 = std::make_unique<int>(42);
        if (errorCondition()) return;  // 自动释放，无泄漏

        // 不会double free
        auto p2 = std::make_unique<int>(42);
        // p2只能移动，不能复制
        auto p3 = std::move(p2);
        // p2现在是nullptr

        // 不会use-after-free
        auto p4 = std::make_unique<int>(42);
        // p4释放后自动变为nullptr（通过移动语义）

        // shared_ptr：共享所有权
        auto shared1 = std::make_shared<int>(42);
        auto shared2 = shared1;  // 引用计数+1
        // 当所有shared_ptr销毁时自动释放
    }

    // ✅ 使用weak_ptr避免循环引用
    class Node {
    public:
        std::shared_ptr<Node> next;
        std::weak_ptr<Node> prev;  // 弱引用，不增加引用计数
    };

private:
    bool errorCondition();
};
```

```cpp
        int sum = 0;
        for (int val : data) {
            sum += val;
        }

    }
```

```cpp
class SafeStringProcessing {

    }

        if (!cstr) return "";
        size_t len = strnlen(cstr, maxLen);
        return std::string(cstr, len);
    }

        for (char c : username) {
            if (!((c >= 'a' && c <= 'z') ||
                  (c >= 'A' && c <= 'Z') ||
                  (c >= '0' && c <= '9') ||
                  c == '_')) {
                return false;
            }
        }
        return true;
    }
```

### 7.2 安全的数值处理

```cpp
// 安全的数值处理模式

#include <limits>
#include <stdexcept>

class SafeNumeric {
public:
    // ✅ 安全的整数加法（检测溢出）
    template<typename T>
    static T safeAdd(T a, T b) {
        if constexpr (std::is_signed_v<T>) {
            if (b > 0 && a > std::numeric_limits<T>::max() - b) {
                throw std::overflow_error("整数加法溢出");
            }
            if (b < 0 && a < std::numeric_limits<T>::min() - b) {
                throw std::overflow_error("整数加法下溢");
            }
        } else {
            if (a > std::numeric_limits<T>::max() - b) {
                throw std::overflow_error("无符号整数加法溢出");
            }
        }
        return a + b;
    }

    // ✅ 安全的整数乘法（检测溢出）
    template<typename T>
    static T safeMul(T a, T b) {
        if (a == 0 || b == 0) return 0;

        if constexpr (std::is_signed_v<T>) {
            if (a > std::numeric_limits<T>::max() / b ||
                a < std::numeric_limits<T>::min() / b) {
                throw std::overflow_error("整数乘法溢出");
            }
        } else {
            if (a > std::numeric_limits<T>::max() / b) {
                throw std::overflow_error("无符号整数乘法溢出");
            }
        }
        return a * b;
    }

    // ✅ 安全的类型转换
    template<typename Dest, typename Source>
    static Dest safeCast(Source value) {
        if constexpr (!std::is_same_v<Dest, Source>) {
            if constexpr (std::is_integral_v<Dest> && std::is_integral_v<Source>) {
                if constexpr (sizeof(Dest) < sizeof(Source) ||
                             (sizeof(Dest) == sizeof(Source) &&
                              std::is_signed_v<Dest> != std::is_signed_v<Source>)) {
                    if (static_cast<Source>(static_cast<Dest>(value)) != value) {
                        throw std::overflow_error("类型转换溢出");
                    }
                }
            }
        }
        return static_cast<Dest>(value);
    }

    // ✅ 安全的大小计算（用于内存分配）
    static size_t safeSizeForAlloc(size_t count, size_t elementSize) {
        if (count == 0 || elementSize == 0) return 0;
        if (count > std::numeric_limits<size_t>::max() / elementSize) {
            throw std::overflow_error("分配大小溢出");
        }
        return count * elementSize;
    }
};
```
