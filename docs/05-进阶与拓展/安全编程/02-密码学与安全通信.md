> 💡 **通俗理解 - 什么是密码学？**

想象一下：

- **对称加密** 就像"同一把钥匙开锁和上锁"——你和朋友各持一把相同的钥匙
- **非对称加密** 就像"信箱"——任何人可以投信（公钥加密），只有你有钥匙取信（私钥解密）
- **哈希函数** 就像"指纹"——给任意数据生成唯一标识，不可逆推
- **数字证书** 就像"身份证"——由权威机构签发，证明"你就是你说的那个人"

> 🔬 **抽象理解 - 密码学的本质**：
>
> - **机密性**：只有授权方可以读取信息
> - **完整性**：信息在传输中未被篡改
> - **认证性**：确认通信双方的身份
> - **不可否认性**：发送方无法否认已发送的信息

## 🟢 1. 密码学基础概念

### 1.1 对称加密

```
对称加密流程：

发送方                          接收方
┌──────────┐    密文           ┌──────────┐
│ 明文      │───加密算法───→    │ 密文      │
│ + 密钥K   │    + 密钥K       │ + 密钥K   │
└──────────┘                   └──────────┘
                                   │
                               解密算法
                               + 密钥K
                                   │
                                   ▼
                              ┌──────────┐
                              │ 明文      │
                              └──────────┘

特点：
- 加密和解密使用同一把密钥
- 速度快，适合大量数据加密
- 密钥分发是核心难题
```

### 1.2 非对称加密

```
非对称加密流程：

发送方                            接收方
┌──────────┐     密文            ┌──────────┐
│ 明文      │───加密算法───→     │ 密文      │
│ + 公钥    │    + 公钥          │ + 私钥    │
└──────────┘                    └──────────┘
                                    │
                                解密算法
                                + 私钥
                                    │
                                    ▼
                               ┌──────────┐
                               │ 明文      │
                               └──────────┘

特点：
- 公钥加密，私钥解密（加密场景）
- 私钥签名，公钥验证（签名场景）
- 解决了密钥分发问题
- 速度慢，通常用于交换对称密钥
```

### 1.3 哈希函数

```
哈希函数特性：

输入（任意长度）        输出（固定长度）
┌──────────────┐      ┌──────────┐
│ "Hello"      │──→   │ 185f8db..│  (SHA-256)
│ "Hello!"     │──→   │ 334d0a95│  (完全不同！)
│ 1GB文件      │──→   │ 7a3c2f..│  (同样64字符)
└──────────────┘      └──────────┘

核心特性：
1. 单向性：无法从哈希值反推原始数据
2. 抗碰撞性：找不到两个不同输入产生相同哈希
3. 雪崩效应：输入微小变化，输出完全不同
4. 固定长度：无论输入多大，输出长度固定
```

## 🟡 2. 常见加密算法

### 2.1 AES（高级加密标准）

```cpp
// AES核心参数
// AES-128: 128位密钥, 10轮加密
// AES-192: 192位密钥, 12轮加密
// AES-256: 256位密钥, 14轮加密

// AES加密模式对比：
// ┌──────────────┬──────────────────────────────────────┐
// │ 模式          │ 特点                                  │
// ├──────────────┼──────────────────────────────────────┤
// │ ECB          │ 相同明文→相同密文，不安全              │
// │ CBC          │ 需要IV，串行加密                       │
// │ CTR          │ 可并行，需要nonce+计数器               │
// │ GCM          │ 认证加密（加密+完整性），推荐          │
// │ CFB          │ 流密码模式，需要IV                     │
// │ OFB          │ 流密码模式，错误不传播                  │
// └──────────────┴──────────────────────────────────────┘

// ❌ ECB模式的问题：相同明文块产生相同密文块
// 著名的"ECB企鹅"——用ECB加密图像后仍能看到轮廓

// ✅ 推荐使用GCM模式：同时提供加密和认证
```

### 2.2 RSA（非对称加密）

```cpp
// RSA原理简述：
// 1. 选择两个大素数 p, q
// 2. 计算 n = p * q（模数）
// 3. 计算 φ(n) = (p-1)(q-1)（欧拉函数）
// 4. 选择 e，满足 1 < e < φ(n)，gcd(e, φ(n)) = 1（公钥指数）
// 5. 计算 d，满足 e * d ≡ 1 (mod φ(n))（私钥指数）
// 6. 公钥 = (e, n)，私钥 = (d, n)

// 加密：ciphertext = plaintext^e mod n
// 解密：plaintext = ciphertext^d mod n

// RSA密钥长度要求：
// ┌──────────────┬──────────────────────────────────────┐
// │ 密钥长度      │ 安全性评估                            │
// ├──────────────┼──────────────────────────────────────┤
// │ 1024位       │ 已不安全，可被破解                     │
// │ 2048位       │ 当前最低要求                           │
// │ 3072位       │ 推荐使用                               │
// │ 4096位       │ 高安全需求                             │
// └──────────────┴──────────────────────────────────────┘

// RSA的限制：
// - 加密速度慢，不适合大数据量
// - 明文长度不能超过密钥长度
// - 实际使用中RSA用于交换对称密钥，而非直接加密数据
```

### 2.3 SHA（安全哈希算法）

```cpp
// SHA家族对比：
// ┌──────────────┬──────────┬──────────┬──────────────────┐
// │ 算法          │ 输出长度  │ 状态     │ 说明              │
// ├──────────────┼──────────┼──────────┼──────────────────┤
// │ SHA-1        │ 160位    │ 已破解   │ 不再使用          │
// │ SHA-256      │ 256位    │ 安全     │ 最广泛使用        │
// │ SHA-384      │ 384位    │ 安全     │ SHA-512截断       │
// │ SHA-512      │ 512位    │ 安全     │ 64位平台更快      │
// │ SHA-3-256    │ 256位    │ 安全     │ 不同内部结构      │
// │ MD5          │ 128位    │ 已破解   │ 绝对不要使用      │
// └──────────────┴──────────┴──────────┴──────────────────┘

// HMAC：基于哈希的消息认证码
// HMAC-SHA256(key, message) = SHA256(key ⊕ opad || SHA256(key ⊕ ipad || message))
// 同时验证消息完整性和真实性
```

## 🟡 3. SSL/TLS协议原理

### 3.1 TLS握手流程

```
TLS 1.2握手流程：

客户端                              服务器
  │                                   │
  │──── ClientHello ─────────────────→│  支持的TLS版本、密码套件、随机数
  │                                   │
  │←── ServerHello ──────────────────│  选定的TLS版本、密码套件、随机数
  │←── Certificate ──────────────────│  服务器证书链
  │←── ServerKeyExchange ────────────│  DH参数（如使用DHE/ECDHE）
  │←── ServerHelloDone ──────────────│
  │                                   │
  │──── ClientKeyExchange ──────────→│  预主密钥（RSA）或DH公钥
  │──── ChangeCipherSpec ───────────→│  切换到加密通信
  │──── Finished ───────────────────→│  验证握手完整性
  │                                   │
  │←── ChangeCipherSpec ─────────────│  切换到加密通信
  │←── Finished ─────────────────────│  验证握手完整性
  │                                   │
  │════════ 加密数据传输 ═════════════│
```

### 3.2 TLS 1.3改进

```
TLS 1.3握手流程（1-RTT）：

客户端                              服务器
  │                                   │
  │──── ClientHello ─────────────────→│  + 密钥共享（提前发送DH公钥）
  │                                   │
  │←── ServerHello ──────────────────│  + 密钥共享
  │←── ChangeCipherSpec ─────────────│
  │←── EncryptedExtensions ──────────│  （已加密！）
  │←── Certificate ──────────────────│  （已加密！）
  │←── CertificateVerify ────────────│  （已加密！）
  │←── Finished ─────────────────────│  （已加密！）
  │                                   │
  │──── ChangeCipherSpec ───────────→│
  │──── Finished ───────────────────→│  （已加密！）
  │                                   │
  │════════ 加密数据传输 ═════════════│

TLS 1.3关键改进：
1. 握手从2-RTT减少到1-RTT
2. 0-RTT恢复（对已知服务器）
3. 移除了不安全的密码套件
4. 握手大部分内容已加密
5. 强制前向保密（PFS）
```

### 3.3 密码套件

```
密码套件命名规则：
TLS_AES_256_GCM_SHA384
 │    │     │    │
 │    │     │    └── PRF/哈希算法
 │    │     └────── 加密模式
 │    └──────────── 加密算法
 └───────────────── 协议

TLS 1.3支持的密码套件（仅5个）：
- TLS_AES_256_GCM_SHA384
- TLS_CHACHA20_POLY1305_SHA256
- TLS_AES_128_GCM_SHA256
- TLS_AES_128_CCM_8_SHA256
- TLS_AES_128_CCM_SHA256

TLS 1.2推荐密码套件：
- TLS_ECDHE_RSA_WITH_AES_256_GCM_SHA384
- TLS_ECDHE_RSA_WITH_AES_128_GCM_SHA256
- TLS_ECDHE_RSA_WITH_CHACHA20_POLY1305

不安全的密码套件（应禁用）：
- TLS_RSA_WITH_RC4_128_SHA      （RC4已破解）
- TLS_RSA_WITH_3DES_EDE_CBC_SHA  （3DES过时）
- TLS_RSA_WITH_AES_128_CBC_SHA   （无前向保密）
- 所有包含NULL加密的套件
- 所有包含EXPORT的套件
```

```
X.509证书包含：

┌──────────────────────────────────────┐

终端证书 → 中间CA证书 → 根CA证书
  │            │              │
  └──被签名──→ └──被签名──→  └──自签名（信任锚）
```

```
PKI (Public Key Infrastructure) 公钥基础设施：

┌──────────────────────────────────────────────┐
│                  根CA                         │
│            （离线保存，最高信任）               │
│               │                              │
│      ┌────────┴────────┐                     │

证书吊销检查方式：
1. CRL (证书吊销列表) - 定期下载，可能有延迟

3. OCSP Stapling - 服务器缓存OCSP响应
```

## 🟡 5. C/C++加密库使用

### 5.1 OpenSSL基础操作

```cpp
// OpenSSL编译: gcc -o program program.cpp -lssl -lcrypto

#include <openssl/evp.h>
#include <openssl/rand.h>
#include <openssl/err.h>
#include <openssl/sha.h>
#include <openssl/rsa.h>
#include <openssl/pem.h>
#include <iostream>
#include <vector>
#include <string>

// ============================================
// AES-256-GCM 加密/解密（推荐模式）
// ============================================

struct AesGcmResult {
    std::vector<unsigned char> ciphertext;
    std::vector<unsigned char> iv;        // 12字节初始化向量
    std::vector<unsigned char> tag;       // 16字节认证标签
};

// AES-256-GCM加密
AesGcmResult aes256gcm_encrypt(const std::string& plaintext,
                                const std::vector<unsigned char>& key) {
    AesGcmResult result;

    // 生成随机IV（12字节）
    result.iv.resize(12);
    RAND_bytes(result.iv.data(), 12);

    result.ciphertext.resize(plaintext.size());
    result.tag.resize(16);

    EVP_CIPHER_CTX* ctx = EVP_CIPHER_CTX_new();

    // 初始化加密
    EVP_EncryptInit_ex(ctx, EVP_aes_256_gcm(), nullptr, nullptr, nullptr);

    // 设置IV长度
    EVP_CIPHER_CTX_ctrl(ctx, EVP_CTRL_GCM_SET_IVLEN, 12, nullptr);

    // 设置密钥和IV
    EVP_EncryptInit_ex(ctx, nullptr, nullptr, key.data(), result.iv.data());

    // 加密
    int outlen;
    EVP_EncryptUpdate(ctx, result.ciphertext.data(), &outlen,
                      reinterpret_cast<const unsigned char*>(plaintext.data()),
                      plaintext.size());

    // 完成加密
    EVP_EncryptFinal_ex(ctx, result.ciphertext.data() + outlen, &outlen);

    // 获取认证标签
    EVP_CIPHER_CTX_ctrl(ctx, EVP_CTRL_GCM_GET_TAG, 16, result.tag.data());

    EVP_CIPHER_CTX_free(ctx);
    return result;
}

// AES-256-GCM解密
bool aes256gcm_decrypt(const AesGcmResult& encrypted,
                       const std::vector<unsigned char>& key,
                       std::string& plaintext) {
    EVP_CIPHER_CTX* ctx = EVP_CIPHER_CTX_new();

    EVP_DecryptInit_ex(ctx, EVP_aes_256_gcm(), nullptr, nullptr, nullptr);
    EVP_CIPHER_CTX_ctrl(ctx, EVP_CTRL_GCM_SET_IVLEN, 12, nullptr);
    EVP_DecryptInit_ex(ctx, nullptr, nullptr, key.data(), encrypted.iv.data());

    // 解密
    std::vector<unsigned char> buf(encrypted.ciphertext.size());
    int outlen;
    EVP_DecryptUpdate(ctx, buf.data(), &outlen,
                      encrypted.ciphertext.data(),
                      encrypted.ciphertext.size());

    // 设置认证标签
    EVP_CIPHER_CTX_ctrl(ctx, EVP_CTRL_GCM_SET_TAG, 16,
                        const_cast<unsigned char*>(encrypted.tag.data()));

    // 验证标签并完成解密
    int ret = EVP_DecryptFinal_ex(ctx, buf.data() + outlen, &outlen);

    EVP_CIPHER_CTX_free(ctx);

    if (ret > 0) {
        plaintext.assign(buf.begin(), buf.end());
        return true;
    }
    return false;  // 认证失败，数据被篡改
}
```

### 5.2 SHA-256哈希

```cpp
// SHA-256哈希计算
std::vector<unsigned char> sha256(const std::string& input) {
    std::vector<unsigned char> hash(SHA256_DIGEST_LENGTH);
    SHA256(reinterpret_cast<const unsigned char*>(input.data()),
           input.size(), hash.data());
    return hash;
}

// 使用EVP接口（更通用）
std::vector<unsigned char> compute_hash(const std::string& input,
                                         const EVP_MD* md) {
    unsigned int hash_len;
    std::vector<unsigned char> hash(EVP_MAX_MD_SIZE);

    EVP_MD_CTX* ctx = EVP_MD_CTX_new();
    EVP_DigestInit_ex(ctx, md, nullptr);
    EVP_DigestUpdate(ctx, input.data(), input.size());
    EVP_DigestFinal_ex(ctx, hash.data(), &hash_len);
    EVP_MD_CTX_free(ctx);

    hash.resize(hash_len);
    return hash;
}

// 使用示例
void hash_examples() {
    auto sha256_hash = compute_hash("Hello, World!", EVP_sha256());
    auto sha512_hash = compute_hash("Hello, World!", EVP_sha512());
    auto sha3_hash   = compute_hash("Hello, World!", EVP_sha3_256());
}
```

### 5.3 RSA签名与验证

```cpp
// RSA签名
std::vector<unsigned char> rsa_sign(const std::string& message,
                                     EVP_PKEY* private_key) {
    EVP_MD_CTX* ctx = EVP_MD_CTX_new();
    EVP_SignInit_ex(ctx, EVP_sha256(), nullptr);
    EVP_SignUpdate(ctx, message.data(), message.size());

    unsigned int sig_len;
    std::vector<unsigned char> signature(EVP_PKEY_size(private_key));
    EVP_SignFinal(ctx, signature.data(), &sig_len, private_key);
    EVP_MD_CTX_free(ctx);

    signature.resize(sig_len);
    return signature;
}

// RSA验证
bool rsa_verify(const std::string& message,
                const std::vector<unsigned char>& signature,
                EVP_PKEY* public_key) {
    EVP_MD_CTX* ctx = EVP_MD_CTX_new();
    EVP_VerifyInit_ex(ctx, EVP_sha256(), nullptr);
    EVP_VerifyUpdate(ctx, message.data(), message.size());

    int result = EVP_VerifyFinal(ctx, signature.data(),
                                 signature.size(), public_key);
    EVP_MD_CTX_free(ctx);

    return result == 1;
}
```

## 🟢 6. 安全通信最佳实践

### 6.1 密钥管理

```cpp
// 密钥管理最佳实践

class KeyManager {
public:
    // ✅ 从安全来源获取密钥
    static std::vector<unsigned char> deriveKey(
        const std::string& password,
        const std::vector<unsigned char>& salt,
        int iterations = 600000)  // OWASP推荐迭代次数
    {
        std::vector<unsigned char> key(32);  // 256位密钥

        // PBKDF2密钥派生
        PKCS5_PBKDF2_HMAC(password.data(), password.size(),
                          salt.data(), salt.size(),
                          iterations, EVP_sha256(),
                          key.size(), key.data());
        return key;
    }

    // ✅ 安全地清除密钥内存
    static void secureWipe(unsigned char* data, size_t len) {
        OPENSSL_cleanse(data, len);
    }

    // ❌ 不安全：直接memset可能被编译器优化掉
    // memset(key, 0, key_len);  // 编译器可能删除此调用
};

// 密钥存储建议：
// 1. 永远不要硬编码密钥在源代码中
// 2. 使用密钥管理服务（KMS、Vault）
// 3. 密钥使用后立即安全清除
// 4. 不同用途使用不同密钥
```

### 6.2 TLS配置最佳实践

```cpp
// TLS服务器配置最佳实践

#include <openssl/ssl.h>

SSL_CTX* create_secure_server_ctx() {
    SSL_CTX* ctx = SSL_CTX_new(TLS_server_method());

    // ✅ 最低TLS 1.2
    SSL_CTX_set_min_proto_version(ctx, TLS1_2_VERSION);

    // ✅ 设置证书和私钥
    SSL_CTX_use_certificate_file(ctx, "server.crt", SSL_FILETYPE_PEM);
    SSL_CTX_use_PrivateKey_file(ctx, "server.key", SSL_FILETYPE_PEM);

    // ✅ 设置密码套件（优先ECDHE实现前向保密）
    SSL_CTX_set_cipher_list(ctx,
        "ECDHE-ECDSA-AES256-GCM-SHA384:"
        "ECDHE-RSA-AES256-GCM-SHA384:"
        "ECDHE-ECDSA-CHACHA20-POLY1305:"
        "ECDHE-RSA-CHACHA20-POLY1305:"
        "ECDHE-ECDSA-AES128-GCM-SHA256:"
        "ECDHE-RSA-AES128-GCM-SHA256");

    // ✅ 服务器密码套件偏好
    SSL_CTX_set_options(ctx, SSL_OP_CIPHER_SERVER_PREFERENCE);

    // ✅ 启用OCSP Stapling
    SSL_CTX_set_tlsext_status_type(ctx, TLSEXT_STATUSTYPE_ocsp);

    return ctx;
}
```

### 7.1 不要自己实现加密算法

### 7.4 时序攻击

```cpp
// ❌ 危险：字符串比较可能泄露信息
bool insecure_compare(const std::string& a, const std::string& b) {
    if (a.size() != b.size()) return false;  // 长度不同立即返回
    for (size_t i = 0; i < a.size(); ++i) {
        if (a[i] != b[i]) return false;  // 第一个不同字符立即返回
        // 攻击者通过测量响应时间逐字符猜测
    }
    return true;
}

// ✅ 安全：恒定时间比较
bool secure_compare(const std::vector<unsigned char>& a,
                    const std::vector<unsigned char>& b) {
    if (a.size() != b.size()) return false;
    // CRYPTO_memcmp是恒定时间的
    return CRYPTO_memcmp(a.data(), b.data(), a.size()) == 0;
}

// ✅ HMAC验证必须使用恒定时间比较
bool verify_hmac(const std::vector<unsigned char>& expected,
                 const std::vector<unsigned char>& actual) {
    return CRYPTO_memcmp(expected.data(), actual.data(),
                         expected.size()) == 0;
}
```

## 🟢 8. 本章小结

| 主题 | 核心要点 |
|------|---------|
| 对称加密 | AES-256-GCM/ChaCha20-Poly1305，避免ECB模式 |
| 非对称加密 | RSA-3072+/Ed25519，用于密钥交换和签名 |
| 哈希函数 | SHA-256/SHA-3，避免MD5/SHA-1 |
| SSL/TLS | TLS 1.3优先，禁用不安全密码套件 |
| 数字证书 | X.509证书链验证，OCSP吊销检查 |
| OpenSSL | EVP接口，AES-GCM加密，安全随机数 |
| 安全陷阱 | 不要自造加密、注意IV重用、恒定时间比较 |

**关键理解**：

1. **不要自己实现加密算法**：使用经过充分审查的库（OpenSSL、libsodium）
2. **优先使用AEAD模式**：GCM或ChaCha20-Poly1305，同时提供加密和认证
3. **密钥管理比算法选择更重要**：再好的算法，密钥泄露也白搭
4. **TLS 1.3是当前最佳实践**：更快的握手、更强的安全性
5. **警惕时序攻击**：比较密钥/HMAC时使用恒定时间函数
6. **算法会过时**：定期评估使用的算法是否仍然安全
7. **安全是系统问题**：密码学只是安全的一部分，实现错误同样致命
