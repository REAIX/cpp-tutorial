# 编译期反射与代码生成

> 在编译期获取类型信息，自动生成重复代码

***

> **Reflection is the ability of a program to examine and modify its own structure and behavior.**
> （反射是程序检查和修改自身结构与行为的能力。）

> **The best code is the code you don't have to write.**
> （最好的代码是你不需要写的代码。）

---

> **🎯 让编译器替你写代码。**
>
> （编译期反射让我们在编译时获取类型信息，结合代码生成技术，可以自动实现序列化、比较、遍历等重复性工作。）

> 💡 **通俗理解 - 什么是编译期反射？**

想象一下：

- **反射** 就像"照镜子"——程序在运行时看到自己的结构
- **编译期反射** 就像"设计图审查"——在施工前就了解建筑结构
- **代码生成** 就像"3D打印"——根据设计图自动生成实体
- **手动反射** 就像"手绘设计图"——用宏和模板手动描述结构

> 🔬 **抽象理解 - 编译期反射的本质**：
>
> - **类型内省**：在编译期获取类型的成员、方法、基类等信息
> - **自动遍历**：遍历类型的所有成员，执行统一操作
> - **代码生成**：根据类型信息自动生成序列化、比较等代码
> - **零运行时开销**：所有信息在编译期确定，运行时无额外成本

## 🟢 1. 什么是编译期反射

### 1.1 反射的概念

```
反射的分类：

┌──────────────┬──────────────────────────────────────┐
│ 类型          │ 说明                                  │
├──────────────┼──────────────────────────────────────┤
│ 静态反射      │ 编译期获取类型信息，零运行时开销       │
│ 动态反射      │ 运行时获取类型信息（Java/C#风格）     │
│ 编译期反射    │ C++追求的方向，编译期完全确定          │
└──────────────┴──────────────────────────────────────┘

反射能做什么：
1. 枚举类型的所有成员变量
2. 获取成员的名称和类型
3. 遍历所有成员执行操作
4. 自动生成序列化/反序列化代码
5. 自动生成比较运算符
6. 自动生成对象绑定（ORM）
7. 自动生成接口（RPC、消息传递）
```

### 1.2 为什么C++需要反射

```cpp
// 没有反射时的重复代码

struct Person {
    std::string name;
    int age;
    double height;
    std::string email;
};

// 手动实现序列化
std::string serialize(const Person& p) {
    return fmt::format("name={},age={},height={},email={}",
                       p.name, p.age, p.height, p.email);
}

// 手动实现比较
bool operator==(const Person& a, const Person& b) {
    return a.name == b.name &&
           a.age == b.age &&
           a.height == b.height &&
           a.email == b.email;
}

// 手动实现遍历
void print(const Person& p) {
    std::cout << "name: " << p.name << "\n";
    std::cout << "age: " << p.age << "\n";
    std::cout << "height: " << p.height << "\n";
    std::cout << "email: " << p.email << "\n";
}

// 问题：每添加一个成员，需要修改所有函数
// 如果有反射，这些都可以自动生成！
```

## 🟡 3. 手动反射技术

### 3.1 宏描述成员

```cpp
// 手动反射：用宏描述类型成员

// 反射宏定义
#define REFLECT_FIELDS(...) \
    static constexpr auto get_fields() { \
        return std::make_tuple(__VA_ARGS__); \
    }

#define FIELD(name) \
    std::make_pair(#name, &name)

#include <tuple>
#include <string>
#include <iostream>

// 使用宏描述可反射的类型
struct Person {
    std::string name;
    int age;
    double height;

    REFLECT_FIELDS(
        FIELD(name),
        FIELD(age),
        FIELD(height)
    )
};

// 通用遍历函数
template<typename T, typename Func>
void for_each_field(T& obj, Func&& func) {
    auto fields = T::get_fields();
    std::apply([&](auto&... field) {
        (func(field.first, obj.*(field.second)), ...);
    }, fields);
}

// 自动生成序列化
template<typename T>
std::string serialize(const T& obj) {
    std::string result;
    bool first = true;
    for_each_field(obj, [&](const char* name, const auto& value) {
        if (!first) result += ",";
        result += std::string(name) + "=" + fmt::format("{}", value);
        first = false;
    });
    return result;
}

// 自动生成打印
template<typename T>
void print_fields(const T& obj) {
    for_each_field(obj, [](const char* name, const auto& value) {
        std::cout << name << ": " << value << "\n";
    });
}
```

### 3.2 注册式反射

```cpp
// 注册式反射：将类型信息注册到全局表

#include <any>
#include <unordered_map>
#include <functional>
#include <string>

class TypeInfo {
public:
    struct FieldInfo {
        std::string name;
        std::function<std::any(const void*)> getter;
        std::function<void(void*, const std::any&)> setter;
    };

    std::string name;
    std::vector<FieldInfo> fields;

    static TypeInfo& register_type(const std::string& type_name) {
        static std::unordered_map<std::string, TypeInfo> registry;
        return registry[type_name];
    }
};

// 注册宏
#define REFLECT_REGISTER(Type, ...) \
    static bool _registered_##Type = []() { \
        auto& info = TypeInfo::register_type(#Type); \
        info.name = #Type; \
        __VA_ARGS__ \
        return true; \
    }()

#define REFLECT_FIELD(Type, field) \
    info.fields.push_back({ \
        #field, \
        [](const void* obj) -> std::any { \
            return static_cast<const Type*>(obj)->field; \
        }, \
        [](void* obj, const std::any& val) { \
            static_cast<Type*>(obj)->field = std::any_cast< \
                decltype(Type::field)>(val); \
        } \
    })

// 使用
struct Product {
    std::string name;
    double price;
    int stock;

    REFLECT_REGISTER(Product,
        REFLECT_FIELD(Product, name);
        REFLECT_FIELD(Product, price);
        REFLECT_FIELD(Product, stock);
    )
};
```

## 🟡 4. magic_get/pfr库

### 4.1 Boost.PFR原理

```cpp
// Boost.PFR (Pod Flat Reflection)
// 利用C++17结构化绑定自动遍历聚合类型的成员

#include <boost/pfr.hpp>
#include <iostream>
#include <string>

// 简单聚合类型——无需任何宏或注册！
struct Point {
    double x;
    double y;
    double z;
};

struct Employee {
    std::string name;
    int id;
    double salary;
    bool active;
};

// 自动遍历所有成员
void pfr_example() {
    Point p{1.0, 2.0, 3.0};

    // 遍历所有字段
    boost::pfr::for_each_field(p, [](const auto& field) {
        std::cout << field << " ";
    });
    // 输出: 1 2 3

    // 带索引遍历
    boost::pfr::for_each_field(p, [](const auto& field, std::size_t idx) {
        std::cout << "field[" << idx << "] = " << field << "\n";
    });

    // 获取字段数量
    constexpr size_t field_count = boost::pfr::tuple_size_v<Point>;
    static_assert(field_count == 3);

    // 按索引访问
    double x = boost::pfr::get<0>(p);
    double y = boost::pfr::get<1>(p);

    // 自动比较
    Point p1{1.0, 2.0, 3.0};
    Point p2{1.0, 2.0, 3.0};
    bool equal = boost::pfr::eq(p1, p2);  // true

    // 自动流输出
    std::cout << boost::pfr::io(p) << std::endl;
    // 输出: {1, 2, 3}
}
```

### 4.2 PFR的限制

```
Boost.PFR的限制：

1. 仅支持聚合类型（Aggregate）
   - 无自定义构造函数
   - 无虚函数
   - 无基类（C++17限制，C++20放宽）
   - 所有成员都是public

2. 无法获取成员名称
   - 只能按索引访问
   - 不知道字段叫什么名字

3. 编译时间
   - 结构化绑定展开导致编译时间增加
   - 成员数量多时尤其明显

4. 兼容性
   - 需要C++17或更高
   - 不同编译器行为可能不同

适用场景：
- 简单的数据传输对象（DTO）
- 配置结构体
- 不需要成员名称的场景
```

## 🟡 5. 代码生成技术

### 5.1 编译期代码生成

```cpp
// 基于反射信息的编译期代码生成

// 自动生成比较运算符
template<typename T>
auto operator==(const T& a, const T& b)
    -> std::enable_if_t<boost::pfr::tuple_size_v<T> > 0, bool>
{
    return boost::pfr::eq(a, b);
}

template<typename T>
auto operator!=(const T& a, const T& b)
    -> decltype(!(a == b))
{
    return !(a == b);
}

// 自动生成哈希函数
template<typename T>
struct AutoHash {
    size_t operator()(const T& obj) const {
        size_t seed = 0;
        boost::pfr::for_each_field(obj, [&](const auto& field) {
            using FieldType = std::decay_t<decltype(field)>;
            seed ^= std::hash<FieldType>{}(field) + 0x9e3779b9
                    + (seed << 6) + (seed >> 2);
        });
        return seed;
    }
};

// 自动生成toString
template<typename T>
std::string auto_to_string(const T& obj) {
    std::string result = "{";
    bool first = true;
    boost::pfr::for_each_field(obj, [&](const auto& field) {
        if (!first) result += ", ";
        result += fmt::format("{}", field);
        first = false;
    });
    result += "}";
    return result;
}
```

## 🟡 6. 编译期序列化

### 6.1 基于PFR的序列化

```cpp
// 基于Boost.PFR的自动JSON序列化

#include <boost/pfr.hpp>
#include <string>
#include <sstream>

// JSON序列化
template<typename T>
std::string to_json(const T& obj) {
    std::ostringstream oss;
    oss << "{";
    bool first = true;
    boost::pfr::for_each_field(obj, [&](const auto& field) {
        if (!first) oss << ", ";
        first = false;
        using FieldType = std::decay_t<decltype(field)>;
        if constexpr (std::is_same_v<FieldType, std::string>) {
            oss << "\"" << field << "\"";
        } else if constexpr (std::is_arithmetic_v<FieldType>) {
            oss << field;
        } else if constexpr (std::is_same_v<FieldType, bool>) {
            oss << (field ? "true" : "false");
        } else {
            oss << to_json(field);  // 递归处理嵌套类型
        }
    });
    oss << "}";
    return oss.str();
}

// 使用
struct Address {
    std::string city;
    std::string street;
    int zip;
};

struct User {
    std::string name;
    int age;
    Address address;
};

void serialization_example() {
    User user{"Alice", 30, {"Beijing", "Chaoyang Road", 100020}};
    std::cout << to_json(user) << std::endl;
    // {"Alice", 30, {"Beijing", "Chaoyang Road", 100020}}
}
```

## 🔴 7. C++26反射提案展望

### 7.1 P2996提案概览

```cpp
// C++26反射提案 (P2996) 概览
// 注意：以下代码基于提案，语法可能变化

#include <meta>  // 提案中的反射头文件

// 获取类型的反射信息
struct Person {
    std::string name;
    int age;
    double height;
};

// 提案中的用法（概念性代码）
void reflection_example() {
    // 获取Person的反射信息
    constexpr auto info = ^Person;  // ^运算符获取反射元信息

    // 遍历所有成员
    template for (constexpr auto member : define_static_array(members_of(info))) {
        std::cout << name_of(member) << ": ";
        // 访问成员值
    }

    // 获取成员数量
    constexpr auto count = members_of(info).size();

    // 获取成员名称
    template for (constexpr auto member : members_of(info)) {
        std::cout << name_of(member) << "\n";
        // 输出: name, age, height
    }

    // 获取成员类型
    template for (constexpr auto member : members_of(info)) {
        using T = typename type_of(member);
        std::cout << name_of(member) << ": " << name_of(^T) << "\n";
        // 输出: name: string, age: int, height: double
    }
}

// 自动生成序列化（提案语法）
template<typename T>
std::string auto_serialize(const T& obj) {
    std::string result = "{";
    bool first = true;
    template for (constexpr auto member : members_of(^T)) {
        if (!first) result += ", ";
        result += std::format("\"{}\": {}",
                              name_of(member),
                              obj.*member);
        first = false;
    }
    result += "}";
    return result;
}
```

## 🟢 8. 本章小结

| 主题 | 核心要点 |
|------|---------|
| 反射概念 | 编译期获取类型信息，自动生成代码 |
| C++现状 | 无原生反射，需手动实现或使用库 |
| 宏+模板 | 手动描述成员，灵活但侵入性强 |
| Boost.PFR | 零侵入，仅限聚合类型，无法获取名称 |
| 代码生成 | 外部工具生成反射代码，灵活但构建复杂 |
| 编译期序列化 | 基于反射信息自动实现序列化 |
| C++26提案 | 原生反射支持，语法优雅，尚未标准化 |

**关键理解**：

1. **C++尚无原生反射**：需要使用宏、模板或第三方库实现
2. **Boost.PFR是最实用的方案**：零侵入，支持聚合类型的自动遍历
3. **宏方案最灵活**：可以获取成员名称，但侵入性强
4. **代码生成适合大型项目**：Protobuf/FlatBuffers提供完整方案
5. **C++26反射值得期待**：原生支持将彻底改变C++元编程
6. **选择方案需权衡**：侵入性、灵活性、编译时间、可维护性
7. **反射的目标是减少重复**：序列化、比较、遍历等代码应自动生成

> **下一步**：关注C++26反射提案的进展，同时在实际项目中善用Boost.PFR和宏反射技术。
