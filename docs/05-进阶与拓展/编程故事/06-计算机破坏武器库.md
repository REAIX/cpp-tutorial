```

├── 木马（Trojan）— 伪装成正常程序，暗藏恶意功能
├── 勒索软件（Ransomware）— 加密文件，勒索赎金

│   └── ARP污染 — 局域网流量劫持
├── 监听与窃听 — 无声的信息收割
│   ├── 网络嗅探 — 混杂模式抓包
│   ├── 中间人攻击 — 插入通信双方之间
│   ├── SSL剥离 — 降级加密为明文
│   └── 大规模监听 — 国家级通信截获
├── 数据窃取 — 精准掠夺高价值信息
│   ├── 凭证窃取 — 密码/令牌/Cookie
│   ├── 文档窃取 — 机密文件/数据库拖库
│   ├── 商业间谍 — 知识产权/商业机密
│   └── 数据外传 — DNS隧道/隐写术/物理外传
├── 变异与多态 — 恶意软件的隐身术
│   ├── 多态病毒 — 换壳不换芯
│   ├── 变形病毒 — 连芯都换了
│   ├── 免杀技术 — 绕过杀毒软件检测
│   └── AI变异 — 机器学习生成变体
└── 加密武器 — 用密码学武装攻击
    ├── 加密勒索 — AES+RSA混合加密
    ├── 加密隐藏 — 加密壳保护恶意代码
    ├── 加密C2 — 隐藏指挥控制通道
    └── 加密货币 — 匿名支付与挖矿劫持
```

## 2. 病毒（Virus）— 寄生感染

### 1. 什么是病毒

**比喻**：病毒像生物病毒——不能独立生存，必须寄生在宿主（正常文件）中。你运行了被感染的文件，病毒就激活了。

### 2. 病毒的类型

| 类型 | 感染方式 | 代表 |
|------|---------|------|
| 文件型病毒 | 感染.exe/.com可执行文件 | CIH病毒 |
| 引导型病毒 | 感染硬盘主引导记录（MBR） | Stone病毒 |
| 宏病毒 | 感染Office文档的宏代码 | Melissa病毒 |
| 多态病毒 | 每次感染时改变自身代码特征 | Marburg病毒 |
| 驻留型病毒 | 常驻内存，感染每个运行的程序 | Yankee Doodle |

### 3. 经典案例：CIH病毒（1998年）

**故事**：

台湾大学生陈盈豪编写的CIH病毒，每年4月26日触发，覆盖硬盘数据并破坏BIOS芯片，导致全球6000万台电脑损坏，损失超10亿美元。

**技术原理**：

```c
// CIH病毒的破坏逻辑（简化示意）
void cih_payload() {
    // 1. 覆盖硬盘前256个扇区（分区表+文件系统）
    for (int sector = 0; sector < 256; sector++) {
        write_sector(0x80, sector, garbage_data, 512);
    }

    // 2. 破坏Flash BIOS（如果芯片可写）
    if (flash_bios_writable()) {
        erase_flash_bios();  // 主板变砖
    }
}
```

**为什么4月26日**：切尔诺贝利核事故纪念日（1986年4月26日），CIH又名"切尔诺贝利病毒"。

**防御**：不运行来历不明的程序、启用杀毒软件、BIOS写保护。

## 3. 蠕虫（Worm）— 自我复制传播

### 1. 什么是蠕虫

**比喻**：蠕虫像蝗虫——不需要宿主，自己就能繁殖和传播，通过网络从一台电脑爬到另一台。

**与病毒的区别**：

| 维度 | 病毒 | 蠕虫 |
|------|------|------|
| 是否需要宿主 | 需要（寄生在文件中） | 不需要（独立存在） |
| 传播方式 | 随文件传播 | 通过网络自动传播 |
| 用户操作 | 需要运行被感染文件 | 不需要用户操作 |
| 传播速度 | 较慢 | 极快（指数级） |

### 2. 经典案例1：Morris蠕虫（1988年）

**故事**：互联网历史上第一个大规模蠕虫，感染了互联网10%的计算机（约6000台），导致大量系统瘫痪。

**传播方式**：

```
Morris蠕虫的三种传播方式：

1. sendmail漏洞
   └── 利用sendmail的DEBUG模式，发送包含恶意命令的邮件

2. fingerd缓冲区溢出
   └── 向finger服务发送超长字符串，覆盖返回地址执行恶意代码

3. 弱密码
   └── 尝试432个常见密码字典暴力破解rsh/rexec
```

**为什么失控**：Morris本意是"测量互联网大小"，但蠕虫的传播速度远超预期。一台机器可能被多次感染，每次都启动新的传播进程，导致系统资源耗尽。

### 3. 经典案例2：ILOVEYOU蠕虫（2000年）

**故事**：一封标题为"ILOVEYOU"的邮件，附件是"情书.vbs"。打开后蠕虫通过Outlook通讯录自动发送给所有人，感染了全球1000万台电脑，损失约100亿美元。

**技术原理**：

```vbscript
' ILOVEYOU蠕虫核心逻辑（简化）
Set outlook = CreateObject("Outlook.Application")
Set contacts = outlook.GetNameSpace("MAPI").AddressLists(1)

' 遍历通讯录，给每个人发邮件
For Each contact In contacts
    Set mail = outlook.CreateItem(0)
    mail.Subject = "ILOVEYOU"
    mail.Body = "kindly check the attached LOVELETTER coming from me."
    mail.Attachments.Add "LOVE-LETTER-FOR-YOU.TXT.vbs"
    mail.Send
Next

' 覆盖MP3/JPG等文件
Set fs = CreateObject("Scripting.FileSystemObject")
For Each file In fs.GetFolder("C:\").Files
    If Right(file.Name, 4) = ".mp3" Or Right(file.Name, 4) = ".jpg" Then
        file.Copy file.Path & ".vbs"
        file.Delete
    End If
Next
```

**为什么传播这么快**：利用了人类的好奇心——谁不想看一封情书呢？

### 4. 经典案例3：Code Red蠕虫（2001年）

**故事**：利用微软IIS服务器的缓冲区溢出漏洞，19天内感染了35万台服务器，在白宫网站上留下"Hacked By Chinese!"。

**技术特点**：完全驻留内存，不写入硬盘，重启即消失但可再次感染。

### 5. 经典案例4：Conficker蠕虫（2008年）

**故事**：利用Windows MS08-067漏洞，感染了全球900-1500万台电脑，至今仍有大量感染机器。它使用了多种先进技术：

- 域名生成算法（DGA）每天生成250个随机域名作为C2服务器
- 通过U盘和局域网多种方式传播
- 禁用Windows更新和杀毒软件
- 利用P2P网络进行更新分发

## 4. 木马（Trojan）— 伪装潜入

### 1. 什么是木马

**比喻**：特洛伊木马——希腊人藏在木马里进城，表面是礼物，里面是士兵。软件也一样，表面是正常程序，里面藏着恶意代码。

### 2. 木马的类型

| 类型 | 伪装方式 | 目的 |
|------|---------|------|
| 下载器木马 | 伪装成有用软件 | 下载更多恶意软件 |
| 盗号木马 | 伪装成游戏外挂 | 窃取游戏/银行账号 |
| 远控木马（RAT） | 伪装成系统工具 | 完全控制受害者电脑 |
| 银行木马 | 伪装成银行插件 | 篡改网银交易 |
| 勒索木马 | 伪装成安全软件 | 加密文件勒索 |

### 3. 经典案例1：Back Orifice（1998年）

**故事**：黑客组织Cult of the Dead Cow在DefCon上发布，名字讽刺微软的BackOffice产品。它是一个远程管理工具，可以完全控制Windows电脑——查看屏幕、记录键盘、传输文件、开关光驱。

**技术原理**：

```
Back Orifice架构：

[攻击者] ←→ [网络] ←→ [受害者电脑上的BO服务器]
                           │
                           ├── 文件管理（上传/下载/删除）
                           ├── 进程管理（启动/杀死进程）
                           ├── 注册表管理（读/写/删）
                           ├── 屏幕捕获
                           ├── 键盘记录
                           ├── 摄像头/麦克风
                           └── 网络包嗅探
```

### 4. 经典案例2：Zeus银行木马（2007年）

**故事**：史上最成功的银行木马，感染了全球数百万台电脑，窃取了数亿美元。它通过"中间人"方式篡改网银交易——你看到的是转账100元给张三，实际转账10000元给黑客。

**技术原理**：

```
Zeus的网页注入攻击：

1. 用户访问银行网站
2. Zeus注入恶意JavaScript到银行页面
3. 页面多出"安全验证"输入框（实为窃取额外信息）
4. 用户确认转账时，Zeus修改转账金额和目标账号
5. 银行服务器收到的是篡改后的请求
6. 用户看到的是伪造的确认页面
```

### 5. 经典案例3：Emotet（2014-2021年）

**故事**：最初是银行木马，后来演变为"恶意软件即服务"（MaaS）平台，被FBI称为"世界上最危险的恶意软件"。它像快递公司一样，把其他恶意软件（勒索软件、挖矿软件）投递到目标电脑。

```
Emotet攻击链：

钓鱼邮件 → Word宏 → Emotet → 下载TrickBot → 下载Ryuk勒索软件
                                              └── 整个企业网络被加密勒索
```

## 5. 勒索软件（Ransomware）— 加密勒索

### 1. 什么是勒索软件

**比喻**：有人把你的所有文件锁进保险箱，然后告诉你"付钱给密码"。你的文件还在，但打不开了。

### 2. 勒索软件的演进

```
第一代（1989年）：AIDS Trojan
  └── 软盘传播，简单替换文件名，寄钱到巴拿马邮箱获取解密密码

第二代（2005-2012年）：Gpcode、Archiveus
  └── 使用RSA加密，但密钥较短，可被暴力破解

第三代（2013-2016年）：CryptoLocker、TeslaCrypt
  └── RSA-2048+AES-256，加密强度无法破解，比特币支付

第四代（2017-2019年）：WannaCry、NotPetya
  └── 蠕虫式传播+勒索，不依赖用户操作

第五代（2019至今）：Ryuk、REvil、Conti
  └── 定向攻击大企业，索要数百万美元赎金，"双重勒索"
```

### 3. 经典案例1：WannaCry（2017年）

**故事**：利用NSA泄露的"永恒之蓝"漏洞，150个国家30万台电脑被加密。英国NHS医院系统瘫痪，手术被迫取消。

**加密方案**：

```
WannaCry加密流程：

1. 生成随机AES-256密钥
2. 用AES-256加密每个文件（速度快）
3. 用内置的RSA-2048公钥加密AES密钥
4. 删除原始文件（卷影副本也删）
5. 显示勒索信息，要求比特币
6. 只有攻击者的RSA私钥能解密AES密钥

没有私钥 = 文件永远无法恢复
```

**Kill Switch**：安全研究员MalwareTech发现WannaCry启动时会访问一个域名，如果域名存在就停止传播。他花10美元注册了这个域名，意外地阻止了蠕虫的进一步扩散。

### 4. 经典案例2：NotPetya（2017年）

**故事**：伪装成勒索软件，实际上是**破坏性擦除攻击**。即使付了赎金也无法恢复——因为加密的是主文件记录（MFT）而非文件本身，且"解密"功能是假的。

**影响**：全球损失100亿美元，是史上破坏力最大的网络攻击。Maersk（全球最大航运公司）损失3亿美元，被迫重装4000台服务器。

**真相**：这是俄罗斯对乌克兰的国家级网络攻击，伪装成勒索软件以掩盖其破坏目的。

### 5. 经典案例3：Colonial Pipeline（2021年）

**故事**：黑客用窃取的VPN密码入侵美国最大燃油管道公司，部署DarkSide勒索软件，加密关键系统。美国东海岸燃油供应中断6天，17个州出现汽油短缺，总统宣布紧急状态。

**赎金**：公司支付了75个比特币（约440万美元）。FBI后来追回了63.7个比特币，但此时比特币贬值，只值230万美元。

## 6. 间谍软件与键盘记录器

### 1. 什么是间谍软件

**比喻**：你家里被装了窃听器和针孔摄像头，你不知道，但有人一直在偷看偷听。

### 2. 键盘记录器

```
键盘记录器的两种实现：

1. 软件键盘记录器
   └── Hook系统键盘事件（Windows Hook API）
   └── 内核级驱动拦截键盘输入
   └── 定期将记录发送到远程服务器

2. 硬件键盘记录器
   └── 插在键盘和电脑之间的USB设备
   └── 记录所有按键，事后物理取回
   └── 软件无法检测
```

### 3. 经典案例：Pegasus（飞马间谍软件）

**故事**：以色列NSO集团开发的手机间谍软件，可以零点击感染iPhone和Android——不需要用户做任何事，发一条iMessage就能入侵。

**能力**：

```
Pegasus能做什么：
├── 读取所有聊天记录（WhatsApp/Signal/微信）
├── 实时监听通话
├── 打开摄像头和麦克风
├── 读取邮件和文档
├── 获取GPS定位
├── 窃取密码和密钥
└── 以上全部，用户毫无察觉
```

**受害者**：记者、人权活动家、政客。沙特记者卡舒吉被杀害前，其妻子手机被Pegasus感染。

## 7. Rootkit — 最深的潜伏

### 1. 什么是Rootkit

**比喻**：Rootkit像变色龙——融入环境让你看不见。它修改操作系统本身，让所有"查"的动作都看不到它。

### 2. Rootkit的层次

| 层次 | 名称 | 隐藏方式 | 检测难度 |
|------|------|---------|---------|
| 用户态 | User-mode Rootkit | 修改API返回结果 | 中等 |
| 内核态 | Kernel-mode Rootkit | 修改内核数据结构 | 困难 |
| 引导态 | Bootkit | 修改引导加载程序 | 极困难 |
| 固件态 | Firmware Rootkit | 感染BIOS/UEFI/网卡固件 | 几乎不可能 |

### 3. 经典案例：Sony BMG Rootkit（2005年）

**故事**：索尼在数百万张音乐CD中植入了DRM Rootkit。当用户把CD放入电脑光驱，Rootkit自动安装，隐藏自身和所有以"$sys$"开头的文件/进程/注册表项。

**后果**：

- 黑客利用索尼的隐藏机制，把自己的恶意软件命名为`$sys$xxx`，自动被Rootkit隐藏
- 索尼被迫召回数百万张CD，赔偿消费者
- 这是"合法"公司使用恶意技术的标志性事件

### 4. 经典案例：Stuxnet（2010年）

**故事**：美以联合开发，第一个已知的国家级网络武器，使用3个零日漏洞+Windows Rootkit+西门子PLC Rootkit，摧毁了伊朗1000台离心机。

```
Stuxnet的Rootkit双层结构：

第1层：Windows Rootkit
├── 隐藏恶意DLL文件
├── 隐藏注册表项
└── 拦截API调用，返回伪造结果

第2层：PLC Rootkit
├── 拦截PLC读写请求
├── 返回正常的监控数据（伪造）
└── 实际上离心机在异常转速运转

效果：监控人员看到一切正常，但离心机正在被摧毁
```

## 8. 僵尸网络（Botnet）— 傀儡军团

### 1. 什么是僵尸网络

**比喻**：黑客是木偶操纵者，被感染的电脑是木偶。成千上万的木偶同时行动——一起发垃圾邮件、一起攻击网站、一起挖矿。电脑主人完全不知道自己的机器被操控了。

### 2. 僵尸网络的架构

```
[攻击者/C2服务器]
      │
      ├── IRC通道 ──→ [僵尸机1] [僵尸机2] ... [僵尸机N]
      │
      ├── HTTP通道 ──→ [僵尸机1] [僵尸机2] ... [僵尸机N]
      │
      └── P2P通道 ──→ [僵尸机1] ←→ [僵尸机2] ←→ [僵尸机N]
                                        ↑ 没有中心服务器，更难摧毁
```

### 3. 经典案例1：Mirai僵尸网络（2016年）

**故事**：3个大学生为了在Minecraft游戏中DDoS对手，编写了Mirai。它专门感染物联网设备（摄像头、路由器），默认密码暴力破解。最终控制了60万台设备，发动了史上最大DDoS攻击。

**攻击事件**：

- 攻击KrebsOnSecurity网站，流量620Gbps
- 攻击法国托管商OVH，流量1.1Tbps
- 攻击DNS服务商Dyn，导致Twitter/Reddit/GitHub等大站无法访问

**Mirai源码**：攻击者后来公开了源码，导致无数变种出现。

### 4. 经典案例2：Emotet僵尸网络（2014-2021年）

**故事**：从银行木马演变为"恶意软件即服务"平台，被Europol称为"世界上最危险的恶意软件"。2021年，国际执法行动联合摧毁了Emotet基础设施。

## 9. DDoS攻击 — 洪水淹没

### 1. 什么是DDoS

**比喻**：100万人同时挤进一家小店，真正的顾客进不去。不是偷东西，是让你无法做生意。

### 2. DDoS的类型

| 类型 | 原理 | 比喻 |
|------|------|------|
| SYN Flood | 发送大量SYN包，耗尽半连接队列 | 不断按门铃但不进门 |
| UDP Flood | 发送大量UDP包，耗尽带宽 | 不断往信箱塞垃圾 |
| HTTP Flood | 发送大量HTTP请求，耗尽服务器资源 | 100万人同时刷新网页 |
| DNS Amplification | 利用DNS服务器放大攻击流量 | 用大喇叭喊话，回声比原声大100倍 |
| NTP Amplification | 利用NTP服务器放大攻击 | 同上，用时间服务器放大 |

### 3. 经典案例：GitHub DDoS攻击（2018年）

**故事**：GitHub遭受1.35Tbps的DDoS攻击，是当时史上最大。攻击方式是**Memcached放大攻击**——利用暴露在互联网上的Memcached服务器，将攻击流量放大5万倍。

```
放大攻击原理：

攻击者发送15字节的请求 → Memcached返回750KB的响应
放大倍数：750,000 / 15 = 50,000倍

攻击者只需20Mbps的上行带宽
就能产生1Tbps的攻击流量
```

## 12. 你可能不知道的攻击类型

### 1. 水坑攻击（Watering Hole）

**比喻**：不直接追猎物，而是在猎物必经的水源下毒。

**案例**：攻击者知道目标公司的员工经常访问某个技术论坛，于是入侵该论坛植入恶意代码。员工访问论坛时自动被感染。

### 2. 供应链攻击（Supply Chain Attack）

**比喻**：不攻击堡垒本身，而是在运送粮草的路上动手脚。

**案例**：SolarWinds（2020年）、xz-utils（2024年），详见[安全风暴](01-安全风暴.md)。

### 3. 冷启动攻击（Cold Boot Attack）

**比喻**：趁你睡着时，把你脑子里的记忆冷冻保存，然后拿走慢慢读。

**原理**：电脑关机后，RAM中的数据不会立即消失，在低温下可保持数分钟。攻击者重启电脑，用特殊工具读取残留的内存数据，获取加密密钥。

### 4. 侧信道攻击（Side-Channel Attack）

**比喻**：不看信的内容，而是通过观察信封的厚度、重量、投递时间来推断内容。

**类型**：

| 侧信道 | 观察什么 | 能推断什么 |
|--------|---------|-----------|
| 时序攻击 | 操作耗时 | 密钥的某些位 |
| 功耗分析 | 芯片功耗变化 | 密钥的位模式 |
| 电磁辐射 | 电磁波泄露 | 屏幕内容/加密运算 |
| 声音分析 | CPU发出的声音 | 密钥/操作类型 |
| 缓存攻击 | CPU缓存命中/未命中 | 其他进程的密钥 |

**经典案例**：Spectre/Meltdown（2018年）——利用CPU的投机执行和缓存侧信道，一个进程可以读取另一个进程的内存，打破进程隔离。

### 5. BadUSB — 伪装的USB设备

**比喻**：你以为是键盘，其实是一台电脑在假装键盘。

**原理**：修改USB设备的固件，让U盘伪装成键盘。插入后，"键盘"自动输入恶意命令。

```
BadUSB攻击流程：

1. 用户插入看似正常的U盘
2. U盘伪装成键盘（HID设备）
3. "键盘"自动输入：Win+R → cmd → 下载并执行恶意程序
4. 整个过程不到5秒，用户只看到屏幕闪了一下
```

### 6. Rowhammer — 翻转内存位

**比喻**：不停敲隔壁的墙，震得你家的东西掉下来。

**原理**：反复访问DRAM的同一行，导致相邻行的电荷泄露，翻转0→1或1→0。纯软件方法修改硬件数据。

```
正常内存：  0 1 0 0 1 1 0 1
Rowhammer后：0 1 0 1 1 1 0 1  ← 第4位从0变成1
                              ← 不需要任何硬件修改！
```

**后果**：可以绕过所有软件安全机制，直接在硬件层面修改内存中的权限位。

### 7. AI驱动的攻击

**比喻**：以前黑客用锤子破门，现在用AI造了一把万能钥匙。

| 攻击方式 | 说明 |
|---------|------|
| AI钓鱼 | 用LLM生成完美无瑕的钓鱼邮件，语法/语气/上下文无可挑剔 |

## 13. 复合型恶意软件 — 集多种特征于一身的终极武器

```
   └── 因为IP属于另一个国家的另一个卫星用户
```

### 7. 复合型恶意软件的共同特征

| 特征 | 说明 |
|------|------|
| **模块化架构** | 核心常驻+按需加载模块，像手机App Store |
| **多阶段攻击** | 投递→植入→侦察→横向移动→数据窃取/破坏 |
| **反分析** | 检测虚拟机/沙箱/调试器/杀毒软件 |
| **多通道C2** | HTTP/DNS/HTTPS/P2P/卫星，一条路断了换另一条 |
| **持久化** | 多种自启动机制，删一个还有另一个 |
| **加密通信** | 所有C2通信加密，网络监控无法识别 |
| **代码签名** | 使用伪造或窃取的数字证书，绕过信任检查 |
| **自毁机制** | 完成任务后删除自身，消除取证证据 |

### 8. 为什么复合型恶意软件越来越普遍

```
原因1：攻击成本下降
  └── 模块化开发，核心代码复用，新功能只需加模块

原因2：防御能力提升
  └── 单一功能容易被检测，多管齐下更难防范

原因3：恶意软件即服务（MaaS）
  └── Emotet出租投递服务，任何人都能"租"一个僵尸网络

原因4：攻击回报增大
  └── 一个企业网络的勒索赎金可达数百万美元

原因5：国家级攻击常态化
  └── Stuxnet/Flame/Turla证明国家愿意投入巨资开发复合武器
```

## 14. 污染攻击 — 毒化数据与信任链

### 1. 什么是污染攻击

**比喻**：污染攻击像在水源中投毒——不直接攻击你，而是让你赖以生存的"水源"（数据、DNS、代码依赖）变得有毒。你喝下被污染的水，毒就从内部发作。

```
污染攻击的三大方向：

数据污染 ─── 篡改训练数据，让AI学错
DNS污染 ─── 篡改域名解析，让你访问假网站
代码污染 ─── 篡改依赖库，让软件自带后门
```

### 2. DNS污染/劫持 — 把你引向假网站

**原理**：DNS是互联网的"电话簿"——把域名翻译成IP地址。DNS污染就是篡改这个翻译结果，让你访问的"银行网站"其实是攻击者的假网站。

```
正常DNS解析：

用户输入 www.bank.com
    │
    ▼ DNS查询
DNS服务器返回 203.0.113.10（真正的银行服务器）
    │
    ▼ 用户访问
连接到真正的银行 ✅

DNS污染攻击：

用户输入 www.bank.com
    │
    ▼ DNS查询
攻击者在途中篡改响应
DNS返回 198.51.100.99（攻击者的假银行）
    │
    ▼ 用户访问
连接到攻击者的假银行 ❌
    └── 用户输入账号密码 → 被攻击者窃取
```

**DNS污染的实现方式**：

| 方式 | 原理 | 代表 |
|------|------|------|
| DNS缓存投毒 | 向DNS缓存服务器注入伪造记录 | Kaminsky攻击（2008年） |
| DNS劫持 | 修改路由器/本机DNS设置 | 路由器恶意固件 |
| 中间人DNS | 在网络层拦截并篡改DNS响应 | ISP级DNS污染 |
| BGP劫持 | 伪造BGP路由，劫持DNS服务器IP | Pakistan YouTube事件（2008年） |

**经典案例：Kaminsky攻击（2008年）**

```
Dan Kaminsky发现的DNS缓存投毒漏洞：

1. 攻击者向目标DNS服务器发送查询：random123.attacker.com
2. 在DNS服务器的递归查询返回之前，攻击者发送大量伪造响应
3. 伪造响应中包含：
   └── attacker.com 的NS记录指向攻击者的DNS服务器
4. 如果伪造响应先于真实响应到达（竞态条件）
5. DNS服务器缓存被污染
6. 之后所有对attacker.com子域的查询都指向攻击者

影响：全球几乎所有DNS服务器都受影响
修复：引入DNSSEC（DNS安全扩展）和源端口随机化
```

### 3. 数据投毒 — 让AI学错

**原理**：机器学习模型依赖训练数据。如果攻击者能向训练数据中注入精心构造的"毒数据"，模型就会学到错误的知识。

```
数据投毒的类型：

1. 标签翻转攻击
   └── 把垃圾邮件标注为"正常"，让AI把垃圾邮件当正常邮件

2. 后门投毒
   └── 在训练数据中植入"触发器+目标标签"的配对
   └── 例如：图片角落加一个小黄点 → 模型识别为"安全"
   └── 正常使用时模型表现正常，但看到触发器就输出错误结果

3. 模型窃取
   └── 大量查询API，逆向还原模型参数

4. 对抗样本
   └── 对输入做微小修改，让模型输出完全错误
   └── 例如：停车标志上贴几张贴纸 → AI识别为限速标志
```

**经典案例：Tay聊天机器人（2016年）**

微软发布的AI聊天机器人Tay，在Twitter上线不到24小时就被网友"教坏"——通过大量发送种族歧视和纳粹言论，Tay开始模仿并自动生成类似内容，微软被迫紧急下线。

### 4. 代码污染 — 供应链投毒

**原理**：现代软件严重依赖第三方库（npm/PyPI/crates.io等包管理器）。攻击者上传与流行包名相似的恶意包，或直接入侵流行包的维护者账号，就能污染整个依赖链。

```
代码污染的常见手法：

1. 拼写劫持（Typosquatting）
   └── 上传恶意包名与流行包相似
   └── 例如：npm中的 "crossenv" 伪装成 "cross-env"
   └── 用户拼错一个字母就中招

2. 依赖混淆（Dependency Confusion）
   └── 在公共仓库发布与内部私有包同名的包
   └── 构建系统优先从公共仓库拉取 → 安装了恶意包
   └── Alex Birsan在2021年用此方法入侵Apple/Microsoft/Yelp

3. 维护者账号劫持
   └── 入侵流行包维护者的npm/GitHub账号
   └── 直接在正版包中注入恶意代码
   └── 例如：event-stream事件（2018年）

4. 社会工程接管
   └── 伪装成热心贡献者，逐渐获取包的维护权限
   └── 例如：xz-utils事件（2024年）
```

**经典案例：event-stream事件（2018年）**

```
攻击时间线：

1. 攻击者"friendly"向event-stream作者贡献代码
2. 作者将项目维护权转交给"friendly"（社会工程）
3. "friendly"添加了flatmap-stream依赖
4. flatmap-stream中隐藏了比特币钱包窃取代码
5. 代码使用hex编码+eval()执行，极难发现
6. 影响了数百万下载量的事件流库

恶意代码的隐藏方式：

// 表面上看是正常的hex数据处理
// 实际上hex解码后是一段JavaScript代码
// 再经过多层解密和eval执行
// 最终窃取比特币钱包中的私钥
```

### 5. ARP污染 — 局域网中的"指路错误"

**原理**：ARP协议将IP地址映射到MAC地址，但ARP没有认证机制。攻击者发送伪造的ARP响应，就能让局域网中的设备把数据发到攻击者的机器上。

```
ARP污染攻击流程：

正常通信：
[电脑A] ─── 数据包 → [路由器] ─── → 互联网

ARP污染后：
[电脑A] ─── 数据包 → [攻击者] ─── 转发 → [路由器] → 互联网
                         │
                         └── 中间人：监听/篡改所有流量
```

### 6. 污染攻击防御

| 攻击类型 | 防御方法 |
|---------|---------|
| DNS污染 | DNSSEC验证、DNS-over-HTTPS、DNS-over-TLS |
| 数据投毒 | 数据来源验证、异常检测、差分隐私、模型鲁棒性测试 |
| 代码污染 | 锁定依赖版本（lockfile）、SBOM、可重复构建、签名验证 |
| ARP污染 | 静态ARP绑定、DHCP Snooping、端口安全 |

## 15. 监听与窃听 — 无声的信息收割

### 1. 什么是监听攻击

**比喻**：监听攻击像在电话线上搭线窃听——你正常打电话，但有人在旁边默默听你说的每一句话。你完全不知道有人在听，因为通信本身没有受到任何干扰。

```
监听攻击的层次：

网络层监听 ─── 嗅探网络上的数据包
通信层拦截 ─── 中间人攻击，解密加密流量
物理层窃听 ─── 电磁辐射、声学、光学侧信道
```

### 2. 网络嗅探 — 监听网络上的所有流量

**原理**：网卡默认只接收发给自己的数据包（单播），但可以设置为"混杂模式"（Promiscuous Mode），接收网络上所有数据包。

```
正常模式：
[网卡] 只接收目标MAC地址是自己的数据包

混杂模式：
[网卡] 接收网络上所有数据包 → 嗅探器

嗅探到的信息：
├── HTTP请求 → 用户名、密码、Cookie（明文）
├── FTP传输 → 文件内容（明文）
├── SMTP邮件 → 邮件内容（明文）
├── Telnet会话 → 远程登录命令（明文）
└── DNS查询 → 用户访问了哪些网站
```

**常用嗅探工具**：

| 工具 | 用途 | 合法/非法 |
|------|------|----------|
| Wireshark | 网络协议分析和排错 | 合法（网络管理员使用） |
| tcpdump | 命令行抓包工具 | 合法（系统管理员使用） |
| Ettercap | 局域网嗅探+中间人攻击 | 双用途 |
| Bettercap | 现代网络攻击框架 | 双用途 |
| dsniff | 网络嗅探套件 | 主要用于攻击 |

**经典案例：Firesheep（2010年）**

Firefox浏览器插件，一键劫持未加密WiFi上的HTTP会话。在咖啡店打开Firesheep，就能看到同一WiFi下所有人的Facebook/Twitter/Tumblr会话，点击即可接管。

```
Firesheep的原理：

1. 咖啡店WiFi是开放网络（无加密）
2. 用户登录Facebook后，浏览器保存了Session Cookie
3. 后续请求通过HTTP发送（明文），Cookie在请求头中
4. Firesheep嗅探到Cookie
5. 攻击者使用这个Cookie → 直接登录该用户的Facebook

为什么可怕：零技术门槛，一键劫持
影响：推动了全站HTTPS的普及
```

### 3. 中间人攻击（MITM）— 你以为在和服务器说话，其实在和攻击者说话

**原理**：攻击者插入到客户端和服务器之间，双方都以为在直接和对方通信，实际上所有流量都经过攻击者。

```
正常通信：
[客户端] ←───── 加密通道 ─────→ [服务器]

中间人攻击：
[客户端] ←── 加密通道1 ──→ [攻击者] ←── 加密通道2 ──→ [服务器]
                            │
                            └── 解密→查看→篡改→重新加密→转发

攻击者可以看到明文：密码、Cookie、银行卡号...
攻击者可以篡改内容：下载的文件、网页内容、软件更新...
```

**MITM的实现方式**：

| 方式 | 原理 | 难度 |
|------|------|------|
| ARP欺骗 | 伪造ARP响应，让流量经过攻击者 | 低 |
| DNS欺骗 | 篡改DNS响应，指向攻击者服务器 | 低 |
| WiFi热点 | 建立伪造WiFi热点，直接控制流量 | 低 |
| SSL剥离 | 将HTTPS降级为HTTP | 中 |
| 证书伪造 | 使用伪造CA证书，解密HTTPS流量 | 高 |
| BGP劫持 | 伪造路由，将IP流量导向攻击者 | 极高 |

**经典案例：Superfish（2015年）**

```
Lenovo预装广告软件Superfish的事件：

1. Lenovo在出厂电脑中预装了Superfish广告软件
2. Superfish插入了自签名的根CA证书到系统信任库
3. 所有HTTPS流量被Superfish解密→注入广告→重新加密
4. 相当于Lenovo在每台电脑上装了一个"合法的中间人"
5. 问题：Superfish的私钥可以被提取
   └── 任何人都能用这个私钥伪造证书
   └── 在同一WiFi下可以对Lenovo用户进行MITM攻击

影响：数百万台Lenovo电脑受影响
教训：永远不要为了"方便"而破坏加密信任链
```

### 4. SSL/TLS剥离 — 把加密变成明文

**原理**：很多网站同时支持HTTP和HTTPS。SSL剥离工具在用户访问HTTPS网站时，将重定向到HTTPS的响应替换为HTTP，让用户以为在安全连接上，实际是明文传输。

```
SSL剥离攻击流程：

1. 用户输入 bank.com（浏览器默认用HTTP）
2. 服务器返回301重定向到 https://bank.com
3. 攻击者（中间人）拦截重定向
4. 攻击者把HTTPS重定向替换为HTTP
5. 用户浏览器继续用HTTP访问
6. 攻击者嗅探明文流量
7. 攻击者同时和服务器建立HTTPS连接，转发请求

用户看到：地址栏没有锁头图标（但很多人不注意）
```

**防御**：HSTS（HTTP Strict Transport Security）——服务器告诉浏览器"只能用HTTPS访问我"，浏览器记住后不再尝试HTTP。

### 5. 通信拦截 — 国家级大规模监听

**经典案例：PRISM计划（2013年）**

```
斯诺登揭露的PRISM计划：

NSA直接从以下公司获取用户数据：
├── Google — 邮件、文档、搜索记录
├── Microsoft — Hotmail、Skype、SkyDrive
├── Apple — iCloud、iMessage
├── Facebook — 消息、帖子
├── Yahoo — 邮件、联系人
├── Skype — 视频通话
└── YouTube — 视频数据

NSA的其他监听项目：
├── XKeyscore — 全球互联网流量实时搜索
├── Upstream — 直接从光纤骨干网截获流量
├── Bullrun — 破解加密通信
└── Tempora — 英国GCHQ的海量数据截获
```

### 6. 监听攻击防御

| 攻击类型 | 防御方法 |
|---------|---------|
| 网络嗅探 | 全站HTTPS、VPN、避免使用开放WiFi |
| ARP欺骗+MITM | 静态ARP、HTTPS+HSTS、证书锁定（Certificate Pinning） |
| SSL剥离 | HSTS、浏览器预加载HSTS列表 |
| WiFi热点攻击 | 不连接不明WiFi、使用VPN、验证热点名称 |
| 国家级监听 | 端到端加密、Tor网络、零知识证明 |

## 16. 数据窃取 — 有针对性的精准掠夺

### 1. 什么是数据窃取

**比喻**：如果说监听是在街上偷听路人说话，数据窃取就是有目标地潜入某人的保险箱，精准拿走最值钱的东西。攻击者明确知道要偷什么、从哪里偷、怎么偷。

```
数据窃取的目标层级：

个人级 ─── 银行凭证、身份信息、私密照片
企业级 ─── 商业机密、客户数据、源代码、财务数据
国家级 ─── 军事机密、外交电报、情报数据、科研成果
```

### 2. 数据窃取的技术手段

```
窃取技术全景：

1. 凭证窃取
   ├── 键盘记录 — 记录每一次按键
   ├── 表单抓取 — 浏览器提交表单前截获数据
   ├── Cookie窃取 — 劫持已登录的会话
   ├── 密码提取 — 从浏览器/邮件客户端提取保存的密码
   └── 令牌窃取 — 窃取OAuth/访问令牌

2. 文档窃取
   ├── 全盘扫描 — 搜索特定扩展名（.doc/.pdf/.xls/.ppt）
   ├── 关键词搜索 — 搜索包含"机密""密码""财务"的文件
   ├── 邮件窃取 — 导出Outlook/PST邮箱数据
   └── 数据库拖库 — 导出整个数据库

3. 屏幕窃取
   ├── 定时截屏 — 每隔N秒截取屏幕
   ├── 剪贴板监控 — 监控复制粘贴内容
   └── 远程查看 — 实时查看受害者屏幕

4. 网络窃取
   ├── 流量嗅探 — 从网络流量中提取敏感信息
   ├── 中间人拦截 — 解密并读取加密流量
   └── DNS监控 — 监控用户访问了哪些网站
```

### 3. 经典案例1：Equifax数据泄露（2017年）

```
事件概况：
1.45亿美国人的个人信息被窃取
包括：姓名、SSN（社会安全号）、出生日期、地址、驾照号

攻击过程：
1. Equifax的Apache Struts框架存在已知漏洞（CVE-2017-5638）
2. 补丁已发布2个月，但Equifax没有及时更新
3. 攻击者利用漏洞进入Equifax网络
4. 在网络中潜伏76天，未被发现
5. 窃取1.45亿条记录
6. 使用加密通道将数据外传

为什么76天没发现：
├── 没有对出站流量进行监控
├── 没有入侵检测系统
├── 敏感数据没有加密存储
├── 漏洞扫描只覆盖了部分系统
└── 安全团队人手不足
```

### 4. 经典案例2：OPM数据泄露（2015年）

```
事件概况：
2210万美国联邦雇员的安全审查资料被窃取
包括：SF-86表格（极其详细的个人背景调查）
  ├── 家庭成员信息
  ├── 心理健康记录
  ├── 药物使用历史
  ├── 外国联系人
  └── 指纹数据（560万条）

攻击者：疑似中国APT组织（APT10/XiPS）

攻击过程：
1. 首先入侵OPM承包商KeyPoint的凭证
2. 使用窃取的凭证登录OPM网络
3. 提权到管理员权限
4. 部署恶意软件建立后门
5. 窃取数据并通过加密通道外传

为什么影响如此严重：
├── SF-86表格是情报人员的"命脉"
│   └── 知道谁在做情报工作、他们的弱点是什么
├── 指纹数据不可更改（不像密码可以换）
└── 可以用于对情报人员的勒索和策反
```

### 5. 经典案例3：商业间谍软件 — Pegasus


## 17. 变异与多态 — 恶意软件的隐身术

### 1. 什么是变异

**比喻**：变异像变色龙——每次出现都换一层"皮"，让杀毒软件认不出来。核心功能不变，但外观（代码特征）每次都不同。

```
恶意软件逃避检测的进化路线：

第一代：固定特征码
  └── 每次感染代码完全相同 → 杀毒软件用特征码轻松识别

第二代：加密型
  └── 代码加密存储，运行时解密 → 解密后代码相同，仍可识别

第三代：多态型（Polymorphic）
  └── 每次感染时用不同的加密密钥+不同的解密例程
  └── 解密后的代码相同，但解密器每次不同 → 特征码失效

第四代：变形型（Metamorphic）
  └── 每次感染时重写自身代码
  └── 功能相同但代码完全不同 → 连解密后的代码也无法匹配

第五代：AI辅助变异
  └── 用AI生成功能等价但代码不同的变体
  └── 每个变体都是"全新"的代码
```

### 2. 多态病毒 — 换壳不换芯

**原理**：多态病毒的核心恶意代码不变，但每次感染时使用不同的加密密钥和不同的解密算法，使得杀毒软件无法通过特征码识别。

```
多态病毒的代码结构：

┌─────────────────────────┐
│  解密器（每次不同）       │ ← 变异的部分
│  ┌───────────────────┐  │
│  │  加密的恶意代码    │  │ ← 不变的部分（但加密密钥每次不同）
│  └───────────────────┘  │
└─────────────────────────┘

运行过程：
1. 解密器执行
2. 解密器用内置密钥解密恶意代码
3. 跳转到解密后的恶意代码执行
4. 恶意代码执行完毕后，生成新的加密密钥
5. 用新密钥加密自身，生成新的解密器
6. 感染下一个文件
```

**多态引擎的变异手法**：

| 手法 | 说明 | 示例 |
|------|------|------|
| 等价指令替换 | 功能相同但指令不同 | `MOV AX, 0` ↔ `XOR AX, AX` |
| 垃圾指令插入 | 插入不影响功能的指令 | `NOP`、`MOV BX, BX` |
| 寄存器交换 | 交换使用的寄存器 | `AX↔BX`、`CX↔DX` |
| 代码重排 | 改变指令执行顺序（用跳转连接） | 交换基本块位置 |
| 加密算法变换 | 使用不同的加密方式 | XOR/ADD/ROL/RC4 |
| 解密器变形 | 不同的解密循环实现 | for/while/递归 |

**经典案例：Marburg病毒（1998年）**

```
Marburg病毒的多态特征：

1. 感染PE文件（Windows可执行文件）
2. 使用多态引擎，每次感染生成不同的解密器
3. 解密器代码长度和结构每次不同
4. 使用不同的加密密钥
5. 杀毒软件无法提取固定特征码

多态引擎的变异示例（伪代码）：

// 变体1的解密器
mov ecx, encrypted_size
mov esi, encrypted_start
decrypt_loop1:
  xor byte [esi], 0x5A
  inc esi
  loop decrypt_loop1

// 变体2的解密器（功能完全相同，但代码不同）
push encrypted_size
pop edx
lea edi, [encrypted_start]
add edx, edi
swap_loop:
  not byte [edi]
  inc edi
  cmp edi, edx
  jl swap_loop
```

### 3. 变形病毒 — 连芯都换了

**原理**：变形病毒比多态更进一步——不只是加密壳不同，连恶意代码本身都被重写。每次感染时，病毒分析自身代码，生成功能等价但代码完全不同的新版本。

```
多态 vs 变形：

多态病毒：
  [解密器A] → 解密 → [恶意代码X]  ← 解密后代码相同
  [解密器B] → 解密 → [恶意代码X]  ← 解密后代码相同
  [解密器C] → 解密 → [恶意代码X]  ← 解密后代码相同
  杀毒软件：只要识别恶意代码X即可

变形病毒：
  [恶意代码变体A]  ← 代码完全不同
  [恶意代码变体B]  ← 代码完全不同
  [恶意代码变体C]  ← 代码完全不同
  杀毒软件：无法用特征码识别，因为每个变体的代码都不同
```

**变形引擎的工作流程**：

```
变形引擎（Metamorphic Engine）：

1. 反汇编自身代码
   └── 将机器码转换为汇编指令

2. 分析代码语义
   └── 理解每条指令的功能和依赖关系

3. 应用变换规则
   ├── 等价指令替换
   ├── 寄存器重命名
   ├── 代码块重排
   ├── 死代码插入
   └── 控制流扁平化

4. 重新组装
   └── 将变换后的汇编代码重新编译为机器码

5. 验证等价性
   └── 确保变换后的代码功能与原始代码相同
```

**经典案例：Simile病毒（2002年）**

```
Simile（也称为MetaPHOR）：

1. 第一个真正意义上的跨平台变形病毒
2. 同时感染Windows PE和Linux ELF文件
3. 约14000行汇编代码，其中变形引擎约9000行
4. 每次感染生成的代码完全不同
5. 杀毒公司花了几个月才开发出可靠的检测方法

Simile的变形能力：
├── 寄存器重命名：随机选择使用的寄存器
├── 指令替换：用等价指令替换原始指令
├── 代码块重排：随机排列基本块，用跳转连接

```

```
免杀（FUD — Fully Undetectable）技术全景：
```

## 18. 加密武器 — 用密码学武装攻击

### 1. 加密在攻击中的双重角色

**比喻**：加密像一把锁——好人用锁保护财产，坏人用锁把赃物锁起来让你拿不回去，或者用锁把作案工具锁起来让你看不到里面是什么。

```
加密在攻击中的三大用途：

1. 加密勒索 — 把你的数据加密，不给钱不给你解密
2. 加密隐藏 — 把恶意代码加密，杀毒软件看不懂
3. 加密通信 — C2通信加密，网络监控无法识别
```

### 2. 加密勒索 — 勒索软件的核心武器

**原理**：勒索软件的核心就是加密——用强加密算法加密受害者的文件，只有攻击者持有解密密钥。

```
现代勒索软件的加密流程：

1. 生成随机的AES-256密钥（对称加密，速度快）
2. 用AES-256加密每个文件
3. 用RSA-2048公钥加密AES密钥（非对称加密，只有私钥能解密）
4. 删除原始文件
5. 删除卷影副本（Windows备份）
6. 删除AES密钥（内存中）
7. 显示勒索信：支付比特币 → 获得RSA私钥 → 解密AES密钥 → 解密文件

为什么无法破解：
├── AES-256暴力破解需要2^256次运算（宇宙年龄都不够）
├── RSA-2048暴力破解需要数百万年
├── 没有实现错误的情况下，数学上不可逆
└── 即使抓到攻击者，如果私钥已删除，文件也无法恢复
```

**勒索软件的加密演进**：

| 代际 | 加密方式 | 代表 | 破解可能性 |
|------|---------|------|-----------|
| 第一代 | 简单XOR/自定义加密 | AIDS Trojan（1989年） | 高（加密算法有缺陷） |
| 第二代 | 单AES密钥 |早期CryptoLocker | 中（密钥管理有缺陷） |
| 第三代 | AES+RSA混合 | WannaCry/NotPetya | 低（实现正确时几乎不可能） |
| 第四代 | AES+RSA+离线密钥 | Ryuk/Conti | 极低（每个文件独立密钥） |
| 第五代 | 双重勒索 | Maze/REvil | 无（加密+威胁泄露） |

**双重勒索（Double Extortion）**：

```
传统勒索：加密文件 → 要赎金解密
  └── 受害者可以靠备份恢复 → 不付钱

双重勒索：先窃取数据 → 再加密文件 → 两个要挟
  ├── 要挟1：不付钱就不给解密密钥
  └── 要挟2：不付钱就公开你的机密数据

三重勒索（Triple Extortion）：
  ├── 要挟1：不给解密密钥
  ├── 要挟2：公开机密数据
  └── 要挟3：DDoS你的网站/通知你的客户

四重勒索：
  ├── 要挟1：不给解密密钥
  ├── 要挟2：公开机密数据
  ├── 要挟3：DDoS攻击
  └── 要挟4：直接联系你的客户/合作伙伴施压
```

**经典案例：WannaCry（2017年）**

```
WannaCry的加密机制：

1. 生成RSA-2048密钥对（每次感染不同）
2. 随机生成AES-128密钥用于加密每个文件
3. 用RSA公钥加密AES密钥
4. 加密文件后添加.WNCRY扩展名
5. 勒索信要求支付比特币

WannaCry的加密实现缺陷：
├── 没有正确验证RSA密钥
├── 使用了硬编码的"kill switch"域名
└── 部分实现有bug，导致某些情况下可以恢复

但核心加密（AES+RSA）是安全的
  └── 没有实现缺陷的文件无法被免费解密
```

### 3. 加密隐藏 — 用加密保护恶意代码

**原理**：杀毒软件通过扫描文件中的已知特征码来检测恶意软件。如果恶意代码被加密，杀毒软件只能看到密文，无法匹配特征码。

```
加密隐藏的层次：

1. 简单加密壳
   └── 整个恶意代码用XOR/RC4加密
   └── 入口点是一个小的解密stub
   └── 运行时解密到内存执行

2. 多层加密
   └── 外层加密 → 解密后是第二层加密 → 解密后是第三层...
   └── 每层使用不同的加密算法和密钥
   └── 杀毒软件需要逐层解密才能看到真实代码

3. 运行时解密
   └── 只在需要时解密特定功能模块
   └── 用完后立即重新加密
   └── 内存中同时只有一小段明文代码

4. 虚拟机保护
   └── 恶意代码转换为自定义虚拟机的字节码
   └── 运行时由虚拟机解释执行
   └── 杀毒软件无法理解自定义指令集
```

**加密恶意代码的典型结构**：

```c
// 加密恶意代码的加载器（简化示意）

void loader() {
    unsigned char encrypted_payload[] = {
        0x3a, 0x7f, 0x12, 0x9b, 0x45, 0xcd, 0x88, 0x21,
        // ... 加密后的恶意代码 ...
    };
    int payload_size = sizeof(encrypted_payload);
    unsigned char key[] = {0x5A, 0x3C, 0x7E, 0x1F};

    // 解密
    for (int i = 0; i < payload_size; i++) {
        encrypted_payload[i] ^= key[i % sizeof(key)];
    }

    // 在内存中执行
    void (*execute)() = (void(*)())encrypted_payload;
    execute();
}
```

### 4. 加密C2通信 — 隐藏指挥控制通道

**原理**：恶意软件需要和C2（Command & Control）服务器通信来接收指令和上传数据。如果通信是明文的，网络监控可以轻松检测和阻断。加密C2通信让恶意流量看起来像正常的HTTPS/DNS流量。

```
加密C2通信的方式：

1. HTTPS C2
   └── 使用标准HTTPS协议通信
   └── 混在正常的Web流量中，难以区分
   └── 例如：Cobalt Strike的HTTPS Beacon

2. DNS over HTTPS (DoH) C2
   └── 通过加密DNS通道传输指令
   └── 网络监控只能看到DNS查询
   └── 实际数据编码在DNS请求/响应中

3. 域前置（Domain Fronting）
   └── HTTPS连接的SNI指向合法域名（如cdn.example.com）
   └── HTTP Host头指向C2域名（如c2.evil.com）
   └── CDN根据Host头路由到C2服务器
   └── 网络监控只看到与CDN的连接

4. 加密即时消息C2
   └── 通过Telegram/Discord/Slack API通信
   └── 流量看起来像正常的即时消息
   └── 指令编码在消息内容中

5. 区块链C2
   └── 通过比特币/以太坊交易数据传输指令
   └── 完全去中心化，无法关停
   └── 指令编码在交易的OP_RETURN字段中
```

**域前置攻击详解**：

```
正常HTTPS连接：
[恶意软件] ── SNI: cdn.example.com ──→ [CDN]
                                       Host: cdn.example.com
                                       └── CDN返回正常内容

域前置攻击：
[恶意软件] ── SNI: cdn.example.com ──→ [CDN]
                                       Host: c2.evil.com
                                       └── CDN路由到C2服务器

网络监控看到：
  └── 连接到 cdn.example.com（合法CDN）✅ 看起来正常
  └── 实际上在和 c2.evil.com 通信 ❌
```

### 5. 加密货币与攻击 — 匿名支付通道

```
加密货币在攻击中的角色：

1. 勒索支付
   └── 比特币/门罗币作为赎金支付方式
   └── 伪匿名性使追踪困难
   └── 门罗币（Monero）提供更强的隐私保护

2. 挖矿劫持
   └── 偷偷用受害者的CPU/GPU挖矿
   └── 不需要用户交互，安静地赚钱
   └── 隐蔽型：限制CPU使用率，用户不易察觉

3. 混币服务
   └── 通过混币服务将追踪的比特币"洗白"
   └── 多个用户的币混合后重新分配
   └── 打断区块链上的交易链追踪

4. 去中心化C2
   └── 使用智能合约作为C2通道
   └── 指令编码在区块链交易中
   └── 不可篡改、不可关停
```

### 6. 加密攻击防御

| 攻击类型 | 防御方法 |
|---------|---------|
| 勒索加密 | 离线备份、3-2-1备份策略、网络隔离、EDR |
| 加密隐藏 | 行为分析、内存扫描、沙箱动态分析 |
| 加密C2 | 流量分析（即使加密也能分析流量模式）、威胁情报、域前置阻断 |
| 加密货币支付 | 区块链追踪、交易所KYC、支付监控 |
| 挖矿劫持 | CPU使用率监控、进程审计、浏览器挖矿防护 |
