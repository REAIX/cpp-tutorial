## 1. AI伦理为什么突然重要

- 成为AI伦理课程中的**经典案例**
- 证明了AI系统在开放环境中面临的**社会工程攻击**风险

## 3. COMPAS算法的种族偏见

### 1. 事件背景

COMPAS（Correctional Offender Management Profiling for Alternative Sanctions）是美国法院广泛使用的量刑评估算法，由Northpointe公司（现Equivant）开发。它通过分析被告的历史数据，预测其再次犯罪的风险，评分结果直接影响法官的量刑决定——保释、判刑长度、假释批准。

```
  COMPAS在司法流程中的位置
  ──────────────────────────────────────────────────────

  逮捕 → 起诉 → ┌──────────────┐ → 量刑 → 服刑 → 假释
                  │  COMPAS评估   │
                  │              │
                  │ 输入：       │
                  │ · 犯罪历史   │
                  │ · 个人信息   │
                  │ · 面试回答   │
                  │              │
                  │ 输出：       │
                  │ 1-10风险评分 │
                  │ 高/中/低风险 │
                  └──────────────┘
                        ↓
                 影响法官决策
              （但法官未必理解算法）
```

### 2. ProPublica的调查发现

2016年5月，调查新闻机构ProPublica发布了重磅报告《Machine Bias》，分析了COMPAS在佛罗里达州布劳沃德县的7000多名被告数据。结果令人震惊：

| 指标 | 黑人被告 | 白人被告 |
|------|----------|----------|
| 被错误标记为高风险的比例 | **44.9%** | 23.5% |
| 被错误标记为低风险的比例 | 28.0% | **47.7%** |
| 实际再犯罪率 | 51.4% | 59.1% |

核心发现：**COMPAS对黑人的假阳性率几乎是白人的两倍**——大量不会再次犯罪的黑人被算法判定为"高风险"，从而受到更严厉的量刑。

### 3. 算法偏见的三种来源

```
  算法偏见的来源
  ──────────────────────────────────────────────────────

  ┌─────────────────────────────────────────────────┐
  │                  算法偏见来源                    │
  ├─────────────┬─────────────┬─────────────────────┤
  │  训练数据   │  特征选择   │     标签偏差        │
  │             │             │                     │
  │ · 历史逮捕  │ · 邮政编码  │ · "再犯"定义       │
  │   数据本身  │   作为代理  │   基于逮捕而非     │
  │   存在种族  │   种族变量  │   实际犯罪         │
  │   偏见      │             │                     │
  │             │ · 就业状态  │ · 被逮捕≠有罪      │
  │ · 黑人被    │   间接反映  │ · 黑人社区警力     │
  │   逮捕率    │   种族差异  │   更密集→逮捕率   │
  │   更高      │             │   更高             │
  │             │ · 家庭背景  │                     │
  │ · 历史判决  │   与种族    │ · 标签本身嵌入    │
  │   影响新    │   高度相关  │   了系统性偏见    │
  │   数据      │             │                     │
  └─────────────┴─────────────┴─────────────────────┘
```

**1. 训练数据偏见**

COMPAS的训练数据来自历史犯罪记录。但美国司法系统本身存在种族差异——黑人被逮捕、起诉、定罪的比例高于白人，这不完全是因为犯罪率更高，而是因为执法资源分配不均、历史性歧视等因素。算法从这些有偏见的数据中学习，自然会产生有偏见的预测。

**2. 特征选择偏见**

COMPAS不直接使用"种族"作为输入变量（这在法律上被禁止），但它使用了与种族高度相关的"代理变量"：邮政编码（反映居住地的种族构成）、就业状态、教育水平等。这些变量间接编码了种族信息。

**3. 标签偏差**

COMPAS预测的"再犯"标签基于**再次被逮捕**的记录，而非**实际再次犯罪**。由于黑人社区警力部署更密集，黑人被逮捕的概率更高，因此即使实际犯罪率相同，黑人的"再犯"标签也更可能为正。

### 4. 影响与教训

- Northpointe公司否认算法存在偏见，声称算法在不同种族间的**预测准确率相同**——但这掩盖了错误类型的不对称性
- 引发了学术界关于**算法公平性定义**的激烈辩论：公平无法同时满足所有定义
- 多个美国城市开始限制或禁止在司法中使用算法评估工具
- 2019年，纽约州通过法律，要求对用于量刑的算法进行偏见审计

## 4. Deepfake深度伪造危机

### 1. 从换脸娱乐到伪造政治言论

Deepfake技术源自2017年底Reddit用户"deepfakes"发布的换脸视频。最初，它被用于将名人面孔替换到成人影片中。但随着技术民主化，Deepfake的威胁迅速升级。

```
  Deepfake威胁等级
  ──────────────────────────────────────────────────────

  威胁等级
    │
    │  ★★★★★  国家安全：伪造国家领导人宣战声明
    │
    │  ★★★★   金融市场：伪造CEO声明操纵股价
    │
    │  ★★★    司法公正：伪造证据干扰审判
    │
    │  ★★     个人名誉：色情报复、网络霸凌
    │
    │  ★      娱乐恶搞：换脸表情包
    │
    └──────────────────────────────────────────────────→ 制作难度降低
```

### 2. Deepfake色情：沉默的受害者

Deepfake色情是这项技术最广泛、最伤害个人的滥用形式。根据2023年的一项研究：

- **98%的Deepfake视频**是色情内容
- **99%的Deepfake色情**针对女性
- 受害者包括名人、网红和**普通女性**
- 制作工具在暗网以不到10美元的价格出售

受害者往往在不知情的情况下被"换脸"到色情视频中，当这些视频在网络上传播时，她们面临名誉损毁、心理创伤和职业打击，而维权极其困难。

### 4. 检测与防御的军备竞赛

```
  Deepfake攻防军备竞赛
  ──────────────────────────────────────────────────────

  攻击方（伪造）              防御方（检测）
  ────────────              ────────────
  GAN生成换脸    ──→        面部边缘伪影检测
       ↓                         ↓
  扩散模型提升质量 ──→       生理信号检测（心跳/眨眼）
       ↓                         ↓
  实时视频伪造   ──→        多模态联合分析
       ↓                         ↓
  对抗性扰动     ──→        数字取证+AI检测
       ↓                         ↓
  ???             ←──→       ???

  规律：攻击方总是领先一步
```

当前检测技术的困境：

- **猫鼠游戏**：每当检测器升级，伪造者就改进技术绕过检测
- **泛化问题**：在已知伪造方法上训练的检测器，面对新方法往往失效
- **实时性挑战**：视频通话中的实时检测准确率远低于离线分析
- **对抗性攻击**：伪造者可以故意添加噪声来欺骗检测器

## 5. 自动驾驶的伦理困境

### 2. 事故原因分析

美国国家运输安全委员会（NTSB）的调查揭示了多重失败：

| 失败层面 | 具体问题 |
|----------|----------|
| **算法设计** | 紧急制动功能被禁用，为减少"误报"而牺牲安全冗余 |
| **感知系统** | 对行人的分类反复摇摆，无法稳定识别 |
| **安全员** | 安全员分心看手机，未履行监控职责 |
| **安全文化** | Uber内部降低安全标准以追赶测试进度 |
| **道路设计** | 行人不在人行横道，但道路缺乏行人过街设施 |
| **监管缺失** | 亚利桑那州对自动驾驶测试几乎没有监管要求 |

### 3. 电车难题的现实版

自动驾驶将哲学家们的"电车难题"变成了工程问题：

```
  自动驾驶的伦理决策
  ──────────────────────────────────────────────────────

  场景：刹车失灵，必须选择碰撞方向

        ┌─────┐
        │ 自  │
        │ 驾  │
        │ 车  │
        └──┬──┘
           │
     ──────┼──────
           │
     ┌─────┴─────┐
     │           │
  ┌──┴──┐    ┌──┴──┐
  │ 3名 │    │ 1名 │

  │(左转)│    │(直行)│
```

MIT的"道德机器"（Moral Machine）实验收集了全球数百万人对自动驾驶伦理决策的偏好，发现不同文化、不同国家对"该救谁"的回答差异巨大——这意味着不存在全球统一的伦理算法。

### 4. 特斯拉Autopilot事故统计

截至2024年，美国国家公路交通安全管理局（NHTSA）记录的Autopilot相关事故：

- **超过1000起**事故报告
- **至少40起**致死事故
- 事故模式多为：Autopilot未能识别前方静止车辆或障碍物
- 特斯拉的辩护：Autopilot比人类驾驶更安全（每英里事故率更低）
- 批评者的反驳：数据不透明，无法独立验证

## 6. AI生成代码的安全隐患

### 1. Copilot生成的漏洞代码研究

2022年，纽约大学和卡内基梅隆大学的研究团队对GitHub Copilot进行了系统性的安全评估，结果令人担忧：

```
  Copilot安全风险研究
  ──────────────────────────────────────────────────────

  研究方法：向Copilot提供89个安全相关的编程场景
  测试轮次：每个场景生成25次代码

  结果：
  ┌─────────────────────────────────────────────┐
  │                                             │
  │   约40% 的生成代码存在安全漏洞              │
  │                                             │
  │   ┌───────────────────────────────────┐     │
  │   │  CWE-79  XSS跨站脚本    25%      │     │
  │   │  CWE-787 缓冲区溢出     20%      │     │
  │   │  CWE-89  SQL注入        18%      │     │
  │   │  CWE-22  路径遍历       15%      │     │
  │   │  其他    各类漏洞       22%      │     │
  │   └───────────────────────────────────┘     │
  │                                             │
  │   在60%的场景中，至少一次生成存在漏洞       │
  │                                             │
  └─────────────────────────────────────────────┘
```

常见的安全问题包括：

- **SQL注入**：Copilot经常生成直接拼接SQL语句的代码，而非使用参数化查询
- **XSS攻击**：生成的Web代码往往不转义用户输入
- **硬编码密钥**：AI倾向于将API密钥和密码直接写在代码中
- **不安全的加密**：使用过时的加密算法或不安全的随机数生成器

### 2. AI幻觉导致错误API使用

AI代码生成的另一个严重问题是"幻觉"——AI自信地生成不存在的API、错误的函数签名或虚构的库：

```
  AI代码幻觉的常见类型
  ──────────────────────────────────────────────────────

  类型1：虚构API
  ┌─────────────────────────────────────────────┐
  │ // AI生成的代码                             │
  │ const db = require('mongodb');              │
  │ db.connectAndFind('users', {name: 'foo'});  │
  │ // ↑ 这个方法不存在！                       │
  └─────────────────────────────────────────────┘

  类型2：错误的参数
  ┌─────────────────────────────────────────────┐
  │ // AI生成的代码                             │
  │ crypto.encrypt(data, 'AES-256', key);       │
  │ // ↑ 参数顺序和名称都不对                   │
  └─────────────────────────────────────────────┘

  类型3：混搭不同库的API
  ┌─────────────────────────────────────────────┐
  │ // AI把React和Vue的API混在一起              │
  │ const [state, setState] = ref(0);           │
  │ // ↑ ref是Vue的，useState才是React的        │
  └─────────────────────────────────────────────┘
```

这些幻觉代码在语法上可能完全正确，甚至能通过编译，但运行时会崩溃或产生安全漏洞。更危险的是，缺乏经验的开发者可能不会意识到代码是错误的。

### 3. AI代码的版权争议

AI生成代码的版权问题是一个法律灰色地带：

- **训练数据**：Copilot基于GitHub上的开源代码训练，这些代码受各种开源协议保护
- **代码复制**：研究发现Copilot有时会逐字复制训练数据中的代码片段，而不保留原始许可证声明
- **GPL争议**：2022年，程序员Matthew Butterick对GitHub Copilot提起集体诉讼，指控其违反开源许可
- **归属问题**：AI生成的代码版权归谁？使用者？AI公司？还是训练数据的原作者？

### 4. 开发者过度信任AI的危险

```
  过度信任AI的危险循环
  ──────────────────────────────────────────────────────

  ┌─────────────────────────────────────────────┐
  │                                             │
  │  开发者使用AI生成代码                       │
  │         ↓                                   │
  │  代码"看起来"正确                          │
  │         ↓                                   │
  │  开发者跳过代码审查                         │
  │         ↓                                   │
  │  漏洞进入生产环境                           │
  │         ↓                                   │
  │  安全事故发生                               │
  │         ↓                                   │
  │  开发者更加依赖AI来"修复"问题              │
  │         ↓                                   │
  │  AI可能引入新的漏洞                         │
  │         ↓                                   │
  │  回到起点...                                │
  │                                             │
  └─────────────────────────────────────────────┘
```

斯坦福大学2023年的一项研究发现，使用AI辅助编程的开发者比不使用的开发者**更少进行安全审查**，因为他们潜意识中认为"AI生成的代码应该是安全的"。

## 7. AI军备竞赛与自主武器

### 1. 自主武器系统的伦理争议

自主武器系统（Lethal Autonomous Weapons Systems, LAWS）是指能够在没有人类干预的情况下选择并攻击目标的武器系统。

```
  武器系统的自主等级
  ──────────────────────────────────────────────────────

  人类控制度
    ↑
    │  ┌─────────────────────────────────────┐
    │  │ 人类在环（Human in the loop）       │
    │  │ 人类决定是否开火                    │
    │  │ 例：当前的无人机系统                │
    │  ├─────────────────────────────────────┤
    │  │ 人类在环上（Human on the loop）     │
    │  │ 机器选择目标，人类可以否决          │
    │  │ 例：以色列"铁穹"防空系统           │
    │  ├─────────────────────────────────────┤
    │  │ 人类在环外（Human out of the loop） │
    │  │ 机器自主选择并攻击目标              │
    │  │ 例：？？？（各国正在研发）          │
    │  └─────────────────────────────────────┘
    │
    └──────────────────────────────────────────→ 自主程度
```

已知的自主武器系统：

- **以色列"哈洛普"（Harop）**：巡飞弹，可自主搜索并攻击雷达目标
- **俄罗斯"标记"（Marker）**：无人战斗车辆，可自主识别目标
- **土耳其Kargu-2**：2020年利比亚内战中，据联合国报告可能自主攻击了撤退士兵
- **美国"海上猎手"**：自主反潜无人舰

### 3. AI在网络攻击中的攻防

AI正在改变网络攻击和防御的格局：

**攻击方的AI应用：**
- 自动化漏洞发现：AI可以比人类更快地扫描和发现软件漏洞
- 钓鱼邮件生成：AI可以生成高度个性化的钓鱼邮件，大幅提高成功率
- 恶意软件变异：AI可以自动生成免杀的恶意软件变种
- 口令破解：AI驱动的口令猜测比传统暴力破解效率高数倍

**防御方的AI应用：**
- 异常检测：AI可以实时监测网络流量中的异常行为
- 威胁情报分析：AI可以快速分析海量威胁数据
- 自动化响应：AI可以在毫秒级响应攻击
- 漏洞预测：AI可以预测哪些代码最可能存在漏洞

### 4. AI驱动的信息战

AI使信息战的规模和效率达到了前所未有的水平：

- **深度伪造**：伪造政治人物言论，制造社会分裂
- **AI生成假新闻**：GPT类模型可以批量生成逼真的假新闻
- **社交媒体机器人**：AI驱动的假账号可以模拟真实用户行为
- **精准微定向**：AI分析个人数据，为每个目标定制信息


2024年3月，欧盟通过了《人工智能法案》（EU AI Act），这是全球首部全面的AI立法：

- **不可接受风险**：禁止社会评分、实时远程生物识别等
- **高风险**：严格审查要求，包括司法、医疗、教育中的AI
- **有限风险**：透明度要求，如聊天机器人必须标明是AI
- **最小风险**：自由使用，如AI游戏、垃圾邮件过滤

### 2. 红队测试

红队测试（Red Teaming）是评估AI系统安全性的关键方法：

- **定义**：组织专门的团队，模拟恶意用户对AI系统进行攻击
- **目标**：在AI系统发布前发现潜在的安全漏洞和伦理风险
- **方法**：对抗性提示、越狱攻击、数据投毒、偏见探测等
- **案例**：OpenAI在GPT-4发布前进行了长达6个月的红队测试

### 3. 可解释AI

可解释AI（Explainable AI, XAI）旨在让AI的决策过程对人类可理解：

```
  黑箱 vs 可解释
  ──────────────────────────────────────────────────────

  黑箱AI：                          可解释AI：

  输入 ──→ [???] ──→ 输出          输入 ──→ [可审查] ──→ 输出
           │                                      │
           │ 无人知道内部                          │ 决策依据清晰
           │ 如何做出决策                          │ 可以质疑和纠正
           │                                      │
           ↓                                      ↓
  "你的贷款被拒"                   "你的贷款被拒，原因如下：
  "原因：算法说不行"                1. 债务收入比超过40%
                                   2. 信用历史不足3年
                                   3. 近6个月有3次逾期"
```

### 4. 人类在环

人类在环（Human-in-the-Loop, HITL）是确保AI安全的关键原则：

- **高风险决策**必须有人类最终审批权
- **AI建议，人类决定**——而非AI决定
- **异常情况**必须能触发人类介入
- **反馈机制**：人类决策应持续改进AI系统

### 5. 程序员的AI伦理责任

作为程序员，你在AI伦理中扮演着关键角色：

```
  程序员的AI伦理责任
  ──────────────────────────────────────────────────────

  ┌─────────────────────────────────────────────────┐
  │                                                 │

  │     · 理解AI生成代码的含义                      │
  │                                                 │
  │  2. 考虑偏见影响                                │
  │     · 审视训练数据的代表性                      │
  │     · 测试系统在不同群体上的表现                │
  │     · 设计公平性指标                            │
  │                                                 │
  │  3. 透明和可审计                                │
  │     · 记录AI系统的决策逻辑                      │
  │     · 提供可解释的输出                          │
  │     · 保留审计追踪                              │
  │                                                 │
```
