## 1. 常量折叠与传播

### 1.1 常量折叠（Constant Folding）

常量折叠在编译期计算常量表达式的值：

```cpp
// 常量折叠示例

// 优化前：
int x = 3 + 5;          // 运行时计算 3 + 5
int y = 10 * 2;          // 运行时计算 10 * 2
double z = 3.14 * 2.0;   // 运行时计算浮点乘法

// 优化后：
int x = 8;               // 编译期直接算出结果
int y = 20;               // 编译期直接算出结果
double z = 6.28;          // 编译期直接算出结果

// 更复杂的常量折叠
// 优化前：
int a = 10;
int b = a + 5;
int c = b * 2;

// 优化后（结合常量传播）：
int a = 10;
int b = 15;   // a 是常量 10，10 + 5 = 15
int c = 30;   // b 是常量 15，15 * 2 = 30
```

### 1.2 常量传播（Constant Propagation）

常量传播将已知的常量值替换到使用点：

```cpp
#include <unordered_map>
#include <string>
#include <optional>

// 常量传播分析器
class ConstantPropagation {
private:
    // 变量 → 常量值的映射
    std::unordered_map<std::string, std::optional<int>> constants;

public:
    // 分析并传播常量
    void analyze(TACInstructionList& instructions) {
        bool changed = true;
        while (changed) {
            changed = false;
            for (auto& inst : instructions) {
                changed |= processInstruction(inst);
            }
        }
    }

private:
    bool processInstruction(TACInstruction& inst) {
        switch (inst.op) {
            case TACOp::ASSIGN: {
                // x = 常量
                if (isConstant(inst.arg1)) {
                    constants[inst.result] = std::stoi(inst.arg1);
                    return true;
                }
                // x = y（y 是已知常量）
                auto it = constants.find(inst.arg1);
                if (it != constants.end() && it->second.has_value()) {
                    constants[inst.result] = it->second;
                    inst.arg1 = std::to_string(it->second.value());
                    return true;
                }
                break;
            }

            case TACOp::ADD: {
                // x = y + z
                auto leftVal = getConstantValue(inst.arg1);
                auto rightVal = getConstantValue(inst.arg2);

                if (leftVal.has_value() && rightVal.has_value()) {
                    // 两个操作数都是常量，折叠
                    int result = leftVal.value() + rightVal.value();
                    constants[inst.result] = result;
                    inst.op = TACOp::ASSIGN;
                    inst.arg1 = std::to_string(result);
                    inst.arg2 = "";
                    return true;
                }

                // 部分常量传播
                if (leftVal.has_value()) {
                    inst.arg1 = std::to_string(leftVal.value());
                    return true;
                }
                if (rightVal.has_value()) {
                    inst.arg2 = std::to_string(rightVal.value());
                    return true;
                }
                break;
            }

            // 其他运算类似处理...

            default:
                break;
        }

        // 非常量赋值：标记变量为非常量
        if (!inst.result.empty()) {
            constants.erase(inst.result);
        }

        return false;
    }

    std::optional<int> getConstantValue(const std::string& operand) {
        // 直接是数字常量
        if (isConstant(operand)) {
            return std::stoi(operand);
        }
        // 查找变量是否是已知常量
        auto it = constants.find(operand);
        if (it != constants.end() && it->second.has_value()) {
            return it->second;
        }
        return std::nullopt;
    }

    bool isConstant(const std::string& s) {
        if (s.empty()) return false;
        for (char c : s) {
            if (!isdigit(c) && c != '-') return false;
        }
        return true;
    }
};
```

### 1.3 条件常量传播（SCCP）

稀疏条件常量传播（Sparse Conditional Constant Propagation）结合了常量传播和死代码消除：

```
SCCP 算法：
1. 初始化：所有变量标记为"未定义"（TOP）
2. 前向传播：
   - 遇到常量赋值：标记为该常量值
   - 遇到非常量赋值：标记为"非常量"（BOTTOM）
   - 遇到条件分支：如果条件可确定为常量，删除不可达分支
3. 迭代直到收敛

示例：
int foo(int x) {
    int a = 10;        // a = 10（常量）
    int b = a + 5;     // b = 15（常量折叠+传播）
    if (b > 20) {      // 15 > 20 = false（常量）
        return a * 2;  // 死代码（不可达）
    }
    return b;          // 返回 15
}

SCCP 优化后：
int foo(int x) {
    return 15;
}
```

## 2. 死代码消除

### 2.1 死代码的定义

死代码（Dead Code）是程序执行中永远不会到达或其结果永远不会被使用的代码：

```
死代码的三种类型：

1. 不可达代码（Unreachable Code）
   - 永远不会被执行到的代码
   - 例：return 之后的代码、if(false) 块

2. 死赋值（Dead Assignment）
   - 变量被赋值但从未被使用
   - 例：int x = 10; x = 20; // 第一个赋值是死代码

3. 死存储（Dead Store）
   - 写入内存但该值从未被读取
   - 例：arr[i] = 0; arr[i] = 1; // 第一个存储是死代码
```

### 2.2 死代码消除算法

```cpp
#include <set>
#include <map>
#include <vector>

// 活跃变量分析 + 死代码消除
class DeadCodeElimination {
private:
    // 活跃变量分析
    void livenessAnalysis(std::vector<BasicBlock>& blocks) {
        // 反向数据流分析
        bool changed = true;
        while (changed) {
            changed = false;
            // 反向遍历基本块
            for (auto it = blocks.rbegin(); it != blocks.rend(); ++it) {
                auto& block = *it;

                // 计算出口活跃集：后继入口活跃集的并集
                std::set<std::string> newOut;
                for (BasicBlock* succ : block.successors) {
                    newOut.insert(succ->liveIn.begin(), succ->liveIn.end());
                }

                // 计算入口活跃集
                std::set<std::string> newIn = newOut;
                // 反向遍历指令
                for (auto instIt = block.instructions.rbegin();
                     instIt != block.instructions.rend(); ++instIt) {
                    auto& inst = *instIt;

                    // 从活跃集中删除被定义的变量
                    if (!inst.result.empty()) {
                        newIn.erase(inst.result);
                    }

                    // 将使用的变量加入活跃集
                    if (!inst.arg1.empty() && isVariable(inst.arg1)) {
                        newIn.insert(inst.arg1);
                    }
                    if (!inst.arg2.empty() && isVariable(inst.arg2)) {
                        newIn.insert(inst.arg2);
                    }
                }

                // 检查是否收敛
                if (newIn != block.liveIn || newOut != block.liveOut) {
                    changed = true;
                    block.liveIn = newIn;
                    block.liveOut = newOut;
                }
            }
        }
    }

public:
    // 执行死代码消除
    bool eliminate(std::vector<BasicBlock>& blocks) {
        // 1. 活跃变量分析
        livenessAnalysis(blocks);

        // 2. 删除死代码
        bool changed = false;
        for (auto& block : blocks) {
            std::set<std::string> live = block.liveOut;

            auto it = block.instructions.rbegin();
            while (it != block.instructions.rend()) {
                // 检查结果变量是否活跃
                bool isDead = false;
                if (!it->result.empty() && isVariable(it->result)) {
                    if (live.find(it->result) == live.end()) {
                        // 结果变量不活跃，这是死代码
                        isDead = true;
                    }
                }

                if (isDead) {
                    // 删除死指令
                    block.instructions.erase(std::next(it).base());
                    changed = true;
                } else {
                    // 更新活跃集
                    live.erase(it->result);
                    if (!it->arg1.empty() && isVariable(it->arg1)) {
                        live.insert(it->arg1);
                    }
                    if (!it->arg2.empty() && isVariable(it->arg2)) {
                        live.insert(it->arg2);
                    }
                }
                ++it;
            }
        }

        return changed;
    }

private:
    bool isVariable(const std::string& s) {
        // 临时变量或命名变量
        return !s.empty() && (s[0] == 't' || s[0] == '%');
    }
};
```

### 2.3 不可达代码消除

```cpp
// 不可达代码消除
class UnreachableCodeElimination {
public:
    bool eliminate(std::vector<BasicBlock>& blocks) {
        if (blocks.empty()) return false;

        // 从入口块开始 BFS，标记可达块
        std::set<BasicBlock*> reachable;
        std::queue<BasicBlock*> worklist;
        worklist.push(&blocks[0]);

        while (!worklist.empty()) {
            BasicBlock* block = worklist.front();
            worklist.pop();

            if (reachable.find(block) != reachable.end()) continue;
            reachable.insert(block);

            for (BasicBlock* succ : block->successors) {
                if (reachable.find(succ) == reachable.end()) {
                    worklist.push(succ);
                }
            }
        }

        // 删除不可达块
        size_t originalSize = blocks.size();
        blocks.erase(
            std::remove_if(blocks.begin(), blocks.end(),
                [&reachable](const BasicBlock& b) {
                    return reachable.find(const_cast<BasicBlock*>(&b)) == reachable.end();
                }),
            blocks.end()
        );

        return blocks.size() < originalSize;
    }
};
```

## 3. 循环优化

### 3.1 循环展开（Loop Unrolling）

循环展开通过复制循环体来减少循环控制开销：

```cpp
// 循环展开示例

// 优化前：
for (int i = 0; i < 100; i++) {
    a[i] = b[i] + c[i];
}

// 展开 4 次后：
for (int i = 0; i < 100; i += 4) {
    a[i]   = b[i]   + c[i];
    a[i+1] = b[i+1] + c[i+1];
    a[i+2] = b[i+2] + c[i+2];
    a[i+3] = b[i+3] + c[i+3];
}
// 注意：需要处理循环次数不是展开因子的倍数的情况

// 循环展开的好处：
// 1. 减少循环条件判断次数（100次 → 25次）
// 2. 减少分支预测失败
// 3. 暴露指令级并行性（4次迭代可并行执行）
// 4. 便于后续优化（如向量化）
```

### 3.2 循环不变量外提（Loop Invariant Code Motion, LICM）

将循环中不变的计算移到循环外：

```cpp
// 循环不变量外提示例

// 优化前：
for (int i = 0; i < n; i++) {
    a[i] = b[i] * (x + y);  // x + y 在循环中不变
}

// 优化后：
int temp = x + y;            // 提到循环外
for (int i = 0; i < n; i++) {
    a[i] = b[i] * temp;      // 使用预计算的值
}

// LICM 算法：
// 1. 识别循环不变量：
//    - 操作数在循环外定义
//    - 或者操作数本身也是循环不变量
// 2. 检查是否可以安全外提：
//    - 外提不能改变程序语义
//    - 特别是：外提不能引入新的异常
// 3. 将不变量移到循环前置节点
```

```cpp
// LICM 实现
class LoopInvariantCodeMotion {
private:
    // 判断指令是否是循环不变量
    bool isLoopInvariant(const TACInstruction& inst,
                        const std::set<std::string>& loopDefs) {
        // 如果指令修改了内存或有副作用，不能外提
        if (hasSideEffects(inst)) return false;

        // 检查操作数是否在循环外定义
        if (!inst.arg1.empty() && isVariable(inst.arg1)) {
            if (loopDefs.find(inst.arg1) != loopDefs.end()) {
                return false;  // arg1 在循环内定义
            }
        }
        if (!inst.arg2.empty() && isVariable(inst.arg2)) {
            if (loopDefs.find(inst.arg2) != loopDefs.end()) {
                return false;  // arg2 在循环内定义
            }
        }

        return true;
    }

    // 检查是否可以安全外提
    bool isSafeToHoist(const TACInstruction& inst,
                      const std::set<std::string>& loopDefs) {
        // 必须满足以下条件之一：
        // 1. 指令支配所有出口（即无论如何都会执行）
        // 2. 指令的结果在循环外不被使用
        // 3. 指令没有副作用

        // 简化实现：只外提纯计算指令
        return inst.op != TACOp::CALL &&
               inst.op != TACOp::STORE &&
               inst.op != TACOp::PARAM;
    }

public:
    void hoistInvariants(BasicBlock* loopHeader,
                        BasicBlock* loopPreheader,
                        const std::vector<BasicBlock*>& loopBody) {
        // 1. 收集循环内定义的所有变量
        std::set<std::string> loopDefs;
        for (BasicBlock* block : loopBody) {
            for (const auto& inst : block->instructions) {
                if (!inst.result.empty()) {
                    loopDefs.insert(inst.result);
                }
            }
        }

        // 2. 迭代识别并外提循环不变量
        bool changed = true;
        while (changed) {
            changed = false;
            for (BasicBlock* block : loopBody) {
                for (auto it = block->instructions.begin();
                     it != block->instructions.end(); ) {
                    if (isLoopInvariant(*it, loopDefs) &&
                        isSafeToHoist(*it, loopDefs)) {
                        // 移到循环前置节点
                        loopPreheader->instructions.push_back(*it);
                        it = block->instructions.erase(it);
                        loopDefs.erase(it->result);
                        changed = true;
                    } else {
                        ++it;
                    }
                }
            }
        }
    }

private:
    bool hasSideEffects(const TACInstruction& inst) {
        return inst.op == TACOp::CALL || inst.op == TACOp::STORE ||
               inst.op == TACOp::PARAM;
    }

    bool isVariable(const std::string& s) {
        return !s.empty() && (s[0] == 't' || s[0] == '%');
    }
};
```

### 3.3 循环向量化（Loop Vectorization）

向量化将标量运算转换为 SIMD 向量运算：

```cpp
// 自动向量化示例

// 原始标量循环：
for (int i = 0; i < 1024; i++) {
    c[i] = a[i] + b[i];
}

// 向量化后（假设 4 元素 SIMD）：
for (int i = 0; i < 1024; i += 4) {
    // 一条指令同时处理 4 个元素
    __m128 va = _mm_load_ps(&a[i]);      // 加载 4 个 float
    __m128 vb = _mm_load_ps(&b[i]);      // 加载 4 个 float
    __m128 vc = _mm_add_ps(va, vb);      // 一条指令完成 4 次加法
    _mm_store_ps(&c[i], vc);             // 存储 4 个 float
}

// 向量化的条件：
// 1. 循环迭代之间没有数据依赖
// 2. 内存访问是连续的
// 3. 没有复杂的控制流
// 4. 数据类型支持 SIMD 操作

// LLVM 的向量化 Pass：
// - SLP 向量化（超字长级并行）：将同一条指令的多个标量操作组合
// - Loop 向量化：将循环转换为 SIMD 操作
```

## 4. 内联优化

### 4.1 函数内联原理

函数内联将函数调用替换为函数体本身，消除调用开销：

```cpp
// 内联示例

// 优化前：
inline int square(int x) { return x * x; }

int main() {
    int a = square(5);    // 函数调用
    int b = square(10);   // 函数调用
    return a + b;
}

// 内联后：
int main() {
    int a = 5 * 5;        // 直接替换为函数体
    int b = 10 * 10;      // 直接替换为函数体
    return a + b;
}

// 常量折叠后：
int main() {
    int a = 25;
    int b = 100;
    return 125;
}
```

### 4.2 内联决策

```cpp
// 内联决策算法
class Inliner {
private:
    // 函数信息
    struct FunctionInfo {
        int instructionCount;     // 指令数
        int callCount;            // 调用次数
        bool isRecursive;         // 是否递归
        bool hasSideEffects;      // 是否有副作用
        bool isHot;               // 是否热点函数
    };

    std::unordered_map<std::string, FunctionInfo> funcInfo;
    int maxInlineSize = 200;      // 最大可内联函数大小

public:
    // 判断是否应该内联
    bool shouldInline(const std::string& caller,
                     const std::string& callee) {
        const auto& info = funcInfo[callee];

        // 不内联的情况
        if (info.isRecursive) return false;       // 递归函数不内联
        if (info.instructionCount > maxInlineSize) return false;  // 太大不内联
        if (info.hasSideEffects && !info.isHot) return false;     // 冷代码有副作用不内联

        // 积极内联的情况
        if (info.instructionCount <= 10) return true;   // 小函数总是内联
        if (info.isHot) return true;                     // 热点函数优先内联

        // 权衡决策
        // 内联收益：消除调用开销 + 暴露更多优化机会
        // 内联代价：代码膨胀 → 指令缓存压力
        int benefit = estimateInlineBenefit(callee);
        int cost = estimateInlineCost(caller, callee);

        return benefit > cost;
    }

private:
    int estimateInlineBenefit(const std::string& callee) {
        const auto& info = funcInfo[callee];
        int benefit = 0;

        benefit += 10;  // 消除调用开销的基本收益
        if (info.instructionCount <= 5) benefit += 20;  // 极小函数收益大
        if (info.isHot) benefit += 30;                  // 热点代码收益大

        return benefit;
    }

    int estimateInlineCost(const std::string& caller,
                          const std::string& callee) {
        const auto& callerInfo = funcInfo[caller];
        const auto& calleeInfo = funcInfo[callee];

        int cost = calleeInfo.instructionCount;  // 代码膨胀

        // 如果调用者已经很大，增加额外代价
        if (callerInfo.instructionCount > 500) {
            cost *= 2;
        }

        return cost;
    }
};
```

## 5. 尾调用优化

### 5.1 尾调用原理

尾调用是函数的最后一步操作是调用另一个函数，此时可以复用当前栈帧：

```cpp
// 尾调用示例

// 普通递归（不是尾调用）：
int factorial(int n) {
    if (n <= 1) return 1;
    return n * factorial(n - 1);  // 递归调用后还要乘 n
    // 每次递归都需要保留栈帧，n=10000 会栈溢出
}

// 尾递归版本：
int factorial_tail(int n, int acc = 1) {
    if (n <= 1) return acc;
    return factorial_tail(n - 1, n * acc);  // 尾调用：最后一步是函数调用
    // 编译器优化后，复用栈帧，不会栈溢出
}

// 优化前（尾递归未优化）的调用栈：
// factorial_tail(5, 1)
//   → factorial_tail(4, 5)
//     → factorial_tail(3, 20)
//       → factorial_tail(2, 60)
//         → factorial_tail(1, 120)
//           → 返回 120
// 5 层栈帧

// 优化后（尾调用优化）：
// 等价于循环：
int factorial_optimized(int n) {
    int acc = 1;
    while (n > 1) {
        acc = n * acc;
        n = n - 1;
    }
    return acc;
}
// 只有 1 层栈帧
```

### 5.2 尾调用优化的实现

```llvm
; LLVM IR 中的尾调用优化

; 优化前：
define i32 @factorial_tail(i32 %n, i32 %acc) {
entry:
    %cmp = icmp sle i32 %n, 1
    br i1 %cmp, label %base, label %recurse

base:
    ret i32 %acc

recurse:
    %n_minus_1 = sub i32 %n, 1
    %new_acc = mul i32 %n, %acc
    %result = call i32 @factorial_tail(i32 %n_minus_1, i32 %new_acc)
    ret i32 %result
}

; 优化后（使用 tail call）：
define i32 @factorial_tail(i32 %n, i32 %acc) {
entry:
    %cmp = icmp sle i32 %n, 1
    br i1 %cmp, label %base, label %recurse

base:
    ret i32 %acc

recurse:
    %n_minus_1 = sub i32 %n, 1
    %new_acc = mul i32 %n, %acc
    %result = tail call i32 @factorial_tail(i32 %n_minus_1, i32 %new_acc)
    ;          ^^^^ tail 关键字告诉编译器可以复用栈帧
    ret i32 %result
}
```

```cpp
// C++ 中确保尾调用优化的技巧

// 方法1：使用尾递归形式
size_t fib_tail(size_t n, size_t a = 0, size_t b = 1) {
    if (n == 0) return a;
    if (n == 1) return b;
    return fib_tail(n - 1, b, a + b);  // 尾调用
}

// 方法2：使用 [[musttail]] 属性（Clang 扩展）
int helper(int n);
int wrapper(int n) {
    // 必须是尾调用，编译器会验证
    [[clang::musttail]] return helper(n);
}

// 方法3：手动转为循环（最可靠）
size_t fib_iterative(size_t n) {
    if (n == 0) return 0;
    size_t a = 0, b = 1;
    for (size_t i = 2; i <= n; i++) {
        size_t temp = a + b;
        a = b;
        b = temp;
    }
    return b;
}
```

## 6. 逃逸分析

### 6.1 逃逸分析原理

逃逸分析确定对象的作用域是否"逃逸"出函数：

```
逃逸的三种级别：
1. 不逃逸（NoEscape）：对象仅在函数内使用
   → 可以在栈上分配（而非堆上）
   → 可以被标量替换

2. 参数逃逸（ArgEscape）：对象通过参数传递给被调用函数
   → 可能需要保留在堆上

3. 全局逃逸（GlobalEscape）：对象被返回或存入全局变量
   → 必须在堆上分配
```

### 6.2 逃逸分析实现

```cpp
#include <set>
#include <map>
#include <string>

// 逃逸级别
enum class EscapeLevel {
    NoEscape,       // 不逃逸
    ArgEscape,      // 参数逃逸
    GlobalEscape    // 全局逃逸
};

// 逃逸分析器
class EscapeAnalyzer {
private:
    // 变量 → 逃逸级别
    std::map<std::string, EscapeLevel> escapeInfo;

    // 更新逃逸级别（只升不降）
    void updateEscapeLevel(const std::string& var, EscapeLevel level) {
        auto& current = escapeInfo[var];
        if (level > current) {
            current = level;
        }
    }

public:
    // 分析函数中的逃逸情况
    void analyze(FunctionAST* function) {
        // 第一遍：收集逃逸信息
        for (const auto& stmt : function->body) {
            analyzeStatement(stmt);
        }

        // 第二遍：传播逃逸信息
        propagateEscapeInfo();
    }

    // 分析语句
    void analyzeStatement(const StatementAST* stmt) {
        switch (stmt->type) {
            case StmtType::RETURN:
                // 返回值中的变量全局逃逸
                analyzeReturnExpr(stmt->expr);
                break;

            case StmtType::ASSIGN:
                // 赋值给全局变量 → 全局逃逸
                if (isGlobalVar(stmt->target)) {
                    updateEscapeLevel(stmt->value, EscapeLevel::GlobalEscape);
                }
                break;

            case StmtType::CALL:
                // 传递给函数的参数 → 参数逃逸
                for (const auto& arg : stmt->arguments) {
                    analyzeCallArg(arg);
                }
                break;

            default:
                break;
        }
    }

    // 分析返回表达式
    void analyzeReturnExpr(const ExprAST* expr) {
        if (expr->type == ExprType::VARIABLE) {
            updateEscapeLevel(expr->name, EscapeLevel::GlobalEscape);
        }
        if (expr->type == ExprType::ADDRESS_OF) {
            // 取地址并返回 → 全局逃逸
            updateEscapeLevel(expr->operand, EscapeLevel::GlobalEscape);
        }
    }

    // 分析函数调用参数
    void analyzeCallArg(const ExprAST* arg) {
        if (arg->type == ExprType::VARIABLE) {
            updateEscapeLevel(arg->name, EscapeLevel::ArgEscape);
        }
        if (arg->type == ExprType::ADDRESS_OF) {
            // 传递指针 → 可能全局逃逸
            updateEscapeLevel(arg->operand, EscapeLevel::ArgEscape);
        }
    }

    // 传播逃逸信息
    void propagateEscapeInfo() {
        // 如果变量 A 的值赋给变量 B，且 A 逃逸，则 B 也逃逸
        // ...（数据流分析）
    }

    // 查询逃逸级别
    EscapeLevel getEscapeLevel(const std::string& var) const {
        auto it = escapeInfo.find(var);
        if (it != escapeInfo.end()) return it->second;
        return EscapeLevel::NoEscape;
    }

    // 判断是否可以在栈上分配
    bool canStackAllocate(const std::string& var) const {
        return getEscapeLevel(var) == EscapeLevel::NoEscape;
    }
};
```

### 6.3 逃逸分析的应用

```cpp
// 逃逸分析的应用：标量替换

// 优化前：
struct Point { float x, y; };

float distance(Point* p1, Point* p2) {
    // p1 和 p2 不逃逸 → 可以标量替换
    float dx = p1->x - p2->x;
    float dy = p1->y - p2->y;
    return sqrt(dx * dx + dy * dy);
}

// 标量替换后：
float distance(float p1_x, float p1_y, float p2_x, float p2_y) {
    // 结构体被拆解为标量，无需内存分配
    float dx = p1_x - p2_x;
    float dy = p1_y - p2_y;
    return sqrt(dx * dx + dy * dy);
}

// Java/C# 中的逃逸分析更重要：
// 不逃逸的对象 → 栈上分配（而非堆上）→ 减少GC压力
// 标量替换 → 消除对象分配 → 直接使用标量变量
```

## 7. LLVM优化Pass编写

### 7.1 LLVM Pass 框架

LLVM 的优化以 Pass 为单位，每个 Pass 实现一种优化：

```
LLVM Pass 的分类：
┌──────────────────────────────────────────────┐
│  Module Pass    - 以模块为单位遍历            │
│  Function Pass  - 以函数为单位遍历            │
│  BasicBlock Pass - 以基本块为单位遍历         │
│  Loop Pass      - 以循环为单位遍历            │
│  Region Pass    - 以区域为单位遍历            │
│  CallGraph Pass - 以调用图为单位遍历          │
└──────────────────────────────────────────────┘

LLVM 新 Pass Manager（LLVM 13+）：
- 使用 PassInfoMixin 基类
- 更好的 Pass 依赖管理
- 更细粒度的分析结果管理
```

### 7.2 编写自定义优化 Pass

```cpp
// 自定义 LLVM Pass：统计函数中的基本块数量
// 基于 LLVM 新 Pass Manager

#include "llvm/IR/Function.h"
#include "llvm/IR/PassManager.h"
#include "llvm/Passes/PassBuilder.h"
#include "llvm/Passes/PassPlugin.h"
#include "llvm/Support/raw_ostream.h"

using namespace llvm;

// 统计基本块数量的 Pass
struct BasicBlockCounterPass : public PassInfoMixin<BasicBlockCounterPass> {
    // 主入口：对每个函数执行
    PreservedAnalyses run(Function& F, FunctionAnalysisManager& AM) {
        int blockCount = 0;
        int instCount = 0;

        for (const BasicBlock& BB : F) {
            blockCount++;
            instCount += BB.size();
        }

        errs() << "函数 " << F.getName()
               << ": " << blockCount << " 个基本块, "
               << instCount << " 条指令\n";

        // 返回 PreservedAnalyses::all() 表示未修改 IR
        return PreservedAnalyses::all();
    }

    // 是否为必需 Pass（如果不运行此 Pass，其他 Pass 的结果可能不正确）
    static bool isRequired() { return false; }
};

// 自定义优化 Pass：简单的常量折叠
struct SimpleConstantFoldingPass : public PassInfoMixin<SimpleConstantFoldingPass> {
    PreservedAnalyses run(Function& F, FunctionAnalysisManager& AM) {
        bool changed = false;

        for (BasicBlock& BB : F) {
            for (Instruction& I : BB) {
                // 检查是否是二元运算且操作数都是常量
                if (auto* binOp = dyn_cast<BinaryOperator>(&I)) {
                    Value* lhs = binOp->getOperand(0);
                    Value* rhs = binOp->getOperand(1);

                    // 如果两个操作数都是常量整数
                    if (auto* lhsConst = dyn_cast<ConstantInt>(lhs)) {
                        if (auto* rhsConst = dyn_cast<ConstantInt>(rhs)) {
                            // 在编译期计算结果
                            Constant* result = ConstantExpr::get(
                                binOp->getOpcode(), lhsConst, rhsConst);

                            // 用常量替换指令
                            I.replaceAllUsesWith(result);
                            I.eraseFromParent();
                            changed = true;
                        }
                    }
                }
            }
        }

        return changed ? PreservedAnalyses::none() : PreservedAnalyses::all();
    }

    static bool isRequired() { return false; }
};

// 自定义优化 Pass：死代码消除
struct SimpleDCEPass : public PassInfoMixin<SimpleDCEPass> {
    PreservedAnalyses run(Function& F, FunctionAnalysisManager& AM) {
        bool changed = false;
        SmallVector<Instruction*, 16> deadInstructions;

        // 收集死指令
        for (BasicBlock& BB : F) {
            for (Instruction& I : BB) {
                // 如果指令没有使用且没有副作用
                if (I.use_empty() && !I.mayHaveSideEffects()) {
                    deadInstructions.push_back(&I);
                }
            }
        }

        // 删除死指令
        for (Instruction* I : deadInstructions) {
            I->eraseFromParent();
            changed = true;
        }

        return changed ? PreservedAnalyses::none() : PreservedAnalyses::all();
    }

    static bool isRequired() { return false; }
};

// ==================== Pass 注册 ====================

// 注册为插件
extern "C" LLVM_ATTRIBUTE_WEAK ::llvm::PassPluginLibraryInfo
llvmGetPassPluginInfo() {
    return {
        LLVM_PLUGIN_API_VERSION, "MyOptimizationPasses", "1.0",
        [](PassBuilder& PB) {
            // 注册为函数级 Pass
            PB.registerPipelineParsingCallback(
                [](StringRef Name, FunctionPassManager& FPM,
                   ArrayRef<PassBuilder::PipelineElement>) {
                    if (Name == "bb-counter") {
                        FPM.addPass(BasicBlockCounterPass());
                        return true;
                    }
                    if (Name == "simple-constfold") {
                        FPM.addPass(SimpleConstantFoldingPass());
                        return true;
                    }
                    if (Name == "simple-dce") {
                        FPM.addPass(SimpleDCEPass());
                        return true;
                    }
                    return false;
                }
            );
        }
    };
}
```

## 8. 本章小结

### 核心要点回顾

| 优化技术 | 关键内容 |
|---------|---------|
| 常量折叠与传播 | 编译期计算常量表达式，传播已知常量值 |
| 死代码消除 | 删除不可达代码和结果未使用的指令 |
| 循环优化 | 展开、不变量外提、向量化、强度消减等 |
| 内联优化 | 消除函数调用开销，暴露更多优化机会 |
| 尾调用优化 | 复用栈帧，将尾递归转为循环 |
| 逃逸分析 | 确定对象作用域，支持栈分配和标量替换 |
| LLVM Pass | 可插拔的优化模块，支持自定义扩展 |

### 关键理解

1. **优化是迭代过程**：多个优化 Pass 反复执行直到收敛
2. **优化之间相互促进**：内联暴露更多优化机会，常量传播使更多代码成为死代码
3. **正确性是底线**：任何优化都不能改变程序的可观测行为
4. **编译时间 vs 运行性能**：优化级别越高，编译越慢，收益递减
